## 这一篇讲什么

`main()` 在 Zephyr 里**不是程序的全部，只是一个线程**——
而且是内核替你建好的两个系统线程之一（另一个是 idle）。
理解这两个线程的优先级和角色，才能解释启动时序里看到的所有现象。

## 两个天生的线程

| | main 线程 | idle 线程 |
|---|---|---|
| 创建者 | 内核（启动流程自动建） | 内核（调度器启动前必建） |
| 默认优先级 | **最高抢占式**（`K_PRIO_PREEMPT(0)`，数值最小的抢占级） | **全系统最低**（数值最大的那一级） |
| 栈 | `CONFIG_MAIN_STACK_SIZE`（默认 1024） | `CONFIG_IDLE_STACK_SIZE`（默认 320） |
| 角色 | 跑你的 `main()` | 没事干时垫场 + 进低功耗（`__WFI`） |
| 终止 | main 返回 → 线程正常结束，世界继续 | 永远在场，不可终止 |

对照 FreeRTOS：

| | FreeRTOS | Zephyr |
|---|---|---|
| main | 启动代码一路跑到 main，main 里"手动"建任务、手动 vTaskStartScheduler | **main 本身就是线程**，静态线程可能已经在跑 |
| idle | 优先级 0，收尸人（释放已删任务的 TCB+栈） | 最低优先级，**没有收尸职责**（Zephyr 线程正常返回后资源由内核直接处理） |
| 空闲钩子 | vApplicationIdleHook | `CONFIG_IDLE_HOOK`？——Zephyr 主要靠 idle 里进 WFI + pm 子系统 |

## main 线程的两个反直觉点

**① main 的默认优先级是"最高抢占式"。**
意味着 main 里写的初始化代码会压过所有你建的抢占式应用线程（除非你也用 0 级）。
启动时序的实际样子：

```
上电 → 内核初始化（SYS_INIT 各级）→ 静态线程建完
     → main 线程跑（抢占式 0 级，最高）
       → 你的动态 k_thread_create 在这发生
       → main 返回 / 或 main 里 k_sleep 让出
     → 应用线程按优先级接管
```

**② main 返回是合法的。**
main 线程结束 = 这个线程终止，其他线程照跑。
所以 Zephyr 工程的 main 常见三种形态：
初始化完就返回（线程交给静态定义的）；自己当主循环（`for(;;)` 里干活）；
或初始化完 `k_sleep(K_FOREVER)` 挂起自己。

## idle 线程与低功耗

idle 线程循环的核心就一件事：`__WFI()`（等中断）。
这与 FreeRTOS 空闲钩子里的简易睡法一致；
Zephyr 的正式电源管理（`CONFIG_PM`）会在 idle 路径上
自动选睡眠深度——对应 FreeRTOS ch10 的 tickless 思想，
但 Zephyr 把它做成了**子系统**而不是"一个 config 开关 + 一个钩子"。

## 要点回顾

1. `main()` 是内核建好的线程：默认最高抢占式优先级，返回合法。
2. idle 线程全系统最低优先级，循环里 WFI，是电源管理的入口。
3. 与 FreeRTOS 分工不同：Zephyr idle **不收尸**，main 不手动启动调度器。

<details>
<summary>Q1：main 里 k_sleep(K_FOREVER) 和直接返回有什么区别？</summary>

返回：main 线程终止，栈/TCB 资源按内核流程处理；
K_FOREVER：main 线程永久挂起，资源保留着。
功能上几乎没差（都不跑了）；**想要"明确结束"就返回**，
保留句柄以后可能 wakeup 就 K_FOREVER。多数工程选返回，干净。

</details>

<details>
<summary>Q2：能让 main 线程变成协作式吗？</summary>

能，`CONFIG_MAIN_THREAD_PRIORITY` 可以配成负数——
main 就变成协作式（跑完前抢占式线程全等）。
某些"初始化必须原子完成"的严肃工程会这么干。
学习工程保持默认即可，但要知道这个旋钮存在。

</details>
