# 4.1 线程是什么：k_thread、TCB 与栈

## 这一篇讲什么

Zephyr 的 thread 和 FreeRTOS 的 task 是**同一个概念的两个名字**：
一个独立执行流 = 一份 CPU 现场 + 一个栈 + 一个内核控制块。
这一篇把三个组成部分摆清楚，重点在 Zephyr 特有的地方。

## 线程的三件家当

```
struct k_thread {          ← TCB（控制块），内核调度/排队都引用它
    /* 现场保存区、优先级、状态、各等待队列节点…… */
};
+ 一个栈（K_THREAD_STACK 或 k_thread_stack_alloc 分配）
+ 一个入口函数：void entry(void *p1, void *p2, void *p3)
```

与 FreeRTOS 逐项对照：

| | FreeRTOS | Zephyr |
|---|---|---|
| 控制块 | TCB_t | `struct k_thread` |
| 入口原型 | `void f(void *)` 一个参数 | `void f(void*, void*, void*)` **三个参数** |
| 栈来源 | pvPortMalloc（heap_4） | 静态 K_THREAD_STACK / 动态 k_thread_stack_alloc |
| 铁律"永不返回" | 返回 = 事故 | **可以返回**——Zephyr 允许线程函数返回，线程就此终止 |

最后一行是**世界观差异**：Zephyr 线程函数返回是**合法的结束方式**
（内核帮你收尾），FreeRTOS 返回是事故。当然长期驻留的服务线程
照样写 `for(;;)`，但"干完就退出"的一次性线程在 Zephyr 里是正经用法。

## 栈：Zephyr 把"静态分配"做成了默认美学

FreeRTOS 里栈从 ucHeap 动态切（[ch02](../../../freertos/book-notes/02-heap-memory/README.md)），
Zephyr 主推**静态分配**：

```c
K_THREAD_STACK_DEFINE(my_stack, 1024);   /* 编译期定死的 1KB 栈，进 .bss */
```

好处和裸机静态分配一脉相承（[ch13](../../../stm32/book-notes/13-dynamic-memory/README.md)）：
大小链接期可见、无碎片、无分配失败路径；`nm` / 链接 map 里直接查得到每个栈的位置。
动态分配（`k_thread_stack_alloc`）留给了真正需要的场景
（且要 CONFIG_DYNAMIC_THREAD，F103 的 20K RAM 上基本不会开）。

## 栈溢出防护的家底

Zephyr 在栈保护上的配置项（写 prj.conf 时选）：

| 配置 | 机制 | 开销 |
|---|---|---|
| `CONFIG_STACK_SENTINEL` | 栈底放一个魔数，切换时检查被改没 | 极小，只查切换点 |
| `CONFIG_HW_STACK_PROTECTION` | 用 MPU 在栈底划保护区，越界当场 MemManage 异常 | 需 MPU（F103 有） |
| `CONFIG_THREAD_STACK_INFO` | 允许运行时查询栈用量（水位线） | 小 |

对照 FreeRTOS：方法≈`configCHECK_FOR_STACK_OVERFLOW` 的 1/2，
MPU 方案 FreeRTOS 也有（FreeRTOS-MPU 是单独分支，Zephyr 是主线内置）。

## 与 LDD- 侧对照

Linux 线程 = task_struct + 内核栈 + 用户栈；Zephyr 无线程/内核态分离，
`k_thread` 一个结构包打天下——和 FreeRTOS 一样，**MCU RTOS 没有双栈分家，
MSP/PSP 的硬件双栈（ch20.1）是中断隔离用的，不是权限隔离用的**。

## 要点回顾

1. Zephyr thread ≈ FreeRTOS task：控制块 + 栈 + 入口函数；入口收**三个** void*。
2. 世界观差异：Zephyr 线程函数**可以返回**（正常终止），FreeRTOS 返回是事故。
3. Zephyr 主推静态栈（K_THREAD_STACK_DEFINE），栈保护有 sentinel/MPU/水位三档。

<details>
<summary>Q1：线程函数能返回，那"干完活还想保留结果"怎么办？</summary>

返回值没地方放（入口原型是 void），结果走共享变量 + 同步对象
（k_sem / k_msgq），或者让别的线程 `k_thread_join` 等它结束后再读结果。
`k_thread_join` 见 [4.6](4.6-生命周期与栈检测.md)。

</details>

<details>
<summary>Q2：K_THREAD_STACK_DEFINE 的栈有对齐要求吗？</summary>

有，宏内部已处理（`K_THREAD_STACK_LEN`/`__aligned`）。
但**自己定义字节数组当栈**是常见翻车点：MPU 栈保护要求栈大小是 2 的幂
（F1 的 MPU 区域粒度限制），K_THREAD_STACK_DEFINE 会自动向上取整，
裸数组不会。要栈保护就老实走宏。

</details>
