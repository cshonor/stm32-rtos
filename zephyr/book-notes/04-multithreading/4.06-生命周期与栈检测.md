## 这一篇讲什么

线程的三种死法（正常返回 / abort / 异常）、怎么"等它死"（join）、
以及死后验尸工具（栈水位、栈保护）。收尾 ch04。

## 三种死法

| 死法 | 路径 | 善后 |
|---|---|---|
| **正常返回** | 入口函数 return（[4.01](4.01-线程是什么.md)：Zephyr 里合法） | 内核标记 dead，等待 join 或资源回收 |
| **k_thread_abort(tid)** | 别的线程（或自己）强制终止 | 同上；**abort 自己 = 立刻让出 CPU** |
| **异常**（除零/越界/栈溢出触发 MPU） | CPU 异常 → 内核 fatal error 处理 | 默认进 `k_fatal_error` → 打印现场停机 |

对照 FreeRTOS：只有"任务调 vTaskDelete"一条死路（且函数返回是事故）。
Zephyr 把"正常结束"扶正，让线程模型更接近 pthread
（pthread 也是 return 正常退出 + pthread_join 收尸）。

## k_thread_join：等它死，顺便同步

```c
k_tid_t t = k_thread_create(...);   /* 或 K_THREAD_DEFINE 的符号名 */
k_thread_join(t, K_FOREVER);        /* 阻塞到 t 结束 */
```

等价于 pthread_join。典型用途："主线程 fork 出计算线程，
join 等结果"——一次性任务的标准模式。
**注意 join 的是 tid，死的线程也能 join**（立刻返回），
但不能 join 自己（死锁，内核会拦）。

abort 的规矩和 FreeRTOS vTaskDelete 同款警告：
**abort 不替你收拾线程自己拿的资源**（信号量、互斥量、申请的内存）。
能设计"正常退出路径"就别用 abort——它只是逃生门。

## 栈溢出：三道防线怎么配

复习 [4.01](4.01-线程是什么.md) 的家底，加上使用姿势：

```conf
# prj.conf
CONFIG_HW_STACK_PROTECTION=y    # 防线1：MPU 栈底保护区，越界当场 MemManage
CONFIG_STACK_SENTINEL=y         # 防线2：栈底魔数，切换时抽查（无 MPU 时的低配）
CONFIG_THREAD_STACK_INFO=y      # 防线3：允许运行时查栈信息
CONFIG_THREAD_RUNTIME_STATS=y   # 配套：水位/CPU 占用统计
```

运行时读水位（开发期调栈大小的正规方法）：

```c
size_t unused;
k_thread_stack_space_get(tid, &unused);
printk("%s 栈剩余 %u 字节\n", k_thread_name_get(tid), unused);
```

**调栈方法论**（与 [freertos 2.03](../../../freertos/book-notes/02-heap-memory/2.03-本仓选型heap_4.md)
"先宽后紧"同哲学）：先给宽裕值 → 跑全功能 → 读水位 → 收紧到
"历史最深用量 × 1.5"。防线 1/2 是保险丝，水位统计是调表工具——
**保险丝不能代替调表**。

## 栈大小去哪查（链接期视角）

静态栈（K_THREAD_STACK_DEFINE / K_THREAD_DEFINE）全部落在 `.bss`，
`nm zephyr.elf | grep stack` 或 map 文件直接可见——
20K RAM 的 F103 上，所有线程栈 + main 栈 + idle 栈 + 中断栈的总账，
**链接期就该算平**，不要等运行时爆炸。

## 要点回顾

1. 三种死法：返回（合法）/ abort（逃生门）/ 异常（fatal）；join 等死并同步。
2. abort 不收资源，能走正常退出就别 abort。
3. 栈保护三道防线 + 水位统计；静态栈让总账链接期可算。

<details>
<summary>Q1：线程死了 tid 还能用吗？</summary>

死了的 tid 可以 join（立即返回）、可以查名字；
但**不能**重新调度它（K_THREAD_DEFINE 的线程死了就是死了，
想"重启"得再 k_thread_create 一个新的，复用同一块栈/TCB 存储）。
悬垂 tid 的其他用法 = 未定义行为，和 FreeRTOS 悬垂句柄同款规矩。

</details>

<details>
<summary>Q2：fatal error 后能自动复位而不是停机吗？</summary>

能，`k_sys_fatal_error_handler` 是可覆盖的弱函数（weak）——
产品里通常改成"记录现场 → 看门狗复位"。
学习阶段保持默认（停机），调试器里看现场比反复复位有用得多。

</details>
