# 4.03 优先级两个世界：协作式负数 vs 抢占式非负

## 这一篇讲什么

Zephyr 优先级一句话：**数字越小越高（和中断优先级同向），
并且按符号分成两个世界——负数是协作式线程，非负是抢占式线程。**
协作式线程是 FreeRTOS 没有的概念，也是 Zephyr 调度设计的最大特色。

## 优先级全景图

```
数值：  -16 …… -1      0      1 …… 14
        ├──协作式──┤  ├────抢占式────┤
        （coop）      （preempt）
        高 ◄──────── 优先级 ────────► 低
```

- **协作式（负数，-16~-1）**：一旦跑起来，**任何抢占式线程都抢不走它**，
  直到它自己阻塞/让出。只有两个东西能打断它：① 它自己让；② 中断。
- **抢占式（非负，0~14 常见）**：FreeRTOS 式的世界——
  数值小的高优先，高的就绪立即抢占低的。

默认范围由 Kconfig 定（`CONFIG_NUM_COOP_PRIORITIES` / `CONFIG_NUM_PREEMPT_PRIORITIES`），
便捷宏：`K_PRIO_COOP(n)` = -n-1，`K_PRIO_PREEMPT(n)` = n。

## 与 FreeRTOS 的三层对照

| | FreeRTOS | Zephyr |
|---|---|---|
| 数字方向 | 大 = 高 | **小 = 高**（与 NVIC 中断优先级同向！） |
| 协作式 | 只有全局开关（关抢占，全内核协作） | **按线程分**：负数即协作，一等公民 |
| 时间片 | 同优先级每 tick 轮转（可开关） | 同优先级轮转需配 `CONFIG_TIMESLICING`（默认关！） |

第二行值得停下来体会：FreeRTOS 里"数字大=高"，Zephyr 里"数字小=高"——
**从 FreeRTOS 过来的人第一次配 Zephyr 优先级几乎必配反**。
Zephyr 的理由：和中断优先级方向一致，整个系统一套"小=急"的直觉。

第三行是默认行为陷阱：Zephyr **默认不做时间片轮转**——
同优先级的两个抢占式线程，一个不让出，另一个**永远饿死**。
想要 FreeRTOS 那种同优先级公平轮转，得在 prj.conf 里开
`CONFIG_TIMESLICING=y` 并给 `CONFIG_TIMESLICE_SIZE`。

## 协作式线程的正经用途

既然协作式"占住不放"，要它干嘛？

1. **临界小任务**：一段不能被抢占的初始化/校准代码，
   用协作式跑完即退出——比关中断温柔（中断照走），比互斥量简单；
2. **驱动/协议栈内部线程**：网络栈、BLE 栈的内部线程多是协作式——
   协议处理到一半被应用线程抢占会引发状态机复杂度爆炸；
3. **优先级天花板的妙用**：协作式任何一级都高于所有抢占式——
   "必须最先跑完"的东西放负数，语义一目了然。

代价同样明显：**协作式线程里写死循环 = 整个抢占式世界停摆**
（连 idle 都是抢占式的，见 4.5）。协作式线程的纪律比 FreeRTOS 的
"高优先级要常阻塞"更严。

## 一图总结调度决策

```
有协作式线程就绪？ ──是──► 跑数值最小的那个协作式（抢占式全体等待）
     │否
有抢占式线程就绪？ ──是──► 跑数值最小的；同级且开了 TIMESLICING 才轮转
     │否
idle
```

## 要点回顾

1. Zephyr 优先级**小=高**（与 NVIC 同向，与 FreeRTOS 反向）——移植时最易配反的点。
2. 负数 = 协作式：不被抢占式线程抢占，用于临界小任务与协议栈内部。
3. **时间片默认关**：同优先级公平轮转要显式开 CONFIG_TIMESLICING。

<details>
<summary>Q1：协作式线程之间会互相抢占吗？</summary>

会。协作式只免疫"抢占式线程的抢占"；更高（数值更小）的协作式线程就绪，
照样立即换人。所以严格说：协作式线程只被 ① 更高协作式 ② 中断 打断。

</details>

<details>
<summary>Q2：工作队列（system workqueue）跑在什么优先级？</summary>

系统 workqueue 是**协作式线程**（默认 K_PRIO_COOP(…)）——
这就是"work 项里别磨洋工"的结构性原因：它卡着，所有抢占式应用线程陪着等。
长活要么建自己的 workqueue（可配优先级），要么丢给专用线程。
（workqueue 详见 [ch05](../05-ipc-workqueues/README.md)。）

</details>
