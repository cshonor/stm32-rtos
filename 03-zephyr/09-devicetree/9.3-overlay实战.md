## 这一篇讲什么

板级 dts 已带 led0（PA5）和 sw0（PC13）。这一篇做两件事：
**① overlay 追加外接 LED（PB0）和外接按钮；② 改 console（控制台：系统打日志、敲命令用的那个串口）波特率**——
体会 overlay"追加新节点"和"覆盖旧属性"两种姿势。

## 先用人话说一遍（新手铺垫）

你的实验接线（面包板上插一颗 LED、一个按钮）是**你这个项目的私事**，
而板级 dts 是**所有用这块板的人共享的公共资产**。
直接把私事写进公共资产，别人编自己的工程时就会被你的接线污染——
所以 Zephyr 给每个工程留了一张"附加条款"：overlay。

类比租房装修：房东的房本（SoC dtsi + 板级 dts）你不能改，
但你可以在**自己的租约附加条款**（app.overlay）里写"我在阳台
加一个花架"（追加新节点）、"我把客厅灯换成 115200 流明"
（覆盖 `&usart2` 的波特率）。退租（删掉 overlay）房子恢复原样，
房本一个字没动。合并规则对应"附加条款与房本冲突时，以附加条款为准"
——这就是 9.1 说的"后写的赢"。

动手后记住一条验证纪律：**不猜，看产物**。overlay 写没写对，
打开 `build/zephyr/zephyr.dts`（合并结果）搜你的节点名，
一秒钟见分晓——比盯着源码排查快得多。

| 术语 | 一句话解释 |
|---|---|
| `GPIO_ACTIVE_HIGH/LOW` | 有效电平标志：高电平算"点亮"还是低电平算"点亮"，写在 gpios 属性里 |
| `GPIO_PULL_UP` | 上拉电阻标志：按钮不按时引脚被拉到高电平，按下降沿触发 |
| `#gpio-cells` | 控制器的"字段个数声明"：决定 gpios 属性里每个引用要写几个数 |
| `boards/<板名>.overlay` | 只对指定板生效的 overlay：板相关改动的推荐存放位置 |
| `/delete-node/` | overlay 的删除语法：移除板级 dts 里已有的节点，少用，优先用 status="disabled" |

## 姿势一：追加新节点

工程根建 `app.overlay`（或 `boards/nucleo_f103rb.overlay`，只对这块板生效）：

```
/ {
    myleds {
        compatible = "gpio-leds";     /* 复用 Zephyr 自带 binding */
        ext_led0: ext_led_0 {
            gpios = <&gpiob 0 GPIO_ACTIVE_HIGH>;  /* 控制器 + 引脚 + 极性 */
            label = "External LED";
        };
    };

    mybuttons {
        compatible = "gpio-keys";
        ext_btn0: ext_button_0 {
            gpios = <&gpioc 1 (GPIO_ACTIVE_LOW | GPIO_PULL_UP)>;  /* 按钮常见配方 */
            label = "External Button";
        };
    };

    aliases { ext-led = &ext_led0; };  /* 起别名，应用层引用 */
};
```

逐行拆：`compatible = "gpio-leds"` 声明按该 binding 解读（自带，无需驱动）；
`&gpiob 0 GPIO_ACTIVE_HIGH` 三个字段的个数由控制器的 `#gpio-cells` 决定；
flags 可按位或。

应用侧（[9.2](9.2-DT宏族与设备模型.md) 三层读法）：

```c
static const struct gpio_dt_spec ext_led =
    GPIO_DT_SPEC_GET(DT_ALIAS(ext_led), gpios);
gpio_pin_configure_dt(&ext_led, GPIO_OUTPUT_INACTIVE);
gpio_pin_set_dt(&ext_led, 1);
```

**全程没出现一个地址**——和 [01-stm32 手写法](../../01-stm32/04-numbers-and-bitops/4.12-用位操作控制内存映射IO寄存器.md) 的世界观差异。

## 姿势二：覆盖旧属性

```
&usart2 { current-speed = <115200>; };   /* 覆盖板级值 */
&gpiob  { status = "okay"; };            /* dtsi 默认 disabled，用前必 okay */
```

`&label { ... }` 引用既有节点：**同名属性覆盖，新属性追加**。
常见翻车点：用了 `&gpiob` 的引脚却忘了 okay gpiob 控制器本身——
构建不报错，运行时 `device_is_ready` 返回 false。

## overlay 查找与验证

| 文件 | 生效范围 |
|---|---|
| `boards/<板名>.overlay` | 只对这块板（**推荐**，板相关改动收敛于此） |
| `app.overlay` | 对所有板生效 |
| `-DDTC_OVERLAY_FILE=...` | 命令行显式指定（调试用） |

验证叠加结果**不猜，看产物**：`build/zephyr/zephyr.dts` 是合并后的完整 dts，
`build/zephyr/include/generated/devicetree_generated.h` 是最终宏。
overlay 没生效？先查这两个文件里有没有你的节点。

## 该写 overlay 还是不该

| 场景 | 做法 |
|---|---|
| 试验性外接硬件、应用特有接线 | overlay（属于应用） |
| 板载硬件（LED、Flash 分区） | 属于板级 dts，别用 overlay 打补丁 |
| 改软件功能（shell（串口里敲命令的小系统）、日志级别） | 去 prj.conf（见 [9.1](9.1-dts语法与三层叠加.md) 分工表） |

## 要点回顾

1. 两种姿势：`/` 下追加新节点，`&label` 覆盖/追加既有节点属性。
2. 用某控制器的引脚，必须先 okay 控制器——最常见运行时翻车。
3. 板相关改动优先 `boards/<板名>.overlay`；生效与否看 build/ 产物，不猜。
4. gpios 三元组替代手写"基址+偏移+位掩码"。

<details>
<summary>Q1：compatible = "gpio-leds" 需要驱动吗？</summary>

不需要。gpio-leds / gpio-keys 是"约定俗成的容器 binding"，
不生成设备，纯靠应用 GPIO_DT_SPEC_GET 读属性自己操作。
对照 "st,stm32-spi" 这种才真有驱动匹配、生成 struct device（见 [9.4](9.4-SPI-I2C节点解剖.md)）。

</details>

<details>
<summary>Q2：overlay 里能删节点/属性吗？</summary>

能但少用：`/delete-node/ &xxx;`、`/delete-property/ xxx;`。
更常见替代是 `status = "disabled"`——效果等同"不存在"且可重新打开；
删语法留给板级 dts 写死、应用确定不要的东西。

</details>

## 坑点速查

| 坑点 | 书 / 常识怎么说 | 实际是什么 |
|---|---|---|
| 用了 `&gpiob` 的引脚就能用 | 引脚写了就生效 | 控制器本身忘 okay：构建不报错，运行时 `device_is_ready` 返回 false |
| overlay 没生效就盯源码排查 | 逐行读自己的 overlay | 不猜，看产物：`build/zephyr/zephyr.dts` 搜节点名，一秒见分晓 |
| `compatible = "gpio-leds"` 要写驱动 | compatible 就得配驱动 | 它是容器 binding，不生成设备，应用 `GPIO_DT_SPEC_GET` 自己读属性 |
| 不想要的节点用 `/delete-node/` | 删掉最干净 | 优先 `status = "disabled"`——效果等同且可重新打开，删语法少用 |

## 代码自测

_注：本节示例按本篇正文语义编写，未在本仓库环境实跑，仿真验证见「验证路径」。_

演示 overlay 两种姿势（追加 + 覆盖）与应用侧读法：

```dts
/* boards/nucleo_f103rb.overlay */
&usart2 { current-speed = <115200>; };   /* 姿势二：覆盖旧属性 */
&gpiob  { status = "okay"; };            /* 用 PB0 前必 okay 控制器 */

/ {
    myleds {
        compatible = "gpio-leds";
        ext_led0: ext_led_0 {
            gpios = <&gpiob 0 GPIO_ACTIVE_HIGH>;
            label = "External LED";
        };
    };
    aliases { ext-led = &ext_led0; };    /* 姿势一：追加新节点 + 别名 */
};
```

```c
/* main.c：全程无地址 */
static const struct gpio_dt_spec ext_led =
    GPIO_DT_SPEC_GET(DT_ALIAS(ext_led), gpios);

void main(void)
{
    if (!device_is_ready(ext_led.port)) {
        return;             /* 忘 okay gpiob 时在这里翻车 */
    }
    gpio_pin_configure_dt(&ext_led, GPIO_OUTPUT_INACTIVE);
    gpio_pin_set_dt(&ext_led, 1);
}
```

**预期现象**：

- `build/zephyr/zephyr.dts` 里搜到 `ext_led0`、波特率 115200、gpiob okay；
- 应用跑起来后 PB0 拉高（外接 LED 亮）；
- 故意删掉 `&gpiob { status = "okay"; };` 重编：构建仍过，运行时 `device_is_ready` 返回 false。

**验证路径**：`west build -b nucleo_f103rb`，查 `build/zephyr/zephyr.dts` 后烧真板（或纯看产物验证叠加）。

**常见翻车点**：

- 改动板相关却写进 `app.overlay`（对所有板生效）——板相关改动收敛到 `boards/<板名>.overlay`；
- `gpios` 字段个数写错——个数由控制器 `#gpio-cells` 决定，对照板级 dts 里 led0 的写法抄。
