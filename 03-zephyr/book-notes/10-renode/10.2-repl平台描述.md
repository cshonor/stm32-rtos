## 这一篇讲什么

.repl（REnode PLatform）干的事和 devicetree（[ch09](../09-devicetree/README.md)）
惊人地像：**用文本声明"板上有哪些外设、占什么地址、中断怎么连"。**
这一篇给最小骨架，再配 .resc 脚本把 zephyr.elf 跑起来。

## .repl 最小骨架

```
cpu: CPU.CortexM @ sysbus
    cpuType: "cortex-m3"
    nvic: nvic

nvic: IRQControllers.NVIC @ sysbus 0xE000E000
    -> cpu@0

flash: Memory.MappedMemory @ sysbus 0x08000000
    size: 0x20000          // 128K（F103RB）

sram: Memory.MappedMemory @ sysbus 0x20000000
    size: 0x5000           // 20K——和 01-stm32 链接脚本里的数一致

usart2: UART.STM32_UART @ sysbus 0x40004400
    -> nvic@38             // IRQ38：手册里的 USART2 中断号

gpioPortA: GPIOPort.STM32_GPIOPort @ sysbus 0x40010800
```

和 dts 逐条对照（学过 [9.1](../09-devicetree/9.1-dts语法与三层叠加.md) 秒懂）：

| .repl | dts 对应 | 含义 |
|---|---|---|
| `UART.STM32_UART` | `compatible = "st,stm32-usart"` | 用哪个外设**模型**（C# 类） |
| `@ sysbus 0x40004400` | `reg = <0x40004400 ...>` | 基址（还是手册那个数） |
| `-> nvic@38` | `interrupts = <38 ...>` | 中断线连接 |
| `size: 0x20000` | `reg = <... 0x20000>` | 窗口长度 |

**本质仍然是"基址 + 偏移 + 中断号"**——和 01-stm32 手写宏、
和 dts 的 reg/interrupts，三处写的是同一份手册数据。
区别只在消费者：手写宏给编译器，dts 给 Zephyr 构建系统，.repl 给 Renode。

## .resc 脚本：把 elf 跑起来

.resc（REnode SCript）是 Monitor 命令的批处理：

```
# hello.resc
mach create                                     # 建虚拟机
machine LoadPlatformDescription @hello.repl     # 装入平台
sysbus LoadELF @build/zephyr/zephyr.elf         # 按段加载 elf
showAnalyzer sysbus.usart2                      # UART2 接终端窗口
start                                           # 开跑
```

运行 `renode hello.resc`，终端窗口里看到 `Hello World!`——
和真板接串口看到的**同一份固件输出**，只是这次的 UART 是 C# 模型。

## UART 交互：不止输出，还能输入

`showAnalyzer` 打开的窗口是双向的：固件 printk/shell 输出显示在里面，
你敲的字符作为 UART RX 送进模型——**Zephyr shell 在 Renode 里真能交互**
（tab 补全、命令历史都有）。对无板期验证 `CONFIG_SHELL` 功能尤其值钱。

## 最小 .repl 要画哪些东西

跑通 hello world 级别，真正必需的只有四样：

| 外设 | 为什么必需 |
|---|---|
| cpu + nvic | 没有核和中断控制器，什么都没有 |
| flash + sram | elf 的 .text/.data 要有地方放 |
| 一个 UART | printk 出口（usart2，对齐板级 dts 的 zephyr,console） |
| SysTick | 内核 tick 源（CortexM 模型自带，不用单独声明） |

LED、按钮、SPI、I2C **用到才加**——访问未建模地址只会让 Renode 告警，
不会把仿真弄崩，迭代着补即可。

## 要点回顾

1. .repl = Renode 版 dts：类型@基址 + 中断连线，数据与手册/dts/手写宏同源。
2. .resc 四步：mach create → LoadPlatformDescription → LoadELF → showAnalyzer + start。
3. UART analyzer 双向交互，Zephyr shell 可真实操作。
4. 最小平台只要 cpu/nvic/flash/sram/uart；外设用到才加，访问未建模地址只告警。

<details>
<summary>Q2：仿真里程序跑得比真板快还是慢？</summary>

不一定，也**不重要**：Renode 默认用虚拟时间，墙钟速度取决于宿主机。
关键是 [10.1](10.1-Renode与QEMU定位差异.md) 说的局限——虚拟时间和真板时序
无对应关系，"延时 100ms 的灯闪"在仿真里闪多快都不能当时序证据。

</details>
