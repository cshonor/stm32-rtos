## 这一篇讲什么

没板子也想跑 zephyr.elf，有两条路：**Zephyr 自带的 `qemu_cortex_m3`** 和
**Antmicro 的 Renode**。两者经常被混为一谈，其实定位不同——
QEMU 仿真的是"一颗核"，Renode 仿真的是"一整块板"。

## 定位差异一图流

```
QEMU (qemu_cortex_m3)                Renode
┌─────────────────┐                  ┌──────────────────────────┐
│ Cortex-M3 内核   │                  │ 文本描述的平台 (.repl)：  │
│ + 极简外设模型   │                  │  Cortex-M 内核            │
│ (UART/SysTick)  │                  │  + UART/SPI/I2C/GPIO/RTC │
└─────────────────┘                  │  + 外设之间的连线         │
  "能跑指令、能 printk"               │  + 多板互联/网络拓扑      │
                                     └──────────────────────────┘
                                       "整板、整系统、甚至多机"
```

| 面 | QEMU (`qemu_cortex_m3`) | Renode |
|---|---|---|
| 仿真单位 | 指令集 + 少数外设 | **整块板**（SoC + 外设 + 连线），可多机 |
| 板子怎么描述 | 写死在 QEMU 源码里 | **.repl 文本**，用户可改可写 |
| 外设模型 | 少（够跑 hello 就行） | 多（UART/SPI/I2C/GPIO/以太网…，C# 实现） |
| 自动化测试 | 自己包脚本 | **内建 Robot Framework 集成**，官方 CI 方案 |
| 交互调试 | gdb stub | Monitor 命令行（类 GDB + 外设检查）+ gdb stub |
| Zephyr 支持 | `west build -b qemu_cortex_m3 -t run` | `west build -t run`（部分板卡）或手动 renode 命令 |

## 各自适合验什么（选型表）

| 要验的东西 | 选谁 | 理由 |
|---|---|---|
| 内核机制（调度、IPC、栈溢出） | **QEMU** | 只要核能跑指令就够，启动快、零配置 |
| printk/console 冒烟测试 | 都行 | QEMU 更省事 |
| **外设驱动逻辑**（SPI 读写、GPIO 中断） | **Renode** | QEMU 根本没有那些外设模型 |
| 无板期复刻目标板行为 | **Renode** | .repl 可以照着真板外设清单写 |
| CI 里跑 RTOS 回归测试 | **Renode** | Robot 断言 UART 输出/外设状态，官方生态成熟 |
| 多节点通信（BLE/网络栈雏形） | **Renode** | 支持多机互联，QEMU 单机 |

一句话记忆：**QEMU 验"软件逻辑"，Renode 验"软件+硬件接口的逻辑"。**

## 为什么 CI 几乎必选 Renode

CI 环境的三条硬约束，Renode 恰好全中：

1. **确定性**：同一份 elf + 同一份 .resc 脚本，每次跑出的 UART 输出可断言——
   真板的抖动、接触不良在 CI 里是噪声源；
2. **可编程观测**：Monitor 命令能直接读外设寄存器/引脚电平，
   断言"点了 LED"不用接示波器；
3. **零硬件库存**：GitHub Actions 容器里 `renode` 一条命令，
   不用维护一架子开发板 + USB  hub。

Zephyr 官方和 Antmicro 自己的 CI 都大量用 Renode 跑 samples 回归——
这是它"一等公民"地位的来源。

## 局限：仿真不是真板（诚实清单）

| 局限 | 影响 |
|---|---|
| **时序不真实** | 仿真时钟和真板时钟无对应关系；竞态、时序敏感的 bug 仿真里可能永不出现 |
| **外设模型不全** | 某颗传感器的怪癖（上电时序、边界寄存器行为）模型里往往没实现 |
| **模型可能有 bug** | 仿真通过 ≠ 真板通过；仿真失败也可能是模型错而非你的错 |
| **模拟外设 ≠ 模拟电气** | 上拉/下拉、驱动能力、信号完整性这些仿真一概不管 |

纪律：**Renode 是"第一遍过滤器"，不是"最终验收"。**
本仓有 F103 真板，最终结论永远以真板为准（仿真路径优先级低，见章 README 技术债）。

## 要点回顾

1. QEMU 仿真指令集+极简外设，Renode 仿真整板（.repl 可编程描述）——前者验软件逻辑，后者验软硬件接口。
2. CI 选 Renode 因为确定性、可编程观测、零硬件库存。
3. 时序不真实 + 外设模型不全：仿真是第一遍过滤器，最终验收在真板。

<details>
<summary>Q1：Renode 能仿真我手里这块板吗？</summary>

看两点：① SoC 的内核 Renode 都支持（Cortex-M/A 全系）；
② 外设模型——去 Renode 源码的 platforms/cpus/ 找有没有现成 .repl，
以及 peripheral 模型目录里有没有你的外设。
ST 的 STM32F1/F4/L4 等常见型号社区已有平台文件；
冷门外设可能要自己写 C# 模型（门槛不低，这也是本仓优先真板的原因之一）。

</details>

<details>
<summary>Q2：Renode 里能单步调试吗？</summary>

能，而且比真板自由：内建 Monitor 支持断点/单步/查看任意外设状态，
也提供 gdb stub 可以接 arm-none-eabi-gdb（流程和真板 ST-Link 调试几乎一样，
参考 openocd+gdb 的肌肉记忆）。**而且没有"调试器占用 SWD 引脚"这类真板烦恼。**

</details>
