## 这一篇讲什么

板级 dts 已带 led0（PA5）和 sw0（PC13）。这一篇做两件事：
**① overlay 追加外接 LED（PB0）和外接按钮；② 改 console 波特率**——
体会 overlay"追加新节点"和"覆盖旧属性"两种姿势。

## 姿势一：追加新节点

工程根建 `app.overlay`（或 `boards/nucleo_f103rb.overlay`，只对这块板生效）：

```
/ {
    myleds {
        compatible = "gpio-leds";     /* 复用 Zephyr 自带 binding */
        ext_led0: ext_led_0 {
            gpios = <&gpiob 0 GPIO_ACTIVE_HIGH>;  /* 控制器 + 引脚 + 极性 */
            label = "External LED";
        };
    };

    mybuttons {
        compatible = "gpio-keys";
        ext_btn0: ext_button_0 {
            gpios = <&gpioc 1 (GPIO_ACTIVE_LOW | GPIO_PULL_UP)>;  /* 按钮常见配方 */
            label = "External Button";
        };
    };

    aliases { ext-led = &ext_led0; };  /* 起别名，应用层引用 */
};
```

逐行拆：`compatible = "gpio-leds"` 声明按该 binding 解读（自带，无需驱动）；
`&gpiob 0 GPIO_ACTIVE_HIGH` 三个字段的个数由控制器的 `#gpio-cells` 决定；
flags 可按位或。

应用侧（[9.2](9.2-DT宏族与设备模型.md) 三层读法）：

```c
static const struct gpio_dt_spec ext_led =
    GPIO_DT_SPEC_GET(DT_ALIAS(ext_led), gpios);
gpio_pin_configure_dt(&ext_led, GPIO_OUTPUT_INACTIVE);
gpio_pin_set_dt(&ext_led, 1);
```

**全程没出现一个地址**——和 [01-stm32 手写法](../../../01-stm32/book-notes/04-numbers-and-bitops/4.12-用位操作控制内存映射IO寄存器.md) 的世界观差异。

## 姿势二：覆盖旧属性

```
&usart2 { current-speed = <115200>; };   /* 覆盖板级值 */
&gpiob  { status = "okay"; };            /* dtsi 默认 disabled，用前必 okay */
```

`&label { ... }` 引用既有节点：**同名属性覆盖，新属性追加**。
常见翻车点：用了 `&gpiob` 的引脚却忘了 okay gpiob 控制器本身——
构建不报错，运行时 `device_is_ready` 返回 false。

## overlay 查找与验证

| 文件 | 生效范围 |
|---|---|
| `boards/<板名>.overlay` | 只对这块板（**推荐**，板相关改动收敛于此） |
| `app.overlay` | 对所有板生效 |
| `-DDTC_OVERLAY_FILE=...` | 命令行显式指定（调试用） |

验证叠加结果**不猜，看产物**：`build/zephyr/zephyr.dts` 是合并后的完整 dts，
`build/zephyr/include/generated/devicetree_generated.h` 是最终宏。
overlay 没生效？先查这两个文件里有没有你的节点。

## 该写 overlay 还是不该

| 场景 | 做法 |
|---|---|
| 试验性外接硬件、应用特有接线 | overlay（属于应用） |
| 板载硬件（LED、Flash 分区） | 属于板级 dts，别用 overlay 打补丁 |
| 改软件功能（shell、日志级别） | 去 prj.conf（见 [9.1](9.1-dts语法与三层叠加.md) 分工表） |

## 要点回顾

1. 两种姿势：`/` 下追加新节点，`&label` 覆盖/追加既有节点属性。
2. 用某控制器的引脚，必须先 okay 控制器——最常见运行时翻车。
3. 板相关改动优先 `boards/<板名>.overlay`；生效与否看 build/ 产物，不猜。
4. gpios 三元组替代手写"基址+偏移+位掩码"。

<details>
<summary>Q1：compatible = "gpio-leds" 需要驱动吗？</summary>

不需要。gpio-leds / gpio-keys 是"约定俗成的容器 binding"，
不生成设备，纯靠应用 GPIO_DT_SPEC_GET 读属性自己操作。
对照 "st,stm32-spi" 这种才真有驱动匹配、生成 struct device（见 [9.4](9.4-SPI-I2C节点解剖.md)）。

</details>

<details>
<summary>Q2：overlay 里能删节点/属性吗？</summary>

能但少用：`/delete-node/ &xxx;`、`/delete-property/ xxx;`。
更常见替代是 `status = "disabled"`——效果等同"不存在"且可重新打开；
删语法留给板级 dts 写死、应用确定不要的东西。

</details>
