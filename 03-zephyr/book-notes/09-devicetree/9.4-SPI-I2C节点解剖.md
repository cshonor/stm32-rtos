## 这一篇讲什么

LED/按钮是"应用自己读属性"，SPI/I2C 是**真驱动链路**：
dts 节点 → compatible → binding → 驱动 → struct device → 总线 API。
这一篇逐环拆开，讲清总线父子关系和 SPI 特有的 cs-gpios。

## 一条完整的匹配链

"在 SPI1 上挂一颗 BME280"的 overlay：

```
&spi1 {
    status = "okay";                    /* ① 先开控制器 */
    pinctrl-0 = <&spi1_sck_pa5 &spi1_miso_pa6 &spi1_mosi_pa7>;  /* ② 引脚复用 */
    pinctrl-names = "default";
    cs-gpios = <&gpioa 4 GPIO_ACTIVE_LOW>;                      /* ③ 片选 */

    bme280@0 {                          /* ④ 子节点：挂在 spi1 总线上 */
        compatible = "bosch,bme280";
        reg = <0>;                      /* SPI 上 reg = 片选索引（第 0 个 cs） */
        spi-max-frequency = <4000000>;
        status = "okay";
    };
};
```

匹配链逐环：

```
compatible = "bosch,bme280"
  → bindings yaml（属性 schema）
  → 驱动里 DT_DRV_COMPAT = bosch_bme280 + CONFIG_BME280=y（9.1 分工表）
  → DEVICE_DT_INST_DEFINE 生成 struct device → 应用 DEVICE_DT_GET 拿指针
```

**compatible 是链上唯一"人写的字符串"**，写错一个字母，
构建期 binding 检查直接报错。

## 总线父子关系：子节点 = "挂在这条总线上"

| | SPI | I2C |
|---|---|---|
| 父节点 | `&spi1`（控制器） | `&i2c1`（控制器） |
| 子节点 `reg` | **片选索引** | **7 位从机地址**（如 `<0x76>`） |
| 节点名后缀 | `bme280@0` | `bme280@76` |
| 寻址谁负责 | 驱动收发前拉对应 cs | 控制器硬件按地址发 START |

I2C 对照写法：

```
&i2c1 {
    status = "okay";
    pinctrl-0 = <&i2c1_scl_pb8 &i2c1_sda_pb9>;
    pinctrl-names = "default";
    bme280@76 { compatible = "bosch,bme280"; reg = <0x76>; status = "okay"; };
};
```

**同一份驱动两种挂法都支持**——驱动对 SPI/I2C 各注册一份 bus ops，
dts 写在哪条总线下就走哪条通路。传感器换接口，应用代码零改动。

## cs-gpios：SPI 的 Zephyr 特色坑

- 写在**控制器**节点上，是数组（可多路片选）；子节点 `reg = <0>` 指第 0 个；
- 极性（`GPIO_ACTIVE_LOW`）写在 cs-gpios 里，驱动收发时自动拉/放；
- 对照裸机（01-stm32）手写 `GPIOA->BSRR = 1<<4`：DT 时代由驱动按声明自动完成。

应用侧读法：

```c
static const struct spi_dt_spec spi_dev =
    SPI_DT_SPEC_GET(DT_NODELABEL(bme280), SPI_WORD_SET(8) | SPI_TRANSFER_MSB, 0);
spi_write_dt(&spi_dev, &buf);
```

## 原书怎么说 / 实际是什么

| 原书怎么说 | 实际是什么（Zephyr 3.x） |
|---|---|
| 引脚复用写成散装 pinmux 节点 | 现行统一 **pinctrl**：`pinctrl-0` 引用 `pinctrl/soc/` 预定义引脚组 |
| 驱动代码里写死片选 GPIO | 现行强制 cs-gpios 声明在 dts，驱动只读 |
| `spi_write(dev, ...)` 传裸指针 | 推荐 `spi_write_dt(&spec, ...)`，片选/频率由 spec 携带 |

## 要点回顾

1. 匹配链：compatible → binding → DT_DRV_COMPAT → Kconfig → 生成设备——缺一环都点不亮。
2. 子节点挂总线：SPI reg 是片选索引，I2C reg 是 7 位地址；同一驱动可双挂。
3. cs-gpios 写在控制器上、是数组；片选拉放驱动自动完成，告别手写 BSRR。
4. 引脚复用走 pinctrl 预定义引脚组，不再散装 pinmux。

<details>
<summary>Q1：dts 里 okay 了 spi1，设备还是不在？</summary>

按链排查：① 控制器 pinctrl 引脚组；② CONFIG_SPI=y；③ 子节点 compatible 拼写；
④ 传感器 CONFIG_BME280=y。四个开关分属 dts/Kconfig 两边——
"两个都要对，驱动才真的进固件"（9.1）。

</details>

<details>
<summary>Q2：两个同型号传感器怎么写？</summary>

写两个子节点，reg 不同（不同 cs 或不同 I2C 地址），各打各的 nodelabel。
驱动侧 DT_INST_FOREACH_STATUS_OKAY 对每个 okay 实例生成独立 config/data——
**一份驱动代码服务 N 个实例**，这是设备模型对比裸机"一份驱动死磕一个硬件"的核心收益。

</details>
