## 这一篇讲什么

Zephyr 的 thread 和 FreeRTOS 的 task 是**同一个概念的两个名字**：
一个独立执行流 = 一份 CPU 现场 + 一个栈 + 一个内核控制块（内核记录这个执行流状态的结构体，调度器认人全靠它）。
这一篇把三个组成部分摆清楚，重点在 Zephyr 特有的地方。

## 先用人话说一遍（新手铺垫）

线程听起来玄，拆开来就是"一个打工人上班需要的三样东西"：
**工牌**（控制块 `k_thread`，调度器认人全靠它）、
**工作台**（栈，放干到一半的活：局部变量、函数调用现场）、
**手头在做的事**（CPU 现场：寄存器值，换班时存起来、回来时恢复）。
三样凑齐，一个执行流就成立了——本篇开头那张图说的就是这个。

真正值得停一秒的是 Zephyr 的一个"宽容"：FreeRTOS 只收**长工**——
任务函数敢返回就是事故；Zephyr 也收**钟点工**——
线程函数干完 return，内核帮你办离职手续（终止线程、回收现场）。
所以"初始化完就没用的一次性线程"在 Zephyr 里是正经写法，
不用再包一层 `for(;;)` 装成长工。

栈的部分记住一个审美差异就够：FreeRTOS 默认从堆里切栈（像现租工位），
Zephyr 主推编译期定死的静态栈（像工位数量写进大楼图纸）——
好处是链接期就能在 map 文件里点名查每个栈，
"栈会不会炸"从运行时惊喜变成链接期事实。

| 术语 | 一句话解释 |
|---|---|
| 栈哨兵（STACK_SENTINEL） | 栈底放一个已知魔数，调度切换时检查它被改没——改了说明栈溢出过 |
| MPU | 存储保护单元：可给栈底划硬件保护区，越界当场触发异常（比哨兵发现得早） |
| 栈水位线 | 运行时查询"这个栈历史最深用到哪"：给栈定大小从猜变成量 |
| `K_THREAD_STACK_DEFINE` | 静态定义线程栈的宏：编译期分配、自动处理对齐和 MPU 取整 |

## 线程的三件家当

```
struct k_thread {          ← TCB（控制块），内核调度/排队都引用它
    /* 现场保存区、优先级、状态、各等待队列节点…… */
};
+ 一个栈（K_THREAD_STACK 或 k_thread_stack_alloc 分配）
+ 一个入口函数：void entry(void *p1, void *p2, void *p3)
```

与 FreeRTOS 逐项对照：

| | FreeRTOS | Zephyr |
|---|---|---|
| 控制块 | TCB_t | `struct k_thread` |
| 入口原型 | `void f(void *)` 一个参数 | `void f(void*, void*, void*)` **三个参数** |
| 栈来源 | pvPortMalloc（heap_4） | 静态 K_THREAD_STACK / 动态 k_thread_stack_alloc |
| 铁律"永不返回" | 返回 = 事故 | **可以返回**——Zephyr 允许线程函数返回，线程就此终止 |

最后一行是**世界观差异**：Zephyr 线程函数返回是**合法的结束方式**
（内核帮你收尾），FreeRTOS 返回是事故。当然长期驻留的服务线程
照样写 `for(;;)`，但"干完就退出"的一次性线程在 Zephyr 里是正经用法。

## 栈：Zephyr 把"静态分配"做成了默认美学

FreeRTOS 里栈从 ucHeap 动态切（[ch02](../../../02-freertos/book-notes/02-heap-memory/README.md)），
Zephyr 主推**静态分配**：

```c
K_THREAD_STACK_DEFINE(my_stack, 1024);   /* 编译期定死的 1KB 栈，进 .bss */
```

好处和裸机静态分配一脉相承（[ch13](../../../01-stm32/book-notes/13-dynamic-memory/README.md)）：
大小链接期可见、无碎片、无分配失败路径；`nm`（列出可执行文件符号表的命令行工具） / 链接 map 里直接查得到每个栈的位置。
动态分配（`k_thread_stack_alloc`）留给了真正需要的场景
（且要 CONFIG_DYNAMIC_THREAD，F103 的 20K RAM 上基本不会开）。

## 栈溢出防护的家底

Zephyr 在栈保护上的配置项（写 prj.conf 时选）：

| 配置 | 机制 | 开销 |
|---|---|---|
| `CONFIG_STACK_SENTINEL` | 栈底放一个魔数，切换时检查被改没 | 极小，只查切换点 |
| `CONFIG_HW_STACK_PROTECTION` | 用 MPU 在栈底划保护区，越界当场 MemManage 异常（Cortex-M 的存储保护异常：非法访问内存立即触发） | 需 MPU（F103 有） |
| `CONFIG_THREAD_STACK_INFO` | 允许运行时查询栈用量（水位线） | 小 |

对照 FreeRTOS：方法≈`configCHECK_FOR_STACK_OVERFLOW` 的 1/2，
MPU 方案 FreeRTOS 也有（FreeRTOS-MPU 是单独分支，Zephyr 是主线内置）。

## 与 LDD- 侧对照

Linux 线程 = task_struct + 内核栈 + 用户栈；Zephyr 无线程/内核态分离，
`k_thread` 一个结构包打天下——和 FreeRTOS 一样，**MCU RTOS 没有双栈分家，
MSP/PSP（Cortex-M 的两根硬件栈指针：中断用 MSP，线程用 PSP）的硬件双栈（ch20.1）是中断隔离用的，不是权限隔离用的**。

## 要点回顾

1. Zephyr thread ≈ FreeRTOS task：控制块 + 栈 + 入口函数；入口收**三个** void*。
2. 世界观差异：Zephyr 线程函数**可以返回**（正常终止），FreeRTOS 返回是事故。
3. Zephyr 主推静态栈（K_THREAD_STACK_DEFINE），栈保护有 sentinel/MPU/水位三档。

<details>
<summary>Q1：线程函数能返回，那"干完活还想保留结果"怎么办？</summary>

返回值没地方放（入口原型是 void），结果走共享变量 + 同步对象
（k_sem / k_msgq），或者让别的线程 `k_thread_join` 等它结束后再读结果。
`k_thread_join` 见 [4.6](4.6-生命周期与栈检测.md)。

</details>

<details>
<summary>Q2：K_THREAD_STACK_DEFINE 的栈有对齐要求吗？</summary>

有，宏内部已处理（`K_THREAD_STACK_LEN`/`__aligned`）。
但**自己定义字节数组当栈**是常见翻车点：MPU 栈保护要求栈大小是 2 的幂
（F1 的 MPU 区域粒度限制），K_THREAD_STACK_DEFINE 会自动向上取整，
裸数组不会。要栈保护就老实走宏。

</details>

## 坑点速查

| 坑点 | 书 / 常识怎么说 | 实际是什么 |
|---|---|---|
| 线程函数永不返回 | FreeRTOS 铁律：任务函数返回 = 事故 | Zephyr 里 return 是**合法终止**，内核帮你收尾；一次性线程不用再包 `for(;;)` |
| 入口一个参数 | FreeRTOS 入口 `void f(void *)` | Zephyr 入口 `void f(void*, void*, void*)`，**三个**参数 |
| 自己定义字节数组当栈 | 栈不就是一块内存，数组也能用 | MPU 栈保护要求栈大小是 2 的幂，裸数组不会向上取整——要栈保护就老实走 `K_THREAD_STACK_DEFINE` |
| 动态栈随时可用 | 栈不够就运行时分配 | `k_thread_stack_alloc` 要开 CONFIG_DYNAMIC_THREAD，F103 的 20K RAM 上基本不会开 |

## 代码自测

_注：本节代码按 Zephyr API 语义编写，未在本仓库环境实跑，仿真验证见「验证路径」。_

```c
#include <zephyr/kernel.h>

K_THREAD_STACK_DEFINE(one_shot_stack, 1024);   /* 静态栈，进 .bss，map 可查 */
static struct k_thread one_shot_data;          /* TCB 存储也是调用者提供 */

static void one_shot(void *p1, void *p2, void *p3)
{
    for (int i = 0; i < 3; i++) {
        printk("一次性线程 work %d\n", i);
        k_msleep(100);
    }
    /* Zephyr 世界观：return 是合法终止，内核替你收尾（FreeRTOS 里这是事故） */
}

int main(void)
{
    k_thread_create(&one_shot_data, one_shot_stack,
                    K_THREAD_STACK_SIZEOF(one_shot_stack),
                    one_shot, NULL, NULL, NULL,
                    5, 0, K_NO_WAIT);
    k_msleep(1000);
    printk("main：它 return 了，世界照常\n");
    return 0;
}
```

**预期现象**：

- 打印 work 0/1/2 各间隔约 100ms；
- 之后线程安静消失，**没有** fatal error——返回是合法终止；
- 最后打印 `main：它 return 了，世界照常`。

**验证路径**：`west build -b qemu_cortex_m3` 后 `west build -t run`，QEMU 控制台看输出；Renode 参照 10-renode 章。

**常见翻车点**：

- 栈 / TCB 用成函数局部变量：离开作用域后悬垂，调度器读写野内存；
- 用裸字节数组当栈：MPU 栈保护要求 2 的幂，数组不取整，要走 `K_THREAD_STACK_DEFINE`。
