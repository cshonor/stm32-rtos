# 4.4 调度与睡眠：k_sleep / k_yield / k_wakeup

## 这一篇讲什么

线程让出 CPU 的三个动词：**k_sleep（睡一段时间）、k_yield（主动让一次）、
k_busy_wait（占着 CPU 等）**，外加反向操作 k_wakeup。
以及周期任务怎么写才不漂——Zephyr 的答案和 FreeRTOS 不同。

## 三动词对照

| API | 干什么 | 状态变化 | 对应 FreeRTOS |
|---|---|---|---|
| `k_sleep(K_MSEC(100))` | 睡 100ms（阻塞，可被 k_wakeup 提前叫醒） | → 挂起（sleeping） | `vTaskDelay` |
| `k_usleep(50)` | 睡 50µs（精度到 tick 以下时内核会忙等补齐） | 同上 | 无直接对应 |
| `k_yield()` | 让出：回就绪队列尾，同/低优先级里换人 | 保持就绪 | `taskYIELD()` |
| `k_busy_wait(10)` | **占着 CPU** 空转 10µs | 不换态 | 裸机忙等（19.4 第一种） |
| `k_wakeup(tid)` | 把睡在 k_sleep 里的 tid 提前叫醒 | sleeping → ready | 无直接对应（FreeRTOS 删了 vTaskWake） |

`k_timeout_t` 类型值得记：`K_NO_WAIT`（不等待，轮询式调用用）、
`K_FOREVER`（死等）、`K_MSEC/K_SECONDS/K_TICKS(n)`。
Zephyr 所有带超时的 API 都吃这一个类型——**超时语义全内核统一**，
这点比 FreeRTOS 的 `TickType_t xTicksToWait` + 两个宏常量更整齐。

## 睡眠的精度：±1 tick 的同款边界

`k_sleep(K_MSEC(1))` 和 `vTaskDelay(1)` 有完全相同的边界问题：
在当前 tick 的任意相位调用，到下一个 tick 边界就到期，实际睡 0~1ms。
（[freertos 3.4](../../../02-freertos/book-notes/03-task-management/3.4-两种延时.md) 的量化误差分析原样适用。）
要亚 tick 精度用 `k_usleep`——它在不足一个 tick 的尾巴上会忙等补齐。

## 周期任务怎么写才不漂：k_uptime 手动锚定

FreeRTOS 有 `vTaskDelayUntil`（绝对节拍）；**Zephyr 没有直接对应物**——
官方写法是用 uptime 自己锚定：

```c
int64_t next = k_uptime_get();            /* ms 级系统时间 */
const int64_t period = 10;
for( ;; )
{
    next += period;
    干活();
    int64_t now = k_uptime_get();
    if (next > now) {
        k_sleep(K_TIMEOUT_ABS_MS(next));  /* 睡到绝对时刻（3.x 起支持） */
    }
    /* next <= now：这拍超时了，不睡，立刻进下一拍（不累积多拍） */
}
```

`K_TIMEOUT_ABS_MS`（绝对超时）是 Zephyr 3.x 补上的能力，
效果与 vTaskDelayUntil 相同：**唤醒点锚在固定网格上，干活耗时被吸收**。
书（2024 版）写作时这个 API 刚落地，用法以官方文档为准。

## k_wakeup 的意义：睡眠是可打断的

FreeRTOS 里 `vTaskDelay` 睡到一半**没法提前醒**（只能删任务重建）；
Zephyr 的 `k_sleep` 可以被 `k_wakeup(tid)` 提前打断。
典型用途：配置变了——"采样线程本来睡 10s，现在马上起来按新参数跑"。
这让 k_sleep 同时扮演了"延时"和"可被信号打断的等待"两个角色。

## 与裸机/LDD 对照

| 等待方式 | 裸机（19.4） | FreeRTOS | Zephyr |
|---|---|---|---|
| 占 CPU 短等 | while 计数 | （不推荐） | `k_busy_wait`（us 级正统用法） |
| 相对睡眠 | SysTick 数标志 | `vTaskDelay` | `k_sleep` |
| 绝对节拍 | 手动 | `vTaskDelayUntil` | `K_TIMEOUT_ABS_MS` + uptime |
| 提前叫醒 | — | 无 | `k_wakeup` |

## 要点回顾

1. 让出三动词：k_sleep（睡）/ k_yield（让）/ k_busy_wait（占着等）；反向 k_wakeup。
2. `k_timeout_t` 全内核统一（K_NO_WAIT / K_FOREVER / K_MSEC…）。
3. 周期不漂：`k_uptime_get` + `K_TIMEOUT_ABS_MS` 锚定，效果 = vTaskDelayUntil。

<details>
<summary>Q1：k_yield 会让给低优先级线程吗？</summary>

不会。yield 只把"当前线程放回它那一级的队尾"——
如果就绪队列里没有**同级**线程，它立刻又被选中（等于白让）。
想让低优先级跑，得睡（k_sleep）或阻塞。这和 taskYIELD 语义一致。

</details>

<details>
<summary>Q2：k_busy_wait 在协作式线程里用安全吗？</summary>

危险加倍：协作式线程本来就免疫抢占（4.3），再 busy_wait 就是
"整个抢占式世界 + 同级协作式一起停摆"。**busy_wait 只用于微秒级硬件时序**
（如传感器 reset 脉冲宽度），毫秒级等待一律 k_sleep/k_msleep。

</details>
