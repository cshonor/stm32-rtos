## 这一篇讲什么

Zephyr 的 socket 层叫 **zsock_***，名字加了前缀，语义和 BSD socket
逐项对齐——从 Linux 网络编程过来几乎零成本。这一篇给出对应表、
一个 TCP echo 骨架、以及 TLS（mbedTLS）怎么接进来。

## 对应表：就是换了个前缀

| POSIX / Linux | Zephyr | 备注 |
|---|---|---|
| `socket()` | `zsock_socket()` | 域/类型一致：AF_INET、SOCK_STREAM |
| `bind/listen/accept` | `zsock_bind/listen/accept` | 语义全同 |
| `connect/send/recv` | `zsock_connect/send/recv` | sendto/recvfrom 同理 |
| `setsockopt` | `zsock_setsockopt` | 选项子集（见缺口） |
| `poll` | `zsock_poll` | 多路复用只有 poll，没有 select/epoll |
| `close` | `zsock_close` | 别和文件系统的 close 混 |

`CONFIG_POSIX_API=y` 时可以直接用**无前缀**的 POSIX 名字
（socket/send/recv 直接可用），移植现成代码少改字。

## TCP echo 服务器骨架

```c
int srv = zsock_socket(AF_INET, SOCK_STREAM, IPPROTO_TCP);

struct sockaddr_in addr = {
    .sin_family = AF_INET,
    .sin_port = htons(4242),
    .sin_addr.s_addr = htonl(INADDR_ANY),
};
zsock_bind(srv, (struct sockaddr *)&addr, sizeof(addr));
zsock_listen(srv, 1);

for (;;) {
    int client = zsock_accept(srv, NULL, NULL);   /* 阻塞等连接 */
    char buf[128];
    ssize_t n;
    while ((n = zsock_recv(client, buf, sizeof(buf), 0)) > 0) {
        zsock_send(client, buf, n, 0);            /* 原样回发 */
    }
    zsock_close(client);
}
```

和 Linux 版逐行同构——**差异不在 API，在资源观**：
128 字节的 buf 在 Linux 上可笑，在 F103 上是郑重其事的 RAM 预算。
UDP echo 同理，把 SOCK_STREAM 换 SOCK_DGRAM + sendto/recvfrom 即可。

## 缺口清单（移植时先查这张表）

- **没有 select/epoll**：多路复用只有 `zsock_poll`。
- **非阻塞靠 fcntl**：`zsock_fcntl(fd, F_SETFL, O_NONBLOCK)`，支持。
- **setsockopt 子集**：常用项（SO_RCVTIMEO、TCP_NODELAY）在，冷门项未必。
- **错误码走 errno**：和 Linux 一致，`errno` 看失败原因。

## TLS：mbedTLS 架在 socket 选项上

Zephyr 的 TLS 不走独立 API，而是**用 setsockopt 给普通 socket 开光**：

```c
/* CONFIG_NET_SOCKETS_SOCKOPT_TLS=y + mbedTLS 已启用 */
zsock_setsockopt(fd, SOL_TLS, TLS_SEC_TAG_LIST, sec_tag_list, sizeof(sec_tag_list));
zsock_setsockopt(fd, SOL_TLS, TLS_HOSTNAME, hostname, strlen(hostname) + 1);
zsock_connect(fd, ...);   /* connect 时自动完成 TLS 握手，之后 send/recv 即密文 */
```

- 证书/私钥以 **sec tag** 引用，编译期通过 `tls-credential` 模块或
  `CONFIG_TLS_CREDENTIAL_KEYS` 存进固件。
- mbedTLS 是默认 TLS 后端（`CONFIG_MBEDTLS`），RAM 开销可观
  （一个 TLS 连接的收发缓冲轻松上 10K）——F103 上 TLS 基本告别，
  这也是为什么"MCU 上云"主流是模组把 TLS 做在模组里（见 [8.3](8.3-F103上网路径.md)）。

## 书 API 年代差

| 原书怎么说 | 实际是什么（Zephyr 3.x） |
|---|---|
| `net_ctx`/`net_context` 收发包 | 已移除，zsock_* 是唯一正门（见 [8.1](8.1-网络栈架构.md)） |
| TLS 需要手写 mbedTLS 上下文包 socket | 现行用 SOL_TLS setsockopt 方案，应用层不直接碰 mbedTLS API |

## 要点回顾

1. zsock_* 与 BSD socket 逐项对齐；`CONFIG_POSIX_API` 后可省前缀。
2. 缺口：只有 poll 没有 epoll，setsockopt 是子集；资源观（RAM）才是主要差异。
3. TLS = 普通 socket + SOL_TLS setsockopt，后端 mbedTLS；F103 上 TLS 交给模组。

<details>
<summary>Q1：zsock_recv 返回 0 和 -1 各是什么？</summary>

和 POSIX 一致：返回 0 = 对端正常关闭（FIN）；返回 -1 = 出错，看 errno
（EAGAIN 表示非阻塞/超时暂无数据，ECONNRESET 表示对端 RST）。
echo 循环里 ">0 才回发"就是在同时处理这两种结束。

</details>

<details>
<summary>Q2：一个应用里能同时开多少个 socket？</summary>

由 `CONFIG_NET_MAX_CONN`（连接跟踪数）和 socket 数配置共同限制，
默认值很小（个位数到十几个）。每个 socket 都占 net_buf 配额
（[8.1](8.1-网络栈架构.md)），F103 上按"够用最省"原则配，
别照搬 PC 思维开几十个。

</details>
