## 这一篇讲什么

Zephyr **自带完整 TCP/IP 栈**（native stack，不用外挂 lwIP）。
这一篇把分层摆清楚：网卡驱动怎么进栈、包怎么走上走下、
收发各跑在什么线程——socket 细节留给下一篇。

## 分层全景

```
应用：zsock_socket / zsock_sendto ...（BSD socket 风格，见 8.2）
   │
socket 层：zsock_*（薄封装，直接进内核网络栈）
   │
协议层：IPv4 / IPv6 / TCP / UDP / ICMP（Zephyr native 实现）
   │
L2 层：Ethernet / IEEE 802.15.4 / 串口 SLIP / 虚拟口（QEMU 用）
   │
网络接口（struct net_if）：一个物理/虚拟网卡一个 iface
   │
L2 驱动：eth_stm32_hal、w5500、esp_at……
```

与 lwIP 方案（很多国产 RTOS 的选择）的对照：

| | Zephyr native | lwIP |
|---|---|---|
| 地位 | 主线内置，与内核同源维护 | 第三方移植，各家自己粘 |
| API | zsock_* 直通，与 POSIX 对齐 | socket 层是 lwIP 自己模拟的 |
| 线程模型 | 收/发各有内核线程（见下） | tcpip_thread 单线程信箱模型 |
| IPv6 | 一等公民（Matter/Thread 生态需要） | 支持但常配 |

## 网络接口（net_if）：多网卡的门牌

每块网卡（或虚拟接口）注册成一个 `struct net_if`，IP 地址、
MTU、上下线状态都挂在它上面。多网卡并存时（Ethernet + Wi-Fi），
路由按 iface 选择出口。常用查询：

```c
struct net_if *iface = net_if_get_default();   /* 默认接口 */
net_if_up(iface);                              /* 拉起 */
/* 等拿到 IP（DHCP 场景）：事件回调或 net_mgmt 等待 */
```

**net_mgmt 事件**是网络版的中断通知：IP 地址到手、接口上线、
Wi-Fi 连上 AP，都以事件形式广播，应用注册回调或同步等待。

## 线程模型：收和发分开

回到 [ch04](../04-multithreading/README.md) 的词汇：

| 线程 | 职责 | 配置项 |
|---|---|---|
| **RX 线程** | 驱动收包 → 协议处理 → 投递给 socket | `CONFIG_NET_RX_STACK_SIZE` |
| **TX 线程** | 协议组包 → 驱动发送（可配置多个优先级） | `CONFIG_NET_TX_STACK_SIZE` |
| **管理/定时线程** | TCP 重传、DHCP 续约等定时任务 | 系统 workqueue / 内核定时器 |

socket 的 `zsock_recv` 本质是**在应用线程里阻塞等 RX 线程投递**——
和中断里等信号量是同一个模式（[ch04](../04-multithreading/4.4-调度与睡眠.md)）。
对时延敏感的应用（HFT 关联点）：**RX 线程优先级和 socket 所在线程优先级
直接决定收包路径的抖动分布**。

## 缓冲区：net_pkt / net_buf

包在栈里的载体是 `net_pkt`（包元数据）+ `net_buf` 链表（数据分片）。
配额由配置控制：

```conf
CONFIG_NET_PKT_RX_COUNT=14
CONFIG_NET_PKT_TX_COUNT=14
CONFIG_NET_BUF_RX_COUNT=36
```

**缓冲耗尽是网络栈最常见的翻车点**：症状是丢包、TCP 卡死、
大 MTU 流量直接断流。F103 的 20K RAM 对这些配额要精打细算。

## 书 API 年代差

| 原书怎么说 | 实际是什么（Zephyr 3.x） |
|---|---|
| `net_context_*` API 收发包 | **net_context 已移除**，现行一律 BSD socket（zsock_*），net_context 只作为内部实现残留 |
| `net_app_*` 高层封装 | 已废弃；HTTP/MQTT/CoAP 各自有独立库直接架在 socket 上 |

## 要点回顾

1. Zephyr 自带 native TCP/IP 栈：驱动 → net_if → L2 → IP → socket，不依赖 lwIP。
2. 每块网卡一个 net_if；地址到手、接口上线走 net_mgmt 事件。
3. RX/TX 各是内核线程，优先级决定时延分布；net_buf 配额是 RAM 与稳定性的对价。

<details>
<summary>Q1：QEMU 里没有真网卡，网络栈怎么测？</summary>

Zephyr 支持 QEMU + 主机 TAP/SLIP 网络：编译 `qemu_x86` 目标，
配合 `net-tools` 仓库提供的脚本建 TAP 设备，QEMU 里的 Zephyr 就能和主机互通。
这是**无硬件验证 socket 代码**的正规路径（见 [8.3](8.3-F103上网路径.md)）。

</details>

<details>
<summary>Q2：zephyr 网络栈和 BLE host 的线程划分像吗？</summary>

神似（对照 [7.1](../07-ble/7.1-BLE栈架构.md)）：都是"RX 线程收、TX 线程发、
回调不许阻塞"。MCU 协议栈的共同形态——中断只搬数据到队列，
协议处理全在线程上下文，应用回调在协议栈线程里跑。
学会一个，另一个只是换名字。

</details>
