## 这一篇讲什么

把前两篇串成一条线：从 `west build` 到 `zsock_connect` 成功，最少要点亮
哪些 Kconfig、写几行连接代码。官方参考 `samples/net/wifi`——本篇是它的导读。

## 最小 Kconfig 清单

```conf
# 网络栈（ch08 那一套）
CONFIG_NETWORKING=y
CONFIG_NET_IPV4=y
CONFIG_NET_TCP=y
CONFIG_NET_SOCKETS=y
# Wi-Fi 管理面（12.1）
CONFIG_WIFI=y
CONFIG_NET_MGMT=y
CONFIG_NET_MGMT_EVENT=y
# DHCP：连上后拿 IP（不然得配静态地址）
CONFIG_NET_DHCPV4=y
# 驱动：按硬件路径选（12.2），例如 ESP32 原生或 esp_at modem
```

Wi-Fi 驱动本身通常由板级 defconfig 或 shield 配置带进来，prj.conf 只管上面的协议层开关。

## 最小连接代码

```c
static struct net_mgmt_event_callback wifi_cb;
static K_SEM_DEFINE(connected, 0, 1);

static void on_wifi_event(struct net_mgmt_event_callback *cb,
                          uint64_t evt, struct net_if *iface)
{
    if (evt == NET_EVENT_WIFI_CONNECT_RESULT) {
        const struct wifi_status *s = (const struct wifi_status *)cb->info;
        if (s->status == 0)
            k_sem_give(&connected);      /* 连上了，放主线程走 */
    }
}

void wifi_connect_blocking(void)
{
    struct net_if *iface = net_if_get_default();
    struct wifi_connect_req_params params = {
        .ssid = (const uint8_t *)"MyAP", .ssid_length = 4,
        .psk = (const uint8_t *)"password", .psk_length = 8,
        .security = WIFI_SECURITY_TYPE_PSK,
        .channel = WIFI_CHANNEL_ANY,
    };
    net_mgmt_init_event_callback(&wifi_cb, on_wifi_event,
                                 NET_EVENT_WIFI_CONNECT_RESULT);
    net_mgmt_add_event_callback(&wifi_cb);
    net_mgmt(NET_REQUEST_WIFI_CONNECT, iface, &params, sizeof(params));
    k_sem_take(&connected, K_SECONDS(30));   /* 12.1：异步转同步 */
}
```

连上之后是 ch08 的老朋友，一行不改：

```c
int fd = zsock_socket(AF_INET, SOCK_STREAM, IPPROTO_TCP);
zsock_connect(fd, (struct sockaddr *)&addr, sizeof(addr));
zsock_send(fd, "hello\n", 6, 0);
```

## 与 ch08 的衔接点

| 层 | ch08（以太网语境） | 本章（Wi-Fi 增量） |
|---|---|---|
| 链路就绪 | 插网线 / 链路上电即就绪 | 多一步：scan/connect 异步流程 + 等事件 |
| 拿地址 | DHCPv4 | **同一个** DHCPv4，连上后自动触发 |
| socket 编程 | zsock_* | 完全不变 |
| 新增状态机 | 无 | "未连/连接中/已连/断开重连"要自己维护 |

一句话：**Wi-Fi 给 ch08 加的只有"链路层握手"前传**，socket 层及以上零改动。

## 常见翻车点（官方文档语义整理）

| 症状 | 常见原因 |
|---|---|
| connect 事件回 status != 0 | 密码/安全类型不匹配（PSK vs SAE），或 `ssid_length` 忘了不含 '\0' |
| 事件回调从不触发 | 漏 `CONFIG_NET_MGMT_EVENT=y` 或没调 `net_mgmt_add_event_callback` |
| 连上了但 socket 超时 | DHCP 没拿到地址就发数据；应再等 IPv4 地址就绪事件 |
| 回调里打印卡死 | 回调跑在系统 workqueue，重活/长日志堵全局（12.1） |

## 要点回顾

1. 最小配置 = ch08 网络栈 + `CONFIG_WIFI`/`NET_MGMT(_EVENT)` + DHCPv4 + 板级驱动。
2. 连接代码三步：注册事件回调 → 发 `NET_REQUEST_WIFI_CONNECT` → sem 等结果。
3. 连上后 socket 代码与 ch08 逐字节相同；本篇配置摘自官方 sample 语义、**未经实测**，硬件到位后以 `samples/net/wifi` 校准。

<details>
<summary>Q1：ssid_length 到底算不算结尾的 '\0'？</summary>

不算。`.ssid` / `.psk` 都是"指针 + 显式长度"，长度是有效字节数
（`"MyAP"` 是 4 不是 5）；多算 1 会把 '\0' 也发进认证流程导致失败。

</details>

<details>
<summary>Q2：DHCP 也要等事件吗？</summary>

推荐等。`NET_EVENT_IPV4_ADDR_ADD`（net_mgmt 的 IPv4 事件组）通知地址就绪后
再开 socket 最稳；连上就用可能撞上"还没拿到 IP"的窗口。

</details>
