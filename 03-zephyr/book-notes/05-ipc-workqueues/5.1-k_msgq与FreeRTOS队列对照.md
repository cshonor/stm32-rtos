# 5.1 k_msgq：与 FreeRTOS queue 的逐项对照

## 这一篇讲什么

`k_msgq` 是 Zephyr 里和 FreeRTOS queue 对应关系最直接的对象——
**固定大小消息 + 环形缓冲 + 阻塞读写**。但 Zephyr 把 FreeRTOS
"创建时传参"换成了**静态定义宏**，把"超时参数"换成了**`k_timeout_t`
统一时间类型**。本篇逐项对照，从 FreeRTOS 过来的人一眼找到映射。

## 创建：静态定义 vs 动态创建

```c
/* FreeRTOS：运行时创建，返回句柄 */
QueueHandle_t q = xQueueCreate( 10, sizeof( uint32_t ) );

/* Zephyr：编译时静态定义，零动态分配 */
K_MSGQ_DEFINE( my_q, sizeof( uint32_t ), 10, 4 );
/*          名字    单项大小          深度  对齐 */
```

`K_MSGQ_DEFINE` 在 `.bss` 里展开出一个 `struct k_msgq` + 环形缓冲区。
**没有 heap 参与，没有创建失败的可能**——RAM 用量编译时就知道了。
这是 Zephyr 全系统的设计偏好：能静态就不动态
（见 [4.2 创建线程两法](../04-multithreading/4.2-创建线程两法.md)
里 `K_THREAD_DEFINE` 的同一思路）。

FreeRTOS 也有静态创建（`xQueueCreateStatic`），但那是"可选优化"；
Zephyr 里静态定义是**主流写法**。

## 收发 API 对照

```c
/* FreeRTOS */
xQueueSend( q, &val, pdMS_TO_TICKS(100) );
xQueueReceive( q, &val, portMAX_DELAY );

/* Zephyr */
k_msgq_put( &my_q, &val, K_MSEC(100) );
k_msgq_get( &my_q, &val, K_FOREVER );
```

| | FreeRTOS | Zephyr |
|---|---|---|
| 发送 | `xQueueSend(q, &item, wait)` | `k_msgq_put(&q, &item, timeout)` |
| 接收 | `xQueueReceive(q, &buf, wait)` | `k_msgq_get(&q, &buf, timeout)` |
| 队列头读不删 | `xQueuePeek` | `k_msgq_peek` |
| 清空队列 | `xQueueReset` | `k_msgq_purge` |
| 覆盖写（长度1） | `xQueueOverwrite` | **无直接对应**（用 k_poll 或应用层） |
| 返回值 | `pdPASS`/`pdFAIL` | `0`/`-ENOMSG`/`-EAGAIN` |

## 超时体系：k_timeout_t 统一一切

FreeRTOS 每个 API 各自收 `TickType_t xTicksToWait`；
Zephyr 用一个**统一时间类型** `k_timeout_t` 贯穿所有内核对象：

| 宏 | 语义 | FreeRTOS 对应 |
|---|---|---|
| `K_NO_WAIT` | 不阻塞 | `0` |
| `K_MSEC(n)` | 等 n 毫秒 | `pdMS_TO_TICKS(n)` |
| `K_FOREVER` | 死等 | `portMAX_DELAY` |
| `K_TIMEOUT_ABS_MS(t)` | 睡到绝对时刻 t | `vTaskDelayUntil`（间接对应） |

**好处**：`k_msgq_put` / `k_sem_take` / `k_mutex_lock` / `k_sleep`
全吃同一种超时参数，不用记每个 API 的时间单位。
**代价**：`k_timeout_t` 是结构体不是整数，调试时不能 `printf("%d")`。

## ISR 里用：不用换 API，换超时参数

FreeRTOS 的规则是"ISR 里必须用 FromISR 变体"；
Zephyr 的规则是**同一个 API，传 `K_NO_WAIT`**：

```c
/* ISR 里 */
if( k_msgq_put( &my_q, &byte, K_NO_WAIT ) != 0 )
{
    dropped++;  /* 满了，丢了——与 FreeRTOS 的 errQUEUE_FULL 同义 */
}
```

`K_NO_WAIT` 保证不阻塞，API 内部检测到 ISR 上下文时不会尝试调度。
**不用记两套函数名**——这是 Zephyr 比 FreeRTOS 干净的地方。
但语义相同：ISR 里满了就丢，缓冲不是解药。

## 读不删与清空

```c
/* FreeRTOS */
xQueuePeek( q, &val, 0 );        /* 读了不删 */
xQueueReset( q );                 /* 清空 */

/* Zephyr */
k_msgq_peek( &my_q, &val );       /* 读了不删（无超时参数——有数据才返回 0） */
k_msgq_purge( &my_q );            /* 清空 */
```

`k_msgq_peek` 没有超时参数：队列空就返回 `-ENOMSG`，
语义等价于 FreeRTOS 的 `xQueuePeek(q, &val, 0)`。

## 查询状态

```c
/* FreeRTOS */
uxQueueMessagesWaiting( q );       /* 有几条数据 */
uxQueueSpacesAvailable( q );       /* 还能塞几条 */

/* Zephyr */
k_msgq_num_used_get( &my_q );      /* 有几条数据 */
k_msgq_num_free_get( &my_q );      /* 还能塞几条 */
```

## 逐项对照速查表

| 维度 | FreeRTOS queue | Zephyr k_msgq |
|---|---|---|
| 创建 | `xQueueCreate(len, size)` 动态 | `K_MSGQ_DEFINE(name, size, len, align)` 静态 |
| 发送 | `xQueueSend(q, &item, wait)` | `k_msgq_put(&q, &item, timeout)` |
| 接收 | `xQueueReceive(q, &buf, wait)` | `k_msgq_get(&q, &buf, timeout)` |
| 超时 | `TickType_t`（tick 数） | `k_timeout_t`（统一类型） |
| ISR | 专用 `FromISR` API | 同 API + `K_NO_WAIT` |
| 覆盖写 | `xQueueOverwrite` | 无直接对应 |
| 队列集 | `xQueueCreateSet` | `k_poll`（ch05 后续） |
| 返回值 | `pdPASS`/`pdFAIL` | `0`/负 errno |

## 要点回顾

1. `k_msgq` ≈ FreeRTOS queue，但创建走静态宏 `K_MSGQ_DEFINE`。
2. 超时用统一 `k_timeout_t`：`K_NO_WAIT`/`K_MSEC`/`K_FOREVER`。
3. ISR 里不用换 API，传 `K_NO_WAIT` 即可。
4. 无覆盖写、无队列集——Zephyr 用别的方式解决（k_poll、应用层）。

<details>
<summary>Q1：k_msgq 的对齐参数是干什么的？</summary>

`K_MSGQ_DEFINE(name, size, depth, align)` 的 `align` 指定
环形缓冲区的内存对齐（字节）。传 4 = 按 4 字节对齐（word 对齐），
Cortex-M 上大多数场景用 4 或 1。DMA 场景可能要 32（cache line）。
对齐影响 RAM 用量——深度 10 × 4 字节对齐时，缓冲区是 40 字节；
对齐 32 时可能 padding 到 64。

</details>

<details>
<summary>Q2：Zephyr 有没有对应 xQueueOverwrite 的东西？</summary>

没有直接对应。k_msgq 满了 `k_msgq_put` 就失败/超时。
"只留最新值"的语义在 Zephyr 里通常用**原子变量 + k_poll_signal**
或 **zbus 通道**（见 [ch11 zbus](../11-zbus/README.md)）实现。
k_msgq 的定位就是"不丢数据的 FIFO"，丢旧值不是它的设计目标。

</details>

## 衔接

k_msgq 是"固定大小消息的 FIFO"，对应 FreeRTOS queue 的核心场景。
但有些数据流不是离散消息而是**字节流**（UART），有些传递的不是
数据本身而是**指针**——Zephyr 为这些细分场景准备了
k_pipe、k_fifo、k_lifo。下一篇
[5.2 k_pipe 与 k_fifo/k_lifo](5.2-k_pipe与k_fifo_k_lifo.md)。
