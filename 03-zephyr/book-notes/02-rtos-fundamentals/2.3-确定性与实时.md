# 2.3 确定性、deadlines 与"实时"到底承诺什么

## 这一篇讲什么

"实时"（real-time）是嵌入式里被滥用最严重的词。
本篇把承诺拆成可检验的几条：**确定性、deadline 的三种硬度、
以及优先级反转这个"承诺被违背"的经典剧本**——
同一个剧本在 FreeRTOS 和 Zephyr 里的解药各叫什么。

## "实时"承诺的不是快，是可预期

- **快**（fast）：平均延迟小；
- **实时**（real-time）：**最坏情况**有界，且这个界可分析。

一个系统可以很快但不实时（桌面 Linux），也可以不快但很实时
（100Hz 的控制环，每次必然在 10ms 内完成）。
RTOS 卖的是后者：**最坏情况响应时间（WCET/延迟上界）可论证**。

## Deadline 的三种硬度

| 硬度 | 错过 deadline 的后果 | 例子 |
|---|---|---|
| Hard | 系统失效/事故 | 气囊点火、电机换相 |
| Firm | 本次结果作废，系统继续 | 音视频帧丢弃 |
| Soft | 价值随延迟递减 | UI 响应、日志上传 |

工程含义：**只有 hard real-time 需要可证明的 WCET 上界**；
soft 场景"大概率够快"即可。选 RTOS、设计优先级前，
先问自己这个系统里哪条路径是 hard 的——通常只有一两条。

## 确定性的敌人清单

RTOS 内核只能保证调度器自己的那部分确定，
以下每一项都能单独击穿承诺：

| 敌人 | 机理 | 两内核的对策 |
|---|---|---|
| 关中断过久 | ISR 延迟 = 关中断时长 + 硬件延迟 | Zephyr：ISR 分快/慢两级；FreeRTOS：FromISR API + 延迟到 task |
| 无界临界区 | 关调度器期间高优先级无法运行 | 都有 API，纪律靠自己 |
| 优先级反转 | 见下 | 双方答案一致：优先级继承 |
| 动态内存碎片 | 分配耗时不可预期 | Zephyr 主推静态/k_mem_slab；FreeRTOS 用 heap_4 或静态分配 |
| Cache/总线争抢 | WCET 分析的硬件噪声 | 超出内核职责，选芯片时考虑 |

## 优先级反转：同一剧本，两味解药

剧本（[02-freertos ch07](../../../02-freertos/book-notes/07-resource-management/README.md) 演过）：
低持锁、中被抢占、高等锁 → 高实际排在中间任务后面。

| | FreeRTOS | Zephyr |
|---|---|---|
| 解药对象 | xSemaphoreCreateMutex | k_mutex |
| 机制 | 优先级继承（持锁者临时升到等待者优先级） | **同为优先级继承** |
| 注意 | 二值信号量**没有**继承，用错对象即无药 | k_sem **没有**继承（呼应 [2.1](2.1-词汇对照表.md) 坑 2） |

两个内核在这件事上结论完全一致：
**互斥语义的资源保护，必须用带继承的 mutex 对象，不能拿计数/二值信号量凑。**

## Tick 与 tickless：确定性的时间基座

- Zephyr 默认 tick 驱动（`CONFIG_SYS_CLOCK_TICKS_PER_SEC`），
  k_sleep 等超时以 tick 为粒度向上对齐（[2.1](2.1-词汇对照表.md) 坑 1）；
- `CONFIG_TICKLESS_KERNEL=y` 时无周期性 tick，睡到下一个事件才唤醒
  ——省电（对照 [02-freertos ch10](../../../02-freertos/book-notes/10-low-power/README.md)），
  但"定时粒度"由硬件定时器精度决定，不是更准，是**更省**；
- 需要严格周期的任务：FreeRTOS 用 vTaskDelayUntil，Zephyr 用 k_timer
  或按绝对时刻 k_sleep——**相对延时叠加必然漂移**。

## 要点回顾

1. 实时 = 最坏情况有界且可分析，不是"快"。
2. Deadline 分 hard/firm/soft；只有 hard 需要可证明的 WCET。
3. 优先级反转两内核同解：带继承的 mutex（xSemaphoreCreateMutex / k_mutex）。
4. tickless 是省电特性不是精度特性；严格周期用绝对时刻机制。

<details>
<summary>Q1：Zephyr 算 hard RTOS 吗？</summary>

内核机制（固定优先级抢占、优先级继承、tickless、零延迟中断选项）
具备支撑 hard real-time 的要素，但"算不算"取决于**整个系统**：
你的 ISR 时长、临界区、内存策略、芯片的 cache 行为。
内核给的是工具，证明要自己（或审计方）做。

</details>

<details>
<summary>Q2：既然协作式线程不被抢占，它是不是更"实时"？</summary>

只对"它自己这一段"实时——它运行时别人全停，包括更高优先级的
抢占式线程。把长工作放进协作式线程，是把别人的 deadline 拿去换
自己的确定性。正确用法：协作式只做短而原子的片段（呼应 [2.2](2.2-优先级两个世界.md)）。

</details>
