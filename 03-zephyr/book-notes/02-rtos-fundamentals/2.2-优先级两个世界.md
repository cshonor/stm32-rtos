## 这一篇讲什么

优先级是 RTOS 里最常用的数字，也是两个内核**方向完全相反**的数字。
更反直觉的是：Zephyr 的优先级轴上有一道坎——
**负数是协作式，非负是抢占式**，同一个调度器里住着两个世界。
本篇把坐标系画清楚，细节深挖留给 [4.3](../04-multithreading/4.3-优先级两个世界.md)。

## 两个坐标系

```
FreeRTOS：  0 ────────────────► configMAX_PRIORITIES-1
            低优先级              高优先级（数字大 = 先跑）

Zephyr：   -CONFIG_NUM_COOP_PRIORITIES ──► -1 │ 0 ──► +CONFIG_NUM_PREEMPT_PRIORITIES-1
            ◄── 最高优先级（数字小 = 先跑）      │
                  协作式世界                     │ 抢占式世界
```

三条硬规则：

1. **Zephyr 数字越小越优先**（和 FreeRTOS 相反，和 Linux nice 值同向）；
2. **负数 = 协作式线程**：一旦跑起来，不会被任何线程（包括更高优先级的
   抢占式线程）抢占，直到它自己阻塞/让出/返回；
3. **非负 = 抢占式线程**：和我们熟悉的抢占调度一样，
   更高优先级就绪即切换，同优先级按时间片轮转。

## 协作式是一等公民，FreeRTOS 为什么没有

FreeRTOS 里要"不被打断"，只有关中断（临界区）或关调度器
（vTaskSuspendAll）——都是**全局**手段，影响所有任务。
Zephyr 把"不可抢占"做成了**单个线程的属性**：
负优先级线程自己跑到底，别的线程照常按优先级调度，中断也照常响应。

| | FreeRTOS | Zephyr |
|---|---|---|
| "我要一口气跑完" | vTaskSuspendAll（全系统停调度） | 给线程配负优先级（只保护它自己） |
| 粒度 | 全局、有界（期间中断延迟上涨的是关中断版） | 单线程、天然有界（看它自己跑多久） |
| 典型用途 | 短临界区 | 驱动底半、协议栈内部状态机 |

风险也对称：协作式线程里写个死循环 = 整个抢占式世界停摆。
**协作式是特权，不是默认**——新手线程一律用非负优先级。

## Meta-IRQ：比协作式更高的隐藏楼层

开启 `CONFIG_NUM_METAIRQ_PRIORITIES` 后，协作式区间的**最低端几个**
（如 -4..-1 中的最低几位）成为 Meta-IRQ 优先级。
它们是内核给"协作式里的协作式"留的位置：
普通协作式线程之间互不抢占，但 **Meta-IRQ 线程可以抢占普通协作式线程**。
典型用途是内核内部/驱动的关键底半处理。应用一般不用，
但读内核代码见到要认识。

手写协作式调度器时，所有"任务"都是协作式——
那就是一个只有负优先级的世界。Zephyr 相当于把那个世界完整保留，

## 原书怎么说 / 实际是什么

| 原书（Eliasz 2024） | 实际（官方文档语义） |
|---|---|
| 协作式优先级范围写作 "负值直到 -CONFIG_NUM_COOP_PRIORITIES" | 准确表述：范围是 **-CONFIG_NUM_COOP_PRIORITIES 到 -1**；若启用 Meta-IRQ，最低若干层被 Meta-IRQ 占用 |
| 暗示协作式 = "不能被打断" | 精确说法：不能被**线程**抢占；**中断照常**（ISR 不归调度器管） |

## 要点回顾

1. 方向相反：FreeRTOS 大数优先；Zephyr 小数优先（同 Linux nice）。
2. Zephyr 负数 = 协作式：运行期间不被任何线程抢占，直到自己让出。
3. 协作式是单线程粒度的"不可抢占"，对应 FreeRTOS 的全局停调度——更优雅，也更危险。
4. Meta-IRQ 是协作式区间最低端的隐藏楼层，可抢占普通协作式线程。

<details>
<summary>Q1：协作式线程里调 k_sleep 会怎样？</summary>

正常睡眠并切走——协作式只是"不被抢占"，主动阻塞随时发生。
醒来重新就绪后，如果它是当前最高优先级，继续跑。
所以协作式线程里完全可以有等待，只要别"自旋等待"。

</details>

<details>
<summary>Q2：两个世界会不会互相饥饿？</summary>

会，而且方向明确：任何就绪的协作式线程都排在所有抢占式线程前面。
一个长时间占着 CPU 的协作式线程会饿死整个抢占式世界。
工程对策：协作式只用于"短而必须原子"的工作，长任务一律非负优先级。

</details>
