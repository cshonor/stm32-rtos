## 本章讲什么

**把 RTOS 通用概念（任务、调度、抢占、优先级反转、IPC）用 Zephyr 的词汇
重新讲一遍。**对本仓库的读者这章是"复习 + 换词表"：
机制在 [01-stm32/book-notes ch20](../../../01-stm32/book-notes/20-towards-freertos/README.md)

已经学过，这里重点是**同一件事在 Zephyr 里叫什么名字**。

## 只看这一页（速览）

**主线一句话**：本章解决"学过 FreeRTOS 的人怎么换到 Zephyr 词汇"——一张总对照表打底，再逐个校准两处最大的世界观差异：优先级坐标系（方向相反 + 负数协作世界）和"实时"承诺的真实边界。

| 小节 | 一句话结论 |
|---|---|
| 2.1 | 语义最近的一对是 queue↔k_msgq；k_mutex 可重入带所有权 ≠ 二值信号量；Zephyr 里叫 "queue" 的是指针链表 |
| 2.2 | Zephyr 数字越小越优先，负数 = 协作式（不被任何线程抢占）；新手线程一律用非负优先级 |
| 2.3 | 实时 = 最坏情况有界且可分析，不是"快"；优先级反转两内核同解——带继承的 mutex |

本章最容易踩的坑：

- 按 FreeRTOS 肌肉记忆给"最重要的线程"配大数字，结果它最后才跑（2.2）
- 在协作式线程里写长活/死循环 = 整个抢占式世界停摆（2.2 Q2）
- 拿 k_sem 当互斥锁用：它没有所有权和优先级继承，优先级反转无药（2.1 坑 2 / 2.3）
- 用相对延时叠加做周期任务必然漂移，严格周期用 k_timer 或绝对时刻（2.1 坑 1 / 2.3）
- 以为 tickless 是精度特性——它是省电特性（2.3）
