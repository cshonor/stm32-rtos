## 这一篇讲什么

学一个项目先查户口：谁生的、谁养的、什么许可证、谁在用。
Zephyr 的家谱直接解释了它的两个性格——**工程化审美像 Linux**、
**生态玩法像基金会项目**。本篇把这两件事的来龙去脉摆清楚。

## 家谱：商业 RTOS 的开源转身

```
Wind River Rocket OS（商用 RTOS，VxWorks 的轻量兄弟）
        │  2016 年
        ▼
Linux 基金会托管，改名 Zephyr，Apache 2.0 发布
        │
        ▼
TSC（技术指导委员会）治理，会员制
主力贡献者：Nordic、NXP、Intel、Silicon Labs、ST……
```

关键点不是"开源了"，而是**托管方**：代码不进任何一家公司的口袋，
治理走基金会的 TSC 模式（和 Linux 内核、Kubernetes 一个套路）。
这决定了：

- 厂商贡献了代码也锁不死生态——对使用者是长期保险；
- 决策公开（公开 issue / PR / TSC 纪要），路线图可查；
- 安全响应有正式流程（Zephyr 是有安全委员会和 CVE 编号的 RTOS，
  这在 MCU RTOS 里是少数派）。

## 许可证：Apache 2.0 意味着什么

| 项 | Apache 2.0（Zephyr） | LGPL v3（libopencm3） |
|---|---|---|
| 闭源商用 | 可以 | 库本身的修改要开源，动态链接/可重链接有要求 |
| 专利授权 | **明示授予**（Apache 2.0 独有条款） | GPL 系靠隐含解释 |
| 义务 | 保留版权声明；改了 Zephyr 源码建议但不强制回馈 | 修改库源码须按 LGPL 发布 |
| 对产品 | 应用代码随便闭源 | 静态链接进固件时要给用户提供重链接手段，MCU 上单 bin 发货很尴尬 |

一句话：**做产品的固件团队几乎可以闭眼用 Zephyr**；
而用 libopencm3（[01-stm32 侧](../../../01-stm32/book-notes/README.md) 的依赖）
在产品化阶段要过一遍法务。这也是大厂愿意把 Zephyr 当底座的原因之一。

## 生态：谁在生产环境用它

- **Nordic**：nRF Connect SDK 就是 Zephyr 加自家协议栈的发行版——
  买 nRF52/nRF53 做 BLE，官方路径就是 Zephyr（本仓 [ch07 BLE](../07-ble/README.md) 走这条路）；
- **NXP / ST / Renesas 等**：给 Zephyr 贡献 HAL 与板卡支持，把它当"第二 SDK"；
- 模块（modules）生态：TF-M、MCUboot、LittleFS、lvgl、OpenThread……
  以 west 模块形式挂进来（见 [3.1 west](../03-dev-environment-build/3.1-west是什么.md)）。

## 为什么"第二遍"学 RTOS 选它

本仓第一遍 RTOS 是 FreeRTOS（[02-freertos](../../../02-freertos/book-notes/README.md)），
学的是**机制**：调度、队列、信号量。第二遍换 Zephyr，学的是**工程化**：

- Kconfig / devicetree 与 Linux 内核同源，学会即迁移到 LDD- 侧；
- west + CMake 的构建编排是"大项目怎么组织"的活教材；
- 基金会治理 + 模块生态是"商业级开源项目长什么样"的样本。

机制两边是通的，**词汇和默认值换了**——这正是 [ch02](../02-rtos-fundamentals/README.md) 要干的事。

## 要点回顾

1. Zephyr = Wind River Rocket 开源转身，2016 起由 Linux 基金会托管，TSC 治理。
2. Apache 2.0：闭源商用友好 + 明示专利授权；比 LGPL 的 libopencm3 更适合产品。
3. Nordic 全家走 Zephyr（nRF Connect SDK），生态以 west 模块形式扩张。
4. 第二遍学 RTOS 选 Zephyr，学的是工程化（Kconfig/devicetree/west），机制与 FreeRTOS 同源。

<details>
<summary>Q1：Apache 2.0 会不会被云厂商/大厂"白嫖"后闭源分叉？</summary>

会，而且这是设计允许的。基金会的对冲手段是治理而非许可证：
主线的贡献者生态足够强，分叉维护成本极高，厂商自然留在主线。
对使用者来说这意味着——跟主线走，别跟分叉走。

</details>

<details>
<summary>Q2：Zephyr 里有 GPL 组件吗？会污染我的固件吗？</summary>

Zephyr 本体全 Apache 2.0，但**可选模块各有许可证**（如某些协议栈）。
构建时只链接你 Kconfig 选中的部分；选型时看一眼模块 LICENSE 即可。
这也是"全家桶按需裁剪"（[1.2](1.2-内核vs平台.md)）的现实意义。

</details>
