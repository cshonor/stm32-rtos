## 这一篇讲什么

FreeRTOS 的官网自称 "kernel"，Zephyr 自称 "RTOS + 全家桶"。
这不是措辞差异，是**工程形态差异**：一个给你发动机，一个给你整车。
本篇把"平台比内核多出来的四层"摆清楚，并说明这对学习方法意味着什么。

## 一张分层图说透

```
┌──────────────── 你的应用 ────────────────┐
├─ 子系统：文件系统 / 日志 / shell / 设置存储 ─┤  ← FreeRTOS：自己找第三方或手写
├─ 协议栈：BLE / Thread / LwM2M / CAN / USB ─┤  ← FreeRTOS：自己集成（各家 SDK）
├─ 驱动模型：DEVICE_DT_DEFINE + 统一 API ───┤  ← FreeRTOS：直接调 HAL/寄存器
├─ 构建系统：west + CMake + Kconfig + DTS ──┤  ← FreeRTOS：你自己的 Makefile
├─ 内核：调度器 + IPC + 内存管理 ──────────┤  ← FreeRTOS 的全部 ≈ 这一层
└─ 硬件：SoC / 板卡 ──────────────────────┘
```

**FreeRTOS ≈ 最下面一层（内核），其余全是"你的问题"。**
Zephyr 把上面四层全部纳入主线，统一构建、统一裁剪、统一许可证审查。

## 逐项对照

| | FreeRTOS | Zephyr |
|---|---|---|
| 交付物 | 几个 .c/.h（内核源码） | 完整源码树 + 构建系统 + 数百板卡支持 |
| 驱动 | 无驱动模型，直接摸 HAL | Linux 风格驱动模型，统一 `device_get_binding` 系 API |
| 协议栈 | 内核不管（FreeRTOS+TCP 等是另立项目） | 主线内置 BLE/host、网络栈、USB、CAN |
| 配置方式 | `FreeRTOSConfig.h`（一个头文件，几十行） | Kconfig 树（几千个符号，分层裁剪） |
| 硬件描述 | 无概念，板级代码自己写 | devicetree（板级 dts + 应用 overlay） |
| 集成方式 | 把内核加进**你的**构建 | 把**你的应用**挂进它的构建 |
| 学习重心 | 机制（调度/IPC 语义） | 机制 + 框架的使用方式 |

最后一行是本仓两条轨分工的原因：
[02-freertos](../../../02-freertos/book-notes/README.md) 学机制，
本轨学"机制 + 平台怎么用"。

## 平台化的代价与收益

**代价**：

- 学习曲线陡——ch03 的三件套（west/Kconfig/devicetree）是最大拦路虎；
- 构建慢、镜像偏大（可裁剪，但裁剪本身要学）；
- 想绕开框架干一件事，往往比顺着框架干更费劲。

**收益**：

- **换板不改应用**：应用代码只引用 devicetree 别名（如 `led0`），
  换板卡只是 `west build -b` 换个参数（见 [1.3](1.3-板卡与架构.md)）；
- 协议栈/文件系统开箱即用且互相适配过，不用自己做集成苦役；
- 全家桶同一许可证审查体系，产品化合规成本骤降（呼应 [1.1](1.1-Zephyr家谱.md)）。

## 什么时候仍然选 FreeRTOS

| 场景 | 选谁 |
|---|---|
| 极小资源（< 32K Flash），只要调度+队列 | FreeRTOS |
| 已有成熟厂商 SDK（含协议栈），缺个调度器 | FreeRTOS 贴进去 |
| 需要主线级 BLE/网络/USB 且要长期维护 | Zephyr |
| 团队有 Linux 背景，要往驱动/内核方向发展 | Zephyr（技能直通 LDD- 侧） |
| 学习 RTOS 机制本身 | 先 FreeRTOS（干扰少） |

## 要点回顾

1. FreeRTOS 是内核，Zephyr 是平台：多出来的四层 = 构建系统、驱动模型、协议栈、子系统。
2. 集成方向相反：FreeRTOS 进你的 Makefile，你的应用进 Zephyr 的构建。
3. 平台化收益主打"换板不改应用"和开箱即用的全家桶；代价是曲线陡、构建重。
4. 极小资源 / 已有 SDK 的场景，FreeRTOS 仍是合理选择。

<details>
<summary>Q1：Zephyr 的内核能不能单独剥出来用？</summary>

工程上不推荐。内核和 Kconfig/devicetree/驱动模型咬得很死
（对象定义、初始化级别都依赖构建系统生成）。只想要个调度器，
请直接用 FreeRTOS——这正是"定位差异"的实践含义。

</details>

<details>
<summary>Q2：FreeRTOS 也有生态（+TCP、+FAT、coreMQTT），算不算平台？</summary>

算"半平台"：组件存在但**各自独立集成**，没有统一的配置/硬件描述层，
拼装的缝（build system、配置文件风格、HAL 适配）都要自己填。
Zephyr 的差异是把"缝"也做成了产品（Kconfig/DTS/west 三件套）。

</details>
