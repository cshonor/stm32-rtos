# 14.6 缓冲与刷新

> 书：第 14 章 缓冲文件 I/O · 14.6 缓冲与刷新（原书 p202–211 区间内）
> 上一篇：[14.5 二进制 I/O](14.5-二进制IO.md) ｜ 下一篇：[第 14 章目录](README.md)
> 对应实验：**全部为本次实测**（clang 23.1.0 / macOS arm64）— 磁盘文件大小随刷新变化、
> 三种 `setvbuf` 模式对照、缓冲区满自动刷新

## 书这一节讲什么

一句话：**`printf`/`fwrite` 写的数据先进"用户态缓冲区"，
要等缓冲区满、`fflush`、或 `fclose` 才真正到达目的地。**

书上讲这三个刷新时机。本篇把它们**用磁盘文件大小实测出来**——
因为"缓冲区存在"这件事，**看不见、摸不着，但能用 `stat` 量出来**。

## 一、实测：缓冲区的存在性（看磁盘文件大小）

```c
FILE *f = fopen("buf2.txt","w");
fprintf(f,"hello");
printf("fprintf(\"hello\") 之后，磁盘上的文件大小 = %ld\n", fsz("buf2.txt"));
fflush(f);
printf("fflush() 之后，磁盘上的文件大小       = %ld\n", fsz("buf2.txt"));
fprintf(f,"world");
printf("又写 5 字节不 flush，磁盘大小         = %ld\n", fsz("buf2.txt"));
fclose(f);
printf("fclose() 之后，磁盘大小               = %ld\n", fsz("buf2.txt"));
```

```
$ clang -O0 -o buf buf.c && ./buf
fprintf("hello") 之后，磁盘上的文件大小 = 0    ← ⚠ 还没落盘
fflush() 之后，磁盘上的文件大小       = 5
又写 5 字节不 flush，磁盘大小         = 5
fclose() 之后，磁盘大小               = 10
```

**这就是缓冲的直接证据**：写了 5 个字节，文件还是 **0 字节**。
数据在你进程的用户态缓冲区里，**没进内核、更没进磁盘**。

**三个刷新时机**：

| 时机 | 实测证据 |
|---|---|
| **缓冲区满** | 见第三节（64 B 缓冲，写到第 128 字节时才刷出 64） |
| **`fflush(f)`** | 实测 0 → **5** |
| **`fclose(f)`** | 实测 5 → **10**（隐式刷新） |

## 二、⚠ 实测：三种 `setvbuf` 模式的行为差异

```c
setvbuf(f, buf, mode, size);      /* 必须在读写之前调用！ */
```

**实测**（写 5 字节，再写 5 字节，每次查磁盘大小）：

```
无缓冲 写 5 字节后磁盘大小 = 5  | 再写 5 字节后 = 10
行缓冲 写 5 字节后磁盘大小 = 0  | 再写 5 字节后 = 0
全缓冲 写 5 字节后磁盘大小 = 0  | 再写 5 字节后 = 0
```

| 模式 | 常量 | 实测行为 | 用途 |
|---|---|---|---|
| **无缓冲** | `_IONBF` | **每次写立即落盘**（5 → 10） | 日志、错误输出（**掉电也要保住**） |
| **行缓冲** | `_IOLBF` | 遇到 `\n` 才刷（实测数据里**没有 `\n`** → 一直 0） | **终端输出**（`stdout` 默认） |
| **全缓冲** | `_IOFBF` | 缓冲区满才刷（实测一直 0） | **文件输出**（默认） |

⚠ **行缓冲那一行是 0，不是 bug**——
实测写的是 `"12345"` / `"67890"`，**里面没有换行符**，
所以行缓冲一直没触发。
（[14.3](14.3-读数据.md) 讲过 `fgets` 保留 `\n`，
反过来：行缓冲**靠 `\n` 触发**。）

**默认是什么**：

| 流 | 默认模式 |
|---|---|
| `stdout` **连到终端** | **行缓冲** |
| `stdout` **连到管道/文件** | **全缓冲** |
| `stderr` | ⚠ **无缓冲**（这是刻意的设计） |
| 普通文件 | **全缓冲**（默认 4 KB，实测可 `setvbuf` 改） |

⚠ **`stderr` 无缓冲是刻意的**：
错误信息必须**立刻**出来，哪怕程序下一行就崩。
用 `printf` 打日志、用 `fprintf(stderr, ...)` 打错误，
**两者被缓冲的程度不同，输出的顺序会和代码顺序不一致**。

⚠ **本机的实测限制**：我测过 `isatty(fileno(stdout))` 返回 **0**，
因为这个环境的 stdout 是管道不是终端——
所以"连终端 vs 连管道"的差异**没能在本机直接演示**。
上表关于"终端=行缓冲"的部分来自标准规定，**未实测**。

## 三、实测：缓冲区满会自动刷新

```c
FILE *f = fopen("sv_full.txt","w");
setvbuf(f, buf, _IOFBF, 64);          /* 64 字节缓冲 */
for(int i=0;i<64;i++)  fputc('x', f);  /* 写满 64 */
printf("写到第 64 字节时 = %ld", fsz(...));
for(int i=0;i<64;i++)  fputc('x', f);  /* 再写 64 */
printf("  | 写到第 128 字节时 = %ld\n", fsz(...));
```

```
全缓冲(64B) 写到第 64 字节时 = 0  | 写到第 128 字节时 = 64
```

⚠ **注意这个"差一格"**：

| 已写字节数 | 磁盘大小 |
|---|---|
| 64 | **0**（刚好填满，还没触发） |
| 65 | 应该刷 **64**（实测第 128 字节时看到 64） |

**刷新是在"写不下"的时候触发的**——
第 65 个字节来了，发现缓冲区满了，
**先把已有的 64 字节刷出去**，再把第 65 个放进去。

**所以：缓冲区满不会丢数据，只是"延迟一个字节"。**

## 四、⚠ 最重要的后果：崩溃 / 掉电时缓冲区里的数据全丢

这是本节唯一真正要记住的一条。

```
fprintf(f, "重要数据");        /* 在缓冲区里 */
/* ⚠ 这里程序崩溃 / 掉电 / 复位 */
                              /* → 这 5 个字节永远消失了 */
```

| 场景 | 后果 |
|---|---|
| **程序崩溃**（段错误） | 缓冲区内容**全丢**（`fclose` 没机会跑） |
| **掉电** | 同上 |
| **裸机复位** | 同上 |
| **`_exit()` / `abort()`** | ⚠ **`_exit` 不刷新缓冲区**（`exit` 会） |

⚠ **`exit()` 会刷新，`_exit()` 不会**：

```c
exit(1);        /* ✅ 会 flush stdio 缓冲 */
_exit(1);       /* ❌ 直接系统调用，不 flush */
abort();        /* ❌ 不保证 flush */
```

这是"程序崩了，日志少最后几行"的**头号原因**。

## 五、裸机上的对应：UART 输出缓冲

书上的 `FILE*` 缓冲在裸机上的对应物非常直接——
[ch09](../09-uart-serial/README.md) 的串口输出 + [ch10](../10-interrupts/README.md) 的环形缓冲：

```c
static char   g_tx_buf[128];
static unsigned g_tx_len;

void log_putc(char c){
    g_tx_buf[g_tx_len++] = c;
    if (g_tx_len >= sizeof(g_tx_buf) || c == '\n') log_flush();   /* 满 or 换行 */
}
void log_flush(void){
    for (unsigned i = 0; i < g_tx_len; i++) uart1_putc(g_tx_buf[i]);
    g_tx_len = 0;
}
```

⚠ **和 `FILE*` 一模一样的教训**：
`log_putc` 之后不 `log_flush`，数据就在 RAM 里，
**掉电/复位就没了**。

**最讽刺的一点**：

> **出 HardFault 时最想要的那几行日志，
> 恰恰就是没 flush 的那几行。**

**三条对策**：

| 对策 | 做法 |
|---|---|
| ① **关键日志立即 flush** | 错误、断言失败这类**马上 flush**；普通日志可以攒着 |
| ② **HardFault handler 里 flush** | `HardFault_Handler` 第一件事就是 `log_flush()` |
| ③ **ISR 里只入队** | [ch10](../10-interrupts/10.4-用缓冲区提速.md) 的环形缓冲，主循环里输出 |

⚠ **对策②的实现细节**：HardFault 时系统状态可能已经很乱，
`log_flush` 要走**轮询**发送（不能用中断，NVIC 可能已经坏了）：

```c
void HardFault_Handler(void){
    log_flush_polling();          /* 轮询发完，不依赖中断 */
    gpio_led_on();
    for(;;) {}
}
```

## 六、刷新的代价（实测支撑）

⚠ **"立即 flush"不是免费的**：

| 层面 | 代价 |
|---|---|
| **PC** | 每次 `fflush` = 一次 `write` 系统调用（**用户态→内核态切换**） |
| **裸机** | 每字节 86.8 µs（115200，[ch09](../09-uart-serial/9.4-串行通信简史.md) 实测） |

无缓冲模式下**每个字节一次系统调用**——
写 1 MB 就是 100 万次系统调用，**慢几个数量级**。

**所以是个权衡**：

| | 安全（少 flush） | 可靠（多 flush） |
|---|---|---|
| 崩溃时 | **丢数据** | 已落盘 |
| 正常运行时 | 快 | 慢 |

**工程上的通常做法**：

- **普通日志**：全缓冲（攒着），行尾或满了再刷；
- **错误/断言**：**无缓冲或立即 flush**；
- **关键数据写完**：显式 `fflush` + 检查 `fclose` 返回值
  （[14.4](14.4-打开文件.md) 讲过 `fclose` 也可能失败）。

## 坑点（书 / 常识怎么说 / 实际是什么）

| 书 / 常识怎么说 | 实测是什么 |
|---|---|
| "写了就进文件了" | ❌ 实测：写 5 字节后磁盘大小 = **0**。`fflush` 后才变 5，`fclose` 后变 10 |
| "`fflush` 是可选的" | 崩溃/掉电时**缓冲区里的全丢**。`_exit()` / `abort()` **不 flush**（`exit()` 会） |
| "`setvbuf` 随便调" | ⚠ 必须在**任何读写之前**调用，之后再调行为未定义 |
| "行缓冲会刷" | ⚠ 实测：数据里**没有 `\n`** 时行缓冲一直是 0。它靠换行符触发 |
| "缓冲区满就刷" | ⚠ 实测差一格：写满 64 字节时磁盘还是 0，**第 65 个字节来才刷出 64** |
| "`stderr` 和 `stdout` 一样" | ❌ `stderr` **无缓冲**（刻意的）。两者混用时**输出顺序和代码顺序不一致** |
| "无缓冲更可靠，那就一直用" | ⚠ 每字节一次系统调用。115200 下每字节 86.8 µs——**慢几个数量级** |

## 代码自测

<details>
<summary>Q1：怎么证明缓冲区真的存在？</summary>

**写几个字节，然后立刻查磁盘上的文件大小——它不是你写的那个数。**

**实测**：

```c
FILE *f = fopen("buf2.txt","w");
fprintf(f,"hello");                  /* 写 5 字节 */
printf("磁盘大小 = %ld\n", fsz("buf2.txt"));
fflush(f);
printf("磁盘大小 = %ld\n", fsz("buf2.txt"));
fprintf(f,"world");                  /* 再写 5 字节 */
printf("磁盘大小 = %ld\n", fsz("buf2.txt"));
fclose(f);
printf("磁盘大小 = %ld\n", fsz("buf2.txt"));
```

```
fprintf("hello") 之后，磁盘上的文件大小 = 0    ← ⚠ 写了 5 字节，文件还是 0
fflush() 之后，磁盘上的文件大小       = 5
又写 5 字节不 flush，磁盘大小         = 5
fclose() 之后，磁盘大小               = 10
```

**为什么 `stat` 能看到**：
`stat` 问的是**内核**（文件系统的元数据），
而 `fprintf` 只写到了**用户态的 stdio 缓冲区**——两者之间隔着 `write` 系统调用。

```
你的代码                                        磁盘
─────────                                      ─────
fprintf(f, "hello")
   ↓
[stdio 缓冲区]  ← 数据在这，stat 看不到
   ↓  fflush / 缓冲满 / fclose
[内核页缓存]  write(2)
   ↓  fsync / 内核回写
[磁盘]        ← stat 能看到大小了
```

⚠ **还有一个层次**：即使 `write(2)` 成功了，
数据也可能还在**内核页缓存**里没到磁盘。
要真的落盘得 `fsync(fileno(f))`。
**"程序退出了"不等于"数据到磁盘了"**——
掉电时页缓存里的也会丢。

**三种"看见"的办法**：

| 办法 | 看什么 |
|---|---|
| `stat()` 查大小（本节实测） | 数据有没有进内核 |
| 另一个进程读这个文件 | 同上 |
| `strace` / `dtruss` 看 `write` 调用 | 什么时候真的调了系统调用 |

**裸机上的等价验证**：
写 Flash 配置区之后，**读回来比对**
（[ch11](../11-linker/11.6-高级用法.md) 的 `crc32` 字段就是干这个的）。
思路完全一样：**"写"和"真的写进去了"是两件事，要用读来验证。**
</details>

<details>
<summary>Q2：程序崩溃时，缓冲区里的数据会怎样？怎么避免丢？</summary>

**全丢。这是"日志少了最后几行"的头号原因。**

**为什么**：崩溃时 `fclose` 没有机会执行，
缓冲区还在用户态内存里，进程一死，那块内存就被回收了。

⚠ **而且最讽刺的是**：
**崩溃前最后写的那几行，恰恰是你最需要的**
（"崩溃前发生了什么"）。

---

**`exit` vs `_exit` vs `abort`（这是个大坑）**：

| 函数 | 刷新 stdio 缓冲吗 |
|---|---|
| `exit(status)` | ✅ **会**（atexit 回调 + 刷新 stdio） |
| `_exit(status)` | ❌ **不会**（直接 `_exit` 系统调用） |
| `_Exit(status)` | ❌ **不会**（C99 加的，同 `_exit`） |
| `abort()` | ❌ **不保证**（会产生 `SIGABRT`） |
| `return` from `main` | ✅ 会（等价于 `exit`） |
| 段错误 / 崩溃 | ❌ **不会** |

⚠ **所以如果你的程序用 `_exit(1)` 退出**，
**之前所有 `printf` 的输出可能都没了**。

---

**三条对策**：

**① 关键输出立即 `fflush`**

```c
fprintf(f, "FATAL: ...");
fflush(f);            /* ← 立刻落盘，别攒着 */
```

代价：一次系统调用。但**错误信息通常不多**，这个代价可以接受。

**② 把关键流设成无缓冲**

```c
setvbuf(logfile, NULL, _IONBF, 0);      /* ⚠ 必须在第一次读写之前 */
```

实测过：`_IONBF` 下写 5 字节磁盘立刻是 5（不是 0）。

**③ 崩溃前能做的最后一件事：信号处理器里 flush**

```c
static FILE *g_log;
void on_fatal(int sig){
    if (g_log) { fflush(g_log); }
    _exit(1);
}
signal(SIGSEGV, on_fatal);
signal(SIGABRT, on_fatal);
```

⚠ **在信号处理器里能做的事很有限**（不是 async-signal-safe），
`fflush` 严格说也不安全。**但总比什么都不做强**——
这是"崩溃诊断"场景下的实用妥协。

---

**裸机上的对应（更重要）**：

```c
void HardFault_Handler(void){
    log_flush_polling();      /* ← 第一件事：把缓冲里的日志发完 */
    gpio_led_on();
    for(;;) {}
}
```

⚠ **必须是轮询版**，不能用中断版——
HardFault 时 NVIC 的状态不可信，中断可能已经不工作了：

```c
void log_flush_polling(void){
    for (unsigned i = 0; i < g_tx_len; i++) {
        while (!(USART1->SR & TXE)) { }      /* 轮询等 */
        USART1->DR = g_tx_buf[i];
    }
    g_tx_len = 0;
}
```

**还有一条更彻底的做法**：
**关键日志根本不进缓冲**——直接同步发送。
慢（115200 下每字节 86.8 µs，
[ch09](../09-uart-serial/9.4-串行通信简史.md) 实测），
但**保证发出去了**。

**取舍表**：

| 日志级别 | 策略 |
|---|---|
| 普通调试日志 | 攒着（全缓冲），满了/换行才发 |
| **错误 / 断言失败** | **立即同步发送** |
| **HardFault handler** | **轮询同步发送** |
</details>

<details>
<summary>Q3：`setvbuf` 三种模式实测差多少？什么时候用哪个？</summary>

**实测（写 5 字节 → 查磁盘大小 → 再写 5 字节 → 再查）**：

```
无缓冲 写 5 字节后磁盘大小 = 5  | 再写 5 字节后 = 10
行缓冲 写 5 字节后磁盘大小 = 0  | 再写 5 字节后 = 0
全缓冲 写 5 字节后磁盘大小 = 0  | 再写 5 字节后 = 0
```

| 模式 | 常量 | 刷新时机 | 实测结果 |
|---|---|---|---|
| **无缓冲** | `_IONBF` | 每次写立即 | **5 → 10** |
| **行缓冲** | `_IOLBF` | 遇到 `\n` | 0 → 0（**数据里没 `\n`**） |
| **全缓冲** | `_IOFBF` | 缓冲区满 | 0 → 0 |

⚠ **行缓冲那两行是 0 不是 bug**：
实测写的是 `"12345"` / `"67890"`，**里面没有换行符**，
所以行缓冲一直没触发。这正好说明**行缓冲靠 `\n` 触发**。

**缓冲区满自动刷新的实测**（64 字节缓冲）：

```
全缓冲(64B) 写到第 64 字节时 = 0  | 写到第 128 字节时 = 64
```

⚠ **"差一格"**：写满 64 字节时磁盘还是 0，
**第 65 个字节到达时才刷出前 64 个**。
刷新是在"装不下"的时候触发的。

---

**什么时候用哪个**：

| 场景 | 模式 | 理由 |
|---|---|---|
| **日志文件**（要可靠） | `_IONBF` 或频繁 `fflush` | 崩溃时不丢（见 Q2） |
| **`stdout` 连终端** | `_IOLBF`（**默认**） | 交互式：一行一行出，符合直觉 |
| **`stdout` 重定向到文件** | `_IOFBF`（**默认**） | 吞吐优先 |
| **`stderr`** | `_IONBF`（**默认，别改**） | 错误必须立刻出 |
| **高频数据写入** | `_IOFBF` + 大缓冲 | 系统调用次数最少 |
| 裸机 UART 输出 | 全缓冲 + 换行触发 | 兼顾吞吐和"行"的直觉 |

⚠ **两条使用约束**：

**① `setvbuf` 必须在任何读写之前调用**

```c
FILE *f = fopen(path, "w");
setvbuf(f, buf, _IOFBF, 4096);       /* ✅ 在读/写之前 */
fprintf(f, "x");
setvbuf(f, ...);                     /* ❌ 之后调用行为未定义 */
```

**② 传给 `setvbuf` 的缓冲区必须活到 `fclose`**

```c
void setup(void){
    char buf[4096];                       /* ⚠ 栈上的，函数返回就失效 */
    setvbuf(f, buf, _IOFBF, sizeof buf);
}                                          /* ← buf 没了，f 还在用它 → 内存破坏 */
```

要么用 `static`/全局缓冲，要么用 `malloc`，
要么传 `NULL` 让 libc 自己分配（**推荐**）：

```c
setvbuf(f, NULL, _IOFBF, 4096);      /* ✅ libc 自己分配，fclose 时释放 */
```

---

**裸机上的对应**：

裸机没有 `setvbuf`，但你自己写的输出函数**就是**一个缓冲策略：

```c
static char g_tx_buf[128];
static unsigned g_tx_len;

void log_putc(char c){
    g_tx_buf[g_tx_len++] = c;
    /* 两种触发：满了 或 换行 —— 就是 _IOFBF + _IOLBF 的混合 */
    if (g_tx_len >= sizeof(g_tx_buf) || c == '\n') log_flush();
}
```

**这里"换行也 flush"是有道理的**：
[ch10](../10-interrupts/README.md) 讲过 ISR 里不能做慢操作，
而"换行"是**日志行的自然边界**——
**一行完整发出去，比"发了一半"有用得多**。

⚠ **一个常见 bug**：
`g_tx_len >= sizeof(g_tx_buf)` 写成 `>` 会**越界一个字节**；
写成 `>=` 是对的（索引 0..127，写第 128 个时 `g_tx_len` 变 128 = sizeof，触发 flush）。
——**差一错误**，[ch06](../06-arrays-pointers-strings/README.md) 讲过这类边界。
