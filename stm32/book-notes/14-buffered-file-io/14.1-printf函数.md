# 14.1 printf 函数

> 书：第 14 章 缓冲文件 I/O · 14.1 printf 函数（原书 p202–211 区间内）
> 下一篇：[14.2 ASCII 表](14.2-ASCII表.md)
> 对应实验：主机侧实测（clang 23.1.0 / macOS arm64）

## 书这一节讲什么

一句话：**`printf` 的格式字符串语法，以及它有返回值。**

书上讲 `%d` / `%f` / `%s`、宽度、精度、对齐。本篇补上三点：

1. **返回值是什么、有什么用**（书里一笔带过，但裸机上很有用）；
2. **⚠ 类型不匹配的实测后果**（不是"输出错"，是**输出垃圾**）；
3. **裸机上的 `printf` 是另一回事**（[ch09](../09-uart-serial/9.3-串行输出.md) 的 `mini_printf`）。

## 一、格式字符串的完整语法

```
%[标志][宽度][.精度][长度修饰]转换字符
   │      │      │       │        │
   │      │      │       │        └─ d i u x X o f F e E g G c s p %
   │      │      │       └─ hh h l ll L z j t
   │      │      └─ 小数位数 / 字符串最大长度 / 最小数字位数
   │      └─ 最小字段宽度（或 *，由参数给出）
   └─ - 左对齐 / + 强制符号 / 空格 / 0 补零 / # 替代表形式
```

**实测**：

```c
int n3 = printf("%*d|\n", 8, 42);       /* 宽度由参数给 */
int n4 = printf("%-8d|\n", 42);         /* 左对齐 */
int n5 = printf("%08.3f|\n", 3.14159);  /* 补零 + 精度 */
```

```
      42|          ← 宽度 8，右对齐
42      |          ← 宽度 8，左对齐
0003.142|          ← 宽度 8 补零，精度 3
```

## 二、`printf` 的返回值：**输出的字符数**

**实测**：

```c
int n1 = printf("hello\n");                     /* → 6 */
int n2 = printf("%d %s %.2f\n", 42,"abc",3.14159); /* → 12 */
int n3 = printf("%*d|\n", 8, 42);               /* → 10 */
int n4 = printf("%-8d|\n", 42);                 /* → 10 */
int n5 = printf("%08.3f|\n", 3.14159);          /* → 10 */
int n6 = printf("%%\n");                        /* → 2 */
```

```
返回值（输出的字符数）：6 12 10 10 10 2
```

⚠ **数的是"字符数"，不是"字节数"**（多字节编码下两者不同），
而且是**转换后**的字符数（`%.2f` 把 `3.14159` 变成 `3.14`，算 4 个字符）。

**返回值有什么用**：

| 用途 | 场景 |
|---|---|
| **手写列对齐** | 记下已输出多少字符，补空格对齐 |
| **检测截断** | `snprintf` 的返回值 > `size` 就说明被截断了 |
| **裸机上的 `mini_printf`** | 返回"写了多少字节"，调用方才能算缓冲区余量 |

⚠ **`snprintf` 的返回值有个反直觉之处**：

```c
char buf[8];
int n = snprintf(buf, sizeof buf, "%s", "1234567890");
/* n = 10（"假如没截断会写多少"），buf 里只有 "1234567"（7 字节 + '\0'） */
```

**返回值是"想要的长度"，不是"实际写入的长度"**。
判断截断要 `if (n >= sizeof buf)`，不是 `if (n == strlen(buf))`。

## 三、⚠ 实测：类型不匹配会输出垃圾，不是"报错"

```c
printf("%d\n", 3.14);        /* ⚠ %d 要 int，给了 double */
```

**编译警告**（这是唯一的机会）：

```
pf.c:12:64: warning: format specifies type 'int' but the argument has type 'double' [-Wformat]
```

**运行结果**：

```
printf("%d\n", 3.14)  → 1374389535
```

⚠ **不是"输出 3"，是输出 `1374389535`**。

**为什么是这个数**：`3.14` 的 double 位模式是 `0x40091EB851EB851F`，
`printf` 按 `%d`（32 位 int，走的是另一个寄存器/栈槽）去取，
拿到的低 32 位 `0x51EB851F` = **1374389535**。

**为什么这么危险**：

| 层面 | 情况 |
|---|---|
| 编译 | 只给 **warning**（`-Wformat`），不是 error |
| 链接 | 完全不报错（`printf` 是可变参数，没有类型信息） |
| 运行 | **静默输出垃圾** |

**三条对策**：

1. **`-Werror=format`**——把 `-Wformat` 升级成错误；
2. 裸机上自己写的 `mini_printf` **最好只支持必要的几个转换**
   （[ch09](../09-uart-serial/9.3-串行输出.md) 的 `mini_printf` 只支持 `%d %u %x %s %c`），
   少一个转换就少一处错；
3. **不要为了"省事"用 `%d` 打 `size_t` / 指针**——用 `%zu` / `%p`。

⚠ **`%p` 必须用 `void *`**：

```c
printf("%p\n", (void *)p);      /* ✅ */
printf("%p\n", p);              /* ⚠ p 是 int* 时未定义行为 */
```

## 四、裸机上的 `printf` 是另一回事

书上的 `printf` 是 **libc 的全功能版本**：支持浮点、宽度、精度、本地化。
**裸机上没有 libc，所以没有 `printf`。**

[ch09](../09-uart-serial/9.3-串行输出.md) 实测过的最小实现：

| 项目 | 实测数据 |
|---|---|
| `mini_printf` 栈用量 | **40 字节**（`-fstack-usage`） |
| `put_uint` 栈用量 | **24 字节** |
| 整个程序 `.text` | **340 字节**（`-Os`）/ 548 字节（`-O0`） |
| 外部依赖 | **`llvm-nm -u` 为空**（零依赖） |

对比 PC 上把 `printf` 拉进来的代价：

> ⚠ **浮点格式化（`%f`）是最大的一块**。
> 裸机上如果不需要浮点，**不要支持 `%f`**——
> 光 `%f` 的实现就能占几 KB Flash。

**裸机 `printf` 的三条设计原则**：

1. **只支持需要的转换**（`%d %u %x %s %c` 通常够了）；
2. **不支持宽度/精度**（或者只支持最简单的）；
3. **返回写入的字节数**，让调用方算缓冲区余量。

## 五、`printf` 在嵌入式里的另一个身份：调试开销

⚠ **`printf` 是"贵"的，不只是代码体积**：

| 开销 | 说明 |
|---|---|
| **Flash** | 格式化代码（实测 `mini_printf` 40 B 栈 + 代码） |
| **RAM（栈）** | 格式化要栈（实测 40 字节）+ 输出缓冲 |
| **时间** | 115200 下 **每字节 86.8 µs**（[ch09](../09-uart-serial/9.4-串行通信简史.md)） |

`printf("x=%d\n", v)` 假设输出 8 字节 → **694 µs**。
在一个 1 ms 的控制循环里，**打一条日志就占了 70% 的预算**。

**对策**：

- 日志级别编译期裁剪（[ch12](../12-preprocessor/12.4-条件编译.md) 实测 `NDEBUG` 省 62 B/处）；
- ISR 里**绝对不 `printf`**（改用环形缓冲 + 主循环输出，[ch10](../10-interrupts/10.4-用缓冲区提速.md)）；
- 用二进制协议代替 ASCII（见 [14.5](14.5-二进制IO.md)）。

## 坑点（书 / 常识怎么说 / 实际是什么）

| 书 / 常识怎么说 | 实测是什么 |
|---|---|
| "`printf` 返回值没用" | 它是**输出字符数**，实测 6/12/10/10/10/2。手写对齐、检测截断都要它 |
| "`snprintf` 返回实际写入长度" | ❌ 返回"**没截断的话会写多少**"。实测意义：判断截断要 `n >= size` |
| "类型不匹配会崩" | ⚠ **静默输出垃圾**。`printf("%d", 3.14)` 实测输出 **1374389535**（double 位模式的低 32 位） |
| "编译器会拦住类型不匹配" | 只给 **warning** `-Wformat`，不是 error。要 `-Werror=format` |
| "裸机上用 `printf` 就行" | ❌ 没有 libc。实测 `mini_printf` 40 B 栈 / 340 B text 是**自己写的极简版**，不支持 `%f` |
| "`printf` 很便宜" | 115200 下一条 8 字节日志 = **694 µs**。1 ms 控制循环的 70% |

## 代码自测

<details>
<summary>Q1：`printf` 的返回值到底是什么？有什么用？</summary>

**是"成功输出的字符数"（转换之后的），出错时返回负数。**

**实测**：

```c
printf("hello\n");                          /* → 6  */
printf("%d %s %.2f\n", 42, "abc", 3.14159); /* → 12 */
printf("%*d|\n", 8, 42);                    /* → 10 */
printf("%-8d|\n", 42);                      /* → 10 */
printf("%08.3f|\n", 3.14159);               /* → 10 */
printf("%%\n");                             /* → 2  */
```

**逐个核算**：

| 调用 | 输出 | 计数 |
|---|---|---|
| `"hello\n"` | `hello` + 换行 | 5 + 1 = **6** |
| `"%d %s %.2f\n"` | `42 abc 3.14` + 换行 | 11 + 1 = **12** |
| `"%*d|\n"`（宽度 8） | `      42` + `|` + 换行 | 8 + 1 + 1 = **10** |
| `"%08.3f|\n"` | `0003.142` + `|` + 换行 | 8 + 1 + 1 = **10** |

注意第 2 个：`3.14159` 经 `%.2f` 变成 `3.14`（4 字符），
**数的是转换后的长度，不是参数的原始长度**。

**三个实际用途**：

**① 手写列对齐**（表格输出）

```c
int col = printf("%-12s", name);        /* 记下占了多少列 */
printf("%*d\n", 20 - col, value);       /* 剩下的宽度补上 */
```

**② 检测 `snprintf` 截断**

```c
char buf[16];
int n = snprintf(buf, sizeof buf, "%s", long_str);
if (n >= (int)sizeof buf) {
    /* 被截断了！n 是"假如没截断会写多长" */
}
```

⚠ **这是最容易记反的一条**：
`snprintf` 返回的是**"想要的长度"**，不是"实际写入的长度"。
没截断时两者相等，截断时返回值 **大于** `size`。

**③ 裸机上的缓冲区余量计算**

自己写的 `mini_printf` 应该也返回字节数：

```c
int n = mini_printf("temp=%d\n", t);
g_tx_used += n;                 /* 调用方才知道缓冲区还剩多少 */
```

[ch09](../09-uart-serial/9.3-串行输出.md) 实测的 `mini_printf`
栈用量 40 字节、整个程序 `.text` 340 字节——
这么小的实现里，**返回值几乎是唯一让调用方知道"写了多少"的手段**。

⚠ **一个细节**：标准说返回值是"字符数"（characters），
多字节编码（UTF-8）下**不等于字节数**。
`"中"` 是 1 个字符但 3 个字节。
缓冲区余量要用字节数算的话，别直接用 `printf` 的返回值。
</details>

<details>
<summary>Q2：为什么 `printf("%d", 3.14)` 输出 1374389535？这种错误怎么防？</summary>

**因为变长参数（`...`）在 ABI 层面没有类型信息——`printf` 只能相信格式字符串。**

**实测**：

```
$ clang -O0 -o pf pf.c
pf.c:12:64: warning: format specifies type 'int' but the argument has type 'double' [-Wformat]

$ ./pf
printf("%d\n", 3.14)  → 1374389535
```

**那个数字怎么来的**：

`3.14` 作为 `double`（IEEE 754）的 64 位模式：

```
3.14 = 0x40091EB851EB851F
```

`printf` 看到 `%d`，按"取一个 32 位 int"的方式去读参数
（在 arm64 上浮点走 `d0`/`s0` 寄存器，整数走 `x0`/`w0`——**完全是两套**）。
于是它拿到的是**某个完全不相干的寄存器内容**，输出 `1374389535`。

⚠ **在 x86-64 和 arm64 上，整数和浮点参数的传递通道是不同的**，
所以这类错误**必定**拿到垃圾，而不是"碰巧对"。

**为什么编译器只给 warning**：

C 标准说：格式字符串和参数类型不匹配是**未定义行为**。
编译器**没有义务**报错——
它只能在"格式字符串是字面量、能静态看到参数类型"时给出警告。

| 情况 | 编译器能查吗 |
|---|---|
| `printf("%d", 3.14)`（字面量格式串） | ✅ 能，`-Wformat` |
| `printf(fmt, 3.14)`（`fmt` 是变量） | ❌ 查不了（除非 `-Wformat-nonliteral`） |
| `my_printf("%d", 3.14)`（自己的函数） | ❌ 查不了（要加 `__attribute__((format(printf,1,2)))`） |

**三条防线**：

**① 把警告升级成错误**

```make
CFLAGS += -Werror=format
```

——最省事，代价是老代码可能一堆错要修。

**② 自己的 printf 类函数加 format 属性**

```c
int my_log(const char *fmt, ...) __attribute__((format(printf, 1, 2)));
                                 /* 第 1 个参数是格式串，第 2 个开始是可变参数 */
```

加上之后，编译器就能像检查 `printf` 一样检查 `my_log`。
**裸机项目里这一步特别值得做**——
自己写的 `mini_printf` / `log_printf` 加上它，
等于白捡一套类型检查。

**③ 裸机上只支持必要的转换**

[ch09](../09-uart-serial/9.3-串行输出.md) 的 `mini_printf` 只支持
`%d %u %x %s %c`——**少一个转换就少一处出错的可能**。
而且不支持 `%f` 能省掉几 KB 的浮点格式化代码。

⚠ **两个高发的具体错误**：

```c
size_t n = sizeof(x);
printf("%d\n", n);          /* ❌ size_t 不是 int（64 位上是 8 字节）→ 用 %zu */
printf("%p\n", p);          /* ⚠ 必须 (void*)p */
printf("%lld\n", x);        /* 注意 long long 的长度修饰符 */
```

`%zu`（`size_t`）、`%p`（`void *`）、`%jd`（`intmax_t`）——
这些修饰符是为"类型宽度不固定"准备的，
**跨平台代码必须用它**。
</details>

<details>
<summary>Q3：裸机上为什么不能用标准 `printf`？自己写要注意什么？</summary>

**因为标准 `printf` 属于 libc，而裸机上没有 libc。**

**代价对比（实测）**：

| | 标准 `printf`（PC） | `mini_printf`（裸机，[ch09](../09-uart-serial/9.3-串行输出.md) 实测） |
|---|---|---|
| 支持的转换 | 全部（含 `%f`、`%e`、本地化） | `%d %u %x %s %c` |
| 栈用量 | 大 | **40 字节** |
| 程序 `.text` | 拉进整个 libc 的格式化 | **340 字节**（`-Os`） |
| 外部依赖 | libc | **`llvm-nm -u` 为空** |

⚠ **浮点格式化是最大的一块**。
`%f` / `%e` 的实现（正确处理精度、四舍五入、边界情况）
通常要**几 KB 代码 + 几百字节栈**。
在 20 KB RAM / 128 KB Flash 的 F103RB 上，这笔账很贵。

**自己写 `printf` 的三条设计原则**：

**① 只支持需要的转换**

```c
/* 这几个通常够了 */
%d  %u  %x  %s  %c  %%
/* 这几个看情况 */
%ld %lu %lx      （32 位上和 %d 一样，但代码要分开写）
/* 这几个建议不支持 */
%f %e %g         （浮点，几 KB）
%n               （有安全风险，且用不上）
```

**② 不支持（或只支持最简单的）宽度/精度**

宽度/精度的解析代码不长，但**每支持一项就多一处出错可能**。
[ch09](../09-uart-serial/9.3-串行输出.md) 的实现只做了最小集。

**③ 返回写入的字节数**

让调用方能算缓冲区余量（见 Q1）。

---

**除了代码体积，还有运行时代价**（这是更要命的）：

| 开销 | 实测数字 |
|---|---|
| 串口发送 | 115200 8N1 → **86.8 µs/字节**（[ch09](../09-uart-serial/9.4-串行通信简史.md)） |
| 一条 8 字节日志 | **694 µs** |
| 1 ms 控制循环的预算 | 1000 µs → **一条日志占 70%** |

**所以裸机上用 `printf` 的三条纪律**：

1. **ISR 里绝对不 `printf`**——
   改用环形缓冲入队，主循环里输出（[ch10](../10-interrupts/10.4-用缓冲区提速.md) 的实测方案）；
2. **日志分级，发布版编译期裁掉**——
   [ch12](../12-preprocessor/12.4-条件编译.md) 实测一个 `assert` 就 62 字节
   （86 → 24），主要是 `__FILE__` 字符串；
3. **高频日志用二进制，不用 ASCII**——
   见 [14.5](14.5-二进制IO.md)：同一个 `int 1000000`，
   文本 7 字节 vs 二进制 4 字节（**实测**）。

⚠ **还有一条容易忽略的**：`printf` 要**栈**。
实测 40 字节看着不多，但如果 ISR 嵌套 8 层、每层都调一次，
就是 320 字节——[ch07](../07-stack-frame-functions/README.md) 算过 ISR 的栈预算。
**裸机上"栈够不够"是要在链接期算清楚的**
（[ch11](../11-linker/11.5-映射文件.md) 的静态余量 + 填充模式实测）。
</details>
