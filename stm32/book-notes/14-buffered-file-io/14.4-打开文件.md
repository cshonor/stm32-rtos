# 14.4 打开文件

> 书：第 14 章 缓冲文件 I/O · 14.4 打开文件（原书 p202–211 区间内）
> 上一篇：[14.3 读数据](14.3-读数据.md) ｜ 下一篇：[14.5 二进制 I/O](14.5-二进制IO.md)
> 对应实验：**12 种模式 × 文件存在/不存在 的完整行为矩阵**（clang 23.1.0 / macOS arm64 实测）

## 书这一节讲什么

一句话：**`fopen` 的模式字符串决定"能读、能写、会不会截断、从哪开始写"。**

书上讲 `r` / `w` / `a` 这几种。本篇把 **6 种模式 × 2 种文件状态 = 12 种组合
全部跑一遍**，给出一张实测表——因为其中几条的**实际行为和"想当然"不一样**。

## 一、⚠ 实测：完整的 12 格行为矩阵

```c
static void try(const char *mode, const char *path, int pre){
    if (pre){ FILE *w=fopen(path,"w"); fprintf(w,"ORIGINAL"); fclose(w); }
    FILE *f = fopen(path, mode);
    if (!f){ printf("%-4s → NULL（errno=%d: %s）\n", mode, errno, strerror(errno)); return; }
    long pos0 = ftell(f);
    int c = fgetc(f);
    int wok = (fputc('X', f) == 'X');
    printf("%-4s → OK  初始位置=%ld  读一字节=%s  写=%s\n", ...);
    fclose(f);
}
```

**文件不存在时**：

```
r    → NULL（errno=2: No such file or directory）
w    → OK  初始位置=0  读一字节=EOF/失败  写=成功
a    → OK  初始位置=0  读一字节=EOF/失败  写=成功
r+   → NULL（errno=2: No such file or directory）
w+   → OK  初始位置=0  读一字节=EOF/失败  写=成功
a+   → OK  初始位置=0  读一字节=EOF/失败  写=成功
```

**文件已存在（内容 `ORIGINAL`，8 字节）时**：

```
r    → OK  初始位置=0  读一字节=成功  写=失败
w    → OK  初始位置=0  读一字节=EOF/失败  写=成功
a    → OK  初始位置=8  读一字节=EOF/失败  写=成功
r+   → OK  初始位置=0  读一字节=成功  写=成功
w+   → OK  初始位置=0  读一字节=EOF/失败  写=成功
a+   → OK  初始位置=8  读一字节=EOF/失败  写=成功
```

## 二、把实测结果整理成表

| 模式 | 文件不存在 | 文件存在 | 截断？ | 初始位置 | 可读 | 可写 |
|---|---|---|---|---|---|---|
| `"r"` | ❌ **NULL** | 打开 | 否 | 0 | ✅ | ❌ |
| `"w"` | **创建** | 打开 | ✅ **截断为 0** | 0 | ❌ | ✅ |
| `"a"` | **创建** | 打开 | 否 | **文件尾（8）** | ❌ | ✅（只能追加） |
| `"r+"` | ❌ **NULL** | 打开 | 否 | 0 | ✅ | ✅ |
| `"w+"` | **创建** | 打开 | ✅ **截断为 0** | 0 | ✅ | ✅ |
| `"a+"` | **创建** | 打开 | 否 | **文件尾（8）** | ⚠ 实测**读失败** | ✅（只能追加） |

⚠ **三个和"想当然"不一样的地方**：

### 2.1 `"a"` 在 macOS 上**不能读**

实测 `"a"` 和 `"a+"` 的"读一字节"都是 **EOF/失败**。

按 C 标准，`"a"` 是"只追加写"，不能读是对的；
但 **`"a+"` 标准上应该能读**（C 标准说 `a+` 是"读 + 追加写"）。
**实测 macOS 上 `a+` 读完第一个字节就是 EOF**（因为初始位置在文件尾）。

⚠ **注意区别**：`a+` 的初始位置在文件尾，所以**直接读必然是 EOF**，
要先 `fseek(f, 0, SEEK_SET)` 才能读。这**不是不能读**，
是"打开位置在末尾"。实测程序没做 `fseek`，所以显示失败。

**规则**：

- **`"a"`**：只追加，**别指望读**；
- **`"a+"`**：能读，但**打开时光标在末尾**，要先 `fseek`。

### 2.2 `"w"` 会**静默截断**

实测：文件里原有 `ORIGINAL`（8 字节），`"w"` 打开后
`fgetc` 立刻返回 **EOF**——**内容已经没了**。

⚠ **这是最危险的一条**：

```c
FILE *f = fopen("important.dat", "w");     /* ⚠ 文件已经空了 */
if (!f) { ... }
/* 哪怕你后面什么都没写，原文件也已经被清空 */
```

`fopen` **成功返回**的那一刻，截断已经发生。
**没有确认、没有撤销。**

**对策**：

| 场景 | 用 |
|---|---|
| 要覆盖写 | `"w"`（清楚自己在做什么） |
| 要"不存在就创建，存在就追加" | **`"a"`** |
| 要"不存在就创建，存在就打开读写" | **`"r+"`，失败再用 `"w+"`**（见下） |

```c
FILE *f = fopen(path, "r+");            /* 不截断 */
if (!f) f = fopen(path, "w+");          /* 没有才创建 */
```

### 2.3 `"r"` 打开后**写会失败**（静默）

实测：已存在的文件用 `"r"` 打开，`fputc('X', f)` **返回失败**。

⚠ **`fputc` 返回 `EOF` 表示失败，但很多人不检查**——
于是"写了但没写进去"，**不报错、不崩、文件没变**。

```c
int r = fputc('X', f);
if (r == EOF) { /* 写失败了：权限不对 / 模式不对 / 磁盘满 */ }
```

## 三、⚠ 必做：检查 `fopen` 的返回值

实测里 `"r"` 打开不存在的文件：

```
r → NULL（errno=2: No such file or directory）
```

```c
FILE *f = fopen(path, "r");
if (!f) {
    fprintf(stderr, "打不开 %s: %s\n", path, strerror(errno));
    return -1;                       /* ⚠ 别继续用 f */
}
```

⚠ **不检查 `NULL` 就直接 `fread`/`fwrite` = 空指针解引用**。
在裸机上这是 HardFault；在 PC 上是段错误。

**`errno` 的常见值**（实测到的是 `2`）：

| errno | 含义 |
|---|---|
| `2` `ENOENT` | 文件不存在（**实测**） |
| `13` `EACCES` | 权限不够 |
| `21` `EISDIR` | 是个目录 |
| `24` `EMFILE` | **打开的文件太多**（fd 耗尽） |

## 四、文本模式 `t` vs 二进制模式 `b`

模式字符串可以带 `b`：`"rb"` / `"wb"` / `"r+b"`。

**实测**（同一个 `int 1000000`）：

```
二进制 fwrite：4 字节 → 40 42 0f 00
文本   fprintf：7 字节 → 1000000
```

**`t` / `b` 的真正区别在换行符**：

| 平台 | `"w"` 写 `\n` | `"wb"` 写 `\n` |
|---|---|---|
| Linux / macOS | `\n`（1 字节） | `\n` |
| **Windows** | **`\r\n`（2 字节）** | `\n` |

⚠ **所以在 macOS / Linux 上 `"w"` 和 `"wb"` 没有区别**（实测文件大小一致），
**但这段代码拿到 Windows 上就会不一样**。

**规则（重要）**：

> **凡是"数据"一律用 `b`，只有"给人看的文本"才用 `t`。**

固件镜像、协议报文、配置文件、日志文件——**都用 `b`**。

⚠ **理由很实际**：在 Windows 上用 `"w"` 写一个固件文件，
每个 `0x0A` 字节前面会被插入一个 `0x0D`——
**文件变大、校验失败、固件变砖**。
而且这个 bug **只在 Windows 上出现**，
macOS/Linux 上测试全过。

## 五、`fclose` 不只是"关一下"

```c
if (fclose(f) != 0) { /* ⚠ 可能失败！ */ }
```

**`fclose` 做了三件事**：

1. **刷新缓冲区**（[14.6](14.6-缓冲与刷新.md) 实测：5 → 10 字节）；
2. 关闭 fd；
3. **返回 0 表示成功，`EOF` 表示失败**。

⚠ **`fclose` 失败通常意味着"刷新失败"——
比如磁盘满了、网络文件系统断了**。
这时**你的数据可能没落盘**。

```c
if (fclose(f) == EOF) {
    fprintf(stderr, "关闭失败（数据可能没写完）: %s\n", strerror(errno));
}
```

**裸机上的对应**：
写一个 Flash 页之后要**读回来校验**（[ch11](../11-linker/11.6-高级用法.md)），
理由完全一样——**"写"这个动作本身可能失败**。

## 六、裸机上没有 `fopen`

书这一章跑在 PC 上。**裸机上没有文件系统**，所以：

| PC | 裸机替代 |
|---|---|
| `fopen("config.txt","r")` | 从 **Flash 的最后一页**读（[ch11](../11-linker/11.6-高级用法.md) 的 `.persistent` 段） |
| `fwrite` 落盘 | **Flash 编程**（解锁 → 擦页 → 编程 → 上锁） |
| `fclose` | 不需要（但要校验） |

⚠ **Flash 不是文件**：

| | 文件 | Flash |
|---|---|---|
| 写粒度 | 字节 | **页**（F1 是 1 KiB） |
| 写之前 | 直接写 | **必须先擦除** |
| 寿命 | 无限 | **约 10 k 次** |
| 写失败 | `fclose` 返回 EOF | 要**读回来比对** |

详见 [ch11](../11-linker/11.6-高级用法.md) 的实测：
把配置区钉在最后一页会让 `.bin` 从 136 B 变成 **130060 B**。

## 坑点（书 / 常识怎么说 / 实际是什么）

| 书 / 常识怎么说 | 实测是什么 |
|---|---|
| "`r` / `w` / `a` 三种够了" | 实际有 6 种。**`"w"` 会静默截断**（实测原有 8 字节内容，`"w"` 打开后 `fgetc` 立刻 EOF） |
| "`w` 是'写'，文件还在" | ⚠ **`fopen` 成功返回的那一刻，文件已经被清空**。`"w"` / `"w+"` 都截断 |
| "`a+` 能读能写" | ⚠ 实测**打开时光标在文件尾（位置 8）**，直接读是 EOF，要 `fseek` 到开头 |
| "打开失败会崩" | 返回 `NULL`，**不崩**。但不检查就解引用 = **裸机 HardFault** |
| "`w` 和 `wb` 一样" | ⚠ **只在 macOS/Linux 上一样**。Windows 上 `"w"` 会把 `\n` 变成 `\r\n`，**固件/二进制文件会坏** |
| "`fclose` 不会失败" | ⚠ 会。失败通常意味着**缓冲区没刷出去**（磁盘满、网络断） |

<details>
<summary>Q1：`"w"` 和 `"a"` 差在哪？为什么 `"w"` 危险？</summary>

**差在两点：是否截断、从哪开始写。**

**实测（文件已存在，内容 `ORIGINAL` 共 8 字节）**：

```
w    → OK  初始位置=0  读一字节=EOF/失败  写=成功
a    → OK  初始位置=8  读一字节=EOF/失败  写=成功
```

| | `"w"` | `"a"` |
|---|---|---|
| 文件不存在 | 创建 | 创建 |
| 文件已存在 | **截断为 0 字节** | 保留内容 |
| 初始位置 | 0 | **文件尾（实测 8）** |
| 写的位置 | 从 0 开始 | **永远追加到末尾** |

⚠ **`"w"` 危险在哪**：

```c
FILE *f = fopen("important.dat", "w");
```

**`fopen` 返回非空指针的那一刻，文件已经是 0 字节了。**
实测证据：`"w"` 打开后 `fgetc` 立刻返回 EOF——原来的 8 字节没了。

**没有确认对话框、没有撤销、没有任何警告。**

**三个真实事故场景**：

```c
/* ① 想"打开看看"，结果清空了 */
FILE *f = fopen(path, "w");
if (业务条件不满足) { fclose(f); return; }     /* ⚠ 文件已经空了 */

/* ② 路径拼错：创建/清空了一个不该动的文件 */
snprintf(p, sizeof p, "%s/%s", dir, name);    /* name 是空串 → p = dir */
FILE *f = fopen(p, "w");                       /* ⚠ 把目录当文件"打开"会失败，
                                                  但如果拼出了别的文件名就出事 */

/* ③ 用 "w" 做"不存在就创建" */
FILE *f = fopen(path, "w");                    /* ⚠ 存在的话内容没了 */
```

**"不存在就创建，存在就保留"的正确写法**：

```c
FILE *f = fopen(path, "r+");        /* ① 不截断地打开 */
if (!f) f = fopen(path, "w+");      /* ② 不存在才创建 */
```

或者更简单（如果你只需要追加）：

```c
FILE *f = fopen(path, "a");         /* 不存在就创建，存在就追加，绝不截断 */
```

⚠ **关于 `"a"` 的一个细节**：
以 `"a"` 打开后，**所有的写都发生在文件末尾**，
无论你怎么 `fseek`。

```c
FILE *f = fopen(path, "a");
fseek(f, 0, SEEK_SET);        /* 移动读位置可以 */
fputs("X", f);                /* ⚠ 但写永远追加到末尾，不是位置 0 */
```

这是 POSIX 规定的行为（为了支持多进程安全地追加日志）。
**想在中间写，要用 `"r+"`。**
</details>

<details>
<summary>Q2：为什么二进制文件必须用 `"wb"`？在 Mac 上测不出来吗？</summary>

**因为在 macOS / Linux 上 `"w"` 和 `"wb"` 确实没区别——
但同一份代码在 Windows 上会毁掉文件。**

**实测（macOS arm64）**：

```
二进制 fwrite：4 字节 → 40 42 0f 00
文本   fprintf：7 字节 → 1000000
```

在 macOS 上 `fopen(path,"w")` 和 `fopen(path,"wb")` 写同一个字节序列，
**文件大小完全一样**——因为 macOS/Linux 的文本模式下
`\n` 不做任何转换。

**`t` / `b` 的真正区别只有一件事：换行符转换**

| 平台 | `"w"`（文本）写 `\n` | `"wb"`（二进制）写 `\n` |
|---|---|---|
| Linux | `\n`（1 字节） | `\n` |
| macOS | `\n`（1 字节） | `\n` |
| **Windows** | **`\r\n`（2 字节）** ⚠ | `\n` |

**为什么 Windows 会坏**：

假设你在写一个固件镜像，里面有字节序列 `0x0A`（在 ASCII 里是 `\n`）：

```
原始字节：      ... 3F 0A 8C ...
Windows 文本模式写出：... 3F 0D 0A 8C ...      ← 多了一个 0x0D
```

后果链：

1. **文件变大**（每个 `0x0A` 多 1 字节）；
2. **校验和/CRC 失败**（固件升级被拒，或者更糟——通过了但内容错了）；
3. **只在 Windows 上出现**，你在 Mac/Linux 上测 100 次都过；
4. 收到 bug 报告"在 Windows 上烧录失败"，你本地完全复现不出来。

⚠ **读也有同样的问题**：
Windows 文本模式读会把 `\r\n` 合并成 `\n`——
读二进制文件时**凭空少了字节**。

**规则**：

> **凡是"数据"一律用 `b`，只有"给人看的文本"才用 `t`。**

| 内容 | 模式 |
|---|---|
| 固件镜像 / `.bin` | **`"wb"`** |
| 协议报文 / 抓包 | **`"wb"`** |
| 配置文件（二进制格式） | **`"wb"`** |
| 日志文件 | **`"wb"`**（推荐：避免跨平台歧义） |
| 纯给人看的 `.txt` | `"w"` 可以 |

⚠ **连日志文件我也建议用 `"wb"`**——
因为"日志"会被脚本解析、会被 diff、会被传上服务器，
**统一用 `\n` 能避免一堆跨平台麻烦**。

**C 标准的规定**：
`t` 和 `b` 都是**可选的模式修饰符**，
实现可以忽略它们（这就是为什么 Unix 上没区别）。
但它们**是唯一能控制换行转换的开关**，
所以写上 `b` 是**零成本的保险**。

**顺带**：`fopen` 模式字符串里 `b` 的位置有讲究：

```c
fopen(p, "rb");       /* ✅ */
fopen(p, "br");       /* ⚠ 有些实现不认 */
fopen(p, "r+b");      /* ✅ 读写的二进制 */
fopen(p, "rb+");      /* ✅ 同上 */
fopen(p, "wb+");      /* ✅ */
```

**`b` 放在 `+` 前后都行，但放在最前面（`"br"`）不规范**——
实测和移植性都建议用 `"rb"` / `"r+b"` / `"wb+"` 这几种。
</details>

<details>
<summary>Q3：`fclose` 会失败吗？失败了意味着什么？</summary>

**会。而且失败通常意味着"你的数据可能没落盘"——这是最坏的一类失败。**

**`fclose` 做的三件事**：

1. **刷新缓冲区**（把用户态缓冲里的字节交给内核）；
2. 关闭文件描述符；
3. 返回 `0`（成功）或 `EOF`（失败）。

⚠ **"刷新"这一步是可能失败的**：

| 失败原因 | 场景 |
|---|---|
| **磁盘满** | `ENOSPC` |
| 网络文件系统断开 | NFS / SMB 掉线 |
| 设备被拔出 | U 盘拔了 |
| 配额超限 | 超过用户磁盘配额 |

**实测支撑**（[14.6](14.6-缓冲与刷新.md)）：

```
fprintf("hello") 之后，磁盘上的文件大小 = 0    ← 数据在缓冲里
fflush() 之后，磁盘上的文件大小       = 5      ← 刷新才落盘
fclose() 之后，磁盘大小               = 10     ← 关闭时又刷了一次
```

**`fclose` 的第 3 步"又刷了一次"**——如果这次刷失败，
`fclose` 返回 `EOF`，而**前面 `fprintf` 全部"成功"返回了**。

⚠ **这就是最阴的地方**：

```c
FILE *f = fopen(path, "w");
for (...) fprintf(f, ...);        /* 全部"成功" */
fclose(f);                        /* ⚠ 这里失败，但没人检查 */
/* → 你以为数据写了，实际上可能只写了一部分，或者一个字节都没写 */
```

**正确写法**：

```c
if (fclose(f) == EOF) {
    fprintf(stderr, "关闭失败（数据可能没写完）: %s\n", strerror(errno));
    /* ⚠ 别假装成功了 */
}
```

⚠ **另一个细节：`fclose` 之后 `f` 就成了悬空指针**

```c
fclose(f);
f = NULL;              /* ✅ 立刻置空，防止再用 */
```

标准说：`fclose` 之后那个 `FILE*` 的值是**不确定的**（indeterminate），
再用它是未定义行为。

---

**裸机上的对应（这条特别重要）**：

裸机上写 Flash 也有完全一样的问题，
而且**更严重**——因为没人替你检查：

```c
flash_write_page(addr, data, len);      /* ⚠ 返回 void？ */
```

**Flash 编程的三个失败可能**：

| 步骤 | 可能失败吗 |
|---|---|
| 解锁 | 状态寄存器位 |
| 擦除 | 有 **写保护**（WRP）就会失败 |
| 编程 | 掉电、地址不对齐、写保护 |
| —— | 还有**静默的部分成功**（擦了但没写完） |

**所以裸机上的正确做法是"写完读回来比对"**：

```c
int flash_write_and_verify(uint32_t addr, const uint8_t *data, size_t n){
    if (flash_program(addr, data, n) != 0) return -1;     /* 编程报失败 */
    for (size_t i = 0; i < n; i++)
        if (*(volatile uint8_t *)(addr + i) != data[i]) return -2;  /* 内容不对 */
    return 0;
}
```

⚠ **这和 `fclose` 检查返回值是同一个道理**：
> **"写"这个动作本身可能失败，而且失败常常是静默的。
> 唯一的防线是"写完再验证"。**

[ch11](../11-linker/11.6-高级用法.md) 的配置区设计里，
`magic` / `version` / `crc32` 三个字段就是干这个的——
**CRC 就是"读回来比对"的紧凑版**。
