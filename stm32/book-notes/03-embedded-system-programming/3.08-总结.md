## 书这一节讲什么

一章讲完，回头看这七节其实是**一条直线**：

```
3.1 板子是什么          →  你手里有什么硬件
3.2 建立一个项目        →  代码住在哪
3.3 写出第一个程序      →  ★ 第一次真的改变了硬件电平
3.4 探索构建过程        →  这段代码是怎么变成 Flash 里的字节的
3.5 探索项目文件        →  哪些是源、哪些是产物、哪些别碰
3.6 调试应用程序        →  让程序停下来，看它到底做了什么
3.7 逐步执行程序        →  一行一行走，看清每一步
```

**3.3 是分水岭**：前两节在准备，从 3.3 开始你的代码第一次让物理世界发生变化。
后面四节（3.04–3.07）全是"**让你相信并验证这件事真的发生了**"。

## 本章最该记住的五件事

**① 外设使用前必须开时钟，而"不开"的后果是静默的。**
实测：写丢失、读配置寄存器得到复位值、读 `IDR` 得到 0，**全程无异常**
（`stage=13` 跑完）。三次独立验证：`portprobe.c`、`GPIOC` 探针、
以及 [3.06](3.06-调试应用程序.md) 里"连调试器写 BSRR 都无效"。

**② 一个寄存器管多个引脚时，必须"先清后置"。**
`GPIOA_CRL = 0x00200000` 会顺手把 PA0–PA4/PA6/PA7 改成模拟输入。

**③ 改单个引脚用 `BSRR`，不要 `ODR ^=`。**
实测：`BSRR` 一条 `str`（硬件原子），`ODR` 读-改-写三条指令（中间可被中断打断）。
而且 `ODR` 复位值不是 0（是 `0x0000a000`），直接赋值会抹掉调试口上拉。

**④ 产物 vs 源，界线要清楚。**
6 个源文件，9 个产物。判据：**删掉它 `make` 能不能重建**。
`.bin` 才是烧进芯片的东西（376 B），`.elf` 是给 gdb 看的（134856 B）。

**⑤ 调试时行号会说谎，寄存器不会。**
`-Os` 下行号会跳（实测 `96 → 93 → 96 → 94`），函数会被内联
（`break delay` → `Function not defined`）。**用 `x` / `info registers` /
`stepi` 验证，别相信高亮行。**
还有个专门坑：`monitor reset halt` 之后 gdb 的寄存器视图是**陈旧的**，
必须 `maintenance flush register-cache`。

## 与 LDD-（Linux 驱动）的对照

本章的全部内容，在 Linux 驱动里都有对应物 —— **对照着看，两边都会更清楚**：

| 本章（裸机） | LDD-（Linux 驱动） | 差别在哪 |
|---|---|---|
| `RCC_APB2ENR \|= (1<<2)` 开时钟 | `clk_prepare_enable(clk)` | 内核帮你记账、能报错、能省电管理 |
| 直接写 `GPIOA_CRL` | `gpio_direction_output()` / pinctrl | 内核有抽象的 gpio 子系统 |
| `GPIOA_BSRR = (1<<5)` | `gpiod_set_value()` | 同上 |
| 向量表 96 字节 | IRQ 子系统（`request_irq`） | 内核管理几百个中断线 |
| 自己写 `startup.S` + `linker.ld` | Kbuild + `vmlinux.lds` | 内核替你准备好了 |
| `-fstack-usage` 量栈 | 内核任务的 8K/16K 栈 | 内核里栈溢出会**安静地毁掉别人** |
| 调试器连上去看寄存器 | `devmem` / `debugfs` / Ftrace | 内核可观测性丰富得多 |

**一句话**：裸机让你看清**机制**（时钟门控、位操作、原子性），
Linux 让你看清**抽象**（子系统、错误处理、并发）。
**先机制后抽象，顺序反了就是死记硬背。**
