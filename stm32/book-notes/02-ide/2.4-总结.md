## 这一章要带走的一句话

**IDE 不是编译器，是一层"替你敲命令"的壳。**

拆开之后只有三条链路：**构建 / 烧录 / 调试**，每条都有清晰的文件边界：

| 链路 | 输入 | 输出 | 命令行 |
|---|---|---|---|
| 构建 | `.c` / `.S` / `.ld` | `.elf`（给调试）+ `.bin`（给烧录） | `make` |
| 烧录 | `.bin` + 起始地址 | Flash 里的字节 | `openocd -c "program ... verify reset exit"` |
| 调试 | `.elf`（符号）+ 目标 | 断点 / 单步 / 变量 | `openocd` + `arm-none-eabi-gdb` |

## 我的额外结论（书里没有）

| 结论 | 依据 |
|---|---|
| **不需要 IDE 也能有源码级调试** | gdb + openocd 实测停在 `main.c:38`，变量、断点、单步都可用 |
| **IDE 唯一不可替代的是 SVD 寄存器视图** | 但 VSCode + Cortex-Debug 也能做到，且复用现有 openocd |
| **不要在 Mac 上为 SW4STM32 折腾** | 已停止维护 + 需要 Java + Gatekeeper + 英文路径，收益为负 |
| **如果以后要装完整 IDE，等真的需要寄存器视图/RTOS 线程视图时再装** | 判据见 [book-notes/README](../README.md) 的"工具链事实" |

## 代码自测

<details>
<summary>Q1：如果 IDE 哪天彻底消失，你手里还剩什么？</summary>

剩下**四类文件 + 三条命令**：

| 类别 | 具体 | 为什么不会消失 |
|---|---|---|
| 源文件 | `.c` / `.S` | 是 C 语言，与工具无关 |
| 构建描述 | `Makefile` | 就是命令行的封装 |
| 器件地图 | `linker.ld` | 描述物理地址空间，芯片决定 |
| 调试符号 | `.elf` 里的 DWARF | 是开放标准格式 |
| 命令 | `clang` / `ld.lld` / `openocd` / `gdb` | 全是开源可自建的工具 |

反过来，如果只剩 IDE 而**没有**这四类文件（很多人是这样），
那他就真的被锁死了——工程文件是 IDE 的私有格式。

**这就是为什么要自己写一遍。** 不是为了"手写更酷"，是为了**资产归属明确**。
</details>
