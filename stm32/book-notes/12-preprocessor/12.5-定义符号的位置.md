# 12.5 定义符号的位置

> 书：第 12 章 预处理器 · 12.5 定义符号的位置（原书 p174–185 区间内）
> 上一篇：[12.4 条件编译](12.4-条件编译.md) ｜ 下一篇：[12.6 命令行定义的符号](12.6-命令行定义的符号.md)
> 对应实验：块内 `#define` 作用域实测、`#undef` 实测、宏重定义警告实测

## 书这一节讲什么

一句话：**宏可以定义在三个地方——源文件里、头文件里、命令行上。选哪个有讲究。**

书上讲的是"定义在文件开头"。本篇补上两件书里没展开的事：

1. **宏没有块作用域**（实测：在函数体里 `#define`，会泄漏到文件尾）；
2. **重定义的行为**（实测：值相同合法，值不同只有**警告**，不报错）。

## 一、三个位置怎么选

| 位置 | 写法 | 适用 | 例子 |
|---|---|---|---|
| **① 源文件顶部** | `#define X 1` | 只在这个 `.c` 里用 | 文件内部的常量、私有位定义 |
| **② 头文件** | `config.h` / `board.h` | 多个 `.c` 共享 | 板子配置、协议常量、日志级别 |
| **③ 命令行 `-D`** | `-DBOARD_F103` | **换一次编译换一份配置** | 选板子、开关功能、版本号 |

**判断标准（一句话）**：

> **"换板子/换客户/换版本时要改的东西"放命令行；
> "这个模块自己的实现细节"放源文件；其余放头文件。**

## 二、⚠ 实测：宏**没有块作用域**

这是和变量最大的差别，也是最容易踩的一点。

```c
void f(void){
#define INNER 1          /* 写在函数体里 */
    int a = INNER;
#undef INNER              /* 显式取消 */
#ifdef INNER
    int b = 2;
#else
    int b = 3;
#endif
}
#ifdef INNER
int leaked = 1;
#else
int leaked = 0;
#endif
```

```
$ clang -E -P sc.c
void f(void){
    int a = 1;
    int b = 3;            ← #undef 生效了
}
int leaked = 0;           ← 没有泄漏
```

**去掉 `#undef` 再看**：

```
$ clang -E -P sc2.c
void f(void){ int a = 1; }
int leaked = 1;           ← ⚠ 泄漏到文件尾了
```

**规则**：

> **宏从 `#define` 那一行开始生效，到文件末尾或 `#undef` 为止——
> 和 `{}` 完全无关。**

⚠ **`#define` 写在函数体里是合法的**，但**强烈不建议**：

- 读代码的人会以为它有块作用域；
- 忘记 `#undef` 就污染后面的所有代码；
- 报错定位困难。

**唯一合理的用例**：临时调试时定义一次，用完立刻 `#undef`。
正式代码里一律放文件顶部或头文件。

## 三、重定义：值相同合法，值不同只有警告

**实测**：

```c
#define FOO 1
#define FOO 1          /* 值相同 */
int x = FOO;
```

```
$ clang -fsyntax-only rd2.c
$                       ← 无输出：合法
```

```c
#define FOO 1
#define FOO 2          /* 值不同 */
int x = FOO;
```

```
$ clang -fsyntax-only rd.c
rd.c:2:9: warning: 'FOO' macro redefined [-Wmacro-redefined]
    2 | #define FOO 2
      |         ^
rd.c:1:9: note: previous definition is here
    1 | #define FOO 1
      |         ^
1 warning generated.
```

⚠ **是 warning，不是 error**。而且**生效的是后一个**（`FOO` = 2）。

**为什么危险**：

```c
/* board.h */
#define CFG_BAUD  115200

/* 某个 .c 里，有人"顺手"改了一下 */
#define CFG_BAUD  9600        /* ⚠ 只有警告，编译照过 */

void uart_init(void){ ... CFG_BAUD ... }   /* 用的是 9600 */
```

——编译通过、下载运行、**波特率不对、串口全是乱码**。
而警告只在**编译那一次**出现，很容易被刷屏盖掉。

**两条对策**：

| 对策 | 做法 |
|---|---|
| ① **配置宏一律用 `#ifndef` 兜底** | 见下 |
| ② **把警告升级成错误** | `CFLAGS += -Werror=macro-redefined` |

**①的写法**（头文件的标准姿势）：

```c
/* board.h —— 给默认值，命令行可以覆盖 */
#ifndef CFG_BAUD
#  define CFG_BAUD  115200
#endif
```

这样：

- 命令行 `-DCFG_BAUD=9600` → 用 9600；
- 没给 → 用 115200；
- **不可能重定义**（`#ifndef` 已经挡住了）。

⚠ **顺序很重要**：`#ifndef` 兜底必须写在**可能被 `-D` 覆盖的头文件里**，
且该头文件要在**所有使用点之前**被包含。

## 四、`#undef` 的三个正经用途

| 用途 | 例子 |
|---|---|
| ① **临时宏用完即弃** | `#define DEBUG_PRINT ...` 用几行后 `#undef` |
| ② **覆盖第三方头文件的定义** | `#undef assert` → 再 `#define assert(...)` 自己的版本 |
| ③ **防止配置泄漏到别的模块** | 头文件末尾 `#undef` 内部辅助宏 |

⚠ **② 要小心**：undef 掉标准库的东西之后，**同一翻译单元里后面的所有代码都用你的版本**。
如果一个 `.c` 里既有你的 `assert` 又有系统 `assert` 的语义期待，会很乱。
本仓库的做法是**自己定义一个新名字**（`ASSERT`），不去动系统的。

## 五、头文件里放配置的标准套路

综合上面几条，一个 `board.h` 长这样：

```c
#ifndef BOARD_H
#define BOARD_H                       /* ← 守卫名带模块前缀（12.4 的重名坑） */

/* ---- 板子选择：必须由命令行给出，否则报错 ---- */
#if !defined(BOARD_NUCLEO_F103RB) && !defined(BOARD_F407_DISCOVERY)
#  error "未指定板子：请 -DBOARD_NUCLEO_F103RB 或 -DBOARD_F407_DISCOVERY"
#endif

/* ---- 板子相关定义 ---- */
#if defined(BOARD_NUCLEO_F103RB)
#  define LED_PORT         GPIOA
#  define LED_PIN          5
#  define LED_ACTIVE_HIGH  1
#elif defined(BOARD_F407_DISCOVERY)
#  define LED_PORT         GPIOF
#  define LED_PIN          9
#  define LED_ACTIVE_HIGH  0
#endif

/* ---- 可选配置：给默认值，命令行可覆盖 ---- */
#ifndef CFG_BAUD
#  define CFG_BAUD   115200
#endif
#ifndef LOG_LEVEL
#  define LOG_LEVEL  1
#endif

#endif /* BOARD_H */
```

**四件事各司其职**：

| 行 | 防什么 |
|---|---|
| `#ifndef BOARD_H` | 重复包含（[12.4](12.4-条件编译.md) 的重名坑） |
| `#error` | 忘了给 `-D`（[12.4](12.4-条件编译.md) 实测） |
| `#if defined(...)` | 板子二选一 |
| `#ifndef CFG_BAUD` | 命令行可覆盖，且不重定义 |

## 六、什么时候**不该**用宏

书里没讲这条，但它和"定义在哪"一样重要：

| 场景 | 别用宏，用 |
|---|---|
| 只是"一个不该改的值" | `static const` / `enum`（[12.1](12.1-简单宏.md)） |
| 有类型的常量集合 | `enum` |
| 需要调试器看到名字 | `enum` / `static const` |
| 逻辑（不是常量） | `static inline` |

理由是**宏没有任何约束**：没有类型、没有作用域、能被随意重定义
（还只是警告）。能用语言特性表达的，就别用文本替换。

## 坑点（书 / 常识怎么说 / 实际是什么）

| 书 / 常识怎么说 | 实测是什么 |
|---|---|
| "宏定义在文件开头" | 其实**哪儿都行**，包括函数体里。实测块内 `#define` 会**泄漏到文件尾**（除非 `#undef`） |
| "宏有块作用域" | ❌ **完全没有**。实测 `void f(void){ #define INNER 1 ... }` 之后文件尾 `#ifdef INNER` 仍为真 |
| "重复 `#define` 会报错" | ⚠ 值相同**合法**；值不同只有 **warning** `-Wmacro-redefined`，且**后定义的生效** |
| "配置宏直接写死" | 应该用 `#ifndef X / #define X 默认 / #endif` 兜底，命令行才可覆盖且不重定义 |
| "`#undef` 用不上" | 三个正经用途：临时宏、覆盖第三方定义、防泄漏 |
| "宏能当常量用" | 能用但没类型没作用域。**只是"不该改的值"时优先 `enum` / `static const`** |

## 代码自测

<details>
<summary>Q1：`#define` 写在函数体里会怎样？它有块作用域吗？</summary>

**没有块作用域。宏从 `#define` 那一行生效，到文件末尾或 `#undef` 为止。**

**实测**：

```c
void f(void){
#define INNER 1          /* 写在函数体里 */
    int a = INNER;
#undef INNER              /* ← 有这一行 */
#ifdef INNER
    int b = 2;
#else
    int b = 3;
#endif
}
#ifdef INNER
int leaked = 1;
#else
int leaked = 0;
#endif
```

```
$ clang -E -P sc.c
void f(void){
    int a = 1;
    int b = 3;            ← #undef 之后就是假的了
}
int leaked = 0;           ← 没泄漏
```

**去掉 `#undef`**：

```
$ clang -E -P sc2.c
void f(void){ int a = 1; }
int leaked = 1;           ← ⚠ 泄漏到文件尾
```

**为什么是这样**：预处理器**不懂 C 语法**。
它看到的是一行行的文本，`{}` 对它毫无意义。
`#define` 就是"从这行开始，记住这个替换规则"，
`#undef` 才是唯一的取消手段。

**实践后果**：

⚠ 在一个 `.c` 中间 `#define BUF_SIZE 64`，
后面**所有代码**（包括后面的 `#include` 的头文件）都会看到 `BUF_SIZE`。
如果某个头文件里也有 `BUF_SIZE`，就是**重定义**（见 Q2）。

**所以规则**：

1. **正式代码里 `#define` 只写在文件顶部或头文件里**；
2. 万不得已写在中间，**用完立刻 `#undef`**；
3. 别指望 `{}` 帮你隔离——它隔离不了。

**一个有用的推论**：
头文件里定义的宏会**泄漏到包含它的所有源文件**，
这也是为什么[12.4](12.4-条件编译.md) 强调
"守卫名要带模块前缀"——名字撞了就是全局范围的冲突。
</details>

<details>
<summary>Q2：重复定义同一个宏会怎样？为什么"只有警告"很危险？</summary>

**值相同 → 合法；值不同 → `-Wmacro-redefined` 警告（不是错误），且后定义的生效。**

**实测**：

```c
#define FOO 1
#define FOO 1          /* 值相同 */
int x = FOO;
```

```
$ clang -fsyntax-only rd2.c
$                       ← 无输出，合法
```

```c
#define FOO 1
#define FOO 2          /* 值不同 */
int x = FOO;           /* → int x = 2; 生效的是后一个 */
```

```
$ clang -fsyntax-only rd.c
rd.c:2:9: warning: 'FOO' macro redefined [-Wmacro-redefined]
    2 | #define FOO 2
      |         ^
rd.c:1:9: note: previous definition is here
    1 | #define FOO 1
      |         ^
1 warning generated.
```

**为什么"只有警告"很危险**：

```c
/* board.h */
#define CFG_BAUD  115200

/* 某个 .c 里有人想临时改一下试试，改完忘了删 */
#define CFG_BAUD  9600

void uart_init(void){ ... CFG_BAUD ... }    /* 用的是 9600 */
```

后果链条：

1. 编译**通过**（只是警告）；
2. 警告在满屏输出里**很容易被漏看**；
3. 下载运行，**波特率错了**，串口输出全是乱码；
4. 你会去查时钟配置、查 BRR 计算、查线序……**很难想到是宏被覆盖了**。

**两条对策**：

**① 配置宏用 `#ifndef` 兜底**（推荐）：

```c
#ifndef CFG_BAUD
#  define CFG_BAUD  115200
#endif
```

这样别人想改，只能：

- 用命令行 `-DCFG_BAUD=9600`（✅ 可复现、能进 git）；
- 或者改 `board.h` 里的默认值（✅ 只有一处）。

**不可能出现"两个 `#define` 打架"**——`#ifndef` 已经挡住了第二种。

**② 把警告升级成错误**：

```make
CFLAGS += -Werror=macro-redefined
```

⚠ 这个选项会**连带影响第三方头文件**
（有些库确实会重复定义同一个宏，且是故意的）。
启用前先全量编译一次看看有多少处。

**顺带**：如果想**显式地**改一个宏而不想看到警告，正确写法是：

```c
#undef  CFG_BAUD
#define CFG_BAUD  9600
```

——`#undef` 之后就没有"重定义"了。
但更好的是别这么干，用命令行覆盖（[12.6](12.6-命令行定义的符号.md)）。
</details>

<details>
<summary>Q3：一个 `board.h` 应该长什么样？（综合本节和 12.4 的所有坑）</summary>

四层防护，每层防一个具体的坑：

```c
#ifndef BOARD_H                    /* ← ① 守卫：防重复包含 */
#define BOARD_H

/* ② 强制要求指定板子：忘了 -D 就报错 */
#if !defined(BOARD_NUCLEO_F103RB) && !defined(BOARD_F407_DISCOVERY)
#  error "未指定板子：请 -DBOARD_NUCLEO_F103RB 或 -DBOARD_F407_DISCOVERY"
#endif

/* ③ 板子相关定义：二选一 */
#if defined(BOARD_NUCLEO_F103RB)
#  define LED_PORT         GPIOA
#  define LED_PIN          5
#  define LED_ACTIVE_HIGH  1        /* 高电平点亮 */
#  define PCLK2_HZ         8000000u /* 上电默认 HSI */
#elif defined(BOARD_F407_DISCOVERY)
#  define LED_PORT         GPIOF
#  define LED_PIN          9
#  define LED_ACTIVE_HIGH  0        /* 低电平点亮 */
#  define PCLK2_HZ         84000000u
#endif

/* ④ 可选配置：给默认值，命令行可覆盖，且不重定义 */
#ifndef CFG_BAUD
#  define CFG_BAUD   115200
#endif
#ifndef LOG_LEVEL
#  define LOG_LEVEL  1
#endif

#endif /* BOARD_H */
```

**每层防什么**（全部有实测支撑）：

| 层 | 写法 | 防的坑 | 实测 |
|---|---|---|---|
| ① | `#ifndef BOARD_H` | 重复包含；**守卫重名会静默吞掉整个头文件** | [12.4](12.4-条件编译.md)：两个 `CONFIG_H` → `FROM_B=FROM_B` |
| ② | `#error` | 忘了给 `-D` → 一堆莫名其妙的错 | [12.4](12.4-条件编译.md)：`#error` 实测（注意它**不停止预处理**，要看第一条报错） |
| ③ | `#if defined(...)` | 用 `#ifdef` 会在 `-DX=0` 时误判 | [12.4](12.4-条件编译.md)：`-DFOO=0` 时 `#ifdef`→1，`#if`→0 |
| ④ | `#ifndef X / #define X 默认` | 重定义（只有警告，后定义的生效） | 本节实测：`-Wmacro-redefined` |

**用法**：

```sh
# Makefile 里（可复现，进 git）
CFLAGS += -DBOARD_NUCLEO_F103RB
CFLAGS += -DCFG_BAUD=115200      # 可选，不给就用 115200
```

⚠ **几个容易漏的细节**：

1. **守卫名要带模块前缀**（`BOARD_H` 不是 `CONFIG_H`）——`CONFIG_H` 是重灾区；
2. **`#error` 放在 `#if !defined(A) && !defined(B)` 里**，
   不是 `#else`——因为可能同时定义两个板子（也是错的，可以再加一条检查）；
3. **`#endif` 后面加注释**（`/* BOARD_H */`）——嵌套多了靠这个认；
4. **别在头文件里 `#undef` 别人的宏**——会污染所有包含它的源文件。

**再加一层（可选）：互斥检查**

```c
#if defined(BOARD_NUCLEO_F103RB) && defined(BOARD_F407_DISCOVERY)
#  error "不能同时定义两块板子"
#endif
```

——防止有人 `-DBOARD_A -DBOARD_B`，
那样会**静默地用 A 的配置**（`#elif` 不生效）。
</details>
