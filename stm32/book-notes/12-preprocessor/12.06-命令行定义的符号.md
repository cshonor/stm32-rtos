# 12.06 命令行定义的符号

> 书：第 12 章 预处理器 · 12.06 命令行定义的符号（原书 p174–185 区间内）
> 上一篇：[12.05 定义符号的位置](12.05-定义符号的位置.md) ｜ 下一篇：[第 12 章目录](README.md)
> 对应实验：`-D` / `-U` / `-E -dM` 实测、漏给 `-D` 的报错实测、字符串宏的 shell 引号实测

## 书这一节讲什么

一句话：**`-DNAME=value` 在命令行上定义宏——换一次编译换一份配置，不用改源码。**

书上讲的是 `-D` 的语法。本篇补上书里没讲的两件事：

1. **`-D` 和"写在源码里"的取舍**（为什么命令行更好）；
2. **忘了给 `-D` 会发生什么**（实测：不是"用默认值"，是**编译错误**）。

## 一、三种写法

```sh
clang -DFOO            ...      # 定义 FOO，值为 1
clang -DFOO=0          ...      # 定义 FOO，值为 0
clang -DFOO='"abc"'    ...      # 定义 FOO 为字符串 "abc"（注意引号）
clang -UFOO            ...      # 取消定义（覆盖前面的 -D）
```

**实测**：

```c
const char *fw  = FW_VERSION;
int baud        = CFG_BAUD;
int dbg         = LOG_LEVEL;
int has_x       =
#ifdef FEATURE_X
1
#else
0
#endif
;
```

```
$ clang -E -P -DFW_VERSION='"1.2.3"' -DCFG_BAUD=115200 -DLOG_LEVEL=2 -DFEATURE_X cmd.c
const char *fw = "1.2.3";
int baud = 115200;
int dbg = 2;
int has_x =
1
;
```

### 1.1 ⚠ 字符串宏的引号坑

`-DFW_VERSION='"1.2.3"'` 这一串看起来很怪，原因是**两层引号**：

| 层 | 作用 |
|---|---|
| 外层 `'...'` | 给 **shell**：让它不要把内容拆开 |
| 内层 `\"` 或 `"1.2.3"` | 给 **C**：让宏的值是一个字符串字面量 |

如果只写 `-DFW_VERSION="1.2.3"`，shell 会先把双引号吃掉，
传给 clang 的是 `-DFW_VERSION=1.2.3` → 宏的值是 `1.2.3`（**不是字符串**）→
`const char *fw = 1.2.3;` → 编译错误。

**Makefile 里同样要小心**：

```make
CFLAGS += -DFW_VERSION='"1.2.3"'      # ✅
CFLAGS += -DFW_VERSION="1.2.3"        # ⚠ make 也会处理引号，结果依赖 make 版本
```

更稳的写法是让宏值**不带引号**，需要字符串时在 C 里字符串化：

```c
#define STR(x)   #x
#define XSTR(x)  STR(x)
const char *fw = XSTR(FW_VERSION);     /* -DFW_VERSION=1.2.3 → "1.2.3" */
```

（`#` 的双层展开见 [12.02](12.02-带参数的宏.md)。）

### 1.2 `-U` 取消定义

```
$ clang -E -P -DCFG_BAUD=115200 -UCFG_BAUD -DCFG_BAUD=9600 cmd.c
int baud = 9600;
```

⚠ **顺序有意义**：`-U` 只取消**它之前**的定义。
上面的例子里，先 `-D` 再 `-U` 再 `-D`，最终是 9600。

## 二、怎么确认 `-D` 真的生效了：`-E -dM`

```
$ clang -E -dM -DCFG_BAUD=115200 cmd.c | grep -E "CFG_BAUD|LOG_LEVEL"
#define CFG_BAUD 115200
               ↑
         只有 CFG_BAUD，没有 LOG_LEVEL（没给 -D）
```

**`-dM` 把"当前所有已定义的宏"全打出来**——
包括编译器预定义的（ `__STDC_VERSION__`、`__clang_major__` 等）
和你用 `-D` 加的。

**排查"-D 没生效"的标准三步**：

```sh
# ① 看它到底在不在
clang -E -dM $(CFLAGS) foo.c | grep CFG_BAUD

# ② 看条件编译走了哪个分支
clang -E -P $(CFLAGS) foo.c

# ③ 对比两次（开关前后）
diff <(clang -E -P foo.c) <(clang -E -P -DCFG_X=1 foo.c)
```

⚠ **第①步最常见的问题是"Makefile 里的 CFLAGS 没传进去"**——
`clang -E -dM foo.c` 忘了加 `$(CFLAGS)`，当然看不到。

## 三、⚠ 实测：忘了给 `-D` 不是"用默认值"，是编译错误

这是书里没讲、但天天会碰到的事。

```c
int dbg = LOG_LEVEL;        /* LOG_LEVEL 打算用 -D 给 */
```

```
$ clang -fsyntax-only -DCFG_BAUD=115200 cmd.c        ← 忘了 -DLOG_LEVEL
cmd.c:1:19: error: use of undeclared identifier 'FW_VERSION'
    1 | const char *fw  = FW_VERSION;
      |                   ^~~~~~~~~~
cmd.c:3:19: error: use of undeclared identifier 'LOG_LEVEL'
2 errors generated.
```

**为什么不是"用默认值"**：

预处理器看到 `LOG_LEVEL` 时，它**不是已定义的宏** →
**原样保留**（`clang -E` 的输出里就是 `int dbg = LOG_LEVEL;`）。
然后编译器把一个**没有声明过的标识符**当成变量名 → 报"未声明"。

⚠ **区分两种情况**：

| 用法 | 忘了 `-D` 会怎样 |
|---|---|
| `int x = SYM;`（当值用） | **编译错误**：`use of undeclared identifier` |
| `#if SYM`（当条件用） | **静默当 0**！不报错（[12.04](12.04-条件编译.md) 实测） |
| `#ifdef SYM` | **静默当假**！不报错 |

**第二种最危险**：`#if LOG_LEVEL >= 2` 在忘了给 `-DLOG_LEVEL` 时
变成 `#if 0 >= 2` → 日志被**静默裁掉**，编译照过。

**对策**：必须给的宏，用 `#error` 强制（[12.05](12.05-定义符号的位置.md)）：

```c
#ifndef LOG_LEVEL
#  error "必须定义 LOG_LEVEL（如 -DLOG_LEVEL=2）"
#endif
```

## 四、为什么命令行比"写在源码里"好

| | 写在源码里 | **命令行 `-D`** |
|---|---|---|
| 换配置 | 改源码 → 产生 diff | 改 Makefile 一行 / 换一个 build target |
| 同一份代码出多个固件 | 要分支或复制 | ✅ `make BOARD=f103` / `make BOARD=f407` |
| 可复现性 | 靠人记得改了哪 | ✅ CFLAGS 在 git 里，谁编都一样 |
| 误提交风险 | ⚠ 改了 `#define` 忘了改回来 | 无 |

**典型用法——一套代码出两份固件**：

```make
# Makefile
BOARD ?= nucleo_f103rb

ifeq ($(BOARD),nucleo_f103rb)
CFLAGS += -DBOARD_NUCLEO_F103RB -DCFG_BAUD=115200
else ifeq ($(BOARD),f407_discovery)
CFLAGS += -DBOARD_F407_DISCOVERY -DCFG_BAUD=921600
endif
```

```sh
make BOARD=nucleo_f103rb      # 出一份
make BOARD=f407_discovery     # 出另一份，源码一个字没改
```

⚠ **`-D` 要写进 Makefile 的 `CFLAGS`，不要每次手敲**——
手敲的编译命令**不可复现**，两周后你自己都不知道当初编的是哪份。

## 五、`-D` 在裸机上的四个典型用途

| 用途 | 例子 |
|---|---|
| ① **选板子 / 选芯片** | `-DBOARD_NUCLEO_F103RB` |
| ② **开关功能** | `-DFEATURE_DMA=1` |
| ③ **日志级别** | `-DLOG_LEVEL=2` |
| ④ **版本号** | `-DFW_VER_MAJOR=1 -DFW_VER_MINOR=2` |

⚠ **①和③要注意**：

- ①用 `#if defined(...)` 判断（值判断没意义）；
- ③用 `#if LOG_LEVEL >= 2` 判断（值判断）；
- **别把两种混在一个宏上**（[12.04](12.04-条件编译.md) 的 `-DFOO=0` 陷阱）。

## 六、⚠ `-D` 不能做的事

| 想做的事 | 为什么不行 | 替代 |
|---|---|---|
| 定义**带参数**的宏 | `-D` 只接受 `NAME` 或 `NAME=值` | 放头文件里 |
| 定义**多行**宏 | 命令行里换行很痛苦 | 放头文件里 |
| 定义含 `#` / `##` 的宏 | shell 转义地狱 | 放头文件里 |
| 定义**函数** | 同上 | 放头文件里 |

**规则**：

> **`-D` 只用来定义"简单的值"和"开关"。
> 复杂宏一律放头文件，用 `-D` 只做"选哪套配置"。**

## 坑点（书 / 常识怎么说 / 实际是什么）

| 书 / 常识怎么说 | 实测是什么 |
|---|---|
| "`-D` 就是定义个宏" | 对，但**忘了给不是用默认值**：当值用 → 编译错误 `use of undeclared identifier`；**在 `#if` 里 → 静默当 0**（最危险） |
| "`-DFOO='"abc"'` 写法好怪" | 两层引号：外层给 shell，内层给 C。只写一层会被 shell 吃掉 |
| "`-U` 能取消任何定义" | 只取消**它之前**的。实测 `-D 115200 -U -D 9600` → 结果 9600 |
| "手敲 `-D` 就行" | ❌ 不可复现。要写进 Makefile 的 `CFLAGS` |
| "`-D` 能定义任意宏" | ❌ 带参数 / 多行 / 含 `#` `##` 的都不行，放头文件 |
| "宏在 `#if` 里没定义会报错" | ❌ **静默当 0**。实测 `#if LOG_LEVEL >= 2` 忘了 `-D` → 日志被裁掉，编译照过 |

## 代码自测

<details>
<summary>Q1：忘了给 `-D` 会怎样？三种用法三种结果。</summary>

**三种完全不同的结果，其中一种最危险。**

**① 当值用 → 编译错误（好，至少能发现）**

```c
int dbg = LOG_LEVEL;
```

```
$ clang -fsyntax-only -DCFG_BAUD=115200 cmd.c     ← 忘了 -DLOG_LEVEL
cmd.c:3:19: error: use of undeclared identifier 'LOG_LEVEL'
    3 | int dbg         = LOG_LEVEL;
      |                   ^~~~~~~~~
```

预处理器看到 `LOG_LEVEL` 不是宏 → **原样保留** →
编译器把它当成**未声明的变量名** → 报错。

**② 在 `#if` 里 → 静默当 0（⚠ 最危险）**

```c
#if LOG_LEVEL >= 2
    LOG_D("...");        /* 被裁掉了，不报错 */
#endif
```

C 标准规定：**`#if` 里未定义的标识符当作 0**。
所以 `#if LOG_LEVEL >= 2` 变成 `#if 0 >= 2` → 假 → **日志被静默裁掉**。

```
$ clang -E -P -DCFG_BAUD=115200 cmd.c
...
int has_x =
0
;                        ← 同理：#ifdef FEATURE_X 忘了 -D 就是 0
```

**编译通过、下载运行、日志没了**——而且你不会收到任何提示。

**③ 在 `#ifdef` 里 → 静默当假**

同理，`#ifdef FEATURE_X` 在忘了 `-DFEATURE_X` 时为假，不报错。

---

**为什么"静默"这么糟**：

| 用法 | 后果 | 多久能发现 |
|---|---|---|
| 当值用 | 编译错误 | 立刻 |
| `#if` 里 | **功能被裁掉** | 可能几周后才发现"日志怎么一直没输出" |

**对策：必须给的宏用 `#error` 强制**

```c
#ifndef LOG_LEVEL
#  error "必须定义 LOG_LEVEL（如 -DLOG_LEVEL=2）"
#endif
```

或者给默认值（如果确实可以有默认）：

```c
#ifndef LOG_LEVEL
#  define LOG_LEVEL 1
#endif
```

**判断该用哪个**：

- **没有合理默认值的**（板子、芯片型号）→ `#error`；
- **有合理默认值的**（日志级别、波特率）→ `#ifndef` 兜底。

⚠ **还有一个变体**给了错的值：

```sh
clang -DLOG_LEVEL=two ...        # ⚠ 拼错
```

`#if LOG_LEVEL >= 2` → `#if two >= 2` → `two` 未定义当 0 → `#if 0 >= 2` → 假。
**同样是静默的**。所以检查配置生效与否，
最可靠的方法是 `clang -E -P $(CFLAGS) foo.c` 看展开结果。
</details>

<details>
<summary>Q2：怎么确认 `-D` 真的生效了？</summary>

**三步，从粗到细。**

**① `clang -E -dM` —— 看宏在不在**

```
$ clang -E -dM -DCFG_BAUD=115200 cmd.c | grep -E "CFG_BAUD|LOG_LEVEL"
#define CFG_BAUD 115200
```

`-dM` 把**当前所有已定义的宏**全打出来（含编译器预定义的）。
grep 不到就说明**真的没定义**。

⚠ **最常见的原因不是 `-D` 写错了，而是忘了把 CFLAGS 传进去**：

```sh
clang -E -dM foo.c                    # ❌ 没带 CFLAGS，当然没有
clang -E -dM $(CFLAGS) foo.c          # ✅
```

**② `clang -E -P` —— 看条件编译走了哪个分支**

```
$ clang -E -P -DFEATURE_X cmd.c
int has_x =
1
;
```

直接看输出里是 `1` 还是 `0`，不用猜。

**③ `diff` 两次展开 —— 看这个开关到底影响了什么**

```sh
diff <(clang -E -P foo.c) <(clang -E -P -DCFG_X=1 foo.c)
```

这招在"某个功能莫名其妙出现了/消失了"时最好用——
一眼看出这个宏**实际改变了哪些代码**。

---

**顺带：查编译器预定义了哪些宏**

```
$ clang -E -dM -x c /dev/null | grep __STDC_VERSION__
#define __STDC_VERSION__ 201710L        ← C17（本机 clang 23.1.0）
```

交叉编译时特别有用：

```
$ clang --target=armv7m-none-eabi -mcpu=cortex-m3 -mthumb -E -dM -x c /dev/null | grep __ARM
```

——**不用去猜"编译器认不认识 `__ARM_ARCH_7M__` 这类宏"**，
`-dM` 一次列全。这类宏在写"一份代码适配多个 Cortex-M 核"时天天用：

```c
#if defined(__ARM_ARCH_7M__) || defined(__ARM_ARCH_7EM__)
    /* M3/M4/M7：有 IT 指令、有硬件除法 */
#elif defined(__ARM_ARCH_6M__)
    /* M0：没有硬件除法（ch09 实测过 udiv 的差异） */
#endif
```

**一句话**：**`-dM` 是宏世界的 `ls`，`-E -P` 是宏世界的 `cat`。**
排查宏问题的顺序永远是：先 `ls`（在不在），再 `cat`（是什么）。
</details>

<details>
<summary>Q3：为什么 `-D` 要写进 Makefile，不能手敲？</summary>

**因为手敲的编译命令不可复现。**

**场景**：你在调试，手敲了一条长命令：

```sh
clang --target=armv7m-none-eabi -mcpu=cortex-m3 -mthumb -ffreestanding -Os \
      -DBOARD_NUCLEO_F103RB -DCFG_BAUD=115200 -DLOG_LEVEL=2 \
      -c main.c -o main.o
```

两周后你想"复现当时的固件"，问题来了：

- 那条命令在 shell history 里，但**混在几百条命令中间**；
- 你当时可能**试过好几个 `-D` 组合**，不知道哪个是最后用的；
- 同事要编同样的东西，**无从得知你用了什么**。

**写进 Makefile 之后**：

```make
BOARD ?= nucleo_f103rb

ifeq ($(BOARD),nucleo_f103rb)
CFLAGS += -DBOARD_NUCLEO_F103RB -DCFG_BAUD=115200
else ifeq ($(BOARD),f407_discovery)
CFLAGS += -DBOARD_F407_DISCOVERY -DCFG_BAUD=921600
endif

CFLAGS += -DLOG_LEVEL=$(LOG_LEVEL)
```

**四个好处**：

| 好处 | 说明 |
|---|---|
| **可复现** | CFLAGS 在 git 里，`git clone` 后编出来的就是同一个东西 |
| **可切换** | `make BOARD=f407_discovery` 一份代码出两份固件 |
| **可审查** | code review 能看到"发布版用的是什么配置" |
| **可自动化** | CI 能 `make BOARD=xxx` 批量出所有板子的固件 |

⚠ **一个常见错误**：把 `-D` 写在 `.c` 里当"临时配置"。

```c
#define CFG_BAUD  9600        /* ⚠ "先改一下试试" */
```

——改完忘了删（或者删了但 git 里有别的分支还留着），
而且**它和 `board.h` 里的定义冲突时只有警告**（[12.05](12.05-定义符号的位置.md) 实测）。

**规则**：

> **任何"换一次编译就换一份"的东西，只能出现在 Makefile 的 `CFLAGS` 里。**
> 源码里的 `#define` 只放"这个模块自己的、永远不变的"东西。

**顺带：Makefile 里的引号**

```make
CFLAGS += -DFW_VERSION='"1.2.3"'      # ✅ 外层单引号给 shell
```

make 本身也会处理引号，`CFLAGS += -DFW_VERSION="1.2.3"` 的
**结果依赖 make 的版本**，不可靠。
更稳的做法是**让宏值不带引号**，C 里用 `XSTR()` 字符串化
（[12.02](12.02-带参数的宏.md)）：

```c
#define STR(x)  #x
#define XSTR(x) STR(x)
const char *fw = XSTR(FW_VERSION);     /* -DFW_VERSION=1.2.3 → "1.2.3" */
```
</details>
