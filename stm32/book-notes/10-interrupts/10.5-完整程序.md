# 10.5 完整程序

> 对应实验：`--target=armv7m-none-eabi -mcpu=cortex-m3 -mthumb -ffreestanding`（完整骨架 `-Os` + `llvm-size`）

## 书这一节讲什么

一句话：**把前四节的零件装成一个完整程序**——
初始化 + 中断使能 + ISR + 环形缓冲 + 主循环。

书给的是一个能跑的完整例子。这里给的是**本仓库的版本**，
并且把"每部分分别占多少资源"测出来——因为完整程序最容易出的问题不是逻辑错，
而是**装起来之后 Flash/栈超了**。

## 一、完整骨架（USART1 接收中断）

```c
#include <stdint.h>
#include <stddef.h>

/* ---------- 寄存器（ch08 8.12 的风格：这里用宏，结构体检完再换） ---------- */
#define RCC_APB2ENR (*(volatile uint32_t *)0x40021018u)
#define GPIOA_CRH   (*(volatile uint32_t *)0x40010804u)
#define USART1_SR   (*(volatile uint32_t *)0x40013800u)
#define USART1_DR   (*(volatile uint32_t *)0x40013804u)
#define USART1_BRR  (*(volatile uint32_t *)0x40013808u)
#define USART1_CR1  (*(volatile uint32_t *)0x4001380Cu)
#define NVIC_ISER1  (*(volatile uint32_t *)0xE000E104u)

#define RXNE   (1u << 5)
#define TXE    (1u << 7)
#define RXNEIE (1u << 5)

#define PCLK2_HZ  8000000u
#define UART_BAUD 115200u
#define UART_BRR_VAL ((PCLK2_HZ + UART_BAUD/2u) / UART_BAUD)   /* 编译期 = 69 */

/* ---------- 环形缓冲（10.4） ---------- */
#define RB_SIZE 64u
_Static_assert((RB_SIZE & (RB_SIZE - 1u)) == 0u, "RB_SIZE 必须是 2 的幂");

typedef struct { volatile uint32_t head, tail; uint8_t buf[RB_SIZE]; } ringbuf_t;
static ringbuf_t g_rx_rb;
static volatile uint32_t g_rx_overflow;      /* 溢出计数：必须的 */

static int rb_put(ringbuf_t *rb, uint8_t c){
    uint32_t next = (rb->head + 1u) & (RB_SIZE - 1u);
    if (next == rb->tail) return -1;
    rb->buf[rb->head] = c;
    rb->head = next;
    return 0;
}
static int rb_get(ringbuf_t *rb, uint8_t *c){
    if (rb->head == rb->tail) return -1;
    *c = rb->buf[rb->tail];
    rb->tail = (rb->tail + 1u) & (RB_SIZE - 1u);
    return 0;
}

/* ---------- ISR（10.3）：只入队 ---------- */
void USART1_IRQHandler(void){
    if (USART1_SR & RXNE) {
        uint8_t c = (uint8_t)USART1_DR;      /* 读 DR 自动清 RXNE */
        if (rb_put(&g_rx_rb, c) != 0) g_rx_overflow++;
    }
}

/* ---------- 初始化：时钟 → 引脚 → BRR → CR1 → 两道门 ---------- */
static void uart1_init(void){
    RCC_APB2ENR |= (1u<<2) | (1u<<14);                 /* ① 时钟 */
    GPIOA_CRH &= ~(0xFu<<4); GPIOA_CRH |= (0xBu<<4);   /* ② PA9 AF-PP */
    GPIOA_CRH &= ~(0xFu<<8); GPIOA_CRH |= (0x4u<<8);   /*    PA10 浮空输入 */
    USART1_BRR = UART_BRR_VAL;                         /* ③ 69（编译期常量） */
    USART1_CR1 = (1u<<13)|(1u<<3)|(1u<<2);             /* ④ UE+TE+RE */
    USART1_CR1 |= RXNEIE;                              /* 门 1：外设 IE */
    NVIC_ISER1  = (1u << (37u - 32u));                 /* 门 2：NVIC */
}

/* ---------- 发送：轮询（10.1） ---------- */
static void uart1_putc(char c){
    while ((USART1_SR & TXE) == 0u) { }
    USART1_DR = (uint32_t)(uint8_t)c;
}
static void uart1_puts(const char *s){ while (*s) uart1_putc(*s++); }

/* ---------- 主循环：取出来慢慢处理 ---------- */
static void process(uint8_t b){ (void)b; /* 协议解析在这里，可以慢 */ }

int main(void){
    uart1_init();
    uart1_puts("boot\n");
    for (;;) {
        uint8_t b;
        while (rb_get(&g_rx_rb, &b) == 0) process(b);   /* 排空缓冲 */
        /* 别的活 */
    }
}
```

## 二、实测：这个程序占多少资源

把上面编译一遍（去掉 `main` 里的循环，只测代码体积）：

```
$ clang --target=armv7m-none-eabi -mcpu=cortex-m3 -mthumb -ffreestanding -Os -c full.c
$ llvm-size full.o
   text    data     bss     dec     hex filename
    294       0      76     370     172 full.o

$ llvm-nm --print-size --defined-only full.o
00000000 00000020 T rb_put                 ←  32 字节
00000020 00000024 T rb_get                 ←  36 字节
00000044 00000042 T USART1_IRQHandler      ←  66 字节
00000086 00000014 T uart1_putc             ←  20 字节
0000009a 00000064 T uart1_init             ← 100 字节
00000000 00000048 b g_rx_rb                ←  72 字节（.bss）
00000048 00000004 b g_rx_overflow          ←   4 字节（.bss）

$ llvm-nm -u full.o
（空 —— 零外部依赖）
```

汇总：

| 部件 | Flash（`-Os` 实测） | 栈（`-fstack-usage`，`-Os`） |
|---|---|---|
| `rb_put` | **32 字节** | **0** |
| `rb_get` | **36 字节** | **0** |
| `USART1_IRQHandler` | **66 字节** | 0 |
| `uart1_putc` | **20 字节** | 0 |
| `uart1_init` | **100 字节** | 0 |
| 合计 `.text` | **294 字节** | — |
| **RAM（`.bss`）** | — | `g_rx_rb` 72 + `g_rx_overflow` 4 = **76 字节** |
| `mini_printf` 全家桶（[ch09](../09-uart-serial/9.3-串行输出.md)） | 340 字节 | 40 |

**整个"中断接收 + 轮询发送"机制的成本**：**294 字节 Flash + 76 字节 RAM**，
ISR 路径 **0 字节栈**。在 128 KB Flash / 20 KB RAM 上完全不算什么。

⚠ 但要注意 **ISR 的栈是叠加的**：硬件压 32 字节 + ISR 自身帧。
所以栈预算要按"最深调用链 + 32 + ISR 帧"算（[ch07](../07-stack-frame-functions/README.md)）。

## 三、装配清单：五步自检

每次写完中断程序，按这个顺序自查（**每一步都有"漏了会怎样"的实测依据**）：

| # | 检查项 | 漏了会怎样 |
|---|---|---|
| 1 | 外设时钟开了吗 | **静默失败**（ch03） |
| 2 | 引脚配成复用模式了吗 | 引脚有电平但不是 UART 波形（ch09 9.5） |
| 3 | BRR 算对了吗（用哪个 PCLK） | 乱码（ch09 9.4） |
| 4 | **两道门**都开了吗（外设 IE + NVIC_ISER） | **静默不进中断**（10.2） |
| 5 | ISR 名字和向量表一致吗 | 链接到默认 handler（ch03 实测的弱别名） |

第 4 步是最容易漏的——它和"漏开时钟"并列为裸机两大静默失败。

## 四、从"能跑"到"能交付"

完整程序还差三件事（书没讲，但工程上必须有）：

**① 溢出计数（必须）**

```c
if (rb_put(&g_rx_rb, c) != 0) g_rx_overflow++;    /* 静默丢数据 → 可观测 */
```

**② 错误标志处理**

`USART_SR` 里还有 **ORE（溢出错误）、NE（噪声）、FE（帧错误）、PE（奇偶错误）**。
如果只检查 RXNE 而不检查这些：

```c
void USART1_IRQHandler(void){
    uint32_t sr = USART1_SR;
    if (sr & (ORE|NE|FE)) { (void)USART1_DR; g_uart_err++; return; }  /* 读了 DR 才能清 */
    if (sr & RXNE) { ... }
}
```

⚠ **ORE 的清除要求"读 SR 后读 DR"**——不读 DR 清不掉，会一直触发。
这是"只读 RXNE 不读错误标志"导致 ISR 风暴的另一个来源。

**③ 超时 / 帧边界**

UART 是字节流，没有帧概念。协议层要自己定帧边界（[ch09 9.1 Q1](../09-uart-serial/9.1-一次写一个字符的字符串.md)）：
定长 / 分隔符（`\n`）/ 长度前缀。

## 坑点（书 / 常识怎么说 / 实际是什么）

| 书 / 常识怎么说 | 实际是什么 |
|---|---|
| "完整程序就是拼起来" | 拼起来最容易出的是**资源超限**和**静默失败**。按五步自检逐项查 |
| "ISR 检查一下 RXNE 就行" | ⚠ 还要处理 **ORE/NE/FE**。而且 ORE 要"读 SR 后读 DR"才清得掉 |
| "缓冲满了丢掉就行" | 静默丢数据。**必须有 `g_rx_overflow` 计数** |
| "这个程序占资源不多" | 实测：**294 字节 `.text` + 76 字节 `.bss`**，ISR 路径 0 字节栈。但 ISR 会额外叠 32 字节硬件帧（`rb_put` 32 B / `rb_get` 36 B / ISR 66 B / `uart1_init` 100 B） |
| "USART1 是板载串口" | NUCLEO-F103RB 上是 **USART2(PA2/PA3)** 接 ST-Link（ch09 9.5 Q3） |

## 代码自测

<details>
<summary>Q1：调试器里看"中断到底进没进"，该看哪些寄存器？</summary>

按"请求传播的路径"逐段查，每一段都有对应的寄存器：

```
外设事件 → 外设 SR → 外设 IE → NVIC_ISPR → NVIC_ISER → CPU（NVIC_IABR）
```

| 步骤 | 寄存器 | 怎么看 | 含义 |
|---|---|---|---|
| ① 事件发生了吗 | `USART1_SR`（`0x40013800`） | bit5 RXNE | 为 1 = 收到字节了 |
| ② 门 1 开了吗 | `USART1_CR1`（`0x4001380C`） | bit5 RXNEIE | 为 1 = 外设会发请求 |
| ③ 请求挂起了吗 | `NVIC_ISPR1`（`0xE000E204`） | bit5 | 为 1 = **NVIC 收到请求但 CPU 还没响应** |
| ④ 门 2 开了吗 | `NVIC_ISER1`（`0xE000E104`） | bit5 | 为 1 = NVIC 会把请求给 CPU |
| ⑤ 正在执行吗 | `NVIC_IABR1`（`0xE000E304`） | bit5 | 为 1 = **ISR 正在跑**（或卡住了） |

**诊断表**：

| 现象 | 结论 |
|---|---|
| ①=0 | 压根没收到字节（硬件/波特率问题） |
| ①=1, ②=0 | **门 1 没开** |
| ②=1, ③=1, ④=0 | **门 2 没开** ← 最常见的漏项 |
| ③=1, ④=1, ⑤=0 | 优先级太低（被更高优先级中断挡着）或 CPU 在临界区 |
| ⑤=1 一直为 1 | **ISR 卡住了**（多半是中断标志没清掉 → 无限重入） |

gdb 里这么看（[ch03](../03-embedded-system-programming/README.md) 实测过同类读法）：

```
(gdb) x/1xw 0x40013800      # USART1_SR
(gdb) x/1xw 0x4001380C      # USART1_CR1
(gdb) x/1xw 0xE000E204      # NVIC_ISPR1
(gdb) x/1xw 0xE000E104      # NVIC_ISER1
(gdb) x/1xw 0xE000E304      # NVIC_IABR1
```

⚠ **注意 `ISR` 和 `IABR` 的区别**：
- `ISPR`（Interrupt **Set** Pending）= 有请求等待处理；
- `IABR`（Interrupt **Active** Bit）= 正在执行。

正常流程是 ISPR 置 1 → 开始执行 → ISPR 清 0、IABR 置 1 → 执行完 → IABR 清 0。
**如果 ISPR 一直是 1**：请求压根没被响应（门 2 或优先级问题）。
**如果 IABR 一直是 1**：ISR 没返回（标志没清 / 死循环）。

**最强的一招仍然是"绕过代码直接写寄存器"**（[ch09 9.7 Q3](../09-uart-serial/9.7-Linux和macOS与设备通信.md)）：
往 `USART1_DR` 写个 `'A'` 看主机能不能收到——把问题一刀切成两半。
</details>

<details>
<summary>Q2：为什么 ORE（溢出错误）会导致 ISR 风暴？怎么处理？</summary>

因为 **ORE 的清除需要"读 SR 之后读 DR"**，而很多人只读了 RXNE 分支的 DR。

**ORE 是什么**：上一个字节还在 DR 里没被读走，新字节又来了 → 硬件置 ORE。

**正确的处理**：

```c
void USART1_IRQHandler(void){
    uint32_t sr = USART1_SR;                       /* ① 一定要先读 SR */
    if (sr & (ORE | NE | FE | PE)) {
        (void)USART1_DR;                           /* ② 再读 DR —— 两步都做才清得掉 */
        g_uart_err++;
        return;
    }
    if (sr & RXNE) {
        uint8_t c = (uint8_t)USART1_DR;
        if (rb_put(&g_rx_rb, c) != 0) g_rx_overflow++;
    }
}
```

**风暴是怎么形成的**：

```c
/* ❌ 只处理 RXNE */
void USART1_IRQHandler(void){
    if (USART1_SR & RXNE) { rb_put(&g_rx_rb, (uint8_t)USART1_DR); }
}
/* ORE 置位后：
   - 没有分支处理它
   - ORE 本身会触发中断（如果开了 EIE）或者一直挂着
   - 即使没开 EIE，ORE 未清时 RXNE 的行为也可能异常
   → ISR 反复进入，主循环饿死 */
```

⚠ 更隐蔽的版本：**ISR 里只读了 SR，没读 DR**。

```c
if (USART1_SR & RXNE) { /* 忘了读 DR */ }   /* RXNE 清不掉 → 无限重入 */
```

这和 [10.3 Q1](10.3-中断例程.md) 讲的"标志没清"是同一类问题：
**USART 的 RXNE 靠"读 DR"清除，光读 SR 没用**。

**工程上的三条建议**：

1. **ISR 里先读一次 SR 到局部变量**，然后所有判断都用这个快照——
   避免多次读 SR 导致标志状态不一致；
2. **错误分支一定要读 DR**（哪怕是丢弃）；
3. **给错误计数**（`g_uart_err++`）——ORE 意味着你**丢过字节**，
   静默丢数据是最难查的那类 bug。

**什么时候会见到 ORE**：
- 波特率高而 ISR 慢；
- 主循环关中断太久（临界区里跑了慢代码）；
- 有更高优先级的中断长时间占用 CPU。

所以 ORE 计数不只是"错误处理"，它还是**实时性是否达标的指标**——
看到 `g_uart_err` 在涨，说明你的系统有实时性问题，而不只是"串口有点脏"。
</details>

<details>
<summary>Q3：这个完整程序还有什么"书没讲但工程必须有"的东西？</summary>

三样，按重要性：

**① 溢出/错误计数（必须有）**

```c
static volatile uint32_t g_rx_overflow;   /* 缓冲满 */
static volatile uint32_t g_uart_err;      /* ORE/NE/FE */
```

理由：环形缓冲满了会**静默丢字节**。不计数的话，
表现出来就是"协议偶尔解错一帧"——你能查一星期。
有了计数，一次 `printf` 就知道是不是丢过。

**② 帧边界（协议层必须有）**

UART 是**字节流**，没有"一帧"的概念。
你收到的是一串字节，什么时候算一帧结束？三种做法：

| 做法 | 适用 |
|---|---|
| 分隔符（日志用 `\n`） | 文本、命令行 |
| 定长 | 二进制 |
| 长度前缀 | 变长二进制 |

```c
/* 行缓冲：收到 '\n' 就提一帧 */
static char line[128]; static unsigned n;
void on_byte(uint8_t b){
    if (b == '\n' || n >= sizeof(line) - 1) { line[n] = '\0'; handle_line(line); n = 0; }
    else line[n++] = (char)b;
}
```

⚠ `n >= sizeof(line) - 1` 这个长度检查**不能省**——
裸机上缓冲区溢出是静默的（[ch06 6.4](../06-arrays-pointers-strings/6.4-数组溢出.md) 实测）。

**③ 超时（实时系统必须有）**

```c
/* 一帧不能在 100 ms 内收完就丢弃重来 */
static uint32_t g_last_byte_ms;
if (now_ms() - g_last_byte_ms > 100) { n = 0; }   /* 超时重置 */
```

没有超时的话，一个残缺的帧会**永远卡在缓冲区里**，
把后续所有帧都污染掉。

**再往下（书完全没提，但会遇到的）**：

| 主题 | 说明 |
|---|---|
| **DMA** | 波特率高或者数据量大时，ISR 不够用（921600 下预算只有 1.1 µs） |
| **流控** | 没有 RTS/CTS 时，主机发太快会丢。要么硬件流控，要么协议层 ACK |
| **优先级规划** | 多个中断时的优先级分配（SysTick 要设低） |
| **RTOS 集成** | `xQueueSendFromISR`（ch20） |
| **低功耗** | 主循环没事干时 `wfi` 睡下去，靠中断唤醒 |

**一句话**：书里这个程序是"能跑的"，
离"能交付"还差**可观测性（计数）+ 协议边界（帧）+ 健壮性（超时）**这三样。
</details>
