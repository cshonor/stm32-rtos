# 5.05 for

> 书：第 5 章 决策和控制语句 · 5.05 for（原书 p65–77 区间内）
> 上一篇：[5.04 while](5.04-while.md) ｜ 下一篇：[5.06 使用按钮](5.06-使用按钮.md)
> 对应实验：`--target=armv7m-none-eabi -mcpu=cortex-m3`（-O0 / -O2 / -Os 三档对比）

## 书这一节讲什么

一句话：**`for (初始化; 条件; 递增)` 把循环的三件事写在一行**，
适合"已知次数"的循环。

书讲语法。裸机上 `for` 有个专属的重灾区——**拿空 `for` 循环当延时用**。
这在 PC 上是"不准"，在裸机上是"**可能被整个删掉**"。

## 一、实测：空 `for` 循环在不同优化等级下的命运

```c
void d0(void){ for (int i = 0; i < 1000; i++) { } }          /* 普通变量 */
void d1(void){ for (volatile int i = 0; i < 1000; i++) { } }  /* volatile 变量 */
```

```
$ clang --target=armv7m-none-eabi -mcpu=cortex-m3 -mthumb -O0 -c delay.c
00000000 <d0>:
       sub sp,#4 / movs r0,#0 / str r0,[sp]
   8:  ldr r0,[sp] / cmp.w r0,#0x3e8 / bge 0x1c
  10:  b 0x12 / b 0x14
  14:  ldr r0,[sp] / adds r0,#1 / str r0,[sp] / b 0x8      ← 真循环，22 条指令
  1c:  add sp,#4 / bx lr

$ clang ... -O2 -c delay.c
00000000 <d0>:
       0: 4770     bx  lr        ← 循环整个消失
00000004 <d1>:  （保留真循环）

$ clang ... -Os -c delay.c
00000000 <d0>:
       0: 4770     bx  lr        ← 同样消失
00000002 <d1>:  （保留真循环）
```

**`-O2` / `-Os` 下，普通变量的空循环被删得只剩一条 `bx lr`。**
也就是说：你写的延时函数**在打开优化之后变成 0 延时**——
表现为"程序逻辑全对，但 LED 闪得飞快/外设时序全乱"。

加 `volatile` 的版本（`d1`）在每个优化等级下都保留了真实的循环。
这就是 [4.03 赋值](../04-numbers-and-bitops/4.03-赋值.md) 里那句
"`volatile` 只保证访问不被优化掉"的实际用途之一。

## 二、但 `volatile` 延时仍然是错的

保留了循环 ≠ 延时准确。三个原因：

1. **指令数随优化等级变**（实测 `-O0` 22 条、`-Os` 13 条），
   同样的 C 代码，延时差一倍；
2. **时钟频率不确定**：上电默认 HSI 8 MHz，配了 PLL 变 72 MHz，
   同一个循环差 9 倍；
3. **Flash 等待周期**：STM32F1 在 72 MHz 下要插等待周期，
   取指速度不是线性于主频的。

正解是**用硬件定时器**（[ch19 SysTick](../19-systick-and-timer/19.04-三种等待的对比.md)）：
`SysTick` 每 1 ms 打一次，软件读它的计数，跟主频和优化等级都无关。

## 三、`for` 的三个经典陷阱

**① 倒序循环 + unsigned = 死循环**

```c
for (unsigned i = n; i >= 0; --i) { }     /* ❌ i >= 0 恒真 */
for (unsigned i = n; i-- > 0; ) { }       /* ✅ 惯用写法 */
```
（[4.08 无符号整数类型](../04-numbers-and-bitops/4.08-无符号整数类型.md) 展开过）

**② 循环变量用 `uint8_t`**

`uint8_t` 上限 255，`i <= 255` 恒成立 → 死循环；
而且每次运算会被整型提升再截断，多生成指令。用 `uint32_t`。

**③ 在循环条件里做 I/O**

```c
for (int i = 0; i < 10 && (USART1_SR & RXNE); i++)   /* 每个条件判断都读一次 SR */
```
每次判断都真实访问硬件，次数不直观、还可能吃掉数据。

## 四、`for` 和 `while` 怎么选

实测（[5.03](5.03-循环.md)）：**两者机器码完全相同**。所以只看可读性：

| 形态 | 用 |
|---|---|
| 次数已知、要一个下标 | `for (i = 0; i < n; i++)` |
| 遍历数组/缓冲区 | `for` |
| 等到某个条件 | `while` |
| 先做一次再判断 | `do-while` |

## 坑点（书 / 常识怎么说 / 实际是什么）

| 书 / 常识怎么说 | 实际是什么 |
|---|---|
| "`for` 就是计数循环" | 对，但它也常被误用成"延时循环"，而**空循环在 `-O2/-Os` 下会被整个删掉**（实测 `bx lr`） |
| "加个 `volatile` 就能当延时" | 循环保住了，但**延时不准**：实测 `-O0` 22 条指令 vs `-Os` 13 条，且随主频变 |
| "`for (unsigned i=n; i>=0; --i)` 很自然" | ❌ 死循环（`i>=0` 恒真），用 `i-- > 0` |
| "循环变量用小类型省内存" | `uint8_t` 会被整型提升 + 截断，反而多指令，且容易死循环 |
| "`for` 比 `while` 快" | 实测机器码完全相同（[5.03](5.03-循环.md)） |

## 代码自测

<details>
<summary>Q1：为什么 `-O0` 能跑的延时，开 `-O2` 就不延时了？</summary>

因为**空循环体 + 非 volatile 变量 = 编译器可以证明这个循环没有任何可观察效果**，
于是整个删掉。

实测对照：

```
-O0:  d0 = 22 条指令的真实循环（规规矩矩 ldr/cmp/adds/str/b）
-O2:  d0 = 一条 bx lr
-Os:  d0 = 一条 bx lr
d1（volatile int i）: 三档都保留真实循环
```

编译器的推理：`i` 是局部变量，循环里除了 `i` 自己没有任何东西被修改，
循环结束后 `i` 就消失了 → **这个循环对程序的可观察行为没有任何贡献** → 删掉。

`volatile` 的作用在这里是"**每一次写 `i` 都是可观察行为，不许删**"，
所以循环被保留。但要清楚：这只是让循环**存在**，没有让它**准确**——
延时还是要靠定时器。

调试这类问题的第一反应应该是：
**"我有没有依赖编译器不负责任何东西？"** 空循环、空 `while` 等待、
"变量反正会被 ISR 改"——这三处是 `volatile` 缺失的重灾区。
</details>

<details>
<summary>Q2：裸机上到底怎么写延时？</summary>

按可靠性排序：

**① 硬件定时器（唯一正确的做法）**

```c
/* SysTick 配置为 1ms 中断，中断里 ticks++ */
static volatile uint32_t ticks;
void delay_ms(uint32_t ms){
    uint32_t start = ticks;
    while ((uint32_t)(ticks - start) < ms) { __asm__ volatile("wfi"); }
}
```

注意 `(uint32_t)(ticks - start)` 用**差值**比较——
即使 `ticks` 在延时期间回绕，差值依然正确
（[4.08](../04-numbers-and-bitops/4.08-无符号整数类型.md) 讲过 unsigned 回绕）。
`（[ch19](../19-systick-and-timer/19.02-配置成1ms心跳.md) 讲 SysTick 怎么配）`

**② 定时器 + `wfi`**：上面那段已经用了——延时期间 CPU 睡觉，不耗电。

**③ 循环 + 已知周期数（只在启动早期可用）**

时钟还没配好、中断还没开时（比如初始化阶段等 PLL 锁定），
可以用循环，但要：

- 循环变量 `volatile`；
- 注释写清"这是 HSI 8MHz 下的大约值，配了 PLL 就不准"；
- 更好的是**等硬件标志**（`while (!(RCC_CR & HSERDY))`），而不是数时间。

**④ 禁止：普通空循环延时。** 实测开优化就没了，且随主频和优化等级变。
</details>

<details>
<summary>Q3：`for (int i = 0; i < n; i++)` 里 `int` 该换成什么？</summary>

`uint32_t`（或 `size_t` 用于数组下标）。三个理由：

1. **上限**：`int` 是 signed，溢出是 UB（[4.09](../04-numbers-and-bitops/4.09-溢出.md)）；
   `uint32_t` 溢出是定义好的回绕。
2. **别用 `uint8_t`/`uint16_t`**：上限太小容易死循环，
   且运算时被整型提升成 `int` 再截断，多生成指令。
3. **和 `sizeof` 一致**：`sizeof` 返回 `size_t`（unsigned），
   用 `int` 比较会有 `-Wsign-compare`，负值还会被提升成巨大正数。

数组遍历的标准写法：

```c
for (size_t i = 0; i < sizeof buf / sizeof buf[0]; i++) { ... }
```

倒序遍历（需要下标从大到小时）：

```c
for (size_t i = n; i-- > 0; ) { /* 使用 i */ }     /* i 从 n-1 到 0 */
```

`i-- > 0` 这个写法看着奇怪，但它是 unsigned 倒序的唯一简洁写法：
判断用的是"自减之前的值"，且不需要 `>= 0`（对 unsigned 恒真的那个陷阱）。
</details>
