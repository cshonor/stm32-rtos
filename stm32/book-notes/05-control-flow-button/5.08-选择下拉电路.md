# 5.08 选择下拉电路

> 上一篇：[5.07 初始化](5.07-初始化.md) ｜ 下一篇：[5.09 获取按钮状态](5.09-获取按钮状态.md)

## 书这一节讲什么

一句话：**按键松开时，引脚必须通过一个电阻接到确定的电平（VDD 或 GND）**，
否则引脚悬空、电平不确定。书选了**下拉**电路。

这是全书少有的**纯硬件**一节，也是很多人第一次意识到
"**没连接 ≠ 低电平**"这件事的地方。

## 一、电路图与真值表

```
VDD ──┬──[ 10k 上拉 ]──┬── PA0 ──┐
      │                │         │
      │           [ 按键开关 ]────┴── GND
```

| 状态 | 开关 | 引脚通过什么接到哪 | 读到 |
|---|---|---|---|
| 按下 | 闭合 | 直接接 GND | **0** |
| 松开 | 断开 | 经 10k 电阻接 VDD | **1** |

**关键**：松开时引脚不是"断开了"，而是**通过电阻接到 VDD**——
所以有一个确定的、需要一点点电流才能改变的电平。

上拉/下拉两种：

| 电路 | 空闲电平 | 按下电平 | 代码 |
|---|---|---|---|
| 上拉（pull-**up**） | 1 | **0** | `(IDR & BIT) == 0` |
| 下拉（pull-**down**，书里用这种） | 0 | **1** | `(IDR & BIT) != 0` |

## 二、为什么必须有这个电阻：悬空引脚是天线

CMOS 输入引脚的输入阻抗极高（MΩ 级），
**引脚上感应的电荷没有泄放路径**，于是：

- 手靠近 → 电平变；
- 旁边的走线翻转 → 电平变；
- 湿度变化 → 电平变。

实测上表现为"按键没按，程序却偶尔触发"——
这类偶发故障在裸机上极难查，因为它跟代码无关。

> ⚠ 本篇没有在真机上测"悬空读到的随机值"（实验待建），
> 上面是 CMOS 输入的普遍特性，不是本仓库的实测数字。

## 三、内部电阻 vs 外部电阻

STM32 内部就集成了上/下拉电阻（典型值 30–50 kΩ，具体看 Datasheet），
可以省掉一个外部元件：

| | 内部 | 外部 |
|---|---|---|
| 元件 | 0 | 1 个电阻（通常 4.7k–10k） |
| 阻值精度 | 差（±30% 以上，典型 40 kΩ） | 准 |
| 适用 | 按键这种慢速、低噪声场景 | 长线、噪声环境、需要确定上升时间（I²C 等） |
| 配置 | F1：输入模式下写 `ODR` 位；F0/F4：写 `PUPDR` | 不用配（但要**别**重复配内部） |

**F1 特有的坑**（实测 5.7 的第 ③ 步）：

```c
GPIOA_CRL &= ~(0xFu << 0);
GPIOA_CRL |=  (0x8u << 0);   /* CNF=10 = 上/下拉输入 MODE=00 = 输入 */
GPIOA_ODR |=  (1u << 0);     /* F1：输入模式下 ODR 位 = 1 → 上拉，= 0 → 下拉 */
```

F1 **没有独立的 `PUPDR` 寄存器**，靠 `ODR` 位兼任。
漏掉最后一行 = 配成了"上/下拉输入"但没选是哪一种 → **实际是浮空**。
F0/F4 有 `PUPDR`（每引脚 2 位：00 无、01 上拉、10 下拉），不共用 `ODR`。

## 四、怎么选上拉还是下拉

按优先级：

1. **先看原理图**。板子上已经焊了什么就用什么，猜是没用的；
2. **没外部电阻就开内部的**（省元件，按键这种慢信号够用）；
3. **安全相关选上拉**：断线/接触不良会被读成"按下"（**显性故障**），
   而不是"没按"（隐性故障，可能掩盖故障）。这和工业 PLC 的惯例一致。

## 坑点（书 / 常识怎么说 / 实际是什么）

| 书 / 常识怎么说 | 实际是什么 |
|---|---|
| "按键按下读到 1" | 那是因为书用了**下拉**。上拉电路（Nucleo 板上常见）按下读 **0** |
| "引脚没接就是低电平" | ❌ 悬空 = 天线，电平由感应电荷决定，会随机跳变 |
| "内部有上拉就不用管了" | 要**显式配置**：F1 写 `ODR` 位（易漏），F0/F4 写 `PUPDR` |
| "板上焊了外部电阻，再开内部更保险" | ❌ 两个电阻**并联**，实际阻值变小、电流变大；而且电平可能不符合预期。二选一 |
| "上下拉阻值随便选" | 太大 → 上升沿慢、抗噪声差；太小 → 按下时电流大（10k/3.3V 约 0.33 mA）。常用 4.7k–10k |

## 代码自测

<details>
<summary>Q1：上拉和下拉，工程上该选哪个？</summary>

三个考量，按顺序：

**① 板子上已经有什么？** 这一条压倒一切。
看原理图——NUCLEO 板的用户按键通常已经带外部上拉，你只管读就行；
自己画的板子则看你在哪一侧放了电阻。

**② 没外部电阻时的默认选择：上拉。**
理由是**故障显性**：

| 电路 | 断线/接触不良时读到 | 后果 |
|---|---|---|
| 上拉 | **0 = 按下** | 设备报"按键卡住"，故障被发现（fail-safe） |
| 下拉 | 0 = 没按 | 故障被掩盖，看起来一切正常（fail-dangerous） |

工业控制（PLC 的漏型/源型输入）也普遍遵循这个思路：
让"线路断了"表现为"触发"而不是"正常"。

**③ 电流和功耗**：
上拉电阻在按键按下期间会一直有电流流过
（10 kΩ / 3.3 V ≈ 0.33 mA；内部 40 kΩ 约 0.08 mA）。
电池供电的设备要考虑这一点——
可以用"按键按下时才把上拉打开"的轮询策略，或者直接走中断唤醒。

反过来说，内部 40 kΩ 上拉驱动的上升沿较慢，
用在 I²C 这种对上升时间有要求的总线上通常**不够**——那是外部电阻的场合（常见 2.2k–4.07k）。
</details>

<details>
<summary>Q2：STM32 内部上/下拉在 F1 上怎么配？我配了 CNF=10 为什么还是浮空？</summary>

因为**F1 还要额外写 `ODR` 的对应位**——这是 F1 和 F0/F4 最大的区别之一。

F1 的完整三步（实测 5.7）：

```c
GPIOA_CRL &= ~(0xFu << 0);     /* ① 清 PA0 的 4 位 */
GPIOA_CRL |=  (0x8u << 0);     /* ② CNF=10（上/下拉输入）+ MODE=00（输入） */
GPIOA_ODR |=  (1u << 0);       /* ③ F1 特有：ODR 位=1 → 上拉；=0 → 下拉 */
```

漏掉第 ③ 步，引脚处于"上/下拉输入模式"但**既没选上也没选下**，
实际表现就是浮空——电平随机。这个坑很常见，因为：

- 很多 F4 的教程直接写 `GPIOA->PUPDR |= ...`，F1 上**没有这个寄存器**；
- `ODR` 通常被认为是"输出数据寄存器"，在输入模式下写它看着很反直觉；
- 现象（电平随机）和原因（漏配 ODR）之间隔了三层。

F0/F4 的对照写法：

```c
GPIOA->MODER &= ~(0x3u << (2*0));          /* 输入模式 */
GPIOA->PUPDR = (GPIOA->PUPDR & ~(0x3u << (2*0))) | (0x1u << (2*0));  /* 01 = 上拉 */
```

一句话：**在 F1 上看到"按键电平不对"，先查 `ODR` 那一位。**
</details>

<details>
<summary>Q3：内部上拉的 40 kΩ 够用吗？什么时候必须上外部电阻？</summary>

分场景：

| 场景 | 内部上拉够不够 | 理由 |
|---|---|---|
| 板载按键（走线 < 5 cm） | ✅ 够 |  parasitics 小，40 kΩ 也能在微秒级拉起来，按键是毫秒级事件 |
| 长线 / 接插件引出（> 20 cm） | ❌ 不够 | 线间电容大，40 kΩ 上升沿慢；噪声容限也差 |
| I²C 总线（SCL/SDA） | ❌ 必须外部 | 协议对上升时间有硬性要求（标准模式 1000 ns），40 kΩ 远不够，通常 2.2k–4.07k |
| 高速信号 / 边沿触发中断 | ⚠ 看情况 | 上升沿慢会导致边沿检测抖动，配合软件去抖 |
| 低功耗设备 | ⚠ 注意电流 | 内部 40 kΩ 约 0.08 mA（3.3V），看着小，但电池设备常年累积可观 |

判断方法：**估算 RC 时间常数**。
引脚输入电容约 5–10 pF，走线电容约 1 pF/cm：

- 内部 40 kΩ × 10 pF = 0.4 µs → 对按键（ms 级）完全够；
- 内部 40 kΩ × 100 pF（20 cm 线）= 4 µs → 还行，但噪声容限变差；
- I²C 需要 < 1 µs 的上升时间且要驱动总线电容（可达 400 pF）→ 40 kΩ 完全不行。

> 上面是典型值的**估算**，不是本仓库实测。实际设计要查 Datasheet 的
> "I/O port characteristics" 章节里的 $R_{PU}$ 和 $C_{IO}$。
</details>
