## 书这一节讲什么

一句话：**用引脚之前要先初始化**（配方向、配上拉、配速率）。

书把它当流程讲。裸机上的真正问题是：**这些步骤有严格的顺序**，
而且**顺序错了不会报错**——只是那个外设静默地不工作。

## 一、实测：初始化的三步与它们的机器码

```c
void button_init(void){
    RCC_APB2ENR |= BIT(2);          /* ① 开 GPIOA 时钟 */
    GPIOA_CRL &= ~(0xFu << 0);      /* ② 清 PA0 的 4 位 */
    GPIOA_CRL |=  (0x8u << 0);      /*    CNF=10 上/下拉输入, MODE=00 输入 */
    GPIOA_ODR |= BIT(0);            /* ③ F1：输入模式下 ODR 位=1 选上拉 */
}
```

```
$ clang ... -Os -c btn.c && llvm-objdump -d btn.o
00000000 <button_init>:
       0: movw/movt r0, #0x40021018     ; RCC_APB2ENR
       8: ldr r1,[r0] / orr r1,r1,#0x4 / str r1,[r0]      ← ① 开时钟（3 条）
      10: movw/movt r0, #0x40010800     ; GPIOA_CRL
      18: ldr r1,[r0] / bic r1,r1,#0xf / str r1,[r0]      ← ② 清位（3 条）
      20: ldr r1,[r0] / orr r1,r1,#0x8 / str r1,[r0]      ←    置位（3 条）
      28: ldr r1,[r0,#0xc] / orr r1,r1,#0x1 / str r1,[r0,#0xc] ← ③ 选上拉（3 条）
      30: bx lr
```

三步各 3 条指令（ldr/运算/str），加上两条取地址和返回，共 16 条。

## 二、为什么顺序不能换

**① 开时钟必须在配置 GPIO 寄存器之前。**

这是 STM32 的省电设计：复位后所有外设时钟都是关的。
时钟没开时写 `CRL`，**写不进去**（实测上表现为读出 0）——
而 CPU 完全不知道，没有总线错误、没有异常。

> 唯一例外：`RCC` 自己的寄存器（它在 AHB 上，时钟总是开的）。

**② 清位必须在置位之前。**

`CRL` 一个寄存器管 8 个引脚（PA0–PA7 各 4 位）。
不先 `&= ~` 就把新的配置 `|=` 进去，旧的配置位会**残留并参与或运算**——
结果是一个你没写过的组合值（[4.12](../04-numbers-and-bitops/4.12-用位操作控制内存映射IO寄存器.md)）。

**③ 选上/下拉要在模式配成"上/下拉输入"之后。**

F1 上 `ODR` 的对应位兼任上/下拉选择——但**只有在 CNF=10（上/下拉输入）模式下才有意义**。
先写 `ODR` 再配 `CRL` 不会出错，但中间会短暂处于"浮空"状态；
反过来（先配 CRL 再写 ODR）更稳。

## 三、初始化的"复位值"思维

裸机初始化的第一原则：**每个寄存器的复位值是什么？我要改哪些位？**

```
复位后 GPIOA_CRL = 0x44444444   （所有引脚 = 浮空输入 CNF=01 MODE=00）
我要 PA0 = 上拉输入          →  bit 3:0 从 0x4 改成 0x8
```

`0x4` = `CNF=01, MODE=00`（浮空输入）
`0x8` = `CNF=10, MODE=00`（上/下拉输入）

**不要写 `GPIOA_CRL = 0x...`（整寄存器赋值）**——那会把另外 7 个引脚一起改掉。
永远 `&= ~` 清 + `|=` 置。

## 四、初始化的组织方式：一次性 vs 分模块

```c
/* 一次性（书里的做法，小项目够用） */
int main(void){
    button_init();
    led_init();
    while (1) { ... }
}

/* 分模块 + 显式顺序（工程做法） */
int main(void){
    clock_init();        /* ① 时钟树（必须先于一切） */
    gpio_init();         /* ② GPIO（依赖时钟） */
    uart_init();         /* ③ 外设（依赖时钟 + GPIO 复用） */
    enable_irq();        /* ④ 最后才开中断 */
    while (1) { ... }
}
```

**最后才开中断**是裸机初始化的通用纪律：
初始化期间中断来了会访问还没配好的外设。

## 坑点（书 / 常识怎么说 / 实际是什么）

| 书 / 常识怎么说 | 实际是什么 |
|---|---|
| "初始化就是配一下寄存器" | 有严格顺序：**先开时钟，再配寄存器**。顺序错了**不报错**，只是静默失效 |
| "配置引脚写 `CRL = 0x...` 就行" | 会覆盖同寄存器里另外 7 个引脚。必须 `&= ~` + `\|=`（实测两步各 3 条指令） |
| "复位后引脚是低电平" | 复位后是**浮空输入**（`CRL = 0x44444444`），电平不确定 |
| "初始化顺序无所谓" | 时钟 → GPIO → 外设 → 开中断，这个顺序有物理原因，不是风格 |
| "初始化完就能用" | 有些外设还要等就绪标志（PLL 锁定 `HSERDY`、Flash 就绪），要配超时等待 |

## 代码自测

<details>
<summary>Q1：为什么"忘记开时钟"是裸机第一大坑？</summary>

因为**它是唯一一个"完全没报错"的错误**。

对比其他错误：

| 错误 | 系统反应 |
|---|---|
| 访问未对齐地址（某些情况） | HardFault |
| 访问不存在的地址 | HardFault（总线错误） |
| 除以零 | （Cortex-M 上）默认返回 0 或触发 UsageFault |
| **访问时钟未开的外设** | **什么都不会发生**——读回 0，写不进去 |

原因：STM32 把外设挂在总线上，每个外设前面有一个**时钟门控**。
门关着的时候，那个外设的寄存器根本不响应总线访问——
在 F1 上通常表现为读到 0、写无效，**不产生总线错误**。

排查方法（经验顺序）：

1. 读回来的寄存器值是不是全 0？（说明没写进去 / 时钟没开）
2. `RCC->APB2ENR` / `AHBENR` 里对应位是不是 1？
3. 引脚/外设所在的总线对不对？（GPIOA 在 APB2，不是 AHB——
   芯片手册的"系统架构"图里有）

一句话：**裸机任何时候"读回来是 0"，第一个要查的就是时钟。**
</details>

<details>
<summary>Q2：`&= ~` 清位这一步能不能省？直接 `|=` 不行吗？</summary>

不能省，因为**复位值不是 0**（这是最容易想当然的地方）。

实测/手册事实：`GPIOA_CRL` 复位值是 `0x44444444`，不是 `0x00000000`。
你要把 PA0 配成 `0x8`（上拉输入）：

```c
GPIOA_CRL |= 0x8u;        /* 0x44444444 | 0x8 = 0x4444444C  ← 错！ */
```

`0x4 | 0x8 = 0xC`（`CNF=11` = 保留/复用功能），**不是你要的 0x8**。
位或运算没法把已经是 1 的位清成 0，所以必须先 `&= ~0xF`：

```c
GPIOA_CRL &= ~0xFu;       /* 0x44444440 —— PA0 的 4 位清零 */
GPIOA_CRL |=  0x8u;       /* 0x44444448 —— PA0 = 0x8 ✓ */
```

代价（实测）：清位 3 条指令 + 置位 3 条指令。
因为初始化时中断通常还没开，这两次读-改-写没有并发风险。

**什么时候可以省**：如果你明确知道目标位当前就是 0（比如刚复位、或前面已经清过），
单次 `|=` 是安全的。但"知道"要来自手册的复位值，不能靠猜。
</details>

<details>
<summary>Q3：初始化代码该写成一大坨还是分模块？</summary>

分模块，而且**顺序要显式写在代码里**。

裸机没有 OS 的 `initcall` 机制（Linux 内核有），
也没有 C++ 的构造函数自动执行（`.init_array` 要自己实现），
所以**所有初始化顺序都是你手写的**。分成小函数的好处：

1. **依赖关系可读**：

```c
int main(void){
    clock_init();     /* 依赖：无（最先） */
    gpio_init();      /* 依赖：clock */
    uart_init();      /* 依赖：clock + gpio（复用引脚） */
    systick_init();   /* 依赖：clock */
    enable_irq();     /* 依赖：全部初始化完成（最后） */
    ...
}
```
看代码就知道顺序，不用读一坨寄存器操作去脑补。

2. **可复用**：换板子只改 `gpio_init()`。
3. **可测试**：主机侧可以单独验证纯逻辑部分。

还有一个工程细节：**每个 init 函数应该是幂等的**（重复调用不产生副作用），
因为某些场景（从低功耗唤醒、错误恢复）会重新初始化。
实现上就是每次都完整地 `&= ~` + `|=`，而不是只改"变化的部分"。
</details>
