# 5.3 循环

> 上一篇：[5.2 if-else](5.2-if-else.md) ｜ 下一篇：[5.4 while](5.4-while.md)

## 书这一节讲什么

一句话：**C 有三种循环：`while`、`for`、`do-while`**，
书在这里给个总览，后面 5.4/5.5 分别讲 `while` 和 `for`。

书没单独讲 `do-while`（它归在这一节里）。而在裸机上 **`do-while` 是最有存在感的那个**——
因为"先做一次，再检查"正是硬件操作的常态（写寄存器 → 等它完成）。

## 一、三种循环的差异只有一句话

| 循环 | 语义 | 裸机典型用途 |
|---|---|---|
| `while (c)` | **先检查，可能一次都不做** | 等待某个条件成立（等标志位、等缓冲非空） |
| `for (i=0; c; i++)` | 计数循环的语法糖 | 遍历缓冲区、固定次数重试 |
| `do { } while (c)` | **先做一次，再检查** | 先写一字节再等"发送完成"；先读再判是否继续 |

`do-while` 的那个"至少一次"在裸机上是刚需：

```c
/* 发送一字节：必须先写 DR，才有"等 TXE"的意义 */
USART1_DR = c;
while (!(USART1_SR & TXE)) { }        /* 等发送缓冲空 */
```

如果写成 `while (!(USART1_SR & TXE)) USART1_DR = c;`，
第一次判断时还没写过 DR——逻辑就反了。

## 二、实测：`for` 和 `while` 生成完全相同的机器码

```c
int sum_for(int n){ int s=0; for (int i=0;i<n;i++) s+=i; return s; }
int sum_while(int n){ int s=0; int i=0; while (i<n){ s+=i; i++; } return s; }
```

```
$ clang ... -Os -c loop.c && llvm-objdump -d loop.o
00000000 <sum_for>:
       cmp r0,#1 / it lt / movlt r0,#0 / bxlt lr
       subs r1,r0,#1 / subs r0,#2
       umull r0,r2,r1,r0     ← 等差求和被识别成乘法公式！
       and r2,r2,#1 / lsrs r2,#1 / rrx r0,r0 / add r0,r1
       bx lr
00000020 <sum_while>:  （逐字节相同）
```

两个信息：

1. **`for` 就是 `while` 的语法糖**，编译器眼里没有区别——选哪个只看可读性；
2. 更狠的是：编译器**认出了这是等差数列求和**，直接用 `umull`（乘法）算出结果，
   **循环整个消失了**。这说明"-O2/-Os 下循环不是你写的那个循环"——
   想靠空循环做延时，就必须靠 `volatile`（[5.5](5.5-for.md) 实测）。

## 三、裸机的主循环：`while (1)`

`main` 的结尾必须是死循环（[ch01](../01-hello-world/1.3-我们的第一个程序.md) 讲过为什么：
`main` 返回之后没有 OS 可回）。三种写法：

```c
while (1) { ... }        /* 最常见 */
for (;;) { ... }         /* 某些编译器下能少一条警告（条件恒真） */
do { ... } while (1);    /* 少见 */
```

裸机上更好的是**低功耗主循环**（[ch19 SysTick](../19-systick-and-timer/19.4-三种等待的对比.md)）：

```c
while (1) {
    handle_events();                  /* 处理 ISR 置的标志 */
    __asm__ volatile ("wfi");         /* Wait For Interrupt：睡觉，等中断唤醒 */
}
```

`wfi` 让 CPU 在没事干时停掉时钟——**轮询循环和电池寿命之间只差这一条指令**。

## 坑点（书 / 常识怎么说 / 实际是什么）

| 书 / 常识怎么说 | 实际是什么 |
|---|---|
| "三种循环只是写法不同" | 语义不同：`do-while` 至少做一次，而"先写寄存器再等标志"必须用它 |
| "`for` 比 `while` 快" | 实测机器码完全相同 |
| "循环会按我写的次数跑" | 不一定：`-O2` 下求和循环被 `umull` 替代，**循环整个消失**（实测） |
| "主循环空转会一直耗电" | 是的。加 `wfi` 让 CPU 睡（[ch19](../19-systick-and-timer/19.4-三种等待的对比.md)） |
| "循环条件里的变量会每轮重读" | 只有 `volatile` 才会（[5.14](5.14-反模式.md) 实测 `wait_bad` → `bx lr`） |

## 代码自测

<details>
<summary>Q1：为什么裸机里"先做一次再检查"这么常见？</summary>

因为**硬件操作的因果顺序是"你先下命令，硬件才产生状态"**。

三个典型：

```c
/* ① 发送：先写 DR，才有"TXE 空了"这件事 */
USART1_DR = c;
while (!(USART1_SR & TXE)) { }

/* ② 启动转换：先写触发位，才有"EOC 转换完成" */
ADC1_CR2 |= ADC_CR2_SWSTART;
while (!(ADC1_SR & ADC_SR_EOC)) { }

/* ③ 擦除 Flash：先写擦除命令，才有"BSY 忙" */
FLASH_CR |= FLASH_CR_PER;
FLASH_AR = page_addr;
FLASH_CR |= FLASH_CR_STRT;
while (FLASH_SR & FLASH_SR_BSY) { }      /* 等擦完 */
```

这三处如果用 `while (条件) 动作;` 的写法，第一次判断时动作还没发生，
条件永远不成立（或永远成立），逻辑直接错。

`do-while` 正是为这种形状设计的：

```c
do {
    send_next_byte();
} while (more_to_send());
```

一句话：**"状态是动作的产物"时，用 `do-while`；"状态先于动作存在"时，用 `while`。**
</details>

<details>
<summary>Q2：实测里求和循环被改成了 `umull`，编译器到底有多大权限？</summary>

只要**可观察行为不变**，编译器可以任意改写你的代码。

`sum_for` 里没有 `volatile`、没有 I/O、循环次数有限，
所以编译器可以证明"这个循环等价于 n*(n-1)/2"，于是用乘法替代。
实测生成的是 `umull`（64 位乘法的低 32 位）+ 一些移位修正。

权限的边界在 **volatile 和副作用**上：

```c
for (int i=0;i<1000;i++) { }                  /* 无副作用 → 可以被整个删掉 */
for (volatile int i=0;i<1000;i++) { }         /* 每轮写 volatile → 必须保留 */
for (int i=0;i<1000;i++) { GPIOA_ODR ^= 1; }  /* 写 volatile 寄存器 → 必须保留，
                                                 但可能被合并/重排成别的形式 */
```

所以裸机上判断"编译器有没有权力改我的循环"，只需要问：
**这个循环里有没有 `volatile` 访问（或别的副作用）？**
没有 → 编译器可以随便改，包括删掉；有 → 每一轮都必须真的发生。

这正是 [5.14](5.14-反模式.md) 里 `wait_bad` 被编译成 `bx lr` 的同一个道理。
</details>

<details>
<summary>Q3：主循环里 `while(1)` 一直空转，会不会有问题？</summary>

功能上没问题（裸机没有 OS，空转是常态），但**耗电和发热是真实的**。

Cortex-M 在 `while(1) { }` 里会一直取指、译码、执行跳转，
72 MHz 下电流可能是十几 mA；加上 `wfi` 之后降到几 mA 甚至更低
（具体数字取决于芯片和时钟配置，**本篇没实测，别当准**）。

标准做法：

```c
while (1) {
    if (flag_from_isr) { handle(); flag_from_isr = 0; }
    __asm__ volatile ("wfi");        /* 睡到下一个中断 */
}
```

关键点：

1. **`wfi` 只是"等待中断"**，任何中断都会唤醒它，然后继续下一轮循环；
2. 唤醒后**先处理标志再睡**，否则可能丢事件；
3. `wfi` 前后是 `__asm__ volatile`——`volatile` 在这里是告诉编译器
   "别把它挪走或删掉"（跟 MMIO 那个 `volatile` 是同一个关键字，同一个语义）。

需要周期性做事（闪灯、采样）时，用 SysTick 定时唤醒（[ch19](../19-systick-and-timer/19.4-三种等待的对比.md)），
而不是靠空循环数时间。
</details>
