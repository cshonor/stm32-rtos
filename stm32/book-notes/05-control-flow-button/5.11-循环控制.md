## 书这一节讲什么

一句话：**`break` 跳出循环、`continue` 跳到下一轮**——书在这一节给总览，
5.12/5.13 分别展开。

本篇先讲书里没展开、但裸机上天天要用的另一件事：**嵌套循环的退出**，
以及 `goto` 为什么在裸机（和 Linux 内核）里是**正当**的。

## 一、`break` / `continue` 的机器形态

```c
int f_break(int *a, int n){ int s=0; for(int i=0;i<n;i++){ if(a[i]<0) break; s+=a[i]; } return s; }
int f_cont (int *a, int n){ int s=0; for(int i=0;i<n;i++){ if(a[i]<0) continue; s+=a[i]; } return s; }
```

```
$ clang ... -Os -c bc.c && llvm-objdump -d bc.o
00000000 <f_break>:
       8: f852 3b04  ldr  r3, [r2], #4
       c: 2b00       cmp  r3, #0x0
       e: d405       bmi  0x1c          ← break = 一条条件跳转，跳出循环体
      10: subs r1,#1 / add r0,r3
      14: it eq / bxeq lr
      18: b 0x8                          ← 回循环头
      1c: bx lr

0000001e <f_cont>:
      28: f852 3b04  ldr  r3, [r2], #4
      2c: subs r1,#1
      2e: ea23 73e3  bic.w r3, r3, r3, asr #31   ← continue 被改写成"负数清零"
      32: 4418       add  r0, r3
      34: bne 0x28
      36: bx lr
```

两点值得注意：

1. **`break` 就是一条条件跳转**（`bmi`）到循环外；
2. **`continue` 被编译器优化掉了**——它把"负数就跳过累加"改写成
   `bic.w r3, r3, r3, asr #31`（负数变 0、非负数不变），
   **循环里根本没有跳转**。

第二点说明：`continue` 是给**人**读的，编译器会按数据流重写。
（详见 [5.13](5.13-continue.md)。）

## 二、嵌套循环怎么退出：裸机上 `goto` 是正当的

```c
/* 在二维表里找一项，找到了就整个退出 */
for (int r = 0; r < ROWS; r++)
    for (int c = 0; c < COLS; c++)
        if (tbl[r][c] == key) goto found;      /* break 只能退一层 */
found:
    ...
```

`break` 只跳一层。替代写法（标志变量）更啰嗦：

```c
int done = 0;
for (int r = 0; r < ROWS && !done; r++)
    for (int c = 0; c < COLS && !done; c++)
        if (tbl[r][c] == key) { done = 1; break; }
```

裸机和 Linux 内核里 `goto` 的正当用途有两个，都是**向前跳**：

1. **跳出多层循环**（本例）；
2. **统一清理/错误处理**：

```c
int init_all(void){
    int rc;
    if ((rc = uart_init()) != 0) goto err_uart;
    if ((rc = spi_init())  != 0) goto err_spi;
    if ((rc = i2c_init())  != 0) goto err_i2c;
    return 0;

err_i2c: spi_deinit();
err_spi: uart_deinit();
err_uart:
    return rc;
}
```

这个"倒序回滚"的结构在 C 里没有别的方式能写得这么清楚
（没有 RAII、没有 `try/finally`）。Linux 内核里到处都是。

**纪律**：`goto` 只往前跳（跳到函数末尾的清理标签），
**绝不往后跳**——往后跳就是在手写循环，那是自找麻烦。

## 三、循环控制的三个裸机注意点

| 点 | 说明 |
|---|---|
| 循环里的 `volatile` 读 | 每轮都真读；`break` 之前的那次读也算（别指望编译器合并） |
| ISR 里的 `break` | 可能跳过清中断标志 → 中断反复触发（[5.12](5.12-break.md) 展开） |
| 循环 + 超时 | `for (tmo = N; tmo; tmo--)` 配 `break`，别写成无限等待 |

## 坑点（书 / 常识怎么说 / 实际是什么）

| 书 / 常识怎么说 | 实际是什么 |
|---|---|
| "`break` 只跳一层" | 对。多层要用 `goto`（向前跳）或标志变量 |
| "`goto` 是有害的" | 那条 1968 年的论断针对**任意跳转**。向前跳做清理/退出多层，在 C 里是最清楚的写法（Linux 内核大量使用） |
| "`continue` 会产生跳转" | 实测被优化成 `bic.w` 条件清零，**循环里没有跳转** |
| "循环里读寄存器很自然" | 每次读都是真实硬件访问，且可能读清标志（[5.1](5.1-if.md)） |
| "循环跑不完就是死循环" | 也可能是**硬件没响应**。裸机的循环要有超时退出（[5.4](5.4-while.md)） |

## 代码自测

<details>
<summary>Q1：都说 `goto` 有害，为什么 Linux 内核里全是 `goto`？</summary>

因为 Dijkstra 1968 年那篇《Go To Statement Considered Harmful》反对的是
**无约束的任意跳转**（到处跳来跳去，形成"面条代码"），
而不是"C 语言里向前跳到清理标签"这个具体用法。

C 语言没有这些机制：

- C++ 的 RAII（析构函数自动清理）；
- Java/Python 的 `try/finally`；
- Rust 的 `?` 运算符 + `Drop`。

所以在 C 里做"多步初始化，任一步失败要回滚前面所有步"，
可选写法只有：

```c
/* 写法 A：goto 集中清理（内核风格） */
int init_all(void){
    if (uart_init()) goto err1;
    if (spi_init())  goto err2;
    if (i2c_init())  goto err3;
    return 0;
err3: spi_deinit();
err2: uart_deinit();
err1: return -1;
}

/* 写法 B：嵌套 if（缩进越来越深，回滚逻辑分散） */
int init_all(void){
    if (!uart_init()) {
        if (!spi_init()) {
            if (!i2c_init()) return 0;
            spi_deinit();
        }
        uart_deinit();
    }
    return -1;
}
```

**A 更清楚**：正常路径是一条直线，错误路径集中在末尾，且回滚顺序一目了然
（利用标签穿透：`err3` 会顺带执行 `err2`、`err1`）。

纪律（内核和本仓库都遵守）：**只向前跳，只跳到本函数内的清理标签。**
向后跳是在手写循环——那种 `goto` 才是真的有害。
</details>

<details>
<summary>Q2：嵌套循环退出，用标志变量还是 `goto`？</summary>

看退出后要不要做某事：

**只是"找到了就停"** → 标志变量也够，但 `goto` 更短：

```c
/* goto 版：意图直接 */
for (int r = 0; r < ROWS; r++)
    for (int c = 0; c < COLS; c++)
        if (tbl[r][c] == key) goto found;
found: ;

/* 标志版：每个循环条件都要加 && !found */
int found = 0;
for (int r = 0; r < ROWS && !found; r++)
    for (int c = 0; c < COLS && !found; c++)
        if (tbl[r][c] == key) { found = 1; }
```

**退出后还要回滚/清理** → `goto` 明显更好（见 Q1 的 init 例子）。

**性能上有差别吗？** 实测层面：两者通常生成相同的机器码
（标志变量多一次寄存器比较，`goto` 是一次直接跳转，都极便宜）。
**选可读性好的那个**，别为这个纠结。

一个折中：如果嵌套只有两层且逻辑简单，
可以把内层抽成函数，用 `return` 代替 `goto`：

```c
static int find_in_row(int r, int key){ for (int c=0;c<COLS;c++) if(tbl[r][c]==key) return c; return -1; }
```
这样连 `goto` 都不需要——**能抽函数就抽函数**，这通常是可读性最好的。
</details>

<details>
<summary>Q3：裸机的循环里，`break` 之前读过的寄存器算不算数？</summary>

算数，而且**每一次读都是真实发生的硬件访问**——不会被编译器合并掉。

```c
for (int i = 0; i < 10; i++) {
    uint32_t sr = USART1_SR;        /* volatile 读：每轮都真读 */
    if (sr & RXNE) { c = USART1_DR; break; }   /* 读 DR 会清 RXNE */
}
```

要注意的是两类寄存器的**副作用**：

1. **读清标志（read-clear）**：`USART_SR` 的 `RXNE` 靠**读 `DR`** 清除；
   `EXTI_PR` 靠**写 1** 清除。所以 `break` 之前如果读了 `DR`，
   标志已经清了——不会残留到下一次中断。
2. **读一次就变的寄存器**：`IDR`（引脚电平）、`CNT`（计数器）——
   `break` 的那一轮读到的值，和下一轮（如果没 break）读到的可能不同。

所以 `break` 之前**把要用的值存下来**：

```c
uint32_t sr = USART1_SR;    /* 一次快照 */
if (sr & RXNE) { c = USART1_DR; break; }
if (sr & ORE)  { err_count++; break; }   /* 判断基于同一次快照 */
```

一句话：**`break` 是控制流的跳转，不是"撤销这一次读"。**
读了就是读了，硬件已经产生了那次访问的全部副作用。
</details>
