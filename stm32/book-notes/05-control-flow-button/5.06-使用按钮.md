## 书这一节讲什么

一句话：**按钮就是一个接到引脚上的开关**，读它的电平就知道按下没有。

这是全书第一次从"**输出**"（点灯）转向"**输入**"（读按键）。
输出是你说了算，输入是**外部世界说了算**——
这个转向带来三个裸机独有的新问题：引脚要配成输入、要有确定的空闲电平、读到的值会抖。

## 一、输入引脚和输出引脚，配置差在哪

| | 输出（点灯） | 输入（按键） |
|---|---|---|
| `CRL/CRH` 的 MODE 位 | 非 00（有速率） | **00**（输入模式） |
| `CRL/CRH` 的 CNF 位 | 00/01（推挽/开漏） | **10**（上/下拉输入）/ 01（浮空） |
| 读/写 | 写 `ODR` / `BSRR` | 读 `IDR`（**只读**） |
| 空闲电平 | 由你写的值决定 | **由外部电路（上拉/下拉电阻）决定** |

最后一行是本节的核心：**输入引脚的电平不是"没接就是 0"**，
而是由外部电路拉到某个确定值——见 [5.08 选择下拉电路](5.08-选择下拉电路.md)。

## 二、实测：一个最小按键程序的机器码

```c
typedef unsigned int u32;
#define RCC_APB2ENR (*(volatile u32 *)0x40021018u)
#define GPIOA_CRL   (*(volatile u32 *)0x40010800u)
#define GPIOA_ODR   (*(volatile u32 *)0x4001080cu)
#define GPIOA_IDR   (*(volatile u32 *)0x40010808u)
#define BIT(n) (1u << (n))

void button_init(void){
    RCC_APB2ENR |= BIT(2);          /* ① 开 GPIOA 时钟 */
    GPIOA_CRL &= ~(0xFu << 0);      /* ② 清 PA0 的 4 位 */
    GPIOA_CRL |=  (0x8u << 0);      /*   CNF=10 上/下拉输入, MODE=00 输入 */
    GPIOA_ODR |= BIT(0);            /* ③ F1：输入模式下 ODR 位=1 选上拉 */
}
int button_pressed(void){           /* 上拉：按下 = 0 */
    return (GPIOA_IDR & BIT(0)) == 0;
}
```

```
$ clang --target=armv7m-none-eabi -mcpu=cortex-m3 -mthumb -Os -c btn.c -o btn.o
$ llvm-objdump -d btn.o

00000000 <button_init>:                       ; 共 16 条指令
       0: movw/movt r0, #0x40021018          ; RCC_APB2ENR
       8: ldr r1,[r0] / orr r1,r1,#0x4 / str r1,[r0]     ← ① 开时钟
      10: movw/movt r0, #0x40010800          ; GPIOA_CRL
      18: ldr r1,[r0] / bic r1,r1,#0xf / str r1,[r0]     ← ② 清位
      20: ldr r1,[r0] / orr r1,r1,#0x8 / str r1,[r0]     ←    置位
      28: ldr r1,[r0,#0xc] / orr r1,r1,#0x1 / str r1,[r0,#0xc] ← ③ 选上拉
      30: bx lr

00000032 <button_pressed>:                    ; 只有 6 条
      32: movw/movt r0, #0x40010808          ; GPIOA_IDR
      3a: ldr  r0, [r0]                      ; 读整个 IDR
      3e: movs r1, #0x1
      40: bic.w r0, r1, r0                   ; ← 一条指令完成"取反的位与"
      42: bx lr
```

三点观察：

1. **初始化 16 条指令，读取只要 6 条**——配置的成本远高于读一次；
2. `button_pressed` 里编译器把 `(IDR & 1) == 0` 优化成 `bic.w r0, r1, r0`
   （即 `1 & ~IDR`）——**一条指令**，跟 [4.12](../04-numbers-and-bitops/4.12-用位操作控制内存映射IO寄存器.md) 里的 `ubfx` 一样是"位检查"的最优形态；
3. 第 ③ 步在 **F1 上容易漏**：F1 没有独立的上/下拉寄存器，
   靠 `ODR` 位在输入模式下兼任选择——漏了就是"浮空输入"（[5.08](5.08-选择下拉电路.md)）。

## 三、按键的输入路径

```
物理开关 → 上/下拉电阻决定空闲电平 → 引脚施密特触发器整形
        → IDR 的对应位 → 你的 (IDR & BIT(n))
```

注意中间那个**施密特触发器**：STM32 的每个输入引脚都有，
它带滞回（hysteresis），能抑制缓慢变化的电平和一点点噪声。
但它**不解决机械抖动**（那是毫秒级的），去抖是软件的事（[5.10](5.10-运行程序.md)）。

## 坑点（书 / 常识怎么说 / 实际是什么）

| 书 / 常识怎么说 | 实际是什么 |
|---|---|
| "按键按下读到 1" | 取决于电路。**上拉时按下读到 0**（书里用下拉，所以按下是 1）。看原理图，别猜 |
| "配成输入就能读" | 还要**开时钟**（`RCC_APB2ENR`）+ **选上/下拉**。实测初始化要走 3 步 16 条指令 |
| "引脚悬空 = 低电平" | 错。悬空是**天线**，电平不确定（手靠近就变）。必须上拉或下拉 |
| "`IDR` 是普通寄存器" | 它是**只读**的（`w` 在手册里标 `r`），写它没意义 |
| "读一次就够了" | 机械抖动会让一次按下产生多次跳变，要去抖（[5.10](5.10-运行程序.md)） |
| "F1 上有 `PUPDR` 寄存器" | ❌ F1 没有。`PUPDR` 是 F0/F4 才有，F1 靠 `ODR` 位兼任（实测第 ③ 步） |

## 代码自测

<details>
<summary>Q1：为什么读个按键要配三件事？一个 `IDR` 不就够了吗？</summary>

因为**引脚在上电复位后处于"浮空输入 + 时钟关闭"的状态**，不配置的话读到的不是按键状态。

三件事各有不可替代的作用：

1. **开时钟**（`RCC_APB2ENR |= BIT(2)`）：STM32 为了省电，**外设时钟默认是关的**。
   时钟没开时访问该外设的寄存器——在 F1 上通常读到 0 / 写不进去，
   而**没有任何报错**。这是裸机最经典的"代码完全正确但没反应"。
2. **配输入模式**（`CRL` 的 CNF/MODE）：复位默认是浮空输入。
   浮空意味着没有上/下拉，引脚悬空 → 电平不确定。
3. **选上/下拉**（F1 上靠 `ODR` 位）：给引脚一个**确定的空闲电平**，
   这样开关断开时读到的才是稳定的 1（上拉）或 0（下拉）。

漏掉任何一步都不会报错，只会"读到的值不对"——
所以裸机初始化的检查方式是**逐项对照手册寄存器**，
而不是"跑一下看看对不对"。
</details>

<details>
<summary>Q2：`(IDR & BIT(0)) == 0` 为什么编译成了 `bic.w r0, r1, r0`？</summary>

`bic` 是 **Bit Clear**：`bic Rd, Rn, Rm` = `Rd = Rn & ~Rm`。

编译器推导：`(IDR & 1) == 0` 等价于"IDR 的 bit0 不是 1"，
也就是"用 1 去与 ~IDR 的 bit0"，即 `1 & ~IDR`：

```
movs  r1, #0x1      ; r1 = 1
bic.w r0, r1, r0    ; r0 = r1 & ~r0  = 1 & ~IDR
```

- `IDR` 的 bit0 = 0 → `~IDR` 的 bit0 = 1 → 结果 1（表示"按下"）✓
- `IDR` 的 bit0 = 1 → 结果 0 ✓

**一条指令完成"读位 + 取反 + 比较"**，比"读位 → 比较 → 设置返回值"少两条指令。

这件事的意义不在于你会手写 `bic`，而在于：
**写可读性最好的 `(reg & BIT(n)) != 0`，编译器能自己找到最优形态**
（[4.12](../04-numbers-and-bitops/4.12-用位操作控制内存映射IO寄存器.md) 里另一个例子是 `ubfx`）。
所以别手写移位和掩码去"优化"，那只会让代码更难读。
</details>

<details>
<summary>Q3：书里说按下读到 1，我的板子读到 0，谁错了？</summary>

都没错，**电路不同**。

| 电路 | 空闲（松开） | 按下 | 代码 |
|---|---|---|---|
| **下拉**（书里用这种） | 0 | **1** | `return (IDR & BIT) != 0;` |
| **上拉**（Nucleo 板上常见） | 1 | **0** | `return (IDR & BIT) == 0;` |

判断方法只有一个：**看原理图**。

- NUCLEO-F103RB：板载用户按键（B1）接的是 **PC13**，外部上拉 → 按下读 0；
- 书里的 NUCLEO-F030R8 + 面包板按键：书自己选了下拉 → 按下读 1。

> ⚠ 本篇的 PC13/上拉这条**是按 Nucleo 常见设计的说明，没有在本机上实测读数**
> （`stm32/05-exti-button` 实验还没做）。接自己的板子前先查原理图，
> 或者用万用表/读 `IDR` 打印一次确认。

工程上的建议：把"按下读到什么"封装成一个函数，
全工程只用这个函数，**不要到处写 `(IDR & BIT)`**——
换板子时只改一处。
</details>
