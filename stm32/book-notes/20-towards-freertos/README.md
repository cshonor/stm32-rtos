## 为什么书里没有这一篇

全书 18 章讲的是"单线程的裸机 C"——`main` 一路跑到底，
中断来了进 ISR、出 ISR 回 `main`。这是裸机的标准世界观。

但工程上还有一步必须迈出去：**当一个超级循环里塞了 5 个任务、
其中一个要"等传感器 50 ms 响应"时，整个系统停摆 50 ms**
（这个墙在 [19.04](../19-systick-and-timer/19.04-三种等待的对比.md) 已经撞见过）。
RTOS 就是跨这堵墙的工具，而书停在了墙的这一边。

选 FreeRTOS 的理由（事实来自仓库根 README）：

- **MIT 许可证**——MCU 裸机无 GPL 类义务，做产品可放心静态链接；
- 移植只碰 `FreeRTOSConfig.h` + port 层；
- F103 是 Cortex-M3，用现成的 `GCC/ARM_CM3` port，不用自己写汇编。

## 这一篇在讲什么

**FreeRTOS 的四个核心概念——任务、调度、队列、信号量——
分别落在硬件的哪里、以及落在本仓库的哪个实验里。**

```
任务是什么、调度器靠什么硬件跑起来（20.01）
   → 任务之间、ISR 与任务之间怎么传数据（20.02）
   → 什么时候该上 RTOS、第一个实验长什么样（20.03）
```

三个讲法约定：

1. **每个概念都落到硬件**：调度不是魔法，它落在 SysTick + PendSV 这两个
   Cortex-M 异常上（20.01 展开）；
2. **每个概念都落到一个实验**：本篇不出现"以后会讲"，
   落点全是 `freertos/01`~`04` 里的具体实验；
3. **每个概念都与 LDD- 侧对照一遍**：Linux 调度器 vs RTOS 调度器，
   学两遍记两遍。
