# 第 7 章 局部变量和函数 —— 章节导航

> 书：第 7 章 局部变量和函数（原书 p89–97）
> 对应实验：`--target=armv7m-none-eabi -mcpu=cortex-m3`，`-O0` / `-Os` 两档对照 + `-fstack-usage`

## 这一章在讲什么

PC 上"局部变量"是个不需要思考的概念：函数进来就有，返回就没。
**在裸机上它变成一个必须预算的资源**，因为：

- 栈的大小是**链接脚本里写死的一行**（`_estack = ORIGIN(RAM) + LENGTH(RAM)`）；
- **没有 MMU、没有守卫页**，栈溢出不会报错，只会静静踩掉 `.bss`/`.data`；
- 递归的深度直接决定会不会爆栈，而这个数字**可以算出来**——也必须算出来。

本章的两件工具：**`-fstack-usage`（静态算单帧）+ 反汇编（看栈帧怎么建/拆）**。
这两件事合起来，能把"20 KB 够不够"从猜测变成算术。

## 与书的差异（重要）

| 书 | 我 |
|---|---|
| 把递归当正常手段讲 | 20 KB RAM 上**几乎不该用**：实测 `-O0` 下 `fact` 每帧 24 B，深度不可静态证明 |
| 讲"栈帧"概念 | 用反汇编钉成数字：`sub sp, #0x20` / `add sp, #0x20` = 32 字节，与 `.su` 完全对上 |
| 讲隐藏变量 | 补上裸机的三类隐藏开销：`push {r7,lr}`（栈）、`__aeabi_memcpy`（Flash）、软件浮点（时间） |
| 讲通用编程风格 | 落到裸机硬规则：不递归、不用 VLA、大缓冲不压栈、等待必须超时 |

## 核心实测数据（本章的锚点）

```
$ clang ... -Os -fstack-usage -c ch07.c     $ clang ... -O0 -fstack-usage -c ch07.c
ch07.c:1:leaf         4    static           ch07.c:1:leaf         12   static
ch07.c:2:with_locals  32   static           ch07.c:2:with_locals  44   static
ch07.c:6:fact          0   static           ch07.c:6:fact         24   static
ch07.c:7:deep          0   static           ch07.c:7:deep         16   static
```

- `-Os` 的 `fact` **没有 `bl fact`**：被改写成 `muls` + `bhi` 的循环（栈 0）；
- `-O0` 的 `fact` 是 `push {r7,lr}` + `sub sp,#0x10` = 24 B/帧，真的 `bl` 自己；
- `with_locals` 是叶子函数：**没有 `push {lr}`**，只有 `sub sp, #0x20`（= `buf[8]`）。

## 读完本章你应该能回答

- 同一个函数 `-Os` 和 `-O0` 的栈用量为什么差 3 倍？（`leaf` 4 vs 12 字节）
- `-fstack-usage` 报的 24 字节是什么？怎么和 `push {r7,lr}` + `sub sp,#0x10` 对上？
- 为什么 `-Os` 下 `fact` 栈用量是 0？能不能依赖它？
- 20 KB 栈能递归多深？为什么不递归是更好的选择？
- 哪些"隐藏变量"在裸机上有成本？怎么看见它们？（`llvm-nm -u`）
- 为什么要禁 VLA？（`.su` 出现 `dynamic` 意味着什么）
- 放栈还是放静态区，判据是什么？
