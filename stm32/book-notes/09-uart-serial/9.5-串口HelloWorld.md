# 9.5 串口 Hello World

> 书：第 9 章 STM 上的串口输出 · 9.5 串口 Hello World（原书 p119–134 区间内）**——本章核心**
> 上一篇：[9.4 串行通信简史](9.4-串行通信简史.md) ｜ 下一篇：[9.6 Windows 与设备通信](9.6-Windows与设备通信.md)
> 对应实验：`--target=armv7m-none-eabi -mcpu=cortex-m3 -mthumb -ffreestanding`（`-Os` 反汇编 + M3/M0 除法指令对照）

## 书这一节讲什么

一句话：**UART 初始化四步 + 发一个字符**，让板子说出第一个 "Hello World"。

这是本章的操作核心。书上写"初始化几个寄存器"，
实际上**四步一个都不能少，且顺序固定**——漏任何一步都是"静默失败"。

## 一、四步，一步都不能少

```c
#define RCC_APB2ENR (*(volatile uint32_t *)0x40021018u)
#define GPIOA_CRH   (*(volatile uint32_t *)0x40010804u)
#define USART1_BRR  (*(volatile uint32_t *)0x40013808u)
#define USART1_CR1  (*(volatile uint32_t *)0x4001380Cu)

void uart1_init(uint32_t pclk2, uint32_t baud){
    RCC_APB2ENR |= (1u<<2)|(1u<<14);       /* ① 开 GPIOA + USART1 时钟 */
    GPIOA_CRH  &= ~(0xFu << 4);            /* ② PA9(TX) 复用推挽输出 */
    GPIOA_CRH  |=  (0xBu << 4);
    GPIOA_CRH  &= ~(0xFu << 8);            /*    PA10(RX) 浮空输入 */
    GPIOA_CRH  |=  (0x4u << 8);
    USART1_BRR  = (pclk2 + baud/2u) / baud;/* ③ 波特率分频（四舍五入） */
    USART1_CR1  = (1u<<13)|(1u<<3)|(1u<<2);/* ④ UE(使能) + TE(发) + RE(收) */
}
```

| 步骤 | 漏掉的后果 | 现象 |
|---|---|---|
| ① 开时钟 | **写 BRR/CR1 无效**（时钟门控） | 什么都不发生，用调试器看 BRR 是 0 |
| ② 配引脚复用（AFIO） | PA9 还是普通 GPIO | 示波器上 TX 脚没波形 |
| ③ 算波特率 | 波特率不对 | 能发，主机收到**乱码** |
| ④ 使能 UE/TE | UART 没开 | 什么都不发生 |

**第 ① 步是裸机第一号坑**（[ch03](../03-embedded-system-programming/README.md) 讲过）：
STM32 上电后**所有外设时钟都是关的**，写没开时钟的外设寄存器**不报错、不生效**。

## 二、实测：`uart1_init` 编译出来 28 条指令

```
$ clang --target=armv7m-none-eabi -mcpu=cortex-m3 -mthumb -ffreestanding -Os -c uart.c
$ llvm-objdump -d uart_Os.o
00000026 <uart1_init>:
      26: f241 0c18  movw  r12, #0x1018     ; 0x40021018 = RCC_APB2ENR
      2a: f2c4 0c02  movt  r12, #0x4002
      2e: f8dc 3000  ldr.w r3, [r12]
      32: f244 0204  movw  r2, #0x4004      ; 0x4004 = bit2|bit14
      36: 431a       orrs  r2, r3
      38: f8cc 2000  str.w r2, [r12]        ; ① 开时钟

      3c: f640 0204  movw  r2, #0x804       ; 0x40010804 = GPIOA_CRH
      40: f2c4 0201  movt  r2, #0x4001
      44: 6813       ldr   r3, [r2]
      4a: f023 03f0  bic   r3, r3, #0xf0    ; ② 清 PA9 的 4 位
      4e: 6013       str   r3, [r2]
      50: 6813       ldr   r3, [r2]
      56: f043 03b0  orr   r3, r3, #0xb0    ;    置 0b1011（复用推挽 50MHz）
      5a: 6013       str   r3, [r2]
      5c: 6813       ldr   r3, [r2]
      62: f423 6370  bic   r3, r3, #0xf00   ;    清 PA10 的 4 位
      66: 6013       str   r3, [r2]
      68: 6813       ldr   r3, [r2]
      6e: f443 6380  orr   r3, r3, #0x400   ;    置 0b0100（浮空输入）
      72: 6013       str   r3, [r2]

      46: eb00 0051  add.w r0, r0, r1, lsr #1   ; ③ (pclk2 + baud/2)
      52: fbb0 f0f1  udiv  r0, r0, r1           ;    / baud
      74: 6008       str   r0, [r1]              ;    写 BRR

      76: f242 000c  movw  r0, #0x200c      ; ④ CR1 = bit13|bit3|bit2
      7a: 6048       str   r0, [r1, #0x4]
      7c: 4770       bx    lr
```

**28 条指令**。几个观察：

1. **`movw` + `movt` 装地址**：4 个不同的外设地址，各花 2 条指令 = 8 条。
   这就是"裸地址宏"风格的固定开销；
   [ch08 8.12](../08-complex-types/8.12-结构体与嵌入式编程.md) 的结构体写法
   **不会减少这个开销**（实测机器码一致），但能校验偏移。
2. **读-改-写四连**（`ldr`/`bic`/`str` ×2 组）：因为只改 CRH 里的 4 位。
   注意这是**非原子的**——不过初始化阶段没并发，无所谓。
3. **`udiv r0, r0, r1`**：除法是真的除法指令。

## 三、实测：M3 有硬件除法，M0 没有（同一段代码）

```c
USART1_BRR = (pclk2 + baud/2u) / baud;      /* 这一行有除法 */
```

```
$ clang --target=armv7m-none-eabi -mcpu=cortex-m3 ... -Os -c uart.c
$ llvm-objdump -d m3.o | grep -c udiv
1                          ← M3：一条 udiv 指令
$ llvm-nm -u m3.o
（无未定义符号）            ← 不需要库函数

$ clang --target=armv6m-none-eabi -mcpu=cortex-m0 ... -Os -c uart.c
$ llvm-objdump -d m0.o | grep -c udiv
0                          ← M0：没有 udiv
$ llvm-nm -u m0.o
         U __aeabi_uidiv   ← 要调软件除法库！
$ llvm-objdump -d m0.o | grep bl
      5a: f7ff fffe  bl 0x5a     ← 函数调用
```

| 内核 | 硬件除法 | 代价 |
|---|---|---|
| **Cortex-M3 / M4 / M7** | ✅ `udiv` / `sdiv` 指令 | 2–12 周期 |
| **Cortex-M0 / M0+** | ❌ | 调 `__aeabi_uidiv`，**几百字节 Flash + 几十周期** |

⚠ **这条很容易记反**。M0 才是没有硬件除法的那个。
如果在 M0 上"只是算个波特率"，就要白搭进一个软件除法库——
**波特率是编译期常量，就该在编译期算掉**：

```c
#define PCLK2_HZ   8000000u
#define UART_BAUD  115200u
#define UART_BRR_VAL  ((PCLK2_HZ + UART_BAUD/2u) / UART_BAUD)   /* 编译期常量 = 69 */

USART1_BRR = UART_BRR_VAL;       /* 一条 mov + str，不需要除法 */
```

## 四、引脚复用的两个易错点

**① CNF/MODE 的 4 位编码（F1）**

PA9（TX）要配成 **复用推挽输出**：

| MODE[1:0] | CNF[1:0] | 含义 |
|---|---|---|
| 11（50 MHz） | 10 | **复用功能推挽输出** ← TX 要这个（`0b1011` = 0xB） |
| 11 | 00 | 通用推挽输出 ← 普通 GPIO 输出（**不是** TX） |
| 00 | 01 | 浮空输入 ← RX 要这个（`0b0100` = 0x4） |

把 TX 配成"通用推挽"（`0b0011`）是经典错误——
引脚能输出电平（示波器上有东西），但**不是 UART 的波形**。

**② F1 还要开 AFIO 时钟吗？**

对** USART1 这种"主功能复用"不需要** `RCC_APB2ENR` 的 AFIO 位（bit0）——
AFIO 只在**重映射（remap）和外中断 EXTI 配置**时才需要开。
这是 F1 特有的坑：很多教程无脑开 AFIO，其实默认复用不用开。

## 五、最小可跑：Hello World

```c
#include <stdint.h>
#define RCC_APB2ENR (*(volatile uint32_t *)0x40021018u)
#define GPIOA_CRH   (*(volatile uint32_t *)0x40010804u)
#define USART1_SR   (*(volatile uint32_t *)0x40013800u)
#define USART1_DR   (*(volatile uint32_t *)0x40013804u)
#define USART1_BRR  (*(volatile uint32_t *)0x40013808u)
#define USART1_CR1  (*(volatile uint32_t *)0x4001380Cu)
#define TXE (1u << 7)

#define PCLK2_HZ  8000000u
#define UART_BAUD 115200u

static void uart_putc(char c){
    while ((USART1_SR & TXE) == 0u) { }
    USART1_DR = (uint32_t)(uint8_t)c;
}
static void uart_puts(const char *s){ while (*s) uart_putc(*s++); }

int main(void){
    RCC_APB2ENR |= (1u<<2) | (1u<<14);                 /* ① 时钟 */
    GPIOA_CRH &= ~(0xFu<<4); GPIOA_CRH |= (0xBu<<4);   /* ② PA9 AF-PP */
    GPIOA_CRH &= ~(0xFu<<8); GPIOA_CRH |= (0x4u<<8);   /*    PA10 浮空输入 */
    USART1_BRR = (PCLK2_HZ + UART_BAUD/2u) / UART_BAUD;/* ③ 69 */
    USART1_CR1 = (1u<<13)|(1u<<3)|(1u<<2);             /* ④ UE+TE+RE */
    for (;;) { uart_puts("Hello World\n"); for (volatile int i=0;i<200000;i++); }
}
```

⚠ **NUCLEO-F103RB 上是 USART2（PA2/PA3）接到 ST-Link 的虚拟串口**，
不是 USART1。上面用 USART1（PA9/PA10）需要自己飞线；
想直接用板载 USB 口看到输出，就把基址和引脚换成 USART2（`0x40004400`）：

```
USART2: 基址 0x40004400，PA2(TX)/PA3(RX)，RCC_APB1ENR(0x4002101C) bit17
```

## 坑点（书 / 常识怎么说 / 实际是什么）

| 书 / 常识怎么说 | 实际是什么 |
|---|---|
| "初始化就是写几个寄存器" | **四步顺序固定**：时钟 → 引脚 → BRR → CR1。实测 28 条指令，一步都不能漏 |
| "漏一步会报错" | **静默失败**：不开时钟写寄存器不生效、不报错、不异常 |
| "TX 配成输出就行" | 要**复用推挽**（`0b1011`），不是通用推挽（`0b0011`）。后者引脚有电平但不是 UART 波形 |
| "F1 要开 AFIO 时钟" | **默认复用不需要**（只有 remap / EXTI 才要）。很多教程无脑开 |
| "波特率运行时算就行" | 实测 M0 上会拉进 `__aeabi_uidiv`（Flash + 时间）。**波特率是常量，编译期算掉** |
| "M3 没有硬件除法" | ❌ **实测反了**：M3 有 `udiv`（grep 到 1 条），**M0 才没有**（`U __aeabi_uidiv` + `bl`） |
| "USART1 就是板子上那个串口" | NUCLEO-F103RB 上**USART2(PA2/PA3)** 才接到 ST-Link VCP |

## 代码自测

<details>
<summary>Q1：四步里最容易漏的是哪一步？漏了怎么发现？</summary>

**第 ① 步：开时钟**，而且它是**最难发现的**——因为失败方式是"静默"。

```c
RCC_APB2ENR |= (1u<<2)|(1u<<14);      /* GPIOA(bit2) + USART1(bit14) */
```

为什么难发现：

| 漏的步骤 | 现象 | 可诊断性 |
|---|---|---|
| ① 时钟 | **什么都不发生**，且程序不崩 | ❌ 最难：代码看着全对，就是不工作 |
| ② 引脚复用 | 示波器上 TX 没波形 | ⚠ 要示波器 |
| ③ BRR | 有波形，但主机收**乱码** | ✅ 有输出就好定位 |
| ④ UE/TE | 什么都不发生 | ⚠ 同① |

**怎么发现**：用调试器直接读寄存器——如果写进去的值**读不出来**，就是时钟没开。

```
(gdb) x/1xw 0x40021018        # RCC_APB2ENR：bit2(GPIOA) bit14(USART1) 是否为 1
(gdb) x/1xw 0x40013808        # USART1_BRR：写进去的 69 还在不在？
(gdb) x/1xw 0x4001380C        # USART1_CR1：0x200C？
```

实测过（[ch03](../03-embedded-system-programming/README.md)）：
程序还没做 GPIO 时 `mdw 0x40021018` 读出 `0x00000000`——
**这就是"时钟全关"的默认状态**。

**一件非常有用的事：把"开时钟"做成显式清单**。

```c
/* rcc.h —— 每个外设一行，漏了就编译不过/一眼看出 */
#define RCC_APB2ENR_GPIOA    (1u << 2)
#define RCC_APB2ENR_AFIO     (1u << 0)
#define RCC_APB2ENR_USART1   (1u << 14)
#define RCC_APB1ENR_USART2   (1u << 17)      /* 注意 USART2 在 APB1！ */

RCC->APB2ENR |= RCC_APB2ENR_GPIOA | RCC_APB2ENR_USART1;
```

⚠ 另一个高频错误：**USART1 在 APB2，USART2/3 在 APB1**——
使能位在不同的寄存器（`RCC_APB2ENR` vs `RCC_APB1ENR`），
波特率公式里的时钟也不同（`PCLK2` vs `PCLK1`）。
抄 USART1 的代码改基址时最容易漏掉这一点。
</details>

<details>
<summary>Q2：BRR 该运行时算还是编译期算？</summary>

**编译期算。** 波特率是常量，没理由在运行时做除法。

实测代价（同一行 `(pclk2 + baud/2u) / baud`）：

```
Cortex-M3 : udiv 指令 × 1，llvm-nm -u 无未定义符号
Cortex-M0 : udiv × 0，U __aeabi_uidiv + bl  ← 拉进软件除法库
```

在 M0 上，就为了算个波特率，你的 Flash 里多了一份软件除法（几百字节），
而且**每次初始化都要跑一遍**。

```c
/* ✅ 编译期常量 */
#define PCLK2_HZ     8000000u
#define UART_BAUD    115200u
#define UART_BRR_VAL ((PCLK2_HZ + UART_BAUD/2u) / UART_BAUD)   /* = 69 */

USART1_BRR = UART_BRR_VAL;
```

实测 `-Os` 下这就是一条 `mov` + 一条 `str`，`udiv` 消失。

**还能更严谨一点——把误差也编译期检查了**：

```c
#define BAUD_REAL  (PCLK2_HZ / UART_BRR_VAL)
#define BAUD_ERR_PPT  (((BAUD_REAL - UART_BAUD) * 1000) / UART_BAUD)   /* 千分比 */
_Static_assert(BAUD_ERR_PPT < 20 && BAUD_ERR_PPT > -20, "波特率误差 > 2%");
```

这是 [ch08 8.12](../08-complex-types/8.12-结构体与嵌入式编程.md) 那套
`_Static_assert` 思路的延伸：**把运行时才发现的"乱码"变成编译期错误**。

⚠ 注意 `_Static_assert` 里的表达式必须是**整数常量表达式**——
所以 `PCLK2_HZ`、`UART_BAUD` 必须都是宏常量，不能是运行时变量。
这也倒逼你把时钟频率写成宏（本来就该这样——见
[ch19 SysTick](../19-systick-and-timer/19.3-g_ms与回绕安全的时间比较.md)）。

**什么时候才需要运行时算**：波特率要在运行时可变（比如自动波特率检测，
或用户通过命令切换）。那时才用除法，而且**M0 上要接受多一份库的代价**。
</details>

<details>
<summary>Q3：我按 USART1 写的代码，为什么插着 NUCLEO 的 USB 口看不到输出？</summary>

因为 **NUCLEO-F103RB 板载 ST-Link 的虚拟串口接的是 USART2（PA2/PA3），不是 USART1（PA9/PA10）**。

三者的对照：

| | USART1 | USART2 |
|---|---|---|
| 基址 | `0x40013800` | `0x40004400` |
| 总线 | **APB2** | **APB1** |
| 使能位 | `RCC_APB2ENR` bit14 | `RCC_APB1ENR` bit17 |
| 时钟 | `PCLK2` | `PCLK1`（注意 F1 上 APB1 最高 36 MHz） |
| 引脚 | PA9(TX) / PA10(RX) | **PA2(TX) / PA3(RX)** ← 接到 ST-Link VCP |

所以二选一：

**方案 A：改用 USART2**（想直接用板载 USB 口）

```c
#define USART2_SR  (*(volatile uint32_t *)0x40004400u)
#define USART2_DR  (*(volatile uint32_t *)0x40004404u)
#define USART2_BRR (*(volatile uint32_t *)0x40004408u)
#define USART2_CR1 (*(volatile uint32_t *)0x4000440Cu)
#define RCC_APB1ENR (*(volatile uint32_t *)0x4002101Cu)
#define GPIOA_CRL   (*(volatile uint32_t *)0x40010800u)    /* PA2/PA3 用 CRL（低 8 位） */

RCC_APB1ENR |= (1u<<17);        /* USART2 时钟 */
RCC_APB2ENR |= (1u<<2);         /* GPIOA 时钟（GPIOA 永远在 APB2） */
/* PA2: CRL bit11:8 = 0xB（复用推挽）; PA3: CRL bit15:12 = 0x4（浮空输入） */
USART2_BRR = ...;               /* 用 PCLK1，不是 PCLK2！ */
USART2_CR1 = (1u<<13)|(1u<<3)|(1u<<2);
```

⚠ 注意两个坑：
- GPIOA 的时钟**永远在 `RCC_APB2ENR`**（bit2），哪怕你用的是 APB1 上的 USART2；
- PA2/PA3 是**低 8 位引脚**，配置寄存器是 `GPIOA_CRL`（`0x40010800`），
  不是 `CRH`（`0x40010804`）。

**方案 B：坚持 USART1**（用外部 USB-TTL 线）

从 PA9(TX) 接 TTL 线的 RX，PA10(RX) 接 TX，共地。
这样能用逻辑分析仪同时抓波形，调试 UART 本身时更好用。

**排查时先确认这一点**——这是"代码全对但收不到"的头号原因。

```
$ ls /dev/cu.usbmodem*        # 本机实测见到：/dev/cu.usbmodem2103
$ screen /dev/cu.usbmodem2103 115200
```
</details>
