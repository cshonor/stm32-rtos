## 书这一节讲什么

一句话：**UART 的帧格式、波特率、电平标准从哪来**——
为什么是 8N1、为什么是 115200、为什么 RS-232 是 ±12 V。

书讲的是历史。历史的意义在于：**现在这些"约定"看着莫名其妙，
但它们每一个都是当年硬件限制的产物**。理解了限制，出错时才知道往哪查。

## 一、帧格式：为什么是"8N1"

```
空闲 ──┐   ┌───┐   ┌───┐   ┌───┐   ┌───┐   ┌───┐   ┌───────
       │   │   │   │   │   │   │   │   │   │   │   │
       └───┘   └───┘   └───┘   └───┘   └───┘   └───┘
       起始位  D0  D1  D2  D3  D4  D5  D6  D7  停止位(可 1/1.5/2)
               ↑ 低位先发（LSB first）
       （可选奇偶校验位插在 D7 和停止位之间）
```

**"8N1" = 8 数据位 / N 无校验 / 1 停止位**，这是最常见的组合。

| 字段 | 作用 | 为什么需要 |
|---|---|---|
| **起始位**（0） | 告诉对方"我要开始发了" | 异步——没有时钟线，必须有同步信号 |
| **8 数据位** | 一个字节 | 早期是 5/7 位（电传打字机、ASCII），8 位成为事实标准 |
| **校验位**（可选） | 检错（奇偶） | 老线路噪声大。⚠ 只能检 1 位错，检不出 2 位错 |
| **停止位**（1） | 给接收方喘息 + 分隔帧 | 早期机械设备的处理时间 |

**关键点：异步 = 双方各自用各自的时钟计时，靠"事先约定的波特率"对齐。**
这也是波特率误差会成为 bug 的根本原因（下面算）。

⚠ **LSB first**：数据位是**低位先发**。用示波器/逻辑分析仪看波形时，
字节 `0x01` 看起来是 `1,0,0,0,0,0,0,0`（不是反过来）。

## 二、波特率：名字就带着历史

"Baud" 来自 **Émile Baudot**（19 世纪法国电报工程师）。
严格说波特（符号率）和比特率不是一回事，但在 UART 里**一个符号 = 一个 bit**，
所以 115200 baud = 115200 bps。

常见波特率看着很怪——`9600 / 19200 / 38400 / 57600 / 115200`——
因为它们来自早期 UART 芯片（8250 / 16550）的**分频链**：

```
1.8432 MHz 晶振 ÷ 16 ÷ N
  9600 = 1.8432M / 16 / 12
 115200 = 1.8432M / 16 / 1
```

**1.8432 MHz 这个晶振值是被波特率倒推出来的**——
它能被 16 整除后还能整除所有常见波特率。

## 三、实测：整数分频必然带来误差（STM32F1）

STM32F1 的公式（RM0008）：`BRR = PCLK / baud`，且 BRR 是
**12 位整数 + 4 位小数**，但很多代码只写整数部分。

用 `(PCLK + baud/2) / baud`（四舍五入）算，实测误差表：

| PCLK2 | 目标 baud | 理想 BRR | 实际 BRR | 实际 baud | 误差 | |
|---|---|---|---|---|---|---|
| 8 MHz（HSI 默认） | 9600 | 833.33 | 833 | 9603.8 | +0.04% | ✅ |
| 8 MHz | 19200 | 416.67 | 417 | 19184.7 | −0.08% | ✅ |
| 8 MHz | 38400 | 208.33 | 208 | 38461.5 | +0.16% | ✅ |
| 8 MHz | 57600 | 138.89 | 139 | 57554.0 | −0.08% | ✅ |
| 8 MHz | 115200 | 69.44 | 69 | 115942.0 | **+0.64%** | ✅ |
| 8 MHz | 230400 | 34.72 | 35 | 228571.4 | −0.79% | ✅ |
| 8 MHz | 460800 | 17.36 | 17 | 470588.2 | **+2.12%** | ⚠ |
| 8 MHz | 921600 | 8.68 | 9 | 888888.9 | **−3.55%** | ⚠ |
| 72 MHz（PLL） | 9600 | 7500 | 7500 | 9600.0 | **0%** | ✅ |
| 72 MHz | 115200 | 625 | 625 | 115200.0 | **0%** | ✅ |
| 72 MHz | 921600 | 78.13 | 78 | 923076.9 | +0.16% | ✅ |

两条结论：

1. **配了 PLL（72 MHz）之后，常见波特率全都是零误差**——
   这就是工程上"先把时钟配到 72 MHz 再开串口"的原因；
2. **8 MHz 下超过 460800 就逼近 5% 极限了**——别在低速时钟上跑高速波特率。

## 四、误差极限为什么是 ±5%（工程上取 ±2%）

接收方在**每个 bit 的中间**采样。一帧 = 10 bit（8N1）。
若双方波特率相对误差为 ε，采样点每个 bit 漂移 ε 个周期：

```
第 1 bit 采样点漂移：≈ 0
第 10 bit 采样点漂移：10ε
```

只要**最后一个数据位**的采样点还在自己的 bit 周期内（漂移 < 0.5 bit），就能采对：

```
10ε < 0.5   →   ε < 5%
```

工程上双方各贡献误差，留余量通常要求 **< 2%**。

## 五、电平标准：TTL / RS-232 / RS-485

| 标准 | 电平 | 距离 | 现在用在哪 |
|---|---|---|---|
| **TTL 串口**（MCU 直接出） | 0 V / 3.3 V（或 5 V） | < 几十 cm | 板内、模块间、USB 转串口 |
| **RS-232** | **−3..−15 V = 1，+3..+15 V = 0**（反相！） | ~15 m | 老式 DB9 串口、工业设备 |
| **RS-485** | 差分 ±1.5 V 以上 | **~1200 m** | 工业总线（Modbus） |

⚠ 两个必踩的坑：

1. **RS-232 是反相的**，而且电平是 ±12 V——
   **直接把 MCU 的 TX 接到 DB9 上会烧芯片**。必须经 MAX232/MAX3232 之类的电平转换；
2. "TTL 串口" 和 "RS-232" 都叫"串口"，但**电平完全不同**。
   买 USB 转串口线时要看清是 **TTL（3.3 V / 5 V）** 还是 RS-232。

**NUCLEO 板上的 ST-Link 自带虚拟串口（VCP）**，
把 MCU 的 TTL 串口转成 USB CDC——所以你不需要额外的转换线。

## 六、现在还剩什么

| 历史产物 | 现在还留着吗 |
|---|---|
| 8N1 帧格式 | ✅ 通用默认 |
| 9600 / 115200 波特率 | ✅ 115200 是调试默认 |
| RS-232 电平 | ⚠ 只在工业/老设备上 |
| 奇偶校验 | ⚠ 基本不用了（改用 CRC / 校验和，因为奇偶只能检 1 位错） |
| 调制解调器（Modem） | ❌ 名字留在 "AT 指令" 里 |
| 流控 RTS/CTS | ⚠ 高速时还需要（没有就丢字节） |

## 坑点（书 / 常识怎么说 / 实际是什么）

| 书 / 常识怎么说 | 实际是什么 |
|---|---|
| "波特率设多少就是多少" | 整数分频必然有误差。实测 8 MHz/115200 = 69.44 → 69，误差 **+0.64%** |
| "误差 5% 以内就行" | 理论极限 5%（双方合计），工程留余量取 **2%**。实测 8 MHz 下 460800 已 +2.12% |
| "115200 随便用" | 前提是时钟配对了。**以为 72 MHz 实际 8 MHz → BRR=625 → 实际 12800 baud，差 9 倍**（满屏乱码） |
| "串口是 0/3.3V" | TTL 串口才是。**RS-232 是 ±12 V 且反相**，直连会烧芯片 |
| "数据位从高位开始发" | **LSB first**，低位先发（看波形时要注意） |
| "校验位能检错" | 奇偶只能检**奇数个**位错，检不出 2 位错。现代协议用 CRC |

## 代码自测

<details>
<summary>Q1：为什么波特率必须双方一致？差多少会出错？</summary>

因为 UART 是**异步**的——没有时钟线，双方各用自己的时钟计时。

发送方按自己的波特率决定"每个 bit 持续多久"；
接收方按自己的波特率决定"什么时候采样"。
两者的时钟**从不协商**，只靠"事先约定"对齐。

所以一旦不一致，采样点就会漂移：

```
发送方 bit 边界：  |    |    |    |    |    |
接收方采样点：      ^    ^    ^    ^    ^     ← 每个 bit 漂移 ε
                   1    2    3    4   ...
```

一帧 10 bit（8N1），第 N 个 bit 的采样点漂移 `N·ε`。
只要漂移 < 0.5 bit（还在自己的位周期内），就能采对：

```
10·ε < 0.5   →   ε < 5%
```

**工程取值**：

| | 值 | 说明 |
|---|---|---|
| 理论极限 | **±5%** | 双方合计 |
| 工程要求 | **< 2%** | 双方各贡献误差时留余量 |
| 实测 HSI 8 MHz/115200 | **+0.64%** | ✅ 安全 |
| 实测 HSI 8 MHz/921600 | **−3.55%** | ⚠ 逼近极限 |

⚠ 一个常被忽略的点：**晶振本身也有误差**。
HSI（内部 RC）精度典型 **±1%**（全温范围可能 ±2~5%），
HSE（外部晶振）典型 **±10~50 ppm**（0.001%~0.005%）。

所以对精度有要求时（比如 460800 以上、或者量产一致性），
**要用 HSE 而不是 HSI**——HSI 自己的误差就可能吃掉全部余量。
</details>

<details>
<summary>Q2："收到乱码"最常见的三个原因是什么？怎么快速定位？</summary>

按出现频率排：

**① 波特率算错了（最常见）**

典型场景：**忘了配 PLL，实际 PCLK2 = 8 MHz，但 BRR 是按 72 MHz 算的**。

```
以为：BRR = 72_000_000 / 115200 = 625
实际：baud = 8_000_000 / 625 = 12800          ← 差 9 倍！
```

实测（Python 按 RM0008 公式）：

```
误配场景：以为 PCLK2=72MHz 写 BRR=625，实际 PCLK2=8MHz
  实际 baud = 8000000/625 = 12800.0 → 与目标 115200 差 9.0 倍
```

主机上就是满屏乱码。**快速验证**：主机上先试 **9600**——
如果 9600 能读，说明板子的实际波特率是"你以为的 ÷9"。

**② 时钟源搞错了**

上电默认用 HSI 8 MHz，配了 PLL 才是 72 MHz。
如果你**只写了 PLL 配置但没等 PLL 就绪**（`RCC_CR` 的 `PLLRDY`），
时钟切换就没生效——还是 8 MHz。

```
(gdb) x/1xw 0x40021000        # RCC_CR：bit25 PLLRDY 是否为 1
(gdb) x/1xw 0x40021004        # RCC_CFGR：bit3:2 SWS 是否为 0b10（PLL 作系统时钟）
```

**③ 帧格式不匹配**

板子 8N1，主机设成了 7E1 或者带流控——能收到东西但全错。

```
$ stty -f /dev/cu.usbmodemXXXX 115200 cs8 -parenb -cstopb clocal
#                                      8 数据位  无校验   1 停止位  无视流控
```

**排查口诀：先证明硬件通，再证明参数对。**

最强的一招是**绕过所有代码直接写寄存器**：

```
(gdb) set {int}0x40013804 = 0x41      # 直接往 USART1_DR 写 'A'
```

如果这样主机能收到 `A`，说明链路和波特率都对，问题在你的代码；
如果收不到，问题在初始化（时钟 / 引脚 / BRR / UE）。
</details>

<details>
<summary>Q3：RS-232 为什么是负逻辑（1 = −12 V）？现在还要管吗？</summary>

历史原因：**早期电话线和长距离线路的电气特性**，
负电压在潮湿/腐蚀环境下更稳定（电化学迁移方向有利），
而且 −12 V 的"空闲"状态能让接收端检测出"线断了"（0 V = 断线，不是有效电平）。

现代影响——三个必须知道的：

**① 电平完全不同，直连会烧芯片**

| | 逻辑 1 | 逻辑 0 |
|---|---|---|
| TTL（MCU 引脚） | **3.3 V**（或 5 V） | **0 V** |
| RS-232 | **−3 .. −15 V** | **+3 .. +15 V** |

把 MCU 的 TX（0/3.3 V）接到 DB9 的 RX 上：
- MCU 发 0 V，RS-232 设备看到"无效电平"；
- RS-232 设备发 −12 V 到 MCU 引脚 → **过压，可能永久损坏**。

必须经电平转换芯片（MAX232 / MAX3232 / SP3232）。

**② 买 USB 转串口线时要分清**

- **TTL 串口线**（CH340 / CP2102 / FT232RL）：4 根线（VCC/GND/TX/RX），
  电平 3.3 V 或 5 V——**接 MCU 用这个**；
- **RS-232 线**（带 DB9 头）：里面已经集成电平转换，接 DB9 设备。

**③ NUCLEO 板上不需要这些**

NUCLEO 的 **ST-Link 自带虚拟串口（VCP）**：
MCU 的 USART2 TX/RX 已经接到 ST-Link，ST-Link 再转成 USB CDC。
所以插上 USB 后主机上会出现 `/dev/cu.usbmodem*`，**直接用就行**。

⚠ 但要注意 NUCLEO-F103RB 上 **USART2（PA2/PA3）是接到 ST-Link 的那个**，
不是 USART1。用 USART1 的话得自己从 PA9/PA10 飞线出来。

**一句话：现在做 MCU 开发几乎只碰 TTL 串口；
RS-232 只在接老工业设备/PLC 时才会遇到，那时记得加转换芯片。**
</details>
