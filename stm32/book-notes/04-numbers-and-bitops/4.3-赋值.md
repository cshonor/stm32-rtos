# 4.3 赋值

> 书：第 4 章 数字和变量 · 4.3 赋值（原书 p44–64 区间内）
> 上一篇：[4.2 声明变量](4.2-声明变量.md) ｜ 下一篇：[4.4 初始化](4.4-初始化.md)
> 对应实验：`--target=armv7m-none-eabi -mcpu=cortex-m3` 交叉编译 + `llvm-objdump -d`

## 书这一节讲什么

一句话：**`=` 把右边的值放进左边的变量里**。语法书上这叫"赋值表达式"。

裸机上真正有意思的问题是：**`=` 的右边和左边，到底发生了几次内存访问？**
因为左边可能不是普通变量，而是**一个硬件寄存器**——那时候 `=` 就不是"改内存"，
而是"给硬件下命令"。

## 一、普通赋值：一次 `str`

```c
int x;
x = 5;
```

在 Cortex-M 上就是往某个 RAM 地址（或寄存器）写一次。
局部变量通常在寄存器里，连 `str` 都不一定有。

## 二、赋给寄存器：一次 `str`，但语义完全不同

```c
#define GPIOA_BSRR (*(volatile uint32_t *)0x40010810u)
GPIOA_BSRR = (1u << 5);
```

```
$ clang --target=armv7m-none-eabi -mcpu=cortex-m3 -mthumb -Os -c vol.c -o vol.o
$ llvm-objdump -d vol.o
00000010 <b>:
      10: f640 000c     movw r0, #0x80c
      18: 2101          movs r1, #0x1
      1a: 6001          str  r1, [r0]      ← 写 1
      1c: 2102          movs r1, #0x2
      1e: 6001          str  r1, [r0]      ← 写 2（没有被合并掉！）
      20: 4770          bx   lr
```

上面这个实测是 `REG = 1; REG = 2;` 两条赋值。**两次 `str` 都在**——
因为 `REG` 是 `volatile`，编译器不敢合并。
（同一份实测里 `unsigned x = REG; unsigned y = REG;` 也生成了两次 `ldr`。）

这正是裸机需要 `volatile` 的原因：**每次赋值都必须真的发生**，
因为"写这个地址"本身就是给硬件的副作用，而不是在更新一个可以被优化掉的值。

## 三、赋值的宽度：左边窄就会截断（静默）

```c
uint32_t reg;
void g(void){ uint8_t b = 0x1FF; reg = b; }
```

```
$ clang ... -Wall -Wextra -c conv.c
conv.c:4:27: warning: implicit conversion from 'int' to 'uint8_t'
      (aka 'unsigned char') changes value from 511 to 255 [-Wconstant-conversion]
```

`0x1FF`（511）塞进 `uint8_t` 变成 255。**编译器这次好心提醒了**，
但只在"常量能算出来"的时候才提醒；运行时才发生的截断（比如 `uint16_t` 里放了个
`uint32_t` 的计算结果）在 `-Wall -Wextra` 下**一声不响**——要 `-Wconversion` 才抓得到，
而 `-Wconversion` 在裸机代码里噪音很大（每次 `reg |= (1u<<n)` 都可能叫）。

## 四、读-改-写：赋值里最危险的一种

```c
GPIOA_ODR = GPIOA_ODR + 1;     /* 读 → 加 → 写，3 条指令 */
```

```
00000012 <g>:
      1a: 6801     ldr  r1, [r0]      ← 读
      1c: 3101     adds r1, #0x1      ← 改
      1e: 6001     str  r1, [r0]      ← 写
```

三条指令之间**可以被中断打断**。如果 ISR 也改了同一个寄存器的另一位，
这里的 `str` 会把 ISR 的修改覆盖回去。
这是本章最重要的一条伏笔，[4.11](4.11-缩写运算符.md) 和
[4.12](4.12-用位操作控制内存映射IO寄存器.md) 会把它彻底讲完。

## 五、赋值 vs 初始化（容易混）

```c
uint32_t a;      /* 声明（定义在 .bss，启动时被清 0） */
a = 5;           /* 赋值：运行时执行的一条指令 */
uint32_t b = 5;  /* 初始化：进入 .data，由启动代码从 Flash 拷过来 */
```

区别不在语法，在**成本**：`b` 的初值要占 Flash，`a = 5` 的 5 在指令编码里（立即数）。
[4.4](4.4-初始化.md) 展开这点。

## 坑点（书 / 常识怎么说 / 实际是什么）

| 书 / 常识怎么说 | 实际是什么 |
|---|---|
| "`x = 5` 就是把 5 放进 x" | 左边是 MMIO 寄存器时，`=` 是**给硬件下命令**；必须有 `volatile`，否则可能被优化掉（实测两次 `str` 都保留） |
| "连续写两次，编译器会合并成最后一次" | 对普通变量会；对 `volatile` 寄存器**不会**（实测 `REG=1; REG=2;` 生成两次 `str`） |
| "赋值会自动转换类型" | 会转换，也会**静默截断**。常量截断 `-Wall` 能报（实测 511→255），运行时截断要 `-Wconversion` |
| "`reg = reg + 1` 是一步" | 实测 3 条指令（ldr/adds/str），中间可被打断 |
| "赋值和初始化是一回事" | 初始化进 `.data`（占 Flash + RAM），赋值是指令里的立即数（只占 Flash 的指令空间） |

## 代码自测

<details>
<summary>Q1：为什么给寄存器赋值必须加 `volatile`，普通变量就不用？</summary>

因为**编译器优化的前提假设是"内存只在程序写的时刻变化"**，
而硬件寄存器违反了这个假设。

实测对照（同一个 `unsigned x = REG; unsigned y = REG;`）：

- 不加 `volatile`：编译器认为两次读的是同一个没被改过的值，合并成一次 `ldr`；
- 加了 `volatile`：生成两次 `ldr`（实测印证）。

写的一侧同理：普通变量的连续两次赋值，后一次会覆盖前一次，编译器直接把前一次删掉；
但对寄存器来说，**"写"这个动作本身就是目的**（比如 `BSRR` 写 1 是置位、
写一次就产生一次电平跳变），删掉一次就少一次硬件动作。

所以裸机的规则是：**凡是地址指向硬件的，声明必须带 `volatile`**，
而且永远用 `#define REG (*(volatile uint32_t *)ADDR)` 这种一次性写对的宏，
不要指望后面记得补。
</details>

<details>
<summary>Q2：`uint8_t b = 0x1FF;` 只是一条警告，真的会出问题吗？</summary>

会，而且是那种"看代码完全正确"的问题。

实测编译器说的是 `changes value from 511 to 255`——你以为写了 511，实际存了 255。
如果这是波特率分频器的高字节、DMA 传输长度、或者某个计数上限，
硬件就会按 255 来工作：**串口波特率差一倍、DMA 少传数据、定时器提前溢出**。

更麻烦的是运行时截断不报警告：

```c
uint16_t len = rx_bytes();      /* rx_bytes() 返回 uint32_t，这里静默截断 */
```

防护手段：
1. 打开 `-Wconversion` 看一遍，把真问题的地方修掉，噪音处用显式转换 `(uint16_t)` 表达"我知道"；
2. 跨界数据（协议长度、缓冲区索引）统一用 `uint32_t`，只在**写寄存器那一刻**才窄化。
</details>

<details>
<summary>Q3：`a = 5;`（赋值）和 `uint32_t a = 5;`（初始化）在 Flash/RAM 账上差多少？</summary>

| 写法 | Flash | RAM | 说明 |
|---|---|---|---|
| `uint32_t a;` + 后面 `a = 5;` | 只多一条 `movs` 指令（2–4 字节） | 4 字节（`.bss`） | 值编码在指令里 |
| `uint32_t a = 5;` | 4 字节（`.data` 的初值镜像） | 4 字节（`.data`） | 上电由启动代码拷贝 |

单个变量差几字节无所谓，但两类场景会放大：

- **大数组/大结构体有初值**：`uint8_t buf[1024] = {1,2,...}` 会在 Flash 里多 1 KB 镜像，
  还要在启动时花时间拷贝；
- **启动时间敏感**：`.data` 拷贝是在 `main` 之前跑的，拷贝量越大，上电到 `main` 越慢。

所以裸机的经验是：**默认不写初值（放 `.bss`），需要非 0 初值才初始化**，
大块的初始数据在 `main` 里用代码填（或干脆 `const` 放 Flash）。
</details>
