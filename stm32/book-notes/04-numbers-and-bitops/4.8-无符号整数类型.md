# 4.8 无符号整数类型

> 书：第 4 章 数字和变量 · 4.8 无符号整数类型（原书 p44–64 区间内）
> 上一篇：[4.7 标准整数](4.7-标准整数.md) ｜ 下一篇：[4.9 溢出](4.9-溢出.md)
> 对应实验：主机侧 clang 23.1.0（`-O2` + `-fsanitize=undefined`）实测

## 书这一节讲什么

一句话：**`unsigned` 类型的取值范围是 `0 .. 2^n-1`，不会是负数**，
所以同样的位宽能表示更大的正数（比如 `uint8_t` 到 255，`int8_t` 只到 127）。

书讲的是"范围更大"这个好处。裸机上真正重要的是另一条性质——
**unsigned 的溢出是被定义好的回绕**，整个嵌入式世界都建立在这条性质上。

## 一、实测：unsigned 溢出是回绕，不是错误

```
$ clang -O2 -o ovf ovf.c && ./ovf
unsigned: UINT_MAX+1 = 0
signed  : INT_MAX+1  = -2147483648

$ clang -O2 -fsanitize=undefined -o ovf_ub ovf.c && ./ovf_ub
ovf.c:5:69: runtime error: signed integer overflow: 2147483647 + 1 cannot be represented in type 'int'
SUMMARY: UndefinedBehaviorSanitizer: undefined-behavior ovf.c:5:69
```

注意 UBSan **只报了 signed 那一行**——unsigned 的回绕不是错误，是规定。

## 二、这条性质撑起了什么：环形缓冲区

这是 unsigned 在裸机上最重要的应用（书第 10 章用它做串口中断缓冲）：

```c
#define RB_SIZE 64                                  /* 2 的幂 */
rb->head = (rb->head + 1) & (RB_SIZE - 1);          /* 位与代替取模 */
uint32_t used = head - tail;                        /* 即使 head 已回绕，差值仍正确 */
```

`head - tail` 在 head 已经回绕（head < tail）时依然算出正确的 "used"，
**靠的就是 unsigned 回绕被定义好**。
如果换成 `int`，`head < tail` 时得到负数，还得额外处理——
而这套"加减完不管，用的时候再算差"的写法，是中断安全的：
ISR 改 `head`、主循环改 `tail`，双方都不需要关中断（单写者/单读者）。

## 三、unsigned 的经典翻车点：倒计时循环

```c
for (unsigned i = n; i >= 0; --i) { }     /* ❌ 死循环：i >= 0 对 unsigned 恒真 */
```

`i >= 0` 永远成立，减到 0 之后再减变成 `UINT_MAX`，循环永不结束。
裸机上这表现为"程序卡死在某个初始化里"，看门狗复位，很难查。

正确写法（二选一）：

```c
for (unsigned i = n; i-- > 0; ) { }       /* 惯用法：先比较后自减 */
for (unsigned i = 0; i < n; i++) { ... }  /* 正向循环，最不容易错 */
```

## 四、`unsigned` 不等于"更安全"

常见误解是"我用了 unsigned 就不会有负数了，所以更安全"。
实际上它只是把一类错误换成了另一类：

| 场景 | signed | unsigned |
|---|---|---|
| 溢出 | UB（编译器可以假定它不发生） | 定义良好的回绕 |
| 减到负数 | 得到负值（可判断） | 变成一个巨大的正数（`0 - 1` = `UINT_MAX`） |
| 与 `sizeof`/数组下标混用 | 会被提升成 unsigned，比较语义变化 | 一致 |
| 边界检查 `if (len > 0)` | 正常 | 正常，但 `len` 是算出来的差值时要小心回绕 |

第三条是隐蔽的坑：`int i = -1; if (i < sizeof(buf))` ——
`sizeof` 是 `size_t`（unsigned），`i` 被提升成 unsigned，
`-1` 变成 `SIZE_MAX`，于是 `i < sizeof(buf)` 为**假**。
这类 bug 在 `-Wall` 下会有 `-Wsign-compare` 提示，值得打开。

## 坑点（书 / 常识怎么说 / 实际是什么）

| 书 / 常识怎么说 | 实际是什么 |
|---|---|
| "unsigned 表示范围更大，更好" | 真正的好处是**溢出行为确定**（实测：UBSan 只报 signed 那行） |
| "unsigned 不会是负数，更安全" | `0 - 1` = `UINT_MAX`，边界判断反而更容易错 |
| "`for (unsigned i=n; i>=0; --i)` 很自然" | ❌ 死循环，恒真。用 `i-- > 0` |
| "`head - tail` 可能减出负数" | unsigned 下回绕仍给出正确差值——这是环形缓冲能无锁工作的前提 |
| "`unsigned` 和 `int` 比较没差别" | 有。`int` 会被提升成 unsigned，负值变成巨大正数（`-Wsign-compare` 能抓） |

## 代码自测

<details>
<summary>Q1：unsigned 溢出"定义良好"，那我是不是可以随便依赖它？</summary>

可以依赖，但要明确你依赖的是哪条规则：**C 标准规定 unsigned 运算结果总是模 2^n**
（n 是该类型位宽）。所以 `UINT_MAX + 1 == 0` 不是碰巧，是保证（实测输出印证）。

能放心依赖的场景：

- **自由回绕的计数器**：`uint32_t ticks`，溢出后继续，用差值算时间
  （差值在"两次读取间隔 < 2^32"时永远正确）；
- **环形缓冲的 head/tail**：见正文；
- **哈希、校验和**：本来就是模运算。

不能依赖的场景：

- **倒计时循环**：`i >= 0` 恒真（见正文）；
- **任何"这个值应该单调增"的假设**：回绕后它突然变小了，
  比如 `if (now > last_timeout)` 在回绕那一刻会误判；
- **用作数组下标前没取模**：回绕后的巨大值直接越界。

一句话：**unsigned 适合"环形的量"（计数器、缓冲下标），不适合"单调的量"（超时判断、序号比较）**
——后者要显式处理回绕（比如用差值比较 `(int32_t)(a - b) > 0`）。
</details>

<details>
<summary>Q2：`uint8_t` 做循环变量有什么问题？</summary>

两个问题，一个是性能，一个是正确性。

**性能**：`uint8_t` 参与运算时会被**整型提升**成 `int`，算完再截断回 8 位。
在 Cortex-M 上这通常意味着额外的 `uxtb`（零扩展）指令：

```c
for (uint8_t i = 0; i < 100; i++)   /* 每次比较/自增都可能多一条指令 */
for (uint32_t i = 0; i < 100; i++)  /* 直接用 32 位寄存器，最快 */
```

**正确性**：`uint8_t` 的上限是 255。写 `for (uint8_t i = 0; i <= 255; i++)` 是死循环
（`i` 永远 ≤ 255），而改成 `< 256` 又因为 `i` 最大 255 而永远成立——两种写法都是死循环。
这类 bug 编译器有时会警告，有时不会。

所以裸机的惯例：**循环变量用 `uint32_t`（或 `size_t`）**，
`uint8_t` / `uint16_t` 只用在"跨界数据"上（UART 字节、协议字段、寄存器字节访问）。
</details>

<details>
<summary>Q3：为什么中断安全的环形缓冲必须用 unsigned 下标？</summary>

因为这套写法要满足"**ISR 改 head、主循环改 tail，双方都不用关中断**"。

```c
/* ISR 里 */
if (((rb->head + 1u) & (RB_SIZE - 1u)) != rb->tail) {
    rb->buf[rb->head] = byte;
    rb->head = (rb->head + 1u) & (RB_SIZE - 1u);
}
/* 主循环里 */
while (rb->tail != rb->head) { c = rb->buf[rb->tail]; rb->tail = (rb->tail + 1u) & (RB_SIZE - 1u); }
```

关键点：

1. **单写者**：`head` 只有 ISR 写、`tail` 只有主循环写 → 不需要互斥；
2. **`tail != head` 判断在回绕下依然正确** → 依赖 unsigned 回绕被定义；
3. **下标本身被 `& (RB_SIZE-1)` 限制在范围内** → 即使 `head` 自由回绕也不越界。

如果换成 `int`，第 2 条就破了：`head` 回绕成负数时 `tail != head` 的语义就乱了，
而且 `buf[head]` 会直接越界。

这就是为什么裸机代码里"看起来应该限制范围"的计数器反而故意用 `uint32_t` 自由回绕：
**回绕是被定义好的，越界不是。**
</details>
