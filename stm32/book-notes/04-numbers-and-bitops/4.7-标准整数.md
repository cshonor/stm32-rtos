# 4.7 标准整数

> 书：第 4 章 数字和变量 · 4.7 标准整数（原书 p44–64 区间内）
> 上一篇：[4.6 数字表示](4.6-数字表示.md) ｜ 下一篇：[4.8 无符号整数类型](4.8-无符号整数类型.md)
> 对应实验：`--target=armv7m-none-eabi -ffreestanding` 实测 + 主机侧 `-Wconversion`

## 书这一节讲什么

一句话：**用 `<stdint.h>` 里的 `uint32_t` / `int16_t` 这些定宽类型，
别用 `int` / `long`**——因为后者的宽度因平台而异。

这是全章**最实用的一节**，也是裸机代码和 PC 代码一眼能看出的区别：
裸机项目里满屏 `uint32_t`，几乎没有裸 `int`。

## 一、实测：`stdint.h` 在裸机上能用吗（没有 libc）

```
$ printf '#include <stdint.h>\nuint32_t x;\nuint8_t y;\n' > fs.c
$ clang --target=armv7m-none-eabi -mcpu=cortex-m3 -mthumb -ffreestanding -c fs.c -o /dev/null
（无报错 → 可用）
```

**能用。** `stdint.h` 是编译器自带的头（clang 的 resource dir 里），
它描述的是**目标平台的类型宽度**，不依赖任何库函数。
这条实测的意义是：**裸机工程可以放心全程使用 `uint*_t`，不需要引入 libc。**

## 二、定宽类型对照表（Cortex-M3 实测通过）

```c
_Static_assert(sizeof(void*) == 4, "ptr on Cortex-M");
_Static_assert(sizeof(int)   == 4, "int");
_Static_assert(sizeof(long)  == 4, "long on Cortex-M != 8");
_Static_assert(sizeof(long long) == 8, "long long");
_Static_assert(sizeof(uint32_t) == 4, "uint32_t");
```

| 需求 | 用这个 | 别用 |
|---|---|---|
| 寄存器值 / 地址 / 掩码 | `uint32_t` | `unsigned int`、`unsigned long` |
| 字节、UART 收发 | `uint8_t` | `char`、`unsigned char` |
| 16 位计数、ADC 值 | `uint16_t` | `short` |
| 有符号差值（温度、增量） | `int32_t` | `int`、`long` |
| 64 位时间戳 | `uint64_t` | `long`（Cortex-M 上是 4 字节！） |
| 指针转整数 | `uintptr_t` | `unsigned long` |

⚠ 本机实测的锚点：**Mac 上 `long`=8，Cortex-M 上 `long`=4。**
所以"用 `long` 存 64 位时间戳"在 Mac 上对、在板子上错——约 71 分钟回绕一次。

## 三、`<stdint.h>` 的另外几个成员

| 类型 | 用途 | 裸机例子 |
|---|---|---|
| `uint_fast8_t` | "至少 8 位、最快" | 循环变量（Cortex-M 上就是 32 位） |
| `uint_least8_t` | "至少 8 位、最小" | 省内存的结构体字段 |
| `uintmax_t` / `intmax_t` | 最宽的整数类型 | 通用打印/比较 |
| `uintptr_t` | 能装下指针的整数 | 把寄存器地址当数字算 |
| `SIZE_MAX` / `UINT32_MAX` 等 | 各类型的极值宏 | 边界判断，不用手背 `0xFFFFFFFF` |

裸机上真正常用的是前四个 + 极值宏。
`UINT32_MAX` 这类宏比手写 `0xFFFFFFFFu` 更可靠——
它跟类型绑定，改类型时不会因为忘了改常量而出错。

## 四、打印定宽类型：`inttypes.h` 的 `PRIu32`

裸机上大多没有 `printf`（要自己接 UART，见 [9.3 串行输出](../09-uart-serial/9.3-串行输出.md)），
但在主机侧调试、或者移植了 `printf` 之后，格式串要对上：

```c
#include <inttypes.h>
printf("ticks=%" PRIu32 " addr=0x%08" PRIx32 "\n", ticks, addr);
```

`PRIu32` 展开成正确的长度修饰符（`"u"` / `"lu"` 取决于平台）。
好处是**同一份代码在 32 位和 64 位主机上都能正确打印**——
手写 `%u` 打印 `uint32_t` 在 `long` 是 8 字节的平台上会触发 `-Wformat` 警告。

## 坑点（书 / 常识怎么说 / 实际是什么）

| 书 / 常识怎么说 | 实际是什么 |
|---|---|
| "用 `stdint.h` 就要有 libc" | 不需要。实测 `-ffreestanding` 下 `#include <stdint.h>` 通过（编译器自带头） |
| "`int` 就够了，改起来麻烦" | 麻烦一次，省一辈子。`long` 在 Mac 是 8、Cortex-M 是 4（实测断言） |
| "`uint8_t` 就是 `unsigned char`" | 语义不一样：前者明确"我就是一个 8 位位模式"，读代码的人不会误会成字符 |
| "写 `0xFFFFFFFF` 当最大值" | 用 `UINT32_MAX`：跟类型绑定，不会因为改了类型而漏改常量 |
| "`printf("%u", x)` 打 `uint32_t`" | 平台相关。用 `PRIu32`（`inttypes.h`），否则 64 位主机上 `-Wformat` 报警 |

## 代码自测

<details>
<summary>Q1：`int` 和 `int32_t` 在 Cortex-M 上都是 4 字节，那还有必要换吗？</summary>

宽度一样，但**表达的信息不一样**：

- `int i` —— 读者只知道"这是个整数"，不知道你有没有依赖它的宽度；
- `int32_t v` —— 读者知道"这个值必须是 32 位"，改平台时它会自动跟着类型定义走。

真正的收益出现在**换平台**和**跨界数据**（协议、寄存器、文件格式）的时候：

```c
uint32_t pkt_len;      /* 从协议里解出来的长度，位模式有外部含义 */
int      retry_count;  /* 纯内政，位模式没有外部含义 */
```

一眼就能分清"哪些数的宽度绝对不能变"。
裸机里前者的数量远多于后者，所以看起来就是"满屏 `uint32_t`"。

一句话：**定宽类型不是给编译器看的，是给下一个读代码的人（包括半年后的你）看的。**
</details>

<details>
<summary>Q2：为什么裸机代码里尽量用无符号（`uint32_t`）而不是 `int32_t`？</summary>

三个理由，按重要性排：

1. **溢出行为确定**。unsigned 溢出是**定义良好**的模 2^n 回绕，signed 溢出是 **UB**
   （实测见 [4.9](4.9-溢出.md)）。裸机上没有 sanitizer，UB 就是静默的错值。
2. **位操作语义干净**。`1u << 31` 是定义良好的 `0x80000000`；
   `1 << 31` 对 signed 是 UB。右移同理：unsigned 补 0，signed 补符号位
   （实测 `(unsigned)(-8) >> 1 = 0x7ffffffc`）。
3. **寄存器是硬件定义的位模式**。手册说 `CRL` 的 bit 23:20 是配置位，
   它没有"正负"的概念，用无符号承载最贴合。

所以裸机的默认选项是 **`uint32_t`**，有符号只用在"真的有负数"的地方
（温度差、增量、PID 误差）。这个默认建立起来之后，就不用每次都纠结。
</details>

<details>
<summary>Q3：`uint_fast8_t` 和 `uint8_t` 该选哪个？</summary>

看你要优化什么：

| 类型 | 含义 | 用在哪 |
|---|---|---|
| `uint8_t` | **正好** 8 位 | 跨界数据：UART 字节、协议字段、寄存器字节访问 |
| `uint_fast8_t` | **至少** 8 位，以"最快"为准 | 纯内部的循环变量、小计数器（Cortex-M 上就是 32 位） |
| `uint_least8_t` | **至少** 8 位，以"最小"为准 | 结构体里想省字节的字段 |

在 Cortex-M 上，`uint_fast8_t` 展开成 32 位——因为 32 位寄存器操作最快，
取一个 8 位反而可能要多一条零扩展指令。

裸机的实际选择：

- **跨界/硬件相关一律 `uint8_t` / `uint16_t` / `uint32_t`**（宽度必须精确）；
- **纯内部的循环变量用 `uint_fast8_t` 或者直接 `uint32_t`**（别用 `uint8_t`，
  它会在每次运算时被提升成 int 再截断，反而生成额外指令）。
</details>
