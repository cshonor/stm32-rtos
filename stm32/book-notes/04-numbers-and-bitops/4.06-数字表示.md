# 4.06 数字表示

> 书：第 4 章 数字和变量 · 4.06 数字表示（原书 p44–64 区间内）
> 上一篇：[4.05 整数的大小和表示](4.05-整数的大小和表示.md) ｜ 下一篇：[4.07 标准整数](4.07-标准整数.md)
> 对应实验：主机侧 clang 23.1.0 实测

## 书这一节讲什么

一句话：**同一个数可以用十进制、八进制、十六进制、二进制写，值都一样**，
计算机内部存的永远是二进制位模式。

书讲的是"怎么写"，本节补的是裸机上的另一半：**芯片手册是用十六进制 + 位号写的，
你的代码必须能用同一种语言跟手册对话**。这是裸机日常工具链的一部分。

## 一、四种写法，实测

```
$ clang -o lit lit.c && ./lit
064  = 52 (八进制陷阱)
0x64 = 100
64   = 64
```

| 写法 | 进制 | 裸机上的典型用途 |
|---|---|---|
| `64` | 十进制 | 数量（延时次数、数组长度） |
| `064` | **八进制** ⚠ | ⚠ 基本不用，且是坑（前导 0） |
| `0x64` | **十六进制** | **寄存器值、地址、掩码（主力）** |
| `0b1010` | 二进制（C23） | 配置位的可读写法（可选） |

八进制那条是纯粹的坑：**`064` = 52**。在写引脚号/位号时手滑多打个 0，
`1u << 064` 就把位移到 52（超出 32 位，UB），结果通常是 0——
"该开的时钟没开，代码看着完全正确"。

二进制字面量是 C23 才标准化的：

```
$ clang -std=c23 -o bin_c23 bin.c && ./bin_c23
0b1010 = 10
$ clang -std=c11 -pedantic -o bin_c11 bin.c
bin.c:2:41: warning: binary integer literals are a C23 extension [-Wc23-extensions]
```

## 二、为什么裸机非十六进制不可：手册是这么写的

打开 RM0008（STM32F1 参考手册）的 `GPIOA_CRL`：

> Bits 23:20 CNF5[1:0] + MODE5[1:0]

它给的是**位区间**，不是数值。于是两边要互相翻译：

| 手册说法 | 代码写法 | 值 |
|---|---|---|
| bit 5（ODR 的第 5 位） | `1u << 5` | `0x20` |
| bits 23:20（CRL 里 PA5 的 4 位） | `0xFu << 20` | `0x00F00000` |
| CNF5=00（推挽）+ MODE5=10（2MHz 输出） | `0x2u << 20` | `0x00200000` |

十进制在这里完全无法胜任：`1048576` 你能看出它是 bit 20 吗？
`0x00100000` 至少能数出第 20 位，`0x1u << 20` 则直接把位号写在代码里。

**经验规则：凡是手册用"位"描述的东西，代码里就用 `(1u << n)` 或十六进制，
绝不用十进制。**

## 三、"同一个位模式，两种读法"

这是本节和 [4.10 补码](4.10-有符号整数的补码表示.md) 的交叉点：

```
$ ./shift
signed   -8 >> 1            = -4
unsigned 0x80000000u >> 1   = 0x40000000
(unsigned)(-8) >> 1         = 0x7ffffffc  (先转无符号再移：补 0)
INT32_MIN = -2147483648 ; 位模式 0x80000000
```

位模式 `0x80000000` 只有一个，但：

- 读成 `int32_t` → `-2147483648`（最小负数）
- 读成 `uint32_t` → `2147483648`（最大的一半）
- 右移：`signed` 补符号位（算术右移），`unsigned` 补 0（逻辑右移）

裸机上这决定了一件事：**读回来的寄存器值，你要按手册定义的语义去解释**。
状态寄存器一般是"位标志集合"→ 用 `uint32_t`；
某些计数/差值寄存器可能是有符号的 → 用 `int32_t` 并注意符号扩展。

## 坑点（书 / 常识怎么说 / 实际是什么）

| 书 / 常识怎么说 | 实际是什么 |
|---|---|
| "四种写法都表示一个值" | 值一样，但**可读性**差一个数量级。手册是十六进制/位号写的，代码也该这么写 |
| "前导 0 无关紧要" | `064` = 52（实测）。位号写成 `064` 会移出界，静默变 0 |
| "十六进制要换算很麻烦" | 熟了之后 `0x` 每两位 = 一个字节，比十进制更容易对齐字节/位边界 |
| "`0b` 最直观，应该多用" | C23 才标准；`-std=c11 -pedantic` 下是扩展警告（实测）。团队工程要统一口径 |
| "右移就是除以 2" | 只对无符号成立。`-8 >> 1 = -4`（算术右移），`0x80000000u >> 1 = 0x40000000`（逻辑右移） |

## 代码自测

<details>
<summary>Q1：为什么芯片手册和裸机代码都痴迷十六进制？</summary>

因为**十六进制的一位正好是 4 个二进制位**，跟"字节/半字节/位域"天然对齐。

- 一个字节 = 两位十六进制：`0xFF` = `1111 1111`
- 一个 32 位寄存器 = 八位十六进制：`0x40010800`
- 手册里的 "bits 23:20" = 十六进制的第 6 位那一位：`0x00F00000`

十进制做不到这种对应：`16777216` 你得先转成二进制才知道它是 bit 24。

所以在裸机里，十六进制不是"习惯"，是**工作语言**：
手册给位区间 → 你算出掩码 → 写进代码 → 调试时从寄存器窗口读回一个 `0x...` → 跟手册对照。
整条链路都用同一种表示，中间不需要换算。
</details>

<details>
<summary>Q2：`0b1010` 和 `0x0A` 和 `(1u<<3)|(1u<<1)`，哪个该用在工程里？</summary>

按优先级排：

1. **`(1u << n)` 的组合** —— 位号直接出现，跟手册的 bit 号一一对应，
   与 C 标准版本无关，改一位只动一个数字。首选。
2. **`0x0A`** —— 适合"手册本身就是给一个整值"的场合
   （比如写 `CRL = 0x44444444` 这种整寄存器的初始化）。
3. **`0b1010`** —— 可读性最好，但要 `-std=c23`（或用 gnu 扩展模式）。
   实测 `-std=c11 -pedantic` 会报 `-Wc23-extensions`。

不推荐的是**裸十进制**：`reg = 10;` 你完全看不出它想设哪两位，
半年后回来改代码只能重新翻手册。
</details>

<details>
<summary>Q3：右移一位"等于除以二"这个说法，什么时候会坑我？</summary>

只在**无符号**或**非负有符号**时成立。

```
$ ./shift
signed   -8 >> 1            = -4        ← 算术右移，补符号位，等于 -8/2 = -4 ✓
unsigned 0x80000000u >> 1   = 0x40000000 ← 逻辑右移，补 0，等于 2147483648/2 ✓
(unsigned)(-8) >> 1         = 0x7ffffffc ← -8 变成 0xfffffff8 再逻辑右移，成了 2147483644 ✗
```

第三行就是坑：把负的 `signed` 转成 `unsigned` 再右移，
符号位不再被复制，出来的值完全不是"除以 2"。

裸机上的实际发作场景：**读一个 12 位 ADC 值做符号扩展**，
或者处理有符号的传感器差值（比如温度 -40.5℃）。
这类数据要先按手册确认是不是补码，再决定用 `int32_t` 还是 `uint32_t` 承接——
选错了，右移和比较的语义全变。见 [4.10](4.10-有符号整数的补码表示.md)。
</details>
