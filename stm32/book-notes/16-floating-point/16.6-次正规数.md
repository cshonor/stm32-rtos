# 16.6 次正规数

> 书：第 16 章 浮点数 · 16.6 次正规数（原书 p219+ 区间内）
> 上一篇：[16.5 不是数字(NaN)](16.5-不是数字NaN.md) ｜ 下一篇：[16.7 替代方案](16.7-替代方案.md)
> 对应实验：主机侧实测（clang 23.1.0 / macOS arm64）

## 书这一节讲什么

一句话：**比"最小正规数"还小的数要用"次正规"（denormal / subnormal）表示，
代价是精度骤降——而且很多 FPU 处理它极慢。**

这是浮点四组特殊值（0 / 次正规 / 正规 / inf·NaN）里最后一组，
也是嵌入式最该主动避开的一组。

## 一、⚠ 实测：正规数和次正规数的边界

```
$ ./fp
DBL_MIN      = 2.2250738585072014e-308   ← 最小【正规】数
DBL_TRUE_MIN = 4.940656458e-324          ← 最小【次正规】数
1e-320 = 9.999888672e-321   是次正规? 是
1e-320 位模式 = 0x00000000000007e8
```

`1e-320` 比 `DBL_MIN`（2.23e-308）**小 12 个数量级**，
它的位模式 `0x00000000000007e8` 里**指数段是 0**——
这就是次正规的标记：

| 指数字段 | 尾数字段 | 含义 |
|---|---|---|
| 全 0 | 全 0 | **±0** |
| **全 0** | **非 0** | **次正规数** |
| 1 ~ 0x7FE | 任意 | 正规数 |
| 全 1（0x7FF） | 全 0 | inf（[16.4](16.4-无穷大.md)） |
| 全 1 | 非 0 | NaN（[16.5](16.5-不是数字NaN.md)） |

## 二、⚠ 实测：精度是怎么"骤降"的

正规数有**隐含前导 1**（尾数是 `1.xxx`），
次正规数**没有**（尾数是 `0.xxx`）——可用的有效位直接变少。

`1e-320` 的位模式是 `0x7e8` = 二进制 `111 1110 1000`，
**只有 10 个有效位**（而 `double` 正常有 53 位）。

**越接近零，有效位越少**——实测把它推到极限：

```
$ ./fp
1.0 连续除 2 共 1074 次 = 4.940656458e-324   ← 最小次正规（只有 1 位有效位）
1.0 连续除 2 共 1075 次 = 0                  ← ⚠ 归零
DBL_TRUE_MIN / 2 = 0                          ← ⚠ 下溢到 0
```

**1074 次是 double 的极限**（52 位尾数 + 1074 = 2^−1074）。
第 1075 次直接变 **0**——**而且是静默的，没有任何提示**。

⚠ **"静默下溢成 0"是嵌入式里最阴的一种 bug**：
你的滤波器系数越来越小，某天突然变成 0，输出从此恒定。

## 三、⚠ 次正规数为什么慢（重要，但本机未实测）

⚠ **诚实标注**：这一段是**机制说明，本机未实测**（需要带 FPU 的板子）。

原因有三条：

1. **数据通路要特殊处理**：次正规少了隐含位，硬件要额外规格化；
2. **很多 FPU 直接走"微码陷阱"**（trap）：遇到次正规就**陷入软件模拟**，
   一次运算从几周期变成几百周期；
3. **Arm 的 `Flush-to-Zero`（FZ）模式**：很多 Cortex-M4F/M7 的 FPU
   可以配置成"次正规直接当 0"（`FPSCR.FZ` 位）——
   开启后**结果不同但速度稳定**。

⚠ **这意味着同一个算法在不同配置下会得到不同结果**——
如果你的算法依赖接近零的小数，必须明确 FZ 的开关状态。

## 四、⚠ 实测：怎么知道自己的数掉进了次正规区

```c
#include <math.h>
if (fpclassify(x) == FP_SUBNORMAL) { ... }   /* 标准做法 */
```

⚠ freestanding 下没有 `<math.h>`，自己判断：

```c
/* 比最小正规数小、又不是 0 → 次正规 */
static inline int is_subnormal_f(float x) {
    return x != 0.0f && (x < FLT_MIN && x > -FLT_MIN);
}
```

实测的 `float` 阈值（`FLT_MIN = 1.175494351e-38`，`FLT_TRUE_MIN = 1.401298464e-45`）：

| 区间 | 状态 |
|---|---|
| `|x| >= 1.175e-38` | ✅ 正规，满精度 |
| `1.40e-45 <= |x| < 1.175e-38` | ⚠ **次正规，精度骤降** |
| `|x| < 1.40e-45` | ⚠ 静默变 0 |

## 五、工程对策

| 对策 | 做法 | 适用 |
|---|---|---|
| **① 加偏置（bias）** | 让计算远离 0：`y = x + 1e-30` | 简单，但改变了结果 |
| **② 主动 flush** | 小于阈值的直接置 0 | ✅ 最常用，和硬件 FZ 一致 |
| **③ 缩放** | 把整个算法放大 2^k 倍 | ✅ 最干净，不改变相对关系 |
| **④ 用定点数** | [16.7](16.7-替代方案.md) | ✅ 彻底没有这个问题 |

⚠ **③ 是最值得学的**：浮点是"相对精度恒定"的，
所以**整体缩放不改变精度**——把 `[1e-40, 1e-38]` 放大成 `[1e-2, 1]`
就回到了正规区。这也是为什么数值算法都要做**归一化（scaling）**。

```c
/* 主动 flush：把次正规当 0（和硬件 FZ 模式行为一致，避免结果依赖配置） */
static inline float flush_denormal(float x) {
    return (x < FLT_MIN && x > -FLT_MIN) ? 0.0f : x;
}
```

## 六、裸机映射

| PC | 裸机 |
|---|---|
| `fpclassify()`（`<math.h>`） | 自己写：`x != 0 && |x| < FLT_MIN` |
| 次正规慢 | ⚠ M0/M3 上**整个浮点都慢**（软件模拟），次正规更是雪上加霜 |
| `FPSCR.FZ` 位 | M4F/M7 上可配，但**裸机启动代码要自己设** |
| —— | ✅ **用整数/定点就完全没有这个问题** |

## 坑点

| 坑 | 原书怎么说 | 实际是什么（实测） |
|---|---|---|
| "`FLT_MIN` 是最小的正数" | —— | ❌ 那是**最小正规数**；最小正数（`FLT_TRUE_MIN`）小 7 个数量级 |
| "次正规只是精度略差" | 提了精度下降 | ⚠ 实测 `1e-320` 只剩 **10 个有效位**（正常 53 位） |
| "下溢会报错" | —— | ❌ 实测 `DBL_TRUE_MIN/2 = 0`，**静默归零** |
| "1.0 除 2 永远除不完" | —— | ⚠ 实测 **1074 次**到最小次正规，**1075 次归零** |
| "次正规只是边缘情况" | —— | ⚠ 滤波器/衰减算法会**主动走进**这个区间 |
| "次正规在所有芯片上一样快" | —— | ⚠ 很多 FPU 走陷阱（**本机未实测**） |

## 代码自测

<details>
<summary>Q1：`FLT_MIN` 和 `FLT_TRUE_MIN` 差多少？为什么要有两个宏？</summary>

实测差 **7 个数量级**：

```
FLT_MIN      = 1.175494351e-38   ← 最小【正规】数（满精度）
FLT_TRUE_MIN = 1.401298464e-45   ← 最小【次正规】数（精度已崩）
DBL_MIN      = 2.2250738585072014e-308
DBL_TRUE_MIN = 4.940656458e-324
```

两个宏是因为**两个区间的行为完全不同**：

| 区间 | 精度 | 速度 |
|---|---|---|
| `[FLT_TRUE_MIN, FLT_MIN)` 次正规 | ⚠ 骤降（无隐含位） | ⚠ 很多 FPU 走陷阱 |
| `[FLT_MIN, FLT_MAX]` 正规 | ✅ 满精度 | ✅ 正常 |

**判断"这个数还算数吗"应该用 `FLT_MIN`（正规数下界），
不是 `FLT_TRUE_MIN`。** 低于 `FLT_MIN` 就该主动 flush 掉。
</details>

<details>
<summary>Q2：我的 IIR 滤波器输出越来越小，最后变成恒定的 0，为什么？</summary>

最可能是**静默下溢**。实测：

```
1.0 连续除 2 共 1074 次 = 4.940656458e-324   ← 最小次正规
1.0 连续除 2 共 1075 次 = 0                  ← ⚠ 静默归零
DBL_TRUE_MIN / 2 = 0
```

IIR 的系数衰减会让状态量指数级趋零，
走到次正规区后**有效位从 53 位掉到只剩几位**，
再往下就直接变 0，**没有任何提示**。

✅ 三种修法：

1. **主动 flush**：小于 `FLT_MIN` 就置 0（行为明确，且和硬件 FZ 一致）；
2. **缩放**：把状态量整体乘 2^k 拉回正规区（浮点相对精度恒定，缩放不损失精度）；
3. **换定点**：[16.7](16.7-替代方案.md)——定点是**绝对精度恒定**，
   衰减到 0 是设计使然而不是意外。
</details>

<details>
<summary>Q3：为什么"整体缩放"能救次正规，而不改变精度？</summary>

因为浮点是**相对精度恒定**的：尾数位数固定，指数随便挪。

把 `[1e-40, 1e-38]` 整体乘 `1e38`，得到 `[1e-2, 1]`：

- 相对误差（`|Δ|/|x|`）**完全不变**；
- 但数值从次正规区（`FLT_MIN=1.18e-38` 以下）回到了正规区；
- 有效位从"个位数"回到 24 位（float）。

⚠ **定点数做不到这一点**——定点是**绝对精度恒定**，
缩放会改变精度。这正是两种表示法的根本区别，也是选型的依据：

| | 浮点 | 定点 |
|---|---|---|
| 精度类型 | **相对**恒定 | **绝对**恒定 |
| 大动态范围 | ✅ 擅长 | ❌ 不擅长 |
| 缩放 | ✅ 不改变精度 | ⚠ 改变精度 |
</details>

<details>
<summary>Q4：裸机上怎么避开次正规数？</summary>

最彻底的办法是**不用浮点**（[16.7](16.7-替代方案.md)）。
必须用时，三步：

1. **判断**（freestanding 下自己写）：

```c
static inline int is_subnormal_f(float x) {
    return x != 0.0f && (x < FLT_MIN && x > -FLT_MIN);
}
```

2. **主动 flush**：

```c
static inline float flush_denormal(float x) {
    return (x < FLT_MIN && x > -FLT_MIN) ? 0.0f : x;
}
```

3. **算法层面缩放**：让所有量远离 0（最根本）。

⚠ 另外，如果你用的是 **M4F/M7**，可以设 `FPSCR.FZ = 1`
让硬件自动把次正规当 0——**但裸机启动代码里没人替你设**，
而且要意识到**这改变计算结果**（开与不开，同一个算法结果不同）。
**明确写出来，别让它依赖默认配置。**
</details>
