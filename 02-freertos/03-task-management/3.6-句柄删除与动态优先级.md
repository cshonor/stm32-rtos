## 这一篇讲什么

`xTaskCreate` 最后一个参数吐出的**任务句柄**（TaskHandle_t）
是之后管理这个任务的全部钥匙：删它、挂它、改它优先级都靠句柄。
这一篇把三件套讲完，顺手解决"删自己"和"删别人"的路径差异。

## 先用人话说一遍（新手铺垫）

句柄就是任务的**工牌**：创建时公司（内核）发给你，之后想替这个
员工办离职（Delete）、停职（Suspend）、调岗级（PrioritySet），
都得出示工牌。不需要管他，建任务时工牌那栏填 NULL 就行。

**删任务像办离职**：工位（TCB（任务控制块：内核给任务建的"档案卡"，见 2.1） + 栈）不是当场清的，是登记到
"待清理名单"上，等夜班保洁（空闲任务，见 3.5）统一收拾——
因为"删自己"的员工此刻还站在自己工位上，总不能当场抽掉地板。
要特别注意：**员工自己领走的办公用品公司不管**——任务运行中
自己申请的内存、拿到的锁，离职前不还清，就永远流失了。

**动态改优先级像临时调岗**：合法场景是"校准期间临时提级"这种；
把它当日常调度手段用，等于岗级天天变，排班表（时序分析）直接作废。

| 术语 | 一句话解释 |
|---|---|
| 悬垂指针 | 指向的内存已被释放还在用的指针；任务删了之后旧句柄就是它，必须清 NULL |
| 不透明类型 | 只给你句柄、不让你看内部结构的设计；TaskHandle_t 内部是 TCB 指针但不该解引用 |
| 优先级继承 | 互斥量的防反转机制（ch07）：持锁的低优先级任务被临时抬到等待者的级别 |

## 句柄是什么

```c
TaskHandle_t xLedTaskHandle = NULL;
xTaskCreate( vLedTask, "LED", 128, NULL, 2, &xLedTaskHandle );
```

句柄本质是指向 TCB 的指针（不透明类型）。
**想要以后管它就存下来，不想管就传 NULL**——
01-hello-task 里两个 LED 任务建完就各跑各的，传 NULL 即可。

## 三件套 API

| API | 干什么 | 传 NULL 的含义 |
|---|---|---|
| `vTaskDelete(h)` | 删除任务（TCB+栈由空闲任务回收，见 [3.5](3.5-空闲任务与钩子.md)） | **删自己** |
| `vTaskSuspend(h)` / `vTaskResume(h)` | 挂起 / 恢复（进/出 Suspended 态） | 挂自己（恢复自己没意义——挂着的任务跑不到这行） |
| `uxTaskPriorityGet(h)` / `vTaskPrioritySet(h, n)` | 读 / 改优先级 | 读/改自己 |

## 删自己 vs 删别人：路径差异

```
删别人：vTaskDelete(h)
   → h 立刻从 Ready/Blocked 名单摘除，挂入"待删除名单"
   → 内存释放：等空闲任务收尸（heap 有空窗期）

删自己：vTaskDelete(NULL)
   → 同上摘除+挂名单
   → 本行返回后立刻触发一次调度（本任务再也不会被选中）
   → 内存释放：同样等空闲任务收尸
```

两种删法的**内存释放都依赖空闲任务**（[3.5](3.5-空闲任务与钩子.md) 的收尸机制）。
差异只在语义：删别人可以在任意时机调；删自己必须保证
"这行之后本任务不再碰任何已属于它的资源"（尤其是它马上要还的栈）。

## 动态优先级：有用，但请克制

`vTaskPrioritySet(h, 3)` 立即生效：如果被调高的任务比当前任务优先级高，
**立刻抢占**（函数返回前世界就变了）。

合法用途：

- **优先级继承的内部实现**（ch07 互斥量（保护共享资源的锁，ch07 细讲）就靠它临时抬优先级）；
- 运行阶段切换模式（如"校准模式"任务在校准期临时提升）。

不合法的用法：把动态优先级当"调度策略"用——
优先级满天飞 = 时序分析做不下去 = 实时性无从谈起。
**静态优先级能表达的设计，不要用动态调整。**

## 一个容易漏的细节：删除不回收"任务自己申请的东西"

`vTaskDelete` 只回收内核给的（TCB + 创建时切的栈）。
任务运行中自己 `pvPortMalloc` 的内存、打开的队列/信号量、
拿到的互斥量——**内核一概不管**。任务自杀前必须自己清理干净，
否则就是教科书级泄漏（外加互斥量永远无人释放的次生灾害）。

## 与 LDD- 侧对照

| | Linux | FreeRTOS |
|---|---|---|
| 句柄 | pthread_t | TaskHandle_t（传 NULL = 自己，类似 pthread_self 语境） |
| 杀线程 | pthread_cancel（危险，同样不回收资源） | vTaskDelete（同样危险，同样不回收资源） |
| 改优先级 | pthread_setschedparam | vTaskPrioritySet |

## 要点回顾

1. 句柄是管理任务的钥匙；不需要管理就传 NULL。
2. 三件套：Delete / Suspend+Resume / PriorityGet+Set；NULL = 自己。
3. 删除只还内核给的（TCB+栈），任务自己拿的资源自己还——且都等空闲任务收尸。

<details>
<summary>Q1：句柄存下来后，任务已经被删了，句柄还能用吗？</summary>

不能——句柄指向的 TCB 已被空闲任务 vPortFree 掉，
再用就是悬垂指针，行为未定义。**规矩：删任务的同时把存句柄的变量清 NULL，
或用事件/通知让"持有方"知道任务已死。**

</details>

<details>
<summary>Q2：vTaskSuspend 正在 Blocked 的任务会怎样？</summary>

叠加态：它既在等事件（Blocked 的账本还在）又被按住。
事件到了它**不会**变 Ready——要先被 Resume 回到 Blocked，再等事件。
所以"挂起一个等队列的任务"不会丢队列数据，但也不会因数据到达而醒。

</details>

## 坑点速查

| 坑点 | 书 / 常识怎么说 | 实际是什么 |
|---|---|---|
| 任务删了，存的句柄接着用 | 句柄只是个 ID 而已 | 句柄指向的 TCB 已被空闲任务 `vPortFree` 掉，再用就是悬垂指针；规矩：删任务同时把句柄变量清 NULL |
| `vTaskDelete` 会把任务的资源都收了 | 删除 = 全回收 | 只回收内核给的 TCB+栈；任务自己 `pvPortMalloc` 的内存、拿到的互斥量一概不管，自杀前必须自己还清 |
| 动态改优先级是个调度手段 | 随时调，灵活 | 合法场景只有"校准期临时提级"这类；优先级满天飞 = 时序分析作废，静态能表达的别用动态 |
| 挂起一个等队列的任务，数据来了它会醒 | Blocked 的账本还在 | 叠加态：事件到了也**不会**变 Ready，得先 Resume 回 Blocked 再等事件；数据不丢，但它不醒 |

## 代码自测

_注：本节代码按 FreeRTOS API 语义编写，未在本仓库环境实跑，上板验证见「验证路径」。_

```c
/* 演示句柄三件套：改优先级 → 挂起 → 恢复 → 删除，句柄清 NULL */
extern void uart_puts( const char * );

static TaskHandle_t xTargetHandle = NULL;

static void vTargetTask( void *pv )
{
    for ( ;; )
    {
        uart_puts( "T\r\n" );
        vTaskDelay( 500 );
    }
}

static void vManagerTask( void *pv )
{
    vTaskDelay( 2000 );
    vTaskPrioritySet( xTargetHandle, 3 );   /* 调到比自己高 → 函数返回前就被抢占 */
    vTaskDelay( 2000 );
    vTaskSuspend( xTargetHandle );          /* 打印停 */
    vTaskDelay( 2000 );
    vTaskResume( xTargetHandle );           /* 打印恢复 */
    vTaskDelay( 2000 );
    vTaskDelete( xTargetHandle );           /* 删除，内存等空闲任务收尸 */
    xTargetHandle = NULL;                   /* 防悬垂指针 */
    vTaskDelete( NULL );                    /* 管理者自己也退场 */
}

int main( void )
{
    xTaskCreate( vTargetTask, "target", 128, NULL, 1, &xTargetHandle );
    xTaskCreate( vManagerTask, "manager", 128, NULL, 2, NULL );
    vTaskStartScheduler();
    for ( ;; );
}
```

**预期现象**：
- 0~2s：每 500ms 一行 `T`。
- 2s：`vTaskPrioritySet` 后 target 变 3 级，行为不变但抢占权限变了。
- 4~6s：挂起，`T` 停止；6s 后恢复。
- 8s：删除，`T` 永久停止；句柄已清 NULL，此后再碰它就是悬垂指针。

**验证路径**：F103 实机 + USART printf，对秒表看五个阶段。

**常见翻车点**：
- 删除后忘了 `xTargetHandle = NULL` → 后续误用悬垂句柄，行为未定义。
- target 任务若自己申请过内存，删除前没释放 → 教科书级泄漏（本例没申请，故安全）。
