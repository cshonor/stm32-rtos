# ch07 · 资源管理 —— 章节导航

> 书第 7 章 · 对应实验：[`02-freertos/04-mutex-priority`](../../04-mutex-priority/README.md)（⬜ 未做）
> 章导航：本篇

## 本章讲什么

**多任务共享资源（外设、全局变量、printf）时的保护手段全家桶：
临界区、挂起调度器、互斥量、守门人任务——以及 RTOS 教科书的头号反派：
优先级反转，和它的解药优先级继承。**

互斥量（mutex）和二值信号量长得像，但 mutex 多带了两样东西：
**所有权**（谁拿谁还）和**优先级继承**（防反转）。用信号量保护共享资源
是新手第一个结构性错误。

## 只看这一页（速览）

**主线一句话**：共享资源怎么护？7.1 把四种保护手段排成光谱，其中最强也最危险的是互斥量——它引出 7.2 的优先级反转事故，7.3 给出解药优先级继承（并讲清它治不了什么），7.4 收互斥量的两个边角规则。

| 小节 | 一句话结论 |
|---|---|
| 7.1 保护手段光谱 | 临界区关中断必须极短、调度器锁只停任务切换、互斥量管任意长占用、守门人把资源私有化——按"管得多宽"选。 |
| 7.2 优先级反转三任务剧本 | H 等 L 的锁，却被不碰锁的 M 无限拖延；拿二值信号量当锁用，反转照发生且没有任何内置解药。 |
| 7.3 优先级继承 | 持锁的 L 临时借到 H 的优先级，把无界等待变有界；但治不了死锁、救不了长持锁，还误伤中间优先级任务。 |
| 7.4 递归互斥与 ISR 禁令 | 普通 mutex 重入即死锁，递归 mutex 计数放行但要"拿几次还几次"；互斥量没有 FromISR，因为所有权和继承都要任务身份。 |

**本章最容易踩的坑**：

- 用二值信号量当互斥锁保护共享资源，等于自动放弃继承机制（7.2）。
- 在临界区里干毫秒级的耗时活（如等 UART 发完整帧），SysTick 停摆毁掉系统心跳（7.1）。
- 调度器锁（vTaskSuspendAll）期间调用任何可能阻塞的 API——调度器停了没人唤醒你（7.1）。
- 临界区/调度器锁忘了配对释放，系统假死（7.1）。
- 想在 ISR 里用互斥量——它是全家族唯一没有 FromISR 版本的对象（7.4）。

## API 速查卡

| API / 命令 | 一句话作用 | 易错点 |
|---|---|---|
| `taskENTER_CRITICAL` / `taskEXIT_CRITICAL` | 关中断进出临界区，保护极短代码段 | 必须配对，忘 EXIT 系统假死；只关到 configMAX_SYSCALL 以下 |
| `taskENTER_CRITICAL_FROM_ISR` / `EXIT_FROM_ISR` | ISR 版临界区 | 参数带中断状态保存/恢复，和任务版别混用 |
| `vTaskSuspendAll` / `xTaskResumeAll` | 只停任务切换，中断照常 | 期间禁止任何可能阻塞的 API |
| `xSemaphoreCreateMutex` | 创建互斥量，自带所有权 + 优先级继承 | 创建即"可用"（不像二值信号量创建为空） |
| `xSemaphoreTake` / `xSemaphoreGive` | 拿锁 / 还锁 | 谁拿谁还，跨任务 Give 是语义级 bug |
| `xSemaphoreCreateRecursiveMutex` | 创建递归互斥量 | 需 `configUSE_RECURSIVE_MUTEXES` 置 1 |
| `xSemaphoreTakeRecursive` / `GiveRecursive` | 递归拿/还，内部计数 | 拿几次还几次，配不上对极难排查 |
| `xQueueSend` + 守门人任务 | 资源私有化，队列串行化 | 操作变异步：发消息 ≠ 已执行 |
