## 这一篇讲什么

多任务 + ISR 都能摸同一块数据（全局变量、外设寄存器、printf 的 UART），
不保护就是数据竞争。FreeRTOS 给了四种保护手段，代价和能力各不同，
本篇把它们排成一条**光谱**，讲清"什么时候用哪个"。

## 竞争从哪来

共享数据被两个以上执行体读写，且至少一方在写：

```
任务A 读 g_count        ISR 也写 g_count      → 任务读到撕裂值
任务A printf 到一半     任务B 抢过去 printf   → 两行日志粘连
任务A 写 SPI 寄存器     任务B 抢占换设备片选   → 数据发到错的设备
```

裸机篇 [ch10 中断](../../../01-stm32/book-notes/10-interrupts/README.md)
的"主循环 vs ISR 共享标志位"就是最小规模竞争——RTOS 只是把竞争方
从 2 个变成 N 个。

## 四种手段一张表

| 手段 | API | 保护范围 | 期间中断 | 期间任务切换 | 典型用途 |
|---|---|---|---|---|---|
| 临界区 | `taskENTER_CRITICAL` / `EXIT` | 极短的几行代码 | **关**（到 configMAX_SYSCALL 以下全关） | 不发生 | 改几个寄存器、更新一个结构体 |
| 调度器锁 | `vTaskSuspendAll` / `xTaskResumeAll` | 较长的一段逻辑 | **照常响应** | 不发生 | 一口气操作多个对象，但不想牺牲中断延迟 |
| 互斥量 | `xSemaphoreCreateMutex` + Take/Give | 任意长的资源占用 | 照常 | **照常**（别人等着） | 独占外设、UART、大缓冲 |
| 守门人 | 守护任务 + 队列 | 整个资源的生命周期 | 照常 | 照常 | printf 串行化、慢外设统一管理 |

**选择逻辑一句话**：能短则临界区；要长且只防任务不防中断就调度器锁；
要长且可阻塞就互斥量；资源操作本身很慢/很复杂就交给守门人串行化。

## 临界区：关中断换来的绝对安静

```c
taskENTER_CRITICAL();
g_tick_shadow = g_tick;   /* 只有几行，纳秒~微秒级 */
g_flag |= FLAG_X;
taskEXIT_CRITICAL();
```

- 关的是**优先级不高于 `configMAX_SYSCALL_INTERRUPT_PRIORITY` 的中断**——
  更紧急的中断照样打断，这就是"可屏蔽范围"的含义。
- 期间没有 SysTick，没有 PendSV，**世界为你暂停**——所以必须短；
  临界区里做耗时的活，等于拿系统实时性祭旗。
- 可嵌套（进出配对计数），**忘了 EXIT 就是系统假死**。
- ISR 侧有 `taskENTER_CRITICAL_FROM_ISR` 版本（多带保存/恢复中断状态的
  参数，用法不同，别混用）。

## 调度器锁：只冻结任务，不碰中断

```c
vTaskSuspendAll();
/* 干一长串活：中断照进，但没有任务能抢占我 */
xTaskResumeAll();   /* 有更高优先级任务就绪？返回值告诉你 */
```

- 和临界区的本质区别：**中断延迟不受影响**，只牺牲任务级响应。
- 期间**禁止调用任何可能阻塞的 API**（Take/Send/Receive 带超时全不行）——
  调度器都停了，阻塞谁去唤醒你？
- 同样可嵌套，配对释放。

## 守门人（gatekeeper）：把资源变成一个任务

```c
/* 打印守门人：全系统唯一摸 UART 的任务 */
void vPrintGatekeeper( void *pv )
{
    char msg[64];
    for( ;; )
    {
        xQueueReceive( xPrintQueue, msg, portMAX_DELAY );
        uart_puts( msg );          /* 只有我在这里 printf */
    }
}
/* 其他任务想打印：xQueueSend( xPrintQueue, line, 0 )，发完就走 */
```

思路来自 [ch04 队列](../04-queue-management/4.1-队列是什么.md)：
**不共享资源，只共享队列**。资源只有一个主人，天然无竞争。
代价：操作变成异步（发消息≠已执行），慢资源会积压。

## 要点回顾

1. 竞争来源：多任务 + ISR 共享可写数据，至少一方在写。
2. 临界区关中断（到 configMAX_SYSCALL），必须极短；调度器锁只停任务切换，中断照常。
3. 互斥量适合"任意长、可阻塞"的独占（详见 7.2/7.3）。
4. 守门人 = 资源私有化 + 队列串行化，消灭共享本身。

<details>
<summary>Q1：调度器锁期间 ISR 里给队列发数据会怎样？</summary>

`xQueueSendFromISR` 本身能跑（中断没被关），等待名单上的任务也会被
标记为就绪——但**不能真的切换过去**，因为调度器锁着。内核把这次
"该做没做的切换"记下来，`xTaskResumeAll` 时补一次 PendSV 统一切换。
所以 ISR 数据不丢，只是接收任务晚点跑。待实验验证补日志证据。

</details>

<details>
<summary>Q2：为什么临界区不能用来保护"等 UART 发完一整帧"？</summary>

发一整帧是毫秒级，临界区期间 SysTick 停摆、可屏蔽中断全哑——
系统心跳都丢了。临界区的设计前提就是"几行代码快进快出"，
长占用请走互斥量（7.2 起）或守门人。

</details>
