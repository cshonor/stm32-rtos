## 这一篇讲什么

多任务 + ISR 都能摸同一块数据（全局变量、外设寄存器、printf 的 UART），
不保护就是数据竞争。FreeRTOS 给了四种保护手段，代价和能力各不同，
本篇把它们排成一条**光谱**，讲清"什么时候用哪个"。

## 先用人话说一遍（新手铺垫）

这一节解决的问题很朴素：两个任务（或任务和中断）同时摸同一份
数据，就会把数据摸坏。画面感一点：几个人共用一个厨房，灶台只有
一口——不立规矩，菜必糊。

FreeRTOS 的四种保护手段，对应厨房里的四种规矩，按"管得有多宽"
排成光谱：

- **临界区** = 用灶台的瞬间把厨房门锁死：谁都进不来，连送外卖的
  都不行。所以你必须快进快出，几秒钟的事；
- **调度器锁** = 挂个"包场"牌子：其他厨师不许进，但外卖照收。
  包场时间可以长一点，代价是不耽误急事；
- **互斥量** = 谁用灶台谁拿钥匙，拿不到的排队等，等的时候不占着
  厨房门口（阻塞会让出 CPU，别人照常干活）；
- **守门人** = 雇一个专属厨师，所有人只递菜单。灶台从此只有一个
  主人，竞争从根上消失。

映射关系：厨师 = 任务，外卖员 = 中断，灶台 = 共享资源（全局变量、
UART、SPI 外设）。正文那张表就是把这四种规矩的"代价"和"能力"
逐列摆开。

| 术语 | 一句话解释 |
|---|---|
| 数据竞争 | 多个执行体读写同一份数据且至少一方在写，结果取决于谁先谁后，不可预期 |
| 临界区 | 一段"关中断快进快出"的代码：进去关中断，出来恢复，期间无人能打断 |
| 调度器锁 | 只暂停任务切换、不关中断的保护手段，适合较长但不需要阻塞的操作 |
| 互斥量（mutex） | 带"所有权"的锁：谁拿到谁才有资格还，用于任意时长的资源独占 |
| 守门人（gatekeeper） | 独占某资源的专用任务，别人经队列把活儿递给它，串行执行 |
| `configMAX_SYSCALL_INTERRUPT_PRIORITY` | 一个优先级门槛：临界区只关优先级不高于它的中断，更急的中断照常 |

## 竞争从哪来

共享数据被两个以上执行体读写，且至少一方在写：

```
任务A 读 g_count        ISR 也写 g_count      → 任务读到撕裂值
任务A printf 到一半     任务B 抢过去 printf   → 两行日志粘连
任务A 写 SPI 寄存器     任务B 抢占换设备片选   → 数据发到错的设备
```

裸机篇 [ch10 中断](../../../01-stm32/book-notes/10-interrupts/README.md)
的"主循环 vs ISR 共享标志位"就是最小规模竞争——RTOS 只是把竞争方
从 2 个变成 N 个。

## 四种手段一张表

| 手段 | API | 保护范围 | 期间中断 | 期间任务切换 | 典型用途 |
|---|---|---|---|---|---|
| 临界区 | `taskENTER_CRITICAL` / `EXIT` | 极短的几行代码 | **关**（到 configMAX_SYSCALL 以下全关） | 不发生 | 改几个寄存器、更新一个结构体 |
| 调度器锁 | `vTaskSuspendAll` / `xTaskResumeAll` | 较长的一段逻辑 | **照常响应** | 不发生 | 一口气操作多个对象，但不想牺牲中断延迟 |
| 互斥量 | `xSemaphoreCreateMutex` + Take/Give | 任意长的资源占用 | 照常 | **照常**（别人等着） | 独占外设、UART、大缓冲 |
| 守门人 | 守护任务 + 队列 | 整个资源的生命周期 | 照常 | 照常 | printf 串行化、慢外设统一管理 |

**选择逻辑一句话**：能短则临界区；要长且只防任务不防中断就调度器锁；
要长且可阻塞就互斥量；资源操作本身很慢/很复杂就交给守门人串行化。

## 临界区：关中断换来的绝对安静

```c
taskENTER_CRITICAL();
g_tick_shadow = g_tick;   /* 只有几行，纳秒~微秒级 */
g_flag |= FLAG_X;
taskEXIT_CRITICAL();
```

- 关的是**优先级不高于 `configMAX_SYSCALL_INTERRUPT_PRIORITY` 的中断**——
  更紧急的中断照样打断，这就是"可屏蔽范围"的含义。
- 期间没有 SysTick（Cortex-M 内置的倒计时定时器，FreeRTOS 拿它当系统心跳，周期性产生 tick 中断），没有 PendSV（Cortex-M 的一种异常，FreeRTOS 的任务切换在它里面执行），**世界为你暂停**——所以必须短；
  临界区里做耗时的活，等于拿系统实时性祭旗。
- 可嵌套（进出配对计数），**忘了 EXIT 就是系统假死**。
- ISR 侧有 `taskENTER_CRITICAL_FROM_ISR` 版本（多带保存/恢复中断状态的
  参数，用法不同，别混用）。

## 调度器锁：只冻结任务，不碰中断

```c
vTaskSuspendAll();
/* 干一长串活：中断照进，但没有任务能抢占我 */
xTaskResumeAll();   /* 有更高优先级任务就绪？返回值告诉你 */
```

- 和临界区的本质区别：**中断延迟不受影响**，只牺牲任务级响应。
- 期间**禁止调用任何可能阻塞的 API**（Take/Send/Receive 带超时全不行）——
  调度器都停了，阻塞谁去唤醒你？
- 同样可嵌套，配对释放。

## 守门人（gatekeeper）：把资源变成一个任务

```c
/* 打印守门人：全系统唯一摸 UART 的任务 */
void vPrintGatekeeper( void *pv )
{
    char msg[64];
    for( ;; )
    {
        xQueueReceive( xPrintQueue, msg, portMAX_DELAY );
        uart_puts( msg );          /* 只有我在这里 printf */
    }
}
/* 其他任务想打印：xQueueSend( xPrintQueue, line, 0 )，发完就走 */
```

思路来自 [ch04 队列](../04-queue-management/4.1-队列是什么.md)：
**不共享资源，只共享队列**。资源只有一个主人，天然无竞争。
代价：操作变成异步（发消息≠已执行），慢资源会积压。

## 要点回顾

1. 竞争来源：多任务 + ISR 共享可写数据，至少一方在写。
2. 临界区关中断（到 configMAX_SYSCALL），必须极短；调度器锁只停任务切换，中断照常。
3. 互斥量适合"任意长、可阻塞"的独占（详见 7.2/7.3）。
4. 守门人 = 资源私有化 + 队列串行化，消灭共享本身。

<details>
<summary>Q1：调度器锁期间 ISR 里给队列发数据会怎样？</summary>

`xQueueSendFromISR` 本身能跑（中断没被关），等待名单上的任务也会被
标记为就绪——但**不能真的切换过去**，因为调度器锁着。内核把这次
"该做没做的切换"记下来，`xTaskResumeAll` 时补一次 PendSV 统一切换。
所以 ISR 数据不丢，只是接收任务晚点跑。待实验验证补日志证据。

</details>

<details>
<summary>Q2：为什么临界区不能用来保护"等 UART 发完一整帧"？</summary>

发一整帧是毫秒级，临界区期间 SysTick 停摆、可屏蔽中断全哑——
系统心跳都丢了。临界区的设计前提就是"几行代码快进快出"，
长占用请走互斥量（7.2 起）或守门人。

</details>

## 坑点速查

| 坑点 | 书 / 常识怎么说 | 实际是什么 |
|---|---|---|
| 临界区"关掉所有中断" | 进了临界区世界完全暂停 | 只关优先级不高于 `configMAX_SYSCALL_INTERRUPT_PRIORITY` 的中断，更急的照样打断 |
| 临界区里可以慢慢干活 | 反正没人能打断我 | SysTick 停摆、系统心跳丢失；毫秒级操作（如等 UART 发完一帧）直接毁掉实时性 |
| 调度器锁期间可以 Take/Send 带超时 | 只是暂停切换，阻塞一下无妨 | 调度器停了没人唤醒你，任何可能阻塞的 API 全禁 |
| 临界区忘了 EXIT 只是小疏漏 | 少写一句应该没事 | 配对计数不归零，中断再不恢复，系统假死 |
| ISR 里也用 `taskENTER_CRITICAL` | 名字差不多应该通用 | ISR 必须用 `taskENTER_CRITICAL_FROM_ISR`，参数带保存/恢复中断状态，混用出错 |

## 代码自测

_注：本节代码按 FreeRTOS API 语义编写，未在本仓库环境实跑，上板验证见「验证路径」。_

```c
/* 互斥量保护 printf：两个任务抢着打印，看日志是否粘连 */
static SemaphoreHandle_t xUartMutex;

static void vPrintTask( void *pv )
{
    const char *pcName = ( const char * ) pv;
    for( ;; )
    {
        xSemaphoreTake( xUartMutex, portMAX_DELAY );
        printf( "[%s] line-1 start\r\n", pcName );   /* 打印分两句， */
        printf( "[%s] line-2 end\r\n",   pcName );   /* 无锁必粘连   */
        xSemaphoreGive( xUartMutex );
        vTaskDelay( pdMS_TO_TICKS( 10 ) );
    }
}

void app_init( void )
{
    xUartMutex = xSemaphoreCreateMutex();            /* 创建即可用 */
    xTaskCreate( vPrintTask, "A", 256, "TaskA", 2, NULL );
    xTaskCreate( vPrintTask, "B", 256, "TaskB", 2, NULL );
}
```

**预期现象**：
- 每个任务的两行日志总是成对出现，TaskA 的 line-1 后面紧跟自己的 line-2。
- 把 Take/Give 注释掉重跑，几秒内就能看到 A 的 line-1 后面插进 B 的 line-1，两行粘连。
- 两任务同优先级，时间片轮转，A/B 出现顺序无固定规律。

**验证路径**：F103 实机，USART1 重定向 printf，串口助手 115200 观察两行是否粘连。

**常见翻车点**：
- 忘了 `xSemaphoreGive`，第二次 Take 起全系统打印停摆。
- printf 本身不可重入又加了浮点格式化，栈 256 字不够溢出，表现为 HardFault。
- 把互斥量换成二值信号量重跑，功能看似一样，但丢掉优先级继承（见 7.2）。
