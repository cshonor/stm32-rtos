## 这一篇讲什么

FreeRTOS 把 Cortex-M 的中断优先级切成两段：**红线之上裸奔、
红线之下受内核管理**。本篇讲清红线的逻辑、临界区的硬件实现
（BASEPRI vs PRIMASK）、以及那个老坑——数字越小优先级越高。

## 老坑复习：方向与任务优先级相反

| 体系 | 数字大 | 数字小 |
|---|---|---|
| FreeRTOS 任务优先级 | 高 | 低（0 最低） |
| Cortex-M 中断优先级 | **低** | **高（0 最高）** |

两套体系共存于一块芯片，[3.1](../03-task-management/3.1-任务函数与创建.md)
已经踩过一次；在中断侧它更阴险——下面所有"高于/低于"都要
在脑里先换算成数字。

## 红线的定义

```
中断优先级数值   0  1  2  3  4 │ 5  6  7 ... 15
                              │↑
硬件紧急度       ← 更高       │       更低 →
                              │ configMAX_SYSCALL_INTERRUPT_PRIORITY = 5
能否调 FromISR API？  ❌ 绝对不能 │ ✅ 可以（受内核管理）
                              │
内核临界区屏蔽范围     不屏蔽（裸奔）  │ 进临界区时被 BASEPRI 屏蔽
```

- **红线之上（数值 < 5）**：内核完全不认识这些中断。它们可以打断
  任何临界区，因此**禁止调任何 RTOS API**——哪怕 FromISR 版
- **红线之下（数值 ≥ 5）**：进内核临界区时被临时屏蔽，
  从 ISR 里调 FromISR API 是安全的
- 本仓 F103 配置：`configMAX_SYSCALL_INTERRUPT_PRIORITY = 5`
  （4 位优先级，0~15），即 0~4 裸奔、5~15 受管

为什么需要红线之上的"裸奔段"？给**硬实时**中断留的逃生通道：
电机换相、过流保护这类微秒级响应，不能被内核临界区拖延。
代价就是它们碰不得任何内核对象。

## 临界区的硬件实现：BASEPRI 而不是 PRIMASK

Cortex-M 有两个屏蔽寄存器：

| 寄存器 | 屏蔽范围 | FreeRTOS 谁在用 |
|---|---|---|
| PRIMASK | 全屏蔽（除 NMI/HardFault） | **不用**——太粗暴 |
| BASEPRI | 只屏蔽"数值 ≥ 某阈值"的中断 | 内核临界区靠它 |

`taskENTER_CRITICAL()` = 写 BASEPRI = 5 对应的硬件编码：
红线下方的中断（含 SysTick、PendSV）被压住，**红线上方的 ISR
照常运行**——这就是"裸奔段不被内核拖延"的机制保证。
退出临界区 BASEPRI 清 0，一切恢复。

裸机篇 [ch10](../../../01-stm32/book-notes/10-interrupts/README.md) 讲 NVIC 时
只用了 PRIMASK（关全局中断）；RTOS 用 BASEPRI 做到了
"只关我管得着的那部分"。

## 越线的后果：为什么是"偶发跑飞"

红线上方的 ISR 若偷调 API（哪怕 FromISR 版）：它可能在内核
**正在改就绪名单/队列内部指针的临界区中间**插进来，
再进同一个数据结构——两个执行流并发改同一份名单，
TCB 指针写花。**不立刻死，攒到某次调度才崩**，现场和肇事中断
毫无时间关联——这是 [1.3](../01-distribution/1.3-FreeRTOSConfig逐项过一遍.md)
说的"三颗雷"里最难查的那颗。

新版内核提供 `configASSERT` 检查：ISR 优先级配错时当场断言停车
（建议开发期必开，发布期再权衡）。

## 中断嵌套与红线

Cortex-M 的抢占规则不变：数值小的能嵌套数值大的。
叠加红线后的完整图景：

- 裸奔 ISR（0~4）：可嵌套一切，包括受管 ISR 和内核临界区
- 受管 ISR（5~15）：可嵌套彼此（按数值），会被临界区临时屏蔽
- PendSV/SysTick（= 15，最低）：永远最后跑，切换在所有 ISR 退净后

## 要点回顾

1. 红线 = `configMAX_SYSCALL_INTERRUPT_PRIORITY`；数值 ≥ 它才能调 FromISR API。
2. 红线上方的裸奔段是给硬实时中断的逃生通道，代价是禁止碰内核。
3. 临界区用 BASEPRI（部分屏蔽），不用 PRIMASK（全屏蔽）——裸奔段因此不被拖延。
4. 越线调 API = 并发改内核名单 = 偶发跑飞；开发期开 `configASSERT` 当场抓。

<details>
<summary>Q1：F103 只有 4 位优先级（0~15），配置宏为什么有时见到写 0x50 之类的数？</summary>

CMSIS 的 NVIC 接口用"高 4 位对齐"的 8 位编码（0x50 = 5 << 4）。
`configMAX_SYSCALL_INTERRUPT_PRIORITY` 的写法随 port 而定，
老代码里常见直接写移位后的值。本仓按数值 5 配，
实际编码由 port 层换算；动手时以所配 port 的 portmacro.h 注释为准，
配错对齐方式 = 红线悄悄移位（待实验验证）。

</details>

<details>
<summary>Q2：任务里的临界区和 ISR 里的临界区是同一个机制吗？</summary>

不完全是。任务用 `taskENTER_CRITICAL`（写 BASEPRI）；
FromISR API 内部用 `portSET_INTERRUPT_MASK_FROM_ISR` /
`portCLEAR_INTERRUPT_MASK`——多了一步"保存旧 BASEPRI 再恢复"，
因为 ISR 不能假设进来时 BASEPRI 是 0（可能嵌套在另一个受管 ISR 里）。

</details>
