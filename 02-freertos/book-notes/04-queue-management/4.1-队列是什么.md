## 这一篇讲什么

队列是 FreeRTOS 唯一的"正规数据通道"。本篇把它的三个本质讲透：
**环形缓冲的实现、值拷贝（by value）的拷贝方向、以及两个等待名单的存在意义。**

## 一个队列 = 一块存储 + 两个名单

```c
/* 创建时就定死的三件事：长度、单项大小、存储位置（heap 里） */
QueueHandle_t q = xQueueCreate( 10, sizeof( uint32_t ) );
/* 内部 ≈ 10*4 = 40 字节环形缓冲 + 读写指针 + 两个任务名单 */
```

内部结构（概念图，非真实结构体）：

```
┌─ 存储区：环形缓冲（写指针绕回） ─────────────┐
│  [u32][u32][u32][u32]...  共 10 格           │
└──────────────────────────────────────────────┘
┌─ xTasksWaitingToSend：队列满，想写的人排队 ──┐
├─ xTasksWaitingToReceive：队列空，想读的人排队 ┤
└──────────────────────────────────────────────┘
```

**两个名单是关键设计**：队列空时读的人不空转，直接进 Blocked 态挂到
`xTasksWaitingToReceive` 上；数据一到，内核从名单头部唤醒一个任务。
这就是 [3.2 任务状态机](../03-task-management/3.2-任务状态机.md) 里
Blocked 态的"燃料"——等待名单就是 Blocked 态的载体。

## 值拷贝语义：进出都是 memcpy

```c
uint32_t x = 42;
xQueueSend( q, &x, portMAX_DELAY );   /* 把 x 的内容拷贝进队列（写指针处） */

uint32_t y;
xQueueReceive( q, &y, portMAX_DELAY );/* 从队列头部拷贝到 y，然后该格作废 */
```

- **发送**：`&x` 指向的内容被 **拷进**队列，之后改 `x` 不影响队列里的数据。
- **接收**：队列头部的内容被 **拷出**到 `&y`，该格标记为空。
- 收发双方都只负责提供缓冲区，数据的所有权随拷贝转移——**没有共享内存，没有指针泄漏**。

为什么传值而不是传引用？因为值拷贝**天然免同步**：
数据进队列的那一刻起，发送方可以立即复用自己的变量，
不用管接收方什么时候读、读多久。这是 RTOS 里少有的"零锁安全"。

## 为什么是 FIFO 而不是 LIFO

队列默认 **先进先出**。头出尾进，读指针追写指针。
FreeRTOS 也提供 `xQueueSendToFront()`（插到头部），用于"紧急插队"，
但那是特例——**常规数据流一律走尾部**（`xQueueSendToBack`，
而 `xQueueSend` 就是它宏别名）。

## 长度与单项大小：创建时就锁死

`xQueueCreate(10, sizeof(uint32_t))` 创建了"最多存 10 个 u32"的队列，
这两个参数**不可更改**。想改就得删了重建。
选型原则见 [4.3 传指针的代价](4.4-传指针的代价与规矩.md)
（大结构体传指针，小数据直接传值）。

## 与裸机篇对照

裸机篇 [ch10.5 环形缓冲](../../../01-stm32/book-notes/10-interrupts/README.md)
手写过一个 ISR→主循环的 ring buffer：数组 + 读写索引 + 取模。
FreeRTOS 队列就是它的**正式版**：

| 裸机 ring buffer | FreeRTOS queue |
|---|---|
| 自己管读写索引 | 内核管 |
| 满了：覆盖 or 丢弃，自己定 | 满了：阻塞 or 超时 or 失败，参数控 |
| 空了：轮询 or 挂标志 | 空了：任务进 Blocked，数据来了内核唤醒 |
| ISR 和主循环都要小心临界区 | ISR 有专用 FromISR API |

## 要点回顾

1. 队列 = 环形缓冲 + 两个等待名单（读空名单 / 写满名单）。
2. 值拷贝语义：发送拷进、接收拷出，天然免同步。
3. FIFO 是默认，插队用 SendToFront（特例）。
4. 长度和单项大小创建时锁死，改不了。

<details>
<summary>Q1：队列能不能存变长数据？</summary>

不能直接存——单项大小创建时定死。
变通做法：存**固定大小的指针**，指向堆上的变长结构体。
见 [4.4 传指针的代价与规矩](4.4-传指针的代价与规矩.md)。
或者用更高级的事件组/任务通知（ch08/ch09），看数据模式选。

</details>

<details>
<summary>Q2：uxQueueSpacesAvailable 和 uxQueueMessagesWaiting 有什么用？</summary>

`uxQueueMessagesWaiting` 返回当前队列里有多少条数据；
`uxQueueSpacesAvailable` 返回还能塞几条。调试时用来看队列健康状况，
**不要**在正式逻辑里轮询它们来代替阻塞——那就白瞎了 Blocked 设计。

</details>
