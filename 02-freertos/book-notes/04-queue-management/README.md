# ch04 · 队列管理 —— 章节导航

## 本章讲什么

**队列是 FreeRTOS 里任务与任务、ISR 与任务之间传数据的唯一正规通道。**
本章回答：队列内部长什么样（环形缓冲 + 两个阻塞名单）、收发时的阻塞语义、
以及为什么传大结构体要传指针而不是传值。

裸机篇 [ch10.5 环形缓冲](../../../01-stm32/book-notes/10-interrupts/README.md) 手写过一个
ISR→主循环的 ring buffer；FreeRTOS 队列就是那个思路的**带阻塞语义的正式版**。

## 只看这一页（速览）

**主线一句话**：队列是任务间、ISR 与任务间传数据的唯一正规通道——4.1 立结构
（环形缓冲 + 值拷贝 + 两个等待名单），4.2 讲 `xTicksToWait` 的阻塞三态与唤醒
顺序，4.3 给 ISR 专用的 FromISR 家族，4.4 谈传指针的所有权三铁律，4.5 用队列
集实现"阻塞在多个来源的并集上"。

| 小节 | 一句话结论 |
|---|---|
| 4.1 队列是什么 | 队列 = 环形缓冲 + 两个等待名单；值拷贝进出都是 memcpy、天然免同步；长度和单项大小创建时锁死 |
| 4.2 阻塞语义与超时 | `xTicksToWait` 三态：0 不阻塞 / N 超时 / portMAX_DELAY 死等；唤醒优先级优先、同级 FIFO |
| 4.3 FromISR 家族 | ISR 里只能用 FromISR 变体，满了立刻失败丢数据；woken + `portYIELD_FROM_ISR` 让高优先级任务退出中断即接手 |
| 4.4 传指针的代价与规矩 | 单项 > 16~32B 考虑传指针；三铁律：长寿命存储、发送后不碰、释放责任写死；只要最新值用长度 1 + Overwrite |
| 4.5 队列集 | 一个任务阻塞在多个队列/信号量的并集上；select 返回句柄后还要再 receive/take 一次 |

**本章最容易踩的坑**

- 把指向局部变量的指针塞进队列：函数返回后指针变野指针（4.4）
- ISR 里调普通版队列 API = 未定义行为，必须 FromISR（4.3）
- ISR 丢字节的对策是让消费端更快，不是加大队列——缓冲不是解药（4.3）
- 队列集容量必须 ≥ 成员长度之和，且注册时成员必须为空，否则 `pdFAIL`（4.5）
- select 拿到句柄不等于数据已取出，还要对句柄再 receive/take 一次（4.5）
