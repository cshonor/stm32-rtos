# 4.5 队列集 Queue Set：一个任务等多个队列

## 这一篇讲什么

一个任务要同时听 UART 队列和 SPI 队列，怎么办？
阻塞读 UART 就错过 SPI，轮询两个都浪费 CPU。
**队列集（Queue Set）让一个任务阻塞在"多个队列的并集"上，
任何一个有数据就醒。** 这是 FreeRTOS 的 `select()`/`poll()`。

## 问题场景

```c
/* 错误示范：串行等待，SPI 数据被饿死 */
for( ;; )
{
    xQueueReceive( uart_q, &d, portMAX_DELAY );  /* SPI 来了也不知道 */
    xQueueReceive( spi_q,  &d, portMAX_DELAY );
}

/* 也错误：轮询，CPU 空转 */
for( ;; )
{
    if( xQueueReceive( uart_q, &d, 0 ) == pdPASS ) { ... }
    if( xQueueReceive( spi_q,  &d, 0 ) == pdPASS ) { ... }
    vTaskDelay( 1 );  /* 还是浪费 */
}
```

## 队列集：并集阻塞

```c
/* 创建：容量 = 所有成员队列长度之和 */
QueueSetHandle_t qs = xQueueCreateSet( 10 + 5 );  /* uart_q(10) + spi_q(5) */

/* 注册成员（创建后不能再改） */
xQueueAddToSet( uart_q, qs );
xQueueAddToSet( spi_q,  qs );

/* 消费端：阻塞在并集上 */
for( ;; )
{
    QueueSetMemberHandle_t which = xQueueSelectFromSet( qs, portMAX_DELAY );
    if( which == uart_q )
    {
        xQueueReceive( uart_q, &data, 0 );  /* 一定有数据，0 超时 */
    }
    else if( which == spi_q )
    {
        xQueueReceive( spi_q, &data, 0 );
    }
}
```

`xQueueSelectFromSet` 返回**有数据的那个队列的句柄**，
你再对它调 `xQueueReceive`（超时给 0，因为数据已经在那里了）。

## 工作原理

队列集本身也是一个队列（特殊的），成员队列在有数据时
**自动把自己的句柄"发"到队列集里**。消费端读队列集 = 读句柄。

```
uart_q ──有数据──→ 把自己句柄 push 进 qs ──→ 消费端 select 返回 uart_q
spi_q  ──有数据──→ 把自己句柄 push 进 qs ──→ 消费端 select 返回 spi_q
```

**队列集的容量必须 ≥ 所有成员长度之和**——最坏情况所有成员同时满，
每个成员都要能把自己的句柄塞进去。

## 不止队列：信号量也能进集合

```c
SemaphoreHandle_t bin_sem = xSemaphoreCreateBinary();
xQueueAddToSet( bin_sem, qs );  /* 二值信号量也能注册 */

/* select 返回 bin_sem 时，用 xSemaphoreTake 消费 */
if( which == bin_sem )
{
    xSemaphoreTake( bin_sem, 0 );
}
```

所以队列集的真正语义是：**"等待一组可阻塞对象中的任何一个就绪"**。
队列、二值信号量、计数信号量都可以当成员。

## 限制与坑

| 坑 | 说明 |
|---|---|
| 创建后不能改容量 | `xQueueCreateSet` 时定死，成员加不进去了只能重建 |
| 成员必须先空 | `xQueueAddToSet` 要求成员队列为空，否则返回 `pdFAIL` |
| select 后还要 receive | 拿到句柄不代表数据已取出——还要再调一次 receive/take |
| 不能嵌套 | 队列集不能注册另一个队列集 |
| 内存开销 | 队列集本身占 RAM（容量 × sizeof(void*) + 管理结构） |

## 与 Linux 对照

| FreeRTOS | Linux | 语义 |
|---|---|---|
| `xQueueCreateSet` + `xQueueSelectFromSet` | `poll()` / `select()` / `epoll_wait()` | 等多路就绪 |
| 成员 = 队列/信号量句柄 | 成员 = fd | 等待对象不同，语义一致 |
| 返回就绪的成员句柄 | 返回就绪的 fd 集合 | 都要二次消费（receive/read） |

`epoll` 的边缘触发/水平触发在 FreeRTOS 里没有对应物——
队列集永远是水平触发：数据还在就会再次返回。

## 要点回顾

1. 队列集 = 一个任务阻塞在多个队列/信号量的并集上。
2. 容量 = 所有成员长度之和；创建后不能改。
3. `xQueueSelectFromSet` 返回有数据的成员句柄，再对它 receive/take。
4. 语义等价于 Linux `poll()`，但只有水平触发。

<details>
<summary>Q1：能不能用多个任务各听一个队列来代替队列集？</summary>

能，而且很多时候**更应该**这么做——每个数据源一个消费者任务，
各自阻塞各自的队列，简单清晰。队列集的真正场景是：
**一个任务必须根据多个数据源做联合决策**（比如"UART 收到命令后
等 SPI 数据到了再一起处理"），拆开就要额外的同步机制。
如果各数据源互不相关，分任务比队列集好。

</details>

<details>
<summary>Q2：xQueueRemoveFromSet 什么时候用？</summary>

运行时动态调整成员——比如某个外设被关闭了，把它的队列从集合里
移除，避免 select 永远等不到它。移除前必须确保该队列为空。
动态增删成员的场景很少见，大部分设计在初始化时就定死了。

</details>
