## 这一篇讲什么

软件定时器 = "到点由内核替你调一个回调函数"的服务。
本篇回答三件事：**单次与周期两种模式差在哪、所有定时器为什么
由同一个守护任务统一执行、守护任务的优先级配错会怎样。**

## 两种模式

```c
TimerHandle_t t1 = xTimerCreate(
    "once",            /* 名字（调试用） */
    pdMS_TO_TICKS(500),/* 周期（单次定时器里是"延时"） */
    pdFALSE,           /* pdFALSE = 单次；pdTRUE = 周期 */
    ( void * ) 0,      /* 定时器 ID（回调里区分多个定时器用） */
    vOnceCallback );   /* 回调函数 */
```

| 模式 | 创建参数 | 到点后行为 | 典型用途 |
|---|---|---|---|
| 单次（one-shot） | `pdFALSE` | 回调执行一次后定时器休眠，要再次触发须重新 start | 超时看门狗："500ms 内没收到应答就报错" |
| 周期（auto-reload） | `pdTRUE` | 回调执行完**自动重新装填**，永远循环 | 周期采样、LED 闪烁、按键扫描 |

裸机篇 [ch19.1](../../../01-stm32/book-notes/19-systick-and-timer/19.1-SysTick是内核自带的心跳.md)
里手写的"g_ms 软件计数器到点翻标志"就是单次定时器的雏形——
内核版把"翻标志 + 主循环轮询"升级成了"直接执行回调"。

## 守护任务：所有定时器共用的执行者

关键事实：**回调函数不在 ISR 里跑，也不在"你的任务"里跑，
而在一个叫定时器服务任务（timer service / daemon task）的系统任务里跑。**

```
vTaskStartScheduler()
  → 若 configUSE_TIMERS == 1，自动创建守护任务
       （优先级 = configTIMER_TASK_PRIORITY，栈深 = configTIMER_TASK_STACK_DEPTH）

tick 中断：只负责"到点没有"的判断与通知
守护任务：被唤醒后逐个执行到点定时器的回调
```

守护任务就是一个普通任务（[ch03](../03-task-management/README.md) 的机制全适用），
由内核在启动调度器时顺手创建——和空闲任务是"双胞胎"。

## 周期从哪一刻起算（书里的坑）

周期定时器的下一次到期时刻，从**本次到期的那一刻**起算，
不是从"回调执行完"起算。含义：

- 回调本身耗时不会"推后"后续周期——名义节奏是钉死的
- 但如果回调耗时**超过一个周期**，到点事件会积压（通过命令队列，
  见 [5.2](5.2-定时器命令队列.md)），表现为回调连轴转、节奏追不回来

所以周期回调的黄金法则：**短**。长活甩给别的任务（队列/任务通知）。

## 守护任务优先级：配高配低都出事

| 配置 | 后果 |
|---|---|
| 太高（如最高级） | 回调一跑就抢占所有应用任务，回调稍长 = 全局卡顿 |
| 太低（如 0） | 任何忙任务都能饿死它，定时器到点了**没人执行**，"定时器不准" |

经验值：比"依赖定时器的最高优先级应用任务"**略高一级**，
让回调能及时跑、又不长期霸占 CPU。F103 上配几级合适待实验验证。

## 三个配置宏

```c
#define configUSE_TIMERS                1     /* 总开关，1.3 节先关掉了 */
#define configTIMER_TASK_PRIORITY       2     /* 守护任务优先级 */
#define configTIMER_QUEUE_LENGTH        10    /* 命令队列深度，见 5.2 */
#define configTIMER_TASK_STACK_DEPTH    256   /* 单位：字 */
```

栈深按"最深的回调调用链"估算，回调里别调深库函数。

## 要点回顾

1. 单次 = 触发一次后休眠；周期 = 自动重装，节奏按到期时刻钉死。
2. 回调全部跑在守护任务上下文——不是 ISR，也不是你的任务。
3. 守护任务优先级要"略高但不霸顶"，两端都出事。
4. 回调必须短；长活用队列/通知甩出去。

<details>
<summary>Q1：软件定时器精度有多高？</summary>

精度上限是一个 tick（1ms @ 1000Hz）：到期判断只在 tick 中断里做，
再加守护任务被调度的延迟。**不能拿它当微秒级时基用**——
要硬实时定时用硬件 TIM（裸机篇 ch19.5）。软件定时器定位是
"毫秒级以上的慢节奏事件调度"。

</details>

<details>
<summary>Q2：定时器 ID（pvTimerID）有什么用？</summary>

多个定时器可以共用一个回调函数，回调里用
`pvTimerGetTimerID()` 区分"是哪个定时器到点了"。
也可以当通用 void* 存上下文指针（指向静态/全局数据，别指局部变量）。

</details>
