## 这一篇讲什么

FreeRTOS 内核源码在几十个关键位置预留了 `traceXXX()` 宏——
默认全是空，**你在 FreeRTOSConfig.h 里定义它，它就在内核内部替你埋点**。
这是 FreeRTOS+Trace / Percepio Tracealyzer 这类可视化工具的底层机制，
也是你自己写轻量调度日志的正规入口。

## 钩子宏是什么：内核留的回调插槽

```c
/* 内核源码里（tasks.c 概念示意）：每次任务切换都会经过 */
traceTASK_SWITCHED_IN();

/* 默认定义（FreeRTOS.h 里）：空 */
#ifndef traceTASK_SWITCHED_IN
    #define traceTASK_SWITCHED_IN()
#endif
```

你不定义 = 零开销（编译器直接删）；
你定义了 = 在**内核最精准的位置**插了自己的代码——
想观测的事件一个不漏，且不用改内核源码（升级 FreeRTOS 不丢补丁）。

## 常用宏速查

| 宏 | 触发时机 |
|---|---|
| `traceTASK_SWITCHED_IN` / `_OUT` | 任务切入 / 切出 |
| `traceTASK_CREATE` / `_DELETE` | 任务创建 / 删除 |
| `traceTASK_DELAY` / `_SUSPEND` / `_RESUME` | 延时 / 挂起 / 恢复 |
| `traceQUEUE_SEND` / `_RECEIVE` | 队列收发（含信号量） |
| `traceISR_ENTER` / `_EXIT` | 进出 ISR（port 层埋点） |
| `traceMALLOC` / `traceFREE` | heap 分配释放 |

## 最小可用示例：切换计数器

```c
/* FreeRTOSConfig.h */
extern volatile uint32_t ulSwitchCount;
#define traceTASK_SWITCHED_IN()  ulSwitchCount++
```

跑一分钟看计数，和预期心跳/事件频率对不上 = 调度行为异常
（比如有个任务在空转抢时间片——结合
[11.3 运行时统计](11.3-任务与堆水位观测.md) 能直接点名是谁）。

## FreeRTOS+Trace / Tracealyzer 的概念

Percepio Tracealyzer 的工作方式（概念，本仓未实测）：
钩子宏定义成"往 RAM 环形缓冲写事件记录"（谁、何时、干了什么，
压缩编码每条几字节）→ 调试器/串口倒出缓冲 →
PC 端重放成时间线图：任务条带、ISR 穿插、队列事件连线。

它回答的是快照 API 回答不了的问题：
**"过去 200 ms 里调度的完整顺序是什么？"**
——死锁、优先级反转、偶发超时这类**时序病**只有连续录像能抓。

书里的定位：trace 工具是"调试核武器"，平时不配，遇到时序型 bug 再上；
真到那一步直接接 Tracealyzer 的 recorder 库，别手写全套。

## 三条军规

1. **钩子里不许阻塞、不许调可能阻塞的 API**——你人在内核肚子里。
2. **钩子里越快越好**——`traceTASK_SWITCHED_IN` 在每次切换都跑，
   里面放个 printf 等于给调度器挂铅球（printf 本身的坑见
   [12.1](../12-troubleshooting/12.1-症状病因对照表.md)）。
3. **观察会改变被观察对象**——记录越细扰动越大，
   时序病抓不到时先减采样率，别把病人治死在手术台上。

## 与其他观测手段的分工

| 手段 | 粒度 | 开销 | 回答什么 |
|---|---|---|---|
| configASSERT（[11.1](11.1-configASSERT总开关.md)） | 事件点 | 极低 | 参数/状态错没错 |
| vTaskList 等快照（[11.3](11.3-任务与堆水位观测.md)） | 单时刻全览 | 一次性 | 现在健不健康 |
| trace 钩子 | 连续事件流 | 持续低开销 | 刚才发生了什么顺序 |
| 调试器断点 | 任意 | 停车 | 此刻的精确现场 |

## 要点回顾

1. trace 宏 = 内核预留的空插槽，定义即埋点，不改内核源码。
2. `traceTASK_SWITCHED_IN` 是观测调度的黄金位置。
3. Tracealyzer = 钩子宏 + RAM 环形缓冲 + PC 端重放，专抓时序病。
4. 钩子三军规：不阻塞、要极快、警惕观察者效应。

<details>
<summary>Q1：trace 钩子和 idle 钩子、tick 钩子是一类东西吗？</summary>

不是。idle/tick/malloc-failed/stack-overflow 钩子是**完整的回调函数**
（见 [3.5](../03-task-management/3.5-空闲任务与钩子.md)）；
trace 宏是**内联插槽**，插在内核函数中间的几十个点上。
前者是"内核请你干活"，后者是"内核让你看它干活"。

</details>

<details>
<summary>Q2：不用 Tracealyzer，自己能做简易 trace 吗？</summary>

能：定义 `traceTASK_SWITCHED_IN` 把 `(任务ID, 时基读数)` 压进
RAM 环形缓冲（复用 [11.3](11.3-任务与堆水位观测.md) 的 TIM2 时基），
事后调试器 dump 出来人工分析，够抓"切换顺序异常"。
要做队列事件追踪和图形化就别造轮子，直接上 Tracealyzer recorder。

</details>
