## 这一篇讲什么

任务通知的官方卖点是"一个顶四个"：二值信号量、计数信号量、
事件组、长度 1 的队列，都能用它顶替。本篇把三种替身写法和
`xTaskNotify` 的五种 `eNotifyAction` 讲透。

## 替身一：信号量（Give/Take）

[ch06 中断管理](../06-interrupt-management/README.md) 的标准模式是
"ISR 给信号量，任务拿信号量做下半部"。通知版把对象省了：

```c
/* 正主：二值信号量 */
xSemaphoreGiveFromISR( xSem, &xWoken );        /* ISR 侧 */
xSemaphoreTake( xSem, portMAX_DELAY );         /* 任务侧 */

/* 替身：任务通知，xSem 这个对象整个消失 */
vTaskNotifyGiveFromISR( xTask, &xWoken );      /* ISR 侧：对方计数 +1 */
ulTaskNotifyTake( pdTRUE, portMAX_DELAY );     /* 任务侧：取走并清零 */
```

`ulTaskNotifyTake` 第一个参数是**清法**：

| 取值 | 效果 | 对应正主 |
|---|---|---|
| `pdTRUE` | 取走时通知值**清零** | 二值信号量（攒多了也只算一次） |
| `pdFALSE` | 取走时通知值**减一** | 计数信号量（来几次处理几次） |

计数信号量场景（比如"来了 N 个数据，逐个处理"）就用 `pdFALSE`，
返回值是减一前的计数——通知值本身就是计数器，
不需要 `uxSemaphoreGetCount` 之类的辅助查询。

## 替身二：事件组（eSetBits + Wait）

[ch08 事件组](../08-event-groups/README.md) 用 24 个事件位表达
"哪几件事发生了"。通知值是 32 位，**全都能当事件位用**：

```c
/* ISR 里置第 0 位："收到一帧" */
xTaskNotifyFromISR( xTask, 0x01, eSetBits, &xWoken );

/* 任务侧：等到后读出全部位，退出时清掉 */
uint32_t val;
xTaskNotifyWait( 0,                  /* 进入时不预清 */
                 0xFFFFFFFF,         /* 成功返回时清掉全部 32 位 */
                 &val, portMAX_DELAY );
if( val & 0x01 ) { /* 处理收到的一帧 */ }
```

和事件组的差别：事件组支持**多任务同等单位**和"等位 A 或位 B"的 OR 语义；
通知只支持一对一，位语义一样，组合能力弱。

## 替身三：轻量邮箱（eSetValueWithOverwrite）

长度 1 队列 + `xQueueOverwrite` 的"最新值邮箱"（见 [4.4](../04-queue-management/4.4-传指针的代价与规矩.md)），通知版：

```c
/* 发送：直接覆写对方通知值 */
xTaskNotify( xTask, sensor_value, eSetValueWithOverwrite );

/* 接收：读出整个 32 位 */
xTaskNotifyWait( 0, 0, &val, portMAX_DELAY );
```

适合"只关心最新值"的单生产者场景（传感器采样、状态字广播给唯一消费者）。

## 五种 eNotifyAction 总表

| eAction | 对通知值的操作 | 典型用途 |
|---|---|---|
| `eNoAction` | 不改值，只更新通知状态 | 纯"拍一下"唤醒，值由别的途径传 |
| `eSetBits` | 按位或（`val |= bits`） | 事件组替身 |
| `eIncrement` | 值 +1 | 计数信号量替身（Give 就是它的封装） |
| `eSetValueWithOverwrite` | 无条件覆写 | 轻量邮箱（最新值） |
| `eSetValueWithoutOverwrite` | 对方还没取走就**失败返回** | 轻量队列（不丢数据，发重了报错） |

注意最后一行：`eSetValueWithoutOverwrite` 是唯一会"发送失败"的动作——
对方上一次的通知还没被 `xTaskNotifyWait` 取走时，返回 `pdFAIL`，
值保持不变。这是通知家族里**唯一的"不覆盖"保证**，
想要"一条都不能丢"就用它并检查返回值。

## 要点回顾

1. Give/Take 顶替信号量：`pdTRUE` 清零 = 二值，`pdFALSE` 减一 = 计数。
2. `eSetBits` + `xTaskNotifyWait` 顶替事件组，32 位全可用。
3. `eSetValueWithOverwrite` 顶替长度 1 的覆写队列（轻量邮箱）。
4. 要"不丢数据"用 `eSetValueWithoutOverwrite` 并检查返回值。

<details>
<summary>Q1：xTaskNotifyWait 的两个清位参数怎么配合？</summary>

第一个 `ulBitsToClearOnEntry`：进入等待**前**清哪些位——
用于丢弃历史残留，常用 0（保留）或全 1（每次从干净状态等）。
第二个 `ulBitsToClearOnExit`：成功返回**后**清哪些位——
常用全 1（读走即清，下次等全新事件），也可以只清已处理的位、
留下没处理的位下次继续看。

</details>

<details>
<summary>Q2：通知能替代所有信号量场景吗？</summary>

不能。互斥锁（mutex）不行——互斥锁有**优先级继承**机制
（见 ch07 资源管理），通知没有。多对一、一对多也不行，
那是通知的结构性限制，下一篇专门讲。

</details>
