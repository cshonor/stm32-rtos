# 9.3 通知的边界：什么时候必须退回用队列

## 这一篇讲什么

任务通知快且省，但它是**有硬边界的优化件**，不是通信原语的终极形态。
本篇把三条边界划清楚：**一对一限制、值的所有权、以及什么场景必须
退回队列/信号量正主**。最后补齐 FromISR 家族的用法。

## 边界一：只能一对一

通知值长在**接收任务的 TCB 里**，这决定了两个方向都受限：

- **不能一对多**：通知发给指定任务句柄，没有"广播给一组任务"的机制。
  事件组能让 N 个任务同等单位，通知做不到。
- **多对一要小心**：多个发送方对同一个 32 位值做读改写，
  没有互斥保护（`eSetBits` 的"或"操作在多发送方并发时会丢位）。
  官方定位就是**一个通知通道配一个发送源**。

## 边界二：只有接收方能阻塞

队列满时**发送方可以阻塞**等空位（[4.2 阻塞语义](../04-queue-management/4.2-阻塞语义与超时.md)）。
通知没有这个机制——发送动作就是改对方 TCB，改完就走，
**发送方无法等"对方把上一条取走"**。

想要"不丢"只能靠 `eSetValueWithoutOverwrite` 的失败返回值自己补救
（重试、计数丢弃），内核不会替你排队。

## 边界三：通知值的所有权

通知值是**无类型的 32 位标量**，所有权语义极简单：
改的那一刻起就归接收方，没有拷贝缓冲、没有排队副本。推论：

- 适合传**标量**：计数、位掩码、状态字、小号数据、指针。
- 传指针时规矩和队列一样（见 [4.4](../04-queue-management/4.4-传指针的代价与规矩.md)）：
  指向的必须是静态/堆存储，且所有权约定要自己管——
  通知本身**只搬 32 位**，不帮你管指针指向的东西。
- 没有"通知里还剩几条没取"的查询——值只有一个，要么在要么被取走。

## 决策表：通知还是正主

| 场景 | 选型 |
|---|---|
| ISR→唯一任务，"发生了一次" | ✅ 通知（Give/Take），最快路径 |
| ISR→唯一任务，传最新采样值 | ✅ 通知（eSetValueWithOverwrite） |
| 唯一发送方→唯一任务，多事件位 | ✅ 通知（eSetBits） |
| 多任务同等事件 | 退回：事件组 |
| 需要互斥 + 优先级继承 | 退回：互斥锁（通知没有继承机制） |
| 数据不能丢、发送方要能等 | 退回：队列（有阻塞语义和多格缓冲） |
| 多对一 / 一对多 | 退回：队列或事件组 |

一句话：**结构上是"一对一管道"的用通知，是"枢纽/总线"的用正主。**

## FromISR 家族：规则和队列那套完全一样

```c
void USART1_IRQHandler( void )
{
    BaseType_t xWoken = pdFALSE;

    /* 收到一帧，通知处理任务（计数 +1 并唤醒） */
    vTaskNotifyGiveFromISR( xRxTask, &xWoken );

    portYIELD_FROM_ISR( xWoken );
}
```

| 任务上下文 | ISR 上下文 |
|---|---|
| `xTaskNotifyGive` | `vTaskNotifyGiveFromISR`（注意 ISR 版返回 void） |
| `xTaskNotify` | `xTaskNotifyFromISR`（多一个 `pxHigherPriorityTaskWoken`） |
| —— | `xTaskNotifyAndQueryFromISR`（顺带读对方旧值，少用） |

规则与 [4.3 FromISR 家族](../04-queue-management/4.3-FromISR家族.md) 完全一致：

- 不能阻塞（本来通知发送就不阻塞，天然适配 ISR）
- `pxHigherPriorityTaskWoken` 初始 `pdFALSE`，退出时 `portYIELD_FROM_ISR`
- 中断优先级数值 ≥ `configMAX_SYSCALL_INTERRUPT_PRIORITY` 才能调

## 要点回顾

1. 通知只能一对一；多发送方并发改值无保护。
2. 发送方不能阻塞——"不丢"只有 `eSetValueWithoutOverwrite` + 自查返回值。
3. 通知值是无类型 32 位，传指针时所有权自己管。
4. 需要互斥、广播、可靠排队时退回正主。
5. FromISR 用法与队列家族同规则。

<details>
<summary>Q1：xTaskNotifyFromISR 的返回值有什么用？</summary>

返回 `pdPASS` 表示通知送达；用 `eSetValueWithoutOverwrite` 且对方
上一条还没取走时返回 `pdFAIL`。ISR 里不能等，收到 `pdFAIL`
的对策和队列满一样：计数丢弃，事后分析——别在 ISR 里重试打转。

</details>

<details>
<summary>Q2：同一个任务能不能同时用通知当信号量和当事件组？</summary>

不推荐。通知值只有一个，Give（+1）和 eSetBits（按位或）会互相污染
对方的语义。新版 FreeRTOS 提供**通知值数组**
（`configTASK_NOTIFICATION_ARRAY_ENTRIES > 1`，每个任务多个槽位），
一个槽位配一种语义才能并存；槽位为 1（默认）时一个任务只用一种。

</details>
