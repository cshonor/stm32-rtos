## 这一篇讲什么

tickless 的三步骨架不变，但"睡多深、用什么叫醒"是 STM32 平台决策。
本篇对照 F103 的三档睡眠各关了什么、能被什么唤醒，
以及和 tickless 配对时的取舍。最后说清**谁不该开 tickless**。

## 先用人话说一遍（新手铺垫）

前两篇的"睡觉"一直没说到底睡多沉。F103 给三档，像房子的
三种省法：**Sleep 是打盹**——灯全亮着，人闭眼，门铃一响
秒应；**Stop 是拉闸限电**——总闸拉掉，只留冰箱和电池门铃
（RTC），省得多，但来电后有些电器要重新开（时钟要重建）；
**Standby 是全家断电出门**——基本全断，回来等于重新搬家
（复位重启，RAM 全丢），这已经不是"小睡"，是"关机"。

选哪档不是贪省电就行，得看**谁能把你叫醒**：拉闸之后只有
电池门铃还响（Stop 只认 EXTI/RTC），所以 UART 想叫醒你得先
把线接到门铃上。还得看**醒来要收拾多久**：Stop 醒来电是来了，
但总闸要重新合（HSI→HSE→PLL 回 72MHz；三者是内部 8MHz RC 时钟→外部晶振→倍频器，合起来才到全速主频），收拾完才能补记
值班日志——顺序反了，时间就对不上。

映射：家电 = 外设时钟，门铃 = EXTI/RTC 唤醒源，合闸 = 唤醒后
时钟重建。正文三张表（档位速查、tickless 配对、谁不该开）
按这个顺序看。

| 术语 | 一句话解释 |
|---|---|
| Sleep / Stop / Standby | F103 由浅到深的三档低功耗模式，关掉的时钟域逐级增多 |
| EXTI | 外部中断/事件线：Stop 模式下唯一能叫醒 CPU 的通道（含 RTC 闹钟映射） |
| RTC / LSE | 实时时钟及其 32.768kHz 低速晶振：深度睡眠下还在走的"电池门铃" |
| 备份域 | Standby 下唯一保持供电的区域（RTC、备份寄存器），其余 RAM 全丢 |
| 时钟重建 | Stop 醒来后系统时钟回落到 HSI 8MHz，需重新拉起 HSE+PLL 才能回 72MHz |
| `DBGMCU` | 调试支持寄存器：置位后睡眠不断调试连接，代价是省电打折，量产要关 |

## F103 三档睡眠速查

| 档位 | 关了什么 | 保留什么 | 唤醒源 | 唤醒后时钟 |
|---|---|---|---|---|
| **Sleep** | CPU 时钟（HCLK） | 所有外设时钟、SRAM、寄存器 | 任意中断 | 不变，立即续跑 |
| **Stop** | CPU + 大部分外设时钟（HSE/HSI 停） | SRAM、寄存器、RTC、低速时钟 | EXTI 线（含 RTC 闹钟、EXTI 引脚） | 回 HSI，要重新切 PLL |
| **Standby** | 几乎全断（1.8V 域断电） | 仅备份域、RTC、WKUP 引脚 | RTC 闹钟、WKUP 上升沿、NRST | **复位重启**（SRAM 全丢） |

裸机篇 [ch19 SysTick](../../../01-stm32/book-notes/19-systick-and-timer/README.md)
讲过 SysTick 挂在 CPU 时钟域——Sleep 下 SysTick 也停了，
Stop 下更是整个停。所以 tickless 里"停 tick"在硬件上是自然结果，
关键是**另找一个还活着的钟来定时唤醒**。

## 与 tickless 的配对

| 档位 | 唤醒定时器选型 | 与 tickless 的配合 |
|---|---|---|
| Sleep | SysTick 自己（拉长重装载） | 官方参考实现的默认做法，改动最小 |
| Stop | RTC 闹钟（32.768kHz LSE 还在走） | 自写 `portSUPPRESS_TICKS_AND_SLEEP`：停 SysTick、编程 RTC、WFI 进 Stop、醒后重配时钟再补 tick |
| Standby | RTC 闹钟 / WKUP | 不适合 tickless——唤醒即复位，RTOS 现场全无，属于"关机"语义 |

**Stop 档的两个额外动作**（自写 port 时必须处理）：

1. **唤醒后时钟重建**：Stop 醒来回 HSI 8MHz，要重新使能 HSE+PLL
   回 72MHz，这期间别补 tick——先把系统时钟扶正再算时间。
2. **唤醒源先接 EXTI**：RTC 闹钟、UART 唤醒线都要映射到 EXTI，
   Stop 只认 EXTI/NRST。

```c
/* Stop 版 portSUPPRESS_TICKS_AND_SLEEP 骨架（概念伪代码） */
停 SysTick;
编程 RTC 闹钟 = 现在 + N tick;
进入 Stop（PWR 寄存器 + __WFI）;
/* ---- 醒来 ---- */
重配系统时钟回 72MHz;
读 RTC 算实际睡了 T;
恢复 SysTick;
vTaskStepTick( T );
```

## 谁不该开 tickless

| 场合 | 原因 |
|---|---|
| 微秒级精度的周期任务 | tickless 的睡眠粒度是 tick（通常 1ms），且进/出睡眠有不可忽略的执行开销，µs 级时序会被抖坏 |
| 高吞吐 ISR 流（如高速串口无 DMA（直接存储器访问：外设自己搬数据进内存、不占用 CPU 的搬运硬件）） | Stop 档下外设时钟停，头几个字节可能在时钟重建期间丢掉 |
| 调试阶段 | 睡着后 SWD（调试器连芯片的两线调试接口，ST-Link 走的就是它）连接常断（下详），开发期建议关掉 |
| 任务几乎不空闲的系统 | 每次算出来 N 都小于阈值，纯白忙 |

**调试器问题**：F103 默认进低功耗后调试域断电，OpenOCD（开源调试软件，配合 ST-Link 在电脑上调试芯片）会丢连接。
置 `DBGMCU->CR` 的 `DBG_SLEEP` / `DBG_STOP` / `DBG_STANDBY` 位，
让调试时钟在睡眠中保持——**代价是省电效果打折**，所以这是
调试期开关，量产固件别开。

## 要点回顾

1. Sleep 配 SysTick 拉长（官方默认）；Stop 配 RTC 闹钟（自写 port）；Standby 不配对 tickless。
2. Stop 唤醒后先重建时钟，再补 tick。
3. µs 级精度、密集 ISR 流、调试期——别开 tickless。
4. 调低功耗时记得 `DBGMCU` 的 DBG_* 位，否则调试器一睡就断。

<details>
<summary>Q1：tick 是 1ms，RTC 是 32.768kHz，补 tick 的精度够吗？</summary>

RTC 分辨率约 30.5µs，远细于 1ms tick，换算回 tick 时取整
误差不足 1 tick。注意 RTC 与 SysTick 是**两个独立时钟源**，
长期运行会有 ppm（百万分之一，衡量时钟快慢偏差的单位）级漂移——对 tick 级超时可忽略，
做日历级计时才需要另行校准。

</details>

<details>
<summary>Q2：用了 HAL（ST 官方固件库，封装寄存器操作的 C 库）库，HAL 的 1ms 时基和 FreeRTOS tick 冲突吗？</summary>

CubeMX 生成的工程通常把 HAL 时基从 SysTick 挪到某个 TIM
（正因为 SysTick 归 FreeRTOS 用）。tickless 睡眠期间如果那个
TIM 也停了，HAL_GetTick 会停走——HAL 侧超时逻辑会受影响。
方案：HAL 时基也改挂 RTC 唤醒，或在 port 层同步补偿 HAL 计数。

</details>

## 坑点速查

| 坑点 | 书 / 常识怎么说 | 实际是什么 |
|---|---|---|
| Stop 醒来第一件事是补 tick | 醒了先把时间补上 | 系统时钟回落到 HSI 8MHz，**先重建 HSE+PLL 回 72MHz 再补 tick**，顺序反了时间全错 |
| Stop 模式下 UART 中断照样能叫醒 CPU | 中断就是唤醒源 | Stop 只认 EXTI/NRST——UART 唤醒线要先映射到 EXTI；高速数据流的头几个字节可能在时钟重建期间丢掉 |
| Standby 睡得最深，tickless 该用它 | 越深越省电越好 | 唤醒即复位、SRAM 全丢，RTOS 现场全无，属"关机"语义，不配对 tickless |
| 接着调试器测低功耗，行为应该一样 | 调试器只是旁观者 | 默认进低功耗调试域断电，SWD 掉线；要置 `DBGMCU->CR` 的 `DBG_*` 位，代价是省电打折、量产必须关 |
| RTC 和 SysTick 是同一个钟 | 都是定时器 | 两个独立时钟源，长期有 ppm 级漂移；RTC 分辨率约 30.5µs，换算回 tick 取整误差不足 1 tick，做日历级计时才需校准（Q1） |

## 代码自测

_注：本节代码按 FreeRTOS API 语义编写，未在本仓库环境实跑，上板验证见「验证路径」。_

```c
/* 验证 Sleep 档 + EXTI 唤醒：按键 PA0 配 EXTI0 上升沿触发 */
static volatile uint32_t ulWokeByButton = 0;

void vApplicationIdleHook( void )   /* configUSE_IDLE_HOOK 置 1 */
{
    __WFI();                        /* Sleep 档：任意中断可唤醒，醒后时钟不变 */
}

void EXTI0_IRQHandler( void )
{
    if( ( EXTI->PR & EXTI_PR_PR0 ) != 0 )
    {
        EXTI->PR = EXTI_PR_PR0;     /* 写 1 清挂起位 */
        ulWokeByButton++;
    }
}

void vReportTask( void *pv )
{
    ( void ) pv;
    for( ;; )
    {
        vTaskDelay( pdMS_TO_TICKS( 2000 ) );
        printf( "button wakeups: %lu\r\n",
                ( unsigned long ) ulWokeByButton );
    }
}
```

**预期现象**：
- 不按按键时计数不变；每按一次 +1，串口正常输出。
- Sleep 档唤醒后系统时钟不用重建，程序立即续跑。
- 换 Stop 档后此代码失效：UART 收/发可能丢头几个字节，且必须醒后重建时钟。

**验证路径**：F103 实机 + 按键接 PA0 + USART printf；万用表/功耗仪对比睡与不睡的电流。

**常见翻车点**：
- EXTI 挂起位忘写 1 清除，进一次 ISR 后反复触发。
- 接着 ST-Link 测睡眠，没置 `DBGMCU` 的 `DBG_SLEEP` 位，调试器一睡就断连。
- Stop 档醒后忘了先重建 HSE/PLL 就补 tick、跑业务。
