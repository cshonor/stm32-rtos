## 这一篇讲什么

Ready 池里站了好几个任务，调度器选谁？答案三句话：
**优先级高的先跑；一样高的轮转跑；新来的高优先级立刻抢。**
难点全在细节里——尤其是那个"数字方向"的坑。

## 铁律零：数字方向（再说一遍，因为它值一篇）

| 体系 | 数字小 | 数字大 | 可用范围 |
|---|---|---|---|
| FreeRTOS **任务**优先级 | 低（0 最低） | **高** | 0 ~ configMAX_PRIORITIES-1 |
| Cortex-M **中断**优先级 | **高**（0 最高） | 低 | 0 ~ 255（按优先级位数） |

任务优先级是**纯软件概念**（就绪名单的数组下标），
中断优先级是**硬件 NVIC 概念**——两套数字方向相反，同片共存。
写 `FreeRTOSConfig.h` 时两类配置紧挨着，是全仓最容易写反的地方。

## 规则一：抢占（preemption）

`configUSE_PREEMPTION = 1`（本仓配置，也是主流）时：

```
任何时刻，Running 的 = Ready 池里优先级最高的那个
高优先级任务一旦变 Ready（延时到/队列到数据）→ 立刻抢，当前任务当场让位
```

"立刻"的硬件路径：SysTick ISR（或 FromISR API）置位 PendSV →
所有中断退完 → PendSV 换现场（[ch20.01](../../../01-stm32/book-notes/20-towards-freertos/20.01-任务与调度的硬件落点.md)）。
**最坏抢占延迟 ≈ 一次临界区或一段关中断时间**，这是 RTOS 实时性的命门指标。

`configUSE_PREEMPTION = 0` 是协作式：任务不主动让（阻塞/yield）就一直跑。
基本只用于教学对照，工程上没人用。

## 规则二：同优先级轮转（time slicing）

`configUSE_TIME_SLICING = 1`（默认）时，同优先级的 Ready 任务
**每个 tick 轮转一次**：SysTick 到点 → 同优先级还有别人 Ready →
换人。所以同优先级任务看到的 CPU 是"每人 ~1 tick 的时间片"。

推论：**两个同优先级任务都忙等不阻塞 = 各占一半 CPU**；
想让出得靠阻塞或 `taskYIELD()`。

## 规则三：空闲任务垫底

优先级 0 预留给空闲任务（[3.05](3.05-空闲任务与钩子.md)），
你的任务从 1 开始排。就绪名单是 `pxReadyTasksLists[0..N-1]` 数组，
调度选人 = 从高到低扫数组找第一个非空名单——**选人 O(1)**
（用 `uxTopReadyPriority` 位图 + CLZ 指令加速，Cortex-M3 有 CLZ）。

## 一图总结调度决策

```
每个 tick（或每次解除阻塞）：
   高优先级有人 Ready？ ──是──► 抢！Running 换人
        │否
   当前任务同优先级还有别人 Ready？ ──是（且时间片开）──► 轮转
        │否
   继续跑
```

## 与 LDD- 侧对照

| | Linux CFS | FreeRTOS |
|---|---|---|
| 调度单位 | vruntime 最小者优先 | 静态优先级最高者优先 |
| 公平性 | 追求公平（按权重分配 CPU） | **不追求公平**——低优先级可以被永远饿死 |
| 抢占延迟 | 较长（吞吐优先） | 极短（实时优先） |
| 时间片 | 动态 | 固定 1 tick（且仅同优先级轮转用） |

**设计哲学差异要刻进脑子**：FreeRTOS 不承诺"每个任务都有机会跑"——
高优先级任务永不阻塞，低优先级就**永远饿死**。这不是 bug，是实时系统的取舍。
优先级分配是设计问题，不是内核问题。

## 要点回顾

1. 任务优先级数字大=高，与 NVIC 中断优先级方向相反，写配置时别串。
2. 抢占式 = 高优先级就绪立即换人；同优先级每 tick 轮转。
3. RTOS 不保证公平：高优先级不阻塞 → 低优先级饿死，优先级分配是设计职责。

<details>
<summary>Q1：configMAX_PRIORITIES 设多大合适？</summary>

够用就好，两个原因：① 就绪名单数组按它开内存，每级一个链表头；
② 用位图加速时它不能超过 32。
F103 学习工程取 **5~7** 足够（空闲 0、应用 1~4、守护任务按配置定）。
优先级多了反而是设计没想清楚的味道。

</details>

<details>
<summary>Q2：同一优先级能建多少个任务？</summary>

没硬上限（heap 够就行）。就绪名单每一级是个链表，同级任务挂同一条链，
轮转就是沿链表走一圈。所以"同级 N 任务"的开销只是轮转时多走几步链表。

</details>
