# ch08 · 事件组 —— 章节导航

> 书第 8 章 · 对应实验：后续追加（骨架未建）
> 章导航：本篇

## 本章讲什么

**事件组 = 一个 24 位的"事件标志字"，任务可以按"任意位置位"（OR）或
"全部置位"（AND）两种条件阻塞等待。**它解决的是"一个任务要等好几件事
都发生/任意发生"的场景——用 N 个信号量做不到，用一个队列语义不对。

## 只看这一页（速览）

**主线一句话**：一个任务要按位等"多件事任一/全部"怎么办？8.1 讲事件组这个 24 位标志字和 WaitBits 的 AND/OR 语义，8.2 升级到多任务互相等的会合点（Sync），8.3 泼冷水摆局限并给选型对照表。

| 小节 | 一句话结论 |
|---|---|
| 8.1 事件位与 WaitBits | 事件组 = 一个字里的 8/24 个自定义标志位；SetBits 是广播，WaitBits 四参数定 AND/OR 与退出清位，FromISR 经守护任务中转有 tick 级延迟。 |
| 8.2 xEventGroupSync 会合点 | 手写"SetBits + WaitBits"两步有原子性漏洞，Sync 把"置我的位 + 等全员的位"焊成一步，最后到达者清位并放行全员。 |
| 8.3 事件组的局限 | 位匿名无所有权、广播会重复消费或清位饿死、24 位封顶且不能跨组等；口诀：数据→队列、次数→信号量、一人一事→任务通知、多人多事→事件组。 |

**本章最容易踩的坑**：

- 用"各自 SetBits 再 WaitBits"手搓会合点，两次调用之间留有竞态窗口（8.2）。
- 多个任务等同一位但 ClearOnExit 策略不统一：先醒的清了位，后醒的白等（8.1/8.3）。
- 以为 `xEventGroupSetBitsFromISR` 立即生效——实际是定时器守护任务代办，强实时链路别用它（8.1/8.3）。
- Sync 参与者位号重复、或有人中途退出，all_bits 永远凑不齐，会合点直接失效（8.2）。

## API 速查卡

| API / 命令 | 一句话作用 | 易错点 |
|---|---|---|
| `xEventGroupCreate` | 创建一个事件组（一个整数当布告栏） | 32 位 tick 只有 24 位可用，高 8 位被内核征用 |
| `xEventGroupSetBits` | 置位（可一次多位），广播唤醒所有等待者 | 不是"救一个"，是唤醒全部满足条件的任务 |
| `xEventGroupClearBits` | 清位 | 不查户口，谁都能清，误清没人拦 |
| `xEventGroupSetBitsFromISR` | ISR 里置位 | 经定时器守护任务中转，有 tick 级延迟，强实时别用 |
| `xEventGroupWaitBits` | 按 AND/OR 等一组位，可配退出清位 | 返回值是快照不是"哪几位满足"，要自己按位与 |
| `xEventGroupSync` | 会合点：置我的位 + 等全员位，原子完成 | 位号不能重复；参与者中途退出全组卡死；超时返回要按位判定 |
