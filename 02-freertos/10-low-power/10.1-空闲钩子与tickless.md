# 10.1 空闲钩子睡法（简单版）vs tickless idle（正式版）

## 这一篇讲什么

所有任务都阻塞时，CPU 上只剩空闲任务在跑（见
[3.5 空闲任务与钩子](../03-task-management/3.5-空闲任务与钩子.md)）。
电池设备上，这段"空转"时间应该拿来睡觉。本章两条路：
**空闲钩子里手动 WFI（简单版）** 和 **tickless idle（正式版）**。
本篇先讲简单版的做法与天花板，再说正式版要解决的问题。

## 先用人话说一遍（新手铺垫）

所有任务都在等事情的时候，CPU 并没有停——空闲任务在那里
空转，一圈一圈地跑，电就这么白白流掉。电池设备上，这段
垃圾时间应该拿来睡觉。问题只剩一个：**怎么睡才能不被自己人
吵醒。**

画面：夜班保安没巡逻任务时打盹。简单版就是他设了个每 1 分钟
响一次的查岗闹钟（SysTick 心跳）——刚闭眼就被自己的闹钟闹醒，
确认没事再睡，一晚上醒 3600 次，等于没睡。正式版（tickless）
是他先翻日程表：下一个预约送货在 3 小时后？那直接把闹钟定到
3 小时后，中间查岗闹钟全停，一觉睡透。醒来后干一件事：
把值班日志按"实际睡了几小时"补记上（补 tick），
后面的人看日志完全察觉不到他睡过。

映射：保安 = 空闲任务，打盹 = WFI，查岗闹钟 = 周期 tick 中断，
日程表上最近的预约 = 内核定时名单里最近的到期时刻。
本篇就讲这两种睡法的差别和各自代价。

| 术语 | 一句话解释 |
|---|---|
| `__WFI()` | Cortex-M 指令"Wait For Interrupt"：CPU 睡到下一个中断到来为止 |
| 空闲钩子 | `vApplicationIdleHook`：空闲任务每圈循环都会调用的用户函数，往里塞省电代码 |
| tickless idle | 正式省电方案：睡眠期间停掉周期 tick，一次性睡到下一个到期事件 |
| 唤醒源 | 能把睡着的 CPU 叫醒的中断/定时器，如外部引脚、RTC 闹钟 |
| port 层 | FreeRTOS 里和具体芯片架构相关的适配代码（Cortex-M port 等） |
| 弱符号 | 链接器概念：库里给的默认实现可以被你的同名实现覆盖，官方 tickless 参考实现就是这样留的口子 |

## 简单版：空闲钩子里 WFI

```c
/* FreeRTOSConfig.h: configUSE_IDLE_HOOK 置 1 */
void vApplicationIdleHook( void )
{
    __WFI();   /* Wait For Interrupt：睡到下一个中断 */
}
```

空闲任务每次循环都执行一条 WFI，CPU 时钟停振，任何中断都能叫醒。
改动极小，立刻见效。

**但它的天花板很明显**：SysTick（Cortex-M 内置的倒计时定时器，FreeRTOS 用它产生周期性 tick 中断当系统心跳）心跳还在走。
`configTICK_RATE_HZ = 1000` 时，**每 1ms 就来一次 tick 中断**，
CPU 刚睡下去就被自己的心跳叫醒——

```
时间轴（1ms tick）:
|睡|醒(tick)|睡|醒(tick)|睡|醒(tick)| ...  ← 每次"睡"不足 1ms
```

睡-醒切换本身也耗电（时钟稳定、上下文进出），
1ms 粒度下省电效果大打折扣。对电池设备，
"每小时被闹钟叫醒 360 万次"就是灾难。

## 正式版：tickless idle 的思路

问题根源：tick 中断是**周期性**的，但下一个"真正有事"的时刻
往往很远。tickless 的思路一句话：

> **既然算出未来 N 个 tick 都没事干，就把周期 tick 停掉，
> 把唤醒源一次性编程到 N tick 之后，连续睡 N tick。**

```
tickless 时间轴:
|←──────── 连续睡 N tick ────────→|醒(定时事件到点)
        中间没有周期性唤醒
```

前提：内核知道"下一个定时事件在 N tick 后"——
这信息内核本来就有（各任务的阻塞超时、软件定时器（内核管理的定时器：到点后在守护任务里执行你注册的回调函数）的到期时间
都挂在定时名单上），空闲任务跑起来时取最近的一个到期时刻即可。

## 两种睡法对照

| | 空闲钩子 + WFI | tickless idle |
|---|---|---|
| 改动量 | 一个钩子函数 | 开 config + port 层支持 |
| 单次睡眠上限 | < 1 个 tick | N 个 tick（N 可达数千） |
| 周期 tick | 照走，照样打断睡眠 | 睡眠期间停掉 |
| 醒后 tick 计数 | 天然正确（每次 tick 都醒过） | 要**补偿**（vTaskStepTick，下篇讲） |
| 适用 | 插电设备顺手省电 | 电池设备的正式方案 |

## 开启条件

```c
/* FreeRTOSConfig.h */
#define configUSE_TICKLESS_IDLE    1
```

开了之后，空闲任务的决策权交给 port 层的
`portSUPPRESS_TICKS_AND_SLEEP()` 宏：内核在空闲时调用它，
由它完成"算睡眠时长 → 停 tick → 睡 → 醒后补 tick"全流程。
Cortex-M 官方 port 自带参考实现（弱符号，可覆写），
F103 上可以直接用或改造成睡 Stop 模式——
具体分两步在下两篇拆。

## 要点回顾

1. 空闲钩子 + WFI 是最小省电改动，但被周期 tick 切成碎觉。
2. tickless 的核心：预知空闲 N tick → 停 tick → 一次性睡 N tick。
3. 开关是 `configUSE_TICKLESS_IDLE`，干活的是 `portSUPPRESS_TICKS_AND_SLEEP`。

<details>
<summary>Q1：空闲钩子里只写 WFI，有副作用吗？</summary>

注意两点：一是钩子函数**不能阻塞**（空闲任务被挂起会导致
"已删除任务的 TCB 没人回收"等内务停摆）；二是 WFI 之后
CPU 醒来的第一个中断可能就是 tick——省电收益小但无害，
插电设备上可以无脑开。

</details>

<details>
<summary>Q2：tick 停了，vTaskDelay 还准吗？</summary>

准——这正是"醒后补 tick"存在的意义。醒来时内核根据
"实际睡了多久"把 tick 计数一次性补齐，被延时阻塞的任务
看到的逻辑时间和没睡一样。补不准的场景（非定时唤醒）
下篇讲 vTaskStepTick 时细说。

</details>

## 坑点速查

| 坑点 | 书 / 常识怎么说 | 实际是什么 |
|---|---|---|
| 空闲钩子里塞个 `__WFI()` 就完成省电改造 | 钩子里 WFI = 最小省电改动 | SysTick 心跳照走，每 1ms 把自己叫醒一次，单次睡眠不足 1 tick，省电大打折扣 |
| 空闲钩子跟普通函数一样，想写啥写啥 | 钩子就是塞省电代码的地方 | 钩子**绝不能阻塞**——空闲任务被挂起，已删除任务的 TCB 没人回收，内务停摆（Q1） |
| tick 停了，`vTaskDelay` 就乱了 | 系统心跳没了时间肯定不准 | 醒后按实际睡眠时长补 tick，逻辑时间严丝合缝（Q2） |
| 插电设备不值得开 WFI 钩子 | 省电是电池设备的事 | 收益小但无害，插电设备可以无脑开（Q1） |

## 代码自测

_注：本节代码按 FreeRTOS API 语义编写，未在本仓库环境实跑，上板验证见「验证路径」。_

```c
/* FreeRTOSConfig.h: configUSE_IDLE_HOOK 置 1 */
static volatile uint32_t ulIdleWakeups = 0;

void vApplicationIdleHook( void )
{
    ulIdleWakeups++;     /* 空闲任务每醒一圈记一次 */
    __WFI();             /* 睡到下一个中断 */
}

void vReportTask( void *pv )
{
    ( void ) pv;
    for( ;; )
    {
        vTaskDelay( pdMS_TO_TICKS( 1000 ) );
        printf( "idle wakeups in 1s: %lu\r\n",
                ( unsigned long ) ulIdleWakeups );
        ulIdleWakeups = 0;
    }
}
```

**预期现象**：
- `configTICK_RATE_HZ = 1000` 时，计数约 1000 次/秒——几乎全被 tick 心跳叫醒。
- 业务事件极少时计数也不掉，说明醒的全是"自己人的闹钟"。
- 打开 `configUSE_TICKLESS_IDLE` 后计数骤降（10.2 的内容）。
- 钩子不执行：先查 `configUSE_IDLE_HOOK` 是否置 1。

**验证路径**：F103 实机 + USART printf，对比开/关 tickless 两种固件的 1 秒唤醒计数。

**常见翻车点**：
- 钩子里顺手 printf——钩子在空闲任务里，高频触发 + printf 毫秒级耗时，直接拖垮系统。
- 在钩子里调了会阻塞的 API，空闲任务挂起，内核内务停摆。
- printf 任务栈只给 128 字，带 `%lu` 格式化直接爆栈。
