## 这一篇讲什么

`xTaskCreate` 最后一个参数吐出的**任务句柄**（TaskHandle_t）
是之后管理这个任务的全部钥匙：删它、挂它、改它优先级都靠句柄。
这一篇把三件套讲完，顺手解决"删自己"和"删别人"的路径差异。

## 句柄是什么

```c
TaskHandle_t xLedTaskHandle = NULL;
xTaskCreate( vLedTask, "LED", 128, NULL, 2, &xLedTaskHandle );
```

句柄本质是指向 TCB 的指针（不透明类型）。
**想要以后管它就存下来，不想管就传 NULL**——
01-hello-task 里两个 LED 任务建完就各跑各的，传 NULL 即可。

## 三件套 API

| API | 干什么 | 传 NULL 的含义 |
|---|---|---|
| `vTaskDelete(h)` | 删除任务（TCB+栈由空闲任务回收，见 [3.5](3.5-空闲任务与钩子.md)） | **删自己** |
| `vTaskSuspend(h)` / `vTaskResume(h)` | 挂起 / 恢复（进/出 Suspended 态） | 挂自己（恢复自己没意义——挂着的任务跑不到这行） |
| `uxTaskPriorityGet(h)` / `vTaskPrioritySet(h, n)` | 读 / 改优先级 | 读/改自己 |

## 删自己 vs 删别人：路径差异

```
删别人：vTaskDelete(h)
   → h 立刻从 Ready/Blocked 名单摘除，挂入"待删除名单"
   → 内存释放：等空闲任务收尸（heap 有空窗期）

删自己：vTaskDelete(NULL)
   → 同上摘除+挂名单
   → 本行返回后立刻触发一次调度（本任务再也不会被选中）
   → 内存释放：同样等空闲任务收尸
```

两种删法的**内存释放都依赖空闲任务**（[3.5](3.5-空闲任务与钩子.md) 的收尸机制）。
差异只在语义：删别人可以在任意时机调；删自己必须保证
"这行之后本任务不再碰任何已属于它的资源"（尤其是它马上要还的栈）。

## 动态优先级：有用，但请克制

`vTaskPrioritySet(h, 3)` 立即生效：如果被调高的任务比当前任务优先级高，
**立刻抢占**（函数返回前世界就变了）。

合法用途：

- **优先级继承的内部实现**（ch07 互斥量就靠它临时抬优先级）；
- 运行阶段切换模式（如"校准模式"任务在校准期临时提升）。

不合法的用法：把动态优先级当"调度策略"用——
优先级满天飞 = 时序分析做不下去 = 实时性无从谈起。
**静态优先级能表达的设计，不要用动态调整。**

## 一个容易漏的细节：删除不回收"任务自己申请的东西"

`vTaskDelete` 只回收内核给的（TCB + 创建时切的栈）。
任务运行中自己 `pvPortMalloc` 的内存、打开的队列/信号量、
拿到的互斥量——**内核一概不管**。任务自杀前必须自己清理干净，
否则就是教科书级泄漏（外加互斥量永远无人释放的次生灾害）。

## 与 LDD- 侧对照

| | Linux | FreeRTOS |
|---|---|---|
| 句柄 | pthread_t | TaskHandle_t（传 NULL = 自己，类似 pthread_self 语境） |
| 杀线程 | pthread_cancel（危险，同样不回收资源） | vTaskDelete（同样危险，同样不回收资源） |
| 改优先级 | pthread_setschedparam | vTaskPrioritySet |

## 要点回顾

1. 句柄是管理任务的钥匙；不需要管理就传 NULL。
2. 三件套：Delete / Suspend+Resume / PriorityGet+Set；NULL = 自己。
3. 删除只还内核给的（TCB+栈），任务自己拿的资源自己还——且都等空闲任务收尸。

<details>
<summary>Q1：句柄存下来后，任务已经被删了，句柄还能用吗？</summary>

不能——句柄指向的 TCB 已被空闲任务 vPortFree 掉，
再用就是悬垂指针，行为未定义。**规矩：删任务的同时把存句柄的变量清 NULL，
或用事件/通知让"持有方"知道任务已死。**

</details>

<details>
<summary>Q2：vTaskSuspend 正在 Blocked 的任务会怎样？</summary>

叠加态：它既在等事件（Blocked 的账本还在）又被按住。
事件到了它**不会**变 Ready——要先被 Resume 回到 Blocked，再等事件。
所以"挂起一个等队列的任务"不会丢队列数据，但也不会因数据到达而醒。

</details>
