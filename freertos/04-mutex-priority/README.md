# 04-mutex-priority —— 优先级反转与互斥量

> 状态：⬜ 未开始（骨架）。
> 对应笔记：[补充 ch20](../../stm32/book-notes/20-towards-freertos/README.md)（20.3 什么时候该上 RTOS）

> 对照：zephyr/04-mutex-priority（k_mutex + CONFIG_ 配置项对比）

## 目标

- 三任务（高/中/低）复现经典**优先级反转**：低优先级持锁 → 高优先级等锁 → 中优先级抢占低优先级，
  高优先级实际排在最后
- 同一实验跑两遍：**信号量版（反转可见）vs 互斥量版（优先级继承生效）**，差异实测

## 步骤

1. 低优先级任务：take 锁 → 长临界区（串口打标记）→ give
2. 高优先级任务：周期性 take 同一把锁，记录「申请→获得」的延迟
3. 中优先级任务：纯计算空转（不占锁）——它是反转的放大器
4. 版 A 用 `xSemaphoreCreateBinary`，版 B 用 `xSemaphoreCreateMutex`
5. 串口打时间线（tick 戳），把反转窗口量出来

## 验收

- 版 A：高优先级任务延迟 ≫ 临界区长度（被中优先级插队），时间线截图/文本
- 版 B：延迟 ≈ 临界区长度（低优先级被临时提优先级），对照表
- 两版 `.text` / RAM 差异写出来

## 坑点（待记）

- 互斥量的优先级继承**只升一级、随释放归还**——嵌套锁 / 递归锁是另一个坑（`xSemaphoreCreateRecursiveMutex`）
- 「互斥量不能在 ISR 里 take」——继承机制依赖任务上下文
