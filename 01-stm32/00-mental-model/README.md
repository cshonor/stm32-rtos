# 00 地基篇 —— 读全书之前必须先钉住的三件事

> 这一部分**不属于书里任何一章**。书第 1 章直接从"装 GCC"开始，
> 但那之前有三个前提没交代清楚，不钉住的话后面每一章都会缺一块地基。

## 只看这一页（速览）

**主线一句话：** 这三篇补上读书前缺的三块地基——C 标准里根本没有"硬件"（freestanding 只保证一小撮头文件）→ 那硬件到底怎么被碰到（MMIO、`volatile`、位运算三招）→ 工具链只是标准的实现，不是标准本身（clang + ld.lld 实测能全程替代 GCC）。

| 小节 | 一句话结论 |
|---|---|
| [00.1](00.1-没有OS的C语言.md) | 没有 OS 时 C 标准只保证 7 个头文件，`memcpy` 隐式调用和 crt0 初始化（搬 `.data`、清 `.bss`）全要你自己兜 |
| [00.2](00.2-操作硬件的三个手段.md) | C 碰硬件只有三招：地址当寄存器用（MMIO）、`volatile` 防编译器优化、位运算改单个位 |
| [00.3](00.3-没有GCC行不行.md) | 标准管语言不管实现，clang + ld.lld 全程零 GNU 交叉工具链也能编出可烧录镜像 |

**本章最容易踩的坑：**

- `volatile` 只保证访问不被删/合并，不保证原子、不保证顺序，多核/DMA 场景就不够（00.2）
- 只写 `memcpy` 链不上——编译器内部叫的是 `__aeabi_memcpy`，且 `__aeabi_memset(dst, n, c)` 参数顺序与 `memset` 相反（00.1）
- `-fno-builtin` 挡不住结构体整体赋值生成的隐式 `memcpy`（00.1）
- `main` 不是第一个运行的函数，`Reset_Handler` 才是；`main` 返回后无处可退，必须自己兜 `for(;;)`（00.1）
- macOS 自带的 `ld` 是 Mach-O 链接器，交叉链接必须写全 `ld.lld`（00.3）

| 篇 | 标题 | 一句话 |

| 如果不知道 | 后面会在哪里卡住 |

## 一句话版（先记住这三句）

1. **裸机上，"标准库"不是不存在，而是变成了你的活。**
2. **C 碰硬件的三个手段：地址当寄存器用、`volatile` 告诉编译器别优化、位运算改单个位。**
3. **标准管语言，不管实现；`arm-none-eabi-gcc` 只是众多实现之一。**
