# 第 8 章 复杂数据类型 —— 章节导航

> 书：第 8 章 复杂数据类型（原书 p98–118）
> 对应实验：主机侧 clang 23.1.0（布局 / 字节序 / 类型兼容性）+ Cortex-M 交叉
> （`--target=armv7m-none-eabi -mcpu=cortex-m3 -mthumb -ffreestanding`，`offsetof` + `_Static_assert` + 反汇编）

## 这一章在讲什么

在普通 C 书里，这一章是**语法课**：枚举、结构体、联合体、typedef。
在裸机上它是**硬件抽象的地基**——核心只有一句：

> **结构体就是寄存器块的地图。**（[8.12](8.12-结构体与嵌入式编程.md)）

芯片把一组相关的寄存器排在连续地址上（GPIOA 的 CRL/CRH/IDR/ODR/BSRR/BRR/LCKR
依次落在 `0x40010800 + 0x00/04/08/0C/10/14/18`），
而 C 的结构体正好描述"一段连续内存里每个偏移是什么"。
所以你可以把基址转成结构体指针，写 `GPIOA->BSRR` 而不是 `*(volatile uint32_t *)0x40010810`。

**机器码完全一样**（[8.8 实测](8.8-结构体指针.md)），
差别在于结构体写法能用 **编译期断言把偏移钉死**——
把"灯不亮"变成"编译失败，实际 16 你写 20"。

本章的三件工具：**`offsetof` + `_Static_assert`（布局校验）+ 反汇编（代价）+ `-Wpadded`（填充报警）**。

## 只看这一页（速览）

**主线一句话**：本章表面是语法课（枚举、结构体、联合体、typedef），实际每一节都在为同一个成品服务——[8.12](8.12-结构体与嵌入式编程.md) 的"结构体就是寄存器块的地图"：枚举先解决"配置值这种魔数怎么起名"（8.1–8.2）；结构体的布局、填充、对齐决定地图能不能和芯片手册逐字节对上（8.3–8.5）；初始化、赋值、传参告诉你用这张地图各花多少钱（8.6–8.8）；命名规则保证结构体能自引用、能前向声明、能藏实现（8.9、8.13、8.15）；联合体给同一块寄存器三副眼镜（8.10）；typedef 讲清类型别名的陷阱，以及它唯一不可替代的场景——函数指针（8.11、8.14）。

**每小节一句话结论**：

| 小节 | 一句话结论 |
|---|---|
| 8.1 枚举 | 枚举给魔数起名零成本，但底层宽度是实现定义的——只用于代码逻辑值，写进寄存器/协议时显式转定宽类型，寄存器结构体成员绝不能用枚举 |
| 8.2 预处理技巧和枚举 | X 宏一处定义多处展开（枚举和字符串表自动同步），但字符串表占 Flash 要用 `#ifdef` 控制；预处理器不认识枚举，`#if` 里只能用 `#define` |
| 8.3 结构体 | 结构体在裸机上最常见的用途是寄存器块地图：成员全 `volatile`、只用定宽类型，写完立刻用 `_Static_assert(offsetof(...))` 钉死 |
| 8.4 内存中的结构体 | `sizeof(结构体)` ≠ 成员之和（`S1{char,int,char}` 实测 12 字节、6 字节是填充）；成员按对齐值降序排最省，`packed` 省空间但导致未对齐访问 |
| 8.5 访问未对齐数据 | M0/M0+ 上未对齐 32 位访问直接 HardFault，M3 支持但慢且非原子——不确定对齐就用字节拼装或 `memcpy`，顺手把字节序也明确了 |
| 8.6 结构体初始化 | 推荐指定初始化器（`.baud =`）防成员重排静默错位；配置结构体加 `const` 进 Flash 不占 RAM；寄存器结构体绝不整体初始化 |
| 8.7 结构体赋值 | 大结构体赋值会生成 `__aeabi_memcpy` 调用（三档优化实测都有）且非原子，中断下会撕裂读；MMIO 结构体绝不整体赋值 |
| 8.8 结构体指针 | `->` 和裸地址机器码完全相同（三档实测零成本）；64 B 结构体传值栈用量 112 B vs 传指针 4 B——超过 16 字节必须传指针 |
| 8.9 结构命名 | `struct` 的 tag 和 typedef 别名是两个命名空间：没 tag 就不能自引用、不能前向声明；成员完全相同的两个结构体也是不同类型 |
| 8.10 联合体 | 裸机主力用途是同一个 32 位寄存器的三种看法（整字 `w` / 位域 `bits` / 字节 `b[4]`）；位域赋值是读-改-写、非原子，只用于读和描述 |
| 8.11 创建自定义类型 | 类型别名必须用 `typedef`（`#define` 是文本替换，`PCHAR_DEF a, b` 里 `b` 不是指针）；`const str_t p` const 的是指针本身不是数据 |
| 8.12 结构体与嵌入式编程 | 本章题眼：结构体 = 寄存器块的地图，`_Static_assert(offsetof(...))` 把"灯不亮"前移成编译失败；禁 `packed`、每个成员都 `volatile` |
| 8.13 typedef | 数组 typedef 做函数参数会退化成指针（`sizeof` 变指针宽）；typedef 有作用域会被内层遮蔽；函数类型别名不是函数指针类型 |
| 8.14 函数指针与 typedef | typedef 唯一不可替代的场景；向量表、驱动操作表、ISR 回调是裸机三大用途；Cortex-M 手写函数地址必须 `+1`（Thumb 位） |
| 8.15 typedef 和 struct | 默认用 `typedef struct tag {...} name_t;`，要隐藏实现用"头文件 typedef 不完整类型 + `.c` 补全定义"；C 里 `struct` 关键字不能省 |

**本章最容易踩的坑**：

- "结构体大小 = 成员之和"——实测 `S1{char,int,char}` 是 12 字节，一半是对齐填充；成员换个顺序能省 4 字节（8.4）
- 给寄存器结构体加 `packed`：偏移错位 + M0 上未对齐访问 HardFault，而且本来全 `uint32_t` 一个字节也省不下（8.12）
- `volatile` 只写在结构体指针上 ≠ 成员 volatile，等待标志位的循环照样被删成一条 `bx lr`（8.12）
- `-fstack-usage` 报 0 是假象：传大结构体时那 64 字节记在**调用者**的栈上，总成本没消失（8.8）
- `const str_t p` 实际是 `char *const`——const 的是指针，指向的数据照样可写（8.11）

## 与书的差异（重要）

| 书 | 我 |
|---|---|
| 把"对齐/填充"当内存浪费讲 | **在裸机上是功能错误**：偏移错了 `GPIOA->BSRR` 写到别的寄存器（[8.4](8.4-内存中的结构体.md)） |
| 把 `packed` 当中性技巧讲 | **寄存器结构体禁用**：偏移错位 + M0 上未对齐访问 **HardFault**（[8.12 Q3](8.12-结构体与嵌入式编程.md)） |
| 讲"结构体可以整体赋值" | 补上代价：大结构体赋值生成 `__aeabi_memcpy`，且**非原子**（撕裂读）（[8.7](8.7-结构体赋值.md)） |
| 讲"结构体传参" | 实测传值 vs 传指针：64 B 结构体在 `-O0` 下栈用量 **112 B vs 4 B**（28 倍）（[8.8](8.8-结构体指针.md)） |
| 把 `typedef` 当风格问题 | 对**函数指针**而言是唯一可读的写法（[8.14](8.14-函数指针与typedef.md)）；对**指针别名**而言 `#define` 会出错（[8.11](8.11-创建自定义类型.md)） |
| 讲递归/联合体的语法 | 联合体在裸机的主力用途是"同一寄存器的三种看法"（[8.10](8.10-联合体.md)） |
| 讲"函数指针就是地址" | 补上 Cortex-M 的 **Thumb 位**：手写常量要 `+1`（[8.14 Q3](8.14-函数指针与typedef.md)） |

## 核心实测数据（本章的锚点）

```
① 布局（Mac 与 Cortex-M3 同数）
S1{char,int,char}   size=12  off(a)=0 off(b)=4 off(c)=8     ← 6 字节填充
S2{int,char,char}   size=8                                   ← 换个顺序省 4 字节
packed P{char,int}  size=5   off(b)=1                        ← 未对齐
union U{uint32_t,uint8_t[4]}  size=4
u.i=0x12345678 → b[0]=0x78 b[1]=0x56 b[2]=0x34 b[3]=0x12     ← 小端

② -Wpadded
warning: padding struct 'struct S1' with 3 bytes to align 'b'
warning: padding size of 'struct S1' with 3 bytes to alignment boundary

③ 寄存器地图校验（Cortex-M）
_Static_assert(offsetof(GPIO_TypeDef, BSRR) == 0x10)   → 通过
故意写成 0x14 →
  error: static assertion failed ... '16 == 20'

④ -> 零成本（-O0/-Os/-O2 三档一致）
via_arrow / via_deref / via_offset  →  都是 movw/movt/str

⑤ 传参代价（-fstack-usage, -O0）
huge_by_value (64B 结构体)  112 字节  ~40 条指令
huge_by_ptr   (指针)          4 字节   7 条指令

⑥ 函数指针
fp=0x100d1be44 add=0x100d1be44   fp(3,4)=7    改指向 sub → -1
-O0: blx r2（间接）   -Os: bx r3（尾调用）
直接调用 -Os 被内联成一条 add r0,r1

⑦ typedef 陷阱
#define PCHAR_DEF char *  →  sizeof(a)=8 sizeof(b)=1      ← b 不是指针
typedef char *pchar_t     →  sizeof(c)=8 sizeof(d)=8
const str_t p             →  编译器诊断：aka 'char *const'（const 的是指针）
```
