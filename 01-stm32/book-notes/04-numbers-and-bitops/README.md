# 第 4 章 数字和变量 —— 章节导航

> 书：第 4 章 数字和变量（原书 p44–64）
> 对应实验：`01-stm32/03-gpio-blink/`（真机）+ 主机交叉编译
> `--target=armv7m-none-eabi -mcpu=cortex-m3`（本篇所有反汇编都来自这套命令）

## 这一章在讲什么

**表面是 C 基础（整数、变量、赋值、初始化、溢出、补码），实际只有一件事是裸机独有的：
4.12「用位操作控制内存映射 I/O 寄存器」。**

前面那些小节（整数大小、数字表示、溢出、补码）在任何一本 C 书里都有。
它们在裸机上的分量之所以不一样，是因为**后果不同**：

- PC 上整数溢出 → 得到一个错的值，程序继续跑；
- 裸机上整数溢出 → 算出来的**寄存器地址或位掩码是错的**，写到了别的寄存器上，
  而且**没有任何报错**。

所以本章的读法是：4.1–4.11 快速过（挑"宽度"和"溢出"两节精读），
**4.12 必须精读**——它是后面所有外设操作的基本功。

## 只看这一页（速览）

这一章解决"整数在裸机上怎么写才不会静默出错"：同一套 C 整数语法，
在裸机上因为**出错无报错、且错值往往就是寄存器地址或位掩码**而变得致命。
读法：4.1–4.11 快速过（宽度与溢出精读），4.12 是全章的落点。

| 小节 | 一句话结论 |
|---|---|
| 4.1 使用整数 | 裸机上整数有**数量 / 地址 / 位模式**三种角色，写错角色不报错只静默改错硬件；前导 0 是八进制（`064` = 52），位操作必须带 `u` 后缀 |
| 4.2 声明变量 | 声明决定段归属：带初值全局进 `.data`（占 Flash + RAM 两份），无初值进 `.bss` 只占 RAM；1 KB 大缓冲必须 `static`，否则爆栈 |
| 4.3 赋值 | 写 MMIO 寄存器的 `=` 是给硬件下命令，必须 `volatile`（实测两次 `str` 都保留）；左边窄就静默截断；读-改-写是 3 条指令，可被中断打断 |
| 4.4 初始化 | 全局变量默认 0 是启动代码清的 `.bss`，不是语言保证；写 `= 0` 反而更贵（挪进 `.data`）；局部变量才是真垃圾（栈残留） |
| 4.5 整数的大小和表示 | `long` 宽度平台相关（实测 Mac 8 / Cortex-M 4），裸机不能跑程序验证，用 `_Static_assert` 把宽度钉死在编译期 |
| 4.6 数字表示 | 手册是十六进制 + 位号写的，代码用同一种语言（`(1u << n)`）；同一串位模式按有/无符号读是两个数，右移语义直接不同 |
| 4.7 标准整数 | `uint32_t` 这类定宽类型是编译器自带头，`-ffreestanding` 实测可用；寄存器值/地址/掩码/协议字段一律定宽 + `u` 后缀 |
| 4.8 无符号整数类型 | unsigned 溢出是**定义好的回绕**（UBSan 只报 signed 那行），环形缓冲靠它无锁工作；但倒计时 `i >= 0` 恒真是死循环 |
| 4.9 溢出 | unsigned 回绕是规定，signed 溢出是 UB——实测 `f(INT_MAX)` 在 `-O0`/`-O2` 跑出两个答案；裸机没有 UBSan，UB 静默变成错值 |
| 4.10 有符号整数的补码表示 | `-1` 是全 1（取反加一）；符号位在哪一位由**数据宽度**决定（12 位 ADC 的符号位在 bit 11）；`abs(INT_MIN)` 是 UB，先扩宽再取负 |
| 4.11 缩写运算符 | `reg \|= BIT(n)` 就是读-改-写（实测 1 行 C = 3 条指令），中断下丢别人的修改；`++i` 与 `i++` 机器码实测相同 |
| 4.12 用位操作控制 MMIO 寄存器 | 寄存器是**位打包**的，改位域必须先 `&= ~` 清再 `\|=` 置；有"写 1 生效"的影子寄存器（`BSRR`）就用普通赋值，物理上免疫竞态 |

**本章最容易踩的坑**：

- 位号手滑多打一个前导 0：`064` 是八进制的 52，`1u << 064` 静默移出界，引脚没开且无报错（4.1）
- 位操作字面量忘带 `u` 后缀：`1 << 31` 是 UB，`1u << 31` 才是定义良好的 `0x80000000`（4.1 / 4.11）
- 全局变量写 `= 0`"更规范"：反而把它从 `.bss` 挪进 `.data`，白占一份 Flash 镜像和一次拷贝（4.4）
- 以为 signed 溢出"就是回绕"：标准不保证——`-O2` 下编译器可据 UB 删掉你的边界检查，换优化等级就变脸（4.9）
- `GPIOA_CRL = 0x00100000` 整寄存器赋值：一个寄存器管 8 个引脚，另外 7 个引脚的配置被全部清掉（4.12）

## 与书的差异（重要）

| 书 | 我 |
|---|---|
| 举 PC 上的算术例子 | 每个结论都配**实测**：主机 `clang -O2` + Cortex-M 交叉反汇编 |
| 用 `int` / `unsigned int` 举例 | 全程 `uint32_t` / `uint8_t`（实测 `long` 在 Mac 是 8、Cortex-M 是 4） |
| 说"溢出会得到错的值" | 分成两种：unsigned 是**定义好的回绕**，signed 是 **UB**——实测 `-O0` 和 `-O2` 跑出**不同结果** |
| 讲"位操作怎么算掩码" | 补上**为什么**：寄存器是位打包的；以及同样一句 C 生成几条指令（实测 6 条 vs 1 条 `str`） |
| 只讲 `\|= / &= ~ / ^=` | 补上"写 1 生效"的 `BSRR` 才是硬件给的正解（实测：无 `ldr`，物理上免疫竞态） |

## 读完本章你应该能回答

- 为什么裸机代码里几乎见不到 `int` 和 `long`？（`long` 跨平台宽度不同，实测断言）
- unsigned 溢出和 signed 溢出差在哪？为什么 `-O0` / `-O2` 会跑出不同答案？
- 全局变量为什么"默认是 0"？谁清的？启动文件没写对会怎样？
- 为什么 `int x = 0;` 在裸机上比 `int x;` 更贵？
- `reg |= BIT(5)` 生成几条指令？什么情况下会被中断打断并丢修改？
- 什么时候该用 `BSRR`（普通赋值）而不是 `|=`？
- 为什么配置引脚必须先 `&= ~` 再 `|=`，不能一步写？
