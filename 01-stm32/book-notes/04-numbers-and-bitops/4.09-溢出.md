# 4.09 溢出

> 书：第 4 章 数字和变量 · 4.09 溢出（原书 p44–64 区间内）
> 上一篇：[4.08 无符号整数类型](4.08-无符号整数类型.md) ｜ 下一篇：[4.10 有符号整数的补码表示](4.10-有符号整数的补码表示.md)
> 对应实验：主机侧 clang 23.1.0（`-O0` / `-O2` / `-fsanitize=undefined` 对比）

## 书这一节讲什么

一句话：**算出来的数超出类型能表示的范围，就叫溢出**，结果不对。

书把它当成一个"要注意的坑"。实测之后你会发现它分成两种性质完全不同的东西：
**unsigned 溢出是规定好的回绕，signed 溢出是未定义行为（UB）**——
后者在 `-O2` 下会让编译器做出你完全没写过的优化。

## 一、实测：signed 溢出是 UB，编译器**有权**假定它不发生

```c
/* assume.c */
int f(int x){ if (x + 1 > x) return 1; return 0; }
int main(void){ printf("f(INT_MAX) = %d\n", f(INT_MAX)); }
```

```
$ clang -O0 -o a0 assume.c && ./a0
f(INT_MAX) = 0          ← 按补码回绕，INT_MAX+1 = INT_MIN，所以不 > x

$ clang -O2 -o a2 assume.c && ./a2
f(INT_MAX) = 1          ← 同一个程序，同一个输入，答案变了！
```

看生成的代码就一目了然：

```
$ clang -O2 -S -o - assume.c | grep -A4 '_f:'
_f:
	mov	w0, #1      ← 直接返回 1，连加法都没算
	ret
```

**`-O2` 把整个判断删了。** 因为编译器可以假定 `x + 1` 不溢出，
那么 `x + 1 > x` 恒真 → 直接返回 1。这不是 bug，是标准允许的。

## 二、UBSan 能抓到，但裸机上没有 UBSan

```
$ clang -O2 -fsanitize=undefined -o ovf_ub ovf.c && ./ovf_ub
ovf.c:5:69: runtime error: signed integer overflow: 2147483647 + 1 cannot be represented in type 'int'
SUMMARY: UndefinedBehaviorSanitizer: undefined-behavior ovf.c:5:69
unsigned: UINT_MAX+1 = 0
signed  : INT_MAX+1  = -2147483648
```

注意 UBSan **只报 signed 那一行**——unsigned 的回绕不是错误：

```
$ clang -O2 -o ovf ovf.c && ./ovf
unsigned: UINT_MAX+1 = 0          ← 定义良好，模 2^32
signed  : INT_MAX+1  = -2147483648 ← UB，这次碰巧是回绕
```

**这是本节最重要的一条**：主机上你有 UBSan、ASan 可以抓；
**裸机上什么都没有**——UB 就静默地变成一个错的值。
而那个错的值往往是**寄存器地址或位掩码**，于是"溢出"变成"改错了硬件"。

## 三、裸机上溢出的三种典型发作

| 场景 | 代码 | 后果 |
|---|---|---|
| 位号移出界 | `1u << n`，`n >= 32` | UB，结果通常 0 → 该开的时钟没开，外设不工作 |
| 延时计数溢出 | `uint16_t i` 数到 70000 | 回绕 → 延时变成瞬间，时序全乱 |
| 时间戳比较 | `if (now > timeout)` 在回绕点 | 误判 → 超时逻辑失效（用差值比较修） |

## 四、怎么防（裸机可执行的手段）

1. **默认用 unsigned**：溢出行为确定（[4.08](4.08-无符号整数类型.md)）；
2. **边界先判后加**：`if (n < UINT32_MAX) n++;` 而不是加了再检查；
3. **差值比较代替绝对值比较**：`if ((uint32_t)(now - last) > TIMEOUT)`——回绕下依然正确；
4. **主机侧跑 UBSan**：把纯逻辑（协议解析、算法）在 Mac 上用
   `-fsanitize=undefined` 跑一遍，实测能抓到 signed 溢出；
5. **编译期断言钉死常量**：`_Static_assert(DELAY_MAX < UINT16_MAX, "")`。

## 坑点（书 / 常识怎么说 / 实际是什么）

| 书 / 常识怎么说 | 实际是什么 |
|---|---|
| "溢出会得到错误的值" | 分两种：unsigned 是**定义好的回绕**，signed 是 **UB**。UB 下编译器可以做任何事 |
| "代码逻辑对，结果就对" | 实测：`f(INT_MAX)` 在 `-O0` 是 0、`-O2` 是 1，同一个程序两种答案 |
| "溢出回绕是硬件行为" | 是硬件行为，但 **signed 的回绕不被标准保证**——编译器可以假定它不发生并据此优化 |
| "加个 `if` 检查就行" | 检查要在**运算之前**：`x + 1 > 0` 这种"先算再查"的写法，在 `-O2` 下会被删掉 |
| "裸机上跑一遍没出错就没问题" | 裸机上 UB 是静默的错值，且依赖优化等级和链接布局——换个 `-O` 就变 |

## 代码自测

<details>
<summary>Q1：为什么 `-O0` 和 `-O2` 跑出不同结果？这不是编译器 bug 吗？</summary>

不是 bug，是 **UB 的直接后果**。

C 标准说 signed 整数溢出是未定义行为，意思是：**编译器可以假定它永远不发生**。
有了这个假定，`x + 1 > x` 就变成一个恒真式——因为"x+1 不溢出"的前提下，
x+1 一定大于 x。于是 `-O2` 直接把判断优化掉，生成 `mov w0, #1; ret`（实测）。

`-O0` 不做这类优化，规规矩矩算 `add w8, w8, #1`，
于是按补码回绕得到 `INT_MIN`，比较为假，返回 0。

这告诉我们一件事：**UB 不是"结果不确定"，是"编译器可以据此做任何优化"**。
在主机上它可能只是算错；在裸机上，同样的优化可能删掉你的边界检查、
删掉你的空指针判断——而且**只在你打开优化之后才发生**。

所以裸机的纪律是：**不要依赖 UB，哪怕它现在能跑**。
用 unsigned、先判后算、在主机侧用 UBSan 验证纯逻辑。
</details>

<details>
<summary>Q2：裸机上没有 UBSan，怎么提前发现溢出？</summary>

三层防线，从便宜到贵：

**① 类型层面（零成本）**：能 unsigned 就 unsigned。
unsigned 的溢出是被定义好的，不会触发编译器的"假定不溢出"优化。

**② 编译期（零成本）**：用 `_Static_assert` 钉死常量边界——

```c
#define DELAY_CYCLES 800000u
_Static_assert(DELAY_CYCLES < UINT32_MAX, "delay too large");
#define RB_SIZE 64
_Static_assert((RB_SIZE & (RB_SIZE - 1)) == 0, "RB_SIZE must be power of 2");
```

第二条尤其有用：环形缓冲用 `& (SIZE-1)` 代替取模的前提是 SIZE 是 2 的幂，
写错就是错的——编译期炸比运行期错好一万倍。

**③ 主机侧运行时（有成本但值得）**：把不依赖硬件的逻辑（协议解析、滤波、
状态机、缓冲管理）单独编译到 Mac 上跑 `-fsanitize=undefined,address`。
实测 UBSan 能精确报出 `signed integer overflow: 2147483647 + 1` 这种问题，
比在板子上猜快得多。

一句话：**能把逻辑挪到主机上验证的，就不要等到板子上再查。**
裸机调试的每一次迭代都要烧录、复位、接探针，成本高一个数量级。
</details>

<details>
<summary>Q3：`1u << n`，n 从变量来，怎么保证不越界？</summary>

先明确规则：**移位位数 ≥ 类型位宽就是 UB**（不管 signed 还是 unsigned）。
`1u << 32` 对 `uint32_t` 是 UB，不是"得到 0"。

三种可靠写法：

```c
/* ① 位号是编译期常量 —— 最安全，用断言钉死 */
#define BIT(n) (1u << (n))
_Static_assert(PIN_NO < 32, "pin number out of range");
RCC_APB2ENR |= BIT(2);

/* ② 位号是运行时变量 —— 先判后移 */
uint32_t mask(uint32_t n){ return (n < 32u) ? (1u << n) : 0u; }

/* ③ 用 for 循环扫描位号时，循环边界本身就是检查 */
for (uint32_t b = 0; b < 32u; b++) if (val & (1u << b)) { ... }
```

裸机上最常见的是第 ① 种——引脚号、外设位号全是编译期常量，
所以**把位号写成宏/枚举 + `_Static_assert` 检查范围**，就能把这一类 UB 彻底堵死。

反例是"从配置表里读位号"：这种运行时位号必须走第 ② 种，
否则一张写错的配置表就能让程序静默失效。
</details>
