# 14.03 读数据

> 书：第 14 章 缓冲文件 I/O · 14.03 读数据（原书 p202–211 区间内）
> 上一篇：[14.02 ASCII 表](14.02-ASCII表.md) ｜ 下一篇：[14.04 打开文件](14.04-打开文件.md)
> 对应实验：主机侧实测（clang 23.1.0 / macOS arm64）

## 书这一节讲什么

一句话：**`scanf` / `fgets` / `fread`——三种读法，各有各的坑。**

书上讲 `scanf` 的格式串。本篇把重点放在**实测出来的行为差异**上，
因为这三者的选择直接决定了你的程序**会不会被输入搞崩**。

## 一、三种读法的定位

| 函数 | 读什么 | 用途 | 危险度 |
|---|---|---|---|
| **`scanf` / `fscanf`** | **格式化**输入（把文本解析成整数/浮点） | 配置文件、命令行参数 | ⚠ **高** |
| **`fgets`** | **一行**（保留 `\n`） | 读文本行 | ✅ 低（有长度限制） |
| **`fread`** | **原始字节** | 二进制数据 | ✅ 低 |

## 二、`scanf` 的三个坑（都有实测）

### 2.1 坑①：`%s` 没有长度限制 = 缓冲区溢出

```c
char buf[8];
scanf("%s", buf);          /* ⚠ 输入 20 个字符就写越界 */
scanf("%7s", buf);         /* ✅ 限制最多读 7 个（+ '\0'） */
```

**实测（用 `sscanf` 演示定长读取）**：

```
① sscanf("%7s") 读入 1 项，buf="1234567"（长度 7）
```

输入是 `"1234567890123456"`（16 字符），`%7s` 只读了 **7 个**，
`buf[8]` 装得下 `1234567` + `'\0'`。

⚠ **不写宽度的 `%s` 和 `gets()` 一样危险**。
`gets()` 已经在 C11 里被**移除**了，理由就是无法限制长度。

**裸机上的对应**：
从 UART 收命令时，如果直接往定长缓冲里塞，
超长命令会踩掉相邻变量——
[ch10](../10-interrupts/README.md) 的环形缓冲正是为了把这个边界管住。

### 2.2 坑②：**返回值必须检查**

```c
int a, b;
int n = sscanf("42 abc", "%d %d", &a, &b);
```

**实测**：

```
② sscanf("42 abc","%d %d") 返回 1（只成功匹配了 1 项，b 未初始化）
```

⚠ **`b` 没有被赋值**——`sscanf` 返回 **1**（成功匹配的项数），
不是 2。如果你不检查返回值就用 `b`，读的是**未初始化的内存**。

**规则**：

```c
if (scanf("%d %d", &a, &b) != 2) { /* 输入不合法，别用 a/b */ }
```

| 返回值 | 含义 |
|---|---|
| `n`（> 0） | 成功**赋值**的项数 |
| `0` | 一个都没匹配上（输入不合法） |
| `EOF`(-1) | **到达文件尾**或读错误 |

⚠ **`0` 和 `EOF` 是两回事**：
`0` 表示"有输入但格式不对"（而且**输入还在那儿，没被消耗**），
`EOF` 表示"没输入了"。
**用 `scanf` 做循环时，返回 0 会造成死循环**——
因为那个不匹配的内容一直留在输入缓冲区里。

### 2.3 坑③：空白字符的处理（比想象的宽松）

**实测**：

```
③ sscanf("10\n20","%d\n%d") 返回 2，a=10 b=20
```

**规则**：

- 格式串里的**任意空白**（空格、`\n`、`\t`）都匹配"**任意多个空白字符，包括零个**"；
- `%d`、`%f`、`%s` 等**会自动跳过前导空白**；
- 只有 `%c`、`%[` 和（部分）`%[...]` **不跳过**。

⚠ **所以 `"%d\n%d"` 里的 `\n` 是多余的**——
`%d` 本来就会跳过空白。写 `\n` 反而有个**副作用**：

```
scanf("%d\n", &x);       /* ⚠ 输入 "42" 后回车，scanf 不返回！ */
```

因为格式串末尾的 `\n` 要"匹配任意多个空白"，
它得**读到下一个非空白字符**才知道空白结束了——
**程序会卡在那里等你再输入**。

**这是 `scanf` 最经典的一个"程序卡住"bug。**
规则：**格式串末尾不要留空白**。

## 三、`fgets`：最安全的读行方式

**实测**：

```
④ fgets 读到 "hello\n"（长度 6，含换行符 \n）
```

⚠ **`fgets` 保留换行符**——这是和 `gets()` 最大的区别，
也是很多人第一次用会踩的坑：

```c
char line[32];
fgets(line, sizeof line, f);
/* 输入 "hello\n" → line = "hello\n\0"（6 个字符 + 结束符） */
```

**去掉换行符的标准写法**：

```c
line[strcspn(line, "\n")] = '\0';       /* ✅ 推荐：处理所有情况 */
/* 或者 */
size_t n = strlen(line);
if (n > 0 && line[n-1] == '\n') line[n-1] = '\0';
```

⚠ **别用 `line[strlen(line)-1] = '\0'`**——
如果行里没有 `\n`（文件最后一行没换行），
`strlen-1` 会把**最后一个有效字符**删掉。

**`fgets` 的三个行为细节**：

| 情况 | 行为 |
|---|---|
| 读到换行符 | **停止**，换行符**保留**在缓冲里 |
| 缓冲满了（n−1 个字符） | **停止**，剩下的留在流里（下次读） |
| 到达 EOF 且没读到任何字符 | 返回 **NULL**，缓冲内容**不变** |

⚠ **第三条**：`fgets` 返回 NULL 时，**不要假设缓冲被清空了**。

## 四、`fscanf` vs `fread`：文本解析 vs 原始字节

**实测**（同一个 `int 1000000`，两种存法）：

```
⑤ fscanf("%d") 读 v.txt  → 1000000（文本解析）
   fread(&w,4,1) 读 v.bin → 1000000（原始字节，小端）
```

| | `fscanf("%d")` | `fread(&w, sizeof w, 1, f)` |
|---|---|---|
| 输入 | 文本 `"1000000"`（7 字节） | 原始字节 `40 42 0f 00`（4 字节） |
| 做了什么 | **字符→整数的转换**（`strtol` 那套） | **直接 memcpy** |
| 速度 | 慢（要解析） | 快（一次拷贝） |
| 字节序 | 无关（文本） | ⚠ **依赖双方字节序一致** |
| 模式 | `"r"` | **`"rb"`** |

⚠ **`fread` 读的字节序取决于写的时候**。
`v.bin` 是 `40 42 0f 00`（小端），
**在一台大端机器上 `fread` 出来就不是 1000000**。

详见 [14.05](14.05-二进制IO.md)。

## 五、裸机上的"读数据"：从串口收帧

书上讲的是读文件，但同样的三个坑在串口接收里**一模一样**：

| 文件 I/O | 串口对应 | 同一个坑 |
|---|---|---|
| `scanf("%s")` 溢出 | 往定长命令缓冲里塞 | **没有长度限制** |
| 不检查 `scanf` 返回值 | 不检查帧校验 | **用了未初始化/错误的数据** |
| `scanf` 末尾 `\n` 卡住 | 等帧结束符等到死 | **没有超时** |

**裸机上正确的收帧模式**（[ch10](../10-interrupts/10.04-用缓冲区提速.md) 实测过）：

```c
/* ISR 里：只入队，不做任何解析 */
void USART1_IRQHandler(void){
    if (SR & RXNE) { uint8_t c = DR; rb_put(&g_rx_rb, c); }
}

/* 主循环里：攒够一行再解析 */
void poll_cmd(void){
    static char line[64];
    static size_t len;
    while (!rb_empty(&g_rx_rb)) {
        char c = rb_get(&g_rx_rb);
        if (c == '\n' || len >= sizeof(line) - 1) {     /* ⚠ 长度上限 */
            line[len] = '\0';
            handle_cmd(line);                            /* ⚠ 校验后再用 */
            len = 0;
        } else {
            line[len++] = c;
        }
    }
}
```

**三条和本章一一对应**：

1. `len >= sizeof(line) - 1` ← 对应 `%7s` 的宽度限制；
2. `handle_cmd` 里做校验 ← 对应检查 `scanf` 返回值；
3. **`while (!rb_empty())` 是轮询，不会"卡住"** ← 对应"`scanf` 末尾别留 `\n`"。

## 坑点（书 / 常识怎么说 / 实际是什么）

| 书 / 常识怎么说 | 实测是什么 |
|---|---|
| "`scanf("%s", buf)` 够用" | ⚠ **没有长度限制 = 溢出**。要 `%7s`（实测读了 7 个就停） |
| "`scanf` 返回值不重要" | ⚠ 实测 `sscanf("42 abc","%d %d")` 返回 **1**，`b` **未初始化** |
| "格式串里写 `\n` 匹配换行" | ⚠ 多余且有害：`%d` 本来就跳过空白；**末尾的 `\n` 会让程序卡住**等下一个非空白字符 |
| "`fgets` 和 `gets` 差不多" | ❌ `fgets` **有长度限制**且**保留换行符**（实测读 `"hello\n"` 长度 6） |
| "`fread` 读出来就是那个数" | ⚠ 依赖**字节序**。`40 42 0f 00` 在小端上是 1000000，大端上不是 |
| "读文件不会出错" | 每次读都要检查返回值：返回 0 是"格式不对"（**输入没被消耗，会死循环**），`EOF` 是"没输入了" |

<details>
<summary>Q1：`scanf` 的返回值为什么要检查？返回 0 和 EOF 有什么区别？</summary>

**因为返回值是"成功赋值了几项"，不是"读到了几项"。**

**实测**：

```c
int a, b;
int n = sscanf("42 abc", "%d %d", &a, &b);
```

```
② sscanf("42 abc","%d %d") 返回 1（只成功匹配了 1 项，b 未初始化）
```

`a` 得到了 42，`b` **根本没被写**。
不检查返回值就用 `b` = **读未初始化的内存**。

---

**返回值的三种情况**：

| 返回值 | 含义 | 输入缓冲区状态 |
|---|---|---|
| `n > 0` | 成功**赋值**了 n 项 | 这 n 项被消耗了 |
| **`0`** | 一个都没匹配上（**格式不对**） | ⚠ **没被消耗！** |
| **`EOF`**(-1) | 到达**文件尾**或读错误 | 没了 |

⚠ **`0` 和 `EOF` 的区别是致命的**——因为它决定了**输入会不会被消耗**。

**死循环的经典写法**：

```c
int x;
while (scanf("%d", &x) != EOF) {      /* ⚠ 碰到非数字就死循环 */
    ...
}
```

输入 `abc` 时：

1. `scanf` 返回 **0**（不是 EOF）；
2. `abc` **还留在输入缓冲区里**；
3. 循环继续，`scanf` 又读到 `abc`，又返回 0；
4. **无限循环**。

**正确写法**：

```c
int x;
while (scanf("%d", &x) == 1) {        /* ✅ 只有成功才继续 */
    ...
}
/* 出了循环，要么 EOF，要么格式不对 —— 后者要清掉残余输入 */
```

或者更稳的：**全部用 `fgets` 读行，再用 `sscanf` 解析**：

```c
char line[128];
while (fgets(line, sizeof line, stdin)) {
    int x;
    if (sscanf(line, "%d", &x) == 1) { ... }    /* 解析失败就丢弃这一行 */
}
```

——**`fgets` 一次消耗一整行**，
所以解析失败也不会留下残余，**不可能死循环**。
这是实际工程里的标准做法。

**规则**：

> **`scanf` 的返回值必须和"你期望的项数"比较，不能和 `EOF` 比较。**
> 或者干脆用 `fgets` + `sscanf`，彻底避开这个坑。
</details>

<details>
<summary>Q2：为什么 `scanf("%d\n", &x)` 会卡住？</summary>

**因为格式串里的空白字符要"匹配任意多个空白（包括零个）"，
它必须读到下一个非空白字符才知道空白结束了。**

**先说规则**（[14.03](14.03-读数据.md) 实测过 `"%d\n%d"` 能正常工作）：

> 格式串中的**任意空白**（空格 / `\n` / `\t`）
> 匹配输入中**任意多个空白字符，包括零个**。

所以：

```c
scanf("%d\n%d", &a, &b);     /* 输入 "10\n20" → 实测返回 2，a=10 b=20 ✅ */
```

中间那个 `\n` 匹配了输入里的 `\n`，正常工作。

**但末尾的 `\n` 就出事了**：

```c
scanf("%d\n", &x);           /* ⚠ 输入 "42" 回车后，scanf 不返回 */
```

过程：

1. `%d` 读走 `42`；
2. 格式串还剩 `\n`，它要"匹配任意多个空白"；
3. 输入里现在有 `\n`（你按的回车）——匹配上了；
4. 但"任意多个"意味着**它还要继续看下一个字符是不是空白**；
5. 下一个字符还没来（你还没输入）→ **阻塞等待**；
6. 你必须再输入一个**非空白字符**，`scanf` 才知道"空白结束了"，然后返回。

⚠ **那个"多读的一个非空白字符"会被退回流里**
（ungetc），下次读会拿到它——
所以不只是"卡一下"，还会**干扰后续的输入**。

**实测可以验证**（在终端里）：

```
$ ./prog
42⏎            ← 输入 42 回车
               ← 程序没反应（卡住了）
abc⏎           ← 再输入任意非空白
               ← 这时 scanf 才返回
```

**规则**：

> **格式串末尾不要留空白字符（空格、`\n`、`\t`）。**

```c
scanf("%d", &x);        /* ✅ */
scanf("%d\n", &x);      /* ❌ 会卡 */
scanf("%d ", &x);       /* ❌ 同样会卡（空格也一样） */
```

⚠ **`%c` 前的空格是唯一"故意要留"的例外**：

```c
scanf(" %c", &c);       /* ✅ 这个空格是必要的 */
```

因为**`%c` 不跳过空白**（和 `%d` 不同），
如果前面输入过数字，残留的 `\n` 会被 `%c` 读到。
加个空格让 `scanf` 先把空白吃掉。

**总结三条空白规则**：

| 位置 | 要不要空白 |
|---|---|
| **格式串末尾** | ❌ **不要**（会卡住） |
| **`%c` / `%[...]` 之前** | ✅ **要**（它们不跳过空白） |
| **`%d` / `%f` / `%s` 之前** | 无所谓（它们自动跳过，写了也多余） |

**顺带**：这也是"用 `fgets` + `sscanf` 更省心"的又一个理由——
`fgets` 一次读一整行，**没有"卡在格式串上"这回事**。
</details>

<details>
<summary>Q3：`fgets` 读进来的行为什么带 `\n`？怎么正确处理？</summary>

**因为 `fgets` 的设计就是"把行结束符也读进来"——
这样你才知道"这一行是不是被缓冲大小截断了"。**

**实测**：

```c
char line[32];
fgets(line, sizeof line, f);      /* 文件内容是 "hello\n" */
```

```
④ fgets 读到 "hello\n"（长度 6，含换行符 \n）
```

**`fgets` 停止的三种情况**：

| 情况 | 缓冲内容 | 流里剩下什么 |
|---|---|---|
| 读到 `\n` | 含 `\n` + `'\0'` | 下一行 |
| 读了 `n-1` 个字符（缓冲满） | **不含** `\n` | **本行剩余部分** |
| EOF 且一个字符都没读到 | **不变** | —— |

⚠ **第二条是个免费的功能**：
**如果读进来的字符串里没有 `\n`，说明这一行被截断了**（缓冲不够大）。
这个信息只有"保留 `\n`"才能给你。

**去掉 `\n` 的正确写法**：

```c
line[strcspn(line, "\n")] = '\0';       /* ✅ 推荐 */
```

`strcspn(line, "\n")` 返回"第一个 `\n` 之前的长度"——
- 有 `\n` → 返回它的下标，把它改成 `'\0'`；
- **没 `\n`** → 返回 `strlen(line)`，把**结束符位置**改成 `'\0'`（无操作）。

**⚠ 反面教材**：

```c
line[strlen(line) - 1] = '\0';          /* ❌ */
```

如果行里没有 `\n`（最后一行没换行，或者被截断），
`strlen-1` 指向的是**最后一个有效字符**——把它删了。

实测场景：文件最后一行是 `"hello"`（**没有换行**），
`fgets` 读进来 `line = "hello"`（长度 5），
`line[4] = '\0'` → 变成 `"hell"`。**少了一个字符，且不报错。**

---

**`fgets` 的三个必须注意的点**：

**① 返回值是 NULL 时，缓冲内容不确定**

```c
if (fgets(line, sizeof line, f) == NULL) {
    /* ⚠ 别假设 line 被清空了 */
}
```

**② 缓冲大小是"最多读 n-1 个字符"**

```c
char buf[8];
fgets(buf, 8, f);        /* 最多读 7 个字符 + '\0' */
```

**③ 不要用 `gets()`**

`gets()` 在 **C11 里被正式移除**了——
它没有长度参数，**无论如何都会溢出**。

```c
char buf[8];
gets(buf);               /* ❌ C11 起不存在；能编过也是 100% 的漏洞 */
```

⚠ 如果你的编译器还能编过 `gets()`，说明它开了旧标准兼容。
**永远不要用它**，用 `fgets(buf, sizeof buf, stdin)`。

**裸机上的对应**：

从 UART 收命令时，同样的三条：

```c
static char line[64];
static size_t len;
/* ... */
if (c == '\n' || len >= sizeof(line) - 1) {    /* ① 长度上限（对应 n-1） */
    line[len] = '\0';
    handle_cmd(line);
    len = 0;
} else {
    line[len++] = c;
}
```

⚠ **`len >= sizeof(line) - 1` 那个 `- 1`** 就是 `fgets` 的 `n-1`，
给 `'\0'` 留位置。**忘了 `-1` 就差一错误**
（[ch06](../06-arrays-pointers-strings/README.md) 讲过数组边界）。
</details>
