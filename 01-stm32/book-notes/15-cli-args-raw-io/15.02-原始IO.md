# 15.02 原始 I/O

> 书：第 15 章 命令行参数和原始 I/O · 15.02 原始 I/O（原书 p212+ 区间内）
> 上一篇：[15.01 命令行参数](15.01-命令行参数.md) ｜ 下一篇：[15.03 二进制模式](15.03-二进制模式.md)
> 对应实验：主机侧实测（clang 23.1.0 / macOS arm64）— `open/read/write` 返回值、
> **无缓冲的实测证据**、短读与 EOF

## 书这一节讲什么

一句话：**`open` / `read` / `write` / `close`——绕过 stdio 缓冲，直接进内核。**

上一章是"带缓冲的 I/O"（`FILE*`），本章是**原始 I/O**（`int fd`）。
本篇把两者的差别**用磁盘文件大小实测出来**，
并给出"短读写"的实测证据。

## 一、和缓冲 I/O 的对照

| | 缓冲 I/O（[ch14](../14-buffered-file-io/README.md)） | **原始 I/O（本章）** |
|---|---|---|
| 句柄 | `FILE *` | **`int fd`** |
| 打开 | `fopen(path, "wb")` | **`open(path, O_WRONLY\|O_CREAT, 0644)`** |
| 读 | `fread` / `fscanf` | **`read`** |
| 写 | `fwrite` / `fprintf` | **`write`** |
| 关闭 | `fclose` | **`close`** |
| **缓冲** | stdio 管（实测 4 KB） | **没有**，直接进内核 |
| 失败 | 返回值 + `ferror` | **返回 -1 + `errno`** |
| 短读写 | 少见 | ⚠ **常见**，必须循环 |

## 二、⚠ 实测：无缓冲的直接证据

这是和 [ch14](../14-buffered-file-io/14.06-缓冲与刷新.md) 最有力的对照。

**ch14 的 stdio 版**（写 5 字节后立刻查磁盘）：

```
fprintf("hello") 之后，磁盘上的文件大小 = 0       ← ⚠ 还在用户态缓冲里
fflush() 之后，磁盘上的文件大小       = 5
```

**本章的 raw I/O 版**（写 3 字节后立刻查磁盘）：

```
$ ./raw
open 返回 fd=3（失败返回 -1 并设 errno）
write(fd,"abc",3) -> 返回 3
  ⚠ 立刻查磁盘大小（raw I/O 无缓冲）= 3        ← ✅ 立刻就是 3
read(fd,buf,3) -> 返回 3, buf="abc"
```

**同一个操作，两种结果**：

| | 写 N 字节后立即查磁盘大小 |
|---|---|
| `fprintf`（stdio） | **0** |
| `write`（raw） | **N** |

——这就是"绕过缓冲"的**实测定义**：
**`write` 返回时，数据已经交给了内核**（虽然可能还在内核页缓存里，没到磁盘）。

⚠ **注意"进了内核"不等于"到了磁盘"**：
真要落盘还得 `fsync(fd)`。掉电时内核页缓存里的也会丢。

## 三、`open` 的返回值与权限位

**实测**：

```
open 返回 fd=3（失败返回 -1 并设 errno）
open 不存在的文件 -> 返回 -1, errno=2 (No such file or directory)
open(...,0600) 建出的文件权限 = 0600（受 umask 影响）
```

⚠ **关于权限位的两条**：

1. **`mode` 参数只在 `O_CREAT` 创建文件时生效**——
   打开已存在的文件时 **mode 被忽略**（已存在的文件权限不会变）；
2. **实际权限 = `mode & ~umask`**。
   实测 `umask = 022`，`open(..., 0600)` 得到 **0600**（因为 0600 & ~022 = 0600）；
   但如果 `open(..., 0666)`，实际得到 **0644**。

```c
int fd = open(path, O_WRONLY | O_CREAT | O_TRUNC, 0644);
if (fd < 0) { perror("open"); return -1; }      /* ⚠ 必须检查 */
```

**常用标志**：

| 标志 | 含义 |
|---|---|
| `O_RDONLY` / `O_WRONLY` / `O_RDWR` | 访问模式（三选一，**必填**） |
| `O_CREAT` | 不存在就创建（要带第 3 个参数 `mode`） |
| `O_TRUNC` | 已存在就截断为 0 |
| `O_APPEND` | 追加（每次写前移到末尾） |
| `O_EXCL` | 配合 `O_CREAT`：**已存在就失败**（用来做"只创建一次"） |

⚠ **`O_EXCL` 是唯一能原子地"创建且仅创建一次"的手段**——
裸机/多进程场景下防止竞态。

## 四、⚠ 短读写是真实存在的（实测）

```c
char buf[100];
ssize_t n = read(STDIN_FILENO, buf, sizeof buf);
```

```
$ echo "hello" | ./sr
请求读 100 字节，实际 read 返回 6，读到 "hello\n"
再读一次 -> 返回 0（0 = EOF，不是错误）
```

**请求 100，只得到 6**——这就是**短读**。

⚠ **短读不是错误**：

| 返回值 | 含义 |
|---|---|
| `> 0` | 读到这么多字节（**可能少于请求的**） |
| **`0`** | **EOF**（对文件是到尾了；对 socket 是对端关闭了） |
| **`-1`** | 出错，看 `errno`（`EINTR` 要重试） |

**短写的常见原因**：

| 场景 | 原因 |
|---|---|
| 网络 socket | 内核发送缓冲区满 |
| 管道 | 管道满 / 被信号打断 |
| 终端 | 写入被 `EINTR` 打断 |

**正确写法（循环直到写完）**：

```c
int write_all(int fd, const void *buf, size_t len){
    const uint8_t *p = buf;
    size_t done = 0;
    while (done < len) {
        ssize_t n = write(fd, p + done, len - done);
        if (n < 0) {
            if (errno == EINTR) continue;     /* 被信号打断，重试 */
            return -1;
        }
        done += (size_t)n;
    }
    return 0;
}
```

⚠ **三个细节**：

1. **`n == 0` 也要防死循环**（某些 fd 上 `write` 可能返回 0）；
2. **`EINTR` 要重试，不是错误**——这是"被信号打断"的正常情况；
3. **`done` 用 `size_t`，`n` 用 `ssize_t`**——
   混用会在 `n` 为 -1 时把它们变成巨大的正数。

## 五、`errno`：不是全局变量那么简单

```c
#include <errno.h>
if (write(...) < 0) {
    /* ⚠ 只有出错时 errno 才有意义 */
    fprintf(stderr, "write 失败: %s\n", strerror(errno));
}
```

⚠ **三条规则**：

| 规则 | 说明 |
|---|---|
| ① **只在出错后读** | 成功的系统调用**可能不改** `errno`，也可能改 |
| ② **出错后立刻读** | 中间调用了别的函数（哪怕 `printf`）就可能被覆盖 |
| ③ **它是线程局部的** | 现代实现里 `errno` 是宏，展开成每线程的变量 |

**实测的两个 errno**：

```
open 不存在的文件 -> errno=2 (No such file or directory)     ← ENOENT
ioctl TIOCGWINSZ  -> errno=102 (Operation not supported...)  ← ENOTSUP（见 15.4）
```

**`perror` / `strerror`**：

```c
perror("open");                              /* 输出 "open: No such file or directory" */
fprintf(stderr, "%s\n", strerror(errno));    /* 只要消息 */
```

⚠ **裸机上没有 `errno`**（没有 libc）。
替代方案：**函数直接返回错误码**，或者用一个全局 `g_last_err`
（[ch09](../09-uart-serial/README.md) 的风格）。

## 六、裸机上这一层就是 `uart1_putc` / `uart1_getc`

| 概念 | PC（raw I/O） | 裸机 |
|---|---|---|
| 句柄 | `int fd` | 没有（`USART1` 是固定地址） |
| 读一个字节 | `read(fd, &c, 1)` | `USART1->DR`（[ch09](../09-uart-serial/README.md)） |
| 写一个字节 | `write(fd, &c, 1)` | 等 TXE 再写 DR |
| 返回值 | `ssize_t`（-1/0/n） | **要自己定义**：-1 无数据 / 0 成功 |
| 无缓冲 | ✅ | ✅ **天然就是** |
| `errno` | 有 | ❌ 没有，要自己返回错误码 |

⚠ **裸机的"短写"**：
轮询版 `uart1_puts` **不会短写**（它会一直等到每个字节发完），
所以 [ch09](../09-uart-serial/README.md) 的实现不需要 `write_all` 那套循环。

但**中断驱动 + 环形缓冲**的版本**会**——
缓冲满了就写不进去，和 socket 的"发送缓冲区满"**完全同构**：

```c
int rb_put(rb_t *rb, uint8_t c){
    if (((rb->head + 1) & (SIZE-1)) == rb->tail) return -1;   /* ⚠ 满 → 失败，不是 UB */
    ...
}
```

（[ch10](../10-interrupts/10.04-用缓冲区提速.md) 实测：`put ok=63 full_reject=137`——
**137 次被拒绝**，这就是裸机版的"短写"。）

## 坑点（书 / 常识怎么说 / 实际是什么）

| 书 / 常识怎么说 | 实测是什么 |
|---|---|
| "`write` 和 `fwrite` 差不多" | ⚠ **差在缓冲**：实测写 3 字节后查磁盘，raw I/O 是 **3**，stdio 是 **0** |
| "`write` 会写完我给的所有字节" | ❌ 会短写。实测 `read` 请求 100 只读到 **6** |
| "`read` 返回 0 是错误" | ❌ **0 = EOF**，不是错误。-1 才是错 |
| "`open` 的 mode 参数就是文件权限" | ⚠ 实际 = `mode & ~umask`；且**只在创建时生效** |
| "出错后 `errno` 一直在" | ⚠ **可能被覆盖**。要出错后**立刻**读 |
| "`EINTR` 是错误" | ❌ 是"被信号打断"，**要重试** |
| "裸机上没有短读写问题" | ⚠ 轮询版没有，但**中断+环形缓冲版有**（实测 137 次被拒绝） |

## 代码自测

<details>
<summary>Q1：怎么证明 raw I/O 没有缓冲？</summary>

**写几个字节，立刻查磁盘大小——它是你写的那个数（而 stdio 是 0）。**

**实测对照**（同样的"写 N 字节 → 立刻 stat"）：

| 接口 | 写完后立即查磁盘大小 |
|---|---|
| `fprintf`（stdio，[ch14](../14-buffered-file-io/14.06-缓冲与刷新.md) 实测） | **0** |
| **`write`（raw，本章实测）** | **3**（写了 "abc" 3 字节） |

```
$ ./raw
open 返回 fd=3
write(fd,"abc",3) -> 返回 3
  ⚠ 立刻查磁盘大小（raw I/O 无缓冲）= 3
read(fd,buf,3) -> 返回 3, buf="abc"
```

**为什么**：
`write` 是一个**系统调用**——它返回时，
数据已经从用户态缓冲区复制到了内核。
而 `fprintf` 只是把数据放进了**用户态的 stdio 缓冲区**，
要等 `fflush` / 缓冲满 / `fclose` 才调 `write`。

**层次图**：

```
你的代码
  │
  ├─ stdio 路径：fprintf → [stdio 缓冲] → write(2) → [内核] → 磁盘
  │                          ↑ 数据在这时，stat 看不到
  │
  └─ raw 路径：  write(2) ─────────────→ [内核] → 磁盘
                                          ↑ write 返回时就到这了
```

⚠ **但"进了内核"不等于"到了磁盘"**：

内核还有一层**页缓存**（page cache）。
`write` 返回成功只保证数据在内核里，
掉电时页缓存里的**照样丢**。

要真的落盘：

```c
write(fd, buf, n);
fsync(fd);               /* ← 强制刷到磁盘（会慢很多） */
```

⚠ **`fsync` 很贵**（要等磁盘真的写完），
只在"必须保证落盘"时用（数据库、固件烧录、配置保存）。

---

**裸机上的对应**：

裸机的 `uart1_putc` **天然就是 raw I/O**——
没有 stdio 缓冲这一层，写 DR 就是发给硬件了。

⚠ **但"发给硬件"不等于"发完了"**：

```c
void uart1_putc(char c){
    while (!(USART1->SR & TXE)) { }      /* 等发送寄存器空 */
    USART1->DR = c;                       /* 写进去 */
    /* ⚠ 这里返回时，字节可能还在移位寄存器里没发出去！ */
}
```

`TXE` 表示"**可以写下一个字节了**"，
`TC` 才表示"**这个字节真的发完了**"。
[ch09](../09-uart-serial/9.02-定义我们的putchar.md) 讲过这个区别——
**关 UART 之前必须等 `TC`**，否则最后一个字节发不出去。

**同样是"两层"**：

| PC | 裸机 |
|---|---|
| `write` 返回 = 进了内核页缓存 | `uart1_putc` 返回 = 进了 DR |
| `fsync` = 真到磁盘 | 等 `TC` = 真发完了 |
| `close` 会隐式刷新 | —— |

**一句话**：
> **"写"这个动作在任何层次上都是分阶段的。
> 要知道数据到了哪一层，就得知道每一层的"完成信号"是什么。**
</details>

<details>
<summary>Q2：为什么要循环处理短读写？怎么写？</summary>

**因为短读写是"正常情况"，不是错误——实测请求 100 字节只读到 6。**

**实测**：

```
$ echo "hello" | ./sr
请求读 100 字节，实际 read 返回 6，读到 "hello\n"
再读一次 -> 返回 0（0 = EOF，不是错误）
```

⚠ **请求 100，返回 6，这不是失败**——管道里就只有 6 个字节。

**短读写什么时候发生**：

| 场景 | 原因 |
|---|---|
| 管道 / 终端 | 数据还没全部到达 |
| **网络 socket** | 内核发送/接收缓冲区满 |
| 被信号打断 | `errno == EINTR` |
| 文件 | 剩下的不足请求量（到尾了） |

**短写的正确写法**：

```c
int write_all(int fd, const void *buf, size_t len){
    const uint8_t *p = buf;
    size_t done = 0;
    while (done < len) {
        ssize_t n = write(fd, p + done, len - done);
        if (n < 0) {
            if (errno == EINTR) continue;     /* ① 被信号打断：重试 */
            return -1;                        /* ② 真出错 */
        }
        if (n == 0) return -1;                /* ③ 防死循环 */
        done += (size_t)n;
    }
    return 0;
}
```

⚠ **三个细节，缺一个就有 bug**：

**① `EINTR` 要重试，不是错误**

信号处理器打断了 `write`，`write` 返回 -1 并设 `errno = EINTR`。
这不是失败——**继续写就行**。
把 `EINTR` 当真错误会导致"莫名其妙的写失败"。

**② `n == 0` 要防死循环**

某些 fd 上 `write` 可能返回 0（不代表进展）。
不处理就 `done` 永远不增加 → **死循环**。

**③ `ssize_t` 转 `size_t` 要在确认 `n > 0` 之后**

```c
done += (size_t)n;        /* ✅ 此时 n > 0 */
```

如果先转换再判断，`n = -1` 会变成 `SIZE_MAX`，
`done` 直接爆掉。

**短读的正确写法**（要读满 N 字节，或直到 EOF）：

```c
ssize_t read_all(int fd, void *buf, size_t len){
    uint8_t *p = buf;
    size_t done = 0;
    while (done < len) {
        ssize_t n = read(fd, p + done, len - done);
        if (n < 0) {
            if (errno == EINTR) continue;
            return -1;
        }
        if (n == 0) break;               /* ⚠ EOF：正常结束，不是错误 */
        done += (size_t)n;
    }
    return (ssize_t)done;                /* 可能 < len，因为遇到 EOF */
}
```

⚠ **和 `write_all` 的关键差别**：
读到 `n == 0` 是 **break**（正常结束），不是错误——
`read_all` 返回实际读到的字节数，可能少于请求量。

---

**裸机上的对应**：

**轮询版 `uart1_puts` 不会短写**——
它内部每个字节都等 TXE：

```c
void uart1_puts(const char *s){ while (*s) uart1_putc(*s++); }
```

所以 [ch09](../09-uart-serial/README.md) 的实现**不需要 `write_all`**。

**但中断驱动 + 环形缓冲版会**：

```c
int rb_put(rb_t *rb, uint8_t c){
    if (((rb->head + 1) & (SIZE-1)) == rb->tail) return -1;   /* ⚠ 满了 */
    ...
}
```

[ch10](../10-interrupts/10.04-用缓冲区提速.md) 实测：

```
put ok=63 full_reject=137 head=63 tail=0
```

**137 次被拒绝**——这就是裸机版的"短写"。

⚠ **处理方式和 PC 上一样**：
要么**重试**（等 ISR 消费掉一些再 put），
要么**丢弃并计数**（`g_rx_overflow++`，至少让你知道丢了多少）。

**规则**：
> **"写"的返回值在每一层都要检查——
> 无论是 POSIX 的 `write` 还是裸机的 `rb_put`。
> 它们的失败语义不同（短写 vs 满），但"必须检查"是一样的。**
</details>

<details>
<summary>Q3：`errno` 怎么用才不出错？</summary>

**三条规则：出错后立刻读、只读自己关心的那个、成功时别读。**

**实测的两个 errno**：

```
open 不存在的文件 -> 返回 -1, errno=2 (No such file or directory)    ← ENOENT
ioctl TIOCGWINSZ  -> errno=102 (Operation not supported on socket)   ← ENOTSUP
```

---

**规则①：只在出错后读**

```c
int fd = open(path, O_RDONLY);
if (fd < 0) {
    /* ✅ 这里读 errno 有意义 */
    fprintf(stderr, "open 失败: %s\n", strerror(errno));
}
/* ❌ 成功之后 errno 的值没有意义（可能残留，也可能被改） */
```

⚠ **成功的系统调用不保证不改 `errno`**——
标准只说"出错时设置"，没说"成功时不变"。
所以成功路径上读 `errno` 是**无意义的**。

**规则②：出错后立刻读**

```c
if (write(fd, buf, n) < 0) {
    printf("出错了\n");                    /* ⚠ printf 本身可能改 errno！ */
    fprintf(stderr, "%s\n", strerror(errno));  /* ❌ 读到的可能不是 write 的错误 */
}
```

**正确做法——先存下来**：

```c
if (write(fd, buf, n) < 0) {
    int e = errno;                          /* ✅ 立刻保存 */
    printf("出错了\n");
    fprintf(stderr, "%s\n", strerror(e));   /* ✅ 用保存的值 */
}
```

**规则③：需要"清零"的场景要手动清**

`strtol` 这类函数**只在出错时设置 errno**，
所以要检测错误必须在调用前清零：

```c
errno = 0;                        /* ⚠ 必须 */
long v = strtol(s, &end, 10);
if (errno == ERANGE) { /* 超出范围 */ }
```

（[15.01](15.01-命令行参数.md) 实测过：不清零会拿到上一次调用残留的 `ERANGE`。）

---

**`errno` 不是全局变量**

```c
/* 现代实现里 errno 是个宏，展开成"每线程的变量" */
#define errno (*__errno_location())      /* glibc 的例子 */
```

所以**多线程下每个线程有自己的 errno**——
这是它设计的用意，不用担心竞争。

⚠ **但它也意味着**：`errno` 的值**不会跨线程传递**。
线程 A 出错设了 errno，线程 B 读到的**不是** A 的那个。

---

**两个输出函数**：

| 函数 | 输出 |
|---|---|
| `perror("open")` | `open: No such file or directory`（**带前缀**，自动加 errno） |
| `strerror(errno)` | `No such file or directory`（只要消息） |

⚠ **`strerror` 返回的是静态缓冲区**（有些实现是线程局部的），
不要保存返回的指针跨调用使用。

---

**裸机上没有 `errno`**

裸机没有 libc，所以：

| 方案 | 做法 | 适用 |
|---|---|---|
| **① 返回错误码**（✅ 推荐） | `int uart_send(...)` 返回 0 / -1 / -2 | 简单、明确、无全局状态 |
| **② 全局 `g_last_err`** | 模仿 errno，但要自己管理 | 需要"错误原因"而不仅是"失败" |
| **③ 返回结构体** | `{ .ok = false, .err = ERR_TIMEOUT }` | Go 风格，C 里略啰嗦 |

**本仓库的取向**：**方案①**——直接返回错误码。
理由：

- 裸机通常是单线程 + ISR，全局错误变量容易被 ISR 覆盖；
- 返回码在函数签名里**看得见**，不会被忘掉检查；
- 代码量最小（Flash 紧张时这条很重要）。

```c
typedef enum { OK = 0, ERR_TIMEOUT = -1, ERR_OVERFLOW = -2, ERR_BAD_ARG = -3 } err_t;
err_t rb_put(rb_t *rb, uint8_t c);      /* 返回值一眼看出要检查 */
```

⚠ **ISR 里尤其不要用全局错误变量**——
[ch10](../10-interrupts/README.md) 讲过 ISR 的不可重入问题。
</details>
