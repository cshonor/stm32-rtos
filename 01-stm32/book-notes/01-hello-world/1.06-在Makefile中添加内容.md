## 书这一节讲什么

从一个文件的 Makefile 长成多文件项目，需要加什么东西：
变量、模式规则、清理规则、以及"新增文件时改哪里"。

## 从单文件长到多文件，真正要加的四样

| 要加的东西 | 为什么 |
|---|---|
| `SRCS` / `OBJS` 变量 | 新增文件只改一行，不改规则 |
| `%.o: %.c` 模式规则 | 一条规则覆盖所有 `.c`，否则每加一个文件抄一遍命令 |
| `clean` 目标 | 换编译器/换标志之后必须清干净（见 [1.04 坑点](1.04-改进程序和构建流程.md)） |
| 链接脚本作为依赖 | 漏了它改脚本不重新链接——**最隐蔽的坑** |

裸机项目里还要额外加两样书里没有的：

| 要加的东西 | 为什么 |
|---|---|
| `.S` 文件的规则 | 启动文件是汇编，要跟 `.c` 分开（大写的 `.S` 表示要先过预处理器） |
| `bin` / `elf` 两个目标分开 | `.elf` 给 gdb，`.bin` 给烧录器，用途不同不能混（见 [2.02](../02-ide/2.02-IDE为我们做了什么.md)） |

## 一份可以直接抄的骨架

```makefile
CC      := clang
TARGET  := armv7m-none-eabi
MCU     := cortex-m3
BUILD   := build

CFLAGS  := --target=$(TARGET) -mcpu=$(MCU) -mthumb -Os -g \
           -ffreestanding -fno-builtin \
           -ffunction-sections -fdata-sections \
           -Wall -Wextra
LDFLAGS := -T linker.ld --gc-sections -Map=$(BUILD)/app.map

SRCS    := $(wildcard *.c)
ASMS    := $(wildcard *.S)
OBJS    := $(addprefix $(BUILD)/,$(SRCS:.c=.o) $(ASMS:.S=.o))

$(BUILD)/app.elf: $(OBJS) linker.ld
	@mkdir -p $(BUILD)
	ld.lld $(LDFLAGS) -o $@ $(OBJS)
	llvm-objcopy -O binary $@ $(BUILD)/app.bin
	llvm-size -A $@

$(BUILD)/%.o: %.c
	@mkdir -p $(dir $@)
	$(CC) $(CFLAGS) -c $< -o $@

$(BUILD)/%.o: %.S
	@mkdir -p $(dir $@)
	$(CC) $(CFLAGS) -c $< -o $@

.PHONY: clean flash
clean:
	rm -rf $(BUILD)
```

关键就一行：**`$(wildcard *.c)` 之后，新增 `.c` 文件不用改 Makefile。**

## 三个最省事的调试手法

```makefile
# ① 打印变量的值（排查"为什么没编进去"）
$(info OBJS = $(OBJS))

# ② 让 make 告诉你它打算跑什么，但不真跑
#    $ make -n
# ③ 让 make 解释"为什么这个目标被认为是新的"
#    $ make --debug=b
```

## 坑点（书 / 常识怎么说 / 实际是什么）

| 书 / 常识怎么说 | 实际是什么 |
|---|---|
| "多文件就是把文件名都列上" | 列了就不叫工程化了。用 `wildcard` + 模式规则，**新增文件零改动** |
| "`$(info)` 是调试用的" | 是。嵌入式 Makefile 大量依赖变量拼接，`$(info ...)` 是唯一能看见中间结果的手段 |
| "`clean` 就是 `rm *.o`" | 裸机项目往往会生成 `.elf`/`.bin`/`.map`/`.su`，以及**递归目录**。`rm -rf $(BUILD)` 更干净 |
| "make 和 CMake 随便选一个" | 学习阶段用 make（**看得见每一步**）；工程阶段 CMake 更合适（多目标、跨平台、IDE 集成）。书成于 2021 只讲 make，STM32CubeIDE 到 2.1.0 才支持 CMake presets |
| "TAB 和空格没区别" | Makefile 里命令行**必须**以真 TAB 开头。编辑器自动把 TAB 转空格是经典杀手，表现为 `missing separator` |

## 代码自测

<details>
<summary>Q1：`$(wildcard *.c)` 有什么隐患？</summary>

三个，都要知道自己踩过：

1. **只匹配当前目录**。子目录要写 `$(wildcard src/*.c)` 或 `$(shell find ...)`——
   注意 `wildcard` 不做递归。
2. **顺序不确定**。`wildcard` 返回的顺序依赖文件系统，**不同机器可能不同**。
   如果链接顺序有影响（库之间有依赖时确实有），要显式 `$(sort ...)` 或手写顺序。
3. **会把你不想编的文件也卷进来**，比如临时写的 `test_xxx.c`、编辑器留下的
   `.#main.c`（emacs lock 文件）。表现是"莫名其妙多了个未定义符号"。

稳妥做法：显式目录 + `$(sort ...)`，并在 CI 里跑一遍 `make -n` 看文件清单。
</details>

<details>
<summary>Q2：为什么启动文件用 `.S` 而不是 `.s`？</summary>

因为**大小写有意义**，这是 Make/GCC 体系的老约定：

| 后缀 | 含义 | 走预处理器吗 |
|---|---|---|
| `.s` | 纯汇编 | **不走** |
| `.S` | 汇编，但先过预处理器 | **走**（cpp） |

对裸机启动文件来说 `.S` 几乎是必需的，因为你要用：

```asm
#define STACK_TOP 0x20005000
    .word STACK_TOP          /* 宏展开 */
#include "memory_map.h"      /* 地址定义集中管理 */
```

用 `.s` 的话这些都用不了，只能把地址硬编码两处——
而"两处硬编码必然不同步"是迟早的事。
</details>
