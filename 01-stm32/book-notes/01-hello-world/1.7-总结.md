## 这一章要带走的三句话

**第一句：编译不是一步，是四步。**

```
hello.c ─[预处理]→ .i ─[编译]→ .s ─[汇编]→ .o ─[链接]→ .elf
```

四步里只有第二步懂 C 语法。所以 `undefined reference` 永远不该去怀疑 C 代码，
而要怀疑"这个 `.o` 有没有参与链接"。

**第二句：裸机开发的"环境"不是装出来的，是按链路分五段确认出来的。**

| 段 | 确认命令 | 通过的样子 |
|---|---|---|
| 编译器 | `clang --target=... -c x.c` | `llvm-readelf -h x.o` 显示 `Machine: ARM` |
| 链接器 | `ld.lld -T linker.ld` | 有 `Entry point` |
| 转镜像 | `llvm-objcopy -O binary` | 生成非空 `.bin` |
| 硬件 | `openocd -f <cfg>` | 出现 `STLINK` + `SWD DPIDR` |
| 调试 | `arm-none-eabi-gdb x.elf` | 打出源码行号 |

哪一段不过，问题就在那一段——**这是本书所有排障动作的总纲**。

**第三句：书里的"安装 GCC / 装 IDE"是手段，不是目的。**
目的是"把 C 变成能在 0x08000000 跑的字节"。达到目的的方式可以完全不同，
但四步流程一步都不会少。

## 代码自测

<details>
<summary>Q1：用一句话说清"编译"和"链接"的分工。</summary>

**编译**回答"这段 C 对应哪些机器指令"（**还不知道放哪**）；
**链接**回答"这些指令最终放在哪个地址"（**以及缺的符号去哪找**）。

分界线就是 `.o`：编译产出 `.o` 时每个段地址都是 0，
链接产出 `.elf` 时地址全部定死。所以——

- 编译错误 → C 语法/类型问题；
- 链接错误 → 文件/库/符号/地址问题。

**两者的排查方向完全不重叠，先分清在哪一层，再动手。**
</details>

<details>
<summary>Q2：这一章哪些内容三年后会过期，哪些不会？</summary>

| 会过期 | 不会过期 |
|---|---|
| 具体 IDE 的操作步骤（SW4STM32 已经没了） | 预处理→编译→汇编→链接四步 |
| 具体工具链版本号、下载地址 | target triple 的语义（`arm-none-eabi`） |
| GCC / clang 的选项拼写（`--specs=nosys.specs` 这类） | `.o` 地址未定、链接期才定地址这个事实 |
| 安装器形式（`.pkg` / `.msi` / `brew`） | `volatile`、段、重定位这些机制 |

**判据很简单：属于"某个工具怎么用"的会过期，属于"计算机怎么工作"的不会。**
书评里说的"工具链章节天然过时"，指的就是左边那一列。
</details>
