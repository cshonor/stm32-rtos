# 11.03 链接器定义的符号

> 书：第 11 章 链接器 · 11.03 链接器定义的符号（原书 p154–173 区间内）
> 上一篇：[11.02 链接过程](11.02-链接过程.md) ｜ 下一篇：[11.04 重定位](11.04-重定位.md)
> 对应实验：`ld.lld 23.1.0` + `llvm-nm -n --print-size`（实测符号值）

## 书这一节讲什么

一句话：**链接脚本可以定义符号**——
`_estack`、`_sdata`、`_edata`、`_sidata`、`_sbss`、`_ebss` 都是这么来的。

这些符号**不在任何 `.c` 文件里定义**，是链接脚本写的。
它们是"启动代码"和"链接脚本"之间唯一的接口。

## 一、实测：这些符号的值

本章真实链接出来的产物：

```
$ llvm-nm -n --print-size blink.elf
08000000 00000010 R g_vectors
08000010 00000002 T Default_Handler
08000012 00000058 T Reset_Handler
0800006c 00000018 T main
08000084 00000000 A _sidata        ← A = absolute（链接器定义）
20000000 00000000 D _sdata
20000000 00000004 D g_has_init
20000004 00000000 D _edata
20000004 00000000 B _sbss
20000004 00000004 B g_tick
20000008 00000000 B _ebss
20005000 00000000 A _estack        ← A = absolute
```

| 符号 | 实测值 | 类型 | 谁用 |
|---|---|---|---|
| `_estack` | **`0x20005000`** | A | 向量表第 0 项（上电装进 MSP） |
| `_sdata` | `0x20000000` | D | 搬运的目标（VMA 起点） |
| `_edata` | `0x20000004` | D | 搬运循环的结束条件 |
| `_sidata` | **`0x08000084`** | **A** | 搬运的源地址（**LMA**） |
| `_sbss` / `_ebss` | `0x20000004` / `0x20000008` | B/B | 清零循环的范围 |

注意 `_sidata` 和 `_estack` 的类型是 **`A`（absolute）**，
其他几个是 `D`/`B`（在段里的地址）——这个差别本身就是线索：
`_sidata` 是"某个段的加载地址"，不是"某个段里的变量"。

## 二、脚本里怎么定义

```ld
MEMORY {
    FLASH (rx)  : ORIGIN = 0x08000000, LENGTH = 128K
    RAM   (rwx) : ORIGIN = 0x20000000, LENGTH = 20K
}

/* ① 段外定义：直接用表达式 */
_estack = ORIGIN(RAM) + LENGTH(RAM);      /* 0x20000000 + 20K = 0x20005000 */

SECTIONS {
    /* ② 段内定义：用 "."（当前位置计数器） */
    .data : {
        _sdata = .;          /* VMA 起点 */
        *(.data*)
        . = ALIGN(4);
        _edata = .;
    } >RAM AT>FLASH

    /* ③ 关键：用 LOADADDR 问 LMA */
    _sidata = LOADADDR(.data);
}
```

三种方式：

| 方式 | 写法 | 得到什么 |
|---|---|---|
| 段外表达式 | `_estack = ORIGIN(RAM) + LENGTH(RAM);` | 纯计算 |
| 段内 `.` | `_sdata = .;` | **当前 VMA** |
| **`LOADADDR(段)`** | `_sidata = LOADADDR(.data);` | **该段的 LMA** |

## 三、⚠ `_sidata` 是最容易写错的那个

```ld
_sidata = .;              /* ❌ 错：拿到的是 VMA（0x20000000） */
_sidata = LOADADDR(.data); /* ✅ 对：拿到 LMA（0x08000084） */
```

**为什么**：`.` 是位置计数器，在 `.data` 段**之后**它停在
RAM 那边（VMA），不是 Flash 那边。

写错的后果：

```c
uint32_t *src = &_sidata;      /* 拿到 0x20000000，而不是 0x08000084 */
while (dst < &_edata) *dst++ = *src++;   /* 从 RAM 读垃圾搬到 RAM */
```

**表现**：全局变量的初值是**随机垃圾**。

⚠ 而这个症状和"忘了搬 `.data`"**一模一样**——
你没法从现象区分"压根没搬"和"搬错了源地址"。
这是能浪费一整天的一类 bug。

**防御办法**：在启动代码里加个断言（或者用调试器直接看 `_sidata` 的值）：

```
(gdb) p/x &_sidata
$1 = 0x8000084        ← 应该是 0x08xxxxxx；如果是 0x20xxxxxx 就错了
```

## 四、C 代码里怎么用这些符号

```c
#include <stdint.h>
extern uint32_t _estack, _sdata, _edata, _sidata, _sbss, _ebss;

void Reset_Handler(void){
    uint32_t *src = &_sidata;
    uint32_t *dst = &_sdata;
    while (dst < &_edata) *dst++ = *src++;

    for (uint32_t *p = &_sbss; p < &_ebss; ) *p++ = 0;

    main();
    for (;;) { }
}
```

⚠ **必须取地址（`&_sidata`）**，不能直接当值用：

```c
uint32_t *src = (uint32_t *)_sidata;   /* ❌ 这样写能编译但语义危险 */
uint32_t *src = &_sidata;              /* ✅ */
```

链接器定义的符号**没有存储空间**——它只是一个地址值。
`_sidata` 这个"变量"的地址恰好等于它的值。
直接写 `_sidata` 在某些编译器/优化档下会真的去读内存（读到垃圾），
而 `&_sidata` 永远是常量折叠。

**更稳的写法**（推荐）：

```c
extern uint32_t _sidata[];         /* 声明成数组 */
uint32_t *src = _sidata;           /* 数组名退化成指针 = 地址 */
```

## 五、`_estack` 为什么是 RAM 的最高地址

因为 Cortex-M 用**满递减栈**：`push` 先减 SP 再存。

```
RAM: 0x20000000 ──────────────────────── 0x20005000 (20 KB)
     ↑                                        ↑
     .data/.bss/.noinit 往上排               _estack ← 栈从这里开始，往下长
     已用的静态区 ──→                    ←── 栈（向下）
```

如果设成 `ORIGIN(RAM)`（最低地址），第一次 `push` 就减到 `0x1FFFFFFC`——
**RAM 外面**，立刻 HardFault。

实测：

```
_estack = 0x20005000
ch03 真机读到 msp = 0x20004f80      ← 比栈顶低 128 字节（已被使用）
```

`msp` 比 `_estack` **小**，方向正确。

⚠ 链接器**不会**自动检查栈和 `.bss` 会不会撞上（两端往中间长）。
所以要在脚本里加 `ASSERT`（[11.02](11.02-链接过程.md) 实测过失败的输出）。

## 六、自定义符号：给应用用

链接脚本定义的符号也能给应用代码用——这是裸机上的常用技巧：

```ld
/* 划一块"配置区"在 Flash 最后一页 */
.cfg_page (NOLOAD) : {
    _scfg = .;
    . = . + 1024;          /* 1 KiB */
    _ecfg = .;
} >FLASH
```

```c
extern uint8_t _scfg[], _ecfg[];
#define CFG_PAGE       ((const void *)_scfg)
#define CFG_PAGE_SIZE  ((size_t)(_ecfg - _scfg))
```

或者反过来——**让链接脚本告诉你还剩多少 RAM**：

```ld
_ram_free_start = _ebss;
_ram_free_end   = _estack - 512;
```

```c
extern uint8_t _ram_free_start[], _ram_free_end[];
size_t free_ram = (size_t)(_ram_free_end - _ram_free_start);
```

## 坑点（书 / 常识怎么说 / 实际是什么）

| 书 / 常识怎么说 | 实测是什么 |
|---|---|
| "这些符号在某个头文件里" | ❌ **在链接脚本里**。实测 `llvm-nm` 显示类型是 `A`（absolute） |
| "`_sidata` 用 `. = .` 取" | ❌ 拿到 VMA。必须 `LOADADDR(.data)`。实测正确值 `0x08000084` |
| "`_estack` 是 RAM 起始" | ❌ 是**最高地址**（满递减栈）。实测 `0x20005000` |
| "直接用 `_sdata` 就行" | ⚠ 要 `&_sdata`（或声明成数组 `_sdata[]`）。链接器符号没有存储空间 |
| "栈和 .bss 撞上会报错" | **不会**。要自己加 `ASSERT`（[11.02 实测](11.02-链接过程.md)） |

<details>
<summary>Q1：`_estack` 为什么等于 `ORIGIN(RAM) + LENGTH(RAM)`？栈不是往下长的吗？</summary>

**正因为栈往下长，栈顶才必须在最高地址。**

Cortex-M 用的是**满递减栈**（full descending）：`push` 时 SP 先减 4 再存。

```
RAM: 0x20000000 ──────────────────────── 0x20005000 (20 KB)
     ↑                                        ↑
     .data/.bss/.noinit 往上排               _estack ← 栈从这里开始，往下长

     已用的静态区 ──→                    ←── 栈（向下）
                  ↑
              中间是"还空着"的区域
```

如果 `_estack` 设成 `ORIGIN(RAM)`（最低地址 `0x20000000`），
那么第一次 `push` 就会减到 `0x1FFFFFFC`——**RAM 外面的地址**，
瞬间 HardFault（或者静默写到别的总线上）。

**实测**：

```
_estack = 0x20005000              （= 0x20000000 + 20 KB）
ch03 真机读到 msp = 0x20004f80    （比栈顶低 128 字节 = 已被使用）
```

`msp` 比 `_estack` **小**，方向正确。

**⚠ 一个必须知道的事**：链接器**不会**帮你检查"栈和 `.bss` 撞上了没"。
它们从两端往中间长，撞上了就是**静默的内存破坏**
（[ch07](../07-stack-frame-functions/README.md)：栈溢出不报错）。

所以要在链接脚本里加 `ASSERT`：

```ld
ASSERT(_ebss < _estack - 512, "RAM 不够：栈至少要 512 字节")
```

这样 RAM 不够时是**链接失败**（明确、可修），而不是运行时玄学。
实测（[11.02](11.02-链接过程.md)）：RAM 缩到 512 字节时
`ld.lld: error: RAM 不够：栈至少要 512 字节`。

**另外两个细节**：

1. **`_estack` 通常要 8 字节对齐**（AAPCS 要求栈指针对齐）。
   `0x20005000` 天然满足（20 KB 是 8 的倍数），但换个 LENGTH 就不一定了；
2. **栈的实际可用空间** = `_estack - _ebss - (heap if any)`。
   ASSERT 里减的 512 是"至少留这么多"，可以按需要调大。
</details>

<details>
<summary>Q2：`_sidata` 写错了会怎样？为什么难查？</summary>

表现为**全局变量的初值是随机垃圾**。

```ld
/* ❌ 错误写法 */
.data : { _sdata = .; *(.data*) _edata = .; } >RAM AT>FLASH
_sidata = .;              /* ← 这里拿到的是 VMA（RAM 地址），不是 LMA */

/* ✅ 正确写法 */
_sidata = LOADADDR(.data);
```

**为什么错**：`.` 是位置计数器。在 `.data` 段结束后，
它停在 RAM 的当前位置（`0x20000004`），**不是 Flash 那边**。
所以 `_sidata` 拿到的是 `0x20000004`，而正确值是 `0x08000084`（实测）。

**启动代码会做什么**：

```c
uint32_t *src = &_sidata;                  /* 0x20000004 —— RAM 里的某个位置 */
uint32_t *dst = &_sdata;                   /* 0x20000000 */
while (dst < &_edata) *dst++ = *src++;     /* 从 RAM 读垃圾 → 写进 .data */
```

结果：`g_has_init` 的值不是 `0xA5A5A5A5`，而是 RAM 里那个位置的随机内容。

**为什么难查**——这个症状和另一类 bug**一模一样**：

| bug | 表现 |
|---|---|
| **忘了搬 `.data`** | 全局变量初值是垃圾 |
| **`_sidata` 写错** | 全局变量初值是垃圾 |

从现象上**无法区分**。你要么看 `_sidata` 的值，要么看反汇编里那个 `src` 寄存器装了什么。

**排查方法**（三选一，从快到慢）：

```
① 直接看符号值
   $ llvm-nm blink.elf | grep _sidata
   08000084 A _sidata            ← 必须是 0x08xxxxxx（Flash）
                                    如果是 0x20xxxxxx（RAM）就错了

② 调试器里看
   (gdb) p/x &_sidata

③ 看反汇编
   800006c: ldr r1, [pc, #0x30]   ← r1 应该是 0x08000084
```

**防御写法**：在启动代码里加个编译期/链接期检查——

```ld
/* 链接脚本里：_sidata 必须在 Flash 区间内 */
ASSERT(_sidata >= ORIGIN(FLASH) && _sidata < ORIGIN(FLASH) + LENGTH(FLASH),
       "_sidata 不在 Flash 里（多半用了 `. = .` 而不是 LOADADDR）")
```

这条 `ASSERT` 能把"查一天"变成"链接时一行错误"。
**这就是把运行时玄学前移的价值**（[11.02 Q2](11.02-链接过程.md)）。
</details>

<details>
<summary>Q3：C 代码里该怎么写 `extern`？为什么推荐"声明成数组"？</summary>

链接器定义的符号有两种声明方式，第二种更稳。

**方式①：声明成变量，用 `&` 取地址**

```c
extern uint32_t _sdata, _edata, _sidata, _sbss, _ebss, _estack;

uint32_t *src = &_sidata;      /* ✅ 正确 */
uint32_t *src = (uint32_t)_sidata;   /* ⚠ 危险 */
```

**为什么第二种危险**：链接器定义的符号**没有存储空间**——
它只是一个数值（地址）。`_sidata` 这个"符号的值"是 `0x08000084`，
而"符号的地址"也恰好是 `0x08000084`（因为它不在任何段里）。

- `&_sidata` → 编译器知道这是链接器符号，直接常量折叠成 `0x08000084`；
- `_sidata` → 编译器可能生成一条 `ldr`，从地址 `0x08000084` **读内存**——
  读到的是 Flash 里那个位置的**内容**（本例中是 `.data` 的初值），不是地址本身。

在 `-O0` 下第二种经常"碰巧能跑"（编译器保守地不优化），
换成 `-Os` 或者换了编译器就可能出错。**别赌**。

**方式②：声明成数组（推荐）**

```c
extern uint8_t _sidata[], _sdata[], _edata[], _sbss[], _ebss[];

uint32_t *src = (uint32_t *)_sidata;      /* 数组名退化成指针 = 地址 */
while (dst < (uint32_t *)_edata) *dst++ = *src++;
```

数组名的语义天然就是"首元素地址"，所以不需要 `&`，
也就不可能误写成"读内存"。

⚠ 用数组声明时，**比较和减法要注意类型**：

```c
extern uint8_t _sbss[], _ebss[];
size_t n = (size_t)(_ebss - _sbss);       /* ✅ 指针相减得到元素数（字节） */

extern uint32_t _sbss32[], _ebss32[];
size_t n = (size_t)(_ebss32 - _sbss32);   /* ⚠ 得到的是"4 字节单位数" */
```

用 `uint8_t[]` 声明，减法直接得到**字节数**，最不容易错。

**本仓库的写法**（ch03 的启动代码用的就是数组式）：

```c
extern uint32_t _sdata, _edata, _sidata, _sbss, _ebss;
/* 搬运： */
uint32_t *src = &_sidata, *dst = &_sdata;
while (dst < &_edata) *dst++ = *src++;
/* 清零： */
for (uint32_t *p = &_sbss; p < &_ebss; ) *p++ = 0;
```

两种都在用；**新代码倾向数组式**（`extern uint8_t _sbss[];`）。
</details>
