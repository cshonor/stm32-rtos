# 11.02 链接过程

> 上一篇：[11.01 编译和链接的内存模型](11.01-编译和链接的内存模型.md) ｜ 下一篇：[11.03 链接器定义的符号](11.03-链接器定义的符号.md)

## 书这一节讲什么

一句话：**链接器做三件事——合并段、定地址、修重定位**。

书讲的是流程。裸机上真正会咬人的是第四件事：
**`--gc-sections` 会把"没人引用的段"丢掉，而向量表就属于"没人引用"**。

## 一、链接的四步

```
① 读入所有 .o 和链接脚本
② 合并同名段（把 N 个 .text 拼成一个 .text）
③ 按脚本定地址（VMA / LMA）
④ 重定位（把符号引用填成最终地址）
   ＋（可选）--gc-sections：丢弃不可达段
```

实测的 map 文件里能看到第 ② 步的结果：

```
 8000010  8000010       74     4 .text                ← 合并后的输出段
 8000010  8000010       5a     4         startup.o:(.text)     ← 输入段 1
 800006c  800006c       18     4         main.o:(.text)        ← 输入段 2
```

两个 `.o` 各自的 `.text` 被拼成了一个输出段，地址连续。

## 二、⚠ 实测：`--gc-sections` 会把向量表丢掉

这是本章最值得记住的实测。

```ld
/* 有 KEEP： */
.isr_vector : { . = ALIGN(4); KEEP(*(.isr_vector)) } >FLASH

/* 无 KEEP： */
.isr_vector : { . = ALIGN(4);  *(.isr_vector) } >FLASH
```

```
$ ld.lld -T linker.ld    -Map=blink.map    --gc-sections -o blink.elf    startup.o main.o
$ llvm-nm blink.elf | grep g_vectors
08000000 R g_vectors                 ← ✅ 在

$ ld.lld -T linker_nok.ld -Map=... --gc-sections -o blink_nok.elf startup.o main.o
$ llvm-nm blink_nok.elf | grep g_vectors
（无输出）
  g_vectors 不见了！                  ← ❌ 被 GC 掉了
```

**为什么**：`--gc-sections` 从入口点（entry）做**可达性分析**——
顺着重定位（函数调用、数据引用）遍历，走不到的段就丢。

向量表的处境特殊：**没有任何代码"引用"它**——
它是被**硬件**读的（上电时从 `0x00000000` 读前两个字）。
所以在可达性图里 `g_vectors` 是孤立节点 → 被丢。

**后果**：`.bin` 的开头不是向量表，板子上电读到的是别的字节 →
立刻 HardFault 或完全不动。**这是"编译链接一切正常、烧进去毫无反应"的经典原因。**

## 三、`__attribute__((used))` 不够

因为它们约束的是**两个不同阶段**：

| 手段 | 约束谁 | 作用 |
|---|---|---|
| `__attribute__((used))` | **编译器** | "即使没人引用，也要编译进 `.o`" |
| `KEEP()` in 链接脚本 | **链接器** | "即使没人引用，也别被 `--gc-sections` 丢掉" |

ch01 实测过这个坑：

> "`__attribute__((used))` 的函数一定会进镜像" ——
> `used` 只约束编译器。链接器 `--gc-sections` 从 entry 做可达性分析，
> 没人调照样丢（实测 `wait_press_bad/good` 没进最终镜像）

**判据**：**"这个东西是被硬件/外部读的，还是被代码读的？"**
被硬件读 → 一定 `KEEP`。

同理要 `KEEP` 的还有：

- `.init_array` / `.fini_array`（C++ 全局构造、`__attribute__((constructor))`）；
- 你自己定义的"硬件要读"的表（中断向量、bootloader 镜像头）。

## 四、实测：`ASSERT` 把"RAM 不够"变成链接失败

链接脚本不只是布局，它还能**做编译期（链接期）检查**：

```ld
ASSERT(_ebss < _estack - 512, "RAM 不够：栈至少要 512 字节")
```

实测（把 RAM 从 20K 改成 512）：

```
$ sed 's/LENGTH = 20K/LENGTH = 512/' linker.ld > linker_tiny.ld
$ ld.lld -T linker_tiny.ld -o /dev/null startup.o main.o -e Reset_Handler
ld.lld: error: RAM 不够：栈至少要 512 字节

$ ld.lld -T linker.ld -o /dev/null startup.o main.o -e Reset_Handler
（成功，无输出）
```

**为什么这条很重要**：

栈和 `.bss` 是**从 RAM 两端往中间长**的：

```
RAM: 0x20000000 ──────────────────────── 0x20005000
     ↑ .data/.bss/.noinit 往上排          ↑ _estack（栈往下长）
```

**链接器不会自动检查它们会不会撞上**。撞上了就是**静默的内存破坏**
（[ch07](../07-stack-frame-functions/README.md)：栈溢出不报错）。

加了 `ASSERT` 之后，RAM 不够就是**链接失败**——明确、可修，
而不是运行几小时后出现的玄学 bug。

这是把"运行时玄学"**前移到链接期**的典型手段，和
[ch08 8.12](../08-complex-types/8.12-结构体与嵌入式编程.md) 的
`_Static_assert`（编译期）是同一套思路的两个层次。

## 五、⚠ `.ARM.exidx` 只能在链接脚本里丢

clang/LLVM 即使加了 `-fno-unwind-tables`，也可能生成 `.ARM.exidx` 段。
实测它不能用编译选项去掉，只能在链接脚本里丢弃：

```ld
/DISCARD/ : { *(.ARM.exidx*) }
```

（ch01 实测：编译出的 `.o` 里仍有 `.ARM.exidx 32` 字节。）

## 六、完整的最小链接脚本（实测可用）

```ld
/* linker.ld —— 本章实测用的那个（简化了注释） */
MEMORY {
    FLASH (rx)  : ORIGIN = 0x08000000, LENGTH = 128K
    RAM   (rwx) : ORIGIN = 0x20000000, LENGTH = 20K
}
_estack = ORIGIN(RAM) + LENGTH(RAM);

SECTIONS {
    .isr_vector : { . = ALIGN(4); KEEP(*(.isr_vector)) } >FLASH

    .text : { *(.text*) *(.rodata*) } >FLASH

    .data : {
        _sdata = .;
        *(.data*)
        . = ALIGN(4);
        _edata = .;
    } >RAM AT>FLASH
    _sidata = LOADADDR(.data);

    .bss : {
        _sbss = .;
        *(.bss*)
        *(COMMON)
        . = ALIGN(4);
        _ebss = .;
    } >RAM

    /DISCARD/ : { *(.ARM.exidx*) }

    ASSERT(_ebss < _estack - 512, "RAM 不够：栈至少要 512 字节")
}
```

四个关键行：

| 行 | 作用 | 漏了会怎样 |
|---|---|---|
| `KEEP(*(.isr_vector))` | 防 GC | **向量表没了 → 上电无反应**（实测） |
| `_sidata = LOADADDR(.data)` | 取 LMA | 写成 `. = .` 拿到 VMA → 全局变量初值是垃圾 |
| `/DISCARD/ : { *(.ARM.exidx*) }` | 去掉 LLVM 硬塞的段 | 多几十字节 Flash |
| `ASSERT(...)` | 链接期栈/静态区冲突检查 | RAM 不够时静默踩内存（实测会报错 vs 不报错） |

⚠ 还有一个实操细节：**要指定 entry**。
实测不加 `-e Reset_Handler` 时 ld.lld 会警告：

```
ld.lld: warning: cannot find entry symbol _start; not setting start address
```

裸机上没有 `_start`（那是 libc 的入口），所以要显式 `-e Reset_Handler`
或者在脚本里写 `ENTRY(Reset_Handler)`。

## 坑点（书 / 常识怎么说 / 实际是什么）

| 书 / 常识怎么说 | 实测是什么 |
|---|---|
| "`--gc-sections` 只丢没用的代码" | 也会丢**向量表**。实测：无 `KEEP` 时 `g_vectors` 直接消失 |
| "`__attribute__((used))` 保证进镜像" | ❌ 只约束编译器。**链接器 GC 管不了**，要 `KEEP`（ch01 实测） |
| "链接脚本只管布局" | 还能 `ASSERT`。实测把 RAM 缩到 512 → `ld.lld: error: RAM 不够：栈至少要 512 字节` |
| "`-fno-unwind-tables` 能去掉 `.ARM.exidx`" | 去不掉。只能在脚本里 `/DISCARD/`（ch01 实测） |
| "入口是 `_start`" | 裸机上是 `Reset_Handler`。实测不加 `-e` 会有 `cannot find entry symbol _start` 警告 |

<details>
<summary>Q1：为什么需要 `KEEP(*(.isr_vector))`？`__attribute__((used))` 不够吗？</summary>

不够，因为**它们约束的是两个不同阶段**。

| 手段 | 约束谁 | 作用 |
|---|---|---|
| `__attribute__((used))` | **编译器** | "即使没人引用，也要把这个符号编译进 `.o`" |
| `KEEP()` in 链接脚本 | **链接器** | "即使没人引用，也不要 `--gc-sections` 掉" |

`--gc-sections` 的工作方式是**从入口点做可达性分析**：
从 `Reset_Handler` 出发，顺着重定位（调用、数据引用）遍历，
凡是走不到的段就丢掉。

向量表的处境很特殊：**没有任何 C 代码"引用"它**——
它是被**硬件**读的（上电时从 `0x00000000` 读两个字）。
所以在链接器的可达性图里，`g_vectors` 是孤立节点 → 被丢。

**实测**（本章跑的对照实验）：

```
有 KEEP：  llvm-nm blink.elf     | grep g_vectors  →  08000000 R g_vectors     ✅
无 KEEP：  llvm-nm blink_nok.elf | grep g_vectors  →  （无输出）                ❌
```

**后果**：没有 `KEEP` 的话，`.bin` 的开头就不是向量表，
板子上电读到的是别的字节 → 立刻 HardFault 或完全不动。
**这是"编译链接一切正常、烧进去毫无反应"的经典原因。**

**同理需要 `KEEP` 的**：

- `.init_array` / `.fini_array`（C++ 全局构造、`__attribute__((constructor))`）；
- 自己定义的"硬件要读"的表（bootloader 的镜像头、CRC 表等）。

**判据一句话**：
**"这个东西是被硬件/外部读的，还是被代码读的？"** 被硬件读 → 一定 `KEEP`。
</details>

<details>
<summary>Q2：`ASSERT` 能检查什么？为什么它比运行时检查好？</summary>

`ASSERT` 在**链接期**求值，能把一整类"运行时玄学"变成"链接失败"。

**能检查的**（用链接脚本里已有的符号）：

```ld
/* ① 静态区和栈有没有撞上（实测过） */
ASSERT(_ebss < _estack - 512, "RAM 不够：栈至少要 512 字节")

/* ② Flash 超了没 */
ASSERT(_etext + SIZEOF(.data) < ORIGIN(FLASH) + LENGTH(FLASH), "Flash 溢出")

/* ③ 某个段必须在特定地址（比如向量表） */
ASSERT(_svector == ORIGIN(FLASH), "向量表不在 Flash 起始")

/* ④ 对齐要求 */
ASSERT((_estack & 7) == 0, "_estack 必须 8 字节对齐")
```

**实测**（把 RAM 从 20K 改成 512）：

```
$ ld.lld -T linker_tiny.ld -o /dev/null startup.o main.o -e Reset_Handler
ld.lld: error: RAM 不够：栈至少要 512 字节

$ ld.lld -T linker.ld    -o /dev/null startup.o main.o -e Reset_Handler
（成功）
```

**为什么比运行时检查好**：

| | 链接期 `ASSERT` | 运行时检查 |
|---|---|---|
| 什么时候发现 | **每次构建** | 要跑到了才发现 |
| 失败形式 | 明确的错误信息 | 静默踩内存 / 偶发崩溃 |
| 代价 | 零（构建时） | 运行时代码 + CPU |
| 覆盖 | 全量（确定的） | 只覆盖被测到的路径 |

栈溢出尤其适合这条：
裸机上栈溢出**不报错**（没有 MMU 守卫页），
只表现为"某个全局变量偶尔变成怪值"——能查一周。
而 `ASSERT(_ebss < _estack - 512)` 在**每次构建**时就把这件事钉死了。

⚠ 但 `ASSERT` **不能**检查"实际会用到多深"——
它只能保证"栈至少有 512 字节可用空间"。
真正会不会溢出，还是要 [ch07 的 `-fstack-usage`](../07-stack-frame-functions/README.md)
配合静态分析。

**两个层次的分工**：

| 阶段 | 手段 | 抓什么 |
|---|---|---|
| 编译期 | `_Static_assert` | 结构体布局、常量计算（[ch08 8.12](../08-complex-types/8.12-结构体与嵌入式编程.md)） |
| **链接期** | `ASSERT` | 内存区间冲突、地址对齐、总量超限 |
| 运行期 | 栈水位魔数、溢出计数 | 实际发生的溢出 |

**能前移的尽量前移**——这是裸机工程里投入产出比最高的一条原则。
</details>

<details>
<summary>Q3：链接时要不要指定 entry？不指定会怎样？</summary>

**要指定**，裸机上入口不是 `_start`。

实测（本仓库的链接命令）：

```
$ ld.lld -T linker.ld -o blink.elf startup.o main.o
ld.lld: warning: cannot find entry symbol _start; not setting start address
```

链接**成功了**，但有警告：
**entry 没有被设置**（`-Map` 里看得到，ELF 头的 `Entry point` 是 0）。

两种指定方式：

```ld
/* 方式①：链接脚本里写 */
ENTRY(Reset_Handler)
```

```bash
# 方式②：命令行
ld.lld -T linker.ld -e Reset_Handler -o blink.elf startup.o main.o
```

**entry 到底影响什么**：

| 影响 | 说明 |
|---|---|
| ELF 头的 `Entry` 字段 | 调试器/gdb 用它知道"程序从哪开始"（`load` 后 PC 设成这个值） |
| **实际硬件行为** | **不受影响**——Cortex-M 上电是从向量表的第 1 项取 PC，不看 ELF 头 |
| `openocd program` / `verify` | 一般也不看 entry |

所以严格说**不指定也不会让板子跑不起来**——
硬件根本不读那个字段。

**但还是要指定**，三个理由：

1. **消除警告**：每次构建都有一条 warning，会淹没真正的警告；
2. **调试器体验**：gdb `load` 之后会把 PC 设成 entry，
   不指定的话 PC 可能是 0 → 单步时看到奇怪的东西；
3. **`--gc-sections` 的起点**：
   GC 的可达性分析需要根（root）。ld.lld 默认把 entry 当根之一——
   不指定的话，`Reset_Handler` 可能靠 `KEEP` 保住，但**它调用的东西**可能被丢掉。

⚠ 第 3 条最实际：本章的实测里 `g_vectors` 被 `KEEP` 保住了，
但如果 `Reset_Handler` 没被当作根，它调用的 `main` 就可能被 GC。
实测里加了 `-e Reset_Handler` 之后链接干净通过。

**规则**：**裸机链接一定显式 `-e Reset_Handler`（或脚本里 `ENTRY()`）。**
</details>
