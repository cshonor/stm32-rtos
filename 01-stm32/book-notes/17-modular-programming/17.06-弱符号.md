# 17.06 弱符号

> 对应实验：主机侧实测（clang 23.1.0 / macOS arm64）
> + **裸机真链接**（`ld.lld` 23.1.0 + 本仓库 `linker.ld`）

## 书这一节讲什么

一句话：**弱符号 = 库/框架给的"默认值"，使用者可以覆盖。
裸机上最经典的用法是默认中断处理函数。**

**这一条在裸机上早就在用了**——
[ch03](../03-embedded-system-programming/README.md) 的 `Default_Handler` 就是。

## 一、实测：弱定义 vs 强覆盖

```c
/* weak_demo.c：库给的默认值 */
__attribute__((weak)) int board_id(void){ return 0; }
int main(void){ printf("board_id() = %d\n", board_id()); }

/* override.c：使用者覆盖 */
int board_id(void){ return 103; }
```

```
$ clang -O1 -o w1 weak_demo.c && ./w1
board_id() = 0              ← 没人覆盖，用弱定义
$ clang -O1 -o w2 weak_demo.c override.c && ./w2
board_id() = 103            ← 强定义覆盖弱定义
```

**四种组合全测了**：

| 情况 | 实测结果 |
|---|---|
| 一个弱，没人覆盖 | ✅ `board_id() = 0` |
| **一个弱 + 一个强** | ✅ `board_id() = 103`（强赢） |
| **两个弱** | ⚠ `board_id() = 0`（**选第一个，不确定**） |
| **两个强** | ❌ `duplicate symbol '_board_id'` |

## 二、⚠ 裸机实测：默认中断处理函数

这是弱符号在嵌入式里**最重要**的用法。模拟启动文件：

```c
void Default_Handler(void) { for (;;) { } }
#define WEAK_ISR(n) __attribute__((weak, alias("Default_Handler"))) void n(void);
WEAK_ISR(NMI_Handler)
WEAK_ISR(HardFault_Handler)
WEAK_ISR(EXTI0_IRQHandler)
WEAK_ISR(USART1_IRQHandler)
```

**① 没人覆盖时**（`llvm-nm`）：

```
08000018 T Default_Handler
08000018 W EXTI0_IRQHandler       ← 大写 W = 弱定义，地址 = Default_Handler
08000018 W HardFault_Handler
08000018 W NMI_Handler
0800001c T Reset_Handler
08000018 W USART1_IRQHandler      ← 四个 ISR 全在 0x08000018
```

**② 提供一个强定义的 `EXTI0_IRQHandler`**：

```
08000018 T Default_Handler
0800002c T EXTI0_IRQHandler       ← ⚠ 变成大写 T（强），地址也变了
08000018 W HardFault_Handler      ← 其余三个没动
08000018 W NMI_Handler
0800001c T Reset_Handler
08000018 W USART1_IRQHandler
```

**这就是全部魔法**：

1. 启动文件**不需要知道你会用哪些中断**——全部预置成弱别名；
2. 你在自己的 `.c` 里写 `void EXTI0_IRQHandler(void){ ... }`（强定义），
   **自动替换**掉默认实现，**不用改启动文件**；
3. 没用到的中断保持默认（死循环）——一旦意外触发，
   调试器能停在那儿让你看到"哦，这个中断来了但我没处理"。

⚠ **`nm` 的大小写含义在这里很关键**：
`W` = 弱定义（weak defined），`w` = 弱**未定义**，`T` = 强定义。

## 三、⚠ 实测：弱【未定义】符号——平台差异很大

```c
__attribute__((weak)) int opt_hook(void);     /* 只声明，不定义 */
if (opt_hook) opt_hook();                     /* 必须先判空！ */
```

| 链接器 | 行为 | 是否实测 |
|---|---|---|
| **ld.lld**（裸机 armv7m） | ✅ **链接成功**，符号解析成 0（`w opt_hook`） | ✅ **本次实测** |
| **macOS ld64** | ❌ **`Undefined symbols for architecture arm64: _opt_hook`** | ✅ **本次实测** |

实测输出：

```
$ ld.lld -T linker.ld -o wu.elf weakundef.o
   ✅ ld.lld 链接成功（未定义弱符号被解析成 0）
      text 36  data 0  bss 4
         w opt_hook          ← 小写 w = 弱未定义
```

```
$ clang -O1 -o w1 weak_demo.c      # macOS ld64，含弱未定义引用
Undefined symbols for architecture arm64:
  "_opt_hook", referenced from: _main in weak_demo-xxxx.o
```

⚠ **这是个真实的移植陷阱**：
同一份"弱钩子"代码，在 GNU ld / lld 上能过，**在 macOS 上链接失败**。

## 四、其他用途

| 用途 | 例子 |
|---|---|
| **默认 ISR** | ch03 的 `Default_Handler`（本节实测） |
| 可选功能钩子 | `__attribute__((weak)) void on_rx_complete(void){}` |
| newlib 的系统调用桩 | `_write`、`_sbrk`、`_read` 都是弱符号，你提供实现就覆盖 |
| 板级适配层 | 弱定义的 `board_early_init()`，各板子可选实现 |
| RTOS 钩子 | FreeRTOS 的 `vApplicationStackOverflowHook`、`vApplicationIdleHook` |

## 五、规则与注意事项

- 弱符号可以被**同名的强符号**覆盖，**不报错**；
- **多个弱符号时选第一个**（实测 `board_id() = 0`）——**不确定，别依赖**；
- 弱符号可以是**未定义的**（只声明不定义）：
  - GNU ld / **lld**：解析成 **0**，代码里要 `if (fn) fn();` 判空；
  - ⚠ **macOS ld64：直接链接失败**（实测）；
- ⚠ **`-ffast-math` 之类的开关不影响弱符号**，
  但 **`--gc-sections` 会丢掉没被引用的弱符号**——通常是好事（省 Flash）；
- ⚠ **弱符号被引用时会把它的实现拉进镜像**，抵消 gc 的收益
  （[17.03](17.03-库.md) 讲过）。

## 坑点

| 坑 | 原书怎么说 | 实际是什么（实测） |
|---|---|---|
| "弱符号就是默认值" | 对 | ✅ 实测：没人覆盖 `0`、强覆盖 `103` |
| "多个弱符号选哪个是确定的" | 没提 | ⚠ **不确定**，实测选第一个（命令行顺序决定） |
| "弱未定义会解析成 0" | 常见说法 | ⚠ **lld 会**（实测 `w opt_hook`），**macOS ld64 直接报错** |
| "两个强定义会像弱符号那样被选一个" | —— | ❌ 实测 `duplicate symbol '_board_id'` |
| "弱符号不影响代码大小" | —— | ⚠ 被引用时会把实现拉进来，抵消 `--gc-sections` |
| "`W` 和 `w` 一样" | —— | ❌ `W` = 弱**定义**，`w` = 弱**未定义**（实测两种都出现过） |

## 代码自测

<details>
<summary>Q1：弱符号在裸机上最经典的用法是什么？</summary>

**默认中断处理函数。**

实测（启动文件把所有 ISR 定义成弱别名指向 `Default_Handler`）：

```
① 没人覆盖：
08000018 T Default_Handler
08000018 W EXTI0_IRQHandler      ← W = 弱定义
08000018 W HardFault_Handler
08000018 W NMI_Handler
08000018 W USART1_IRQHandler     ← 四个都在 0x08000018

② 提供一个强定义的 EXTI0_IRQHandler：
0800002c T EXTI0_IRQHandler      ← 变成 T（强），地址也变了
08000018 W HardFault_Handler     ← 其余三个没动
```

三个好处：

1. 启动文件**不需要知道你会用哪些中断**；
2. 你在自己 `.c` 里写 `void EXTI0_IRQHandler(void)`，**自动替换**，不用改启动文件；
3. 没用到的中断停在 `Default_Handler`（死循环），
   **调试器能让你看到"这个中断来了但我没处理"**——比静默跳过去好查得多。
</details>

<details>
<summary>Q2：`W` 和 `w` 在 `nm` 里有什么区别？</summary>

实测两种都出现过：

| 符号类型 | 含义 | 例子 |
|---|---|---|
| **`W`（大写）** | 弱**定义**（有实现，可被强定义覆盖） | `08000018 W EXTI0_IRQHandler` |
| **`w`（小写）** | 弱**未定义**（只声明不定义，解析成 0） | `w opt_hook` |
| `T`（大写） | 强定义 | `0800002c T EXTI0_IRQHandler` |
| `t`（小写） | 本地（static）函数 | —— |

**判断方法**：看有没有地址。
`08000018 W ...` 有地址 = 有实现；单独的 `w opt_hook` 没地址 = 未定义。

⚠ 弱未定义的符号**必须判空再用**：

```c
__attribute__((weak)) int opt_hook(void);
if (opt_hook) opt_hook();      /* 不判空就是跳到地址 0 */
```
</details>

<details>
<summary>Q3：弱未定义符号在所有平台上都能用吗？</summary>

**不能——实测 macOS 就不行。**

| 链接器 | 行为 | 状态 |
|---|---|---|
| **ld.lld**（armv7m 裸机） | ✅ 链接成功，`w opt_hook` 解析成 0 | **本次实测** |
| **macOS ld64** | ❌ `Undefined symbols for architecture arm64: _opt_hook` | **本次实测** |

实测：

```
# ld.lld
$ ld.lld -T linker.ld -o wu.elf weakundef.o
   ✅ 成功    text 36  data 0  bss 4     w opt_hook

# macOS ld64
Undefined symbols for architecture arm64:
  "_opt_hook", referenced from: _main in weak_demo-xxxx.o
```

⚠ **这是个真实的移植陷阱**：
"库提供可选钩子，用弱未定义 + 判空来实现"这套写法，
在 GNU ld / lld 上是标准做法，**拿到 macOS 上编译就链接失败**。

✅ 更可移植的写法：**弱定义空函数**（而不是弱未定义）：

```c
__attribute__((weak)) void on_rx_complete(void) { /* 默认空 */ }
void uart_isr(void){ ...; on_rx_complete(); }    /* 不用判空 */
```

这样任何链接器都能过，代价是多一个空函数（通常被内联掉，不占空间）。
</details>

<details>
<summary>Q4：弱符号能省 Flash 吗？</summary>

**能，但有前提。**

✅ **省的场景**：库里给 `Default_Handler` 一个弱定义，
你不覆盖 → 所有 ISR 共用**同一个**函数（实测四个 ISR 全在 `0x08000018`）。
如果不用弱符号，就得为每个 ISR 各写一个函数（哪怕都是死循环）。

⚠ **不省反而费的场景**：

1. **弱符号被引用时会把实现拉进镜像**，抵消 `--gc-sections` 的收益
   （[17.03](17.03-库.md)）；
2. **覆盖了**就要付你自己的实现的大小；
3. ⚠ **弱未定义 + 判空**的版本，判空的分支代码也是要的。

**实测的对照**：裸机最小弱钩子程序 text **36 B**——
其中就包含了向量表 + `Reset_Handler` + 判空分支。
**36 B 说明弱符号机制本身几乎不占空间**，真正的开销在你提供的实现里。
</details>
