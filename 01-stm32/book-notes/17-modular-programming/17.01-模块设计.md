# 17.01 模块设计

> 书：第 17 章 模块化编程 · 17.01 模块设计（原书 p227+ 区间内）
> 下一篇：[17.02 命名空间](17.02-命名空间.md)
> 对应实验：主机侧实测（clang 23.1.0 / macOS arm64）+ 交叉编译
> `--target=armv7m-none-eabi -mcpu=cortex-m3`

## 书这一节讲什么

一句话：**一个模块 = 一个 `.h`（公开契约）+ 一个 `.c`（私有实现）；
判断模块化是否成功的标准是"换个板子要改几个文件"。**

本章是全书"工程化"的一章：前面 16 章都在教语言特性，
这一章教的是**怎么把这些特性组织成大型项目**。

## 一、一个裸机模块该长什么样

```c
/* ---- uart.h：公开契约 ---- */
#ifndef UART_H
#define UART_H
#include <stdint.h>
void     uart_init(uint32_t baud);
void     uart_putc(char c);
void     uart_puts(const char *s);
int      uart_getc(void);            /* -1 表示无数据 */
unsigned uart_rx_count(void);
#endif
```

```c
/* ---- uart.c：实现 ---- */
#include "uart.h"
#include "board.h"                    /* 板子相关：基址、时钟 */

/* 寄存器定义：本文件私有 */
#define UART_BASE  BOARD_UART_BASE
#define SR (*(volatile uint32_t *)(UART_BASE + 0x00u))
#define DR (*(volatile uint32_t *)(UART_BASE + 0x04u))

/* 内部状态：static，外部看不到 */
static volatile uint32_t s_rx_count;

/* 内部辅助：static */
static void uart__enable_clock(void){ /* ... */ }

/* 公开接口：与头文件一致，无 static */
void uart_init(uint32_t baud){ uart__enable_clock(); /* ... */ }
```

**三条检验**：

1. `uart.h` 里**没有**任何实现细节（寄存器地址、缓冲区大小）；
2. `uart.c` 里**除了公开接口，全是 `static`**；
3. 换个板子，**只改 `board.h`，`uart.c` 不动**。

## 二、⚠ 实测：模块干不干净，看符号表就知道

同一个模块，两种写法的 `.o` 符号表（`clang -O1 -c` + `llvm-nm`）：

```
--- leaky.o（漏）---
0000000000000008 T _api_get
0000000000000000 T _helper_sum      ← ⚠ 内部辅助函数也全局可见
0000000000000060 S _rx_count        ← ⚠ 内部状态也全局可见

--- clean.o（干净）---
0000000000000000 T _api_get          ← ✅ 只有这一个对外
0000000000000038 b _s_rx_count       ← 小写 b = 本地（static）
```

| | 外部可见符号 | 内容 |
|---|---|---|
| `leaky.o` | **3** | `_api_get` + `_helper_sum` + `_rx_count` |
| `clean.o` | **1** | 只有 `_api_get` |

✅ **这就是模块化的客观指标**：
**一个模块的 `.o` 里，外部可见符号数应该 = 头文件里声明的数量。**

```bash
llvm-nm uart.o | grep -E ' [TDBCS] '   # 大写 = 外部可见（应该很少）
llvm-nm uart.o | grep -E ' [tdbcs] '   # 小写 = static（越多越好）
```

## 三、⚠ 实测：`static inline` 放头文件会"每个 .c 一份"

```c
/* hdr.h */
static inline unsigned inl_add(unsigned a, unsigned b){ return a + b; }
```

两个 `.c` 都 include 它：

```
=== -O0（不内联）===
  use1.o: 0000000000000028 t _inl_add
  use2.o: 0000000000000028 t _inl_add      ← ⚠ 两份，各占 Flash

=== -O1（内联掉）===
  use1.o inl 符号: 0 个
  use2.o inl 符号: 0 个                     ← ✅ 内联进调用点，不生成独立副本
```

| 优化级别 | `inl_add` 的独立副本 | 说明 |
|---|---|---|
| `-O0` | ⚠ **每包含一个 `.c` 一份**（实测两个 `.o` 各有一个 `t _inl_add`） | 小函数无所谓，大的要小心 Flash |
| `-O1`+ | ✅ **0 份**（被内联） | 正常情况 |

⚠ **这就是为什么裸机项目要开优化**：`-O0` 下头文件里的 `static inline`
会变成 N 份真实代码。⚠ 符号是 `t`（本地），所以**不会撞名**，但会占 Flash。

## 四、模块设计检查清单

**头文件（`.h`）**

- [ ] include guard（`#ifndef XXX_H`）——[ch12](../12-preprocessor/README.md) 测过撞名会静默吞掉整个头文件
- [ ] 只有声明，没有实现（除了 `static inline` 的小函数）
- [ ] 不包含实现细节（寄存器地址、缓冲区大小）
- [ ] 所有公开符号有统一前缀（`uart_`、`gpio_`）
- [ ] 类型用 `<stdint.h>` 定宽类型，不用 `int`/`long`
- [ ] 每个函数注明：**做什么、参数范围、返回值语义、会不会阻塞**
- [ ] 标明"ISR 里能不能调"（[ch10](../10-interrupts/README.md) 讲过这是关键信息）

**实现文件（`.c`）**

- [ ] 所有内部函数和变量都是 `static`
- [ ] 寄存器定义放在 `.c` 里，或私有 `xxx_regs.h`
- [ ] 所有寄存器访问都是 `volatile`
- [ ] 有边界检查（裸机上越界是静默的）
- [ ] 关键不变量有 `_Static_assert`
- [ ] 不依赖全局可变状态（可重入性）

**检验命令**

```bash
llvm-nm uart.o | grep -E ' [TDBCS] '     # 泄漏了多少（应等于头文件声明数）
llvm-nm uart.o | grep ' U '              # 需要外部提供什么
clang -fstack-usage ... && cat uart.su   # 栈用量（ch07）
```

## 五、反面例子（常见坏味道）

```c
/* ❌ 坏 */
/* uart.h */
#define USART1_SR (*(volatile unsigned int *)0x40013800)   /* 实现细节泄漏！ */
void set_baud(int baud);                                   /* 无前缀、无单位 */
int  g_rx_count;                                           /* 全局可变状态 */

/* ✅ 好 */
/* uart.h */
void     uart_set_baud(uint32_t baud);
unsigned uart_rx_count(void);        /* 用函数读，不暴露全局变量 */
```

**最后一条判断标准**：

> **"换个板子，我要改几个文件？"**
> 答案是 1（只改 `board.h`），模块化就成功了。

## 坑点

| 坑 | 原书怎么说 | 实际是什么（实测） |
|---|---|---|
| "模块化只是文件拆分" | —— | ⚠ 有客观指标：实测 `leaky.o` 泄漏 **3** 个符号、`clean.o` 只有 **1** 个 |
| "`static inline` 不占空间" | 隐含 | ⚠ `-O0` 下**每个 `.c` 一份**（实测两个 `.o` 各一个 `t _inl_add`）；`-O1` 才是 0 份 |
| "头文件里放点实现方便" | —— | ⚠ 会让每个包含者各得一份副本，且破坏"换板子只改一个文件" |
| "内部变量用全局也行" | —— | ⚠ 实测会变成大写 `S` 符号泄漏出去，还可能撞名 |
| "前缀只是风格" | —— | ⚠ C 没有 namespace，**前缀就是命名空间**（见 [17.02](17.02-命名空间.md)） |

## 代码自测

<details>
<summary>Q1：怎么客观判断一个模块写得好不好？</summary>

看它的 `.o` 泄漏了多少符号。实测对照：

```
--- leaky.o ---                --- clean.o ---
T _api_get                     T _api_get          ← ✅ 只有这一个
T _helper_sum    ← ⚠ 内部函数    （以下都是小写 = 本地）
S _rx_count      ← ⚠ 内部状态    b _s_rx_count
```

| | 外部可见符号数 |
|---|---|
| `leaky.o` | **3** |
| `clean.o` | **1** |

**理想值 = 头文件里声明的函数/变量个数。**

检查命令：

```bash
llvm-nm uart.o | grep -E ' [TDBCS] '   # 大写 = 外部可见
llvm-nm uart.o | grep ' U '            # 还需要外部提供什么
```

⚠ 注意 `nm` 的大小写含义：
**大写 = external（链接器可见），小写 = local（文件内）**。
`T/t` 函数、`D/d` 已初始化数据、`B/b` 未初始化数据、`S/s` small data。
</details>

<details>
<summary>Q2：`static inline` 函数放头文件，会不会重复占用 Flash？</summary>

**取决于优化级别。** 实测（两个 `.c` 都 include 同一个 `hdr.h`）：

| 优化级别 | `inl_add` 的独立副本 |
|---|---|
| `-O0` | ⚠ **2 份**（`use1.o` 和 `use2.o` 各一个 `t _inl_add`） |
| `-O1` | ✅ **0 份**（被内联进调用点） |

- 符号是 **`t`**（本地），所以**不会 multiple definition**——
  这是 `static inline` 能放头文件的原因；
- 但 **`-O0` 下会真生成 N 份代码**，每份都占 Flash；
- ✅ 小函数 + 开优化 → 完全没问题，这也是裸机驱动的常见写法（寄存器访问封装）。

⚠ 大函数别这么干，放 `.c` 里。
</details>

<details>
<summary>Q3：头文件里能不能放寄存器地址宏？</summary>

**不能——这是最常见的坏味道。**

```c
/* ❌ uart.h */
#define USART1_SR (*(volatile unsigned int *)0x40013800)
```

三个后果：

1. **换板子要改头文件**，而头文件是"契约"，改契约意味着所有调用方都要重新审视；
2. **所有包含者都能直接捅寄存器**，模块的封装形同虚设；
3. 宏名没有前缀管理时**撞名概率极高**（`USART1_SR` 这种名字在两个驱动里很容易重复）。

✅ 正确做法：放 `.c` 里，或放一个私有的 `uart_regs.h`（只被 `uart.c` include），
公开头文件里只有 `uart_init()` / `uart_putc()` 这样的函数声明。

**检验标准**：**换个板子（比如 F103 → F407），你要改几个文件？**
如果答案是"只改 `board.h` 或私有寄存器头"，就对了。
</details>

<details>
<summary>Q4：为什么要"用函数读状态"而不是暴露全局变量？</summary>

```c
/* ❌ */ extern int g_rx_count;
/* ✅ */ unsigned uart_rx_count(void);
```

三条理由：

1. **封装**：内部改成环形缓冲、改成 DMA 计数，调用方无感；
2. **防止误写**：`extern int g_rx_count` 谁都能改，改坏了没有任何提示；
3. **实测证据**：全局版本在符号表里是**大写 `S`**（外部可见），
   `static` 版本是**小写 `b`**（本地）——前者泄漏到全局命名空间，
   会撞名（[17.02](17.02-命名空间.md) 实测两个 `rx_count` → duplicate symbol）。

⚠ 在 ISR 里读还要考虑**原子性**：`unsigned uart_rx_count(void)` 内部可以关中断再读，
暴露全局变量则没法保证（[ch10](../10-interrupts/README.md)）。
</details>
