# 17.03 库

> 书：第 17 章 模块化编程 · 17.03 库（原书 p227+ 区间内）
> 上一篇：[17.02 命名空间](17.02-命名空间.md) ｜ 下一篇：[17.04 ranlib 与库链接](17.04-ranlib与库链接.md)
> 对应实验：主机侧实测（clang 23.1.0 + `ar`/`llvm-ar`）
> + **裸机真链接**（`--target=armv7m-none-eabi -mcpu=cortex-m3` + `ld.lld` + 本仓库 `linker.ld`）

## 书这一节讲什么

一句话：**静态库 = 一堆 `.o` 打包；最重要的性质是"链接时只抽取用得上的成员"。**

这对裸机极其重要：**Flash 里不会装进没用到的代码**。

## 一、实测：建库

```
$ clang -O1 -c add.c -o add.o
$ clang -O1 -c mul.c -o mul.o
$ ar rcs libmymath.a add.o mul.o
$ ar -t libmymath.a
__.SYMDEF SORTED
add.o
mul.o
$ llvm-nm libmymath.a
add.o:
0000000000000000 T _add
mul.o:
0000000000000000 T _mul
```

`__.SYMDEF SORTED` 是**索引**（符号名 → 哪个成员），见 [17.04](17.04-ranlib与库链接.md)。

## 二、⚠ 核心实测：只抽用得上的成员

**主机侧**（`main17.c` 只调用 `add`）：

```
$ clang -O1 -o app_only_add main17.c -L. -lmymath && ./app_only_add
add(3,4)=7
$ llvm-nm app_only_add | grep -E "_add|_mul"
0000000100003f68 T _add          ← ✅ 只有 add，mul 完全不在镜像里
```

**换成"两个函数在同一个 `.o`"**（`mymath.o` 里同时有 `add` 和 `mul`）：

```
$ clang -O1 -o app_one_obj main17.c -L. -lmath1 && ./app_one_obj
add(3,4)=7
$ llvm-nm app_one_obj | grep -E "_add|_mul"
0000000100003f60 T _add
0000000100003f68 T _mul          ← ⚠ mul 也被拉进来了！
```

| 库的组织方式 | 只用了 `add`，最终镜像里 |
|---|---|
| `add.o` + `mul.o`（两个成员） | ✅ **只有 `add`** |
| `mymath.o`（一个成员含两个函数） | ⚠ **`add` + `mul` 都有** |

**结论：静态库的抽取粒度是 `.o`（成员）级，不是函数级。**

## 三、⚠ 裸机实测：粒度细化到函数级靠 `--gc-sections`

交叉编译到 M3（`libmath1.a` = 单个 `bmath.o`，含 `add` 和 `mul`，
`Reset_Handler` 只调 `add`）：

```
$ ld.lld -T linker.ld -o nogc.elf bvec.o bapp.o -L. -lmath1
   text 56   data 8   bss 4   → Flash 64 B
   add/mul: 08000030 T add   08000034 T mul      ← ⚠ mul 在

$ ld.lld -T linker.ld --gc-sections -o withgc.elf bvec.o bapp.o -L. -lmath1
   text 52   data 8   bss 4   → Flash 60 B
   add/mul: 0800002e T add                        ← ✅ mul 没了
```

**`mul` 占 4 字节**（56 → 52）。小函数看不出差距，
但一个驱动库里几十个函数时能省下几 KB。

`--print-gc-sections` 能直接看到丢了什么：

```
removing unused section ./libmath1.a(bmath.o):(.text.mul)
removing unused section ./libmath1.a(bmath.o):(.ARM.exidx.text.mul)
```

**两段组合拳**（[ch11](../11-linker/README.md) 讲过）：

```bash
# 编译：每个函数/数据一个 section
clang -ffunction-sections -fdata-sections -c mymath.c

# 链接：丢弃不可达的 section
ld.lld --gc-sections -T linker.ld ...
```

## 四、⚠ 三个会破坏"按需抽取"的东西

| 东西 | 后果 | 出处 |
|---|---|---|
| **`KEEP()`** | 段不会被 GC | [ch11](../11-linker/11.06-高级用法.md)：向量表必须留着 |
| **`.init_array` / `__attribute__((constructor))`** | 被当成可达性分析的 root，整条链都留下 | 同上 |
| **弱符号被引用** | 它的实现会被拉进来 | [17.06](17.06-弱符号.md) |

## 五、裸机上只有静态库

| | PC / Linux | 裸机 STM32 |
|---|---|---|
| 静态库 | `.a` | ✅ `.a` |
| 动态库 | `.so` | ❌ **没有**（没有动态加载器、没有 MMU） |
| 运行时加载 | `dlopen()` | ❌ 没有 |

裸机上所有代码在**链接时**就定死，全部进同一个 Flash 镜像。
所以"按需抽取"是唯一的代码瘦身手段——这也是本章对裸机最重要的意义。

## 六、检验方法

```bash
llvm-size -A app.elf              # 各段大小
llvm-nm app.elf | grep mul        # mul 到底进没进
llvm-nm -s libxxx.a               # 库的索引里有什么
ld.lld --print-gc-sections ...    # 看到底丢了什么
```

## 坑点

| 坑 | 原书怎么说 | 实际是什么（实测） |
|---|---|---|
| "库里的代码都会进镜像" | —— | ❌ **只抽取用得上的成员**（实测：两个成员时 `mul` 完全不在） |
| "抽取粒度是函数级" | —— | ⚠ **是 `.o` 级**：同一个 `.o` 里的 `mul` 会被带进来（实测） |
| "`--gc-sections` 自动生效" | —— | ⚠ 必须配合 **`-ffunction-sections -fdata-sections`**（[ch11](../11-linker/11.05-映射文件.md) 实测过） |
| "裸机能用动态库" | —— | ❌ 没有动态加载器，只有静态库 |
| "`KEEP()` 无所谓" | —— | ⚠ `KEEP` 的段**不会被 GC**（向量表需要它，但别滥用） |

## 代码自测

<details>
<summary>Q1：静态库里的代码会不会全都进我的固件？</summary>

**不会——但粒度是 `.o` 级，不是函数级。**

链接器处理 `.a` 的行为：

```
1. 查库的索引（__.SYMDEF）
2. 看当前"未解决符号表"里有哪些符号
3. 只抽取能提供这些符号的 .o 成员
4. 被抽出来的成员可能又引入新的未解决符号 → 继续解决
```

实测对照（只用了 `add`）：

| 库的组织 | 镜像里的符号 |
|---|---|
| `libmymath.a`（`add.o` + `mul.o`） | ✅ 只有 `_add` |
| `libmath1.a`（`mymath.o` 含两个函数） | ⚠ `_add` + **`_mul`** |

**要把粒度细化到函数级**，必须两段组合拳：

```bash
clang -ffunction-sections -fdata-sections -c mymath.c   # 每个函数一个 section
ld.lld --gc-sections -T linker.ld ...                    # 丢不可达的 section
```

裸机实测：`mul` 占 **4 字节**（text 56 → 52）。
</details>

<details>
<summary>Q2：`--gc-sections` 为什么有时候不生效？</summary>

三个常见原因：

1. **没加 `-ffunction-sections -fdata-sections`**——
   一个 `.o` 的所有代码都在同一个 `.text` 段里，GC 只能整段留或整段丢，
   丢不了单个函数（[ch11](../11-linker/11.05-映射文件.md) 实测过：
   只加 `--gc-sections` 时 134/8 → 134/8，**一点没变**）。
2. **链接脚本里有 `KEEP()`**——`KEEP` 的段是 GC 的 root，不会被丢。
   向量表必须这样保护，但如果误把别的东西也 `KEEP` 了就白搭。
3. **代码被当成可达性 root**：`.init_array`、`__attribute__((constructor))`、
   或被弱符号引用。

✅ 排查命令：

```bash
ld.lld --print-gc-sections -o app.elf ...   # 看丢了什么、什么没丢
llvm-nm app.elf | grep 不该出现的函数名
```
</details>

<details>
<summary>Q3：裸机上有动态库吗？</summary>

**没有。** 裸机没有动态加载器，也没有 MMU 做地址重映射，
所有代码在**链接时**就定死，全部编进同一个 Flash 镜像。

| | PC / Linux | 裸机 |
|---|---|---|
| 静态库 `.a` | ✅ | ✅ |
| 动态库 `.so` | ✅ | ❌ |
| `dlopen()` 运行时加载 | ✅ | ❌ |

⚠ 这意味着"按需抽取 + `--gc-sections`"是裸机**唯一**的代码瘦身手段，
也是本章对裸机最重要的意义：
**Flash 只有 64 KB（F103C8）时，"库里有多少代码"和"固件有多大"是两回事。**

⚠ 顺带一提：裸机上有时需要"运行时换代码"（ bootloader 跳到 app），
那是**两个独立的链接产物 + 固定的跳转地址**，不是动态库。
</details>
