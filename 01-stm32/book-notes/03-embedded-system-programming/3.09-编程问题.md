## Q1：把 LED 从 PA5 换到 PA6，要改几处？

**答案：三处，其中两处是同一个数。**

```c
/* ① 引脚号 */
#define LED_PIN  5u     →    #define LED_PIN  6u

/* ② 引脚配置：CRL 里 PA5 占 bits[23:20]，PA6 占 bits[27:24] */
GPIOA_CRL &= ~(0xFu << (LED_PIN * 4u));    ← 这行不用改（跟着 LED_PIN 走）
GPIOA_CRL |=  (0x2u << (LED_PIN * 4u));    ← 这行也不用改

/* ③ BSRR 的两处 */
GPIOA_BSRR = (1u << LED_PIN);
GPIOA_BSRR = (1u << (LED_PIN + 16u));      ← 两处都跟着 LED_PIN
```

**所以正确答案是：只改 `LED_PIN` 一个数。**

这正是"**把 0x20 这种魔数抽成宏**"的价值。反过来，如果代码里到处写：

```c
GPIOA_CRL  |=  (0x2u << 20);
GPIOA_BSRR =   (1u << 5);
GPIOA_BSRR =   (1u << 21);
```

换个引脚要改 3 处、算对 3 次位偏移（`21 = 5 + 16` 这种还会算错）。**这是最典型的
"省 5 秒、赔 30 分钟"的写法。**

**验证方法**：改完 `make regs`，看反汇编里的立即数（`bic`/`orr` 的常量应该
从 `0xf00000`/`0x200000` 变成 `0xf000000`/`0x2000000`）。

> ⚠ **注意 PA13/PA14/PA15 不能拿来点灯**（它们是 SWDIO/SWCLK/JTDI，
> 实测复位值 `8` = 上下拉输入，是给调试口用的）。**换引脚前先看板子原理图。**

## Q2：`GPIOA_CRL &= ~(0xFu << (LED_PIN * 4u));` 里的 `~` 能不能省？

**答案：不能省，省了就变成"把所有位都置 1"。**

```c
0xFu << 20        = 0x00F00000
~(0xFu << 20)     = 0xFF0FFFFF     ← 只有 PA5 那 4 位是 0，其余全 1
GPIOA_CRL &= 0xFF0FFFFF            ← 与操作：PA5 的 4 位被清零，其余位保持不变 ✅
```

如果省掉 `~`：

```c
GPIOA_CRL &= 0x00F00000     /* ❌ 只有 PA5 那 4 位可能非 0，其余 28 位全被清成 0 */
```

结果是 `CRL` 里其他 7 个引脚全变成 `0000`（模拟输入）。**更隐蔽的是**：
如果 `0x2u << 20` 那行接着执行，PA5 会正常配好 —— **看起来灯还是亮的**，
但 PA0–PA4/PA6/PA7 的配置已经被毁了。这种"功能正常但埋了雷"的 bug 最难查。

**为什么"清"这一步必须存在**：因为 `CRL` 的复位值是 `0x44444444`（不是 0）。
不清就直接 `|=`：

```c
GPIOA_CRL |= (0x2u << 20);      /* 0x44444444 | 0x00200000 = 0x44644444 */
                                /* PA5 = 0b0110 = 通用开漏输出 2MHz —— 不是我要的推挽！*/
```

**实测对照**（本章实验的真值）：

| 操作 | `GPIOA_CRL` | PA5 的 4 位 |
|---|---|---|
| 复位 | `0x44444444` | `0100` 浮空输入 |
| 只 `\|=`（错误） | `0x44644444` | `0110` 通用开漏 ❌ |
| 先 `&= ~` 再 `\|=` | `0x44244444` | `0010` 通用推挽 ✅ |

一个 `~` 的差别，是"推挽"和"开漏"的差别 —— **后者驱动不了 LED 的高电平**。

## Q3：把翻转改成 `GPIOA_ODR ^= (1u << 5);` 行不行？

**答案：能亮，但有三个问题，都不该用。**

```c
GPIOA_ODR ^= (1u << 5);     /* 读-改-写：ldr → eor → str，3 条指令 */
```

| 问题 | 说明 |
|---|---|
| **① 非原子** | `ldr` 和 `str` 之间可以被中断打断。若 ISR 也改了同一个 `ODR` 的另一位，你的 `str` 会把它的修改覆盖掉（第 10 章会正面撞上这个） |
| **② 会动别人的位** | `ODR` 复位值是 `0x0000a000`（bit13/15 = 1，调试口上拉）。读-改-写**本身是安全的**（只翻转 bit5），但只要你写成 `GPIOA_ODR = 0x20`（赋值而非 `^=`），这两个上拉位就被抹了 |
| **③ 慢** | 3 条指令 vs `BSRR` 的 1 条。够不够快？在闪烁这种场景完全够，**但在高频翻转（软件 PWM、DMA 触发）里就是瓶颈** |

**实测反汇编对比**：

```asm
; ODR ^= (1<<5)
ldr   r1, [r0]           ; 读
eor   r1, r1, #0x20      ; 改
str   r1, [r0]           ; 写回

; BSRR = (1<<5)
str.w r12, [r0, #0x10]   ; ★ 就一条
```

**正确写法**：

```c
GPIOA_BSRR = (1u << 5);           /* 置位 */
GPIOA_BSRR = (1u << (5u + 16u));  /* 复位 */
/* 或 */
GPIOA_BRR  = (1u << 5);           /* 复位（BSRR 高 16 位的专用版） */
```

**顺带一个知识点**：`BSRR` **读回来恒为 0**（实测 `0x40010810: 00000000`）——
它是"写操作的门"，不是"存储"。想验证输出状态要读 `ODR`。

## Q4：`.bin` 为什么是 376 字节？把算式写出来。

**答案：376 = 96（`.isr_vector`）+ 280（`.text`）+ 0（`.data`）。**

```console
$ make
section                   size        addr
.isr_vector                 96   134217728     ← 0x08000000
.text                      280   134217824     ← 0x08000060 = 0x08000000 + 0x60
.data                        0   536870912
.bss                        16   536870912     ← 不占 Flash（NOBITS）
.noinit                      8   536870928     ← 不占 Flash（NOBITS）
.flash_overflow_check        0   134218104
.ARM.attributes             37           0     ← 非分配段，不进 .bin
```

**关键点**：`.bin` = 所有 **`PROGBITS`** 段按地址拼起来（空洞补 0）。
`NOBITS` 段（`.bss`/`.noinit`）**一个字节都不占 Flash**。

验证：

```console
$ llvm-readelf -S blink_gpio.elf | grep -E "bss|noinit|data"
  [ 3] .data     PROGBITS  20000000 010178 000000
  [ 4] .bss      NOBITS    20000000 020000 000010    ← NOBITS
  [ 5] .noinit   NOBITS    20000010 020000 000008    ← NOBITS
```

**为什么"段大小加起来 ≠ .bin"是一个常见困惑**：

```
96 + 280 + 0 + 16 + 8 = 400  ❌
96 + 280 + 0          = 376  ✅
```

差 24 字节正是 `.bss`(16) + `.noinit`(8)。**它们的空间是 RAM，内容是启动代码
现造出来的**（`.bss` 清零、`.noinit` 什么都不做）—— 所以没有东西需要写进 Flash。

**延伸**：`.elf` 134856 字节里，除了这 376 还有 13 万多 ——
全是 DWARF 调试信息 + 符号表 + 段头表，**全部不进 Flash**。
`-g` 不花 Flash，只花磁盘。

## Q5：`boot_stage` 为什么必须放 `.noinit`？放 `.bss` 会怎样？

**答案：放 `.bss` 会被启动代码清零，你永远读到 0。**

`Reset_Handler` 干三件事（实测反汇编，[3.07](3.07-逐步执行程序.md)）：

```asm
0x08000060  ldr  r0, [pc, #56]        ; &boot_stage
0x08000062  movs r1, #1
0x08000064  strb r1, [r0]             ; 面包屑 1（上电瞬间）
...                                    ; 搬 .data（Flash → RAM）
0x08000080  ldr  r0, [pc, #24]
0x08000082  movs r1, #3
0x08000084  strb r1, [r0]             ; 面包屑 3（.data 搬完）
0x08000086  ldr  r1, [pc, #36]
...                                    ; 清 .bss（写 0 循环）
```

**`.bss` 的清零循环在启动代码里是必做的**（C 标准要求静态变量初值为 0）。
所以 `.bss` 变量**每次上电都被清成 0** —— 面包屑写了也白写。

`.noinit` 的做法是：**在链接脚本里声明一段 RAM，但启动代码不清它**：

```ld
.noinit (NOLOAD) : {          /* NOLOAD：ELF 里是 NOBITS，不进 Flash */
    _snoinit = .;
    *(.noinit)
    _enoinit = .;
} > RAM
```

**实测效果**（本实验的经典证据）：

```console
(gdb) break main
Breakpoint 1, main () at main.c:70
70	    boot_stage = 1;
(gdb) printf "boot_stage=%u\n", boot_stage
boot_stage=3            ← ★ 上一次运行的最后状态！不是 0
```

**这是裸机上少数几个"黑匣子"**。用途：

| 用途 | 做法 |
|---|---|
| 判断"是冷启动还是热复位" | 上电后先读，非 0 说明是看门狗/异常导致的复位 |
| 定位"死在哪一步" | 每完成一个阶段写一个不同的值，复位后读回来的值就是最后活着的阶段 |
| 保留跨复位的配置 | 比如"上次的波特率",避免每次上电重新协商 |

**两个必知的限制**（都在本章实测过）：

1. **`strb` / `str` 混用会导致高字节残留**（[3.07 Q2](3.07-逐步执行程序.md)）。
2. **`.noinit` 不清零 ≠ 有初值**。如果你想"第一次默认 0，之后保留"，
   必须**自己判断非法值**（比如用一个 magic 数）—— 否则第一次读到的是**随机数**：

```c
#define MAGIC 0x5A5AC0DEu
__attribute__((section(".noinit"))) volatile uint32_t magic;
__attribute__((section(".noinit"))) volatile uint32_t saved_cfg;

if (magic != MAGIC) { magic = MAGIC; saved_cfg = 0; }   /* 首次运行 */
```

## Q6：不烧任何程序，怎么用调试器点亮 LED？按顺序写出命令。

**答案：四步，第一步是开时钟（跳过它，后面全废）。**

```console
(gdb) target remote localhost:3333

# 步骤 1：开 GPIOA 时钟 —— 这一条不做，后面三步全部静默失败
(gdb) set {unsigned int}0x40021018 = 0x4
(gdb) x/1xw 0x40021018
0x40021018:	0x00000004        ← 必须验证！读回 = 4 才继续

# 步骤 2：把 PA5 配成 2MHz 通用推挽输出
(gdb) set {unsigned int}0x40010800 = 0x44244444
(gdb) x/1xw 0x40010800
0x40010800:	0x44244444

# 步骤 3：写 BSRR 置位 PA5
(gdb) set {unsigned int}0x40010810 = 0x20
(gdb) x/1xw 0x4001080c
0x4001080c:	0x0000a020        ← ★ bit5 = 1，LED 亮

# 步骤 4：写 BRR 复位
(gdb) set {unsigned int}0x40010814 = 0x20
(gdb) x/1xw 0x4001080c
0x4001080c:	0x0000a000        ← bit5 = 0，LED 灭
```

**反面对照（本次实测的一半）**：跳过步骤 1，直接写 `BSRR`：

```console
(gdb) set {unsigned int}0x40010810 = 0x20
(gdb) x/1xw 0x4001080c
0x4001080c:	0x0000a000        ❌ 没变，灯不亮（因为时钟是关的）
```

**为什么这一步值得单独作为一道题**：它把"必须先开时钟"从一个**口诀**
变成了一个**带硬件机制的事实** —— 连调试器通过 SWD 直接写总线都写不进去，
说明这是**时钟门控**（寄存器单元的访问被物理切断），不是软件检查。

**排障用法**：这是"灯不亮"的二分之一刀 ——
`mww` 能点亮 ⇒ 硬件通路 OK，问题在代码；`mww` 也点不亮 ⇒ 先查 `RCC_APB2ENR` bit2。

## Q7：想让 LED 闪快一倍，改哪里？有什么风险？

**答案：把 `delay(400000u)` 改成 `200000u` —— 但这只是"看起来对"。**

**风险一：实际频率不是线性的。**
实测 `delay(400000)` 得到半周期 **428 ms**，反推每次迭代 **8.6 个周期**
（不是直觉的 4 个周期：`volatile` 参数让每次迭代多出 `ldr`+`str`，见 [3.03 Q4](3.03-你的第一个嵌入式程序.md)）。
改成 200000 会得到约 214 ms —— **大致减半，但误差在 ms 级别**。

**风险二：优化等级一变，全部重来。**
`-O0`/`-Os`/`-O2` 下同一个 `delay(200000)` 的实际时间不同（实测 `-O0` 与 `-Os`
的 `.text` 差 4%，但**循环体指令数可能差更多**）。所以这个"延时值"是**和
编译器选项绑定的魔数**。

**风险三：主频一变，全部重来。**
本实验跑在默认 HSI 8 MHz。一旦你在 `main` 里配了 PLL（比如跑到 72 MHz），
`delay(400000)` 就快了 9 倍 —— 闪烁频率从 1.17 Hz 变成约 10 Hz。

**风险四：中途被打断就不准了。**
`delay` 期间 CPU 全在空转、**且不响应任何事件**（没有中断的话）。
后面加上中断后，中断处理时间会**累加**进延时。

**正确答案：换成硬件计时器。**

```c
/* 用 SysTick：延时值 = 时间 × 频率，与优化等级无关 */
static void delay_ms(uint32_t ms) {
    uint32_t start = systick_millis();
    while ((int32_t)(systick_millis() - start) < (int32_t)ms) { /* spin */ }
}
```

好处：**改时间不用重算魔数、不受优化影响、不受主频影响**（只要时钟树配对了）、
不同编译器/板子之间可移植。**这就是补充篇 ch19 的主题。**

## Q8：为什么这个实验用 F103RB，而书里用 F030R8？代码能直接互换吗？

**答案：不能直接用，但"要改的地方是固定的几处"。**

| 项 | 书：NUCLEO-F030R8 | 本实验：NUCLEO-F103RB | 影响 |
|---|---|---|---|
| 内核 | Cortex-M0 | **Cortex-M3** | 指令集不同（M0 无 Thumb-2、无 `str.w`、无硬件除法） |
| Flash / RAM | 64K / 8K | **128K / 20K** | `linker.ld` 的 `MEMORY` 两个数字 |
| **GPIO 配置寄存器** | `MODER`（每脚 **2 位**） | `CRL`/`CRH`（每脚 **4 位**） | ★ **最大的差异**，配置代码完全不同 |
| GPIO 时钟使能位 | `RCC_AHBENR` 的 `IOPAEN` | `RCC_APB2ENR` 的 `IOPAEN`(bit2) | 寄存器名和总线都不同 |
| 复位值 | 不同 | `CRL=0x44444444` | —— |
| 中断向量表 | 每系列不同（IRQ 号不同） | `startup_stm32f103xb.s` | 换芯片要换启动文件 |
| 调试口 | 相同（SWD） | 相同 | —— |

**"通用"的部分**（跨系列基本不变）：

- **启动流程**：取 MSP → 取 Reset_Handler → 搬 `.data` → 清 `.bss` → `bl main`
- **`.isr_vector` 前两个字**（MSP + Reset_Handler）
- **`BSRR` 的存在与语义**（低频系列也有，F0 叫 `BSRR`/`BRR`）
- **调试链路**（SWD、openocd、gdb 那一套）

**实测证据**（本实验顺手拿到的）：`GPIOA_CRH = 0x88844444` —— PA13/14/15 的
复位值是 `8`（上下拉输入），因为它们要当 SWDIO/SWCLK/JTDI。
**这个"例外"来自芯片设计，不是系列差异** —— 所有 STM32 都这样。

**结论**：跨系列移植时，
**"能抄的是结构（启动/时钟/BSRR），必须重写的是配置（引脚配置寄存器的位布局）"。**
最省事的做法是让工具生成（CubeMX），最涨知识的做法是**对着新系列的参考手册
把配置那一节重写一遍** —— 本仓库选后者，因为目标就是理解机制。
