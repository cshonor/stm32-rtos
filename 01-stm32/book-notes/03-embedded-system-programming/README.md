## 这一章在讲什么

**让一颗 LED 亮起来，然后证明它真的在亮。**

这条主线看起来简单，但它逼着你把整条链路走通一遍：

```
板子是什么（3.1） → 代码住在哪（3.2） → 写出第一个程序（3.3）
      → 它是怎么变成 Flash 里的字节的（3.4）
      → 项目里哪些文件是源、哪些是产物（3.5）
      → 怎么停下来看它到底做了什么（3.6）
      → 怎么一行一行走（3.7）
```

**3.3 是本章的核心**：它一条直线走完"开时钟 → 配引脚 → 翻转"，
中间任何一步错了灯就不亮。后面四节（3.4–3.7）都是**验证手段** ——
让你在"灯不亮"的时候有办法定位，而不是瞎改代码。

## 与书的差异（重要）

| 书 | 本仓库 | 为什么 |
|---|---|---|
| 板子：**NUCLEO-F030R8**（Cortex-M0，64K/8K） | **NUCLEO-F103RB**（Cortex-M3，128K/20K） | 手上有这块板；M3 有 Thumb-2，反汇编更直观。**引脚配置寄存器完全不同**（`MODER` 2 位 vs `CRL/CRH` 4 位），笔记里两套都标了 |
| IDE：**System Workbench for STM32** | **不用 IDE**：clang + ld.lld + make + openocd + gdb | SW4STM32 已停止维护；而且本章目标就是"看清机制"，IDE 恰好把机制藏起来 |
| 编译器：`arm-none-eabi-gcc` | **clang 23.1.0 + ld.lld** | 工具链纪律（见 [1.1](../01-hello-world/1.1-安装GCC.md)） |
| 点 "Build" 按钮 | `make`（3 行命令） | 可以 diff、可以 code review |
| 用 GUI 看变量 | `openocd` + `arm-none-eabi-gdb`（两终端） | 命令行可控、可脚本化；`monitor` 能看到的比 GUI 多 |
| LED 接在 PA5（和书一致） | PA5 ✅（沿用，方便对照） | —— |

**书里没有、本仓库补上的**：

- **`portprobe.c` 探针实验**：实测"外设时钟没开时读写寄存器会怎样"
  （3.3.1 / 3.3.3）—— 书上只说"必须先开时钟"，没说"不开会怎样"。
- **`.noinit` 面包屑 + 调试器读回**：把"代码真的改了硬件"变成**可复核的证据**，
  不靠"灯亮不亮"这种主观判断（灯还可能被 SB 跳线断开）。
- **`-fstack-usage` 量化栈用量**（3.4）—— 裸机没有守卫页，这个必须自己量。

## 读完本章你应该能回答

- 为什么"开时钟"是第一件事？**不开会怎样**（三个具体后果）？
- `GPIOA_CRL` 的复位值为什么是 `0x44444444` 而不是 0？
- 为什么改单个引脚用 `BSRR` 而不是 `ODR ^=`？（从指令数说）
- `.elf` 十三万字节，为什么烧进去的只有 376 字节？
- `.noinit` 和 `.bss` 有什么区别？为什么面包屑变量必须放前者？
- 复位后 `boot_stage` 能读到上一次运行的值 —— **为什么**，以及怎么验证？
- 为什么 Flash 上的程序只能用**硬件断点**？数量限制是多少？
- `monitor reset halt` 之后 `info registers` 为什么是错的？正确姿势是什么？
- 单步时行号为什么会"乱跳"？冲突时该信谁？
- 不烧程序，只用调试器点亮 LED —— 四步顺序是什么？为什么第一步不能省？

## 本章技术债（诚实记录）

| 债 | 为什么现在不还 |
|---|---|
| `delay()` 是空循环，精度受优化/主频影响 | 本章目标是"看清寄存器"，不是"精确定时"。ch19 还 |
| `main` 里是 `for(;;)` 死循环 | 还没有中断/任务的概念。ch10 / ch20 还 |
| 寄存器地址直接 `#define`，没做结构体映射 | 过早抽象会看不清"哪一位在起作用"。第 8 章 / ch17 还 |
| GPIO 点灯部分只在 PA5（LED）和 PC13（按键读数）实测过 | 按键的**逻辑处理**（去抖/边沿）属于第 5 章 |
