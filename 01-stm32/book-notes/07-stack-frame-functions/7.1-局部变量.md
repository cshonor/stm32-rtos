# 7.1 局部变量

> 书：第 7 章 局部变量和函数 · 7.1 局部变量（原书 p89–97 区间内）
> 下一篇：[7.2 隐藏变量](7.2-隐藏变量.md)
> 对应实验：`--target=armv7m-none-eabi -mcpu=cortex-m3`（`-O0` / `-Os` 两档 + `-fstack-usage`）

## 书这一节讲什么

一句话：**局部变量是函数内部声明的变量，进来就有，出去就没**。

PC 上这是个不需要思考的概念。在裸机上它变成一个**必须预算的资源**：

- 栈的大小是**链接脚本里写死的一行**（`_estack = ORIGIN(RAM) + LENGTH(RAM)`）；
- **没有 MMU、没有守卫页**，栈溢出不报错，只会静静踩掉 `.bss`/`.data`；
- 局部变量的多少和大小，直接决定这条调用链会不会爆栈。

## 一、实测：局部变量到底占多少栈

```c
int leaf(int a, int b){ volatile int t = a + b; return t; }
int with_locals(int n){ int buf[8]; int i; int s=0;
    for(i=0;i<8;i++) buf[i]=n+i;
    for(i=0;i<8;i++) s+=buf[i];
    return s; }
```

```
$ clang --target=armv7m-none-eabi -mcpu=cortex-m3 -mthumb -Os -fstack-usage -c ch07.c -o ch07_os.o
$ cat ch07_os.su
ch07.c:1:leaf         4    static
ch07.c:2:with_locals  32   static

$ clang ... -O0 -fstack-usage -c ch07.c -o ch07_o0.o
$ cat ch07_o0.su
ch07.c:1:leaf         12   static     ← 同一个函数，栈用量翻 3 倍
ch07.c:2:with_locals  44   static
```

**同一个函数，`-Os` 和 `-O0` 的栈用量差 3 倍。**
`with_locals` 的 `int buf[8]` 是 32 字节，正好等于 `-Os` 报的数字；
`-O0` 下多出的 12 字节是给 `i`、`s`、参数 `n` 各自在栈上留的位置
（`-Os` 把它们放寄存器里了）。

## 二、局部变量放哪：三种可能

| 落点 | 什么时候 | 代价 |
|---|---|---|
| **寄存器** | `-Os`/`-O2` 下，短生命周期的标量 | 0（最快，不占内存） |
| **栈** | 需要取地址、寄存器不够、或 `-O0` | 每帧几到几十字节 |
| **静态区**（`static` 局部） | 显式写 `static` | `.bss`/`.data`，**不占栈** |

第三条是裸机上最重要的：**大局部数组一律改成 `static`**。

```c
void parse(void){
    char line[64];          /* 64 B 栈：可接受 */
    static char big[1024];  /* 1 KB：改静态，进 .bss，编译期就能从 map 文件看到总量 */
}
```

## 三、判据：放栈还是放静态区

**判据一（生命周期）**：这个变量是"每次调用一份"还是"全局一份"？

| 放栈 | 放静态区 |
|---|---|
| 每次调用要一份新的 | 全局只要一份 |
| 函数返回就没了 | 程序活着就在 |
| 临时缓冲、循环变量、解析中间量 | 驱动状态、环形缓冲、配置、统计计数 |

**判据二（大小）**：在 20 KB RAM 上，**单个局部数组超过 ~128 字节就要停下来想**。

**静态区的代价：不可重入。** 递归调用、中断嵌套、RTOS 多任务下，
静态缓冲会被覆盖——需要临界区保护（[10.3 中断例程](../10-interrupts/10.3-中断例程.md)）。

## 四、未初始化的局部变量 = 栈上旧数据

```c
void f(void){ int x; printf("%d", x); }     /* 值是上一次调用留下的 */
```

[4.4 初始化](../04-numbers-and-bitops/4.4-初始化.md) 展开过：
PC 上"碰巧"是 0（OS 给的新页清零），**裸机的栈是同一块 RAM 反复复用**，
读到的是上一次调用的残留。裸机纪律：**声明时给初值，或第一次使用前赋值。**

## 坑点（书 / 常识怎么说 / 实际是什么）

| 书 / 常识怎么说 | 实际是什么 |
|---|---|
| "局部变量在函数里，很便宜" | 栈用量随**优化等级**变：实测 `leaf` 4（-Os）vs 12（-O0）字节 |
| "局部变量随便声明" | 大数组压栈会吃掉 20 KB 预算里的一大块。实测 `buf[8]` 就 32 字节 |
| "未初始化的局部变量是 0" | ❌ 是栈上残留。裸机没有 OS 清零新页这回事 |
| "`static` 局部只是延长生命周期" | 它同时把变量**从栈挪到 `.bss`**——裸机上大缓冲必须这么放 |
| "栈够不够跑一下就知道" | 栈溢出**不报错**。要 `-fstack-usage` 静态算 + 运行时水位（[7.4](7.4-栈帧.md)） |

## 代码自测

<details>
<summary>Q1：为什么同一个函数 `-Os` 和 `-O0` 的栈用量差 3 倍？</summary>

因为**优化器决定了多少个变量能留在寄存器里**。

实测 `leaf(int a, int b){ volatile int t = a + b; return t; }`：

```
-Os:  4 字节    ← 只有 volatile 的 t 必须在栈上（volatile 要求它有真实地址）
-O0: 12 字节    ← a、b、t 各自在栈上占一个位置，每次用都 ldr/str
```

看 `-O0` 的反汇编就明白了：

```
00000000 <leaf>:
       0: b083     sub  sp, #0xc        ← 12 字节
       2: 9002     str  r0, [sp, #0x8]  ← 参数 a 存栈
       4: 9101     str  r1, [sp, #0x4]  ← 参数 b 存栈
       6: 9802     ldr  r0, [sp, #0x8]  ← 用的时候再取出来
       8: 9901     ldr  r1, [sp, #0x4]
       a: 4408     add  r0, r1
```

`-O0` 的策略是"每个变量都有固定的栈槽，一一对应源码"——**为了调试器能随时查看**。
`-Os` 则把能放寄存器的都放寄存器，只留非留不可的（这里是 `volatile` 的 `t`）。

工程含义：

1. **别用 `-O0` 的数据估算栈预算**（会高估），也别用 `-Os` 的数据做最坏情况（会低估——
   万一哪天换了编译器/优化等级）；
2. 用**发布时的优化等级**跑 `-fstack-usage`，再留 2 倍余量；
3. 最可靠的是运行时水位（栈区填魔数，看被改到哪）。
</details>

<details>
<summary>Q2：`static` 局部变量和全局变量有什么区别？</summary>

两个区别，第二个才是关键：

**① 作用域**：`static` 局部只在声明它的函数里可见（命名空间干净）；
全局在整个工程可见（除非再加 `static` 限定到文件）。

**② 存储期**：两者都在静态区（`.bss`/`.data`），
**都在 `main` 之前就已经存在**，且只初始化一次。

```c
void counter(void){
    static uint32_t n = 0;    /* 只在第一次"执行到"时初始化一次（C 语义），
                                 实际是编译期放进 .data/.bss */
    n++;
}
```

裸机上关键的两点：

- **`static` 局部的初值也遵循"非 0 才进 `.data`"**：`static int x;` 在 `.bss`，
  `static int x = 5;` 在 `.data`（占 Flash）。
- **不可重入**：同一份内存被所有调用者共享。

| 场景 | 用 `static` 局部安全吗 |
|---|---|
| 只被主循环调用 | ✅ |
| 会被 ISR 和主循环同时调用 | ❌ 需要临界区（[10.3 中断例程](../10-interrupts/10.3-中断例程.md)） |
| 递归 | ❌ 各层互相覆盖 |
| RTOS 多任务共享 | ❌ 需要互斥（FreeRTOS，本仓库 `02-freertos/`） |

所以裸机的规则是：**需要"全局一份"才用 `static`；需要"每调用一份"就必须放栈**
——而"每调用一份 + 很大"是矛盾需求，这时通常要重新设计（比如改成调用者提供缓冲区）。
</details>

<details>
<summary>Q3：多大的局部数组算"太大"？</summary>

取决于**这条调用链上还有谁**，而不是绝对值。判据是比例：

NUCLEO-F103RB 的 RAM 是 **20 KB**，栈从 `_estack = 0x20005000` 往下长，
可用空间 = 20 KB − `.data` − `.bss` − 中断帧预留。

经验阈值（本仓库的口径）：

| 大小 | 建议 |
|---|---|
| ≤ 64 B | 放栈，随便用 |
| 64–256 B | 放栈，但要确认这条调用链上只有它一个 |
| 256 B – 1 KB | **优先改 `static`**，或在设计上改成调用者传缓冲 |
| > 1 KB | 必须 `static` 或全局；放栈就是在赌 |

为什么这些数字这么小：还要留**中断帧**。Cortex-M 进中断时硬件自动压 8 个寄存器
（32 字节，可能再加对齐），这是**叠加在最深调用链之上**的
（[10.3 中断例程](../10-interrupts/10.3-中断例程.md) 会展开）。

算账的例子：

```
main(8) → parse(32) → read_frame(64) → uart_getc(24)   = 128 字节
                                        + 中断帧 32 字节
                                        = 160 字节（正常路径）

如果 parse 里有个 1 KB 的局部数组 → 立刻变成 1152 字节，
且这是"栈峰值"——同一时刻只有一条链在跑，但那条链上的**所有帧**是叠加的。
```

工具：`-fstack-usage` 给每函数的单帧数（[7.4](7.4-栈帧.md)）；
`-Wframe-larger-than=256` 可以直接让编译器对超限的单帧报警。
</details>
