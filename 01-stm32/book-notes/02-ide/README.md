## 这一章在讲什么

书用 System Workbench for STM32 演示"IDE 怎么用"，
但**真正值钱的只有 2.2 一节**——它回答"IDE 到底替你做了什么"。

把这一节答清楚，IDE 就不是黑盒：换任何 IDE、或者根本不用 IDE，你都知道该敲什么。

## 只看这一页（速览）

**主线一句话：** 本章把 IDE 这个黑盒拆开——2.1 先用书里演示的三个按钮（建工程/Build/Debug）说明"会过时的只有按钮位置"，2.2 给出全章的核心答案"IDE 只是构建/烧录/调试三条命令行链路的按钮壳"，2.3 处理一个现实问题"别人的示例工程能不能直接导入"（结论：板子不同会静默失败，不如自己写）。

| 小节 | 一句话结论 |
|---|---|
| [2.1](2.1-使用STM32的System-Workbench.md) | SW4STM32 已停止维护不值得学；Build/Debug 两个按钮背后是 `make` 和 `openocd + gdb`，命令行同样能做到源码级断点 |
| [2.2](2.2-IDE为我们做了什么.md) | IDE 自己一行代码都不编译，它是构建/烧录/调试三条链路的壳；烧录用 `.bin`（纯字节）、调试用 `.elf`（带符号和 DWARF），别混用 |
| [2.3](2.3-导入本书的编程示例.md) | 书的示例是给 F030R8（M0）写的，F103RB 的 GPIO 寄存器模型完全不同，照抄会"编译烧录全过、板子毫无反应"；导入前必须先核链接脚本/启动文件/`-mcpu` |
| [2.4](2.4-总结.md) | 一章收束成一句话：IDE 是替你敲命令的壳；真正的资产是源文件＋Makefile＋链接脚本＋`.elf`，IDE 私有工程文件换家就废 |
| [2.5](2.5-编程问题.md) | 原书习题缺失，换成五道实测自测题（三条最简命令、`init mode failed` 排查顺序、`.bin`/`.elf` 分工、DWARF 行号、gdb 版本） |
| [2.6](2.6-其他问题.md) | 三类杂项：要不要装 CubeIDE（看需求，多数不用）、硬件断点为什么只有 6 个（物理比较器）、链接脚本里哪四类段是必需的 |

**本章最容易踩的坑：**

- 照抄书里 F0 的 GPIO 代码到 F103 上：编译、链接、烧录全通过，板子不亮且零报错（F1 用 `CRL/CRH`，F0 用 `MODER` 系列）（2.3）
- 烧录命令漏写 `exit`，openocd 一直挂着不退（2.2）
- 以为断点可以随便设：Cortex-M3 只有 6 个硬件断点，软件断点改 Flash 一次擦一整页（2.2 / 2.6）
- `init mode failed` 一上来就降 SWD 速度——最常见的原因其实是一根只能充电的 USB 线（2.5）
- 把 IDE 的 `.cproject` 当成工程本身：真正的工程是源文件＋Makefile＋链接脚本，IDE 配置换个 IDE 就作废（2.1）

## 一句话总结本章

**IDE = 构建 + 烧录 + 调试 三条链路的按钮壳。** 三条链路各自的边界很清晰：

```
构建：.c/.S/.ld  →  make  →  .elf（调试用）+ .bin（烧录用）
烧录：.bin + 地址 →  openocd  →  Flash 里的字节
调试：.elf + 目标 →  openocd(server) + gdb(client)  →  断点/单步/变量
```

## 与书的差异

| 书 | 我 |
|---|---|
| System Workbench for STM32（SW4STM32） | **已停止维护**，不装。用 openocd + arm-none-eabi-gdb 等价替代 |
| 板子 NUCLEO-F030R8（Cortex-M0） | NUCLEO-F103RB（Cortex-M3），**GPIO 寄存器模型不同**（见 [2.3](2.3-导入本书的编程示例.md)） |
| 导入配套工程 | 自己手写启动文件/链接脚本/Makefile，写完再对照 |
| 调试用 IDE 图形界面 | gdb + openocd，**同样源码级**（实测停在 `main.c:38`） |
