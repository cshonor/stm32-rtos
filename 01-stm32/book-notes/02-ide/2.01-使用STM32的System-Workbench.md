## 书这一节讲什么

手把手教你用 System Workbench for STM32（SW4STM32）建工程、编译、点调试按钮：
新建 STM32 工程 → 选芯片 → 生成骨架 → Build → Debug → 设断点 → 单步。

## 这一节的操作部分对我没用

**SW4STM32 已经停止维护**（AC6 出的 Eclipse 系 IDE，ST 官方接替品是 STM32CubeIDE）。
照着点一遍，学到的是**一套三年后必然作废的菜单路径**——而菜单路径是最不值钱的知识。

但这一节演示的**三个动作**是永久的，换成任何 IDE 都一样：

| 书里点的按钮 | 永久的那件事 | 命令行等价物 |
|---|---|---|
| New STM32 Project | 生成启动文件 + 链接脚本 + 时钟初始化 | 手写（本仓库路线） |
| Build（锤子） | 调编译器 + 链接器 | `make` |
| Debug（虫子） | 起调试服务器 + 连 gdb + 下载 + 断点 | `openocd` + `arm-none-eabi-gdb` |

**2.1.3「调试程序」是这三个里最值钱的一节**——因为"调试"这件事 IDE 藏得最深，
而命令行做起来也就三条命令。

## 坑点（书 / 常识怎么说 / 实际是什么）

| 书 / 常识怎么说 | 实际是什么 |
|---|---|
| 装 SW4STM32 建工程 | **已停止维护**。而且它是 Eclipse：自带一套 make、一套链接脚本、一堆 `.cproject` XML。学会它 = 学会一个 IDE，不是学会嵌入式 |
| "用 IDE 建工程很快" | 快的是向导。代价是你不知道它生成的 `STM32F103RB_FLASH.ld` 里写了什么。**那才是资产**（ch11 会逐行拆） |
| "IDE 创建 Hello World 会把环境配好" | 配好的是"这台机器上这份 IDE 的环境"。换台机器、换 IDE 版本、换芯片，你**不知道要改什么** |
| "调试必须用 IDE" | gdb + openocd 完全等效，实测源码级停在 `main.c:38`，而且每一步命令都看得见 |
| "IDE 里的工程定义（.cproject）就是工程本身" | 不是。真正的工程 = 源文件 + Makefile + 链接脚本 + 启动文件。IDE 的配置文件只是**它的私有表达**，换个 IDE 就废 |

## 代码自测

<details>
<summary>Q1：IDE 的"Debug"按钮按下之后，到底起了几个进程？</summary>

**至少三个**，而且是**跨机器**的：

| 进程 | 跑在哪 | 作用 |
|---|---|---|
| gdb（或 IDE 内嵌的调试前端） | 你的电脑 | 读 ELF 符号、发 RSP 协议命令、管断点 |
| 调试服务器（ST-LINK_gdbserver / OpenOCD） | 你的电脑 | 把 RSP 翻译成 USB 传输 |
| ST-Link 固件 | **板子上另一颗芯片** | 把 USB 翻译成 SWD 两线时序 |

完整链路：

```
IDE/gdb ──RSP/TCP── 调试服务器 ──USB── ST-Link ──SWD── Cortex-M3 的 DP ── 内存/寄存器
```

**"板子没反应"要分层排查**，就是从这条链的左端往右端一段一段确认，
哪一段的日志没出现，问题就在那一段（详见 [2.02 Q2](2.02-IDE为我们做了什么.md)）。
</details>

<details>
<summary>Q2：为什么书里 2.1.1「启动 IDE」在 macOS 上会很别扭？</summary>

三个层面，都跟"跨平台"有关：

1. **Java**：Eclipse 系 IDE 需要 JRE。新版 CubeIDE 自带 Temurin JRE，
   老版 SW4STM32 要你自己装 Java 8/11，而 macOS 上换 Java 版本是有名的麻烦。
2. **门禁（Gatekeeper）**：从官网下的 `.app` 首次启动会被拦，
   要去"系统设置 → 隐私与安全性"手动放行——书里不会有这一步。
3. **workspace 路径**：社区经验是**必须纯英文路径**，中文/空格路径会导致编译异常。
   这是 Eclipse 系的老问题。

这三个坑都不是"嵌入式"的问题，是"跨平台工具"的问题。
**这也是我倾向命令行的一个实际理由**：命令行工具没有门禁、没有 Java、
没有 workspace 概念，`~/.local/` 解压即用。
</details>
