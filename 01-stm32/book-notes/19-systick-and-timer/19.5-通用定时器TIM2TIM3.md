## 书这一节讲什么

书里没有。**SysTick 只有一个，且分辨率受心跳限制。**
需要精确波形 / 输入捕获 / PWM / 多个独立周期时，就得用**通用定时器**。

| 用途 | 用什么 |
|---|---|
| 系统心跳、延时 | **SysTick**（[19.2](19.2-配置成1ms心跳.md)） |
| PWM（调光、电机） | TIMx 的 OC 通道 |
| 输入捕获（测脉宽/频率） | TIMx 的 IC 通道 |
| 精确周期中断（非 1 ms 整数倍） | TIMx 的更新中断 |
| 编码器接口 | TIMx 的 encoder mode |

## 一、定时周期怎么算：PSC 与 ARR

```
定时周期 = (PSC + 1) × (ARR + 1) / tim_clk
```

两个都是**减到 0 触发**的计数器，所以**两个都要减 1**（和 SysTick 的 RVR 同理）。

72 MHz 下想要 1 kHz（1 ms）——本机算式推导：

| PSC | 计数频率 | ARR | 结论 |
|---|---|---|---|
| 0 | 72.0000 MHz | 71999 | ❌ 超 16 位上限 65535 |
| **71** | **1.0000 MHz** | **999** | ✅ **最常用**（计数频率凑成 1 MHz，好算） |
| 719 | 0.1000 MHz | 99 | ✅ 也行 |
| 7999 | 0.0090 MHz | 8 | ⚠ 精度差（ARR 太小，调节粒度粗） |
| 65535 | 0.0011 MHz | 0.0986 | ❌ 非整数 |

⚠ **`PSC=71` 是个黄金值**：把 72 MHz 分频成 **1 MHz**，
之后 ARR 就等于"微秒数 − 1"，心算即可。

用 `PSC=71` 推常见周期（同样的推导）：

| 目标周期 | ARR | 结论 |
|---|---|---|
| 1 ms | 999 | ✅ |
| 10 ms | 9999 | ✅ |
| 100 ms | 99999 | ❌ **超 65535** |
| 1 s | 999999 | ❌ 超 65535 |

⚠ **16 位定时器在 1 MHz 计数频率下最长只能定 65.536 ms。**
要定更久，只能**加大 PSC**（降计数频率）或**软件再计数**。

**16 位定时器的绝对上限**（`PSC = ARR = 65535`）：

| fclk | 最长周期 |
|---|---|
| 8 MHz | **536.871 s**（≈ 8.95 分钟） |
| 72 MHz | **59.652 s** |
| 168 MHz | **25.565 s** |

## 二、⭐ 实测：TIM2 配置比 SysTick 配置贵一倍

把一段完整的 TIM2 更新中断配置（开时钟 + 设 PSC/ARR + 开中断 + 启动）
编成裸机镜像（`-Os`，`--gc-sections`）：

```
$ llvm-size app_tim.elf
   text    data     bss     dec     hex
     64       0       0      64      40
```

对照 [19.2](19.2-配置成1ms心跳.md) 的 SysTick 版 **text 36**。两者都含 8 字节向量表，
所以**函数体是 56 B vs 28 B——TIM2 贵一倍**。

反汇编看贵在哪（`Reset_Handler`，`tim2_init` 已被内联）：

```
 8000008: movw r0, #0x101c
 800000c: movt r0, #0x4002              ← 0x4002101C = RCC_APB1ENR
 8000010: ldr  r1, [r0]
 8000012: orr  r1, r1, #0x1
 8000016: str  r1, [r0]                 ← ⭐ 先开 TIM2 的时钟（SysTick 不需要！）
 8000018: movs r0, #0xc
 800001a: movt r0, #0x4000              ← 0x4000000C = TIM2_DIER 基址
 800001e: movs r1, #0x47                ← 71
 8000020: strh r1, [r0, #0x1c]          ← TIM2_PSC = 71     ✅ 常量折叠
 8000022: movw r1, #0x3e7               ← 999
 8000026: strh r1, [r0, #0x20]          ← TIM2_ARR = 999    ✅ 常量折叠
 8000028: ldr  r1, [r0]  ; orr #1 ; str ← TIM2_DIER |= 1（更新中断使能）
 8000030: ldr  r1, [r0]  ; orr #1 ; str ← TIM2_CR1  |= 1（CEN 启动）
```

**多出来的 28 字节就在第一条：开 RCC 时钟。**

> ⭐ **这 28 字节揭示了一条规律**：SysTick 是**内核**外设，永远供电，不用开时钟；
> TIM2 是**厂商**外设，默认关着时钟省电，用之前必须先开。
> 忘了开 `RCC_APB1ENR` 的表现是"寄存器写了没反应"——**写不进去也不报错**。

⚠ 另外注意符号表里 `TIM2_IRQHandler` **又不见了**——
和 [19.3](19.3-g_ms与回绕安全的时间比较.md) 是同一个 `--gc-sections` 坑，
这里向量表只写了 2 项。**这个坑对所有 ISR 一视同仁。**

## 三、⚠ APB1 定时器的时钟陷阱（RM0008，本机未实测）

⚠ **F1 的定时器时钟有个陷阱**：`TIM2` 挂在 APB1，
**当 APB1 预分频系数 ≠ 1 时，定时器的时钟是 PCLK1 × 2**（RM0008）。

所以"以为 36 MHz 其实是 72 MHz"是常见错误——**表现是"PWM 频率差一倍"**。

| 你以为 | 实际（APB1 预分频 ≠ 1） |
|---|---|
| TIM2 时钟 = PCLK1 = 36 MHz | **TIM2 时钟 = PCLK1 × 2 = 72 MHz** |

⚠ **诚实标注**：这条来自 RM0008，**本机未实测**（没有真机 + 没有示波器）。
待 `01-stm32/06-timer` 建成后用示波器看 PWM 频率验证。

## 四、ISR 里必须清中断标志

```c
void TIM2_IRQHandler(void){
    TIM2_SR &= ~(1u << 0);           /* 清 UIF，否则中断会不停重入 */
    ...
}
```

⚠ **这一条和 SysTick 不一样**：SysTick 的 `COUNTFLAG` 读 CSR 就自动清，
而 TIM 的 `UIF` **必须手动清**。忘了的话，**中断会以最高频率不停重入**，
主循环几乎得不到执行——表现像"程序卡死但 LED 还在闪"。

## 坑点

| 坑 | 原书怎么说 | 实际是什么（实测 / 推导） |
|---|---|---|
| "ARR 就是想要的计数值" | 书里没讲定时器 | ❌ **要减 1**（和 SysTick 的 RVR 同理），`周期 = (PSC+1)(ARR+1)/fclk` |
| "通道时钟就是 APB 总线时钟" | —— | ⚠ **APB1 预分频 ≠ 1 时是 PCLK1 × 2**（RM0008，**未实测**）→ PWM 频率差一倍 |
| "不用开时钟，直接写寄存器就行" | —— | ❌ 厂商外设默认关时钟；实测配置代码里**第一条就是 `RCC_APB1ENR |= 1`**，多了 28 字节 |
| "ARR 可以随便填大数" | —— | ❌ **16 位上限 65535**；72 MHz + PSC=71 时最长只有 **65.536 ms** |
| "TIM 中断和 SysTick 一样自动清标志" | —— | ⚠ **不一样**：TIM 的 `UIF` 要手动清 `TIM2_SR`，否则中断不停重入 |
| "配个定时器很占 Flash" | —— | ❌ 实测 **text 64 B**（含向量表），只比 SysTick 版多 28 B |

## 代码自测

<details>
<summary>Q1：我想要"每 100 μs 采一次"，SysTick 够吗？</summary>

**取决于你的 SysTick 心跳频率。** 通常配成 1 ms（1 kHz），
那 100 μs 的周期就**做不到**——最快只能每 1 ms 检查一次。

**三种解法**：

**① 提高 SysTick 频率**（简单但代价大）

```c
SYST_RVR = cpu_hz / 10000 - 1;      /* 100 μs = 10 kHz */
```

代价：**中断频率提高 10 倍**。10 kHz 中断、每次进出约 20~30 周期，
8 MHz 下占 2.5~3.75% CPU，还能接受；**100 kHz 就占 30% 了**。

⚠ 而且高频 SysTick 会**挤占 RTOS 心跳的语义**（ch20）——通常不该动它。

**② 用通用定时器的更新中断**（推荐）

```c
TIM2_PSC = 0;                       /* 不分频 */
TIM2_ARR = (tim_clk / 10000) - 1;   /* 100 μs */
TIM2_DIER |= (1u << 0);             /* 更新中断使能 */
TIM2_CR1  |= (1u << 0);             /* 启动 */
/* ISR 里做采样，SysTick 继续做 1 ms 系统心跳 */
```

好处：**两个时基独立**，互不干扰；定时器是硬件的，
**精度由时钟决定，不受中断延迟影响**。

**③ 定时器 + DMA**（高吞吐）

```
定时器 TRGO → 触发 ADC → ADC 结果由 DMA 直接搬到内存
CPU 完全不参与，只在缓冲区半满/全满时处理一次
```

**选择判据**：

| 周期 | 方案 |
|---|---|
| ≥ 1 ms | SysTick + 主循环判据（[19.3](19.3-g_ms与回绕安全的时间比较.md)） |
| 100 μs ~ 1 ms | 通用定时器中断（②） |
| < 100 μs 或高频连续 | 定时器 + DMA（③） |
| 需要精确波形输出 | 定时器的 PWM/OC 模式（硬件产生，无软件抖动） |

⚠ **ISR 抖动（jitter）是真实存在的**：即使定时器周期精确，
ISR 的**响应时间**也会因为"当时正在执行另一个中断/临界区"而推迟几微秒。
需要**严格确定性**的场合，必须用**硬件输出**（OC 通道直接驱动引脚），
不能用"ISR 里翻转 GPIO"。
</details>

<details>
<summary>Q2：为什么实测里 TIM2 配置比 SysTick 多花 28 字节？</summary>

**多在一行：`RCC_APB1ENR |= (1u << 0);`**

反汇编里它是前 4 条指令（`movw` / `movt` / `ldr` / `orr` / `str`，
地址 `0x8000008` ~ `0x8000016`），后面才是 `TIM2_PSC` / `ARR` / `DIER` / `CR1`。

**根因是两类外设的供电策略不同**：

| | SysTick | TIM2 |
|---|---|---|
| 归属 | **ARM 内核** | **ST 厂商** |
| 地址区 | PPB `0xE000E010` | APB1 `0x40000000` |
| 时钟 | 跟着内核走，**永远有时钟** | 默认**关着**，省电 |
| 配置第一步 | 直接写寄存器 | **先 `RCC_APB1ENR |= 1`** |

厂商外设默认是**关时钟**的——这是 STM32 低功耗设计的一部分：
不用的外设不供电，省电。代价是每次用之前都要记着开。

⚠ **这条规律对所有厂商外设都成立**：GPIO（`RCC_APB2ENR`）、
USART（`RCC_APB2ENR` / `APB1ENR`）、SPI、I2C、ADC……
**"寄存器写了没反应"的第一嫌疑永远是"忘了开时钟"**，
而且它**不报任何错**——写进一个没时钟的寄存器，读回来还是 0。
</details>

<details>
<summary>Q3：16 位 ARR 不够用怎么办？</summary>

三条路，按推荐顺序：

**① 加大 PSC，降低计数频率**（首选）

```
72 MHz, PSC=719 → 计数 100 kHz → ARR = 65535 → 最长 655.36 ms
72 MHz, PSC=7199 → 计数 10 kHz → ARR = 65535 → 最长 6.5536 s
```

代价：**分辨率变差**。10 kHz 计数下，ARR 每 ±1 就是 100 μs 的粒度。
所以要在"最长周期"和"分辨率"之间权衡。

**② 软件再计数**（长周期）

```c
/* 定时器每 10 ms 中断一次，ISR 里累加，主循环里判 10 s */
void TIM2_IRQHandler(void){ TIM2_SR &= ~1; g_10ms++; }
if ((int32_t)(g_10ms - t_next) >= 0) { t_next = g_10ms + 1000; ... }
```

和 [19.3](19.3-g_ms与回绕安全的时间比较.md) 的 `g_ms` 完全是同一个套路。

**③ 用 32 位定时器**（如果芯片有）

F1 的 TIM2/TIM5 在某些型号上是 32 位的。有就用，没有就退回 ①②。

⚠ **别忘了还有一个选择：级联**。用一个定时器的更新事件
去触发另一个定时器的时钟（TRGO → ITR），可以把两个 16 位拼成 32 位。
不过这属于进阶玩法，先把 ①② 用熟。

**决策表**：

| 需求 | 做法 |
|---|---|
| 要长周期、不要高精度 | 加大 PSC（①） |
| 要长周期、也要高精度 | 软件再计数（②） |
| 芯片有 32 位定时器 | 直接用（③） |
