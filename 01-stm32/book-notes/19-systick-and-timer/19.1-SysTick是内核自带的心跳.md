# 19.1 SysTick 是内核自带的心跳

## 书这一节讲什么

**书里没有这一节。** 前 18 章里程序只有两种时间观：**没有时间**（写完就跑完）
和**忙等**（`for(i=0;i<10000;i++);`，ch05 说过这不可靠）。

但真实需求全都要时间——去抖要"按下后 20 ms 再看一次"、
LED 要"每 500 ms 翻转"、串口要"3 字符时间内没收就认为一帧结束"、
RTOS 要"每 1 ms 做一次调度检查"。**裸机上没人给你 `sleep()`，时间是自己造的。**

本节先解决"从哪造"：Cortex-M 内核自带一个定时器，叫 **SysTick**。

## 一、SysTick 属于 ARM 内核，不是 ST 的外设

这一条最有实际价值：**它是 Cortex-M 的一部分，所有 Cortex-M 芯片都有**。

地址本身就是证据：

```
SysTick:  0xE000E010 ~ 0xE000E01C     ← 私有外设总线 PPB（0xE0000000 起，ARM 定义）
NVIC:     0xE000E100 ~                ← 同样是内核的
GPIOA:    0x40010800                  ← ST 的外设，在 APB2 上
USART1:   0x40013800                  ← ST 的外设
```

`0xE0000000` 以上是 **ARM 定义的内核私有外设区**，所有 Cortex-M 都一样；
`0x40000000` 是**厂商定义的外设区**，每家每系列都不同。

三个实际意义：

1. **代码可移植**——`SysTick_Config()` 在 STM32 / GD32 / NXP / 瑞萨上完全一样，换芯片不用改时基；
2. **CMSIS 有统一封装**——`SysTick_Config(ticks)` 一行搞定，不必自己写寄存器；
3. **RTOS 依赖它**——FreeRTOS / Zephyr / RT-Thread 的移植层都要实现 `SysTick_Handler`，
   因为它是唯一"所有 Cortex-M 都有"的定时器。

## 二、四个寄存器（地址固定，见上）

| 寄存器 | 地址 | 作用 |
|---|---|---|
| `SYST_CSR` | `0xE000E010` | 控制与状态：ENABLE / TICKINT / CLKSOURCE / COUNTFLAG |
| `SYST_RVR` | `0xE000E014` | 重载值：计数到 0 后自动装回这个值 |
| `SYST_CVR` | `0xE000E018` | 当前值：写任意值清零 |
| `SYST_CALIB` | `0xE000E01C` | 校准值（"10 ms 校准值"，**很多芯片读出来是 0**） |

工作方式是**向下计数**：

```
CVR 从 RVR 开始递减 → 减到 0 → （可选）触发中断 → 自动装回 RVR → 继续
```

⚠ **`SYST_CALIB` 不要依赖**：它是可选的，很多芯片没烧这个值（读到 0）。
老老实实按 CPU 频率算 RVR（见 [19.2](19.2-配置成1ms心跳.md)）。

## 三、时钟源可选，别默认它准

`SYST_CSR` 的 `CLKSOURCE` 位：

| CLKSOURCE | 时钟源 |
|---|---|
| 1 | CPU 时钟（F1 上是 HCLK） |
| 0 | HCLK / 8（有些芯片外部源更准，得看手册） |

**选哪个直接决定 RVR 该填多少**——选错了表现就是"延时差 8 倍"。

## 坑点

| 坑 | 原书怎么说 | 实际是什么（实测） |
|---|---|---|
| "SysTick 是 ST 的外设" | 书里没讲 SysTick | ❌ **是 ARM 内核的**：地址在 PPB 区（`0xE000E010`），与 ST 外设的 `0x40010800`（GPIOA）不在同一个区 |
| "所有定时器都要查芯片手册" | —— | ⚠ SysTick **不用**：地址、位定义全系列一致，查 Cortex-M 手册即可 |
| "`SYST_CALIB` 是官方校准值，用它最准" | —— | ⚠ 它是可选的，**很多芯片读到 0**；按 CPU 频率算 RVR 才可靠 |
| "SysTick 时钟固定是 CPU 主频" | —— | ⚠ `CLKSOURCE=0` 时是 **HCLK/8**，差 8 倍 |
| "SysTick 中断优先级默认就行" | —— | ⚠ 默认 **0（最高）**；RTOS 项目里通常要调低（ch10 讲过优先级分配） |

## 代码自测

<details>
<summary>Q1：怎么一眼判断一个外设是"内核的"还是"厂商的"？</summary>

**看地址落在哪个区。**

```
0xE0000000 ~ 0xE00FFFFF   私有外设总线 PPB —— ARM 定义，全 Cortex-M 一致
                          SysTick 0xE000E010、NVIC 0xE000E100、SCB 0xE000ED00
0x40000000 ~              厂商外设区 —— 每家每系列都不同
                          STM32F1: GPIOA 0x40010800、USART1 0x40013800
```

所以看到 `0xE000_xxxx` 就知道"换个 Cortex-M 芯片这段代码照样能跑"；
看到 `0x4001_xxxx` 就知道"这是 ST F1 特有的，换芯片要改"。

**这条对读代码特别有用**：拿到一份陌生的裸机代码，
扫一眼它操作的地址，立刻就知道哪部分是**可移植的时基/中断控制**，
哪部分是**绑定具体芯片的 GPIO/串口**。
</details>

<details>
<summary>Q2：为什么 RTOS 都用 SysTick 而不是通用定时器做心跳？</summary>

三个理由，按重要性排：

1. **它是唯一"所有 Cortex-M 都有"的定时器**——RTOS 的移植层要写一份
   能跑在任意 Cortex-M 上的代码，只能用 SysTick。用 TIM2 的话，
   换到某个没有 TIM2 或者 TIM2 被占用的芯片就移植失败；
2. **它在内核里，不占用芯片的外设资源**——通用定时器是稀缺资源，
   要留给 PWM / 输入捕获 / 编码器（见 [19.5](19.5-通用定时器TIM2TIM3.md)）；
3. **CMSIS 已经封装好了**——`SysTick_Config()` 一行，不用碰寄存器。

⚠ 代价是：**SysTick 只有一个**。所以 RTOS 项目里，
SysTick 给了内核做心跳之后，需要精确周期的活儿（100 μs 采样）
就必须让通用定时器来干——见 Q3。
</details>

<details>
<summary>Q3：SysTick 只有 24 位，够用吗？最长能定多久？</summary>

**够做心跳，但不能做长定时。** RVR 是 24 位（上限 `0xFFFFFF` = 16777215），
所以单次最长周期随主频升高而急剧缩短：

| fclk | RVR = 0xFFFFFF 时的最长周期 | 1 kHz | 100 Hz | 10 Hz |
|---|---|---|---|---|
| 8 MHz | **2097.152 ms** | RVR=7999 ✅ | 79999 ✅ | 799999 ✅ |
| 72 MHz | **233.017 ms** | RVR=71999 ✅ | 719999 ✅ | 7199999 ✅ |
| 168 MHz | **99.864 ms** | RVR=167999 ✅ | 1679999 ✅ | 16799999 ❌ |

（上表为算式推导 `RVR = fclk/目标频率 − 1`，非真机实测）

⚠ 注意 168 MHz 行：**主频越高，单次能定的时间越短**，
168 MHz 上想直接定 10 Hz（100 ms）**做不到**，得软件再分频。

**做长定时的正确做法**：SysTick 只负责 1 ms 心跳累加 `g_ms`，
长定时用主循环里的判据去比（[19.3](19.3-g_ms与回绕安全的时间比较.md)）。
**永远不要让 SysTick 直接定超过几百毫秒。**
</details>
