## 四、学两遍：与 LDD- 轨汇合

```
MCU 裸机（本仓库）        Linux 驱动（LDD-）
GPIO 寄存器         ←→   /dev + file_operations
NVIC + ISR          ←→   request_irq + 下半部
链接脚本定内存       ←→   kmalloc / 页表
SysTick             ←→   jiffies / hrtimer
环形缓冲            ←→   kfifo
弱符号默认 ISR       ←→   __weak 修饰符 / 驱动 core 的回调框架
静态库按需抽取      ←→   内核模块的 EXPORT_SYMBOL + 按需加载
```

**学两遍 = 记两遍**，而且第二遍会反过来加深第一遍的理解——
这是这两条轨并行推进的全部意义。

⚠ **本仓库的"第二遍"是 Zephyr**：它的 devicetree 与 Linux 同源，
Kconfig 与 Linux 的 `make menuconfig` 同源——
**学它是"用嵌入式的方式再学一遍 Linux 的配置机制"**。

<details>
<summary>Q2：为什么要把 MCU 和 Linux 两条轨并行学？</summary>

因为**机制是同源的，学两遍 = 记两遍**：

```
GPIO 寄存器     ←→  /dev + file_operations
NVIC + ISR      ←→  request_irq + 下半部
链接脚本定内存   ←→  kmalloc / 页表
SysTick         ←→  jiffies / hrtimer
环形缓冲        ←→  kfifo
弱符号默认 ISR   ←→  __weak / 驱动 core 回调
静态库按需抽取  ←→  EXPORT_SYMBOL + 按需加载
```

⚠ **第二遍会反过来加深第一遍**——
比如学了 Linux 的 `kfifo` 再看裸机的环形缓冲，
才真正理解"为什么生产者只改 `head`、消费者只改 `tail`"
（[ch10](../10-interrupts/README.md)）。

**本仓库的"第二遍"是 Zephyr**：devicetree 与 Linux 同源、
Kconfig 与 `make menuconfig` 同源。
</details>

<details>
<summary>Q3：接下来先学什么？</summary>

按"缺口 × 收益"排：

| 优先级 | 内容 | 理由 |
|---|---|---|
| **①** | **SysTick / 通用定时器**（ch19） | ⭐ 裸机没有"时间"就做不了任何实时的事（延时、超时、周期任务） |
| **②** | **UART + DMA** | 打通"调试输出"和"高速数据"，后面所有实验都依赖 |
| **③** | **FreeRTOS**（任务/队列/信号量） | 从"前后台"升级到"多任务"，是复杂度的分水岭 |
| ④ | 时钟树（RCC/PLL） | 想跑满主频、想低功耗都必须懂 |
| ⑤ | 低功耗 / bootloader / OTA | 产品化才需要 |
| ⑥ | Zephyr（工程化第二遍） | 与 Linux 机制同源，学它是"再学一遍 Linux 配置机制" |

⚠ **别跳级**：RTOS 假设你已经懂启动、链接、中断——
[18.02](18.02-学会阅读.md) 里说过"别从 RTOS 开始读"。
</details>
