# 16.3 精度位数

> 书：第 16 章 浮点数 · 16.3 精度位数（原书 p219+ 区间内）
> 上一篇：[16.2 舍入误差](16.2-舍入误差.md) ｜ 下一篇：[16.4 无穷大](16.4-无穷大.md)
> 对应实验：主机侧实测（clang 23.1.0 / macOS arm64）

## 书这一节讲什么

一句话：**`float` 只有 6 位可靠十进制，`double` 15 位——
"精度"不是全局的，它随数值大小漂移。**

本篇用 **ULP（相邻可表示数的间隔）表**把这件事量化，
并给出"打印几位才不丢人"的实测依据。

## 一、⚠ 实测：打印多少位是可信的

```
$ ./prec
0.1f  %.6f  = 0.100000
0.1f  %.9f  = 0.100000001
0.1f  %.15f = 0.100000001490116   ← ⚠ 第 9 位以后全是垃圾
1/3   %.15f = 0.333333343267441
```

`FLT_DIG = 6`（实测）——意思是"**能往返转换回同一 float 的十进制位数是 6**"。

| 打印位数 | `0.1f` 的结果 | 可信吗 |
|---|---|---|
| `%.6f` | `0.100000` | ✅ 在 `FLT_DIG=6` 内 |
| `%.9f` | `0.100000001` | ✅ 9 位是"保证往返"的上限（`FLT_DECIMAL_DIG`） |
| `%.15f` | `0.100000001490116` | ⚠ **后面全是转换噪声**，不是真实精度 |

**规则**：调试打印 `float` 用 `%.6f`~`%.9f`，`double` 用 `%.15f`。
**再多打出来的数字没有信息量**，只会让人误以为精度很高。

## 二、⚠ 实测：ULP 随量级指数增长

```
$ ./prec
  1               float ULP = 1.19209e-07
  10              float ULP = 9.53674e-07
  1000            float ULP = 6.10352e-05
  1000000         float ULP = 0.0625
  10000000        float ULP = 1            ← ⚠ 加 1 已经没意义了
  1000000000      float ULP = 64
  1000000000000   float ULP = 65536
  100000000000000 float ULP = 8.38861e+06
  100000000000000000 float ULP = 8.58993e+09
```

**每跨一个十进制量级，间隔大约涨 8~10 倍**（因为指数每 +1，间隔 ×2；10 ≈ 2^3.32）。

换算成"能表示多少位十进制"：

| 量级 | float ULP | 相当于保留到小数点后 |
|---|---|---|
| 1 | 1.19e-07 | 第 7 位 |
| 1e6 | 0.0625 | 整数位都快保不住了 |
| **1e7** | **1** | ⚠ **`10000001` 根本存不下** |
| 1e9 | 64 | 只能表示 `1e9 ± 64` 的倍数值 |

⚠ **这条对嵌入式是硬约束**：
如果你的 ADC 计数或时间戳会涨到 `1e7` 量级，**用 `float` 存就已经开始丢值了**。

## 三、⚠ 实测：2^24 是 `float` 整数的天花板

```
2^24      = 16777216.0   位模式 0x4b800000
2^24 + 1 == 2^24 ? 是   ← ⚠ 加 1 被吃掉（和上面的 ULP 表一致）
2^24-1 +1 == 2^24 ? 是
2^23 + 1 == 2^23 ? 否   ← 这里还加得上
```

`float` 尾数 24 位（含隐含位）→ **能精确表示的连续整数到 2^24 = 16777216 为止**。

同理 `double`（53 位）→ 到 **2^53 ≈ 9.007e15** 为止。
这也是 [16.2](16.2-舍入误差.md) 实测 `1e15+1` 加得上、`1e16+1` 加不上的原因
（`1e15 < 2^53 ≈ 9.0e15 < 1e16`）。

**记忆点**：

| 类型 | 精确整数上限 | 实测证据 |
|---|---|---|
| `float` | **2^24 = 16777216** | `2^24 + 1 == 2^24` 为"是"，`2^23 + 1` 为"否" |
| `double` | **2^53 ≈ 9.007e15** | `1e15 + 1 != 1e15`，`1e16 + 1 == 1e16` |

## 四、实测：常量一览

```
FLT_DIG=6 DBL_DIG=15 LDBL_DIG=15
FLT_EPSILON=1.192092896e-07  DBL_EPSILON=2.2204460492503131e-16
FLT_MIN=1.175494351e-38  FLT_MAX=3.402823466e+38
DBL_MIN=2.2250738585072014e-308  DBL_MAX=1.7976931348623157e+308
FLT_TRUE_MIN=1.401298464e-45  DBL_TRUE_MIN=4.940656458e-324
FLT_MANT_DIG=24 DBL_MANT_DIG=53
```

| 宏 | 含义 | 实测值 |
|---|---|---|
| `FLT_DIG` / `DBL_DIG` | 能往返的十进制位数 | **6** / **15** |
| `FLT_EPSILON` / `DBL_EPSILON` | 1.0 与下一个可表示数的差 | 1.19e-07 / 2.22e-16 |
| `*_MIN` | **最小正规数** | 1.18e-38 / 2.23e-308 |
| `*_TRUE_MIN` | **最小次正规数** | 1.40e-45 / 4.94e-324 |
| `*_MAX` | 最大值 | 3.40e+38 / 1.80e+308 |
| `*_MANT_DIG` | 尾数位数（含隐含位） | **24** / **53** |

⚠ `FLT_MIN` **不是**最小正数——那是 `FLT_TRUE_MIN`（小 7 个数量级）。
见 [16.6 次正规数](16.6-次正规数.md)。

## 五、裸机：精度决定"选什么类型"

| 你要存的量 | 推荐 | 理由（实测） |
|---|---|---|
| 温度 -40~125 ℃ | `int16_t`（0.1℃ 单位） | 整数无误差，2 字节 |
| 电压 0~3.3 V | `int32_t`（mV 或 µV） | 同上 |
| **时间戳 / 计数 > 1.6e7** | `int32_t` / `int64_t` | ⚠ `float` 在 1e7 处 ULP=1，会丢值 |
| ADC 原始计数（0~4095） | `uint16_t` | 根本不需要浮点 |
| 真正需要小数的中间计算 | Q16.16 定点 | 见 [16.7](16.7-替代方案.md) |
| 大范围物理量（如 1e-6 ~ 1e6） | `float`/`double`（确认有 FPU） | 定点的动态范围不够 |

**本仓库的取向**：物理量一律"**整数 + 单位后缀命名**"
（`temp_mC`、`volt_mV`、`freq_cHz`），
只在确认有 FPU 且确实需要的地方用 `float`，并且**绝不用 `double`**。

## 坑点

| 坑 | 原书怎么说 | 实际是什么（实测） |
|---|---|---|
| "`float` 有 7 位精度" | 常说 7 位 | ⚠ `FLT_DIG=**6**`；`FLT_DECIMAL_DIG`（往返上限）才是 9 |
| "精度是固定的" | —— | ❌ ULP 随量级涨：1 处 1.19e-07，**1e9 处 64** |
| "`float` 能存到 3.4e38" | ✅ 范围对 | ⚠ 但**精度随范围崩**：1e9 附近只能存 64 的倍数 |
| "`FLT_MIN` 是最小正数" | —— | ❌ 最小**正规**数；最小次正规是 `FLT_TRUE_MIN=1.4e-45` |
| "打印越多位越精确" | —— | ❌ 实测 `%.15f` 打 `0.1f` 得 `0.100000001490116`，后 6 位是噪声 |
| "时间戳用 float 够了" | —— | ⚠ 1e7 处 ULP=**1**，毫秒级时间戳会跳变 |

## 代码自测

<details>
<summary>Q1：我用 `float` 存毫秒时间戳，跑到几十分钟后发现时间"跳变"，为什么？</summary>

因为 **ULP 随量级增长**，到了某个点 `+1` 就加不动了。实测：

| 量级 | float ULP |
|---|---|
| 1e6 | 0.0625 |
| **1e7** | **1** |
| 1e9 | 64 |

- 一天 = 86400000 ms ≈ **8.6e7**，此时 `float` 的间隔是 **8** ms——
  时间戳只能跳 8 ms 一跳；
- `float` 能精确表示的连续整数上限是 **2^24 = 16777216**（实测 `2^24 + 1 == 2^24`），
  也就是 **16777 秒 ≈ 4.7 小时**。超过之后 `ms++` 就不再每次都生效。

✅ 改用 `uint32_t` 存毫秒（可到 49 天）或 `uint64_t` 存微秒。
**时间戳是整数，不是小数——不该用浮点。**
</details>

<details>
<summary>Q2：`printf("%.15f", 0.1f)` 打出 `0.100000001490116`，是不是 float 真的有 15 位精度？</summary>

**不是。** 那 15 位是把"一个不精确的二进制值"翻译成十进制得到的，
后面的数字是**转换过程的产物**，不是测量精度。

实测：

```
0.1f  %.6f  = 0.100000           ← FLT_DIG=6，可信
0.1f  %.9f  = 0.100000001        ← 往返上限 9 位
0.1f  %.15f = 0.100000001490116  ← ⚠ 后 6 位无意义
```

`FLT_DIG=6` 的定义是：
**"保留 6 位十进制再读回来，一定能得到同一个 float"**。
超过 9 位打出来的数字，换个编译器/库都可能不一样。

✅ 打印 `float` 用 `%.6f`~`%.9f`；打印 `double` 用 `%.15f~%.17f`。
</details>

<details>
<summary>Q3：`FLT_MIN` 和 `FLT_TRUE_MIN` 差多少？该用哪个？</summary>

实测差 **7 个数量级**：

```
FLT_MIN      = 1.175494351e-38   ← 最小【正规】数
FLT_TRUE_MIN = 1.401298464e-45   ← 最小【次正规】数
DBL_MIN      = 2.2250738585072014e-308
DBL_TRUE_MIN = 4.940656458e-324
```

- 想判断"这个数是不是小到快没了" → 用 `*_TRUE_MIN`；
- 想知道"正常精度的最小范围" → 用 `*_MIN`（低于它精度会骤降）。

⚠ **绝大多数代码应该用 `*_MIN`（正规数）作为下界**。
低于它的数进入次正规区，**精度和速度都会崩**（见 [16.6](16.6-次正规数.md)）。
</details>

<details>
<summary>Q4：ADC 采样 0~4095，用 float 存够吗？用 double 会不会更准？</summary>

**够，但没必要用浮点。** 0~4095 远小于 2^24（实测 float 精确整数上限），
所以 `float` 不会丢值——但 `uint16_t` 也能存，且更快更省。

⚠ 真正的坑在**后续运算**：

- 如果做 1000 点平均，累加值到 4e6，仍 < 2^24，安全；
- 如果累加 100000 点 → 4e8 > 2^24，**此时 `float` 累加会丢值**（ULP=32）；
- ✅ 正确做法：**用 `uint32_t` 累加，最后再除**（整数除法 + 移位），
  既无误差又在 M3 上快得多（[16.1](16.1-数字表示.md) 实测 `U __aeabi_fmul`）。

**用 `double` 当然更准，但在 M3/M4F 上 `double` 是软件模拟的**
（实测 `__aeabi_d*` 未定义符号仍在），代价远大于收益。
</details>
