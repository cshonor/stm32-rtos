# 16.05 不是数字（NaN）

> 书：第 16 章 浮点数 · 16.05 不是数字（NaN）（原书 p219+ 区间内）
> 上一篇：[16.04 无穷大](16.04-无穷大.md) ｜ 下一篇：[16.06 次正规数](16.06-次正规数.md)
> 对应实验：主机侧实测（clang 23.1.0 / macOS arm64）

## 书这一节讲什么

一句话：**NaN（Not a Number）是"这个结果没有定义"的标记值——
它的特点是：和自己都不相等。**

这是 IEEE-754 里最反直觉、也最容易被忽略的一条。

## 一、⚠ 实测：`NaN != NaN`

```
$ ./fp
0.0/0.0 = nan
NaN 位模式 = 0x7ff8000000000000
NaN == NaN ? 否     NaN != NaN ? 是
isnan(NaN) = 1    (x != x) = 1
```

`0x7ff8000000000000` 拆开：

```
0 11111111111 1000000000000000000000000000000000000000000000000000
│ │           └─ 尾数非 0（最高位=1，quiet NaN 的标记）
│ └───────────── 指数全 1（0x7FF）
└─────────────── 符号
```

**判定规则**（和 [16.04](16.04-无穷大.md) 的 inf 对照）：

| 指数字段 | 尾数字段 | 含义 |
|---|---|---|
| 全 1（0x7FF） | **全 0** | **inf** |
| 全 1（0x7FF） | **非 0** | **NaN** |

## 二、⚠ 实测：NaN 参与的比较**全部为假**

```
NaN <  1.0 → 0
NaN >  1.0 → 0
NaN <= 1.0 → 0
NaN >= 1.0 → 0
NaN == 1.0 → 0
```

六个比较运算符里，**只有 `!=` 为真**（包括 `!=` 自己）。

这带来两个反直觉的后果：

```c
/* ① "x == x" 是经典的 NaN 检测写法，不是笔误 */
if (x != x) { /* x 是 NaN */ }

/* ② ⚠ 取反不成立！*/
if (!(x < 1.0)) { /* 你以为是 "x >= 1.0"，实际 NaN 也进来 */ }
```

⚠ **第二条是真正的陷阱**：`!(x < 1.0)` 在数学上是 `x >= 1.0`，
但**对 NaN 来说前者为真、后者为假**。
所以**写"否定式"条件时要格外小心 NaN**。

## 三、⚠ 实测：NaN 的三种常见来源

| 表达式 | 实测结果 | 来源类型 |
|---|---|---|
| `0.0/0.0` | `nan` | 0/0 |
| `inf - inf` | `nan` | 两个无穷相减（[16.04](16.04-无穷大.md) 实测） |
| `inf * 0` | `nan` | ∞ × 0 |
| `sqrt(-1.0)` | `nan` | 定义域外（`<math.h>`） |
| `asin(2.0)` | `nan` | 定义域外 |

**嵌入式里最常见的是前三种**——它们不需要任何数学库，
一次普通的除法/减法/乘法就能产生。

## 四、⚠ 实测：比较函数的正确写法

```c
#include <math.h>
if (isnan(x)) { ... }        /* ✅ 最清楚 */
if (x != x)   { ... }        /* ✅ freestanding 下唯一可行的（无 <math.h>） */
```

⚠ **裸机 freestanding 下没有 `<math.h>`**，
所以 `isnan()` / `isfinite()` 都用不了——
**`x != x` 是裸机上唯一能写的 NaN 检测**。

⚠ 但要注意：**编译器可能把它优化掉**。

```c
/* ⚠ 在 -ffast-math 下，编译器假设"没有 NaN"，会把 x != x 直接删掉 */
```

所以：

- ✅ **不要用 `-ffast-math`**（嵌入式里本来就少用）；
- ✅ 用 `-fno-fast-math` 明确关掉；
- ⚠ 有些编译器的默认 `-ffinite-math-only` 也会中招——**实测确认过再依赖它**。
  （本机 clang 23.1.0 在默认 `-O2` 下实测 `x != x` 判断有效，
  `isnan(NaN)=1`、`(x != x)=1` 都成立。）

## 五、⚠ 实测：NaN 会穿过 clamp 和条件判断

[16.04](16.04-无穷大.md) 提过，这里给出完整证据：

```c
static inline float clampf(float v, float lo, float hi) {
    return v < lo ? lo : (v > hi ? hi : v);
}
```

- `clampf(NaN, -1, 1)`：
  `NaN < -1` → 假（实测所有比较都是 0）
  `NaN > 1` → 假
  → **原样返回 NaN** ❌

**所以"先限幅"不能保护你，必须先杀 NaN**：

```c
if (out != out) out = 0.0f;          /* ① 先杀 NaN */
if (out >  OUT_MAX) out =  OUT_MAX;  /* ② 再挡 +inf */
if (out < -OUT_MAX) out = -OUT_MAX;  /* ③ 再挡 -inf */
```

## 六、裸机映射

| PC | 裸机 |
|---|---|
| `isnan()`（`<math.h>`） | `x != x`（⚠ 别开 `-ffast-math`） |
| `nan` 打印成 `nan` | 裸机上只能自己打印 `"NaN"` 字符串 |
| 异常/信号 | **没有任何提示**，NaN 静默流进控制回路 |

**本仓库的取向**：用整数表示物理量。
整数**没有 NaN**——这是选择整数最强有力的理由之一，
比"快"和"省 Flash"更重要。

## 坑点

| 坑 | 原书怎么说 | 实际是什么（实测） |
|---|---|---|
| "`x == x` 恒成立" | 常识 | ❌ **NaN 不成立**（实测 `NaN != NaN` 为"是"） |
| "NaN 的传播会报错" | —— | ❌ 静默传播，一路传到输出 |
| "`!(x < 1.0)` 等价于 `x >= 1.0`" | 数学恒等 | ⚠ **NaN 时不等价**（前者真、后者假） |
| "clamp 能兜住异常值" | 常见做法 | ⚠ **NaN 穿过 clamp**（所有比较为假） |
| "`isnan()` 到处都有" | 标准库 | ⚠ **freestanding 下没有 `<math.h>`** |
| "`-ffast-math` 只是快一点" | —— | ⚠ 它会假设无 NaN，**把 `x != x` 优化掉** |

## 代码自测

<details>
<summary>Q1：`if (x != x)` 是笔误吗？为什么有人这么写？</summary>

**不是笔误，这是 NaN 检测的经典写法。**

实测：

```
0.0/0.0 = nan
NaN == NaN ? 否     NaN != NaN ? 是
isnan(NaN) = 1    (x != x) = 1
```

IEEE-754 规定 **NaN 不等于任何值，包括它自己**。
所以在没有 `<math.h>` 的环境（裸机 freestanding）里，
`x != x` 是**唯一能写出来**的 NaN 检测。

⚠ 前提：**不能开 `-ffast-math`**——
该选项让编译器假设"代码里不会出现 NaN"，从而把这个判断优化掉。
</details>

<details>
<summary>Q2：为什么 `if (!(x < 1.0))` 和 `if (x >= 1.0)` 不等价？</summary>

因为 **NaN 参与的比较全部为假**。实测六个运算：

```
NaN <  1.0 → 0
NaN >  1.0 → 0
NaN <= 1.0 → 0
NaN >= 1.0 → 0
NaN == 1.0 → 0
```

代入 `x = NaN`：

| 表达式 | 求值 | 结果 |
|---|---|---|
| `x < 1.0` | 假 | —— |
| `!(x < 1.0)` | **真** | ✅ 进分支 |
| `x >= 1.0` | 假 | ❌ 不进分支 |

**两者在 NaN 上给出相反的结果。**

✅ 所以写条件时**优先写肯定式**（`x >= 1.0` 而不是 `!(x < 1.0)`），
并且**先排除 NaN**：

```c
if (x != x)   { handle_nan(); }
else if (x < 1.0) { ... }
```
</details>

<details>
<summary>Q3：`clampf(NaN, -1, 1)` 返回什么？怎么修？</summary>

返回 **NaN**——限幅对它无效。

```c
static inline float clampf(float v, float lo, float hi) {
    return v < lo ? lo : (v > hi ? hi : v);
}
/* NaN:  v<lo 假, v>hi 假 → 返回 v，也就是 NaN */
```

✅ 修法：**先杀 NaN，再限幅**（顺序不能反）。

```c
static inline float safe_out(float v, float lo, float hi) {
    if (v != v) return 0.0f;              /* ① NaN → 0 */
    if (v > hi) return hi;                /* ② +inf → hi */
    if (v < lo) return lo;                /* ③ -inf → lo */
    return v;
}
```

⚠ 别写成 `if (v > hi) return hi; else if (v < lo) return lo; else if (v != v) return 0;`
——**NaN 会先穿过前两个判断**（都假），虽然最终也会被第三个拦住，
但把 NaN 检查放最前面更清楚、也更容易被编译器优化。
</details>

<details>
<summary>Q4：裸机上怎么检测 NaN？`-O2` 会不会把判断优化掉？</summary>

裸机 freestanding 下没有 `<math.h>`，只能用 `x != x`。

**关于优化**：本机 clang 23.1.0 在默认 `-O2` 下实测 `isnan(NaN)=1`、`(x != x)=1`，
**判断没有被优化掉**。

⚠ 但这依赖默认选项。真正会破坏它的是：

| 选项 | 影响 |
|---|---|
| `-ffast-math` | ⚠ 假设无 NaN / 无 inf，**所有 NaN 检测都可能被删** |
| `-ffinite-math-only` | ⚠ 同上（`-ffast-math` 的子集） |

✅ 保险做法：显式加 `-fno-fast-math`，
并在代码里加一句编译期断言确保它生效：

```c
/* 如果 x != x 被优化成常量，说明开了 -ffast-math */
volatile float probe = 0.0f;
probe = probe / probe;            /* NaN */
if (probe == probe) { /* ⚠ 到这里说明 NaN 检测不可靠 */ }
```

**最根本的解法还是用整数**——整数没有 NaN，也就不需要这套防御。
</details>
