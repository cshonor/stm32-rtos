## 这一篇讲什么

NUCLEO-F103RB 上有两个 8 MHz 时钟源：内部 RC（HSI）和外部晶振（HSE）。
可芯片标称主频是 **72 MHz**——这 9 倍从哪来？答案是 **PLL（锁相环）倍频**。
本篇把"从 8 MHz 到每个外设"的整条路走一遍。

## 上电默认：HSI 8 MHz

STM32F103 上电默认跑 **HSI（内部高速 RC 振荡器）8 MHz**。
原因很朴素：**内部 RC 不需要任何外部元件，上电即有**。
晶振起振要时间（毫秒级），还可能焊错、失效——
所以硬件设计者让芯片"先用自己兜里的表，等软件确认外面的表准了再换"。

这就是前面所有实验（点灯、探针）从不配时钟也能跑的原因：
**默认时钟已经够 8 MHz 用。**

> 对照：F407 上电默认 HSI **16 MHz**，跑满 168 MHz 同样要配 PLL
> （仓库根 README 记录）。机制一样，数字不同。

## 从 HSE 8 MHz 到 72 MHz：PLL ×9

NUCLEO-F103RB 的外部晶振是 **HSE 8 MHz**。经典配置链路：

```
HSE 8 MHz ──→ PLL 倍频器（×9）──→ 72 MHz ──→ SYSCLK
```

**PLL（Phase-Locked Loop，锁相环）** 是模拟电路：
它把输入参考时钟的相位锁到一个压控振荡器（VCO）上，
VCO 跑在参考频率的整数倍上——F103 可选 ×2 到 ×16，经典取 **×9 = 72 MHz**。

所以"8 MHz 晶振跑 72 MHz"的完整答案是：

1. 晶振只负责提供**精准的 8 MHz 参考**（内部 RC 误差 ±1%，晶振 ±20 ppm）；
2. **频率是 PLL 乘出来的**，不是晶振自己振出来的；
3. 切换时钟源由软件完成：开 HSE → 等它稳定 → 配 PLL → 等 PLL 锁定 → 切换 SYSCLK。

## 72 MHz 之后还要分：AHB / APB1 / APB2

SYSCLK 不是终点，它还要分给三拨人：

```
SYSCLK 72 MHz
  ├─ AHB 预分频（÷1）  → HCLK  72 MHz  ──→ CPU、SysTick、DMA、内存
  └─ APB 桥
      ├─ APB1（÷2）    → PCLK1 36 MHz  ──→ TIM2~7、USART2/3、I2C…
      │                    └─ 定时器时钟 ×2 规则 → TIM2~7 实际 72 MHz（19.04）
      └─ APB2（÷1）    → PCLK2 72 MHz  ──→ GPIO、USART1、ADC、TIM1…
```

两个必须记住的数字：

- **APB1 最高 36 MHz**（F1 硬件上限）——72 MHz 主频下 APB1 **必须** ÷2；
- 因为 APB1 分频了，**TIM2~7 的时钟触发 ×2 规则** = 72 MHz
  （[19.05](../19-systick-and-timer/19.05-通用定时器TIM2TIM3.md) 那个"频率差一倍"的坑，
  根源就在这张图里）。

## 为什么这条链对前面每一章都重要

| 前面踩过的坑 | 时钟树里的根源 |
|---|---|
| "延时差 9 倍"（19.05） | 以为 72 MHz 实际还在 HSI 8 MHz——PLL 没配 |
| "PWM 频率差一倍"（19.04） | APB1 ×2 规则：PCLK1=36M 时 TIM2~7 是 72 MHz |
| 串口乱码（ch09） | 波特率 = 时钟 / 分频，**时钟算错全错**——这也是 02-libopencm3 把 PLL 留给 UART 一节的原因 |
| SysTick RVR = 7999 还是 71999（19.01） | 取决于 SYSCLK 是 8 还是 72 MHz |

一句话：**所有"算频率"的代码，输入都来自这张图。**
时钟树配错，下游每个外设都错，而且错得"有规律"——差 9 倍、差 2 倍。

## 坑点（常识怎么说 / 实际是什么）

| 常识怎么说 | 实际是什么 |
|---|---|
| "72 MHz 是晶振振出来的" | 晶振只有 8 MHz。**72 MHz 是 PLL 倍频（×9）出来的**；晶振只提供精准参考 |
| "上电就是 72 MHz" | 上电默认 **HSI 8 MHz**（内部 RC）。72 MHz 要软件开 HSE、配 PLL、切换，三步都做完才是 |
| "内部 RC 和晶振差不多" | HSI 误差 **±1%**（温漂更大），HSE 晶振 **±20 ppm** 量级。做 UART/CAN/USB 必须 HSE |
| "APB1 和 APB2 一样的时钟" | F1 上 APB1 上限 36 MHz（必须 ÷2），APB2 可以 72 MHz。**外设挂在哪条总线上，时钟就不同** |
| "F407 和 F103 时钟一样配" | 默认不同（HSI 16M vs 8M）、上限不同（168M vs 72M）、PLL 参数不同。机制相同，数字全要重查 |

## 代码自测

<details>
<summary>Q1：8 MHz 晶振为什么能跑 72 MHz？PLL 做了什么？</summary>

**频率不是晶振给的，是 PLL 乘出来的。**

晶振的本职是提供**稳定、精准的参考频率**（8 MHz ±20 ppm）。
PLL（锁相环）是一个反馈回路：

```
参考 8 MHz ──→ 鉴相器 ←── VCO 输出 ÷9
                ↓ 误差信号
              压控振荡器（VCO）──→ 输出 72 MHz
```

VCO 自己振荡在高频，鉴相器不停比较"VCO ÷ 9"和参考 8 MHz 的相位差，
把 VCO 拉到"恰好 9 倍"并**锁住**——这就是 ×9 的物理实现。

为什么费这个劲，不直接用 72 MHz 晶振？

- 高频晶振贵、体积大、EMI 难处理；
- 低频晶振 + PLL 倍频**便宜且灵活**：同一个 8 MHz 晶振，
  改 PLL 参数就能出 24/36/48/72 MHz；
- 所以现代 MCU 几乎全是"低频晶振 + 内部 PLL"路线。

换到 F407 同理：HSE → PLL → 168 MHz，只是倍频/分频系数不同。
</details>

<details>
<summary>Q2：上电默认 HSI 8 MHz，为什么还要外部晶振？</summary>

因为 **RC 振荡器不准，晶振准**。

| | HSI（内部 RC） | HSE（外部晶振） |
|---|---|---|
| 精度 | ±1%（且随温度漂移） | ±20 ppm 量级（差 500 倍） |
| 起振 | 上电即有 | 要几毫秒稳定时间 |
| 成本 | 0（芯片内置） | 一颗晶振 + 两个负载电容 |

±1% 在点灯时无所谓，但在这些地方直接出局：

- **UART**：115200 波特率下，两端累计误差超过 ~2% 就开始错帧——
  HSI 一颗芯片就吃掉一半预算；
- **USB**：全速 USB 要求时钟 48 MHz ±0.25%，HSI 根本不可能；
- **CAN**：位时序对时钟误差同样敏感。

所以硬件设计留了两条路：**上电先用 HSI 保底（一定能跑），
软件确认 HSE 稳定后切过去（跑得快且准）**。
这也是"时钟树配置代码"总以"开 HSE → 等 ready 标志"开头的原因。
</details>

<details>
<summary>Q3：72 MHz 主频下，APB1 上的定时器时钟是多少？</summary>

**72 MHz**——这是 F1 时钟树最容易答错的题。

推导三步：

1. SYSCLK = 72 MHz，AHB ÷1 → HCLK = 72 MHz；
2. APB1 硬件上限 36 MHz → 必须 ÷2 → **PCLK1 = 36 MHz**；
3. RM0008 的 ×2 规则：APB 预分频 ≠ 1 时，**定时器时钟 = PCLK × 2**
   → TIM2~7 = 36 × 2 = **72 MHz**。

于是出现反直觉的事实：**APB1 总线比 APB2 慢一半，
但 APB1 上的定时器和 APB2 上的 TIM1 一样快**（都是 72 MHz）。
设计意图是让定时器不受低速总线拖累、保持最大计数分辨率。

代价是直觉算错：按"PCLK1 = 36 MHz"配 PSC/ARR，
实际频率全翻倍（19.04 的实测计划就是拿示波器验证这条）。

**记忆法**：F1 上"定时器时钟"和"总线时钟"是两回事，
算之前先看 `RCC_CFGR` 的 APB 分频位，**别凭直觉**。
</details>
