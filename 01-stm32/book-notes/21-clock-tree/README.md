## 为什么书里没有这一篇

书里从第 1 章到第 18 章，所有程序都跑在**上电默认时钟**上：
F030 是 HSI 8 MHz，本仓库的 F103 也是 HSI 8 MHz。
点灯、按键、中断——8 MHz 全都够用，所以书不提时钟树也顺理成章。

但只要往前走一步，时钟树就绕不开：

| 需求 | 为什么默认时钟不够 |
|---|---|
| UART 115200 波特率 | 8 MHz 分出来的误差偏大，串口乱码（02-libopencm3 明说"波特率算错就看不到串口输出"） |
| USB | **必须** 48 MHz，只能从 PLL 出 |
| SysTick/TIM 定时精度 | 19.1 那个"延时差 9 倍"的坑，根源就是 8 MHz vs 72 MHz |
| RTOS 系统吞吐 | 主频 ×9，同样时间能干的活 ×9 |

"8 MHz 晶振为什么能跑出 72 MHz"——答案是 PLL（锁相环倍频）。
这是裸机工程师的第一堂"模拟数字混合"课，书里没写，这里补。

## 这一篇在讲什么

**时钟从晶振/RC 振荡器出发，怎么一路分到 CPU 和每个外设。**

```
时钟树全景：HSI/HSE → PLL → SYSCLK → AHB/APB（21.1）
   → 为什么每个外设用之前都要先"开时钟"（21.2）
```

## 只看这一页（速览）

**主线一句话**：8 MHz 晶振本身振不出 72 MHz——频率是 PLL 倍频出来的，再经 AHB/APB 分频送到 CPU 和每条外设总线（21.1）；而每个外设还有自己的时钟开关，复位后全关（功耗设计），用前必须先在 RCC 里打开，否则"寄存器写了没反应还不报错"（21.2）。

**每小节一句话结论**：

| 小节 | 一句话结论 |
|---|---|
| 21.1 | 72 MHz 是 PLL 把 HSE 8 MHz 倍频 ×9 出来的（晶振只提供精准参考）；上电默认 HSI 8 MHz，APB1 上限 36 MHz 必须 ÷2，且其定时器时钟 ×2 = 72 MHz。 |
| 21.2 | 复位后所有外设时钟全关（省电），不开就"写不进、读回默认值、无任何报错"；`rcc_clock_setup_pll` 打包五步，其中 Flash 等待周期最容易漏。 |

**本章最容易踩的坑**：

1. 以为上电就是 72 MHz，实际还在 HSI 8 MHz → 延时差 9 倍（21.1）。
2. 忘开外设时钟：写寄存器不生效、读回复位值、引脚不动，且无任何报错（21.2，3.3 实测）。
3. 72 MHz 下漏配 Flash 等待周期：CPU 取指比 Flash 快，程序以千奇百怪的方式跑飞（21.2）。
4. APB1 上定时器时钟是 PCLK1 × 2 = 72 MHz，按 36 MHz 配 PSC/ARR 频率全翻倍（21.1，RM0008）。
5. F407 与 F103 数字全不同（HSI 16M vs 8M、168M vs 72M）：机制可抄，参数必须重查（21.1、21.2）。
