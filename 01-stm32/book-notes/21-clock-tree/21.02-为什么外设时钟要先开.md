## 这一篇讲什么

3.3 有一条实测铁律："**开时钟是第一件事**"——GPIO 配之前先写 RCC 寄存器。
当时只说了"不开会怎样"（三个后果），没说"为什么是这个设计"。
本篇补上机制：**外设时钟门控（clock gating）**，
以及配主频时库函数 `rcc_clock_setup_pll` 实际做的事。

## 外设时钟门控：每个外设一个开关

21.1 那张图只画到 APB 总线。总线到具体外设之间还有**最后一道开关**：

```
PCLK2 ──[IOPAEN]──→ GPIOA
      ──[IOPCEN]──→ GPIOC
      ──[USART1EN]─→ USART1
PCLK1 ──[TIM2EN]───→ TIM2
      ──[USART2EN]─→ USART2
        …每个外设一位，全在 RCC_APB1ENR / RCC_APB2ENR / RCC_AHBENR 里
```

**复位后这些开关全是 0**——所有外设都不给时钟。

为什么 ST 要这么设计？一个字：**功耗**。
时钟树一给电，外设内部的触发器就在翻转、就在耗电。
一个外设哪怕什么都不干，只要时钟通着就在烧电流。
所以默认全关，**用谁开谁**——电池供电的产品里这不是洁癖，是续航。

## 不开时钟的三个后果（3.03 实测的回响）

3.3 的 `portprobe.c` 探针实验实测过"时钟没开时读写外设寄存器会怎样"：

| 操作 | 后果 |
|---|---|
| 写寄存器 | **写不进去**（读回还是复位值）——没有时钟，触发器根本不更新 |
| 读寄存器 | 读到复位值或总线错误，**不是你刚写的值** |
| 配好的"引脚" | 电平纹丝不动——GPIO 没电，输出驱动不工作 |

最坑的是**这一切没有任何报错**：代码照跑，灯就是不亮。
症状和"引脚配错/烧录失败/板子坏了"完全一样——
所以 3.3 才把"开时钟"提到第一行，先排除这个变量。

对照代码（02-libopencm3 实测 7 的库版）：

```c
rcc_periph_clock_enable(RCC_GPIOA);   /* ← 永远是第一步 */
gpio_set_mode(GPIOA, GPIO_MODE_OUTPUT_2_MHZ,
              GPIO_CNF_OUTPUT_PUSHPULL, GPIO5);
```

反汇编里 `RCC_GPIOA` 是 `0x302`——libopencm3 把"哪个使能寄存器（0x300=APB2）+
哪一位（bit2=IOPAEN）"编码进一个常量，函数内部分发。手写版就是
`RCC_APB2ENR |= (1u << 2);`，一回事。

## 配主频的落点：`rcc_clock_setup_pll`

21.1 说的"开 HSE → 配 PLL → 切 SYSCLK"三步，libopencm3 收进了一行：

```c
rcc_clock_setup_pll(&rcc_hse_configs[RCC_CLOCK_HSE8_72MHZ]);
```

这一行背后做的事（机制层面）：

```
1. 开 HSE，等 HSERDY（晶振起振，毫秒级）
2. 配 Flash 等待周期（72 MHz 下 CPU 比 Flash 快，必须插等待，否则取指出错）
3. 配 PLL：源 = HSE，倍频 = ×9，等 PLLRDY（锁定）
4. 配总线分频：AHB ÷1、APB1 ÷2（36 MHz 上限）、APB2 ÷1
5. 切 SYSCLK 到 PLL 输出
```

两点值得记住：

- **第 2 步最容易被手写版漏掉**：Flash 跟不上 72 MHz 的取指速度，
  不配等待周期，程序跑飞的方式千奇百怪（本仓库技术债：随 PLL 实测补）；
- 02-libopencm3 目前**故意不碰**这行——跑在复位默认 HSI 8 MHz，
  "留给 UART 那一节（波特率算错就看不到串口输出）"。
  也就是说：**UART 实验的第一个动作就是配时钟树**，本篇是它的预习。

F407 对照（根 README 记录）：上电默认 HSI 16 MHz，
跑满 168 MHz 同样用 `rcc_clock_setup_pll` 配 PLL——
**同一套机制，换一颗芯片就是换一组参数。**

## 与 LDD- 侧对照

| 概念 | Linux | 裸机 STM32 |
|---|---|---|
| 时钟框架 | CCF（Common Clock Framework）：`clk_prepare_enable()` | RCC 使能位：`RCC_APB2ENR |= bit` |
| 默认状态 | 设备树声明，驱动 probe 时按需开 | **复位后全关**，代码第一行开 |
| 为什么开 | 同样是功耗 | 同样是功耗 |
| 主频切换 | cpufreq 调频 | 配 PLL 切 SYSCLK（一次性的） |

Linux 的 CCF 把这套做成了框架（父时钟、分频、门控一棵树），
STM32 的 RCC 寄存器就是**那棵树的裸露形态**——
在 F103 上看 `RCC_CFGR` 的每一位，等于徒手读 CCF 的数据结构。

## 坑点（常识怎么说 / 实际是什么）

| 常识怎么说 | 实际是什么 |
|---|---|
| "外设寄存器上电就能写" | **复位后外设时钟全关**。写寄存器不生效、读回复位值、引脚不动，且**无任何报错**（3.03 实测） |
| "开时钟是 STM32 的怪癖" | 是**功耗设计**：时钟通着就耗电，默认全关、用谁开谁。Linux CCF 是同一思想的框架化 |
| "配 PLL 就是写一个倍频数" | 至少五步，其中 **Flash 等待周期**最容易漏——72 MHz 下漏了程序直接跑飞 |
| "`rcc_clock_setup_pll` 一行很魔法" | 只是打包了固定五步：HSE → Flash latency → PLL ×9 → 总线分频 → 切换。每一步都对应 RCC 里可读的位 |
| "F407 抄 F103 的时钟代码就行" | 默认 HSI 不同（16M vs 8M）、目标不同（168M vs 72M）、PLL 参数全不同。机制可抄，数字必须重查 |

## 代码自测

<details>
<summary>Q1：为什么"不开外设时钟"的 bug 没有任何报错？</summary>

因为**时钟门控是电气层面的断电，不是软件能检测的状态**。

外设时钟关掉时，它内部的触发器不翻转：

- 你 `STR` 写一个寄存器——总线把数据送到了，但触发器不更新，
  **写操作"成功"地消失了**；
- 你 `LDR` 读——读到的是复位值（或总线默认值），
  **和你刚写的无关**；
- CPU 视角看，这两条指令都正常执行了——
  没有异常、没有 fault、没有错误码。

于是症状只剩一个："**代码全对，硬件没反应**"——
和引脚配错、烧录失败、板子坏了**完全同构**。

这就是 3.3 把"开时钟"放在第一行的工程理由：
**它是唯一一个"症状无法区分、但排除成本为零"的故障源**，
先排除它，后面的排查才有意义。
调试时读一下 `RCC_APB2ENR` 确认对应位是 1，三秒钟的事。
</details>

<details>
<summary>Q2：`rcc_clock_setup_pll(&rcc_hse_configs[RCC_CLOCK_HSE8_72MHZ])` 做了哪几步？哪步最容易漏？</summary>

五步（对应 RCC/FLASH 寄存器里可读的位）：

1. **开 HSE**（`RCC_CR.HSEON`），轮询等 `HSERDY`——晶振起振要毫秒级；
2. **配 Flash 等待周期**（`FLASH_ACR.LATENCY`）——
   72 MHz 下 CPU 一个周期 13.9 ns，Flash 读取跟不上，
   必须插 2 个等待周期，否则**取指出错、程序跑飞**；
3. **配 PLL**（`RCC_CFGR`：源 = HSE，倍频 ×9），开 PLL 等 `PLLRDY`；
4. **配总线分频**：AHB ÷1（72M）、APB1 ÷2（36M 上限）、APB2 ÷1（72M）；
5. **切 SYSCLK 到 PLL**（`RCC_CFGR.SW`），等 `SWS` 确认。

**最容易漏的是第 2 步。** 手写版教程常把它省略，
在 8 MHz 下碰巧没事（Flash 跟得上），一切到 72 MHz 就随机跑飞——
故障表现为 HardFault、死循环、莫名其妙的变量值，极难归因。

`RCC_CLOCK_HSE8_72MHZ` 这个枚举名本身就声明了两件事：
**输入是 8 MHz 的 HSE，目标是 72 MHz**——换晶振频率就得换配置，
这是它和"魔法"的区别：参数全在名字里。
</details>

<details>
<summary>Q3：为什么默认所有外设时钟都关着？全开着会怎样？</summary>

**为了功耗。**

CMOS 电路的动态功耗正比于"时钟频率 × 翻转的晶体管数"。
一个外设只要时钟通着，哪怕你不读不写，
它内部的计数器、状态机、同步器全在跟着时钟翻转——**白耗电**。

对电池供电的设备，"没用到的外设全关钟"是基本功：
F1 一个定时器的时钟开着大约多耗几十~几百 μA 量级，
十几个外设全开着，待机电流能差出几倍。

这个设计反过来定了裸机代码的固定开头：

```c
/* 任何外设使用前的固定三步 */
rcc_periph_clock_enable(RCC_GPIOA);   /* 1. 开时钟（本篇） */
gpio_set_mode(...);                   /* 2. 配寄存器 */
gpio_set(...);                        /* 3. 使用 */
```

和 Linux 对照：**CCF 的 `clk_prepare_enable()` 就是同一件事**——
设备树声明时钟树，驱动 probe 时按需打开，suspend 时关掉。
STM32 的 RCC 寄存器是这套框架的"徒手版"：
没有框架帮你记账，**每个使能位都是你自己的责任**。
</details>
