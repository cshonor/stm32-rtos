# 5.1 if

> 下一篇：[5.2 if-else](5.2-if-else.md)
> 对应实验：`--target=armv7m-none-eabi -mcpu=cortex-m3 -Os` 交叉编译 + 主机侧 clang 23.1.0

## 书这一节讲什么

一句话：**`if (条件) 语句`——条件为真才执行**。书上就是 C 语法入门，
举例大概是"如果温度超过阈值就开风扇"这类。

裸机上 `if` 的价值不在语法，而在**条件从哪来**：
PC 上条件是用户输入、文件、网络；裸机上条件几乎永远是
**"某个寄存器的某一位是不是 1"**——也就是
[4.12 位操作](../04-numbers-and-bitops/4.12-用位操作控制内存映射IO寄存器.md) 的那一套。

## 一、`if` 在 Cortex-M 上长什么样（实测）

四种写法，同一个语义：

```c
int a(int x){ if (x > 0) return 1; return 0; }
int b(int x){ if (x > 0) return 1; else return 0; }
int c(int x){ return (x > 0) ? 1 : 0; }
int d(int x){ return x > 0; }
```

```
$ clang --target=armv7m-none-eabi -mcpu=cortex-m3 -mthumb -Os -c ifs.c -o ifs.o
$ llvm-objdump -d ifs.o
00000000 <a>:
       0: 2800     cmp  r0, #0x0
       2: f04f 0000 mov.w r0, #0x0
       6: bfc8     it   gt        ← If-Then 块：下一条指令条件执行
       8: 2001     movgt r0, #0x1
       a: 4770     bx   lr
0000000c <b>:   （与 a 完全相同）
00000018 <c>:   （与 a 完全相同）
00000024 <d>:   （与 a 完全相同）
```

**四种写法生成的机器码一模一样。** 两个信息：

1. **别为了"效率"纠结写法**——编译器把 if / if-else / 三目 / 直接返回布尔都归成一回事；
2. **`it gt` 是 Thumb-2 的 If-Then 指令**，它让后面 1–4 条指令条件执行，
   从而**省掉一次跳转**。Cortex-M 上短分支几乎不产生跳转开销。

## 二、裸机上 `if` 的真实条件：`reg & BIT(n)`

```c
if (GPIOA_IDR & (1u << 0)) { ... }        /* 读引脚电平 */
if (USART1_SR & (1u << 5)) { ... }        /* 读"发送缓冲空"标志（RXNE 是 bit5） */
if (RTC_CRL & (1u << 0)) { ... }          /* 读"秒标志" */
```

配套的实测（[4.12](../04-numbers-and-bitops/4.12-用位操作控制内存映射IO寄存器.md) 里跑过）：
写 `(reg & BIT(5)) != 0` 编译器会生成**单条 `ubfx`** 提取位，
所以**写可读性最好的那种，指令交给编译器**。

## 三、`if` 的三个裸机特有陷阱

| 陷阱 | 说明 |
|---|---|
| **条件里的变量忘了 `volatile`** | 编译器会假定它不变，把整个判断/循环优化掉（实测见 [5.14 反模式](5.14-反模式.md)） |
| **条件读的寄存器有副作用** | 有些寄存器**读一次就清标志**（如 `USART_SR` 读 + 读 DR 清 `RXNE`）。放进 `if` 里读一次，标志就没了 |
| **`=` 写成 `==`** | `if (flag = 1)` 恒真。`-Wparentheses` 会警告（实测见 [5.14](5.14-反模式.md)） |

第二条最隐蔽，展开一下：

```c
if (USART1_SR & RXNE) {          /* ① 读了一次 SR */
    if (USART1_SR & RXNE) {      /* ② 再读一次 —— 值可能已经变了 */
        c = USART1_DR;           /*    读 DR 会清 RXNE */
    }
}
```

**每次"检查条件"都是一次真实的硬件访问**，不是读一个内存变量。
所以裸机的惯例是**读一次存起来，再判断**：

```c
uint32_t sr = USART1_SR;         /* 读一次 */
if (sr & RXNE) { c = USART1_DR; }
if (sr & TXE)  { USART1_DR = c; }
```

## 坑点（书 / 常识怎么说 / 实际是什么）

| 书 / 常识怎么说 | 实际是什么 |
|---|---|
| "`if` 会产生一次跳转，慢" | Cortex-M 上用 `it` 块让后续指令条件执行，**短分支没有跳转**（实测 `it gt` + `movgt`） |
| "三目运算符比 `if` 快" | 实测四种写法机器码完全相同，选可读的 |
| "条件就是个真假值" | 裸机的条件常常是"读寄存器"——**有副作用**（读清标志、读清 FIFO） |
| "`if (a & b)` 和 `if ((a & b) != 0)` 一样" | 语义一样，但显式 `!= 0` 更不容易被误改成 `== b` |
| "编译器不会动我的 `if`" | 它会：条件变量非 `volatile` 时，整个判断可能被删（[5.14](5.14-反模式.md) 实测） |

## 代码自测

<details>
<summary>Q1：为什么裸机代码里常看到"先把寄存器读进局部变量再判断"？</summary>

因为**对 MMIO 寄存器的每一次读都是一次真实的硬件访问，可能有副作用**。

两类副作用：

1. **读清标志（read-clear）**：某些状态位读一次就自动清零
   （`USART_SR` 的 `RXNE` 靠读 `DR` 清，`EXTI_PR` 靠写 1 清）；
2. **值随时变**：`IDR`（引脚电平）、`CNT`（计数器）在你读的那一刻和下一刻可能不同。

如果直接写：

```c
if (USART1_SR & RXNE) { ... }      /* 读 1 次 */
if (USART1_SR & ORE)  { ... }      /* 读 2 次 —— 两次之间 SR 可能已经变了 */
```

两次读之间硬件状态可能已经变化，你判断的依据是**两个不同时刻的快照**，
逻辑上就可能对不上（比如两个标志其实不该同时为真，你却都进了分支）。

标准写法：

```c
uint32_t sr = USART1_SR;           /* 一次快照 */
if (sr & RXNE) { ... }
if (sr & ORE)  { ... }             /* 判断基于同一时刻 */
```

ISR 里尤其要这么写——**先读一次 SR，按需清标志，再处理数据**。
</details>

<details>
<summary>Q2：`it gt` 是什么？为什么 ARM 的 `if` 没有跳转指令？</summary>

`it` 是 Thumb-2 的 **If-Then 指令**：`it gt` 的意思是
"下面 1 条指令在 `gt`（大于）条件下执行，否则当 `nop`"。

它的作用是**避免短分支的跳转开销**：

```
cmp  r0, #0x0      ; 比较，设置标志位
mov.w r0, #0x0     ; 默认 r0 = 0
it   gt            ; 如果上面比较结果是 "大于"
movgt r0, #0x1     ;   才执行这条（否则整条被跳过）
bx   lr
```

对比传统做法（`bgt label` 跳到另一段代码），`it` 块的好处：

- **不打断指令流**：Cortex-M3 没有分支预测器（M3 只有很简单的预取），
  跳转会造成流水线冲刷；
- **代码更短**：`it` + 条件指令通常比 `b` + 两段代码小。

限制：`it` 块后面最多 4 条指令（`it`、`itt`、`ite`、`itet`… 各种组合）。
**超过 4 条，编译器就退化成真正的跳转**——这也解释了为什么
"if 里的代码越长，越可能看到 `b` 指令"。

实测里四个函数都只用了 `it gt` + `movgt`，因为分支体只有一条指令。
</details>

<details>
<summary>Q3：`if (flag = 1)` 这种笔误，编译器能救我吗？</summary>

能，但**只在它觉得你是笔误的时候**。

```
$ clang -Wall -Wextra -c assign.c
warning: using the result of an assignment as a condition without parentheses [-Wparentheses]
```

而**加了括号就不警告了**：

```c
if ((flag = read_flag()))   /* 这种写法是刻意的：赋值 + 判断，编译器不再警告 */
```

于是真正危险的组合是：**你本意写 `==`，手滑写成 `=`，又恰好加了括号**（或者没开 `-Wall`）。

裸机上这个笔误的后果比 PC 上重：`if (status = REG)` 会**在判断的同时写一次寄存器**——
编译器不报错，硬件收到一次莫名其妙的写。

三条防护：

1. **永远开 `-Wall -Wextra`**，把 `-Wparentheses` 当朋友；
2. **常量放左边**：`if (1 == flag)`——写成 `1 = flag` 编译不过（C 里不能给常量赋值）；
3. 裸机上**别在 `if` 条件里写寄存器**，先读进局部变量（见 Q1）。
</details>
