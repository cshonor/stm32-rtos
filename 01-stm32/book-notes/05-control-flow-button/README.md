# 第 5 章 决策和控制语句 —— 章节导航

> 书：第 5 章 决策和控制语句（原书 p65–77）
> 对应实验：主机侧 clang 23.1.0 + `--target=armv7m-none-eabi -mcpu=cortex-m3` 交叉编译
> （真机按键实验 `01-stm32/05-exti-button` ⬜ 待建；本篇所有读数类结论都标注了"未实测"）

## 这一章在讲什么

**C 的控制语句本身没什么可讲的，任何 C 书都有。这一章对裸机的价值集中在两点：**

1. **5.6–5.10「使用按钮」**——第一次从"输出"（点灯）转向"**输入**"（读引脚），
   第一次遇到纯硬件概念：**上拉/下拉电阻**，以及"**悬空 ≠ 低电平**"；
2. **5.14「反模式」**——两个在 PC 上只是"风格不好"、
   在裸机上会变成**循环消失/丢中断**的写法。本篇用反汇编把它们实锤了。

本章最重要的一个实测：**`while (flag == 0) { }` 在 `-Os` 下被编译成一条 `bx lr`——
等待循环整个消失。** 这是裸机新手最贵的一课。

## 只看这一页（速览）

这一章的控制语句本身在任何 C 书里都有，真正要学的是两件裸机独有的事：
**条件第一次从硬件来**（读引脚，5.6–5.10），以及**等待会被编译器合法地删掉**（5.14）。
抓住"读寄存器是有副作用的真实硬件访问"和"volatile + 超时"两条主线即可。

| 小节 | 一句话结论 |
|---|---|
| 5.1 if | 裸机的条件几乎都是"寄存器某一位是不是 1"；每次读都是真实硬件访问（可能读清标志），要读一次存快照再判断；四种写法实测机器码相同 |
| 5.2 if-else | 分支只是"选一个值"就用 `const` 查表（放 Flash 不占 RAM），要做不同动作才用 `if-else`；漏写 `else` = 寄存器保持复位值，时序悄悄差 9 倍 |
| 5.3 循环 | `do-while` 是"先下命令再等标志"的刚需（状态是动作的产物）；`for` 与 `while` 机器码实测相同；`-O2` 下求和循环被识别成乘法，循环整个消失 |
| 5.4 while | 等待循环条件变量必须 `volatile`（实测 `wait_bad` → 一条 `bx lr`）；循环体写 `{ }` 不写 `;`；所有等待都要配超时 |
| 5.5 for | 空 `for` 延时在 `-O2`/`-Os` 下被删成 `bx lr`；加 `volatile` 保住循环也不准（实测 `-O0` 22 条 vs `-Os` 13 条）；正解是 SysTick |
| 5.6 使用按钮 | 输入引脚必须有确定的空闲电平——悬空是天线不是 0；配置三步：开时钟 → 配输入模式 → 选上/下拉，漏一步静默失效 |
| 5.7 初始化 | 顺序有物理原因：**先开时钟再配寄存器**（时钟没开读回 0、写不进去、无报错）；中断最后才开 |
| 5.8 选择下拉电路 | 上拉按下读 0、下拉按下读 1——看原理图别猜；F1 没有独立 `PUPDR`，靠输入模式下写 `ODR` 位兼任选择，漏了就是浮空 |
| 5.9 获取按钮状态 | `IDR` 每次读都是一次真实引脚采样（只读，一个寄存器管 16 个引脚），读一次存快照；"这一瞬间是 0" ≠ "用户按了一次" |
| 5.10 运行程序 | 不去抖一次按下被读成多次（"按一下 LED 翻 5 回"）；忙等 `delay_ms(20)` 去抖阻塞又不准，正解是定时采样状态机 + 每个 task 立刻返回 |
| 5.11 循环控制 | `break` 只退一层；`goto` **向前跳**做集中清理/退出多层是正当写法（Linux 内核风格），绝不向后跳 |
| 5.12 break | ISR 里的 `break` 可能跳过清中断标志 → NVIC 反复重进 ISR、程序假死；纪律：清标志不依赖控制流（先清再干活） |
| 5.13 continue | 实测被编译器重写成条件清零（`bic.w`），循环里没有跳转；真正价值是"守卫链"把多层嵌套拍平成直线 |
| 5.14 反模式 | 空 `while` + 非 volatile 是正确性问题（等待整个消失，标准允许）；条件里赋值加括号会让 `-Wparentheses` 失效；浮点循环变量在无 FPU 的 M3 上又慢又踩舍入边界 |

**本章最容易踩的坑**：

- 等待循环忘加 `volatile`：`while (flag == 0) { }` 在 `-Os` 下被编译成一条 `bx lr`，等待整个消失（5.4 / 5.14）
- 忘开外设时钟就去配寄存器：读回 0、写不进去、**毫无报错**——"代码全对但没反应"先查时钟（5.7）
- 上拉/下拉方向搞反：程序"能跑"但按下读值全反；F1 上漏写 `ODR` 位 = 实际还是浮空，电平随机（5.6 / 5.8）
- ISR 里 `break` 跳过清中断标志：中断无限重触发，主循环永远跑不到，表现为"程序卡死"（5.12）
- 不去抖：一次按下产生多次电平跳变被逐个读到；书里的 `delay_ms(20)` 忙等去抖开优化就没了（5.10）

## 与书的差异（重要）

| 书 | 我 |
|---|---|
| 用下拉电路（按下读到 1） | 说明**上拉电路按下读到 0**，并强调"看原理图，别猜"（Nucleo 板待实测） |
| 去抖用忙等 `delay_ms(20)` | 不给它背书：实测空循环在 `-O2/-Os` 下**被整个删掉**，改用定时采样状态机 |
| 反模式当风格问题讲 | 用反汇编实锤：**`wait_bad` → `bx lr`**、`-Wparentheses` 加括号就失效 |
| 讲 `if` / `for` 语法 | 实测四种 `if` 写法机器码相同、`for` 与 `while` 机器码相同——**别为效率改写法** |
| 没讲 `goto` | 补上：`goto` 向前跳做清理/退出多层循环是**正当**用法（Linux 内核风格） |

## 读完本章你应该能回答

- 为什么 `while (flag == 0) { }` 会被编译成 `bx lr`？加什么能修？（`volatile`）
- 空 `for` 循环在 `-O0` / `-O2` / `-Os` 下分别有多少条指令？（22 / 1 / 1）
- 读按键前要配哪三件事？顺序错了会怎样？（时钟 → 模式 → 上/下拉；错 = 静默失效）
- 上拉和下拉，按下分别读到什么？F1 上"选上/下拉"靠哪个寄存器？（`ODR` 位兼任）
- 一次机械按下为什么会被读成好几次？三种去抖方案哪个该用？
- ISR 里的 `break` 为什么可能让程序"死掉"？（跳过清中断标志）
- `for` 和 `while` 哪个快？（实测：一样）
