> 上一篇：[8.10 联合体](8.10-联合体.md) ｜ 下一篇：[8.12 结构体与嵌入式编程](8.12-结构体与嵌入式编程.md)

## 书这一节讲什么

一句话：**用 `typedef` 给类型起名字**，让代码说"这是什么"，而不是"它占几个字节"。

书讲的是语法。裸机上 `typedef` 的价值高一个量级，因为：
**在裸机里，"类型"经常就是硬件语义本身**——`uint32_t` 是一个 32 位寄存器，
`millis_t` 是一段毫秒时间，`gpio_pin_t` 是一个引脚编号。
把它们 typedef 出来，等于**把语义写进类型系统**。

## 一、实测：`typedef` 和 `#define` 在指针上分道扬镳

这是本节最值得记住的一条：

```c
#define  PCHAR_DEF  char *
typedef char *      pchar_t;

PCHAR_DEF a, b;      /* 展开成：char *a, b;  */
pchar_t   c, d;      /* 两个都是 char *      */
```

```
$ clang -O0 -o td3 td3.c && ./td3
sizeof(a)=8 sizeof(b)=1      ← b 是 char，不是指针！
sizeof(c)=8 sizeof(d)=8      ← 两个都是指针
```

`#define` 是**文本替换**，`*` 只贴在 `a` 上；
`typedef` 是**类型别名**，`pchar_t` 作为一个整体，`c` 和 `d` 都是指针。

这条在裸机上的杀伤力：

```c
#define  REG  volatile uint32_t *
REG crl, crh;        /* crh 是 volatile uint32_t（不是指针）—— 还顺手丢了 volatile？不，丢了 * */
```

```c
typedef volatile uint32_t * reg_t;
reg_t crl, crh;      /* 两个都是指针 */
```

**规则：类型别名一律用 `typedef`，永远不要用 `#define` 定义类型。**

## 二、`typedef` 在裸机上的三种高价值用法

**① 让"单位"进类型（防单位 bug）**

```c
typedef uint32_t millis_t;      /* 毫秒 */
typedef uint32_t ticks_t;       /* SysTick 计数 */

void delay(millis_t ms);
void delay_ticks(ticks_t n);
```

裸机上看错时间单位是极常见的 bug：8 MHz 和 72 MHz 下的"延时 1000"差 9 倍。
typedef 之后写反了**编译器不一定报错**（都是 `uint32_t`），
但**读代码的人一眼能看出来**——这就是价值。

要更强的保证，用**单成员结构体**包一层：

```c
typedef struct { uint32_t v; } millis_t;      /* 和 ticks_t 真的不兼容了 */
```

**② 给"硬件编号"起类型**

```c
typedef uint8_t gpio_pin_t;     /* 0..15 */
typedef uint8_t adc_ch_t;       /* 0..15 */

void gpio_set(gpio_pin_t pin);
void adc_read(adc_ch_t ch);

adc_read(pin);      /* ⚠ 仍不报错（都是 uint8_t），但读者立刻看出有问题 */
```

**③ 命名函数签名（驱动表/回调）**

```c
typedef void (*uart_rx_cb_t)(const uint8_t *buf, unsigned len, void *ctx);
```

这是 `typedef` 唯一"不可替代"的场景——见 [8.14](8.14-函数指针与typedef.md)。

## 三、⚠ 实测：`const` + typedef 指针，const 的是指针不是数据

```c
typedef char *str_t;
const str_t p = "abc";       /* const 修饰的是"指针"还是"指向的字符"？ */
```

两组对照实验：

```c
*p = 'x';      /* ① 改指向的内容 */
```

```
$ clang -c td.c -o /dev/null
（编译通过，无警告）              ← 说明内容可写
```

```c
p = "def";     /* ② 改指针本身 */
```

```
td2.c:5:7: error: cannot assign to variable 'p' with const-qualified type
                  'const str_t' (aka 'char *const')
    5 |     p = "def";
```

编译器的诊断直接写出答案：**`const str_t` = `char *const`**——
`const` 修饰的是**指针本身**，不是指向的数据。

为什么？因为 `typedef` 是一个**整体**：`str_t` 已经是"指向 char 的指针"这个类型，
`const` 加在整个类型上，就是"这个指针变量不可写"。

想要"指向的数据不可写"，只能手写：

```c
const char *p;          /* 数据 const */
char *const p;          /* 指针 const —— 这就是 const str_t */
const char *const p;    /* 两者都 const */
```

**规则：不要 typedef 指针类型再加 `const`。**
要么直接写 `char *const`，要么 typedef 一个"不含指针"的类型。

## 四、什么时候**不该** typedef

| 情况 | 建议 |
|---|---|
| 整数宽度 | 用 `<stdint.h>` 的 `uint32_t` 等，**别自己 typedef `u32`** |
| 只是省几个字符 | 不值得。`uint32_t` 的 4 个字符省下来，换来的是读者要查定义 |
| 掩盖了"这是指针" | `typedef uint32_t *reg_t;` 之后 `reg_t r` 看不出是指针——**可读性反而变差** |
| 标准已有类型 | `size_t`、`uint8_t`、`bool`——别再造 |

裸机老代码里 `u8/u16/u32` 满天飞（本仓库历史代码也有），
写起来快，但 `uint32_t` 是标准的、读者一眼懂宽度。
**新代码倾向 `<stdint.h>`。**

## 坑点（书 / 常识怎么说 / 实际是什么）

| 书 / 常识怎么说 | 实际是什么 |
|---|---|
| "`typedef` 和 `#define` 差不多" | 实测：指针别名场景下 `#define` 让 `b` 变成 `char`（`sizeof(b)=1`），typedef 两个都是 8 |
| "`const str_t p` 是"指向常量的指针"" | 实测**恰恰相反**：编译器诊断写 `aka 'char *const'`，`*p='x'` 能编译，`p="def"` 报错 |
| "typedef 随便用" | 四类不该用：整数宽度（用 stdint）、纯省字符、掩盖指针性、标准已有类型 |
| "typedef 能让类型更严格" | 不能。`typedef uint32_t millis_t` 和 `ticks_t` **仍可互相赋值**；要严格得用单成员结构体 |
| "起个短名字更好写" | 裸机上"单位/语义"信息比"少打几个字符"值钱得多 |

## 代码自测

<details>
<summary>Q1：`#define` 和 `typedef` 都能起别名，为什么类型必须用 typedef？</summary>

因为 `#define` 是**文本替换**，`typedef` 是**类型别名**。实测：

```c
#define  PCHAR_DEF  char *
typedef char *      pchar_t;
PCHAR_DEF a, b;
pchar_t   c, d;
```

```
sizeof(a)=8 sizeof(b)=1      ← b 只有 1 字节，是 char
sizeof(c)=8 sizeof(d)=8      ← 两个都是指针（8 字节，Mac/arm64）
```

`PCHAR_DEF a, b;` 被预处理器展开成 `char *a, b;`，
`*` 只属于 `a`，`b` 是普通 `char`。

在裸机上这类错误的表现：

```c
#define REG volatile uint32_t *
REG crl, crh;
crh = (volatile uint32_t *)0x40010804;    /* ❌ crh 不是指针，赋值类型不对 */
```

而且这类 bug 常常**不报错**——如果右边碰巧是整数，编译器会警告或静默转换。

`typedef` 之所以对，是因为它产生的是一个**真正的类型**：

```c
typedef volatile uint32_t * reg_t;
reg_t crl, crh;      /* 两个都是 volatile uint32_t * */
```

**规则一句话：定义类型用 `typedef`，定义常量/宏函数用 `#define`。两者不要混。**
</details>

<details>
<summary>Q2：`const str_t p` 到底 const 了谁？想要"指向的数据只读"该怎么写？</summary>

实测结论：**`const str_t` = `char *const`，const 的是指针本身。**

```c
typedef char *str_t;
const str_t p = "abc";

*p = 'x';      /* ✅ 编译通过（无警告）→ 数据可写 */
p = "def";     /* ❌ error: cannot assign to variable 'p' with
                        const-qualified type 'const str_t' (aka 'char *const') */
```

编译器诊断里那句 `aka 'char *const'` 就是铁证。

原因是 `typedef` 名字是一个**不可拆的整体**：
`str_t` 已经是"指向 char 的指针"，`const` 加在它上面就是"这个指针变量只读"。

想要另外两种语义，只能手写（不能用 typedef 名字拼）：

```c
const char *p;          /* 数据只读 */
char *const p;          /* 指针只读 —— == const str_t p */
const char *const p;    /* 都只读 */
```

**为什么这条在裸机上要紧**：

```c
typedef volatile uint32_t * reg_t;
const reg_t r = (reg_t)0x40010800;    /* = volatile uint32_t *const —— 地址不能改 */
*r = 0x1234;                          /* ✅ 照样能写寄存器（volatile 没丢） */
```

看起来 `const` 像在说"这个寄存器只读"，**实际上它说的是"地址不能改"**。
想表达"这个寄存器只读"，应该：

```c
typedef const volatile uint32_t * ro_reg_t;    /* 数据只读 + 每次真读 */
ro_reg_t idr = (ro_reg_t)&GPIOA->IDR;
```

**规则：不要对指针 typedef 加 `const`。**
要么写全 `char *const`，要么把 const/volatile 直接写进 typedef 定义里（如上 `ro_reg_t`）。
</details>

<details>
<summary>Q3：typedef 能让类型更"严格"吗？（millis vs ticks）</summary>

**不能——typedef 只是别名，不是新类型。**

```c
typedef uint32_t millis_t;
typedef uint32_t ticks_t;

millis_t a = 100;
ticks_t  b = a;          /* ✅ 编译通过，无声无息 */
void delay(millis_t ms);
delay(b);                /* ✅ 也通过 */
```

`millis_t` 和 `ticks_t` 就是同一个 `uint32_t`，编译器不做任何区分。

那 typedef 的价值是什么？**给读代码的人看。** 这已经很值了：

```c
delay(1000);                  /* 1000 什么？毫秒？周期数？ */
delay(MS(1000));              /* 好一点 */
millis_t t = 1000; delay(t);  /* 类型即文档 */
```

想要**真正的**类型安全，用单成员结构体包一层：

```c
typedef struct { uint32_t v; } millis_t;
typedef struct { uint32_t v; } ticks_t;

millis_t a = { 100 };
ticks_t  b = a;      /* ❌ error: incompatible types */
```

代价是取值要写 `a.v`，加减要自己写函数（或者 C11 没有运算符重载，只能函数）。
在裸机项目里，这个代价通常**不值得**——除非那段时间单位 bug 反复出现。

**实用折中（本仓库的倾向）**：

- 用 typedef 表达语义（`millis_t`），**接受它不严格**；
- 用**变量名后缀**兜底（`delay_ms`、`timeout_ticks`）；
- 真出过 bug 的地方再升级成单成员结构体。

一句话：**typedef 是给人看的文档，不是给编译器的约束。**
需要约束时用结构体，别指望 typedef。
</details>
