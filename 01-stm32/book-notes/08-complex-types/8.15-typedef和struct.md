# 8.15 typedef 和 struct

> 书：第 8 章 复杂数据类型 · 8.15 typedef 和 struct（原书 p98–118 区间内）
> 上一篇：[8.14 函数指针与 typedef](8.14-函数指针与typedef.md) ｜ 下一篇：[章目录](README.md)
> 对应实验：主机侧 clang 23.1.0（`-std=c11 -Wall -Wextra`）+ Cortex-M 交叉（`_Static_assert` 全通过）

## 书这一节讲什么

一句话：**`typedef` 和 `struct` 组合在一起时的各种写法**——
带 tag、不带 tag、先声明后定义、以及 C11 的匿名成员。

这是本章的收尾小节。它把 8.9（命名）、8.13（typedef）合起来，
给出**可以直接抄的写法清单**。

## 一、实测：四种组合形式都能编译，能力不同

```c
/* 形式①：typedef 一个不完整类型，之后再补全 */
typedef struct uart uart_t;
struct uart { volatile uint32_t SR, DR, BRR, CR1; };   /* 定义留在 .c 里 */

/* 形式②：typedef + 定义一次写完（带 tag）—— 最常用 */
typedef struct gpio { volatile uint32_t CRL, CRH; } gpio_t;

/* 形式③：匿名 typedef */
typedef struct { int x, y; } pt_t;

/* 形式④：给已有 tag 再加一个别名 */
typedef struct gpio gpio_alias_t;
```

```
$ clang --target=armv7m-none-eabi -mcpu=cortex-m3 -mthumb -ffreestanding -std=c11 -Wall -c ts_arm2.c
Cortex-M：断言全部通过（uart_t=16 off(CR1)=12 gpio_t=8 pt_t=8 half_t=4）

$ clang -std=c11 -Wall -Wextra -O2 -o ts ts.c && ./ts      # 主机侧
pt_t=8 gpio_t=8 uart_t=16
```

四种形式的对比：

| 形式 | 能自引用 | 能前向声明 | 能隐藏成员 | 适用 |
|---|---|---|---|---|
| ① `typedef struct uart uart_t;` | ✅ | ✅（这就是它） | ✅ | **对外只给句柄** |
| ② `typedef struct gpio {...} gpio_t;` | ✅ | ✅ | ❌ | **最常用** |
| ③ `typedef struct {...} pt_t;` | ❌ | ❌ | ❌ | 一次性小结构 |
| ④ `typedef struct gpio gpio_alias_t;` | ✅ | ✅ | — | 起第二个名字 |

**默认用②，要隐藏实现用①，③只在确实一次性时。**

## 二、形式①的价值：把成员藏进 `.c`

```c
/* uart.h —— 调用方只看到名字 */
typedef struct uart uart_t;
uart_t *uart_open(unsigned baud);
int     uart_write(uart_t *u, const uint8_t *buf, unsigned n);
void    uart_close(uart_t *u);

/* uart.c —— 真正的布局只在这里 */
struct uart {
    volatile uint32_t SR, DR, BRR, CR1;
    uint8_t  tx_buf[64];
    unsigned tx_head, tx_tail;
};
```

好处：

1. 调用方**看不到也改不了**内部成员（编译期强制）；
2. 改内部布局**不用重编译**所有 include 它的文件；
3. 头文件里不用暴露寄存器定义。

代价：调用方只能拿到 `uart_t *`（**不能**在栈上声明 `uart_t u;`，因为大小未知）。
需要栈上对象时用②，或者提供 `uart_t *uart_create(...)`。

实测 `sizeof(uart_t) == 16`（只有 4 个 `uint32_t` 成员的版本），
`offsetof(uart_t, CR1) == 12`——这些断言只能在**看得到完整定义的 `.c`** 里写。

## 三、C11 匿名成员（anonymous member）

```c
typedef union {
    uint32_t w;
    struct { uint32_t lo:16; uint32_t hi:16; };      /* 没有名字 —— C11 匿名成员 */
} half_t;
```

匿名结构的成员被"提升"到外层，可以直接访问：

```c
half_t h = { .w = 0x12345678 };
printf("w=0x%08x lo=0x%04x hi=0x%04x", h.w, h.lo, h.hi);
```

```
$ clang -std=c11 -O2 -o ts ts.c && ./ts
h.w=0x12345678 h.lo=0x5678 h.hi=0x1234
```

省掉一层 `h.bits.lo` 的写法，读起来更顺。

⚠ 三个前提：

1. **C11 才有**（`-std=c11`，C99 下是非标准扩展）；
2. 位域顺序仍是 implementation-defined——实测 `lo` 拿到的是**低 16 位**（`0x5678`），
   这是 clang + 小端的结果，**不是标准保证**；
3. 别用它定义跨平台数据格式（[8.10](8.10-联合体.md) Q2）。

## 四、⚠ `struct` 关键字在 C 里不能省

```c
struct gpio { ... };
gpio_t g;        /* ✅ gpio_t 是 typedef 名，可以单独用 */
gpio   g2;       /* ❌ C 里不行（C++ 才行） */
struct gpio g3;  /* ✅ */
```

这是 C 和 C++ 的一个著名差异。**本仓库是 C 项目，一律带 `struct` 或用 `_t` 别名。**

## 五、本仓库的写法清单（可以直接抄）

```c
/* ===== 头文件 gpio.h ===== */
#include <stdint.h>

/* 寄存器块：形式②，每个成员 volatile */
typedef struct {
    volatile uint32_t CRL, CRH, IDR, ODR, BSRR, BRR, LCKR;
} GPIO_TypeDef;
#define GPIOA ((GPIO_TypeDef *)0x40010800u)

/* 枚举（带 typedef，显式宽度靠 uint32_t 转换） */
typedef enum { PIN_RESET = 0u, PIN_SET = 1u } pin_state_t;

/* 回调：函数指针 typedef */
typedef void (*gpio_cb_t)(unsigned pin, void *ctx);

/* 对外不透明句柄：形式① */
typedef struct gpio_dev gpio_dev_t;

/* 编译期校验（8.12） */
_Static_assert(offsetof(GPIO_TypeDef, BSRR) == 0x10, "与 RM0008 不符");
```

规则汇总：

1. **有 tag 优先**（8.09）——除非确定一次性；
2. **寄存器块每个成员 `volatile`**（8.12）；
3. **不加 `packed`**（8.12 Q3）；
4. **每个偏移一条 `_Static_assert`**（8.12 Q1）；
5. **函数指针一律 typedef**（8.14）；
6. **整数宽度用 `<stdint.h>`**，不自造 `u32`（8.11）。

## 坑点（书 / 常识怎么说 / 实际是什么）

| 书 / 常识怎么说 | 实际是什么 |
|---|---|
| "typedef struct 就是省一个 `struct`" | 还决定了能不能**自引用/前向声明**（8.09 实测） |
| "匿名 typedef 更简洁" | 实测链表自引用写不了，只能退化成 `void *next` |
| "`typedef struct uart uart_t;` 之后就能 `sizeof`" | ❌ 只有**补全定义之后**才能。实测 `sizeof(uart_t)==16` 是在定义之后的断言 |
| "C11 匿名成员随便用" | 要 `-std=c11`；且位域顺序实现相关（实测 `lo` = 低 16 位 `0x5678`） |
| "C 里可以省略 `struct`" | ❌ C++ 才行。实测 `gpio g2;` 编译不过 |
| "四种写法随便挑" | 能力不同：①能隐藏实现、②最通用、③不能自引用、④只是别名 |

## 代码自测

<details>
<summary>Q1：`typedef struct uart uart_t;` 这种"只有名字没有定义"的写法有什么用？</summary>

**用来把结构体的成员藏进 `.c`，只对外暴露一个"句柄类型"。**

```c
/* uart.h */
typedef struct uart uart_t;                       /* 不完整类型（incomplete type） */
uart_t *uart_open(unsigned baud);
int     uart_write(uart_t *u, const uint8_t *buf, unsigned n);
void    uart_close(uart_t *u);
```

```c
/* uart.c —— 真正的布局只有这里知道 */
struct uart {
    volatile uint32_t SR, DR, BRR, CR1;
    uint8_t  tx_buf[64];
    unsigned tx_head, tx_tail;
};
```

实测（定义补全后）：

```
sizeof(uart_t)=16   offsetof(uart_t, CR1)=12        /* 只有 4 个寄存器的版本 */
```

**三个收益：**

1. **封装**：调用方写不出 `u->tx_head = 0;`——编译期就拦住。
   内部不变量（比如环形缓冲的 head/tail 关系）不可能被外部破坏。
2. **编译防火墙**：改 `struct uart` 的成员不会导致所有 include `uart.h` 的文件重编译。
   在裸机项目里这是个实实在在的构建速度收益。
3. **ABI 稳定**：只要 `uart_t *` 的表示不变，库的用户不用重新适配。

**代价（必须知道）：**

- 调用方**不能**声明 `uart_t u;`（大小未知），也不能 `sizeof(uart_t)`；
- 只能通过 `uart_open()` 之类的工厂函数拿指针（通常是静态区或动态分配）；
- `_Static_assert` 只能写在**看得到完整定义**的 `.c` 里。

**什么时候用哪个：**

| 需求 | 形式 |
|---|---|
| 要隐藏实现 / 稳定 ABI | ① `typedef struct uart uart_t;` |
| 要栈上对象 / 要 `sizeof` / 要成员可见 | ② `typedef struct gpio {...} gpio_t;` |
| 只是个坐标、一次性用完 | ③ 匿名 |

裸机上 ② 最常见（寄存器块本来就该公开，它是**硬件事实**，不是实现细节），
①用在**驱动对象**（有状态、有不变量）上。
</details>

<details>
<summary>Q2：C11 匿名成员好用吗？位域顺序能依赖吗？</summary>

**好用，但位域顺序不能依赖。**

```c
typedef union {
    uint32_t w;
    struct { uint32_t lo:16; uint32_t hi:16; };     /* 匿名：成员提升到外层 */
} half_t;

half_t h = { .w = 0x12345678 };
h.lo;  h.hi;        /* 不用写 h.bits.lo */
```

实测：

```
h.w=0x12345678 h.lo=0x5678 h.hi=0x1234
```

`lo` 拿到的是**低 16 位**（`0x5678`）——符合直觉，但：

**⚠ 这是 clang + 小端的结果，不是标准保证的。**

标准对位域只说了"若干个位"，没有规定：

- 从最低位往上排，还是从最高位往下排；
- 位域能否跨越存储单元边界（这里是 `uint32_t`，刚好 32 位，跨不跨没影响）；
- 大端机器上 `lo`/`hi` 的对应关系。

所以：

| 用途 | 能不能用匿名位域 |
|---|---|
| 描述**本芯片、本编译器**下的寄存器位布局 | ✅ 可以（写出来最好再 `_Static_assert` 校验一次） |
| 调试打印 | ✅ 随便用 |
| **协议 / 文件格式 / Flash 持久化结构** | ❌ **绝对不行**——换编译器就变 |
| 跨平台代码 | ❌ 同上 |

另外两个前提：

1. **要 `-std=c11`**（C99 下匿名成员是 GCC/clang 扩展，不是标准）；
2. 实测匿名 union 大小仍是 4（`_Static_assert(sizeof(half_t)==4)` 通过），
   匿名不会引入额外空间。

**规则：匿名成员用于"看同一块内存的方便写法"，
任何需要跨编译器/跨平台稳定的东西，都用显式的移位和掩码**（[8.10](8.10-联合体.md)）。
</details>

<details>
<summary>Q3：四种 `typedef struct` 写法，我该记哪一个？</summary>

记住**默认 + 两个例外**：

**默认用形式②（带 tag，一次写完）**

```c
typedef struct gpio { volatile uint32_t CRL, CRH; } gpio_t;
```

- 能自引用（`struct gpio *next`）；
- 能前向声明；
- 能 `sizeof`、能放栈上；
- 实测 `sizeof(gpio_t) == 8`（Cortex-M 与 Mac 一致）。

这一个能覆盖 80% 的场景。

**例外一：要隐藏实现 → 形式①**

```c
typedef struct uart uart_t;      /* 头文件 */
struct uart { ... };             /* .c 里补全 */
```

用在"驱动对象"上（有状态、有不变量），见 Q1。

**例外二：确实是一次性的小结构 → 形式③（匿名）**

```c
typedef struct { int x, y; } pt_t;
```

判据：只在**一个 `.c`** 里用、不需要自引用、不需要对外暴露。
实测 `sizeof(pt_t) == 8`。
**拿不准就写 tag**——成本是一个单词，收益是三类能力（8.09 实测）。

**形式④（给已有 tag 加别名）基本不用**，只在"同一个类型要两个语义名字"时出现
（比如 `typedef struct gpio gpio_alias_t;`），实际项目里罕见。

**最后加一条 C 的硬约束**：

```c
struct gpio { ... };
gpio   g2;       /* ❌ C 里不行（C++ 才行） */
struct gpio g3;  /* ✅ */
gpio_t g;        /* ✅ typedef 名可以单独用 */
```

本仓库是 C 项目，**要么带 `struct`，要么用 `_t` 别名**，别指望省关键字。
</details>
