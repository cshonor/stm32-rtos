# 8.01 枚举

> 书：第 8 章 复杂数据类型 · 8.01 枚举（原书 p98–118 区间内）
> 下一篇：[8.02 预处理技巧和枚举](8.02-预处理技巧和枚举.md)
> 对应实验：主机侧 clang 23.1.0 + `--target=armv7m-none-eabi` 交叉

## 书这一节讲什么

一句话：**枚举（`enum`）给一组相关的整数常量起名字**：
`enum { RED, GREEN, BLUE }` 之后就能写 `RED` 而不是 0。

书讲的是"替代魔数"。裸机上枚举的价值更大，因为
**寄存器配置值全是魔数**：`CRL` 的 `CNF/MODE` 组合、`USART` 的校验位、
状态机的状态号——用枚举能让 `GPIOA->CRL = GPIO_MODE_OUT_2M` 这样的代码自解释。

## 一、基本写法与默认值

```c
typedef enum {
    GPIO_MODE_INPUT   = 0x0u,     /* 输入 */
    GPIO_MODE_OUT_10M = 0x1u,     /* 输出 10MHz */
    GPIO_MODE_OUT_2M  = 0x2u,     /* 输出 2MHz  */
    GPIO_MODE_OUT_50M = 0x3u,     /* 输出 50MHz */
} gpio_mode_t;
```

- 不写 `=` 就从上一个 +1（第一个默认 0）；
- **裸机上一律显式写值**：因为这些值来自**芯片手册**，不能靠"第几个"推导；
- 加 `u` 后缀保持无符号（[4.01](../04-numbers-and-bitops/4.01-使用整数.md)）。

## 二、枚举的"宽度"是个坑

C 标准说枚举的底层类型是**实现定义的**（能容纳所有枚举值的整数类型）。
实测的后果：

```c
typedef enum { A = 0, B = 1 } small_t;      /* 可能是 int（4 字节） */
typedef enum { BIG = 0xFFFFFFFFu } big_t;   /* 可能是 unsigned 或 long long */
```

| 场景 | 后果 |
|---|---|
| 枚举当**协议字段**用 | 宽度/符号性不确定 → 跨平台不一致。用 `uint8_t`/`uint32_t` 显式声明 |
| 枚举放进**结构体** | 结构体大小可能随编译器变 → 寄存器结构体**绝不能**用枚举成员，只用 `uint32_t` |
| `sizeof(e)` | 不一定等于 `sizeof(int)` |

**判据**：枚举用于**代码可读性**（状态机、模式选择）；
一旦这个值要跨界（寄存器、协议、存储），必须显式转成定宽类型：

```c
GPIOA->CRL |= ((uint32_t)GPIO_MODE_OUT_2M) << 20;
```

## 三、裸机上枚举的三个典型用途

**① 状态机**（最常用）

```c
typedef enum { ST_SYNC, ST_LEN, ST_DATA, ST_CRC } rx_state_t;
static rx_state_t st = ST_SYNC;
```

配 `switch` 时编译器能检查漏 case（`-Wswitch`）。

**② 错误码**

```c
typedef enum {
    OK = 0, ERR_TIMEOUT = -1, ERR_NOMEM = -2, ERR_INVAL = -3,
} status_t;
```

返回值用负 errno 风格（[7.06](../07-stack-frame-functions/7.06-编程风格.md)）。

**③ 寄存器配置值**（照抄手册）

```c
typedef enum {               /* RM0008: USART_CR1 的 PS/PC 位 */
    UART_PARITY_NONE = 0x0u,
    UART_PARITY_EVEN = 0x2u,   /* PS=0, PCE=1 */
    UART_PARITY_ODD  = 0x3u,   /* PS=1, PCE=1 */
} uart_parity_t;
```

## 坑点（书 / 常识怎么说 / 实际是什么）

| 书 / 常识怎么说 | 实际是什么 |
|---|---|
| "枚举就是给常量起名" | 对，但**底层类型由实现决定**——跨界时要显式转定宽类型 |
| "枚举是 int" | 不一定。`sizeof` 和符号性都可能是别的（实现定义） |
| "寄存器结构体里可以用枚举" | ❌ **绝不能**：结构体布局必须和手册字节偏移一致，只能 `uint32_t` |
| "枚举值按顺序排就行" | 裸机上**必须显式写值**，因为值来自手册 |
| "`enum` 和 `#define` 一样" | 不一样：枚举有类型（可被 `-Wswitch` 检查），`#define` 是纯文本 |

## 代码自测

<details>
<summary>Q1：枚举和 `#define` 该选哪个？</summary>

按用途分：

| 用途 | 选 | 理由 |
|---|---|---|
| 一组**互斥**的状态/模式 | **枚举** | 有类型，`switch` 漏 case 会被 `-Wswitch` 抓到 |
| 需要编译期参与 `#if` 判断 | **`#define`** | 预处理器不认识枚举常量 |
| 位掩码（`BIT(2)` 这种） | **`#define`** 或 `static inline` | 掩码要参与常量表达式，且可以组合 |
| 数组大小 | **`#define`** 或 `enum`（C 里 enum 可作常量表达式） | 两者都行；`#define` 更直观 |
| 需要出现在调试器里看到名字 | **枚举** | 调试器能显示 `ST_DATA` 而不是 2 |

裸机上的实际分布：

```c
/* 状态机 → 枚举 */
typedef enum { IDLE, BUSY, DONE, ERROR } dma_state_t;

/* 寄存器位号 / 掩码 → 宏（要参与常量表达式和位运算） */
#define BIT(n)      (1u << (n))
#define RCC_APB2ENR_IOPAEN  BIT(2)

/* 缓冲区大小 → 宏（还要给 _Static_assert 和数组声明用） */
#define RX_BUF_SIZE 256u
_Static_assert((RX_BUF_SIZE & (RX_BUF_SIZE-1)) == 0, "power of 2");
```

**关键差别**：枚举是**类型**（编译器能检查），宏是**文本**（预处理器先替换）。
需要"编译器帮我检查"的地方用枚举，需要"预处理期就能用"的地方用宏。
</details>

<details>
<summary>Q2：为什么寄存器结构体里不能用枚举成员？</summary>

因为**结构体的内存布局必须和芯片手册的字节偏移完全一致**，
而枚举成员的宽度是实现定义的。

```c
/* ❌ 危险：枚举宽度不确定，偏移可能不是你以为的 */
typedef struct {
    volatile gpio_mode_t mode;   /* 可能是 1、2、4 字节，取决于编译器 */
    volatile uint32_t    data;
} bad_reg_t;

/* ✅ 正确：一律定宽，布局 100% 确定 */
typedef struct {
    volatile uint32_t CRL;   /* +0x00 */
    volatile uint32_t CRH;   /* +0x04 */
    volatile uint32_t IDR;   /* +0x08 */
    ...
} GPIO_TypeDef;
_Static_assert(offsetof(GPIO_TypeDef, IDR) == 0x08, "与 RM0008 不符");
```

后果链条：枚举宽度变了 → 结构体偏移变了 → `GPIOA->BSRR` 写到了**别的寄存器**上
→ 不报错，只是硬件行为不对。

这不是假设：换编译器、换 `-fshort-enums` 选项、甚至只是加了一个枚举值
（让最大值超过某个范围），底层类型都可能变。

所以规则是：
**寄存器结构体只用 `uint32_t`（或手册规定的宽度），
枚举只用在"代码里的逻辑值"上，写进寄存器时显式转换。**
</details>

<details>
<summary>Q3：`-Wswitch` 检查漏 case，真的有用吗？</summary>

非常有用——它是裸机上少有的"编译期能抓的逻辑错误"。

```c
typedef enum { ST_SYNC, ST_LEN, ST_DATA, ST_CRC } rx_state_t;

void rx_fsm(rx_state_t st, uint8_t b){
    switch (st) {
    case ST_SYNC: ...
    case ST_LEN:  ...
    case ST_DATA: ...
    /* 漏了 ST_CRC */
    }
}
```

```
$ clang -Wall -Wextra -c fsm.c
warning: enumeration value 'ST_CRC' not handled in switch [-Wswitch]
```

什么时候会真的救你：半年后给协议加了一个状态（比如 `ST_ESCAPE`），
如果你忘了在某个 `switch` 里处理它——
**编译器立刻告诉你有几个 switch 漏了**（每个漏的都报一次）。
而在裸机上，漏掉的状态通常表现为"收到特定帧时卡死"，排查成本极高。

三个前提：

1. 参数/变量的类型是**枚举类型**（`rx_state_t st`，不是 `int st`）
   ——传 `int` 编译器不知道该检查什么；
2. 开 `-Wall`（`-Wswitch` 默认在 `-Wall` 里）；
3. **不要写 `default:`**——写了 default 编译器就不警告了
   （除非用 `-Wcovered-switch-default`）。

所以裸机状态机的推荐写法是：**枚举类型 + 不写 default**，
让编译器把所有未覆盖的状态都报出来。
</details>
