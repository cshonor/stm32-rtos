# 8.13 typedef

> 书：第 8 章 复杂数据类型 · 8.13 typedef（原书 p98–118 区间内）
> 上一篇：[8.12 结构体与嵌入式编程](8.12-结构体与嵌入式编程.md) ｜ 下一篇：[8.14 函数指针与 typedef](8.14-函数指针与typedef.md)
> 对应实验：主机侧 clang 23.1.0（`-std=c11 -Wall -Wextra`，`sizeof` 实测）

## 书这一节讲什么

一句话：**`typedef` 的语法、作用域，以及它能起别名的类型范围**（不只是结构体）。

书讲的是语言细节。这里挑三条**在真实项目里会咬人**的：

1. `typedef` 是**有作用域**的，可以被内层遮蔽（实测 `sizeof(T)` 内外层不同）；
2. 它也能给**数组类型**和**函数类型**起别名——这两个的语义和直觉不太一样；
3. C11 起**重复 typedef 合法**（实测无警告），但 C99 及更早不行。

## 一、`typedef` 的本质：声明一个"类型名"而不是变量

`typedef` 的语法结构就是**在普通声明前面加 `typedef`**，
被声明的"变量"变成了"类型名"：

```c
unsigned char  x;        /* x 是变量 */
typedef unsigned char T; /* T 是类型名 */
```

这个视角能解释所有复杂声明。比如数组：

```c
typedef int arr3_t[3];       /* 把"arr3_t"放在原本写变量名的位置 */
```

```
$ clang -Wall -o td4 td4.c && ./td4
sizeof(arr3_t)=12 a[2]=3
```

`arr3_t` 就是 `int[3]`，12 字节。

## 二、⚠ 数组 typedef 作为参数时会"退化"

```c
typedef int arr3_t[3];
int f(arr3_t a){ return a[0] + a[1] + a[2]; }    /* 参数真类型是 int*，不是 int[3] */
```

```
$ clang -Wall -o td5 td5.c && ./td5
f=6 sizeof(arr3_t)=12
```

看起来 `f` 收了一个 `arr3_t`（12 字节的数组），
**实际上参数被调整成了 `int *`**（[ch06 6.2](../06-arrays-pointers-strings/6.2-底层细节：指针.md) 讲过的数组退化）。

所以 `sizeof(a)` 在函数里是**指针大小**，不是 12。
这个坑在裸机上的表现：

```c
typedef uint8_t frame_t[64];
void send(frame_t f){
    for (unsigned i = 0; i < sizeof(f); i++) ...    /* ❌ sizeof(f) == 4，不是 64 */
}
```

**规则：数组 typedef 好用，但**别在函数参数上依赖它的大小**。
要么显式传长度，要么把数组包进结构体（结构体传参不退化）。

## 三、函数类型 typedef（不是函数指针！）

```c
typedef void isr_t(void);      /* 函数类型：void(void) */
```

注意这和 [8.14](8.14-函数指针与typedef.md) 的 `typedef void (*isr_fn_t)(void)` **不是一回事**：

| 写法 | 是什么 | 能声明变量吗 |
|---|---|---|
| `typedef void isr_t(void);` | **函数类型** | ❌ 不能（`isr_t x;` 非法） |
| `typedef void (*isr_fn_t)(void);` | **函数指针类型** | ✅ 能 |

函数类型 typedef 的用处只有两个：

```c
isr_t *p = my_handler;        /* 声明函数指针（加个 *） */
isr_t  my_handler;            /* 声明函数原型：等价于 void my_handler(void); */
```

裸机上第二种在头文件里**偶尔**能见到——但可读性差，**不推荐**。
要的是函数指针 typedef，见 [8.14](8.14-函数指针与typedef.md)。

## 四、实测：`typedef` 有作用域，会被内层遮蔽

```c
typedef unsigned char T;              /* 外层：1 字节 */
int main(void){
    { typedef double T; T x = 1.5; (void)x;      /* 内层：8 字节 */
      printf("inner sizeof(T)=%zu\n", sizeof(T)); }
    printf("outer sizeof(T)=%zu\n", sizeof(T));
}
```

```
$ clang -Wall -o td6 td6.c && ./td6
inner sizeof(T)=8
outer sizeof(T)=1
```

内层 `typedef double T` **遮蔽**了外层的 `unsigned char`。
这段代码能编译、能跑，输出 8 和 1——但如果调用者以为 `T` 是字节类型，就会出错。

**规则：`typedef` 一律放文件作用域（头文件里），不要在函数体内 typedef。**
函数体内的 typedef 会让读者必须往上翻才能知道 `T` 是什么。

## 五、实测：C11 允许重复 typedef

```c
typedef uint32_t u32_t;
typedef uint32_t u32_t;      /* 再来一遍 */
```

```
$ clang -std=c11 -Wall -Wextra -c td4.c
（无警告）
```

C11 起，重复的、等价的 typedef **合法**。C99 及更早的编译器会警告或报错。

为什么这条有用？——**头文件重复包含**。虽然现在都用 `#pragma once` / include guard，
但老项目里可能没有。知道这条能省掉一次困惑。

⚠ 但**不等价的重复**仍然非法：

```c
typedef uint32_t u32_t;
typedef unsigned  u32_t;      /* ❌ 不同类型，报错（而且这个类型在 Cortex-M 和 Mac 上还不一样宽） */
```

## 六、该放哪儿：头文件

```c
/* gpio.h */
#ifndef GPIO_H
#define GPIO_H
#include <stdint.h>

typedef struct { volatile uint32_t CRL, CRH, IDR, ODR, BSRR, BRR, LCKR; } GPIO_TypeDef;
typedef enum { PIN_RESET = 0u, PIN_SET = 1u } pin_state_t;
typedef void (*gpio_cb_t)(unsigned pin, void *ctx);

#endif
```

规则：

- **公共类型放头文件**，私有类型放 `.c`（8.9 讲的前向声明可以只暴露 tag）；
- typedef **必须在第一次使用之前**；
- **别在头文件里 typedef 一个只在某个 `.c` 里用的类型**（污染全局命名空间）。

## 坑点（书 / 常识怎么说 / 实际是什么）

| 书 / 常识怎么说 | 实际是什么 |
|---|---|
| "typedef 就是起别名" | 语法上是"把声明里的变量名变成类型名"，所以数组/函数/指针都能 typedef |
| "typedef 全局有效" | **有作用域**。实测内层 `typedef double T` 遮蔽外层，`sizeof(T)` 8 vs 1 |
| "`arr3_t` 参数就是 12 字节数组" | 退化成 `int *`（[ch06](../06-arrays-pointers-strings/6.2-底层细节：指针.md)）。实测 `sizeof(arr3_t)=12` 只在函数外成立 |
| "重复 typedef 会报错" | C11 起合法，实测 `-std=c11 -Wall -Wextra` **无警告**；不等价的重复才报错 |
| "`typedef void isr_t(void)` 就是函数指针" | **不是**，是函数类型。`isr_t x;` 非法，要 `isr_t *x;` |
| "typedef 想写哪写哪" | 一律放文件作用域/头文件。函数体内 typedef 会遮蔽，读代码的人要往上翻 |

<details>
<summary>Q1：`typedef void isr_t(void)` 和 `typedef void (*isr_fn_t)(void)` 有什么区别？</summary>

**一个是函数类型，一个是函数指针类型。**

```c
typedef void  isr_t   (void);      /* 函数类型：void(void) */
typedef void (*isr_fn_t)(void);    /* 函数指针类型：void(*)(void) */
```

| | `isr_t` | `isr_fn_t` |
|---|---|---|
| 是什么 | 函数类型 | 指向函数的指针类型 |
| `X x;` 合法吗 | ❌ 非法（不能声明"函数变量"） | ✅ 合法 |
| `X *x;` | ✅ 合法，就是函数指针 | ⚠ 合法，是指向指针的指针 |
| 典型用途 | 声明函数原型 | 声明函数指针变量/数组 |

实际写法：

```c
isr_t my_handler;                 /* 等价于 void my_handler(void); —— 原型声明 */
isr_t *p = my_handler;            /* 函数指针 */

isr_fn_t q = my_handler;          /* 直接就是函数指针，最常用 */
isr_fn_t vector[16];              /* 函数指针数组 —— 向量表就是这个 */
```

裸机上要的是第二种（`isr_fn_t`）：
[ch03](../03-embedded-system-programming/README.md) 实测的向量表就是
`void (*vector[])(void)` 这种函数指针数组。

**建议：只用函数指针 typedef（`typedef void (*isr_t)(void)`）。**
函数类型 typedef 的唯一好处是声明原型时能少写括号，
但可读性反而更差（读者要反应一下"这是个函数"），**不划算**。

命名上做个区分就不会混：

```c
typedef void (*isr_fn_t)(void);   /* _fn_t 后缀 = 函数指针 */
typedef void (*uart_rx_cb_t)(const uint8_t *, unsigned, void *);   /* _cb_t = 回调 */
```
</details>

<details>
<summary>Q2：数组 typedef 用在函数参数上，为什么 `sizeof` 不对？</summary>

因为**参数里的数组类型会退化成指针**。

```c
typedef int arr3_t[3];
int f(arr3_t a){ return a[0] + a[1] + a[2]; }
```

实测：

```
sizeof(arr3_t)=12          /* 在函数外，arr3_t 确实是 12 字节 */
f=6                        /* 调用正常 */
```

但在 `f` 内部，`a` 的类型已经被调整为 `int *`（C 的语言规则，见
[ch06 6.2](../06-arrays-pointers-strings/6.2-底层细节：指针.md)），
所以 `sizeof(a)` 是指针大小（Cortex-M 上 4，Mac 上 8），**不是 12**。

裸机上的翻车现场：

```c
typedef uint8_t frame_t[64];
void send(frame_t f){
    for (unsigned i = 0; i < sizeof(f); i++)   /* ❌ 只发 4 个字节！ */
        uart_putc(f[i]);
}
```

在 Mac 上会是 8 个字节，在 Cortex-M 上是 4 个——**平台相关的静默 bug**。

三个解法：

```c
/* ① 显式传长度（最常用） */
void send(const uint8_t *f, size_t n);

/* ② 包进结构体（结构体参数不退化） */
typedef struct { uint8_t b[64]; } frame_t;
void send(const frame_t *f);          /* sizeof(f->b) == 64，稳 */

/* ③ 用指针 typedef 提醒自己"这里没长度信息" */
typedef uint8_t *frame_ptr_t;         /* 名字里写明是 ptr，就不会去 sizeof 它 */
```

**规则：数组 typedef 适合用在变量声明和结构体成员上，
不适合用来"假装参数有长度"。参数的长度必须显式传。**
</details>

<details>
<summary>Q3：typedef 放头文件还是 `.c`？重名了怎么办？</summary>

**按"谁需要用"决定：**

| 类型 | 放哪 | 理由 |
|---|---|---|
| 对外 API 用到的（配置结构体、回调类型、句柄） | **头文件** | 调用方要声明变量/传参 |
| 只在实现内部用的（寄存器块、内部状态机） | **`.c`** | 不污染全局命名空间 |
| 只想暴露"有个类型"但不想暴露成员 | 头文件放 `struct tag;` 前向声明（[8.9](8.9-结构命名.md)） | 隐藏实现 |

**重名问题**：C 没有命名空间，两个头文件都 typedef 了 `cfg_t` 就冲突。
实测的应对方式：

- **加前缀**：`uart_cfg_t` / `spi_cfg_t`，而不是都叫 `cfg_t`——
  这是裸机和 Linux 内核的通行做法（`struct usb_device` 而非 `struct device`）；
- **重复但等价的 typedef 在 C11 合法**（实测 `-std=c11 -Wall -Wextra` 无警告），
  所以同一个头文件被 include 两次没问题（前提是有 include guard 或 `#pragma once`）；
- **不等价的重复 typedef 一定报错**——比如一个头文件写 `typedef uint32_t u32_t`，
  另一个写 `typedef unsigned u32_t`。这也是"别用 `u32` 这种自造短名"的又一个理由
  （[8.11](8.11-创建自定义类型.md)）：不同作者定义会打架。

**作用域陷阱**（实测）：

```
inner sizeof(T)=8       /* 函数体内 typedef double T 遮蔽了外层的 unsigned char */
outer sizeof(T)=1
```

所以**不要**在函数体内 typedef——它会悄悄遮蔽外层同名类型，
而调用那个函数的人完全看不到。

**本仓库的约定**：公共类型进头文件、加模块前缀（`gpio_` / `uart_` / `systick_`），
私有类型留在 `.c` 里加 `static`。
</details>
