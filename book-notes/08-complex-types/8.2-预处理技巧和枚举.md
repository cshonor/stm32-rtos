## 书这一节讲什么

一句话：**用预处理器的技巧让枚举更好用**——
书讲的是"用宏自动生成枚举相关的字符串表"这类技巧
（`X 宏` 技法：一处定义，多处展开成枚举和字符串数组）。

这是全书少见的"纯技巧"小节。本篇保留它的价值，
但补上裸机上的判断：**这类技巧在 Flash 紧张时是有代价的**（字符串表占 Flash）。

## 一、X 宏技法（书里的技巧）

一处定义，多处展开：

```c
/* ① 定义列表（只有一个真源） */
#define GPIO_MODE_LIST \
    X(GPIO_MODE_INPUT,   0x0u) \
    X(GPIO_MODE_OUT_10M, 0x1u) \
    X(GPIO_MODE_OUT_2M,  0x2u) \
    X(GPIO_MODE_OUT_50M, 0x3u)

/* ② 展开成枚举 */
#define X(name, val) name = val,
typedef enum { GPIO_MODE_LIST } gpio_mode_t;
#undef X

/* ③ 展开成"名字"字符串表 */
#define X(name, val) #name,
static const char *const gpio_mode_names[] = { GPIO_MODE_LIST };
#undef X

/* 用法 */
puts(gpio_mode_names[mode]);     /* 打印 "GPIO_MODE_OUT_2M" */
```

好处：**加一个模式只改一处**，枚举和字符串表自动同步——
不会出现"枚举改了、打印表没改"的经典 bug。

## 二、裸机上的代价：字符串表占 Flash

```
$ llvm-size firmware.elf
   text    data     bss
   3200     12     256        ← text 里就含那些 const 字符串
```

每个名字平均 15–20 字节，10 个模式就是 200 字节 Flash。
在 128 KB Flash 上不算什么，但：

- **日志字符串是大头**：一个完整的日志系统轻松吃掉 10 KB+；
- 可以用**编译期开关**控制：`#ifdef ENABLE_DEBUG_NAMES` 才生成名字表。

```c
#ifdef ENABLE_DEBUG_NAMES
#define X(name, val) #name,
static const char *const gpio_mode_names[] = { GPIO_MODE_LIST };
#undef X
#endif
```

## 三、裸机上更常用的三个"预处理 + 枚举/常量"技巧

**① 编译期校验配置值**

```c
typedef enum { CFG_BAUD_9600 = 9600, CFG_BAUD_115200 = 115200 } baud_t;
_Static_assert(CFG_BAUD_115200 <= 4500000u, "超出 USART 能力");
```

**② 条件编译选择硬件配置**

```c
#if defined(BOARD_NUCLEO_F103RB)
    #define LED_PORT GPIOA
    #define LED_PIN  5
#elif defined(BOARD_F407_DISCOVERY)
    #define LED_PORT GPIOF
    #define LED_PIN  9
#endif
```

**③ 用宏生成寄存器访问（配合枚举的位值）**

```c
#define REG32(base, off) (*(volatile uint32_t *)((base) + (off)))
#define SET_FIELD(reg, field, val) \
    ((reg) = ((reg) & ~(field##_MASK)) | (((uint32_t)(val)) << (field##_SHIFT)))
```

## 四、宏的两个经典陷阱（书的 ch12 会展开，这里先列）

```c
#define SQUARE(x)  x * x
SQUARE(a + 1)      /* 展开成 a + 1 * a + 1 —— 错 */

#define MAX(a,b)  ((a) > (b) ? (a) : (b))
MAX(i++, j++)      /* 副作用被求值两次 —— 错 */
```

裸机上多一条：**宏里的地址常量要带 `u` 后缀**（[4.1](../04-numbers-and-bitops/4.1-使用整数.md)），
否则 `0x40010800 + off` 可能被当 signed，溢出就是 UB。

## 坑点（书 / 常识怎么说 / 实际是什么）

| 书 / 常识怎么说 | 实际是什么 |
|---|---|
| "X 宏一处定义多处展开，很优雅" | 优雅，但**生成的字符串表占 Flash**；用 `#ifdef` 控制是否编译 |
| "宏能替代枚举" | 宏是文本、枚举是类型。需要编译器检查（`switch` 漏 case）时只能用枚举 |
| "宏参数加括号就够了" | 不够：还要防**副作用重复求值**（`MAX(i++, j++)`） |
| "技巧越多代码越高级" | 裸机上更看重"能不能一眼对着手册读懂"。技巧要服务于这个目标 |

## 代码自测

<details>
<summary>Q1：X 宏技法在裸机上值不值得用？</summary>

看规模和维护频率：

**值得用的场景**

- 枚举值 ≥ 8 个，且**需要打印名字**（日志、命令行 help、诊断）；
- 枚举会**经常增删**（协议版本演进、多型号适配）；
- 有"值 ↔ 名字"双向需求（解析命令时要反查）。

这时 X 宏省下的是"忘改一处导致日志打印错名字"这类 bug——
而这类 bug 在裸机上很浪费时间（你会怀疑是数据错了，其实是打印错了）。

**不值得的场景**

- 枚举只有 3–5 个且从不打印名字 → 直接写枚举，别引入 X 宏的阅读成本；
- Flash 极度紧张 → 字符串表不划算（用数字 + 文档代替）；
- 团队不熟悉 → X 宏的 `#define X` / `#undef X` 会让不熟悉的人困惑。

**折中方案**（推荐）：把名字表放进 `#ifdef`：

```c
#ifdef ENABLE_NAMES
#define X(n, v) #n,
static const char *const names[] = { LIST };
#undef X
#endif
```

调试版本打开，发布版本关掉。
这比"要么全有要么全无"更实用。
</details>

<details>
<summary>Q2：`#if` 能用枚举常量吗？</summary>

不能——**预处理器不认识枚举**。

```c
typedef enum { BUF_SIZE = 64 } e_t;

#if BUF_SIZE > 32          /* ❌ 预处理器眼里 BUF_SIZE 未定义 → 当成 0 */
/* 结果是假，整段被跳过，而且不报错！ */
#endif

#if CFG_BUF_SIZE > 32      /* ✅ 宏可以（CFG_BUF_SIZE 是 #define 的） */
#endif
```

这是最阴的一类错误：**不报错，只是条件判断的结果是错的**，
于是某段代码"莫名其妙没被编译进去"。

规则：

| 需求 | 用 |
|---|---|
| 参与 `#if` / `#ifdef` | **`#define`**（预处理器只认宏） |
| 数组大小、case 标签、常量表达式 | 枚举和宏都行 |
| 需要编译器类型检查 | 枚举 |

顺带一个相关陷阱：`_Static_assert` 是**编译器**处理的（不是预处理器），
所以它可以放心用枚举常量：

```c
_Static_assert(BUF_SIZE >= 64, "");     /* ✅ 枚举常量在编译器眼里是常量表达式 */
```
</details>

<details>
<summary>Q3：宏展开里的副作用问题，裸机上有什么特别严重的例子？</summary>

最严重的一类：**宏参数里带寄存器读**（因为读可能有副作用）。

```c
#define MAX(a,b) ((a) > (b) ? (a) : (b))

uint32_t x = MAX(USART1_SR & RXNE, 0);   /* 展开后 SR 被读了两次！ */
```

`USART1_SR` 是 `volatile`，两次读都是真实的硬件访问；
如果那个寄存器是**读清标志**型的，第一次读就把标志清了，
第二次读到的就是别的值——比较结果本身就不可信。

其他裸机特有的：

```c
#define SET_BIT(reg, n) ((reg) |= (1u << (n)))
SET_BIT(GPIOA->ODR, i++);      /* i 被加了两次 */

#define DELAY_US(n) delay(n)
DELAY_US(get_ticks());         /* 参数求值两次 → 时间戳不一致 */
```

三条防护：

1. **宏参数一律加括号**，且**在宏体里只出现一次**
   （做到这点要改用 `static inline` 或 GCC 的 `__typeof__` 语句表达式）；
2. **能写成 `static inline` 函数的就别写宏**（[7.3](../07-stack-frame-functions/7.3-函数.md)）——
   函数参数只求值一次，还有类型检查；
3. **不要把"读寄存器"写进宏参数**：先读进局部变量，再传。

```c
uint32_t sr = USART1_SR;                  /* 读一次 */
uint32_t flag = (sr & RXNE) ? 1u : 0u;    /* 用局部值 */
```
</details>
