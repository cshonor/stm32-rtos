# 8.6 结构体初始化

> 书：第 8 章 复杂数据类型 · 8.6 结构体初始化（原书 p98–118 区间内）
> 上一篇：[8.5 访问未对齐数据](8.5-访问未对齐数据.md) ｜ 下一篇：[8.7 结构体赋值](8.7-结构体赋值.md)
> 对应实验：主机侧 clang 23.1.0 + `--target=armv7m-none-eabi -ffreestanding`

## 书这一节讲什么

一句话：**结构体可以像数组一样用 `{}` 初始化**：
`struct point p = { 1, 2 };`。

书讲语法。裸机上要额外关心两件事：
**初始化让结构体进 `.data`（占 Flash）**，以及**指定初始化器（`.x = 1`）为什么更安全**。

## 一、三种写法

```c
typedef struct { uint32_t baud; uint8_t parity; uint8_t stop; } uart_cfg_t;

uart_cfg_t a = { 115200, 0, 1 };                 /* ① 按位置 */
uart_cfg_t b = { .baud = 115200, .stop = 1 };    /* ② 指定初始化器（推荐） */
uart_cfg_t c;                                    /* ③ 不初始化（全局则 .bss 清零） */
```

**裸机上推荐 ②（指定初始化器）**：

- 成员顺序变了不会静默错位（按名字对齐）；
- 没写的成员自动为 0，不用占位写 `0`；
- 读代码的人一眼看出每个值是什么意思：

```c
static const uart_cfg_t cfg = {
    .baud   = 115200,
    .parity = UART_PARITY_NONE,
    .stop   = 1,
    .flow   = 0,
};
```

## 二、初始化 vs 不初始化：段归属的差别

| 写法 | 段 | Flash | RAM |
|---|---|---|---|
| `uart_cfg_t c;`（全局） | `.bss` | 0 | 全清零（启动时） |
| `uart_cfg_t c = {0};`（全局） | **`.data`** ⚠ | 一份镜像 | 启动时拷贝 |
| `const uart_cfg_t c = {...};` | `.rodata` | 一份 | **0** |
| 局部 `uart_cfg_t c;` | 栈 | —— | 栈上，**值是垃圾** |

（[4.4 初始化](../04-numbers-and-bitops/4.4-初始化.md) 实测过 `D` vs `B` 的符号差别。）

裸机的两条经验：

1. **配置结构体一律加 `const`** → 进 Flash，省 RAM（20 KB 很贵）；
2. **默认全 0 的配置不要写 `= {0}`** → 那会让它从 `.bss` 挪进 `.data`，白占 Flash。

## 三、寄存器结构体**绝对不要**初始化

```c
#define GPIOA ((GPIO_TypeDef *)0x40010800u)     /* ✅ 只是个指针常量 */

GPIO_TypeDef *p = ...;                           /* 不要对 MMIO 结构体做"整体赋值/初始化" */
```

原因：**对寄存器结构体做整体初始化会依次写每一个寄存器**，
包括那些你不该动的（`LCKR` 锁寄存器、保留位）。
裸机的规则永远是**逐字段读-改-写**（[4.12](../04-numbers-and-bitops/4.12-用位操作控制内存映射IO寄存器.md)）。

## 四、嵌套结构体与数组

```c
typedef struct { uint8_t addr; uint8_t reg; const uint8_t *data; uint8_t len; } xfer_t;

static const xfer_t init_seq[] = {
    { .addr = 0x3C, .reg = 0x00, .data = (const uint8_t[]){0xAE}, .len = 1 },  /* 关显示 */
    { .addr = 0x3C, .reg = 0xD5, .data = (const uint8_t[]){0x80}, .len = 1 },  /* 设分频 */
    /* ... */
};
_Static_assert(sizeof init_seq / sizeof init_seq[0] == 2, "");
```

这是裸机上非常常见的"**初始化序列表**"模式（上电给外设灌一串寄存器），
它把"一堆魔法写操作"变成了一张能读的表，而且全在 Flash 里。

## 坑点（书 / 常识怎么说 / 实际是什么）

| 书 / 常识怎么说 | 实际是什么 |
|---|---|
| "结构体初始化就是 `{}`" | 三种写法，指定初始化器（`.x=`）最安全 |
| "局部结构体不初始化也没事" | 值是**栈上残留**（[4.4](../04-numbers-and-bitops/4.4-初始化.md)） |
| "写 `= {0}` 更规范" | 裸机上更贵：从 `.bss` 挪进 `.data`，多占 Flash |
| "可以整体初始化寄存器结构体" | ❌ 会写到你不该写的寄存器（含锁定位和保留位） |
| "`const` 结构体能用吗" | ✅ 强烈推荐：进 Flash，不占 RAM |

## 代码自测

<details>
<summary>Q1：为什么推荐"指定初始化器"而不是按位置？</summary>

因为**按位置初始化在成员顺序变化时静默错位**。

```c
typedef struct { uint32_t baud; uint8_t parity; uint8_t stop; } uart_cfg_t;

/* 某人后来把 stop 挪到了 parity 前面 */
typedef struct { uint32_t baud; uint8_t stop; uint8_t parity; } uart_cfg_t;

uart_cfg_t a = { 115200, 0, 1 };          /* ❌ 静默变成 stop=0, parity=1 —— 反了！ */
uart_cfg_t b = { .baud = 115200, .parity = 0, .stop = 1 };   /* ✅ 按名字，不受影响 */
```

第一种**编译通过、不报警告**（类型都是 `uint8_t`），
行为却变了——这正是裸机上最难查的那类 bug。

三个额外好处：

1. **可以跳过成员**：没写的自动为 0，不用写 `{115200, 0, 0, 0, 0}` 这种占位；
2. **自解释**：`.baud = 115200` 比 `115200` 清楚；
3. **和 `-Wmissing-field-initializers` 配合**：这个警告会提示"哪些成员没写"，
   用指定初始化器时是**有意为之**，用按位置写法时容易漏。

⚠ 注意：C++ 里指定初始化器要求成员顺序与声明一致（C 里允许乱序，C++ 不允许）。
本仓库是 C，可以放心用。
</details>

<details>
<summary>Q2：`const` 结构体真的不占 RAM 吗？</summary>

是的——**落在 `.rodata`，链接脚本把它放进 Flash**。

```
$ clang --target=armv7m-none-eabi -mcpu=cortex-m3 -mthumb -ffreestanding -c strseg.c
$ llvm-nm strseg.o
00000000 D buf      ← char buf[] = "abc"      → .data（RAM）
00000004 R lit      ← const char lit[] = ...  → .rodata（Flash）
00000000 R p        ← 指针常量                 → .rodata（Flash）
```

（[6.5](../06-arrays-pointers-strings/6.5-字符和字符串.md) 的实测。）

条件是：

1. 声明带 `const`；
2. **内容在编译期已知**（不是运行时填的）；
3. 链接脚本把 `.rodata` 放进了 Flash（本仓库的链接脚本如此，[ch11](../ch11-linker.md)）。

例外要注意：**`const` 局部变量**仍在栈上（`const` 只表示"不能改"，不改变存储期）：

```c
void f(void){
    const uart_cfg_t cfg = { .baud = 115200 };   /* 在栈上！每次调用都构造一次 */
}
static const uart_cfg_t cfg = { .baud = 115200 }; /* ✅ 静态 const → Flash */
```

裸机上大量出现的"初始化序列表""查找表""命令表"，
都该写成 `static const` ——一块 RAM 都不占。
</details>

<details>
<summary>Q3：能不能对寄存器结构体做整体赋值？</summary>

不能（几乎总是错误的）。

```c
GPIO_TypeDef *gpio = GPIOA;
*gpio = (GPIO_TypeDef){ .CRL = 0x44444444, .CRH = 0x44444444 };   /* ❌ 别这样 */
```

三个问题：

1. **写到了你不该动的寄存器**：复合字面量里没写的成员是 0，
   于是 `BSRR`、`BRR`、`LCKR` 全被写成 0。
   `LCKR`（配置锁）尤其危险——某些序列会**锁死**引脚配置，直到下次复位；
2. **生成 `memcpy` 调用**：大结构体会变成库函数调用
   （[7.2](../07-stack-frame-functions/7.2-隐藏变量.md) 实测 `U __aeabi_memcpy`），
   既占 Flash 又慢；
3. **丢失"读-改-写"语义**：寄存器操作必须只改关心的位，
   整体赋值是"全量覆盖"（[4.12](../04-numbers-and-bitops/4.12-用位操作控制内存映射IO寄存器.md)）。

正确做法永远是**逐字段、先清再置**：

```c
GPIOA->CRL &= ~(0xFu << 20);       /* 只动 PA5 的 4 位 */
GPIOA->CRL |=  (0x2u << 20);
GPIOA->BSRR = (1u << 5);           /* 写 1 生效，一条 str */
```

一句话：**寄存器是"位打包的硬件接口"，不是一块可以整体覆盖的内存。**
结构体只是用来给每个寄存器**命名**的地图，不是用来整体操作的。
</details>
