# 6.1 数组

> 书：第 6 章 数组、指针和字符串 · 6.1 数组（原书 p78–88 区间内）
> 下一篇：[6.2 底层细节：指针](6.2-底层细节：指针.md)
> 对应实验：主机侧 clang 23.1.0（`-O0`）+ `--target=armv7m-none-eabi` 交叉

## 书这一节讲什么

一句话：**数组是"同一类型的连续一串元素"**，用 `int a[4]` 声明、`a[0]` 访问。

书讲的是用法。裸机上数组的分量更大，因为：
**裸机没有堆（通常不用 `malloc`），所有缓冲区都是编译期定死的数组**
——串口缓冲、ADC 采样序列、协议帧、显示缓冲，全是数组。
所以"数组有多大、放在哪、会不会越界"就是你全部的内存管理。

## 一、实测：数组名不是指针

```c
int a[4] = {10,20,30,40};
int *p = a;
```

```
$ clang -O0 -o arr arr.c && ./arr
a=0x16f68f5f0 p=0x16f68f5f0 &a[0]=0x16f68f5f0     ← 三个地址值完全相同
sizeof(a)=16 sizeof(p)=8                            ← 但 sizeof 完全不同
a+1=0x16f68f5f4  (差 4 字节)
&a+1=0x16f68f600 (差 16 字节)                       ← 步长差 4 倍
```

**地址一样，`sizeof` 不一样**——这是"数组名不是指针"的铁证。

原因是数组名在**大多数表达式里会 decay（退化）成 `&a[0]`**，
但有三个例外：`sizeof(a)`、`&a`、`_Alignof(a)`。

| 表达式 | 类型 | 值/步长 |
|---|---|---|
| `a`（退化后） | `int *` | 首元素地址 |
| `sizeof(a)` | `size_t` | **16**（整个数组） |
| `&a` | `int (*)[4]` | 首地址，但 `+1` 前进 **16** 字节 |
| `&a[0]` | `int *` | 首地址，`+1` 前进 **4** 字节 |

## 二、裸机上数组放在哪（三条规则）

| 声明 | 落点 | 说明 |
|---|---|---|
| 全局 `uint8_t buf[64];` | `.bss` | 占 64 字节 RAM，启动时清零 |
| 全局 `uint8_t buf[64] = {...};` | `.data` | **Flash + RAM 各 64 字节**（[4.2](../04-numbers-and-bitops/4.2-声明变量.md) 实测） |
| `const uint8_t tbl[] = {...};` | `.rodata` → **Flash** | 不占 RAM（查表首选） |
| 局部 `uint8_t buf[64];` | **栈** | ⚠ 栈只有 20 KB 总量，大缓冲别这么放 |
| 局部 `static uint8_t buf[64];` | `.bss` | ✅ 跨函数生命周期的缓冲就该这么写（[4.2](../04-numbers-and-bitops/4.2-声明变量.md)） |

一句话：**大缓冲区 = `static` 或全局；只读数据 = 加 `const` 放 Flash。**

## 三、sizeof 求长度：只在数组可见的作用域里对

```c
#define NELEM(a) (sizeof(a) / sizeof((a)[0]))
```

```c
void f(uint8_t buf[]){                 /* 参数其实是 uint8_t *buf */
    size_t n = sizeof(buf);            /* ❌ 得到的是指针宽度，不是数组长度 */
}
```

**数组传进函数就退化成指针，长度信息丢失。**
所以裸机代码里所有"传数组"的函数都要**额外收一个 `len` 参数**：

```c
void send_bytes(const uint8_t *buf, size_t len);      /* 标准形状 */
```

防御手段（编译期抓这个错误）：

```c
#define NELEM(a) (sizeof(a) / sizeof((a)[0]))
/* 或者用一个"只能接收真数组"的宏（Linux 内核的 ARRAY_SIZE 思路） */
_Static_assert(NELEM(rx_buf) == 64, "rx buffer size");  /* 在能看到数组的那一侧断言 */
```

## 四、数组的初始化

```c
uint8_t a[4] = {1, 2};            /* 剩下的自动为 0 → {1,2,0,0} */
uint8_t b[4] = {0};               /* 全 0（但会进 .data，占 Flash） */
uint8_t c[4];                     /* 全局则 .bss 清零；局部则是栈垃圾值 */
uint8_t d[]  = {1,2,3};           /* 长度由初值推导 = 3 */
```

裸机上的注意点：

- `= {0}` 会把数组从 `.bss` 挪进 `.data`——**1 KB 的缓冲多占 1 KB Flash**
  （[4.4 初始化](../04-numbers-and-bitops/4.4-初始化.md) 讲过同一条）；
- 想让大数组留在 `.bss` 就**不写初值**，在 `main` 里用代码填。

## 坑点（书 / 常识怎么说 / 实际是什么）

| 书 / 常识怎么说 | 实际是什么 |
|---|---|
| "数组名就是指针" | **不是**。实测 `sizeof(a)=16` vs `sizeof(p)=8`；`&a+1` 与 `a+1` 差 16 vs 4 字节 |
| "`sizeof(arr)/sizeof(arr[0])` 求长度" | 只在**数组可见的作用域**里对。传进函数后 `sizeof` 得到指针宽度 |
| "数组越界会崩溃" | 裸机上不会（[6.4 数组溢出](6.4-数组溢出.md) 实测）。常量下标 clang 会 `-Warray-bounds`，运行时下标一声不响 |
| "局部数组挺方便" | 大数组放栈上会**爆栈**（NUCLEO-F103RB 只有 20 KB RAM）。用 `static` |
| "数组初始化成 `{0}` 最规范" | 裸机上更贵：进 `.data`，Flash + RAM 双份 |

## 代码自测

<details>
<summary>Q1：`sizeof(a)` 和 `sizeof(p)` 为什么不一样？打印的地址明明相同。</summary>

因为 `sizeof` 是**编译期按类型**算的，跟运行时的值无关。

```c
int a[4];        /* 类型 int[4] → sizeof = 4×4 = 16 */
int *p = a;      /* 类型 int*  → sizeof = 8（Mac/arm64）或 4（Cortex-M） */
```

打印出来的地址相同，是因为 `printf("%p", a)` 里的 `a` 发生了**数组到指针的退化**——
它变成了 `&a[0]`。退化发生在**除三种情况外的所有表达式**里：

```c
sizeof(a)   /* 不退化 → 16        */
&a          /* 不退化 → 类型 int(*)[4]，+1 前进 16 字节 */
&a[0]       /* 退化   → 类型 int*，+1 前进 4 字节  */
a + 1       /* 退化   → 前进 4 字节 */
&a + 1      /* 不退化 → 前进 16 字节（实测：0x...5f0 → 0x...600） */
```

**裸机上的直接后果**：`GPIOA_BASE + 1` 加的是 1 字节还是 1 个寄存器宽度，
取决于那个 base 是整数常量还是指针。所以本仓库统一用
`REG32(base, off)` 宏把 base 当**整数**算、再显式转换成指针解引用，消掉歧义。
</details>

<details>
<summary>Q2：裸机的缓冲区该声明成什么样？</summary>

按生命周期和大小两个维度：

| 需求 | 写法 | 落点 |
|---|---|---|
| 跨函数、需要保留（串口缓冲、采样序列） | `static uint8_t buf[N];` | `.bss`（RAM） |
| 只在这一次调用里用、很小（< 64 字节） | `uint8_t tmp[32];` | 栈 |
| 只读的查找表、常量数组 | `const uint8_t tbl[] = {...};` | `.rodata`（**Flash，不占 RAM**） |
| 大数组（> 256 字节） | **必须** `static` 或全局 | `.bss` |

三条硬约束：

1. **NUCLEO-F103RB 只有 20 KB RAM**，栈从 `_estack = 0x20005000` 往下长。
   一个 1 KB 的局部数组就能吃掉 5% 的栈预算，而栈溢出**没有任何报错**
   （没有 MMU、没有守卫页），只会静默踩 `.bss`/`.data`。
2. **Flash 有 128 KB**，比 RAM 宽裕得多——所以只读数据一律加 `const` 送进 Flash。
3. 大小用宏定义并配 `_Static_assert`：

```c
#define RX_BUF_SIZE 256u
static uint8_t rx_buf[RX_BUF_SIZE];
_Static_assert((RX_BUF_SIZE & (RX_BUF_SIZE - 1)) == 0, "must be power of 2");
/* 环形缓冲要用 & (SIZE-1) 代替取模，前提是 2 的幂 */
```
</details>

<details>
<summary>Q3：为什么"传数组给函数"一定要额外传长度？</summary>

因为 C 的数组**不携带长度信息**——这是 C 的"原罪"，也是几乎所有缓冲区漏洞的根源。

```c
void send(uint8_t buf[]){        /* 编译器眼里就是 uint8_t *buf */
    for (int i = 0; i < ???; i++)   /* 无从得知长度 */
}
```

实测：`sizeof(buf)` 在函数里得到的是**指针宽度**（Mac 8 字节），不是数组字节数。
所以 `sizeof(buf)/sizeof(buf[0])` 在函数里恒等于 `指针宽/元素宽`，结果完全错。

标准解法就是显式带长度：

```c
void send(const uint8_t *buf, size_t len);
```

这也解释了为什么所有的 C API 都是这个形状：

- POSIX：`write(fd, buf, count)`、`recv(sock, buf, len, flags)`；
- 标准库：`memcpy(dst, src, n)`、`fread(ptr, size, nmemb, stream)`；
- Linux 内核：`copy_to_user(to, from, n)`；
- 本仓库后续：`send_bytes(buf, len)`。

替代方案（更安全但 C 里少见）：把数组包进结构体传（`struct { uint8_t *p; size_t n; }`），
或者用"哨兵值"约定（字符串用 `\0`，但二进制数据没法这么做）。

裸机上尤其要遵守：因为没有 sanitizer，
**长度错了就是静默的内存破坏**（[6.4](6.4-数组溢出.md)）。
</details>
