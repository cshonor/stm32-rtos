# 6.5 字符和字符串

> 书：第 6 章 数组、指针和字符串 · 6.5 字符和字符串（原书 p78–88 区间内）
> 上一篇：[6.4 数组溢出](6.4-数组溢出.md) ｜ 本篇是第 6 章的收尾
> 对应实验：主机侧 clang 23.1.0 + `--target=armv7m-none-eabi -ffreestanding` 交叉

## 书这一节讲什么

一句话：**C 没有字符串类型**，字符串是"以 `\0` 结尾的 `char` 数组"——
一个**约定**，不是语言特性。

书讲的是这个约定。裸机上的额外问题是：
**freestanding 环境没有 `<string.h>`**，`strlen`/`strcpy`/`memcpy` 全要自己来；
而且字符串常量在 Flash 里，写它不会报错。

## 一、实测：`sizeof` 与 `strlen` 差 1

```
$ clang -O0 -o str str.c && ./str
sizeof("abc")=4 strlen("abc")=3        ← 差的就是结尾 '\0'
sizeof(s)=8 (指针) sizeof(buf)=4 (数组)
buf 末字节 = 0 (应为 0)
```

`"abc"` 是 `char[4]`：`{'a','b','c','\0'}`。
所以**分配缓冲区时必须 `strlen + 1`**——
忘了 `+1` 是 C 里最经典的 off-by-one，而它在裸机上是静默的（[6.4](6.4-数组溢出.md)）。

## 二、两种写法的段归属（实测，交叉 ELF）

```c
const char *const p = "abc";      /* 指针 */
char buf[] = "abc";               /* 数组（可写） */
const char lit[] = "abc";         /* const 数组 */
```

```
$ clang --target=armv7m-none-eabi -mcpu=cortex-m3 -mthumb -ffreestanding -c strseg.c
$ llvm-objdump -h strseg.o
  3 .rodata.str1.1  00000004   DATA     ← 字符串字面量
  4 .rodata         00000008   DATA
  6 .data           00000004   DATA     ← buf（可写的那份）
$ llvm-nm strseg.o
00000000 D buf      ← .data（RAM，可写）
00000004 R lit      ← .rodata（Flash，只读）
00000000 R p        ← .rodata（指针本身也在 Flash）
```

| 写法 | 类型 | 位置 | 能不能写 |
|---|---|---|---|
| `char *s = "abc"` | 指针 | 字面量在 `.rodata`（Flash） | ❌ UB |
| `char s[] = "abc"` | 数组 | **`.data`（RAM）** | ✅ |
| `const char s[] = "abc"` | const 数组 | `.rodata`（Flash） | ❌（编译器挡住） |

**裸机上的关键差别**：Linux 上写只读段会 SIGSEGV（有 MMU）；
**裸机没有 MMU，写 Flash 不会触发任何异常**——
Flash 控制器在没有正确编程时序时对写是"忽略"的，
于是 `s[0] = 'A'` **静默无效**，后面读到的还是 `'a'`。
比崩溃更难查，因为程序不崩，只是行为不对。

## 三、裸机没有 `<string.h>`——而且编译器会偷偷调用它

freestanding 下标准只保证 7 个头
（[ch01](../01-hello-world/1.5-编译器在幕后的工作方式.md) 实测）：
`<float.h> <iso646.h> <limits.h> <stdarg.h> <stdbool.h> <stddef.h> <stdint.h>`。

**没有 `<string.h>`**，所以 `strlen`/`strcpy`/`memcpy` 都得自己实现。
但有个陷阱——**你不写 `memcpy`，编译器也会生成对它的调用**：

```c
typedef struct { unsigned a[64]; } big_t;
extern big_t g1, g2;
void f(void){ g1 = g2; }                                  /* 结构体整体赋值 */
void h(unsigned char *d, const unsigned char *s, unsigned n){ __builtin_memcpy(d, s, n); }
```

```
$ clang --target=armv7m-none-eabi -mcpu=cortex-m3 -mthumb -ffreestanding -Os -c memcpy2.c
$ llvm-nm -u m.o
         U __aeabi_memcpy
         U __aeabi_memcpy4
```

**`__aeabi_memcpy` 是未定义符号**——链接时如果没人提供，就是
`undefined reference`（在 `-O0` / `-Os` / `-O2` 三档下都会出现，实测）。

所以最小实现清单：

```c
void *memcpy(void *d, const void *s, size_t n);
void *memset(void *s, int c, size_t n);
int   memcmp(const void *a, const void *b, size_t n);
void *memmove(void *d, const void *s, size_t n);
/* ARM EABI 下的实际符号名（注意 __aeabi_memset 参数顺序和标准 memset 相反！） */
void __aeabi_memcpy (void *d, const void *s, size_t n);
void __aeabi_memset (void *s, size_t n, int c);   /* ← n 和 c 反了 */
```

最后一条是纯粹的坑：`__aeabi_memset(dst, n, c)` vs 标准 `memset(dst, c, n)`。

## 四、裸机上怎么用字符串

`printf` 要靠 UART（[9.3 串行输出](../09-uart-serial/9.3-串行输出.md)），
所以字符串在裸机上的典型用途是：

| 用途 | 说明 |
|---|---|
| **串口命令行解析** | 收到一行 → 拆参数 → 匹配命令表 |
| **日志/调试输出** | 格式化后从 UART 发出（注意 Flash 占用） |
| **协议帧的字段** | 通常不是 `\0` 结尾，而是**显式长度**（二进制协议） |

命令匹配的最小实现（不依赖 `<string.h>`）：

```c
static int cmd_match(const char *cmd, const char *const table[], unsigned n){
    for (unsigned i = 0; i < n; i++) {
        const char *p = table[i], *q = cmd;
        while (*p && *p == *q) { p++; q++; }
        if (*p == '\0' && *q == '\0') return (int)i;
    }
    return -1;
}
```

三条纪律：

1. **比较要有长度上限**：`strncmp` 风格，别用无限长度的 `strcmp`；
2. **拷贝必须给目标大小**：`strncpy(dst, src, sizeof dst - 1); dst[sizeof dst-1] = '\0';`
   （`strncpy` 不保证结尾零！）；
3. **字符串常量加 `const`**：`const char *s = "..."` 让编译器挡住写操作。

## 坑点（书 / 常识怎么说 / 实际是什么）

| 书 / 常识怎么说 | 实际是什么 |
|---|---|
| "字符串长度 = 字符数" | `strlen` **不含**结尾 `\0`。实测 `sizeof("abc")=4`、`strlen=3`，缓冲区要 `+1` |
| "写字符串常量会段错误" | 裸机没有 MMU：写 Flash **静默无效**，读回来还是原值（比崩溃更难查） |
| "裸机也有 `strcpy`" | freestanding 只有 7 个头，**没有 `<string.h>`**。全要自己实现 |
| "我没用 `memcpy` 就不用管" | 编译器会隐式生成 `__aeabi_memcpy`/`__aeabi_memset`（实测 `U` 符号，三档优化都有） |
| "`__aeabi_memset` 和 `memset` 一样" | **参数顺序相反**：`__aeabi_memset(s, n, c)` vs `memset(s, c, n)` |
| "`strncpy` 是安全版" | 它**不保证**结尾 `\0`（源串超长时截断且无零）。用后要手动补 |

## 代码自测

<details>
<summary>Q1：`char *s = "abc"` 和 `char s[] = "abc"` 在裸机上差在哪？</summary>

差在**存储位置和可写性**，实测段归属：

```c
const char *const p = "abc";   /* R → .rodata（Flash） */
char buf[] = "abc";            /* D → .data（RAM，可写） */
const char lit[] = "abc";      /* R → .rodata（Flash） */
```

| | `char *s = "abc"` | `char s[] = "abc"` |
|---|---|---|
| 变量本身 | 一个指针（在栈或 `.data`） | 一个 `char[4]` 数组（在栈或 `.data`） |
| 字符存在哪 | **`.rodata` → Flash** | **跟着变量走**（局部则在栈） |
| `sizeof` | 指针宽度（Mac 8 / Cortex-M 4） | **4**（整个数组） |
| 能不能写 | ❌ UB | ✅ |

裸机上的后果差异：

```c
char *s = "abc";
s[0] = 'A';        /* PC: SIGSEGV（MMU 保护）
                      裸机: 尝试写 Flash → 控制器忽略 → 无声失败
                            printf("%s", s) 还是 "abc" */
```

**"写了但没生效"比"崩溃"难查得多**——程序继续跑，只是行为不对，
而且你会在离写操作很远的地方才发现。

规则：
- 常量字符串一律 `const char *s = "..."`（让编译器挡住写）；
- 需要修改的用数组 `char buf[N]`；
- 注意 `.rodata` 占 Flash，日志字符串多了 Flash 会不够（用 `llvm-size` 看）。
</details>

<details>
<summary>Q2：为什么链接时报 `undefined reference to __aeabi_memcpy`？我明明没写 memcpy。</summary>

因为**编译器会替你生成对它的调用**——你不写，它也会出现。

实测（`typedef struct { unsigned a[64]; } big_t; g1 = g2;`）：

```
$ clang ... -ffreestanding -Os -c memcpy2.c && llvm-nm -u m.o
         U __aeabi_memcpy
         U __aeabi_memcpy4
```

触发场景：

1. **大结构体的整体赋值**（`g1 = g2`）：编译器不逐字段拷贝，直接调 memcpy；
2. **大数组的初始化**（`int a[100] = {...}` 的一部分）；
3. `__builtin_memcpy` / `__builtin_memset` 的显式使用。

小结构体（≤ 几个字）通常被内联展开，不产生调用——
所以这个符号**时有时无**，更容易让人以为是"玄学"。

解决办法（裸机的最小 C 运行时的一部分）：

```c
void *memcpy(void *d, const void *s, size_t n){ /* 字节循环或字拷贝 */ }
void *memset(void *s, int c, size_t n){ /* ... */ }

/* ARM EABI 别名：编译器真正调用的符号 */
void __aeabi_memcpy (void *d, const void *s, size_t n){ memcpy(d, s, n); }
void __aeabi_memset (void *s, size_t n, int c){ memset(s, c, n); }  /* ← 注意顺序 */
void __aeabi_memclr (void *s, size_t n){ memset(s, 0, n); }
```

**`__aeabi_memset` 的参数是 `(s, n, c)`，和标准的 `memset(s, c, n)` 相反**——
照抄标准签名实现会导致"内存被填成了长度值"这种诡异 bug。
</details>

<details>
<summary>Q3：裸机上处理字符串的最小安全清单是什么？</summary>

四条，每条都对应一类真实的静默失败：

**① 所有拷贝都给目标大小，并手动补结尾零**

```c
void safe_copy(char *dst, size_t dstsz, const char *src){
    size_t i = 0;
    while (i + 1 < dstsz && src[i]) { dst[i] = src[i]; i++; }
    dst[i] = '\0';                     /* strncpy 不保证这个！ */
}
```

**② 比较给上限**

```c
static int strn_eq(const char *a, const char *b, size_t n){
    for (size_t i = 0; i < n; i++) {
        if (a[i] != b[i]) return 0;
        if (a[i] == '\0') return 1;    /* 同时结束 */
    }
    return 1;
}
```

**③ 缓冲区大小用宏 + 编译期断言**

```c
#define LINE_MAX 80u
static char line[LINE_MAX];
_Static_assert(LINE_MAX >= 64, "too small for longest command");
```

**④ 二进制数据不用字符串函数**

`strlen`/`strcpy` 遇 `\0` 就停——
而串口收到的数据里 `\0` 是合法字节。
**协议帧一律"指针 + 显式长度"**（[6.1](6.1-数组.md) Q3 的形状），
用 `memcpy`/`memcmp` 而不是 `str*`。

一句话总结：**裸机上字符串处理没有兜底，
所以每个函数都要自带长度上限，
并且"结尾零"这件事要你自己保证。**
</details>
