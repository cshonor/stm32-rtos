# 6.2 底层细节：指针

> 书：第 6 章 数组、指针和字符串 · 6.2 底层细节：指针（原书 p78–88 区间内）
> 上一篇：[6.1 数组](6.1-数组.md) ｜ 下一篇：[6.3 数组和指针算术](6.3-数组和指针算术.md)
> 对应实验：主机侧 clang 23.1.0 + `--target=armv7m-none-eabi -mcpu=cortex-m3`

## 书这一节讲什么

一句话：**指针就是一个装着地址的变量**，书在这里讲"底层发生了什么"。

这一节是全书最值得精读的几节之一，因为在裸机上
**"指针"和"寄存器地址"是同一个东西**——
`*(volatile uint32_t *)0x40010800` 就是把一个整数常量当成地址来解引用。
理解指针 = 理解裸机编程的一半。

## 一、指针的三个组成部分

```c
volatile uint32_t *p;      /* ① 地址值  ② 指向的类型  ③ 类型限定符 */
```

| 组成 | 作用 | 裸机上的意义 |
|---|---|---|
| **地址值** | 一个数字（Cortex-M 上是 32 位） | 就是寄存器/内存的物理地址 |
| **指向的类型** | 决定 `+1` 走多远、解引用读几个字节 | `uint32_t *` 一次读 4 字节 = 一个寄存器 |
| **`volatile`** | 强制每次真读真写，不许优化 | **MMIO 必须有**（[4.3](../04-numbers-and-bitops/4.3-赋值.md) 实测） |

第三点容易被当成"修饰"，但它是**语义的一部分**：

```
$ clang ... -Os -c vol.c      # REG = 1; REG = 2;
（生成两次 str —— volatile 让两次写都真的发生）
```

## 二、实测：指针的宽度

```
$ clang -O0 -o arr arr.c && ./arr          # Mac / arm64
sizeof(a)=16 sizeof(p)=8                    ← 指针 8 字节
```

```
/* arm_width.c（ch04 实测） */
$ clang --target=armv7m-none-eabi -mcpu=cortex-m3 -mthumb -ffreestanding -c arm_width.c
_Static_assert(sizeof(void*) == 4, "ptr on Cortex-M");    ← 通过：Cortex-M 上 4 字节
_Static_assert(sizeof(long)  == 4, "long on Cortex-M != 8");
```

**裸机上的坑**：Cortex-M 上指针和 `int` 都是 4 字节，
所以 `uint32_t addr = (uint32_t)p;` 能编译通过——
但如果把这段代码移植到 64 位主机（比如做主机侧的单元测试），就**截断**了。
正确类型是 `uintptr_t`（[4.7 标准整数](../04-numbers-and-bitops/4.7-标准整数.md)）。

## 三、指针 ↔ 整数：裸机的日常

```c
/* 整数 → 指针（寄存器访问的标准写法） */
#define REG32(base, off) (*(volatile uint32_t *)((base) + (off)))
#define GPIOA_CRL  REG32(0x40010800u, 0x00u)
#define GPIOA_IDR  REG32(0x40010800u, 0x08u)
#define GPIOA_BSRR REG32(0x40010800u, 0x10u)
```

三个细节，每个都是踩过的坑：

1. **`base` 写成 `0x40010800u`（带 `u`）**：避免它被当成 signed int，
   再做加法时溢出成 UB；
2. **`(base) + (off)` 是**整数加法**（加 1 = 1 字节），
   而指针 `p + 1` 是**指针算术**（加 1 = `sizeof(*p)` 字节）——两者别混；
3. **`volatile uint32_t *`**：一次访问 4 字节，且每次都真访问。

## 四、`void *` 与类型双关（type punning）

```c
uint32_t raw = (uint32_t)(uintptr_t)p;      /* 地址 → 整数：用 uintptr_t */
float f = 3.14f;
uint32_t bits;
memcpy(&bits, &f, 4);                        /* ✅ 安全地把 float 位模式搬到整数 */
uint32_t bad = *(uint32_t *)&f;              /* ❌ 违反严格别名（strict aliasing）*/
```

第二种写法在 `-O2` 下是 UB（严格别名规则），编译器可以做反直觉的优化。
**裸机上要读"某个值的位模式"（比如把 float 拆成字节通过串口发），
用 `memcpy`**——它在 `-O2` 下会被优化成一条 `mov`，零成本。

## 五、空指针与未初始化指针

```c
volatile uint32_t *p;       /* 未初始化：值是栈上的垃圾 */
*p = 1;                     /* ❌ 往随机地址写 —— 裸机上会 HardFault 或者更糟 */
```

裸机上往随机地址写的后果：

- 地址落在**有效 RAM** → 静默破坏某个变量（最难查）；
- 地址落在**无效区域** → HardFault（还算好，能定位）；
- 地址落在**某个外设寄存器** → 改了硬件配置（最离谱的一类）。

规则：**指针声明时初始化（`= NULL` 或指向确定的对象），使用前判空。**

## 坑点（书 / 常识怎么说 / 实际是什么）

| 书 / 常识怎么说 | 实际是什么 |
|---|---|
| "指针就是地址" | 地址 + **类型**（决定步长和读写宽度）+ **`volatile`**（决定能不能被优化） |
| "Cortex-M 上指针和 int 一样大，可以互换" | 都是 4 字节，但**别互换**：用 `uintptr_t` 才能安全地在指针和整数间转换 |
| "`p + 1` 就是地址加 1" | 加的是 `sizeof(*p)` 字节（[6.3](6.3-数组和指针算术.md) 实测差 4 字节） |
| "把 float 的位模式强转成整数读出来" | ❌ 违反严格别名，是 UB。用 `memcpy`（`-O2` 下编译成一条 `mov`） |
| "指针没初始化，先用了再说" | 裸机上往随机地址写：踩 RAM（静默）/ HardFault / **改到外设寄存器** |

## 代码自测

<details>
<summary>Q1：为什么裸机访问寄存器要写 `*(volatile uint32_t *)0x40010800u` 这么长一串？</summary>

因为这一串里每一部分都在表达一件**必要**的事：

```c
*(volatile uint32_t *)0x40010800u
  │        │        │      │
  │        │        │      └─ ① 地址是"无符号"整数常量（避免 signed 溢出 UB）
  │        │        └──────── ② 把整数转换成指针（地址 → 指针）
  │        └───────────────── ③ 指向 uint32_t：一次访问 4 字节（一个寄存器）
  └────────────────────────── ④ 解引用：读写那个地址
```

加上 `volatile`（在 `(volatile uint32_t *)` 里）是第五件事：
**每次访问都必须真的发生**，不许被优化掉或合并。

少了任何一部分：

| 漏了 | 后果 |
|---|---|
| `volatile` | 编译器可能合并/删除访问（实测：`REG=1; REG=2;` 变成只写一次） |
| `uint32_t`（写成 `uint8_t`） | 一次只读 1 字节，读不到完整的 32 位寄存器值 |
| `u` 后缀 | 地址可能被当 signed，加法溢出是 UB |
| `*` 解引用 | 那就是个整数，不是访问 |

实际工程里这些都被宏封装掉了：

```c
#define REG32(base, off) (*(volatile uint32_t *)((base) + (off)))
#define GPIOA_CRL REG32(0x40010800u, 0x00u)
```

再往后一步就是结构体映射（[ch08](../ch08-complex-types.md) 的 `GPIOA->CRL`），
那才是 CMSIS 和 Linux 内核的写法。
</details>

<details>
<summary>Q2：`uintptr_t` 是什么？为什么不能用 `uint32_t` 存地址？</summary>

`uintptr_t`（在 `<stdint.h>` 里）是"**足够大、能无损装下一个指针的无符号整数**"。

在 Cortex-M 上它就是 `uint32_t`——所以用 `uint32_t` 存地址**现在是对的**。
但一旦这段代码被移植（比如拿到主机上做单元测试、或者换到 64 位 MCU），
`uint32_t` 就会**截断**高 32 位：

```c
uint32_t addr = (uint32_t)(uintptr_t)p;   /* Mac 上：丢了高 32 位 */
uintptr_t addr2 = (uintptr_t)p;            /* ✅ 任何平台都无损 */
```

实际用处：

1. **打印地址**：`printf("p=%p")` 用 `%p`；要算差值/比较时用 `uintptr_t`；
2. **对齐判断**：`if (((uintptr_t)buf & 3u) == 0)` —— 判断 4 字节对齐
   （DMA 常常要求对齐）；
3. **裸机上把地址当数字算**：`REG32(base, off)` 里 base 就是整数形式的地址。

一句话：**"地址当数字算"用 `uintptr_t`，"地址当地址用"用指针，别用 `int`/`long` 中转。**
（[4.5](../04-numbers-and-bitops/4.5-整数的大小和表示.md) 实测：`long` 在 Mac 是 8、Cortex-M 是 4。）
</details>

<details>
<summary>Q3：严格别名（strict aliasing）是什么？为什么裸机上容易踩？</summary>

严格别名规则说：**不能通过"与被访问对象类型不兼容"的指针去访问那个对象**。
违反就是 UB，编译器在 `-O2` 下可以据此做反直觉的优化。

裸机上的典型场景：把 float/结构体的**位模式**取出来（发串口、算 CRC、写 Flash）。

```c
/* ❌ UB：通过 uint32_t* 访问 float 对象 */
float f = 3.14f;
uint32_t bits = *(uint32_t *)&f;

/* ✅ 安全：memcpy 是按字节拷贝，不违反别名规则 */
uint32_t bits;
memcpy(&bits, &f, sizeof bits);
```

第二种写法在 `-O2` 下会被编译器优化成**一条寄存器传送指令**，零成本——
所以"为了性能用强转"的理由不成立。

裸机上的其他高发场景：

| 场景 | 错法 | 对法 |
|---|---|---|
| float → 字节流（串口发） | `(uint32_t*)&f` | `memcpy(&u, &f, 4)` |
| 收到 4 字节 → 还原 float | `*(float*)rx_buf` | `memcpy(&f, rx_buf, 4)` |
| 结构体 → 字节缓冲（发协议帧） | `(uint8_t*)&st` | `memcpy(buf, &st, sizeof st)` |
| 字节缓冲 → 结构体（收协议帧） | `*(pkt_t*)buf` ⚠ 还有对齐问题 | `memcpy(&st, buf, sizeof st)` |

第二种里还有个裸机特有的坑：**`(pkt_t*)buf` 可能未对齐**，
Cortex-M0 上访问未对齐的 32 位会直接 HardFault
（M3/M4 支持非对齐访问但慢，且不是所有指令都支持）。

一句话：**需要"把一段内存当别的类型看"时，用 `memcpy`，别用强转。**
</details>
