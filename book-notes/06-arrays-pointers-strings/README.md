# 第 6 章 数组、指针和字符串 —— 章节导航

> 书：第 6 章 数组、指针和字符串（原书 p78–88）
> 对应实验：主机侧 clang 23.1.0（含 `-fsanitize=address`）+ `--target=armv7m-none-eabi -ffreestanding` 交叉

## 这一章在讲什么

书按"数组 → 指针 → 算术 → 溢出 → 字符串"从用法讲到到底层。
但真正的心智模型是反过来的：**C 里只有指针，数组只是"连续的一块 + 一个名字"。**

对裸机来说这一章的分量比书里看上去重得多，因为：

1. **裸机通常不用堆**（[ch13](../ch13-dynamic-memory.md)），
   所有缓冲区都是**编译期定死的数组**——串口缓冲、采样序列、协议帧、显示缓冲；
2. **"指针"和"寄存器地址"是同一个东西**——
   理解了指针，就理解了 `*(volatile uint32_t *)0x40010800` 为什么长那样；
3. **数组越界在裸机上永远静默**——是所有 bug 里最难查的一类。

## 与书的差异（重要）

| 书 | 我 |
|---|---|
| 讲数组/指针的用法 | 每个结论配实测：`sizeof(a)=16` vs `sizeof(p)=8`、`a+1` 差 4 字节、`&a+1` 差 16 字节 |
| "越界是 UB" | 分三层实测：常量下标 clang 报 `-Warray-bounds`；**运行时下标一声不响**；ASan 才报 `stack-buffer-overflow` + 调用栈 |
| 讲字符串的 `\0` 约定 | 补上裸机特有的：写 Flash 静默无效、freestanding **没有 `<string.h>`**、编译器隐式生成 `__aeabi_memcpy` |
| 没提"数组该放哪" | 补上：`.bss` / `.data` / `.rodata` 的选择直接决定 20 KB RAM 够不够（实测段归属 `D`/`R`） |

## 读完本章你应该能回答

- `sizeof(a)` 和 `sizeof(p)` 为什么不同？`&a + 1` 和 `a + 1` 各走多远？（16 vs 4 字节）
- 传数组给函数为什么必须额外传长度？
- 常量下标越界和运行时下标越界，编译器反应有什么差别？（实测）
- 裸机上数组越界会踩到什么？（别的变量 / 返回地址 → HardFault）
- `char *s = "abc"` 和 `char s[] = "abc"` 在段归属和可写性上差在哪？（实测 `R` vs `D`）
- 为什么没写 `memcpy` 也会链接报 `undefined reference to __aeabi_memcpy`？
- `__aeabi_memset` 的参数顺序和标准 `memset` 有什么不同？
