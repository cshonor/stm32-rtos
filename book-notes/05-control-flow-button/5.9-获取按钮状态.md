# 5.9 获取按钮状态

> 书：第 5 章 决策和控制语句 · 5.9 获取按钮状态（原书 p65–77 区间内）
> 上一篇：[5.8 选择下拉电路](5.8-选择下拉电路.md) ｜ 下一篇：[5.10 运行程序](5.10-运行程序.md)
> 对应实验：`--target=armv7m-none-eabi -mcpu=cortex-m3 -Os` 交叉编译（真机读数 ⬜ 待建）

## 书这一节讲什么

一句话：**读 `IDR`（Input Data Register）的对应位，就知道引脚当前电平**。

语法上就是 `IDR & BIT(0)`，一行的事。但这一"读"在裸机上有三个讲究：
**读哪个寄存器、读几次、读到的值能用多久**。

## 一、实测：一次"读引脚"的机器码

```c
#define GPIOA_IDR (*(volatile unsigned int *)0x40010808u)
int button_pressed(void){ return (GPIOA_IDR & (1u << 0)) == 0; }
```

```
$ clang ... -Os -c btn.c && llvm-objdump -d btn.o
00000032 <button_pressed>:
      32: f640 0008     movw r0, #0x808       ; 地址低 16 位
      36: f2c4 0001     movt r0, #0x4001      ; 地址高 16 位 → 0x40010808 (GPIOA_IDR)
      3a: 6800          ldr  r0, [r0]         ; 读整个 32 位 IDR
      3e: 2101          movs r1, #0x1         ; 掩码 1
      40: ea21 0000     bic.w r0, r1, r0      ; r0 = 1 & ~IDR —— 一条指令完成取反位与
      42: 4770          bx   lr
```

6 条指令、一次硬件读。注意两点：

1. **读的是整个 32 位 `IDR`**，然后软件取位——STM32 没有"只读一位"的总线操作；
2. 编译器把 `(IDR & 1) == 0` 优化成 `bic.w`（位清除），**一条指令**完成"读位 + 取反 + 比较"。

## 二、`IDR` 的三个性质

| 性质 | 说明 |
|---|---|
| **只读** | 手册里标 `r`。写它没意义（某些系列写 `IDR` 是未定义行为） |
| **每次读都是一次真实的引脚采样** | 不是缓存值。电平在这两次读之间变了，读到的就不同 |
| **一个寄存器管 16 个引脚** | `IDR` 的 bit0–bit15 对应 PA0–PA15 |

第二点最重要，也最容易被当成"普通变量"：

```c
if (GPIOA_IDR & BIT(0)) { ... }        /* 读第 1 次 */
if (GPIOA_IDR & BIT(0)) { ... }        /* 读第 2 次 —— 值可能已经变了 */
```

如果这两次读之间按键弹跳了一下，两个分支的行为就不一致了。
正确的做法是**读一次存起来**（[5.1 if](5.1-if.md) Q1 讲过同一个道理）：

```c
uint32_t idr = GPIOA_IDR;              /* 一次快照 */
if ((idr & BIT(0)) == 0) { /* 按下 */ }
if ((idr & BIT(1)) == 0) { /* 另一个键 */ }
```

## 三、"按下"的语义：== 0 还是 != 0

取决于电路（[5.8](5.8-选择下拉电路.md)），所以**封装成函数，全工程只写一处**：

```c
/* 上拉电路：按下 = 0 */
static inline int button_pressed(void){ return (GPIOA_IDR & BIT(0)) == 0; }
```

好处：换板子/改电路只改这一行；
而且 `static inline` 在 `-Os` 下会被内联（实测 `button_pressed` 就 6 条指令），没有调用开销。

## 四、读到的值能用多久：抖动

机械触点闭合/断开时，金属弹片会在**几毫秒内物理弹跳多次**，
示波器上看是一串毛刺。所以"读一次就知道按下没有"是**不够的**：

```
理想:  ______________|‾‾‾‾‾‾‾‾‾‾|__________
实际:  ___________|‾|_|‾|__|‾‾‾‾‾‾‾‾|_______   ← 弹跳
```

一次按下可能被读成 5 次按下 → "按一下，LED 翻了好几回"。

处理在 [5.10 运行程序](5.10-运行程序.md)：
软件去抖（定时器采样、状态机）或者硬件（RC 滤波 + 施密特）。

## 坑点（书 / 常识怎么说 / 实际是什么）

| 书 / 常识怎么说 | 实际是什么 |
|---|---|
| "读 `IDR` 就知道按键状态" | 对，但**每次读都是真实采样**，两次读之间可能变。读一次存起来 |
| "`IDR` 是个寄存器变量" | 它是**只读**的，且一个寄存器管 16 个引脚，读出来还要取位 |
| "读到 1 就是按下" | 取决于上拉/下拉（[5.8](5.8-选择下拉电路.md)）。封装成函数，别在业务代码里到处写 `(IDR & BIT)` |
| "读一次就够了" | 抖动会让一次按下产生多次跳变（ms 级），要去抖 |
| "读 `IDR` 很快，随便读" | 一次读 6 条指令（实测），不算贵；但**总线访问**比读 RAM 慢，ISR 里别反复读 |

## 代码自测

<details>
<summary>Q1：为什么要"读一次 IDR 存起来"，直接判断不行吗？</summary>

两个理由，第二个更重要。

**① 效率**：每次 `(GPIOA_IDR & BIT(0))` 都是 6 条指令 + 一次总线读。
判断 3 个按键状态就读 3 次，不如读一次比较 3 个位。

**② 一致性**（关键）：多次读到的可能是**不同时刻的快照**。

```c
if ((GPIOA_IDR & BIT(0)) == 0 && (GPIOA_IDR & BIT(1)) == 0) {
    /* 你想表达"两个键同时按下" */
}
```

这两次读之间隔了几条指令。如果按键在这期间弹跳/松开，
你可能读到"第一个键按下"和"第二个键没按"——
或者更糟：读到两个"都按下"但它们其实**不是同时**按的。

```c
uint32_t idr = GPIOA_IDR;    /* 同一时刻的快照 */
if ((idr & (BIT(0)|BIT(1))) == 0) { /* 真的同时按下 */ }
```

这个道理对所有 MMIO 寄存器都成立——
尤其是**状态寄存器**（`USART_SR`、`ADC_SR`、`EXTI_PR`），
因为它们的值变化更快，而且有些读一次还会清标志
（[5.1 if](5.1-if.md) 展开过 read-clear）。

一句话：**裸机读硬件，能读一次就别读两次。**
</details>

<details>
<summary>Q2：`static inline` 封装读按键，会不会有函数调用开销？</summary>

不会——`-Os`/`-O2` 下 `static inline` 会被内联展开，实测就是那 6 条指令。

```
00000032 <button_pressed>:    ← 这是编译器把函数内联/展开后的形态
      3a: ldr  r0, [r0]
      40: bic.w r0, r1, r0
      42: bx   lr
```

（严格说：单独编译时函数还是个函数；调用它的地方在 `-O2` 下会被展开成这几条指令。
`-O0` 下会有真实的 `bl` 调用。）

所以**用 `static inline` 封装硬件访问是零成本的抽象**——
这是裸机代码可读性和性能兼得的标准手段：

```c
static inline uint32_t reg_read(volatile uint32_t *p){ return *p; }
static inline int button_pressed(void){ return (GPIOA_IDR & BIT(0)) == 0; }
static inline void led_on(void){ GPIOA_BSRR = BIT(5); }
```

注意两个前提：

1. **`static`**：否则在多个 `.c` 里会重复定义（除非放头文件里用 `static inline`）；
2. **`-O0` 下不会内联**——所以别用 `-O0` 的性能数据做判断。

这类封装在 Linux 内核里就是 `readl()`/`writel()`，
在本仓库后续会变成结构体写法 `GPIOA->IDR`（[8.12 结构体与嵌入式编程](../08-complex-types/8.12-结构体与嵌入式编程.md)）。
</details>

<details>
<summary>Q3：读 `IDR` 得到的"当前电平"，和"按下了没有"是一回事吗？</summary>

不是。**电平是瞬时值，"按下"是一个持续若干毫秒的事件**。

```
电平:  ___________|‾|_|‾|__|‾‾‾‾‾‾‾‾|_______
                  ↑ 弹跳 ↑        ↑ 弹跳 ↑
"按下"事件:       [============一次按下============]
```

`IDR` 给你的永远是"这一瞬间是 0 还是 1"，
而你要的是"用户按了一次"——中间隔着：

1. **抖动**（几 ms 的多次跳变）→ 软件去抖；
2. **按住不放**（持续低电平）→ 要不要算多次？（长按键、重复触发）；
3. **边沿 vs 电平**：多数应用要的是"**按下的那一刻**"（下降沿），
   而不是"现在是不是低电平"。

处理这几件事的正规结构是**状态机 + 定时采样**：

```c
typedef enum { IDLE, MAYBE_PRESSED, PRESSED, MAYBE_RELEASED } btn_state_t;

/* SysTick 每 1ms 调一次 */
void button_tick(void){
    static btn_state_t st = IDLE;
    static uint8_t cnt = 0;
    int pressed = button_pressed();          /* 读瞬时电平 */

    switch (st) {
    case IDLE:
        if (pressed) { cnt = 0; st = MAYBE_PRESSED; }
        break;
    case MAYBE_PRESSED:
        if (pressed) { if (++cnt >= 20) st = PRESSED; }   /* 连续 20ms 才认定 */
        else st = IDLE;
        break;
    case PRESSED:
        if (!pressed) { cnt = 0; st = MAYBE_RELEASED; }
        break;
    case MAYBE_RELEASED:
        if (!pressed) { if (++cnt >= 20) st = IDLE; }     /* 松开也要去抖 */
        else st = PRESSED;
        break;
    }
}
```

注意 `PRESSED` 状态**只进一次**——这就是"边沿"：
业务代码检测 `st` 从非 `PRESSED` 变成 `PRESSED` 的那一刻，就是"按下事件"。
时基来自 [ch19 SysTick](../ch19-systick-and-timer.md)。
</details>
