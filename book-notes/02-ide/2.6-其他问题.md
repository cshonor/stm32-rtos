## 一、关于 IDE 的杂项

### Q：到底要不要装 STM32CubeIDE？

**看你要什么**，判据如下（详见本仓库 `book-notes/README.md` 的决策表）：

| 需求 | 装什么 |
|---|---|
| 寄存器级裸机（本仓库现在的路线） | **什么都不用装**，clang + make + openocd 已够 |
| 图形配时钟树/引脚，或用 HAL/LL | 装**独立 CubeMX**（Java 小程序，不连带 Eclipse） |
| 要外设寄存器位域视图 | VSCode + Cortex-Debug + SVD（复用现有 openocd） |
| 公司标准 / 要一键复现别人的工程 | 才装完整 CubeIDE |

### Q：那 CubeIDE 集成了什么？

按 ST 官方 release note（CubeIDE 2.1.0 / 2.2.0），**它内置的工具链是两套**：

| 组件 | 版本 |
|---|---|
| Eclipse + CDT | 2025-12 + CDT 12.3.0 |
| GNU tools for STM32 | 基于 GCC 14.3.rel1 |
| **STARM-Clang** | 21.1.1 |
| GDB / 调试服务 | ST-LINK_gdbserver 7.14.0、SEGGER J-Link、OpenOCD 0.12.0+ |
| 烧录 | STM32CubeProgrammer 2.23.0（命令行版） |
| macOS | 2.1.0 起提供 **AArch64 原生包** |

所以"CubeIDE 集成了工具链"这个说法是对的，而且它现在同时给 GCC 和 Clang 两条路。

## 二、关于调试的杂项

### Q：为什么硬件断点只有 6 个？不够用怎么办？

因为断点是**芯片里的物理比较器（FPB 单元）**，不是软件功能。
Cortex-M3 的 FPB 有 6 个指令比较器 + 2 个字面量比较器（实测输出里
`target has 6 breakpoints, 4 watchpoints`）。

不够用的对策，按优先级：

1. **用条件断点代替多个断点**：`break foo if cnt > 100`，条件在主机侧求值，不占硬件资源；
2. **用 `watchpoint` 盯变量而不是在每个写点打断点**；
3. **用数据观察点（DWT）** 做变量改动触发；
4. 实在要很多断点，**改用 printf/UART 打点**（这就是 [ch09](../ch09-uart-serial.md) 存在的理由）。

⚠️ 软件断点（改 Flash 里的指令）在 Flash 上代价很高：**改一个字节要擦一整页**
（[2.2 Q4](2.2-IDE为我们做了什么.md)）。所以别指望"断点随便加"。

### Q：gdb 有没有"不改代码也能看状态"的办法？

有，而且这是 gdb 最有用的能力：

```gdb
(gdb) monitor reset halt        # 复位并停住
(gdb) info registers            # 所有核寄存器
(gdb) x/16xw 0x08000000         # 读 Flash 首地址（向量表）
(gdb) x/4xw 0x20000000          # 读 RAM
(gdb) print g_tick              # 按符号读全局变量
(gdb) info symbol 0x08000061    # 反查地址属于哪个符号
(gdb) disassemble /m main       # 反汇编 + 源码对照
```

**`x/` 系列是裸机上最重要的"printf"**——printf 还没通的阶段，
所有状态观察都靠它。

## 三、关于工程的杂项

### Q：为什么书里的工程体系跟我这边差这么多？

因为**书的板子和我的板子不是一个系列的芯片**：

| 项 | 书（NUCLEO-F030R8） | 我（NUCLEO-F103RB） |
|---|---|---|
| 内核 | Cortex-M0 | Cortex-M3 |
| Flash / RAM | 64K / 8K | 128K / 20K |
| GPIO 配置 | `MODER` / `OTYPER` / `OSPEEDR` / `PUPDR` | `CRL` / `CRH`（每引脚 4 位） |
| 时钟使能 | `RCC_AHBENR` | `RCC_APB2ENR` |

**这不是书的错**——书写在 2021 年，F030R8 是当时最便宜的入门板；
F103RB 在国内更普及（"蓝板"）。但照抄代码会静默失败，
所以本仓库每一处寄存器用法都会标注"F1 是什么/F0 是什么"。

### Q：`STM32F103RB_FLASH.ld` 里那一大堆段，哪些是必需的？

必需的四类（[ch11](../ch11-linker.md) 会逐类展开）：

| 段 | 必需性 | 说明 |
|---|---|---|
| `.isr_vector` | **必须放 Flash 首地址** | 否则复位后拿不到 SP 和入口 |
| `.text` | 必需 | 代码 |
| `.data` | 必需 | 初值在 Flash，变量在 RAM（**VMA ≠ LMA**） |
| `.bss` | 必需 | 清零 |

不需要的（可以丢）：`.ARM.exidx`（纯 C 项目）、`.comment`、`.note.GNU-stack`。
派生出来的：`.noinit`（不初始化的 RAM 段）、`.rodata` 是否并入 `.text`、
栈溢出哨兵——这些都是**工程决定**，不是"必须有"。
