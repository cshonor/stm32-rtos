# 第 14 章 缓冲文件 I/O —— 章节导航

> 书：第 14 章 缓冲文件 I/O（原书 p202–211）
> 对应实验：**全部为本次实测**（clang 23.1.0 / macOS arm64 / Apple Silicon）

## 这一章在讲什么

**书这一章讲"大型机器"（你的电脑）上的文件 I/O。**
对裸机轨来说，价值不在"我会用 `fopen`"，
而在三件事：

1. **缓冲区的存在性**——用磁盘文件大小实测出来（写了 5 字节，文件还是 0 字节）；
2. **文本 vs 二进制**——这个选择会**毁掉一个固件文件**（Windows 的 `\r\n`）；
3. **"写"不等于"写进去了"**——`fclose` 也可能失败。

一句话概括全章：

> **本章的概念直接映射回板子：
> `FILE*` 缓冲 ↔ UART 输出缓冲；
> `fflush` ↔ 把缓冲真的发完；
> 二进制格式 ↔ 协议帧格式。
> 差别只是裸机上没有 libc、没有文件系统，全都得自己写。**

## 与书的差异（重要）

| 书 | 我 |
|---|---|
| 14.1 讲 `printf` | 补上**返回值实测**（6/12/10/10/10/2）；⚠ 实测 **类型不匹配输出垃圾**：`printf("%d", 3.14)` → **1374389535**（double 位模式的低 32 位）；裸机上没有 libc 的 `printf`（[ch09](../09-uart-serial/9.3-串行输出.md) 实测 `mini_printf` 340 B text / 40 B 栈） |
| 14.2 讲 ASCII 表 | 指出它不是"练习"，而是 **hex dump 工具的一半**（右边那列就是同一个 `32..126` 判断）；⚠ 实测为什么不能打控制字符：`0x1B`(ESC) 会被终端当转义序列、`0x0D`(CR) 会覆盖输出、`0x07`(BEL) 会响铃 |
| 14.3 讲读数据 | 三个坑都有实测：`%s` 无长度限制、`sscanf("42 abc","%d %d")` 返回 **1**（`b` 未初始化）、**格式串末尾的 `\n` 会让 `scanf` 卡住**；`fgets` 实测保留 `\n`（长度 6） |
| 14.4 讲打开文件 | **12 格完整行为矩阵实测**（6 模式 × 文件存在/不存在）；⚠ `"w"` 会**静默截断**（原有 8 字节，`"w"` 打开后 `fgetc` 立刻 EOF）；⚠ `fputc` 失败只返回 `EOF`，不检查就"写了但没写进去" |
| 14.5 讲二进制 I/O | ⚠ 实测**直接 `fwrite` 结构体会把填充字节写进文件**：`rec_t` **12 B** vs `packed` **7 B**（5 字节填充，占 42%），且**填充字节的值标准上未指定**；⚠ `fwrite(buf,100,1,f)` 写一半返回 **0**（无法判断写了多少） |
| 14.6 讲缓冲与刷新 | **全部实测**：磁盘大小 0 → 5 → 5 → 10；三种 `setvbuf` 模式对照；**缓冲区满"差一格"**（写满 64 还是 0，第 65 个来才刷出 64）；⚠ `exit` 会 flush 但 `_exit`/`abort` 不会 |
| 书里没提 | 裸机上 HardFault handler 要**轮询 flush**（NVIC 可能已经坏了）；`stderr` 无缓冲导致输出顺序和代码顺序不一致 |

## 核心实测数据（本章的锚点）

```
① 缓冲区的存在性（看磁盘文件大小）
fprintf("hello") 之后，磁盘上的文件大小 = 0    ← ⚠ 写了 5 字节，文件还是 0
fflush() 之后，磁盘上的文件大小       = 5
又写 5 字节不 flush，磁盘大小         = 5
fclose() 之后，磁盘大小               = 10

② 三种 setvbuf 模式（写 5 字节 → 查 → 再写 5 字节 → 查）
无缓冲 写 5 字节后磁盘大小 = 5  | 再写 5 字节后 = 10
行缓冲 写 5 字节后磁盘大小 = 0  | 再写 5 字节后 = 0   ← 数据里没 \n，不触发
全缓冲 写 5 字节后磁盘大小 = 0  | 再写 5 字节后 = 0

③ 缓冲区满自动刷新（64 B 缓冲）
写到第 64 字节时 = 0     ← ⚠ 刚好填满，还没触发
写到第 128 字节时 = 64    ← 第 65 个字节来时才刷出前 64

④ 文本 vs 二进制（同一个 int 1000000）
二进制 fwrite：4 字节 → 40 42 0f 00（小端：0x000F4240）
文本   fprintf：7 字节 → 1000000
$ ls -l → 4 v.bin / 7 v.txt

⑤ ⚠ fwrite 结构体会写进填充字节
rec_t   {u8 flag; u32 value; u16 code;}          sizeof=12  offset(value)=4 offset(code)=8
rec_p_t 同上 + __attribute__((packed))           sizeof=7
自然对齐 fwrite：12 字节 → 01 00 00 00 44 33 22 11 66 55 00 00
                          └flag┘└填充3┘└ value ┘└code┘└填充2┘
packed   fwrite：7 字节 → 01 44 33 22 11 66 55
$ ls -l → 12 r_nat.bin / 7 r_pkd.bin      ← 5 字节填充（42%）

⑥ fopen 模式矩阵（文件已存在，内容 ORIGINAL 共 8 字节）
r    → OK  初始位置=0  读一字节=成功  写=失败
w    → OK  初始位置=0  读一字节=EOF    写=成功   ← ⚠ 已截断
a    → OK  初始位置=8  读一字节=EOF    写=成功
r+   → OK  初始位置=0  读一字节=成功  写=成功
w+   → OK  初始位置=0  读一字节=EOF    写=成功
a+   → OK  初始位置=8  读一字节=EOF    写=成功   ← 光标在尾，要先 fseek
（文件不存在时：r / r+ → NULL，errno=2: No such file or directory）

⑦ printf 返回值（输出的字符数）
printf("hello\n")                        → 6
printf("%d %s %.2f\n",42,"abc",3.14159)  → 12
printf("%*d|\n",8,42)                    → 10
printf("%-8d|\n",42)                     → 10
printf("%08.3f|\n",3.14159)              → 10
printf("%%\n")                           → 2

⑧ ⚠ printf 类型不匹配
warning: format specifies type 'int' but the argument has type 'double' [-Wformat]
printf("%d\n", 3.14)  → 1374389535    ← 垃圾（3.14 位模式的低 32 位）

⑨ scanf / fgets 行为
① sscanf("%7s") 读入 1 项，buf="1234567"（长度 7）     ← 宽度限制生效
② sscanf("42 abc","%d %d") 返回 1（b 未初始化）        ← ⚠ 只匹配了 1 项
③ sscanf("10\n20","%d\n%d") 返回 2，a=10 b=20
④ fgets 读到 "hello\n"（长度 6，含换行符 \n）
⑤ fscanf("%d") 读 v.txt → 1000000（文本解析）
   fread(&w,4,1) 读 v.bin → 1000000（原始字节，小端）

⑩ 裸机侧对照（本章引用的既有实测）
mini_printf：.text 340 B(-Os) / 548 B(-O0)，栈 40 B，llvm-nm -u 空
115200 8N1：每字节 86.8 µs（flush 的真实代价）
配置区钉在最后一页：.bin 从 136 B → 130060 B
一个 assert：86 B → 24 B（省 62 B，主要是 __FILE__ 字符串）
```

## 读完本章你应该能回答

- 写了 5 个字节，磁盘上的文件多大？（实测：**0**）
- `fflush` / `fclose` / 缓冲区满——三个刷新时机的实测证据各是什么？
- 行缓冲为什么实测一直是 0？（**数据里没有 `\n`**）
- 缓冲区写满 64 字节时磁盘是多少？（**0**，"差一格"）
- `exit` / `_exit` / `abort` 哪个会 flush 缓冲？
- `printf("%d", 3.14)` 输出什么？（**1374389535**）
- `printf` 的返回值是什么？`snprintf` 的呢？
- ASCII 表里哪些不可打印？为什么直接打 `0x1B` 很危险？
- hex dump 的右半列和 ASCII 表程序是什么关系？
- `scanf` 返回 0 和 `EOF` 有什么区别？为什么会导致死循环？
- 格式串末尾的 `\n` 会造成什么？（`scanf` **卡住**）
- `fgets` 读进来的行为什么带 `\n`？怎么正确去掉？
- `"w"` 打开一个已有文件会发生什么？（**静默截断**）
- `"a+"` 能读吗？（能，但**光标在文件尾**，要先 `fseek`）
- 为什么二进制必须用 `"wb"`？（Windows 的 `\r\n`）
- `fwrite` 一个结构体会多写多少字节？（实测 **12 vs 7**，5 字节填充）
- `fwrite(buf,100,1,f)` 写一半返回多少？（**0**）
- 二进制文件的字节序问题怎么彻底解决？

clang -O0 -o sv  sv.c  && ./sv

# ② 文本 vs 二进制
clang -O0 -o tb tb.c && ./tb && ls -l v.bin v.txt && od -An -tx1 v.bin

# ③ fopen 模式矩阵
clang -O0 -o fo fo.c && ./fo

# ④ 读数据行为
clang -O0 -o rd rd.c && ./rd

# ⑤ ⚠ 结构体填充进文件

clang -O0 -o pf pf.c && ./pf
