# 00.1 没有操作系统的 C 语言（freestanding）

> 本篇不属于书里任何一章，是读全书之前必须先钉住的前提。
> 下一篇：[00.2 操作硬件的三个手段](00.2-操作硬件的三个手段.md)
> 对应实验：`stm32/00-toolchain-clang/`

## 这一节要解决什么

一个问题：**没有操作系统，C 语言靠什么碰到硬件？**

## 一、C 标准的"抽象机器"里根本没有硬件

ISO C 标准只定义两样东西：**抽象机器**（abstract machine）和**可观察行为**。
"GPIO""Flash""中断向量"这些词，C 标准里一个字都没有。

标准定义的执行环境只有两种：

| 环境 | 是什么 | 标准保证什么 |
|---|---|---|
| hosted | 有 OS，程序从 `main` 开始，`main` 返回即结束 | 全套标准库、`argc/argv`、`exit()` 语义 |
| **freestanding** | 没有 OS | **只保证**一小撮头文件 + 极少数隐式符号 |

裸机就是 freestanding。C11 §4p6 明确列出的、freestanding 实现**必须**提供的头只有 7 个：

```
<float.h>  <iso646.h>  <limits.h>  <stdarg.h>  <stdbool.h>  <stddef.h>  <stdint.h>
```

**没有 `<stdio.h>`，没有 `<stdlib.h>`，没有 `<string.h>`。**

## 二、标准留的那扇后门

标准允许编译器在 freestanding 下仍然**隐式调用**四个函数：`memcpy` / `memmove` /
`memset` / `memcmp`。你不需要 `#include` 它们，但**必须在某个地方提供实现**。

这不是理论。实测（`stm32/00-toolchain-clang`，`make check-libc`）：

```
--- 未定义符号（谁被偷偷调用了）---
U __aeabi_memcpy      ← struct big 整体赋值，编译器替你写了 memcpy 调用
U __aeabi_dadd        ← 浮点乘加，M3 没有 FPU，走软件浮点
U __aeabi_dmul
U __aeabi_ldivmod     ← long long 除法
```

注意符号名是 `__aeabi_memcpy`（ARM EABI 名字），不是 `memcpy`——**只写 `memcpy` 会链不上**。

一句话记住：**在裸机上，"标准库"不是不存在，而是变成了你的活。**

## 三、少掉的不只是一个库

不是"少了一个库"，是少了一整套**替 C 运行环境做初始化的人**。

Linux 上跑一个 C 程序的真实路径：

```
内核 loader 把 PT_LOAD 段映射到内存
  → 设置 SP
  → 跳到 _start（crt1.o 里的汇编，来自 libc）
  → __libc_start_main：初始化 libc、跑 .init_array、设 TLS
  → 调 main(argc, argv)
```

裸机上，这条链上**除了 `main`，其他每一环都没人做**：

| C 运行环境的前置条件 | Linux/PC | 裸机 STM32 | 谁做 |
|---|---|---|---|
| 栈指针 SP | 内核设 | **向量表第 0 个字**，上电时硬件自动加载 | 硬件 |
| 入口 PC | `_start` | **向量表第 1 个字** → `Reset_Handler` | 硬件 + 你 |
| `.data` 初值搬运 | loader / dynamic linker | 手写循环 | 你 |
| `.bss` 清零 | 内核（新页本来就是 0） | 手写循环 | 你 |
| 堆 | `brk` / `mmap` | 自己划一块 SRAM | 你 |
| `printf` | `write(2)` 系统调用 | UART 寄存器 / ITM / semihosting | 你（ch09） |
| `malloc` | glibc | 自己写 allocator 或全静态分配 | 你 |
| 除零 / 访存越界 | SIGFPE / SIGSEGV（内核兜） | **HardFault 向量 → 你的死循环** | 你 |
| 程序退出 | `exit_group` 关进程 | 无处可退，停在原地 | —— |

## 四、实测：那 16 条指令就是"你"那一列

`Reset_Handler` 是这张表里"你"那一列的具体实现（真机烧录后的实测反汇编）：

```
8000054: movw r1, #0x124 / movt r1, #0x800   ; _sidata = 0x08000124（Flash）
8000060: movt r2, #0x2000                    ; _sdata  = 0x20000000（RAM）
8000064: ldr  r3, [r1], #4                   ; 搬 .data
8000068: str  r3, [r2], #4
8000070: movw r0, #0x8 / movt r0, #0x2000    ; _ebss
8000074: movw r1, #0x4 / movt r1, #0x2000    ; _sbss
8000088: str  r2, [r1], #4                   ; 清 .bss
8000090: bl   0x800009c <main>
8000094: b    0x8000094                      ; main 不该返回
```

一个反直觉但准确的结论：**裸机从复位到 `main` 之间的代码，量级等同于
Linux 内核 `start_kernel` 之前那一小段。** 只是内核那段的作者是 Linus，
这里的作者是你，16 行指令。

## 代码自测

<details>
<summary>Q1：`-ffreestanding` 和 `-nostdlib` 有什么区别？只加一个行不行？</summary>

两者管的对象不同，**要一起加**：

- `-ffreestanding`：告诉**编译器前端/中端**"这里没有宿主环境"。影响的是语义判断
  （比如 `main` 不特殊对待、不假定有 `exit`、允许 `__builtin` 走裸实现）。
  它**不阻止**你去链接 libc。
- `-nostdlib`：告诉**链接器**别自动带上 `crt0.o`、`libc`、`libgcc`。

只加 `-ffreestanding`：语义对了，但链接器还是会拉 libc，最后得到一个
"看起来能跑但依赖一堆你不知道的东西"的镜像。
只加 `-nostdlib`：链接干净了，但编译器仍按 hosted 规则优化，可能生成你不期望的调用。

⚠️ 加 `-nostdlib` 之后连 `libgcc`/`compiler-rt` 都没了，`long long` 除法、
软件浮点这些 helper 要自己提供（上面 `__aeabi_ldivmod` 就是被这个逼出来的）。
</details>

<details>
<summary>Q2：为什么 `.bss` 要清零，而 `.data` 要搬运？不能都放 Flash 里省事吗？</summary>

因为 **Flash 是只读的、RAM 是可写的**，而 C 语言对两类变量承诺了不同的语义：

| 段 | C 语义 | 放哪里 | 上电后 |
|---|---|---|---|
| `.data` | 有初值的全局/静态变量，**可写** | 初值存 Flash，变量本体在 RAM | 搬运一次 |
| `.bss` | 无初值的全局/静态变量，**初值 = 0** | 不占 Flash，只在 RAM 里占地址 | 清零 |

如果 `.data` 直接放 Flash，你写它就会失败（NOR Flash 写入要先擦整页，见 ch02 Q4）。
如果 `.bss` 不占 Flash 也不清零，main 里第一个读到全局变量的语句就会读到
**SRAM 上电残留值**——表现是"有时候对、有时候错"，最难查的那类 Bug。
</details>

<details>
<summary>Q3：既然 freestanding 只有 7 个头，我 `#include <stdio.h>` 为什么不一定报错？</summary>

因为报不报错取决于**实现提供了什么**，不取决于标准要求什么。

clang 在你的 SDK 路径下（比如 `--sysroot` 指向 arm-none-eabi 的 newlib）确实能找到
`<stdio.h>` 文件，于是编译通过——然后在**链接**阶段倒在
`undefined reference to 'printf'`。

裸机开发的典型痛点就在这：错误在链接期才暴露，而不是编译期。
所以本仓库的做法是 `-ffreestanding -fno-builtin -nostdlib`，
**宁可编译期就缺，也不要链接期才发现。**
</details>
