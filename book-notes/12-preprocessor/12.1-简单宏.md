# 12.1 简单宏

> 书：第 12 章 预处理器 · 12.1 简单宏（原书 p174–185 区间内）
> 下一篇：[12.2 带参数的宏](12.2-带参数的宏.md)
> 对应实验：`clang -E -P` / `clang -E -dM` 展开实测（clang 23.1.0）

## 书这一节讲什么

一句话：**`#define NAME 替换文本`——预处理器在编译前把 `NAME` 换成后面的文本。**

它是**纯文本替换**，不是变量、不是常量、不占内存。
书上讲的是语法和"宏名要大写"这类约定。本篇把重点放在
**"宏到底展开成什么"怎么查**，以及**宏和 `const`/`enum` 怎么选**。

## 一、怎么看到宏展开成什么（唯一权威方法）

```sh
clang -E -P foo.c        # -E 只做预处理，-P 去掉行号标记
clang -E -dM foo.c       # 把"当前所有已定义的宏"全打出来
```

**实测**（`m1.c`）：

```c
#define SQUARE_OK(x)  ((x)*(x))
#define BIT(n)        (1u << (n))
#define VER           3
...
int result2  = SQUARE_OK(3 + 1);
unsigned b   = BIT(5);
```

```
$ clang -E -P m1.c
int result2 = ((3 + 1)*(3 + 1));
unsigned b = (1u << (5));
```

⚠ **`-E` 是你排查宏问题的唯一武器**。
宏出 bug 时不要靠猜，直接看展开结果——
预处理器做的事**没有任何隐藏逻辑**，展开成什么就是什么。

## 二、裸机上最常用的一类简单宏：寄存器和位

书上讲宏举的是 `PI`、`MAX_SIZE` 这种。嵌入式里高频得多的是这两类：

```c
#define GPIOA_BASE   0x40010800u
#define REG32(base,off) (*(volatile uint32_t *)((base) + (off)))
#define GPIOA_ODR    REG32(GPIOA_BASE, 0x0Cu)
#define BIT(n)       (1u << (n))
#define RCC_APB2ENR  REG32(0x40021000u, 0x18u)
```

| 类别 | 例子 | 为什么用宏而不是变量 |
|---|---|---|
| 地址常量 | `GPIOA_BASE` | 必须是**编译期常量**，才能被折叠进指令（实测见下） |
| 位掩码 | `BIT(5)` | 同上；`1u` 后缀很重要（[ch04](../04-numbers-and-bitops/README.md)） |
| 配置值 | `CFG_BAUD` | 编译期定死，配合 `-D` 换板子（[12.6](12.6-命令行定义的符号.md)） |

**实测：宏展开后是立即数，不占 `.data`**：

```c
#define GPIOA_BASE 0x40010800u
#define REG32(base,off) (*(volatile uint32_t *)((base) + (off)))
#define GPIOA_ODR  REG32(GPIOA_BASE, 0x0Cu)
static inline void led2_set(void){ GPIOA_ODR |= (1u << 5); }
void use_plain(void){ led2_set(); ... }
```

```
$ llvm-objdump -d -j .text.use_plain cm.o
       0: f640 000c    	movw	r0, #0x80c      ← 0x4001080c 被折叠成两条立即数指令
       4: f2c4 0001    	movt	r0, #0x4001
       8: 6801         	ldr	r1, [r0]
       a: f041 0120    	orr	r1, r1, #0x20
       e: 6001         	str	r1, [r0]

$ llvm-size cm.o
   text	   data	    bss
     72	      0	      0                        ← data = 0：地址没进 .data
```

地址 `0x4001080c` 变成 `movw`/`movt` 两条指令的立即数，
**没有一次内存访问去"取地址"**。这就是"必须是编译期常量"的价值。

## 三、宏的四个基本事实

| 事实 | 说明 | 后果 |
|---|---|---|
| **预处理阶段替换** | 编译器**看不到** `BIT(5)`，只看到 `(1u << (5))` | 报错信息里显示展开后的东西 |
| **不占内存** | 宏不是变量，不存在"地址" | 不能 `&BIT(5)` |
| **没有类型** | 纯文本 | 类型错误靠展开后暴露，信息难读 |
| **没有作用域** | 从 `#define` 处生效到文件尾（或 `#undef`） | 会"泄漏"到后面的所有代码 |

## 四、多行宏：用 `\` 续行

```c
#define REG_BIT_DEF(name, reg, bit) \
    static inline uint32_t name##_get(void){ return ((reg) >> (bit)) & 1u; } \
    static inline void name##_set(void){ (reg) |= (1u << (bit)); } \
    static inline void name##_clear(void){ (reg) &= ~(1u << (bit)); }
```

⚠ **两个经典错法**：

1. **最后一行也加了 `\`** → 会把下一行（可能是空行或代码）也粘进来；
2. **`\` 后面有空格** → 反斜杠失去续行作用，且**不报错**。

```
#define FOO 1\      ← ⚠ 反斜杠后有空格
```

第二种特别坑：某些编译器给警告，clang 默认**静默**。
症状是"宏展开结果里多出奇怪的东西"。

## 五、宏 vs `const` / `enum`：怎么选

这是书里没细讲但工程上天天要决定的事。

| 需求 | 用 | 理由 |
|---|---|---|
| 地址常量 / 位掩码 | **宏** | 必须是编译期常量；`const` 变量在 C 里**不是**常量表达式 |
| 编译期可裁剪的配置 | **宏** | 配合 `#if`（`const` 不能进 `#if`） |
| 有类型的常量 | **`enum`** | 调试器能看到符号名（[ch08](../08-complex-types/README.md)） |
| 调试期想看值的常量 | `static const` | gdb 里 `p g_baud` 能看到 |
| 字符串常量 | `static const char[]` | 宏展开会在每次使用时**复制一份**（见下） |

⚠ **字符串宏的体积账**：

```c
#define FW_VERSION "1.2.3"
printf("%s", FW_VERSION);
printf("%s", FW_VERSION);      /* 用两次 */
```

每个使用点都可能产生一份字符串副本（取决于编译器是否合并）。
用 `static const char g_fw[] = "1.2.3";` 则**只有一份**。
Flash 紧张时用 [ch11 的 map 文件](../11-linker/11.5-映射文件.md)看 `.rodata` 的实际大小。

## 六、命名约定

```c
#define MAX_LEN    64          /* ✅ 全大写 + 下划线：一眼看出是宏 */
#define max_len    64          /* ❌ 和变量混在一起，读代码的人会猜错 */
```

带参数的宏**更要注意**：`MAX(a,b)` 看起来像函数，行为却完全不同
（[12.2](12.2-带参数的宏.md) 的两个陷阱）。

## 坑点（书 / 常识怎么说 / 实际是什么）

| 书 / 常识怎么说 | 实测是什么 |
|---|---|
| "宏就是常量" | 不是。它是**文本替换**，没有类型、没有地址、不能取址 |
| "`const int` 能替代宏" | ❌ C 里 `const int` **不是常量表达式**，不能进 `#if`、不能当数组长度（C99 VLA 除外）。地址常量必须用宏 |
| "宏会占内存" | 不占。实测 `llvm-size cm.o`：`data 0 bss 0`，地址被折叠进 `movw`/`movt` 立即数 |
| "宏名大写只是风格" | 是风格，但**在裸机上很重要**：看到全大写就该立刻想到"这是文本替换，可能有陷阱" |
| "多行宏最后一行也要 `\`" | ❌ 最后一行**不要加**；且 `\` 后**不能有任何字符（含空格）**，clang 默认不警告 |
| "字符串宏很省" | 每次展开都是一份副本。多用几次就该换 `static const char[]` |

## 代码自测

<details>
<summary>Q1：宏出 bug 时，第一步该做什么？</summary>

**跑 `clang -E -P`，看它到底展开成什么。**

```
$ clang -E -P m1.c
int result2 = ((3 + 1)*(3 + 1));
unsigned b = (1u << (5));
```

宏**没有任何隐藏逻辑**——预处理器做的事就是文本替换，
展开结果是什么，编译器看到的就是什么。
所以"猜"是没有意义的，看一眼就有答案。

**三个常用开关**：

| 命令 | 用途 |
|---|---|
| `clang -E foo.c` | 展开，保留 `# 行号` 标记（给编译器看的） |
| `clang -E -P foo.c` | 展开，**去掉行号标记**（给人看的，推荐） |
| `clang -E -dM foo.c` | 把**所有已定义的宏**打印出来（含编译器预定义的） |

**`-dM` 查预定义宏**（实测，本机 clang 23.1.0 / Apple arm64）：

```
$ clang -E -dM -x c /dev/null | grep __STDC_VERSION__
#define __STDC_VERSION__ 201710L        ← C17
```

交叉编译时 `-dM` 更实用：

```
$ clang --target=armv7m-none-eabi -mcpu=cortex-m3 -mthumb -E -dM -x c /dev/null | grep __ARM
#define __ARM_ARCH 7
#define __ARM_ARCH_ISA_THUMB 2
...
```

——**不用去猜编译器认识了哪些宏**，`-dM` 一次列全。

⚠ **一个容易忽略的点**：`-E` 会**忠实反映 `-D` 和 `#if` 的结果**。
所以当你怀疑"某个 `-D` 没生效"或者"某个 `#if` 分支没进去"时，
`clang -E` 加上**一模一样的编译选项**看输出，是最快的定位手段。
</details>

<details>
<summary>Q2：裸机上为什么地址常量必须用宏，不能用 `const`？</summary>

**因为 C 语言的 `const` 变量不是"常量表达式"（constant expression）。**

这是个 C 和 C++ 的**重大差异**，从 C++ 转过来的人必踩：

```c
const uint32_t gpioa_base = 0x40010800u;
static uint32_t arr[gpioa_base];      /* ❌ C 下报错（VLA 以外不允许） */
#if gpioa_base == 0x40010800u         /* ❌ #if 里根本看不到 const */
```

而宏可以：

```c
#define GPIOA_BASE 0x40010800u
static uint32_t arr[64];              /* 数组长度用宏没问题 */
#if GPIOA_BASE == 0x40010800u         /* ✅ 预处理器能求值 */
```

**裸机上真正的代价在"能不能折叠成立即数"**。实测：

```c
#define GPIOA_BASE 0x40010800u
#define REG32(base,off) (*(volatile uint32_t *)((base) + (off)))
#define GPIOA_ODR  REG32(GPIOA_BASE, 0x0Cu)
```

```
$ llvm-objdump -d -j .text.use_plain cm.o
       0: f640 000c    	movw	r0, #0x80c
       4: f2c4 0001    	movt	r0, #0x4001      ← 0x4001080c 直接进立即数
       8: 6801         	ldr	r1, [r0]
       a: f041 0120    	orr	r1, r1, #0x20
       e: 6001         	str	r1, [r0]

$ llvm-size cm.o
   text	   data	    bss
     72	      0	      0                          ← data = 0
```

地址被**编译进指令的立即数字段**，运行时**不需要去内存里读地址**。

如果换成 `const uint32_t gpioa_base = 0x40010800u;`：

- 编译器（`-O0` 下）会为它分配一个 `.data` 槽位；
- 每次用都要 `ldr` 先把地址**读出来**；
- 多一次内存访问 + 多 4 字节 Flash + 多 4 字节 RAM。

⚠ **在 `-Os` 下编译器通常还是能把 `const` 优化掉**，
所以这个差别主要体现在：

1. `volatile` 场景（编译器不敢动）；
2. 跨翻译单元（`extern const`，链接期才能定）；
3. `-O0` 调试构建（你想让调试行为和发布行为一致时）。

**判断标准（一句话）**：

> **需要出现在 `#if` 里、数组长度里、或者想让它变成指令立即数的，用宏；
> 只是"一个不该被改的值"，用 `const` 或 `enum`。**
</details>

<details>
<summary>Q3：宏和 `enum` / `const` 怎么选？举个裸机的具体例子。</summary>

按"你要拿它干什么"来分，不要一律用宏：

| 需求 | 选 | 裸机例子 |
|---|---|---|
| 地址 / 位掩码（要进 `#if`、要成立即数） | **宏** | `GPIOA_BASE`、`BIT(5)` |
| 编译期裁剪（`#if` 判断） | **宏** | `LOG_LEVEL`、`BOARD_xxx` |
| 一组相关的状态值，想让调试器显示名字 | **`enum`** | `enum { UART_IDLE, UART_TX, UART_RX };` |
| 一个具体数值，调试时想 `p` 出来看 | `static const` | `static const uint32_t g_baud = 115200;` |
| 字符串 | `static const char[]` | `static const char g_fw[] = "1.2.3";` |

**实测对比：字符串宏 vs `static const`**

```c
#define FW_VERSION "1.2.3"
printf("%s", FW_VERSION);
printf("%s", FW_VERSION);      /* 用了两次 */
```

宏每次展开都是**一份字面量**（编译器可能合并，但**不保证**，
且跨翻译单元一定不合并）。换成：

```c
static const char g_fw[] = "1.2.3";
printf("%s", g_fw);
printf("%s", g_fw);            /* 只有一份 */
```

**用 [ch11 的 map 文件](../11-linker/11.5-映射文件.md)验证**：
看 `.rodata` 的 size，宏版会随使用次数增长，`static const` 版是固定的。

**`enum` 相对宏的优势**（[ch08](../08-complex-types/README.md)）：

```c
enum { LED_OFF = 0, LED_ON = 1 };
```

- 调试器**知道 `LED_ON` 是什么**（宏在编译前就没了，gdb 里看不到）；
- 有**类型**（`enum` 是整型，但至少经过编译器检查）；
- 不会污染全局（宏会泄漏到文件尾）。

⚠ **`enum` 的短板**：

- 不能表示**非整型**的值（地址是可以的，但通常是 `unsigned`，要注意符号性）；
- 不能进 `#if`（预处理器**看不到** `enum`）；
- 不能表示浮点、字符串。

**本仓库的取向**：

> **地址、位、编译期开关 → 宏；状态集合 → `enum`；数值常量 → `static const` 或 `enum`。**

⚠ 还有一条：**宏名一定要全大写**。
`BIT(5)` 和 `max(a,b)` 看起来一个是常量一个是函数，
但在 C 里**两者都可能带副作用**——大写命名是唯一的视觉警报。
</details>
