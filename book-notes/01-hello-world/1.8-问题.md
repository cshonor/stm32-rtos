## Q1：写出把 `main.c` 变成 STM32F103 可烧录镜像的完整命令序列（不用 make）。

```bash
export PATH=~/micromamba/envs/cdev/bin:$PATH
T="--target=armv7m-none-eabi -mcpu=cortex-m3 -mthumb -ffreestanding -fno-builtin -Os -g"

# ① 汇编启动文件
clang $T -c startup.S -o startup_s.o
# ② 编译 C
clang $T -c main.c -o main.o
# ③ 链接（必须写全 ld.lld）
ld.lld -T linker.ld --gc-sections -Map=app.map -o app.elf startup_s.o main.o
# ④ 提取裸镜像
llvm-objcopy -O binary app.elf app.bin
# ⑤ 烧录
~/.local/xpack-openocd-0.12.0-7/bin/openocd -f f103rb.cfg \
  -c "program app.bin 0x08000000 verify reset exit"
```

**评分点**：③ 必须是 `ld.lld` 不是 `ld`；⑤ 必须有 `verify reset exit`，否则 openocd 挂着不退。

## Q2：`undefined reference to '__aeabi_memcpy'` 报错，改哪个文件能修好？

**不是改 C 代码，是提供实现。** 这个符号是编译器为"结构体整体赋值"自动生成的调用
（见 [00.1](../00-mental-model/00.1-没有OS的C语言.md)）。

三种修法，按优先级：

| 修法 | 适用 |
|---|---|
| 自己写 `__aeabi_memcpy`（同时提供 `memcpy`） | 本仓库路线，`-nostdlib` 下唯一可行 |
| 链接 newlib（`--sysroot=` 指过去） | 已经有工具链时省事，代价是体积 |
| 改 C 代码避免结构体整体赋值 | **治标不治本**，别的优化也会生成它 |

⚠️ 常见误判：以为是"没 include `<string.h>`"。include 了也一样——
freestanding 下这个符号**根本没有实现**，include 只是拿到声明。

## Q3：为什么 `make` 之后改了 `linker.ld` 却没生效？

Makefile 里漏了把链接脚本写成依赖：

```makefile
# ❌ 改 linker.ld 不会重新链接
app.elf: startup_s.o main.o

# ✅ 会重新链接
app.elf: startup_s.o main.o linker.ld
```

**没有任何报错**，这是最难自查的一类问题。
验证手法：`touch linker.ld && make -n`，看它有没有打算重新链接。

## Q4：不写 `for (;;)`，`main` 里 `return 0` 会怎样？

会执行 `bl main` 之后的那条指令，而那条指令是什么**取决于你的启动文件**。

- 我们那份 `startup.S` 后面是 `b .`（自己跳自己）→ 看不出来；
- 换一份启动文件，后面可能是数据 → **跑飞**，或者落进 HardFault。

所以 `for (;;)` 是把不确定性变成确定性，不是风格偏好。

## Q5：`.ARM.exidx` 占了 `.text` 的 40%，`-fno-unwind-tables` 能去掉它吗？

**不能。** 本仓库实测加了 `-fno-unwind-tables` 仍然存在。

可靠做法是二选一：

```ld
/* 链接脚本里丢弃 */
/DISCARD/ : { *(.ARM.exidx) }
```

或者依赖 `--gc-sections` 的可达性分析把它收掉（前提是 `-ffunction-sections` 打开了）。

⚠️ 丢弃的代价：**丢失 HardFault 时的调用栈回溯能力**。
调试阶段建议留着，发布时再丢。

## Q6：`-Os` 下我设的断点打不上，是什么原因？

优化把代码结构改掉了，常见三种：

| 现象 | 原因 | 对策 |
|---|---|---|
| 断点行"跳着走" | 多行被合并成一条指令 | 用 `-Og` 或 `-O0` |
| 断点直接被跳过 | 函数被内联进调用者 | 加 `__attribute__((noinline))` |
| 变量显示 `<optimized out>` | 变量在寄存器里，不在栈上 | 加 `volatile`，或调试期降优化 |

**调试期统一用 `-Og`**，发布才 `-Os`。把这两个场景的编译选项在 Makefile 里
拆成 `DEBUG=1` 开关，别手动改。

## 自定义练习（动手做，不是背）

1. **改一个字节，看四步产物怎么变**：把 `add(a,b)` 改成 `a+b+1`，
   用 `clang -E -S -c` 分别看一眼，确认 `.o` 的 `.text` 大小变了多少。
2. **故意制造一个重定位错误**：在 `main.c` 里调用一个不存在的函数，
   观察报错是"编译期"还是"链接期"。
3. **验证 `-g` 不进镜像**：同一份代码分别带 `-g` 和不带，比较 `app.elf` 与 `app.bin` 的大小。
   （预期：`.elf` 差很多，`.bin` **一个字节都不差**。）
4. **验证优化删代码**：写 `while (flag == 0) {}`，`flag` 声明成非 `volatile`，
   用 `-Os` 编译看反汇编——预期变成单条 `bx lr`。
