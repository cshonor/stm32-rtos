## 书这一节讲什么

两件事：**用 make 把命令固化下来**，以及**搞懂编译器标志到底在说什么**。
书里给的是 PC 版的 Makefile；我们这里是裸机版，差异主要在链接那一步。

## 1.4.1 make 程序

`make` 的规则只有一条要背：

> **目标: 依赖 … 然后一行 TAB 缩进 + 命令。**

裸机版的骨架（`stm32/01-bare-metal/Makefile` 的简化版）：

```makefile
CC      := clang
TARGET  := armv7m-none-eabi
MCU     := cortex-m3
CFLAGS  := --target=$(TARGET) -mcpu=$(MCU) -mthumb \
           -ffreestanding -fno-builtin -fdata-sections -ffunction-sections -g -Os
LDFLAGS := -T linker.ld --gc-sections -Map=blink_asm.map

blink_asm.elf: startup_s.o main.o linker.ld
	ld.lld $(LDFLAGS) -o $@ startup_s.o main.o
	llvm-objcopy -O binary $@ blink_asm.bin
	llvm-size -A $@

%.o: %.c
	$(CC) $(CFLAGS) -c $< -o $@

%.o: %.S
	$(CC) $(CFLAGS) -c $< -o $@

clean:
	rm -f *.o *.elf *.bin *.map
```

真实跑出来的样子（实测）：

```
$ make
clang --target=armv7m-none-eabi -mcpu=cortex-m3 -mthumb -g -c startup.S -o startup_s.o
clang ... -ffreestanding -fno-builtin ... -c main.c -o main.o
ld.lld -T linker.ld --gc-sections -Map=blink_asm.map -o blink_asm.elf startup_s.o main.o
llvm-objcopy -O binary blink_asm.elf blink_asm.bin
blink_asm.elf  :
section                   size        addr
.isr_vector                 96   134217728
.text                      196   134217824
.data                        4   536870912
.bss                         8   536870916
.noinit                      4   536870924
```

`134217728 = 0x08000000`（Flash），`536870912 = 0x20000000`（RAM）。
产物 `blink_asm.bin` = **296 字节**。

### make 的三个实用知识点

| 知识点 | 说明 |
|---|---|
| `$@` `$<` `$^` | 目标名 / 第一个依赖 / 全部依赖。写规则就靠这三个 |
| **TAB 不是空格** | Makefile 里命令行必须以真 TAB 开头，空格会报 `missing separator` |
| 为什么用 `%.o: %.c` 模式规则 | 不写模式规则就得为每个 `.c` 抄一遍命令，加文件必忘 |

## 1.4.2 编译器标志

书在这里逐条讲 GCC 选项。**换成 clang 之后，大部分选项名一样，少数不一样**，
这张表是我实测对照过的：

| 作用 | GCC（书里的） | clang（我的） | 备注 |
|---|---|---|---|
| 目标三元组 | `-mcpu` + `--specs=nosys.specs` 等一堆 | `--target=armv7m-none-eabi` | clang 必须显式给 triple |
| CPU 选型 | `-mcpu=cortex-m3` | 同名 | 一致 |
| Thumb | `-mthumb` | 同名 | 一致 |
| 无宿主环境 | `-ffreestanding` | 同名 | 一致 |
| 不带标准库链接 | `-nostdlib` / `--specs=nosys.specs` | `-nostdlib` | GCC 有 specs 文件机制，clang 没有 |
| 禁止内建函数替换 | `-fno-builtin` | 同名 | 一致，但挡不住 `__aeabi_memcpy` |
| 段级回收 | `-ffunction-sections -fdata-sections` + `--gc-sections` | 同名 | 一致 |
| 生成 map | `-Wl,-Map=x.map` | `ld.lld -Map=x.map` | clang 也可用 `-Wl,-Map=` |
| 调试信息 | `-g`（默认 DWARF4） | `-g` | 一致，gdb 都能读 |

**最需要理解的两个标志**（书里也重点讲了）：

1. **`-ffunction-sections -fdata-sections` + `--gc-sections`**
   没有前两个，链接器眼里整个 `.text` 是一整块，没法丢；
   有了之后每个函数独立成段，`--gc-sections` 从入口做可达性分析，
   没人调的函数被整段删掉。实测在 296 字节的镜像上就已经生效
   （`blink_asm.map` 里有 `Discarded input sections`）。
2. **`-Os` vs `-O2`**
   嵌入式通常用 `-Os`（优化尺寸）。但**别在调试阶段用**：

   | 等级 | 后果 |
   |---|---|
   | `-O0` | 单步可预测，变量都在栈上；但代码大、可能有"死代码"假象 |
   | `-Os` | 代码小；但变量被塞进寄存器、函数被内联、空循环被删——**你设的断点可能打不上** |
   | `-Og` | GCC 的折中（clang 也支持），调试友好 + 少量优化，**调试期首选** |

## 坑点（书 / 常识怎么说 / 实际是什么）

| 书 / 常识怎么说 | 实际是什么 |
|---|---|
| "make 就是个批处理脚本" | 它的核心是**依赖图 + 时间戳比较**。`blink_asm.elf: startup_s.o main.o linker.ld` 这一行意味着改了 `linker.ld` 也会重新链接——**很多人漏写链接脚本，改 `-T` 的脚本不生效就是这个原因** |
| "`-g` 会让镜像变大" | 调试信息不占 Flash。`.elf` 会变大，但 `llvm-objcopy -O binary` 出来的 `.bin` 只含 `PT_LOAD` 段，**`-g` 一个字节都不进镜像** |
| "优化等级只影响速度" | 在裸机上它影响**正确性**：非 `volatile` 的空循环会被删、`delay` 函数被优化掉、ISR 里没 `volatile` 的标志变量读不到。实测空 `while` 在 `-Os` 下变成单条 `bx lr` |
| "`clean` 可有可无" | 换编译器/换标志之后必须 `make clean`。增量编译不会因为 CFLAGS 变了而重编（除非改对了依赖），这是"明明改了标志却没生效"的最常见原因 |
| "`-Wall` 加多了会有噪音" | 嵌入式里建议 `-Wall -Wextra -Wshadow -Wconversion`。**`-Wconversion` 尤其值**：寄存器位操作里 `int` → `uint32_t` 的隐式转换是真实 Bug 来源 |

## 代码自测

<details>
<summary>Q1：为什么改 `linker.ld` 之后必须重新链接？漏写依赖会怎样？</summary>

因为链接脚本是**链接器**的输入，不是编译器的输入。它决定：

- 每个段放在哪个地址（`.isr_vector` 必须在 0x08000000）；
- `_sidata`/`_sdata`/`_ebss` 这些符号的值；
- `MEMORY` 区域的边界。

如果 Makefile 里写成 `blink.elf: startup_s.o main.o`（漏了 `linker.ld`），
你改完脚本跑 `make`，make 认为依赖都没变 → **不重新链接** → 你以为改了，
实际产物还是旧的。表现是"我明明改了脚本，怎么没效果"。

这是新手最常撞的一堵墙，而且极难自查，因为**你没有任何报错可看**。
</details>

<details>
<summary>Q2：`-ffreestanding` 已经禁止隐式库调用了，为什么还要 `-fno-builtin`？</summary>

两者管的对象不同：

| 选项 | 管什么 |
|---|---|
| `-ffreestanding` | 告诉编译器"没有宿主环境"：`main` 不特殊、不假定有 `exit`、标准库只要求那 7 个头 |
| `-fno-builtin` | 告诉编译器"**别把我的 `strcpy`/`memset` 调用替换成内建实现**" |

不加 `-fno-builtin` 的后果：你写了一个自己的 `strcpy`，
编译器认出这个函数名，直接把它**替换成内建的、可能带 SIMD 的实现**——
你的实现在你自己的代码里被跳过了，诡异 Bug 就来了。

⚠️ 但这两条**都挡不住结构体整体赋值生成的 `__aeabi_memcpy`**（见
[00.1 Q1](../00-mental-model/00.1-没有OS的C语言.md)）——
那是编译器前端的行为，只能靠提供实现来解决。
</details>

<details>
<summary>Q3：为什么裸机的 Makefile 里没有 `-lm`、`-lc`？</summary>

因为它们根本不存在——`-nostdlib` 已经关掉了默认库搜索，而裸机上也**没有**
`libm.a`/`libc.a` 可以给。

但你可能真的需要它们的**功能**，这时候有两条路：

1. **自己实现**（本仓库路线）：你要 `memset` 就写一个 `memset`——
   而且必须用 `__aeabi_` 前缀名或同时提供两个名字，否则链接器找不到。
2. **带一份 newlib-nano**：Arm GNU Toolchain 自带，clang 可以通过
   `--sysroot=` 指过去。代价是镜像大几千字节，而且 printf 会拖进一堆你不需要的东西。

第 3 条路是**picolibc**（CubeIDE 的 STARM-Clang 就带 1.8.10），
体积小很多。本仓库现在还走第 1 条，等需要 printf 时再评估。
</details>
