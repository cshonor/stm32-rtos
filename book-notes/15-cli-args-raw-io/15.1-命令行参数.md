# 15.1 命令行参数

> 书：第 15 章 命令行参数和原始 I/O · 15.1 命令行参数（原书 p212+ 区间内）
> 下一篇：[15.2 原始 I/O](15.2-原始IO.md)
> 对应实验：主机侧实测（clang 23.1.0 / macOS arm64）— `argc/argv` 实测、
> **`atoi` vs `strtol` 的错误检测对照**

## 书这一节讲什么

一句话：**`int main(int argc, char **argv)`——程序启动时拿到的参数。**

书上讲 `argc` / `argv` 的用法。本篇补上书里**没讲但会咬人**的一件事：
**参数全是字符串，转换成数字时 `atoi` 检测不了错误**（有实测对比）。

## 一、实测：`argc` / `argv` 长什么样

```c
int main(int argc, char **argv){
    printf("argc=%d\n", argc);
    for (int i=0;i<argc;i++) printf("  argv[%d]=%s\n", i, argv[i]);
    printf("argv[argc]（标准保证为 NULL） = %s\n", argv[argc] ? argv[argc] : "(NULL)");
}
```

```
$ ./arg a b 3
argc=4
  argv[0]=./arg
  argv[1]=a
  argv[2]=b
  argv[3]=3
argv[argc]（标准保证为 NULL） = (NULL)

$ ./arg
argc=1
  argv[0]=./arg
argv[argc]（标准保证为 NULL） = (NULL)
```

**四条规则**（全部有实测支撑）：

| 规则 | 实测 |
|---|---|
| **`argv[0]` 是程序自己的路径** | `argv[0]=./arg` |
| **参数从 `argv[1]` 开始** | `argv[1]=a` |
| **`argc` 至少是 1** | 无参数时 `argc=1` |
| **`argv[argc] == NULL`**（标准保证） | 实测确认为 `(NULL)` |

⚠ **`argc` 至少是 1** 这条意味着：
`if (argc == 0)` 的分支**永远不会进**（在标准环境下）。
别写这段死代码。

## 二、⚠ 实测：`atoi` 检测不了错误，`strtol` 能

这是本节最该记住的一条。

```c
const char *in[] = {"3", "  42abc", "abc", "99999999999999999999", ""};
```

```
输入 "3"
   atoi   -> 3   （无法知道失败）
   strtol -> 3  end指向'?' (全部转换) errno=0
输入 "  42abc"
   atoi   -> 42   （无法知道失败）
   strtol -> 42  end指向'a' (有残留) errno=0
输入 "abc"
   atoi   -> 0   （无法知道失败）
   strtol -> 0  end指向'a' (没转换任何字符) errno=0
输入 "99999999999999999999"
   atoi   -> -1   （⚠ 无法知道失败，而且给的是 -1！）
   strtol -> 9223372036854775807  errno=ERANGE(超出范围)
输入 ""
   atoi   -> 0   （无法知道失败）
   strtol -> 0  end指向'?' (没转换任何字符) errno=0
```

⚠ **三个致命之处**：

1. **`atoi("abc")` 返回 0**——和"真的输入了 0"**无法区分**；
2. **`atoi("99999999999999999999")` 返回 `-1`**——
   溢出时 `atoi` 的行为是**未定义的**，这次给了 -1，下次可能给别的；
3. **`atoi("  42abc")` 返回 42**——
   静默忽略了后面的垃圾。

**`strtol` 的三个检测手段**：

```c
char *end = NULL;
errno = 0;                                  /* ⚠ 调用前必须清零 */
long v = strtol(str, &end, 10);

if (end == str)      { /* ① 一个字符都没转换 → 输入不是数字 */ }
else if (*end != '\0'){ /* ② 有残留字符 → 数字后面跟着垃圾 */ }
else if (errno == ERANGE) { /* ③ 超出范围 */ }
```

⚠ **三条都要检查**，而且**`errno` 要在调用前清零**——
`strtol` 只在出错时设置 `errno`，不会主动清零。

**封装成函数用**：

```c
/* 返回 0 成功，-1 失败；成功时 *out 是结果 */
static int parse_long(const char *s, long *out){
    char *end = NULL;
    errno = 0;
    long v = strtol(s, &end, 10);
    if (end == s || *end != '\0' || errno == ERANGE) return -1;
    *out = v;
    return 0;
}
```

## 三、裸机上的对应：串口命令行

裸机没有 shell，但**几乎每个嵌入式项目都会做一个"调试命令行"**——
它就是把 `argc/argv` 模式搬到串口上。

```c
/* 从 UART 收到一行 "led on 500\r\n"，切成 token 数组 */
static char *g_argv[8];
static int   g_argc;

static void split(char *line){
    g_argc = 0;
    for (char *p = strtok_(line, " \t"); p && g_argc < 8; p = strtok_(NULL, " \t"))
        g_argv[g_argc++] = p;
}

/* 命令表：名字 → 处理函数（ch08 的函数指针） */
static const struct { const char *name; int (*fn)(int, char **); } g_cmds[] = {
    { "led",    cmd_led    },
    { "uart",   cmd_uart   },
    { "reboot", cmd_reboot },
};

void handle_cmd(char *line){
    split(line);
    if (g_argc == 0) return;
    for (size_t i = 0; i < sizeof(g_cmds)/sizeof(g_cmds[0]); i++)
        if (strcmp_(g_argv[0], g_cmds[i].name) == 0) { g_cmds[i].fn(g_argc, g_argv); return; }
    puts_("未知命令\r\n");
}
```

⚠ **三条裸机特有的约束**：

| 约束 | 说明 |
|---|---|
| **token 数量必须有上限** | `g_argv[8]`——实测的数组边界（[ch06](../06-arrays-pointers-strings/README.md)） |
| **要自己实现 `strtok` / `strcmp` / `strtol`** | freestanding 没有 `<string.h>` / `<stdlib.h>`（[ch01](../01-hello-world/README.md) 实测过） |
| **参数转换要有边界检查** | 命令行的"越界"在裸机上是**内存破坏**，不是"程序报错退出" |

## 四、环境变量（`envp`）

标准 C 只有 `argc/argv`，但 POSIX 有第三个参数：

```c
int main(int argc, char **argv, char **envp);     /* ⚠ 非标准 */
```

⚠ **这是 POSIX 扩展，不是 C 标准**。
可移植的做法是用 `getenv()`：

```c
#include <stdlib.h>
const char *home = getenv("HOME");        /* 不存在返回 NULL */
```

⚠ **裸机上没有环境变量**，也没有 `getenv`。
配置来源是 **Flash 配置页**（[ch11](../11-linker/11.6-高级用法.md)）——
`magic` / `version` / `crc32` 那套。

## 五、参数解析的三种层次

| 层次 | 做法 | 适用 |
|---|---|---|
| **① 手写** | `if (argc > 1 && strcmp(argv[1], "-v") == 0)` | 参数很少（裸机命令行就是这层） |
| **② `getopt`** | `while ((c = getopt(argc, argv, "ho:v")) != -1)` | POSIX 风格选项（`-h` `-o file`） |
| **③ 库** | argparse / getopt_long | 复杂 CLI |

⚠ **裸机上只有①**——因为 `getopt` 属于 libc。
而且裸机命令行的参数格式通常**更简单**（`led on 500` 而不是 `--led=on --ms=500`），
手写反而合适。

## 坑点（书 / 常识怎么说 / 实际是什么）

| 书 / 常识怎么说 | 实测是什么 |
|---|---|
| "`atoi` 能把字符串转成整数" | ⚠ **检测不了错误**：`atoi("abc")`→0（和真的 0 无法区分）、`atoi("999...")`→**-1**（溢出是 UB） |
| "`argc` 可以是 0" | ❌ 实测无参数时 `argc=1`（总有 `argv[0]`）。`argc==0` 的分支是死代码 |
| "`argv[argc]` 越界" | ❌ 标准保证 `argv[argc] == NULL`，实测确认为 `(NULL)`。可以靠遍历到 NULL 结束 |
| "参数是数字" | ❌ **全是字符串**。`argv[3]` 是 `"3"` 不是 `3`，要转换且**必须检查转换结果** |
| "`main(int, char**)` 是唯一形式" | POSIX 还有第三个 `envp`，但**非标准**。要可移植就用 `getenv()` |

## 代码自测

<details>
<summary>Q1：`atoi` 和 `strtol` 差在哪？为什么不能用 `atoi`？</summary>

**`atoi` 无法区分"转换失败"和"真的转换出了 0"。**

**实测**（五个输入）：

| 输入 | `atoi` | `strtol` + 检查 |
|---|---|---|
| `"3"` | 3 | 3，全部转换 ✅ |
| `"  42abc"` | **42** ⚠ | 42，`end` 指向 `'a'`（**有残留**，可检测） |
| `"abc"` | **0** ⚠ | 0，`end == str`（**没转换任何字符**，可检测） |
| `"99999999999999999999"` | **-1** ⚠ | `LONG_MAX`，`errno = ERANGE`（可检测） |
| `""` | **0** ⚠ | 0，`end == str`（可检测） |

⚠ **最糟的是溢出那个**：
`atoi("99999999999999999999")` 实测返回 **-1**。
C 标准说 `atoi` 在值超出范围时行为是**未定义的**（undefined behavior）——
这次给 -1，换个 libc 可能给别的值。
**而你的代码会把 -1 当成一个合法的输入继续跑。**

**`strtol` 的三个检查**（缺一不可）：

```c
char *end = NULL;
errno = 0;                          /* ⚠ 调用前必须清零 */
long v = strtol(str, &end, 10);

if (end == str)        { /* ① 一个字符都没转换 */ }
else if (*end != '\0') { /* ② 数字后面有垃圾 */ }
else if (errno == ERANGE) { /* ③ 超出 long 的范围 */ }
```

⚠ **`errno = 0` 那行不能省**：
`strtol` 只在**出错时**设置 `errno`，**不会主动清零**。
如果你之前有个函数设了 `ERANGE` 没清，
这里没出错也会看到 `errno == ERANGE`。

**封装成函数**（实测的五个输入都能正确分类）：

```c
static int parse_long(const char *s, long *out){
    char *end = NULL;
    errno = 0;
    long v = strtol(s, &end, 10);
    if (end == s || *end != '\0' || errno == ERANGE) return -1;
    *out = v;
    return 0;
}
```

**同类函数对比**：

| 函数 | 能检测错误吗 | 说明 |
|---|---|---|
| `atoi` | ❌ | 别用 |
| `atol` / `atof` | ❌ | 同上 |
| **`strtol` / `strtoul`** | ✅ | ✅ **用这个** |
| `strtod` / `strtof` | ✅ | 浮点版 |
| `sscanf("%d")` | ⚠ 部分 | 返回值能知道匹配了几项，但**检测不了溢出** |

⚠ **`sscanf` 也检测不了溢出**——
`sscanf("99999999999999999999", "%d", &x)` 的行为在溢出时是未定义的。
所以**用 `strtol`，不要用 `sscanf` 做数字转换**。

**裸机上没 `<stdlib.h>`**：
[ch01](../01-hello-world/README.md) 实测过 freestanding 下找不到标准头文件，
所以要自己写一个最小的 `strtol`——
**并且一定要带"有没有转换任何字符"这个检测**
（返回 bool 或用 out 参数），否则你的串口命令行
输入 `led xyz` 会当成 `led 0` 执行。
</details>

<details>
<summary>Q2：裸机上怎么做"命令行"？和 PC 的 `argc/argv` 是什么关系？</summary>

**关系：完全同构——把一行文本切成 token 数组，然后查表分发。**
差别只是裸机上这些工具都得自己写。

**PC 版**：

```c
int main(int argc, char **argv){
    if (argc > 1 && strcmp(argv[1], "led") == 0) { ... }
}
```

**裸机版**：

```c
static char *g_argv[8];
static int   g_argc;

static void split(char *line){
    g_argc = 0;
    for (char *p = strtok_(line, " \t"); p && g_argc < 8; p = strtok_(NULL, " \t"))
        g_argv[g_argc++] = p;
}

static const struct { const char *name; int (*fn)(int, char **); } g_cmds[] = {
    { "led",    cmd_led    },
    { "uart",   cmd_uart   },
    { "reboot", cmd_reboot },
};

void handle_cmd(char *line){
    split(line);
    if (g_argc == 0) return;
    for (size_t i = 0; i < sizeof(g_cmds)/sizeof(g_cmds[0]); i++)
        if (strcmp_(g_argv[0], g_cmds[i].name) == 0) { g_cmds[i].fn(g_argc, g_argv); return; }
    puts_("unknown\r\n");
}
```

**四个组成部件**：

| 部件 | PC | 裸机 |
|---|---|---|
| **切 token** | shell 做了 | **自己写 `split`**（`strtok` 的裸机版） |
| **参数数组** | `argv` | `g_argv[8]` |
| **命令表** | 手写 `if/else` 或 `getopt` | **函数指针表**（[ch08](../08-complex-types/8.14-函数指针与typedef.md)） |
| **字符串函数** | libc | **自己写**（`strcmp_` / `strtol_`） |

⚠ **三条裸机特有的硬约束**：

**① token 数量必须有上限**

```c
static char *g_argv[8];        /* ⚠ 不是无限 */
... g_argc < 8 ...             /* ⚠ 循环条件里必须有这个判断 */
```

输入 `a a a a a a a a a a`（10 个 token）时，
不检查就会**写越界**——在裸机上是内存破坏，不是"程序报错退出"。

**② 要自己实现字符串函数**

[ch01](../01-hello-world/README.md) 实测：freestanding 下
`<string.h>` / `<stdlib.h>` 都找不到（交叉目标没有 libc）。
所以要自己写 `strcmp_` / `strtol_` / `strtok_`。

⚠ **而且要带边界检查**：
`strtol_` 必须能告诉你"转换失败"（见 Q1），
否则 `led xyz` 会被当成 `led 0`。

**③ 输入侧要能攒一行**

串口是**一个字节一个字节**来的，
所以要先攒够一行（`\r\n` 结尾）再解析。
[ch10](../10-interrupts/10.4-用缓冲区提速.md) 的环形缓冲就是干这个的：

```
ISR: 收到字节 → rb_put()
主循环: rb_get() 攒到 '\n' → handle_cmd()
```

⚠ **别在 ISR 里解析命令**——
[ch10](../10-interrupts/README.md) 讲过 ISR 预算（115200 下 8.7 µs），
解析命令太慢。

**一个实用的补充：命令表也可以放进 Flash**

```c
static const struct cmd { const char *name; int (*fn)(int, char **); }
g_cmds[] = { ... };        /* const → .rodata → Flash，不占 RAM */
```

⚠ **函数指针在 Flash 里存的是带 Thumb 位的奇数地址**
（[ch11](../11-linker/11.4-重定位.md) 实测：向量表里是 `0x08000013` 不是 `0x08000012`）。
编译器会自动处理，**手写地址常量时才要自己 `| 1`**。
</details>

<details>
<summary>Q3：`argv[argc]` 是 NULL 吗？能靠它遍历吗？</summary>

**是。C 标准保证 `argv[argc] == NULL`，实测也确认了。**

**实测**：

```
$ ./arg a b 3
argc=4
  argv[0]=./arg
  argv[1]=a
  argv[2]=b
  argv[3]=3
argv[argc]（标准保证为 NULL） = (NULL)

$ ./arg
argc=1
  argv[0]=./arg
argv[argc]（标准保证为 NULL） = (NULL)
```

**所以两种遍历方式都合法**：

```c
/* ① 用 argc（推荐，更明确） */
for (int i = 0; i < argc; i++) printf("%s\n", argv[i]);

/* ② 靠 NULL 结束（和 execve 的 envp 风格一致） */
for (char **p = argv; *p; p++) printf("%s\n", *p);
```

**但方式②有个前提**：`argv` 必须以 NULL 结尾。
标准保证了这一点（C11 5.1.2.2.1），
**所以正常情况下没问题**。

⚠ **两个"不正常"的情况**：

**① 有人手工构造 argv 传给你的函数**

```c
void handle(int argc, char **argv);
char *my_argv[] = { "led", "on" };        /* ⚠ 没有 NULL 结尾 */
handle(2, my_argv);                        /* 用方式②遍历就会跑飞 */
```

——所以**自己写的函数签名带 `argc` 时，用方式①**。

**② `argc == 0` 的极端情况**

标准说 `argc` 至少是 1（实测无参数时 `argc=1`）。
但**通过 `execve` 直接传空 argv 数组**可以做到 `argc == 0`：

```c
char *argv[] = { NULL };
execve("/path/to/prog", argv, envp);       /* argc = 0 */
```

⚠ 这时 `argv[0]` 是 NULL，`printf("%s", argv[0])` 会崩
（严格说是 UB）。
**处理 argv 时先判 `argc > 0`** 是个便宜的保险。

---

**顺带：`envp` 的三参数 `main`**

```c
int main(int argc, char **argv, char **envp);      /* ⚠ POSIX 扩展，非 C 标准 */
```

实测上 macOS/Linux 都支持，但**它不是标准 C**——
用 `-std=c11 -pedantic` 编译会警告。

**可移植的替代**：

```c
#include <stdlib.h>
const char *home = getenv("HOME");       /* 不存在返回 NULL */
```

⚠ **裸机上没有环境变量，也没有 `getenv`**。
裸机的"配置"来源是：

| 来源 | 特点 |
|---|---|
| **Flash 配置页**（[ch11](../11-linker/11.6-高级用法.md)） | 掉电不丢，但**写要走擦页流程** |
| **编译期 `-D`**（[ch12](../12-preprocessor/12.6-命令行定义的符号.md)） | 改一次配置要重新编译 |
| **串口命令行** | 运行时改，但掉电就没（除非写回 Flash） |

——所以裸机的"环境变量"通常是 **Flash 配置页 + 串口命令行**的组合：
命令行改，改完写回 Flash 保存。
这也是 [ch11](../11-linker/11.6-高级用法.md) 讲 `magic`/`version`/`crc32` 的原因。
</details>
