# 4.12 用位操作控制内存映射 I/O 寄存器

> 书：第 4 章 数字和变量 · 4.12 用位操作控制内存映射 I/O 寄存器
> 上一篇：[4.11 缩写运算符](4.11-缩写运算符.md) ｜ 本篇是第 4 章的收尾
> 对应实验：`stm32/03-gpio-blink/`（真机）+ 主机交叉编译 `--target=armv7m-none-eabi -mcpu=cortex-m3 -Os`

## 书这一节讲什么

一句话：**用 `|=` 置位、`&= ~` 清位、`^=` 翻转、`&` 检查位**，
因为内存映射 I/O 寄存器是**位打包**的——写 32 位就是同时改 32 个语义单元。

这是第 4 章唯一"裸机独有"的一节，前面 4.1–4.11 在任何 C 书里都有。
书里讲的是**掩码怎么算**（定义位的含义、一次设置两位、关闭一位、检查位的值），
本篇补上书里讲得轻的那一半：**为什么**，以及**同样的 C 语句在 Cortex-M 上生成几条指令**。

## 一、五个操作，在裸机上的分工

| 操作 | 用途 | 例子 |
|---|---|---|
| `\|=` OR | **置位**（不动其他位） | `RCC_APB2ENR \|= (1u << 2)` 开 GPIOA 时钟 |
| `&= ~` AND NOT | **清位** | `GPIOA_CRL &= ~(0xFu << 20)` 清 PA5 的 4 个配置位 |
| `^=` XOR | **翻转** | `GPIOA_ODR ^= (1u << 5)`（⚠ 有坑，见实测 ③） |
| `~` NOT | 造掩码 | `~(0xFu << 20)` |
| `<<` `>>` | 位号 → 掩码 | `BIT(5)` = `1u << 5` |

## 二、实测：同样的"改一位"，指令数差 3 倍

```c
typedef unsigned int u32;
#define RCC_APB2ENR (*(volatile u32 *)0x40021018u)
#define GPIOA_CRL   (*(volatile u32 *)0x40010800u)
#define GPIOA_ODR   (*(volatile u32 *)0x4001080cu)
#define GPIOA_BSRR  (*(volatile u32 *)0x40010810u)

void cfg_read_modify_write(void){ GPIOA_CRL &= ~(0xFu << 20); GPIOA_CRL |= (0x1u << 20); }
void toggle_bsrr(void){ GPIOA_BSRR = (1u << 5); GPIOA_BSRR = (1u << (5u + 16u)); }
void toggle_odr_xor(void){ GPIOA_ODR ^= (1u << 5); }
void enable_clock(void){ RCC_APB2ENR |= (1u << 2); }
int  check_bit(void){ return (GPIOA_ODR & (1u << 5)) != 0; }
```

```
$ clang --target=armv7m-none-eabi -mcpu=cortex-m3 -mthumb -Os -c gpio_bits.c -o gpio_bits.o
$ llvm-objdump -d gpio_bits.o
```

**① 清位 + 置位（配置引脚，书里的"先清再置"）**

```
00000000 <cfg_read_modify_write>:
       0: f640 0000     movw r0, #0x800
       4: f2c4 0001     movt r0, #0x4001      ; r0 = 0x40010800 (GPIOA_CRL)
       8: 6801          ldr  r1, [r0]         ; ← 读
       a: f421 0170     bic  r1, r1, #0xf00000
       e: 6001          str  r1, [r0]         ; ← 写
      10: 6801          ldr  r1, [r0]         ; ← 又读
      12: f441 1180     orr  r1, r1, #0x100000
      16: 6001          str  r1, [r0]         ; ← 又写
      18: 4770          bx   lr
```

**6 条指令、两次 ldr/str。** 中间若来中断，ISR 改了同一寄存器的另一位，
第二次 `str` 会把 ISR 的修改覆盖回去。

**② 用 `BSRR` 翻转（一条 `str` 一次）**

```
0000001a <toggle_bsrr>:
      1a: f640 0010     movw r0, #0x810
      22: 2120          movs r1, #0x20         ; 1<<5   → 置位
      24: 6001          str  r1, [r0]
      26: f44f 1100     mov.w r1, #0x200000    ; 1<<21  → 复位
      2a: 6001          str  r1, [r0]
      2c: 4770          bx   lr
```

**没有 `ldr`。** 两次 `str`，每次都是"写 1 生效、写 0 无效"的硬件语义，
**物理上不可能覆盖别人的位**——这就是硬件对"读-改-写不原子"的补偿。

**③ `ODR ^=` 翻转（看着最简洁，实际最危险）**

```
0000002e <toggle_odr_xor>:
      36: 6801          ldr  r1, [r0]         ; 读
      38: f081 0120     eor  r1, r1, #0x20    ; 改
      3c: 6001          str  r1, [r0]         ; 写
```

一条 C 语句 = 3 条指令，中间可被中断打断。

**④ 开时钟（最经典的一行）**

```
00000040 <enable_clock>:
      48: 6801          ldr  r1, [r0]         ; 读 RCC_APB2ENR
      4a: f041 0104     orr  r1, r1, #0x4     ; |= (1<<2)
      4e: 6001          str  r1, [r0]         ; 写回
```

**⑤ 检查位（编译器给的最优解：`ubfx` 一条）**

```
00000052 <check_bit>:
      5a: 6800          ldr  r0, [r0]
      5c: f3c0 1040     ubfx r0, r0, #0x5, #0x1   ; 提取 bit5，一条指令
      60: 4770          bx   lr
```

写 `(reg & BIT(5)) != 0` 比 `(reg >> 5) & 1` 更直观，
而编译器同样能优化成单条 `ubfx`——**写法选可读的，指令交给编译器**。

## 三、一条判据（本篇的结论）

> **凡是"改寄存器里的某几位"，先问一句：这个寄存器有没有"写 1 生效"的影子寄存器
> （`BSRR` / `BRR` / `BSRRH` / 某些系列的 `SCR`）？有就用它，没有才读-改-写，
> 并且读-改-写期间要关中断（[ch10](../ch10-interrupts.md)）。**

再补一条判据（书里完全没有）：

> **"会不会有第二个人（ISR / DMA / 另一个核）同时改这个寄存器？"
> 会 → 用写 1 生效的影子寄存器或临界区；不会 → 读-改-写没问题。**

初始化阶段通常没有并发（中断还没开），所以 `CRL` 的读-改-写是安全的；
运行期动态改引脚方向才是要小心的场合。

## 四、为什么必须位操作：寄存器是位打包的

`GPIOA_CRL` 一个 32 位寄存器管 **8 个引脚**（PA0–PA7 各占 4 位）：

| 位区间 | 引脚 |
|---|---|
| 3:0 | PA0 |
| 7:4 | PA1 |
| … | … |
| 23:20 | PA5 |
| 31:28 | PA7 |

所以 `GPIOA_CRL = 0x00100000` 这种"整寄存器赋值"会**把 PA0–PA4、PA6、PA7 的配置全清成 0**
（复位默认 = 浮空输入）——你只想配 PA5，结果把别的引脚全废了。

正确写法永远是**先清再置**：

```c
GPIOA_CRL &= ~(0xFu << 20);        /* 清 PA5 的 4 位 */
GPIOA_CRL |=  (0x2u << 20);        /* 置成 0b0010 = 推挽输出 2MHz */
```

## 五、BIT 宏：把位号写成自解释的

```c
#define BIT(n)      (1u << (n))
#define BITMASK(h,l) (((1u << ((h)-(l)+1u)) - 1u) << (l))   /* 取 h:l 的掩码 */

RCC_APB2ENR |= BIT(2);              /* 开 GPIOA 时钟 */
GPIOA_CRL  &= ~BITMASK(23, 20);     /* 清 PA5 的 4 位 */
GPIOA_CRL  |=  (0x2u << 20);
```

配合 [4.9](4.9-溢出.md) 里的 `_Static_assert(n < 32, "")`，
把"位移出界"这类 UB 也堵在编译期。

## 坑点（书 / 常识怎么说 / 实际是什么）

| 书 / 常识怎么说 | 实际是什么 |
|---|---|
| "配置引脚写一行 `CRL = 0x00100000` 就行" | 会**覆盖同寄存器里另外 7 个引脚**的配置（CRL 一个寄存器管 8 个引脚） |
| "`ODR ^= (1<<5)` 翻转很优雅" | 实测 3 条指令（ldr/eor/str），中断下会丢别人的修改。用 `BSRR` 只要 1 条 `str` |
| "位操作很慢，能用算术就用算术" | Cortex-M 上恰恰相反：实测 `bic`/`orr` 都能编码成**单条** Thumb-2 指令 |
| "检查位要 `(reg >> 5) & 1`" | 写 `(reg & BIT(5)) != 0` 更直观，编译器同样生成单条 `ubfx`（实测） |
| "`volatile` 加了就万事大吉" | 它只保证访问不被优化掉，**不保证原子**（[ch01](../01-hello-world/1.5-编译器在幕后的工作方式.md) 已实测）。本节的读-改-写正是它管不了的那部分 |
| "`\|=` 是标准写法" | 对"写 1 生效"的 `BSRR` 是错的：应该用**普通赋值**，`\|=` 反而多一次 `ldr` |

## 代码自测

<details>
<summary>Q1：是不是所有寄存器都该用 `BSRR` 那种"一条 str"的写法？</summary>

不是——**前提是硬件提供了"写 1 生效"的寄存器**。

`BSRR` 是 ST 特意加的：写低 16 位某位 = 置位对应引脚，写高 16 位某位 = 复位对应引脚，
**写 0 的位完全不影响**。所以一次 `str` 就是原子的"只改我关心的那一位"。

但 `CRL`（引脚配置）没有这种影子寄存器，只能读-改-写。这时候的正确做法：

1. **尽量在初始化阶段一次性配好**，运行时不再改——初始化时中断还没开，读-改-写是安全的；
2. 运行期必须改（比如动态切换输入/输出）时，**改之前关中断、改完再开**；
3. 或者用 `LDREX/STREX`（M3/M4 支持独占访问）做原子的读-改-写。

判据一句话：**"有没有第二个人同时改这个寄存器？"
会 → 写 1 生效的影子寄存器或临界区；不会 → 读-改-写没问题。**
</details>

<details>
<summary>Q2：为什么"先清再置"要分两步，不能一步写？</summary>

因为**置位操作无法把已经是 1 的位清成 0**。

`CRL` 里 PA5 占 4 位（bit 23:20）。假设原来配置是 `0b1011`（某个别的模式），
你想设成 `0b0010`：

```c
GPIOA_CRL |= (0x2u << 20);    /* ❌ 错：0b1011 | 0b0010 = 0b1011，第 3 位没被清掉 */
GPIOA_CRL &= ~(0xFu << 20);   /* ✅ 先清成 0b0000 */
GPIOA_CRL |=  (0x2u << 20);   /* ✅ 再置成 0b0010 */
```

实测这两步生成 6 条指令（ldr/bic/str + ldr/orr/str），
代价是两次读-改-写——但因为它在初始化阶段执行，没有并发，代价可以接受。

一个改进写法是**先把整个字段读出来、改好、一次写回**：

```c
uint32_t v = GPIOA_CRL;
v &= ~(0xFu << 20);
v |=  (0x2u << 20);
GPIOA_CRL = v;              /* 只有一次 str，窗口更小 */
```

这样把"两次读-改-写"压缩成"一次读 + 一次写"，中断窗口从 6 条指令缩到 4 条。
</details>

<details>
<summary>Q3：书里说"一次设置两位"，代码该怎么写？</summary>

用**位区间掩码**（`BITMASK(h,l)`），而不是把两个 `BIT()` 或起来——
两者在位号连续时等价，但前者跟手册的 "bits 23:20" 写法一一对应：

```c
#define BITMASK(h,l) (((1u << ((h)-(l)+1u)) - 1u) << (l))

/* 手册：CNF5[1:0] + MODE5[1:0] = bits 23:20，设为 0b0010（推挽输出 2MHz） */
GPIOA_CRL = (GPIOA_CRL & ~BITMASK(23,20)) | (0x2u << 20);
```

要注意的两个细节：

1. **`BITMASK` 里的 `1u`**：必须是无符号，否则 `1 << 32`（当 h-l+1 = 32 时）是 UB；
2. **清位用 `~BITMASK(...)`，置位用 `<< l` 对齐后的值**——两者的位区间必须一致，
   写错一个数字就会清掉/覆盖相邻引脚的配置。

再强调一次整寄存器赋值的危险：
`GPIOA_CRL = 0x00200000;` 会把 PA0–PA4、PA6、PA7 全设成 `0b0000`（浮空输入）。
实测里那种"灯不亮但代码没问题"的排查，八成就是这个原因。
</details>
