# 4.2 声明变量

> 书：第 4 章 数字和变量 · 4.2 声明变量（原书 p44–64 区间内）
> 上一篇：[4.1 使用整数](4.1-使用整数.md) ｜ 下一篇：[4.3 赋值](4.3-赋值.md)
> 对应实验：`--target=armv7m-none-eabi` 交叉编译 + `llvm-nm` / `llvm-objdump -h` 看段

## 书这一节讲什么

一句话：**用之前要先声明**，声明就是"给一块内存起个名字 + 定个类型"。

在 PC 上这句话的代价几乎为零——内存是虚拟的、按需分配的、GB 级的。
在裸机上，**"声明"这个动作直接决定这块内存从 20 KB RAM 里分走多少、什么时候生效、会不会被清零**。
这是本节书里没讲、但裸机上必须知道的部分。

## 一、声明 ≠ 定义（书里一笔带过，链接期会咬人）

```c
extern uint32_t g_ticks;     /* 声明：不分配空间，告诉编译器"别处有" */
uint32_t g_ticks = 0;        /* 定义：分配空间，全工程只能有一处 */
```

裸机上踩这个坑的典型症状是链接报 `undefined reference`，或者更糟：
两个 `.c` 里都写了 `uint32_t g_ticks;`（没加 `extern`），
在 `-fcommon` 下它们被**悄悄合并成同一个变量**——两个模块互相踩，毫无征兆。

实测（`-fno-common` 是裸机工程的常见设置）：

```
$ clang ... -ffreestanding -c seg.c -o seg_arm.o
$ llvm-nm seg_arm.o | grep -E 'g_init|g_zero'
00000000 D g_init      ← D = .data
00000004 B g_zero      ← B = .bss
```

## 二、变量声明出来之后，落在哪个段（实测）

```c
/* seg.c */
int g_init = 42;        /* 已初始化全局 */
int g_zero;             /* 未初始化全局 */
static int s_const = 7;
int main(void){ static int l_init = 1; static int l_zero; return g_init+g_zero+s_const+l_init+l_zero; }
```

```
$ clang --target=armv7m-none-eabi -mcpu=cortex-m3 -mthumb -ffreestanding -c seg.c -o seg_arm.o
$ llvm-objdump -h seg_arm.o
Idx Name            Size     VMA      Type
  2 .text           0000003c 00000000 TEXT
  6 .data           0000000c 00000000 DATA      ← g_init(4) + s_const(4) + main.l_init(4)
  7 .bss            00000008 00000000 BSS       ← g_zero + main.l_zero
$ llvm-nm seg_arm.o
00000000 D g_init
00000004 B g_zero
00000004 d main.l_init
00000000 b main.l_zero
```

| 声明方式 | 落点 | 谁负责让它有值 |
|---|---|---|
| 全局 + 有初值 | `.data` | 启动代码从 Flash **拷**到 RAM（ch03 实测过这段拷贝） |
| 全局 + 无初值 | `.bss` | 启动代码**清零**（不是"碰巧是 0"，是有人清的） |
| `static` 局部 + 有初值 | `.data` | 同上 |
| `static` 局部 + 无初值 | `.bss` | 同上 |
| 普通局部变量 | **栈** | 没人管，值是栈上的旧数据（[4.4 初始化](4.4-初始化.md)展开） |

**裸机的关键后果**：每声明一个全局变量，你就在 RAM 预算里花掉 4 字节（或更多）。
NUCLEO-F103RB 只有 20 KB RAM，栈还要从 `_estack = 0x20005000` 往下长——
全局变量的多少直接决定栈还能剩多少（[7.4 栈帧](../07-stack-frame-functions/7.4-栈帧.md) 会算这个账）。

## 三、`static` 在裸机上的两个作用

1. **限制作用域**：`static` 的全局变量只在本 `.c` 可见——这是 C 唯一的"命名空间"手段
   （[ch17](../ch17-modular-programming.md) 展开）。
2. **把变量从栈挪到 `.bss`/`.data`**：`static` 的局部变量有固定的 RAM 地址，
   不占栈空间。裸机上大缓冲区（比如 1 KB 的串口环形缓冲）**必须**这么声明，
   否则栈直接爆。

## 四、`const` 落在 Flash，不是 RAM

```c
const uint32_t baud = 115200;    /* 落在 .rodata → Flash（1 MB），不占 20 KB RAM */
```

这条在裸机上是**省 RAM 的第一手段**：查找表、字符串常量、配置常量一律加 `const`，
它们就去了 Flash（128 KB / 1 MB 级别），而不是跟你抢 20 KB RAM。

## 坑点（书 / 常识怎么说 / 实际是什么）

| 书 / 常识怎么说 | 实际是什么 |
|---|---|
| "声明就是起个名字" | 裸机上声明同时决定了**段归属**：`.data` 要占用 Flash+RAM 两份，`.bss` 只占 RAM |
| "全局变量没初值就是 0" | 是 0，但**因为启动代码清了 `.bss`**，不是语言的自然结果。裸机的启动文件里那句 `bss` 清零循环没了，它就是垃圾值（ch03 的启动文件实测过） |
| "两个文件里都写 `int x;` 会报重复定义" | 不一定。开 `-fcommon` 时会被**静默合并**成一个变量，两个模块互相覆盖。裸机工程一般加 `-fno-common` 让它报错 |
| "局部变量和全局变量差不多" | 局部变量在**栈**上，栈大小是链接脚本写死的一行，溢出不报错只踩 `.bss` |
| "`static` 只是隐藏符号" | 它同时把变量**从栈挪到静态区**——裸机上 1 KB 缓冲区只能这么放 |

## 代码自测

<details>
<summary>Q1：裸机上声明一个 1 KB 的串口接收缓冲，该怎么写？为什么不能直接写在函数里？</summary>

写成 `static`（或全局）：

```c
#define RB_SIZE 1024
static uint8_t rx_buf[RB_SIZE];        /* .bss，固定地址 */
static volatile uint32_t rx_head, rx_tail;
```

**不能直接写在函数里**，因为普通局部变量在栈上：

- 栈的大小是链接脚本里写死的一行（`_estack = ORIGIN(RAM) + LENGTH(RAM)`），
  NUCLEO-F103RB 上只有 20 KB 总量，还得留给中断栈和调用链；
- **没有 MMU、没有守卫页**，栈溢出不会报任何错，只会静默踩掉 `.bss`/`.data` 里的变量；
- 函数返回后缓冲区就没了，而串口中断随时要写它。

所以裸机的规则是：**跨函数生命周期的数据（缓冲、状态、计数器）一律 `static` 或全局**，
栈只用来放"这一次调用期间"的东西。
</details>

<details>
<summary>Q2：为什么 `.data` 段的变量要占两份空间（Flash + RAM）？</summary>

因为 RAM 掉电就丢，而初值必须**永久**保存。

流程是这样的：

1. 编译链接时，`g_init = 42` 的初值 42 被写进 **Flash**（`.data` 的 LMA 在 Flash）；
2. 上电后，启动代码把这一段从 Flash **拷贝**到 RAM（`.data` 的 VMA 在 RAM）；
3. 之后程序访问的都是 RAM 里那份。

所以 `int g_init = 42;` 的真实成本是 **4 字节 Flash + 4 字节 RAM**；
而 `int g_zero;` 只要 **4 字节 RAM**（Flash 里什么都不存，上电清 0 就行）。

这也解释了裸机上的一条经验：**默认值就是 0 的全局变量，别多此一举写 `= 0`**——
写了反而让它从 `.bss` 挪进 `.data`，白占一份 Flash。
</details>

<details>
<summary>Q3：`const` 变量在裸机上为什么值得强调？</summary>

因为它是**免费的**。

```c
const uint32_t lut[256] = { ... };   /* 1 KB 查找表 */
```

加 `const` → 落在 `.rodata` → 链接脚本把它放进 **Flash**。
NUCLEO-F103RB 的 Flash 是 128 KB、RAM 只有 20 KB，
一个 1 KB 的表如果因为漏写 `const` 掉进 `.data`，就是 **1 KB Flash + 1 KB RAM**，
白吃掉 5% 的 RAM 预算——而这类表通常有几十个条目，很容易吃掉一半 RAM。

判断方法：`llvm-nm` 里 `R`/`r` 是只读段（Flash），`D`/`d` 是 `.data`，`B`/`b` 是 `.bss`。
每写完一批全局数据，跑一次 `llvm-size` 看 `.data`/`.bss` 的增长，是裸机上最简单的 RAM 体检。
</details>
