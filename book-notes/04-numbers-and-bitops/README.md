# 第 4 章 数字和变量 —— 章节导航

> 书：第 4 章 数字和变量（原书 p44–64）
> 对应实验：`stm32/03-gpio-blink/`（真机）+ 主机交叉编译
> `--target=armv7m-none-eabi -mcpu=cortex-m3`（本篇所有反汇编都来自这套命令）

## 这一章在讲什么

**表面是 C 基础（整数、变量、赋值、初始化、溢出、补码），实际只有一件事是裸机独有的：
4.12「用位操作控制内存映射 I/O 寄存器」。**

前面那些小节（整数大小、数字表示、溢出、补码）在任何一本 C 书里都有。
它们在裸机上的分量之所以不一样，是因为**后果不同**：

- PC 上整数溢出 → 得到一个错的值，程序继续跑；
- 裸机上整数溢出 → 算出来的**寄存器地址或位掩码是错的**，写到了别的寄存器上，
  而且**没有任何报错**。

所以本章的读法是：4.1–4.11 快速过（挑"宽度"和"溢出"两节精读），
**4.12 必须精读**——它是后面所有外设操作的基本功。

## 与书的差异（重要）

| 书 | 我 |
|---|---|
| 举 PC 上的算术例子 | 每个结论都配**实测**：主机 `clang -O2` + Cortex-M 交叉反汇编 |
| 用 `int` / `unsigned int` 举例 | 全程 `uint32_t` / `uint8_t`（实测 `long` 在 Mac 是 8、Cortex-M 是 4） |
| 说"溢出会得到错的值" | 分成两种：unsigned 是**定义好的回绕**，signed 是 **UB**——实测 `-O0` 和 `-O2` 跑出**不同结果** |
| 讲"位操作怎么算掩码" | 补上**为什么**：寄存器是位打包的；以及同样一句 C 生成几条指令（实测 6 条 vs 1 条 `str`） |
| 只讲 `\|= / &= ~ / ^=` | 补上"写 1 生效"的 `BSRR` 才是硬件给的正解（实测：无 `ldr`，物理上免疫竞态） |

## 读完本章你应该能回答

- 为什么裸机代码里几乎见不到 `int` 和 `long`？（`long` 跨平台宽度不同，实测断言）
- unsigned 溢出和 signed 溢出差在哪？为什么 `-O0` / `-O2` 会跑出不同答案？
- 全局变量为什么"默认是 0"？谁清的？启动文件没写对会怎样？
- 为什么 `int x = 0;` 在裸机上比 `int x;` 更贵？
- `reg |= BIT(5)` 生成几条指令？什么情况下会被中断打断并丢修改？
- 什么时候该用 `BSRR`（普通赋值）而不是 `|=`？
- 为什么配置引脚必须先 `&= ~` 再 `|=`，不能一步写？
